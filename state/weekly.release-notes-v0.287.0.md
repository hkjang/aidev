# v0.287.0 — 주 격자를 옮긴 주에도 분석 화면이 그 주의 보고서를 셉니다

관리자가 주차 시작 요일을 바꾸면 주 격자만 옮겨지고 이미 저장된 보고서는 그 자리에 남습니다. 전환되는 한 주 동안 팀이 이미 써 둔 보고서는 같은 7일을 다른 날짜로 덮고, `weekIsFree` 는 같은 기간의 두 번째 보고서를 만들지 못하게 합니다. 그런데 분석 화면은 그 주의 숫자를 `week_start` 정확일치로 물었습니다. 그래서 모두가 보고한 한 주가 제출률 0%, 상태별 분포 빈칸, 미해결 이슈 0건, 평균 진행률 0 으로 보였습니다 — 누가 다시 써서 되살릴 수도 없는 주입니다.

## 네 숫자가 같은 보고서를 셉니다

- 제출률·상태별 분포와 미해결 이슈·평균 진행률 질의를 날짜 정확일치에서 기간 겹침(`weekCoveringDays`)으로 바꿨습니다. v0.282.0 의 작성 화면, v0.283.0 의 팀원 자료, v0.284.0 의 자동 복제, v0.285.0 의 지난주 계획과 같은 규칙입니다.
- 사람마다 한 건만 셉니다. 어떤 7일을 덮는 보고서는 많아야 하나이므로 이 선택은 `weekIsFree` 가 생기기 전에 쓰인 행 사이에서만 갈리며, 그때는 `currentReport` 와 같이 가장 늦은 `week_start` 를 고릅니다.
- 이슈와 진행률도 분포가 센 바로 그 보고서만 세도록 묶었습니다. 한 화면의 네 숫자가 서로 다른 사람들을 설명하지 않습니다.
- 같은 함수를 MCP 주간 요약(`/api/v1/mcp`)도 읽습니다. 화면 없이 숫자만 받아 요약하는 AI 클라이언트에게는 0% 가 이상하다는 것을 알아챌 자리조차 없었습니다.

격자를 한 번도 옮기지 않은 배포에서는 결과가 종전과 같습니다.

## 검증

회귀 시험 1개(`currentweekgrid_test.go`)를 더했습니다. 요일을 바꾼 직후 전환 주에 팀원 한 명이 옛 격자로 제출해 둔 보고서를 두고 조직장이 분석 화면을 열어, 제출 인원·제출률·미해결 이슈·평균 진행률이 모두 그 보고서를 가리키는지 봅니다. 고치기 전에는 네 숫자 모두에서 실패합니다. 같은 주에 보고한 다른 조직 사람도 한 명 두어, 날짜를 기간으로 넓히면서 보이는 사람까지 넓히지 않았는지 함께 봅니다.

실제 PostgreSQL 위에서 전체 Go 테스트와 `go vet`, 가드 검사, 프런트엔드 121개 시험·린트·프로덕션 빌드, 버전·OpenAPI·모달 검사를 통과했습니다.

## 업그레이드

API 스키마, 데이터베이스 마이그레이션과 새 환경변수는 없습니다. 기존과 같이 PostgreSQL을 백업한 뒤 v0.287.0 이미지를 올리면 바로 적용됩니다. 지나간 전환 주의 숫자도 다시 열면 바르게 나옵니다 — 저장된 값을 고치는 것이 아니라 묻는 방식을 고쳤기 때문입니다.
