## 이 캠페인에서 다른 저장소가 이미 걸린 것 — 시작 전에 확인하고, 끝내기 전에 다시 확인하세요
(캠페인 "mail-2026-09" 의 리뷰 거절·심사 거절·회귀 17건에서 정제한 규칙. 러너가 자동으로 붙였습니다.)
- **발송 결과를 기록하는 UPDATE/INSERT 에는 발송용 컨텍스트를 재사용하지 말고 독립된 짧은 ctx(또는 Background) 를 쓴다. 구현 전에 '재시도 횟수 × 연결 마감 + 대기' 합계가 발송 예산보다 커질 수 있는지 소스에서 계산한다.** — 릴레이가 TCP 는 받되 응답하지 않으면 발송이 예산 끝까지 매달리고, 그 직후의 기록 쓰기가 만료된 ctx 로 실패해 행이 영원히 '대기/발송 중' 으로 남아 '시도마다 기록' 약속이 장애 상황에서 정확히 깨진다. (근거: ai-admin, hunter, seaton, 4회)
- **TLS 없는 연결에서 자격증명을 보낼지 말지 정책을 먼저 정하고, 평문 차단 조건에 쓰는 두 값이 실제로 다른 값인지 소스에서 확인한다. 루프백이 아닌 주소에서 AUTH 만 광고하고 STARTTLS 없는 가짜 릴레이로 직접 돌려 본다.** — server.Name 과 host 를 비교하는 조건은 둘 다 같은 설정값이라 항상 거짓이 되어 비밀번호가 평문으로 나가고, 반대로 표준 PLAIN 은 비-localhost 평문에서 항상 실패해 인증이 동작하지 않는다. (근거: appstore, madi, vibe-coders, 4회)
- **발송 고루틴은 세마포어(버퍼 채널 등)로 동시 수를 제한하고, 상한을 넘는 작업은 대기시키되 기록 INSERT 는 즉시 남긴다.** — 알림마다 무제한으로 고루틴을 띄우면 응답 없는 릴레이에서 고루틴과 열린 TCP 연결이 요청 속도만큼 쌓인다. (근거: ai-admin, dataworks, 2회)
- **메일 본문의 링크와 안내 문장은 한 줄씩 소스와 대조한다: UI 가 라우팅하는 해시 형식, 게이트가 승인을 적용하는 실제 조건, 키 회전이 만료일을 어떻게 다루는지, 행위자 이름이 누구를 가리키는지.** — 틀린 링크는 존재하지 않는 화면을 가리키고, 틀린 안내('다시 보내면 처리됨', '회전하면 새 키')는 사용자가 따르는 순간 스팸이나 반복 메일을 만든다. (근거: dataworks, seaton, sqlon, 4회)
- **발송 트리거는 상태값이 아니라 '상태 전이 한 번' 에만 걸리게 하고, 같은 사용자·같은 대상의 재시도나 반복 이벤트를 억제하는 키(디바운스·중복 억제)를 둔다.** — 상태값만 보면 부분 승인, 식별 헤더 없는 재요청, 만료일이 복사된 회전 키가 같은 분기로 다시 들어와 같은 수신자에게 또 메일이 가고 관리자 전원이 스팸을 받는다. (근거: dataworks, sqlon, seaton, 3회)
- **테스트는 운영 조건으로 실패 경로를 태운다: 127.0.0.1 대신 비-루프백 주소, connection refused 대신 Accept 후 침묵하는 릴레이, 필드를 직접 주입하지 말고 실제 생성 경로로 채운 데이터, 단일 승인뿐 아니라 부분 승인 케이스.** — localhost 예외·즉시 실패·주입된 필드·쉬운 케이스만으로는 평문 인증·기록 유실·미발송·중복 발송 결함이 모두 통과해 회귀 방지가 되지 않고, 잘못된 값을 단언한 테스트는 결함을 고정한다. (근거: vibe-coders, madi, sqlon, dataworks, 5회)
- **알림이 의존하는 필드(작성자·수신자 등)를 운영 코드 어느 경로가 실제로 채우는지 추적한 뒤에 커밋 메시지와 가이드에 그 알림을 약속한다.** — 채우는 경로가 없으면 조건 분기에서 조용히 반환되어 그 알림은 제품에서 한 번도 발송되지 않으며 테스트만 통과한다. (근거: vibe-coders, 1회)
- **시험 발송의 실패 응답(상태 코드·본문 형식)은 기존 프론트 API 클라이언트가 실제로 오류 문구를 표시하고 발송 기록을 갱신하는 형태인지 클라이언트 코드에서 확인한다.** — non-2xx 를 throw 하고 특정 오류 스키마만 파싱하는 클라이언트에서는 서버가 보낸 이유가 일반 문구로 바뀌고 onSuccess 전용 갱신이 실행되지 않아 기록도 갱신되지 않는다. (근거: vibe-coders, 1회)
