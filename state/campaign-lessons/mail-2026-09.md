## 이 캠페인에서 다른 저장소가 이미 걸린 것 — 시작 전에 확인하고, 끝내기 전에 다시 확인하세요
(캠페인 "mail-2026-09" 의 리뷰 거절·심사 거절·회귀 57건에서 정제한 규칙. 러너가 자동으로 붙였습니다.)
- **자격증명을 보내기 전 평문 여부는 server.TLS(또는 TLS 연결 상태) 하나로만 판단한다. `server.Name != host` 류 비교를 가드로 쓰지 않는다(stdlib NewClient 가 넘긴 host 를 그대로 ServerInfo.Name 에 넣어 항상 거짓). TLS 없음+username 설정이면 auto 는 인증을 거부하고 명시적 none 만 허용하는 정책을 문서에 먼저 정한 뒤 구현한다.** — 13개 저장소에서 같은 가드가 무력해 STARTTLS 없는 릴레이에 비밀번호가 base64 평문으로 나갔다. (근거: DartFly, appstore, dataworks, igame, jupiq, madi, moyro, orbit, qurio, relio, seaton, vibe-coders, 17회)
- **인증 경로 테스트는 127.0.0.1 이 아닌 비-루프백 주소에 바인드한 가짜 릴레이로 하고, `AUTH PLAIN LOGIN` 광고와 `AUTH LOGIN` 만 광고하는 두 케이스를 모두 둔다. 비밀번호가 나가지 않는 것과 인증이 항상 실패하지 않는 것(stdlib PlainAuth 는 비-TLS 비-localhost 에서 무조건 실패)을 둘 다 단언한다.** — 루프백 릴레이 테스트는 localhost 예외로 통과해 누출과 '항상 인증 실패' 두 결함을 모두 숨겼다. (근거: igame, madi, vibe-coders, 4회)
- **발송 결과 기록(UPDATE)과 다음 수신자 INSERT 는 발송용 컨텍스트와 분리된 컨텍스트로 수행하고 오류를 버리지 않는다. 발송 예산은 연결 마감×시도 수×수신자 수를 소스에서 계산해 충분히 잡고, TCP 만 받고 응답하지 않는 리스너로 재현 테스트를 둔다.** — 침묵하는 릴레이에서 컨텍스트가 먼저 만료돼 기록이 영원히 '대기/발송 중' 으로 남고 뒤 수신자는 INSERT 조차 안 됐다. (근거: ai-admin, hunter, seaton, 5회)
- **발송 고루틴은 세마포어로 동시 수를 제한하고(기록은 즉시 남기고 발송만 대기), 같은 사용자·같은 요청의 재시도가 새 알림을 만들지 않도록 트리거별 디바운스·묶기 규칙을 둔다.** — 죽은 릴레이+빠른 요청에서 고루틴·TCP 연결이 무한히 쌓이고, API 키 하나로 관리자 전원에게 요청당 N통을 쏟을 수 있었다. (근거: ai-admin, dataworks, 2회)
- **메일 본문의 링크 경로는 프론트 라우터 정의에서 실제 존재하는 경로를 찾아 쓰고, 'X 하면 Y 됩니다' 류 안내 문구는 해당 코드 경로(헤더 요구, 키 회전의 만료일 처리, 누가 어떤 행위를 했는지)로 사실인지 확인한 뒤 쓴다. 테스트는 잘못된 링크·문구를 그대로 단언하지 않는다.** — 존재하지 않는 경로로 링크가 갔고, 안내대로 하면 스팸이 나거나 만료를 벗어나지 못하거나 승인자를 제출자로 오표기했다. (근거: dataworks, seaton, sqlon, 5회)
- **발송 조건은 '호출 후 state==X' 같은 스냅샷이 아니라 실제 상태 전이로, 억제 조건은 '다른 알림 행 존재' 가 아니라 그 알림이 실제로 발송되는지로 판단한다. 트리거를 가르는 필드(작성자 등)는 제품에서 실제로 채워지는 경로가 있는지 추적하고, 테스트에서 직접 주입해 통과시키지 않는다.** — 부분 승인이 제출로 오인돼 중복 메일이 갔고, 묶였다고 버린 멘션 메일이 실제로는 아무 데도 안 갔으며, 채워지지 않는 필드 때문에 알림이 제품에서 한 번도 발송되지 않았다. (근거: sqlon, moina, vibe-coders, 4회)
- **제출 전에 origin/main 최신 위로 rebase 하고 `git merge-tree --write-tree origin/main HEAD` 로 충돌 없음을 확인한다. main 이 이미 같은 수정을 가지고 있으면 main 쪽을 채택한다.** — 8개 저장소에서 base 충돌로 자동 리베이스가 풀리지 않아 러너가 머지하지 못하고 사람에게 넘어갔다. (근거: DartFly, appstore, hunter, moina, postra, qurio, weekly, 8회)
