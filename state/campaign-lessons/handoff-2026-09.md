## 이 캠페인에서 다른 저장소가 이미 걸린 것 — 시작 전에 확인하고, 끝내기 전에 다시 확인하세요
(캠페인 "handoff-2026-09" 의 리뷰 거절·심사 거절·회귀 10건에서 정제한 규칙. 러너가 자동으로 붙였습니다.)
- **Content-Disposition 의 filename*=UTF-8''… 값을 경로용(PathEscape 류) 이스케이프로 만들지 말고 RFC 5987 attr-char 밖의 문자('=', '@', ':', 공백 등)를 모두 퍼센트 인코딩한다. 제출 전에 '='와 '@'가 섞인 제목으로 헤더를 만들어 표준 라이브러리의 media-type 파서(mime.ParseMediaType 등)에 통과시켜 확인한다.** — 경로 이스케이프가 남기는 '=' '@' ':' 때문에 받는 쪽 표준 파서가 헤더 전체를 거부해 제목이 기본값으로 떨어지며, 이 문제는 재심사를 반복해도 잡히지 않아 사람 개입까지 갔다. (근거: madi, orbit, postra, 3회)
- **일회용 claim 토큰이 포함된 URL 로 요청한 뒤 실패를 로그할 때 HTTP 클라이언트 오류 객체를 그대로 찍지 않는다. 오류 문자열에서 URL 을 제거하거나 origin 만 남기고 기록한다.** — 클라이언트 오류 문자열에는 요청 URL 전체가 들어 있어 연결 실패·타임아웃만으로 토큰이 서버 로그에 새어 나간다. (근거: weekly, 1회)
- **로그인 없는 공개 경로에서 감사 기록을 남길 때 요청 컨텍스트의 사용자(principal)로 주체를 정하지 않는다. 수령 대상 리소스의 실제 소유자로 귀속시킨다.** — 공개 경로에는 principal 이 없어 항상 기본 사용자로 기록되므로 다중 사용자 환경에서 남의 문서 수령이 본인 감사 로그에 남지 않고 문서가 약속한 '수령이 감사된다'와 어긋난다. (근거: postra, 1회)
- **파일명에서 확장자를 붙이거나 떼어낼 때 형식 이름('.'+format)이 아니라 handoff 공유 모듈의 확장자 표를 쓴다.** — markdown 형식의 확장자는 '.md'라 형식 이름으로 잘라내면 'notes.md' 같은 제목이 남는다. (근거: ptium, 1회)
- **window.open 에 noopener 를 주면 반환값이 항상 null 이므로 그 핸들로 새 탭을 navigate 하거나 닫는 설계를 쓰지 않는다. 먼저 URL 을 준비한 뒤 한 번에 열거나, 핸들이 필요하면 noopener 없이 열고 opener 를 직접 끊는다.** — 핸들이 null 이라 빈 about:blank 탭이 닫히지 않고 클릭마다 고아 탭이 남는다. (근거: ptium, 1회)
- **작업 시작 전에 저장소에 CI 워크플로가 있는지 확인하고, 없으면 워크플로를 추가하거나 머지 정책 파일에 CI 없이 머지 허용 플래그를 명시한다.** — CI 검사가 없는 커밋은 처리기가 자동 머지하지 못하고 사람 개입 대기로 막힌다. (근거: sqlon, 1회)
- **제출 직전에 최신 base 위로 리베이스하고 충돌을 직접 해결해 둔다. 가능하면 변경을 새 파일에 두고 자주 바뀌는 파일 수정은 최소화한다.** — 처리기의 자동 리베이스가 풀지 못하는 충돌은 수동 해결 대기로 떨어져 캠페인이 멈춘다. (근거: postra, 1회)
