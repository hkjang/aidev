## 이 캠페인에서 다른 저장소가 이미 걸린 것 — 시작 전에 확인하고, 끝내기 전에 다시 확인하세요
(캠페인 "handoff-2026-09" 의 리뷰 거절·심사 거절·회귀 6건에서 정제한 규칙. 러너가 자동으로 붙였습니다.)
- **Content-Disposition 의 filename*=UTF-8''… 값은 경로·쿼리용 이스케이프 함수(PathEscape/QueryEscape 류)로 만들지 말고, RFC 5987 attr-char(영숫자와 !#$&+-.^_`|~) 밖의 모든 바이트를 퍼센트 인코딩하는 전용 함수로 만든다. 제출 전에 '='·'@'·':'·공백이 든 제목으로 헤더를 만들어 받는 쪽이 쓰는 파서(예: mime.ParseMediaType)로 다시 파싱해 본다.** — 경로용 이스케이프는 '=' '@' ':' 를 남기는데 RFC 5987 파서는 이를 거부해 Content-Disposition 전체가 무효가 되고 받는 쪽 제목이 기본값으로 떨어진다. (근거: madi, orbit, 3회)
- **보내기→받기 왕복을 실제로 돌려 받는 쪽에 도착한 제목을 확인한다. 최소 세 케이스: '='·'@'·공백이 섞인 제목, 헤딩이 없는 마크다운 문서, 한글 제목.** — 헤더 인코딩·파일명 확장자 처리처럼 원인은 달라도 결과는 '제목이 기본값이나 notes.md 로 떨어짐'으로 같으며, 이 결함은 왕복 테스트 없이는 리뷰에서만 잡힌다. (근거: madi, orbit, ptium, 3회)
- **파일명에서 제목을 뽑을 때는 포맷 이름('.'+format)이 아니라 파일명을 만들 때 쓴 같은 확장자 표(예: markdown→.md)에서 확장자를 가져와 제거한다.** — 포맷 이름과 실제 확장자가 다르면(markdown vs .md) 접미사가 안 잘려 문서 제목이 'notes.md' 처럼 남는다. (근거: ptium, 1회)
- **로그인 없는 공개 수령 경로에서 감사 로그를 남길 때는 요청 컨텍스트의 사용자(principal)로 주체를 정하지 말고, 클레임/토큰 레코드에 저장된 소유자 ID를 명시적으로 넘겨서 그 사용자의 감사 로그에 기록한다. 감사 기록 함수가 컨텍스트에서 사용자를 꺼내는 방식이라면 공개 경로에서 어떤 값이 나오는지 소스에서 먼저 확인한다.** — 공개 경로에는 principal 이 없어 항상 기본 사용자로 기록되고, 다중 사용자 환경에서 남의 수령 사건이 본인 감사 로그에 남지 않아 문서가 약속한 '수령이 감사된다'가 거짓이 된다. (근거: postra, 1회)
- **프런트엔드에서 '다른 서비스로 보내기'를 구현할 때 window.open 의 feature 문자열에 'noopener' 를 넣으면 반환값이 항상 null 이므로, 빈 탭을 미리 열어 뒀다가 나중에 navigate/close 하는 패턴을 쓰지 않는다. 최종 URL 이 준비된 뒤 한 번만 열거나, 핸들이 꼭 필요하면 noopener 를 빼고 opened.opener=null 로 처리한다.** — 핸들이 null 이면 빈 탭을 이동시키지도 닫지도 못해 클릭마다 about:blank 고아 탭이 남는다. (근거: ptium, 1회)
