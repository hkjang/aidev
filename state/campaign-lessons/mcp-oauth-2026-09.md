## 이 캠페인에서 다른 저장소가 이미 걸린 것 — 시작 전에 확인하고, 끝내기 전에 다시 확인하세요
(캠페인 "mcp-oauth-2026-09" 의 리뷰 거절·심사 거절·회귀 14건에서 정제한 규칙. 러너가 자동으로 붙였습니다.)
- **토큰 검증 실패를 클라이언트용 합성 문구로 바꾸는 모든 분기에서 원본 검증 오류(서명·발급자·만료·nbf 원문)와 요청 ID 를 로그에 남긴다. 요청 ID 는 미들웨어가 이미 채운 X-Request-ID 를 읽어 인증 함수까지 넘기고, 빈 문자열을 넘기는 로그 호출을 남기지 않는다.** — 클라이언트는 합성 문구만 받아야 하지만 운영자는 원인을 알아야 하는데, 4개 저장소가 같은 자리에서 err 를 버리거나 requestID 에 "" 를 넘겨 거절됐다. (근거: Invenqor, SecCheck, ai-admin, igame, 4회)
- **그 거부 로그 호출을 테스트로 고정한다: 실제 로거를 주입해 출력을 버퍼로 캡처하고, 만료·발급자·서명 각 원인의 원문이 detail 에 들어가는지와 요청 ID 가 찍히는지를 단언한다. 테스트에서 nil 로거로 서버를 만들지 않는다.** — 로그가 실제로 찍혀도 어떤 테스트도 캡처·단언하지 않으면 캠페인 규칙 위반으로 거절되며, nil 로거로 만든 통합 테스트는 로그 검증 자체가 불가능하다. (근거: Vendra, appstore, 2회)
- **새 주체 유형(SSO subject)이나 범위 교집합을 도입하기 전에, 기존 코드에서 '빈 값'을 세션·내부 사용자로 해석하는 분기(TokenID=="", len(scopes)==0 등)를 전부 grep 해서 새 주체를 포함하도록 고친다. 범위 교집합이 비면 빈 슬라이스가 아니라 거부를 돌려준다.** — '값 없음 = 세션 인증(무제한)' 센티널을 새 주체가 물려받아 쓰기 도구 전체가 열리거나 외부 에이전트에게 감춰야 할 본문이 반환되는 권한 상승이 두 저장소에서 발생했다. (근거: seaton, madi, 2회)
- **리소스 식별자와 aud 허용값은 설정값에서만 만든다. 설정이 비어 있을 때 요청의 Host 헤더로 대체하지 말고, 기능을 끄거나 시작 시 오류로 거부한다.** — Host 는 클라이언트가 임의로 보내는 헤더라 같은 realm 의 다른 리소스 서버용 토큰이 대상 검사를 통과한다. (근거: jupiq, 1회)
- **OIDC provider discovery 같은 네트워크 호출을 뮤텍스를 잡은 채 하지 않는다. 요청 컨텍스트 취소를 존중하고(WithoutCancel 금지), 실패한 discovery 도 짧은 TTL 로 음성 캐시한다.** — IdP 가 닿지 않으면 JWT 모양 bearer 를 실은 모든 요청이 뮤텍스 뒤에서 타임아웃까지 직렬화돼 /mcp 전체가 멈춘다. (근거: SecCheck, 1회)
- **설정 일괄 저장 핸들러는 모든 키를 먼저 검증한 뒤에만 저장한다. map 을 순회하며 키마다 즉시 저장하지 않고, 문서가 약속한 '실패 시 아무것도 저장하지 않음'과 실제 동작이 일치하는지 확인한다.** — 순회 순서가 무작위라 같은 요청도 일부만 저장되고 런타임에 반영되지 않은 값이 다음 재기동 때 조용히 적용된다. (근거: sqlon, 1회)
- **기존 설정 정의 목록에 새 항목을 끼워넣을 때 diff 의 삭제(-) 줄을 확인해 기존 항목이 사라지지 않았는지 검사하고, 기존 키의 GET/PUT 가 여전히 동작하는지 테스트한다.** — 항목 삽입 중 기존 정의가 삭제되면 콘솔·API 에서 그 설정이 사라지고 갱신 요청이 unknown setting 으로 거부된다. (근거: sqlon, 1회)
- **고침 커밋을 만들기 전에 이전 심사 사유를 처리기 요약이 아니라 원문(review.json)에서 끝까지 다시 읽고, fix-summary 에 'Not addressed' 항목이 남지 않게 한다.** — 처리기가 잘라 전달한 사유를 손대지 않으면 다음 심사에서 같은 이유로 거절되고 두 번 실패 뒤 사람 개입으로 넘어간다. (근거: SecCheck, 1회)
