## 이 캠페인에서 다른 저장소가 이미 걸린 것 — 시작 전에 확인하고, 끝내기 전에 다시 확인하세요
(캠페인 "mcp-oauth-2026-09" 의 리뷰 거절·심사 거절·회귀 32건에서 정제한 규칙. 러너가 자동으로 붙였습니다.)
- **토큰 검증 오류를 클라이언트용 합성 메시지로 바꾸는 모든 분기에서 원본 오류(서명·발급자·만료·nbf·aud 원문)와 비어 있지 않은 request_id 를 함께 로그에 남긴다. 시작 전에 이 저장소의 request-ID 미들웨어(헤더명·ctx 접근자)를 소스에서 확인하고 거부 경로까지 넘기며, 빈 문자열을 넘기는 로그 호출을 남기지 않는다.** — 운영자가 401 의 원인을 알 수 없고 요청과 연결할 수도 없어 7개 저장소가 같은 자리에서 거절됐다. (근거: Invenqor, SecCheck, ai-admin, git-ctx, igame, orbit, relio, 7회)
- **거부 로그를 고정하는 테스트를 넣는다: 저장소의 기존 로그 캡처 패턴을 기존 테스트에서 찾아 그대로 쓰고, 로거를 nil/discard 로 두지 않으며, 잘못된 토큰 케이스마다 캡처한 출력에 원본 원인과 비어 있지 않은 request_id 가 들어 있음을 단언한다.** — 로그 호출이 있어도 테스트로 고정되지 않으면 심사가 통과시키지 않고, 실제로 request_id 누락이 테스트 없이 통과된 사례가 있다. (근거: Vendra, appstore, git-ctx, orbit, ptium, visitflow, 6회)
- **aud 허용값을 요청의 Host/X-Forwarded-Host 로 만들지 않는다. 시작 전에 resource 설정과 public URL 의 마이그레이션 기본값·UI 허용값이 빈 문자열인지 확인하고, 둘 다 비면 SSO 활성화를 거부하거나 aud 검사를 실패시킨다. '다른 리소스용 aud 토큰 + Host 헤더 조작 → 401' 테스트를 넣는다.** — 기본값 설치에서 같은 IdP 의 다른 서비스용 토큰이 Host 헤더 하나로 통과해 5개 저장소에서 재현됐다. (근거: Momento, jupiq, releasedock, seaton, visitflow, 5회)
- **JWKS/discovery 네트워크 호출은 캐시 뮤텍스 밖에서 한다: 락 안은 맵 조회만, 보유 중인 kid 는 TTL 이 지났거나 refetch 가 진행 중이어도 즉시 돌려주고, 갱신은 락 밖에서 singleflight 로, 실패한 discovery 도 짧게 negative-cache 하며 fetch 에 요청 ctx 를 전달한다. '미지 kid 조회가 hang 인 동안 알려진 kid 조회가 ctx 데드라인 안에 돌아온다' 테스트를 넣는다.** — 미지 kid 하나 또는 닿지 않는 IdP 가 정상 토큰 검증 전체를 최대 10~20초 직렬화하고 ctx 취소도 무시되는 것이 4개 저장소에서 확인됐다. (근거: DartFly, SecCheck, sqlon, releasedock, 5회)
- **새 SSO 주체(토큰 ID 없음)를 추가하기 전에 '외부 에이전트/키 클라이언트'를 구분하는 기존 게이트(TokenID != "" 류)를 전부 grep 해 하나의 술어로 모으고 모두 갱신한다.** — 게이트 하나가 빠지면 SSO 클라이언트가 키 클라이언트에게는 감춰지는 본문을 export/consent 단계 없이 받는다. (근거: madi, 2회)
- **최신 base 에서 브랜치를 만들고, 인증 핸들러·설정 정의·마이그레이션 같은 공용 파일은 기존 줄을 지우거나 옮기지 않고 새 파일/새 줄로 추가만 해서 자동 리베이스가 풀 수 있게 한다.** — 자동 리베이스가 풀지 못하는 충돌은 사람에게 넘어가 캠페인이 멈추고, 끼워넣기 과정에서 기존 설정 항목이 삭제된 사례도 있다. (근거: DartFly, Invenqor, sqlon, 2회)
- **토큰 scope 와 관리자 천장의 교집합이 비면 거부한다. 시작 전에 이 저장소의 /mcp 가 빈 scope 를 '무제한'으로 해석하는지 소스에서 확인하고, 빈 교집합 테스트를 넣는다.** — 빈 슬라이스가 '세션 인증(무제한)'으로 해석돼 쓰기 도구까지 열리는 권한 상승이 됐다. (근거: seaton, 1회)
- **SSO 토큰→계정 매핑은 웹 로그인이 쓰는 것과 같은 조회(subject 만)를 쓰고 username/preferred_username 폴백을 넣지 않는다.** — 복구 계정 같은 영구 계정에 preferred_username 만으로 붙어 관리자 권한을 얻을 수 있다. (근거: git-ctx, 1회)
