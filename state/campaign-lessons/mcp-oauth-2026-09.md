## 이 캠페인에서 다른 저장소가 이미 걸린 것 — 시작 전에 확인하고, 끝내기 전에 다시 확인하세요
(캠페인 "mcp-oauth-2026-09" 의 리뷰 거절·심사 거절·회귀 38건에서 정제한 규칙. 러너가 자동으로 붙였습니다.)
- **aud 검사에 쓰는 리소스 식별자는 명시적 설정값에서만 만든다. 전용 resource 설정과 공개 URL 설정이 모두 비었을 때 Host/X-Forwarded-Host/X-Forwarded-Proto 로 폴백하지 말고 SSO 를 비활성으로 두고 사유를 표시한다. 시작 전 소스에서 두 설정의 기본값이 빈 문자열인지, 설정 저장/env 경로가 빈 값을 막는지, 프록시 헤더를 신뢰검증 없이 읽는지 확인한다.** — 같은 IdP realm 의 다른 리소스 서버용 토큰을 가진 사용자가 Host 헤더만 바꿔 교차 리소스 경계 검사를 통과한다. (근거: Momento, appstore, jupiq, releasedock, seaton, vibe-coders, visitflow, 7회)
- **JWKS/discovery 등 네트워크 호출을 캐시 뮤텍스를 잡은 채 하지 않는다. 락 안에서는 캐시 조회/삽입만 하고, 보유 중인 kid 는 TTL 이 지나도 in-flight fetch 뒤에 줄세우지 말고 즉시 반환하며, 실패한 discovery 도 짧게 캐시하고, 대기 경로는 요청 ctx 취소가 먹는 형태로 만든다.** — 모르는 kid 하나나 느린 IdP 때문에 정상 토큰 검증까지 전부 직렬화되고 뮤텍스 대기 중에는 클라이언트 데드라인이 무시된다. (근거: DartFly, SecCheck, sqlon, releasedock, 5회)
- **토큰 검증 오류를 클라이언트용 합성 메시지로 바꾸는 모든 분기에서 원본 오류(서명·발급자·만료·nbf·aud·claims 중 무엇인지)를 로그에 남긴다. 401 을 실제로 쓰는 최종 응답 함수가 로그를 남기는지 먼저 확인하고, 남기지 않으면 원인을 꺼내는 자리에서 직접 로그한다.** — 클라이언트는 합성 문구만 받고 운영자는 원인을 알 수 없어 관리자 문서가 약속한 로그 확인이 불가능해진다. (근거: Invenqor, ai-admin, igame, appstore, relio, 5회)
- **인증 거부·경고 로그에 요청 ID 를 반드시 포함한다. 저장소에 이미 있는 요청 ID 출처(X-Request-ID 헤더, ctx 헬퍼, chi middleware.GetReqID, 응답 헤더)를 찾아 인증 경로 끝까지 전달하고, ID 인자에 빈 문자열을 넘기는 호출을 하나도 남기지 않는다.** — 요청 ID 없는 거부 로그는 실제 요청과 연결할 수 없고 미들웨어가 이미 값을 만들어 두고 있다. (근거: SecCheck, git-ctx, orbit, relio, visitflow, 5회)
- **거부 로그를 고정하는 테스트를 추가한다. 저장소의 기존 로그 캡처 패턴으로 출력을 잡아 원본 원인 문자열과 비어 있지 않은 request_id 가 포함됨을 단언하고, 테스트 헬퍼가 nil 로거나 Discard 핸들러를 쓰면 그 헬퍼부터 고친다.** — 로그가 실제로 찍혀도 테스트가 없으면 다음 변경에서 조용히 사라져 같은 자리가 반복 재발했다. (근거: Vendra, ptium, appstore, orbit, git-ctx, 5회)
- **SSO 주체가 기존 인증 경로보다 넓은 권한을 갖지 않게 한다. 기존 인증 종류를 구분하는 모든 분기를 전수 조사해 새 주체를 반영하고, 권한/범위 교집합이 비면 무제한이 아니라 거부로 처리하며, subject→계정 매핑은 기존 로그인과 동일한 조회 기준만 쓴다(username 폴백 금지).** — 한 군데만 고치거나 빈 범위를 무제한으로 해석해 문서와 정반대의 권한 상승·원문 노출이 생겼다. (근거: madi, seaton, git-ctx, 4회)
- **재수정 라운드는 처리기 요약이 아니라 직전 심사 원문 전체를 다시 읽고 항목별로 코드에서 확인하며, 손대지 않은 항목을 넘기지 않는다. 제출 전 빌드와 테스트를 실제로 실행하고 base 에 리베이스해 충돌을 미리 해소한다.** — 잘려 전달된 이전 지적이 방치돼 2회 실패 후 사람 개입으로 넘어갔고 빌드 실패·미해결 충돌로 심사가 진행되지 못했다. (근거: SecCheck, madi, sqlon, git-ctx, visitflow, DartFly, Invenqor, 7회)
- **설정 정의나 문서에 손댈 때 기존 항목과 계약을 깨지 않는다. 새 설정 삽입 후 diff 에서 삭제된 기존 항목이 없는지 확인하고, 설정 저장 API 는 문서 서술대로 전체 검증 후 저장하도록 해 부분 저장 경로를 만들지 않는다.** — 기능과 무관한 설정 항목 소실과 문서-구현 불일치 자체가 거절 사유가 됐다. (근거: sqlon, 2회)
