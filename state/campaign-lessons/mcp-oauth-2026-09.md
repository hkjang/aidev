## 이 캠페인에서 다른 저장소가 이미 걸린 것 — 시작 전에 확인하고, 끝내기 전에 다시 확인하세요
(캠페인 "mcp-oauth-2026-09" 의 리뷰 거절·심사 거절·회귀 12건에서 정제한 규칙. 러너가 자동으로 붙였습니다.)
- **토큰 검증 오류(서명·발급자·만료·nbf·audience)를 클라이언트용 합성 메시지로 바꾸는 분기를 쓰기 전에, 이 저장소의 요청 ID 를 미들웨어가 어디에 채우고 핸들러가 어떻게 읽는지 소스에서 찾아, 그 분기에서 원문 err 와 요청 ID 를 반드시 운영 로그로 남긴다(401 을 쓰는 공용 헬퍼가 로그를 남기지 않는지도 확인).** — 다섯 저장소에서 운영자가 서명/발급자/만료 중 무엇이 실패했는지 알 수 없거나 요청 ID 가 빈 문자열로 남아 리뷰가 거절됐다. (근거: Invenqor, ai-admin, igame, SecCheck, 4회)
- **토큰 거부 로그는 테스트에서 실제 로그 출력을 캡처해 원문 err 와 요청 ID 가 들어 있음을 단언한다. 이 저장소의 기존 테스트에서 로그 캡처 패턴(기본 로거 교체, 버퍼 핸들러 등)을 먼저 찾아 그대로 쓰고, 테스트 생성자에 nil logger 를 넘기지 않는다.** — 로그 호출은 있었지만 어떤 테스트도 고정하지 않아 두 저장소에서 거절됐고, nil logger 로 만든 테스트는 로그 누락을 잡지 못한다. (근거: Vendra, appstore, 2회)
- **SSO 토큰이라는 새 주체를 추가할 때, 기존 코드가 '토큰 ID 유무', 'bearer 여부', '외부 에이전트 여부' 로 판단하는 모든 분기를 grep 으로 전부 나열하고 하나씩 새 주체에도 맞게 갱신한다. 한 곳만 고치고 나머지를 남기면 안 된다.** — 주체 판별 분기 하나만 고치고 같은 파일의 다른 게이트를 빠뜨려 SSO 클라이언트에 문서 원문이 노출되는 권한 상승이 생겼다. (근거: madi, 1회)
- **scope 교집합·축소를 구현하기 전에 이 저장소가 '빈 scope' 를 무엇으로 해석하는지(무제한인지, 거부인지) 소스에서 확인하고, 관리자 천장과 토큰 scope 의 교집합이 비면 빈 목록을 돌려주지 말고 명시적으로 거부한다. 교집합이 비는 경우를 테스트로 고정한다.** — 빈 scope 를 '세션 인증(무제한)' 으로 읽는 저장소에서 빈 교집합이 쓰기 도구까지 전부 여는 정반대의 권한 상승이 됐다. (근거: seaton, 1회)
- **OIDC discovery 나 JWKS 조회 같은 네트워크 호출은 공유 뮤텍스를 쥔 채 하지 않는다(잠금은 캐시 읽기/쓰기에만). 실패한 discovery 도 짧은 TTL 로 캐시(negative cache)하고, 요청 컨텍스트 취소를 끊지 않는다.** — IdP 가 닿지 않을 때 JWT 모양 bearer 를 실은 모든 /mcp 요청이 잠금 뒤에 직렬화돼 서비스 전체가 막힌다. (근거: SecCheck, 1회)
- **설정 저장 API 에 검증을 넣을 때는 모든 키를 먼저 검증하고 하나라도 실패하면 아무것도 저장하지 않는 순서로 구현하며, 순회 중 즉시 저장하지 않는다. OpenAPI/문서에 적은 원자성 약속과 실제 핸들러 동작이 일치하는지 리뷰 전에 대조한다.** — map 순회 중 키마다 즉시 저장하고 뒤늦게 400 을 돌려줘 무작위 순서로 일부만 저장되는 경로가 새로 생겼고 문서는 반대로 기술했다. (근거: sqlon, 1회)
- **기존 설정 정의·메타데이터 목록에 새 항목을 끼워넣을 때는 diff 를 보고 삭제(-)된 기존 항목이 없는지 확인한다. 변경은 추가만이어야 하고, 기존 키가 여전히 API/콘솔에서 조회·수정되는지 테스트로 확인한다.** — MCP SSO 항목을 넣으면서 기존 캐시 TTL 설정 정의가 사라져 콘솔과 API 에서 그 설정을 바꿀 수 없게 됐다. (근거: sqlon, 1회)
- **시작 전에 최신 base 위로 브랜치를 맞추고, 이전 심사 결과가 있으면 처리기가 요약한 것이 아니라 review.json 원문을 끝까지 읽어 사유 목록을 모두 나열한 뒤 각각 '고침' 또는 '이유와 함께 보류' 로 처리한다. 잘린 사유를 'Not addressed' 로 남긴 채 재제출하지 않는다.** — 처리기에서 잘려 전달된 심사 사유가 그대로 미처리로 남아 재거절됐고, base 충돌은 자동 리베이스로 풀리지 않아 사람 개입이 필요했다. (근거: SecCheck, Invenqor, 2회)
