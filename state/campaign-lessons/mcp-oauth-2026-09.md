## 이 캠페인에서 다른 저장소가 이미 걸린 것 — 시작 전에 확인하고, 끝내기 전에 다시 확인하세요
(캠페인 "mcp-oauth-2026-09" 의 리뷰 거절·심사 거절·회귀 21건에서 정제한 규칙. 러너가 자동으로 붙였습니다.)
- **토큰 거부를 클라이언트용 합성 메시지로 바꾸는 분기는 원본 검증 오류(서명·발급자·만료·nbf·aud 원문)와 비어 있지 않은 request_id 를 함께 로그에 남긴다. 구현 전에 미들웨어가 request ID 를 어디에 넣는지 소스에서 찾아 인증 함수까지 전달하고, 빈 문자열을 넘기는 호출을 남기지 않는다.** — err 를 버리거나 request_id 를 비워 운영자가 무엇이 실패했는지 알 수 없게 된 것이 가장 많이 거절된 사유다. (근거: Invenqor, SecCheck, ai-admin, igame, relio, 5회)
- **그 거부 로그 호출을 테스트로 고정한다. 저장소에 이미 있는 로그 캡처 패턴을 찾아 그대로 쓰고, 원문 cause 와 비어 있지 않은 request_id 가 로그에 들어 있음을 단언한다. nil/Discard 로거로 테스트하지 않는다.** — 로그가 실제로 찍혀도 이를 고정하는 테스트가 없으면 거절된다. (근거: Vendra, appstore, ptium, visitflow, 4회)
- **aud 검사 허용값(리소스 식별자)을 요청의 Host / X-Forwarded-Host 로 만들지 않는다. 설정된 리소스 URL 이 비어 있어도 허용 목록은 설정값·base_url 같은 서버측 값에서만 만들고, 구현 전에 서버가 Host 를 검증하는지와 base_url 기본값이 비어 있는지 소스에서 확인한다.** — 같은 realm 의 다른 리소스 서버용 토큰이 Host 헤더만 바꿔 대상 검사를 통과하는 권한 상승이 된다. (근거: jupiq, seaton, visitflow, 3회)
- **OIDC discovery·JWKS fetch 같은 네트워크 호출을 뮤텍스를 잡은 채 하지 않는다. 캐시 조회와 원격 갱신을 분리하고, 원격 호출은 요청 ctx 를 존중하며, 실패한 discovery 도 잠시 캐시한다.** — IdP 가 느리면 정상 토큰 검증까지 전부 뮤텍스 뒤에 직렬화되고 ctx 타임아웃이 무시된다. (근거: DartFly, SecCheck, 2회)
- **시작 전에 base 를 최신으로 맞추고, 공유 진입점(인증 함수·설정 레지스트리) 수정은 기존 줄을 바꾸지 않고 덧붙이는 방식으로 국소화한다. 리뷰 사유는 잘린 것 없이 전부 읽고 fix-summary 에 'Not addressed' 를 남기지 않는다.** — 자동 리베이스로 풀리지 않는 충돌과 잘려서 전달된 심사 사유 누락으로 사람 손으로 넘어간 저장소가 셋이다. (근거: DartFly, Invenqor, SecCheck, 3회)
- **scope 교집합을 돌려주기 전에 /mcp 가 빈 scope 목록을 어떻게 해석하는지 소스에서 확인한다. 빈 목록이 '무제한'이면 교집합이 비었을 때 빈 슬라이스가 아니라 거부를 돌려준다.** — 천장과 겹치지 않는 토큰이 오히려 쓰기 도구까지 전부 여는 권한 상승이 됐다. (근거: seaton, 1회)
- **새 주체 종류(OAuth subject)를 추가할 때는 기존에 주체 종류를 구분하는 모든 분기(TokenID != "" 같은 게이트)를 grep 해서 빠짐없이 갱신한다.** — 한 곳만 고치고 다른 게이트를 빠뜨려 SSO 클라이언트에 감춰야 할 본문이 그대로 반환됐다. (근거: madi, 1회)
- **설정 레지스트리·설정 저장 핸들러를 건드리면 diff 에서 기존 설정 항목이 삭제되지 않았는지 확인하고, 모든 값을 먼저 검증한 뒤 저장해 부분 저장이 생기지 않게 하며 문서가 약속한 동작과 일치시킨다.** — MCP 항목을 끼워넣으며 기존 설정을 지웠고, 검증 도입으로 문서와 반대인 부분 저장 경로가 생겼다. (근거: sqlon, 2회)
