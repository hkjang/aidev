Enforce the upstream host allow list on inference calls. `PII_MASKER_ALLOW_HOSTS` was documented in the README and parsed by `config.Load` through `normalizeAllowHosts`, but nothing ever checked it — `UpstageConfig.AllowHosts` was referenced only by test fixtures, so the setting was a complete no-op. Worse, `httpClient()` followed redirects under Go's default policy without limit, so an inference endpoint answering `307`/`308` made Go replay the multipart body via `GetBody` and ship the uploaded document — the very file handed over because it contains personal information — to an arbitrary host, and even on `302`-style redirects the `x-api-key` credential header tagged along because it is not one of the headers Go strips across domains. New `Client.checkHostAllowed`/`checkURLAllowed`/`hostAllowed` now validate the target host (1) in `performParseRequest` before the multipart body is built, (2) in `TestConnection` before the request goes out, and (3) in `CheckRedirect` on every redirect hop, which is additionally capped at 5 hops. An empty list falls back to the host of the configured base URL so it can never mean "anything goes", and entries match either host-only (`api.upstage.ai`) or host-with-port (`127.0.0.1:8080`), ignoring case and surrounding whitespace. A blocked target raises a new `blockedHostError` that `classifyRequestError` maps to an `upstream_host_not_allowed` `CallError`, so `/v1/mask` returns `502` with that code and `/v1/test-connection` returns `ok:false`. Adds 5 `internal/upstage` tests (a 9-case host matching table, the base-URL fallback for an empty list, no request reaching a blocked host, a redirect to a disallowed host being refused, and a redirect between allowed hosts still being followed) and 1 integration test asserting `/v1/mask` answers `502` without the upstream ever being contacted, and documents in the README what the variable actually enforces.
