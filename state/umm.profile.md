  - `npm --prefix web run typecheck|lint|build|verify:pwa|test:offline-queue|format`. tsconfig.app.json include=["src"] → **시험 파일도 typecheck 대상**. lint = `oxlint src && prettier --check src`.
  - `make test-web`(Makefile:28-36): offline-queue → audit(high) → typecheck → lint → check-i18n → test → build → verify:pwa. **설치는 하지 않는다.** audit 은 네트워크 필요.
  - `make test-go`(Makefile:7-9): **여전히 `go vet ./...` + `go test ./...` 두 줄.** CI 의 Go 절(`-p 1`·race·govulncheck·임베딩 리포트)과 다르다.
  - `POSTGRES_DSN=<격리 DSN> go test -p 1 ./... -count=1` 가 전체 Go 검증(수 분, store 가 ~26-45s). DSN 없으면 통합 SKIP — 통과로 포장 금지.

  - `node web/scripts/check-i18n.mjs`(1060키). `make build`, `docker build --build-arg VERSION=<VERSION> .` 가 릴리즈 경로. `npm --prefix web run e2e` 는 실제 서버·번들·DB·브라우저 필요.

- 검증 함정:
  - 새 worktree 는 미설치. 미설치 상태의 exit 127 / `not found` 는 저장소 결함이 아니다.
  - **공식 golang 이미지는 `GOTOOLCHAIN=local` 이라 `go.mod` 의 `toolchain` 줄을 무시한다** — go.mod 만 올리면 govulncheck 은 초록이 되고 릴리즈 이미지는 옛 표준 라이브러리를 담는다(2026-10-16 에 실제로 일어남). 릴리즈 변경은 이미지에서 `go version /app/umm` 으로 끝까지 확인.
  - 기존 `src` 파일의 oxlint 경고 약 50건은 상시 남는다 — 새 파일을 가리키는 경고만 보라.
  - `govulncheck` 은 `go run ...@latest` 라 네트워크가 필요하고 커밋이 아니라 취약점 DB 가 판정을 바꾼다.
  - `setLocale` 은 모듈 전역 상태다. i18n 시험은 `afterEach` 로 'ko' 로 되돌릴 것. en.ts 는 한글 키만 필요하다.
  - `oxlint` 의 `toSorted` 권고와 tsconfig lib 의 TS2550 이 충돌한다 — `new Set(...)` 비교로 회피.
  - Prettier 검사는 **web 디렉터리에서** `npm exec -- prettier --check <상대경로>` 로 돌릴 것(루트에서 `--prefix web exec` 는 상대경로를 못 찾아 exit 2).
  - CLI `--help`/`--list` 통과는 E2E 통과가 아니다. 소스 문자열 grep 은 동작의 증거가 아니다(운영자 규칙 5번).
  - 저장소 CLAUDE.md/AGENTS.md 와 독립 ROADMAP/TODO 파일은 없다. 샌드박스가 `./scripts/*.sh` 직접 실행을 막을 수 있다(이번 정찰에서 걸렸다).
