# Ptium 1.69.23

## 표의 행이 반복 구역 안에 있으면, 표가 통째로 사라졌습니다

워드에서 표를 서식으로 만들면, 늘어나는 행은 대개 **반복 섹션 콘텐츠
컨트롤** 안에 들어갑니다. 머리글 한 줄만 표에 직접 있고, 사람이 채워 넣는
행은 전부 `w:sdt` 가 감싸고 있습니다. 칸 하나만 입력란으로 만든 양식도
마찬가지여서, 그 칸의 문단은 칸이 아니라 컨트롤이 들고 있습니다.

리더는 표 바로 아래의 행, 행 바로 아래의 칸, 칸 바로 아래의 문단만
읽었습니다. 그래서 감싸인 것은 보이지 않았습니다.

```
표:     항목 | 값
        └ 반복 구역 ┐ 매출 | 120억
                    └ 영업이익 | 18억
이전:   (슬라이드에 표 없음 — 머리글 한 줄만 남아 표로 치지 않음)
지금:   항목 | 값 / 매출 | 120억 / 영업이익 | 18억
```

칸 안의 컨트롤은 더 조용했습니다. 표는 그려지되 그 칸만 **빈칸**으로
나왔습니다 — 금액을 적어 낸 사람에게는 자기 숫자가 빠진 표가 돌아갔습니다.

1.69.21 에서 본문 블록에 대해 열어 준 것과 같은 방식을, 이제 표의 세 층
모두에 적용합니다. 행·칸·문단을 찾을 때 `w:sdt`·`w:sdtContent`·`w:customXml`
을 열고 들어가며, 겹쳐 있어도 따라갑니다. 컨트롤 이름이나 선택 항목이 든
`w:sdtPr` 은 문단이 아니므로 전과 같이 걸리지 않고, 칸 안에 들어 있는 **다른
표**도 전과 같이 바깥 표의 칸으로 읽지 않습니다. 감싸인 것이 없는 문서는
읽히는 결과가 한 글자도 달라지지 않습니다.

## 지키는 장치

`internal/docs/wordtables_test.go` 가 반복 구역이 행을 들고 있는 표, 칸 안의
콘텐츠 컨트롤, 표 중간의 감싸인 행이 제자리에 오는지, 옛 파일이 쓰는
`w:customXml`, 두 겹으로 감싸인 칸, 감싸인 칸 안의 링크, 그리고 한 칸의 두
문단이 여전히 한 칸인지를 봅니다. 칸 안에 든 표가 바깥 표로 새어 나오지
않는지는 따로 확인합니다.
