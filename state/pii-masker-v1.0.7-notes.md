Reject image uploads that declare an oversized resolution. Upload size limits capped the bytes on the wire, but nothing limited the pixel count after decoding, so a few-hundred-KB PNG whose header declared 40000x40000 made `image.Decode` allocate more than 6GB — a memory exhaustion path reachable through both `masking.MaskImageFile` and `upstage.prepareUpstreamAttachment`. New `document.ValidateImageDimensions`/`DecodeImage` helpers read only the header via `image.DecodeConfig` and reject anything above 50 million pixels (larger than a 600dpi A4 scan); `service.validateAttachment` calls the check for image MIME types so both the synchronous and asynchronous paths fail with a 400 before any pixel buffer is allocated or a job is written to disk, and the two decode sites go through the same guard for defense in depth. Adds 4 unit tests and 2 integration tests (`/v1/mask` error message, `/v1/jobs` returning 400 with no job created) built on a hand-crafted tiny decompression-bomb PNG.
