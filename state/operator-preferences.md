## 운영자(hkjang)가 되풀이해 말한 것 — 이대로 한다 (반려·중지 사유·지시 20건에서 정제, 러너가 자동으로 붙임)
- **수정의 증거는 프로덕션 배선을 실제로 통과하는 테스트와 실제 런타임 타입(진짜 asyncio.Task 등)으로 제시하고, 손으로 만든 의존성 주입·대역·소스 문자열 검사로 대체하지 말 것.** — 수동 주입과 대역은 배선 결함과 실제 취소 동작을 구조적으로 못 본다.
- **감사·로그 이벤트의 details 에는 AgentID 같은 식별자만 넘기고 스크럽 이전 원문 값을 넣지 말 것.** — 값으로 받은 record 의 원문이 audit_events.details 에 저장되고 다시 내보내진다.
- **스캔·검사 범위를 넓히기 전에 그 필드가 다른 필드로 복사되는 경로를 먼저 확인할 것.** — 복사되는 두 필드를 각각 스캔하면 같은 값을 두 번 처리한다.
- **정책 규칙의 행위자는 task.OwnerID 로 잡고 agent.OwnerID 는 자격증명 조회(SCMTokenFor)에만 쓸 것.** — 이 플랫폼의 정책 지점은 모두 작업 소유자를 쓰므로 두 값을 분리해야 한다.
- **계약이 다른 숫자 파서·분류기·렌더러를 통합하거나 한쪽만 넓히지 말고, 고칠 때는 두 경로가 같은 값을 같은 숫자로 읽는지 end-to-end 로 검증할 것.** — 각 파서가 서로 다른 호출자 계약을 지키고 있어 한쪽만 넓히면 다른 경로의 출력이 망가진다.
- **가이드 문서에 API 메서드·HTTP 동사·시그니처를 쓸 때는 소스에서 직접 확인할 것.** — 확인 없이 쓰면 GET/POST 가 어긋난 문서가 남는다.
- **새 가이드를 추가하면 옛 통합 가이드는 함께 정리해 정본을 하나로 유지할 것.** — 둘을 같이 두면 서로 다른 정본이 생긴다.
- **스크립트가 전역·사용자 설정 파일을 수정할 때는 백업 없이 덮어쓰지 말 것.** — 캡처 스크립트가 전역 설정을 백업 없이 덮어써 반려됐다.
- **백그라운드 작업의 종료·shutdown 여부는 명시적 플래그(_shutting_down)로 판정하고 task 상태나 cancelled()/exception() 추론에 의존하지 말 것.** — CancelledError 를 삼키고 정상 반환하는 루프에서 정상 종료마다 오탐 ERROR 가 난다.
- **해당 언어의 빌드·테스트 도구체인이 없어 검증을 실행할 수 없으면 PR 을 올리지 말고 멈춘 뒤 환경 부족을 보고할 것.** — 검증 없이 머지된 변경이 릴리즈를 반복해 깨뜨려 롤백·강등으로 이어졌다.
