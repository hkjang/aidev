# bbmcp 프로필 (2026-10-08)
- 목적: Bitbucket Server 6.9.1 앞의 MCP 게이트웨이로, AI 도구 호출을 요청자 본인의 유효 권한·정책·승인 범위로 제한한다.
- 스택: Go 모듈 github.com/hkjang/bbmcp(go.mod 1.24), PostgreSQL/pgx v5, Keycloak OIDC, chi; web은 React 18·TypeScript·Vite 5·Mantine 7. Node 22로 빌드하는 단일 도커 이미지.
- 구조:
  - cmd/: 실행 진입점. internal/api/: HTTP 서버, 관리/개인 API, OAuth 메타데이터·등록 점검.
  - internal/mcp/: Streamable HTTP 및 JSON-RPC, initialize 세션 헤더, 도구 응답 상한/UTF-8 안전 절단.
  - internal/tools/: 33종 도구·레지스트리·Executor; 정책→사용자 권한→브랜치 제한→승인→실행.
  - internal/identity/: 최초 사용자명 검색과 sub↔Bitbucket ID 매핑, 비활성화·매핑 실패 집계.
  - internal/permission/, internal/policy/: REST/플러그인 권한 해석, 캐시, 프로젝트·저장소·브랜치 정책.
  - internal/approval/, internal/audit/: 인자 해시·PR 버전·일회성 승인, 감사 기록.
  - internal/auth/, internal/apikey/, internal/crypto/: OIDC·로컬 로그인·세션·개인 키·암호화.
  - internal/settings/, internal/config/, internal/database/migrations/: DB 설정·기동 환경변수·자동 마이그레이션.
  - internal/bitbucket/, internal/aiproxy/: 업스트림 클라이언트와 AI 스트리밍 프록시.
  - web/: 프런트 소스; internal/webui/dist에 임베드. docs/: 정적 사이트/관리자·사용자 가이드.
- 빌드·테스트:
  - CI: go build ./...; go vet ./...; TEST_DATABASE_URL='<전용 DSN>' go test ./... -count=1 -p 1.
  - 정찰 실행: TEST_DATABASE_URL='postgres://bbmcp:bbmcp@127.0.0.1:15532/bbmcp_test?sslmode=disable' go test ./... -count=1 -p 1 -v → PASS 123, SKIP 0, FAIL 0, 9패키지 통과.
  - 현재 bbmcp-test-pg 컨테이너가 포트 15532에서 기동 중. 로컬 Go 1.26.7, CI Go 1.24이므로 도구체인 차이에 유의.
  - 웹: cd web && npm ci --no-audit --no-fund && npm run check && npm run build. 이번 정찰에서는 미실행.
  - .github/workflows/ci.yml: go(postgres:16-alpine), web(Node22), image(도커 빌드·/healthz·/api/config 점검). 이미지 잡은 비교적 오래 걸린다.
- 관례: 한국어 Conventional Commits; 영문 주석·식별자, 사용자 메시지는 한국어. README와 docs가 사용자 문서이며 별도 CLAUDE.md/AGENTS.md/로드맵은 저장소 검색에서 발견하지 못했다. 확인한 코드·docs 범위의 TODO/FIXME 없음.
- 설정: 필수 환경변수 4개 DATABASE_URL/BOOTSTRAP_ADMIN/BOOTSTRAP_ADMIN_PASSWORD/ENCRYPTION_KEY. config.Load는 POSTGRES_DSN 별칭과 BBMCP_ADDR 선택값도 지원. 나머지는 DB settings이며 Store 캐시 TTL 30초.
- 위험 구역:
  - internal/auth/*, internal/api/oauth.go: 최근 v0.2.6~v0.2.9가 Keycloak 등록·redirect URI·10 호환 수정. 로그인 회귀 위험이 커 범위를 좁힌다.
  - migrations: 0001 기본 스키마, 0002 사용자 설정, 0003 매핑 오류 sub별 중복 집계. 기존 데이터에 영향, 테스트 추가 때문에 변경하지 않는다.
  - permission/resolver.go, approval/approval.go: fail-closed·PR stale·승인 단일 소비 보존. auth/users.go의 개명 처리는 별도 재현 필요(코드상 sub UNIQUE 충돌 가능성, 런타임 미확인).
  - Dockerfile/.github/workflows: alpine rollup 누락 전력; 변경 시 이미지 잡까지 확인.
- 자주 깨지는 곳: Keycloak OAuth 동적 등록/redirect URI/구버전 호환, alpine 웹 빌드. 과거 정찰 과제서 미작성 실패가 있어 초안부터 남긴다.
- 검증 함정:
  - DB 통합 테스트는 TEST_DATABASE_URL 없으면 t.Skip. 성공 종료만 보지 말고 SKIP 수를 확인한다.
  - 패키지들이 공유 테이블을 TRUNCATE한다. -p 1 필수, t.Parallel/동시 패키지 실행 금지, 실제 운영 DB 금지.
  - tools/integration_test.go:newFixture와 api/mcpoauth_e2e_test.go:newGateway가 실제 프로덕션 타입을 배선하는 기존 하네스다. 새 목을 주입하지 말고 이 하네스를 재사용.
  - identity는 패키지 자체 테스트가 없어도 tools/TestIdentityMappingBindsExactUsernameAndIsStable이 최초 매핑·재사용·재바인딩 거부를 이미 검증한다. 패키지 no test files를 기능 미검증과 혼동하지 않는다.
  - Mapper 실패는 auth.identityFor에서 삼켜진다. 권한 필요 도구는 HTTP 200 + result.isError + structuredContent.code=IDENTITY_UNMAPPED; bitbucket_me는 미매핑 상태에서도 성공한다.
  - mcp/identity/approval/audit/aiproxy/settings/config는 자체 테스트 파일이 없고 일부만 API/tools에서 간접 검증한다. Resolver 직접 테스트는 없으며 기존 tools fixture는 캐시 TTL=0이다.
