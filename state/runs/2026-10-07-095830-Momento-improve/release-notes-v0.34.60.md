# Momento v0.34.60 — 보존 정책 다섯 칸이 저장을 누르기 전에 허용 범위를 말합니다

콘솔 **관리 → 보존 정책**에서 보존기간을 설정하는 관리자를 위한 개선입니다. 지난 릴리스(v0.34.59)는 **저장이 실패한 뒤에 뜨는 문장**을 한국어로 고쳤고, 이번에는 같은 폼에서 **그 실패 자체를 저장 전에 알립니다.** v0.34.58이 「망 대역 추가」의 CIDR 칸에 한 것과 같은 걸음입니다.

## 범위를 알려면 저장을 눌러 400을 받아야 했습니다

허용 범위의 정본은 서버의 `validateRetention`(`internal/httpapi/advanced_analytics.go:80-97`)입니다. 그런데 같은 숫자가 세 곳에 따로 적혀 있었습니다 — 서버의 Go, `adminErrors.ts`의 `INVALID_RETENTION` 안내 다섯 문장, `AdminPage.tsx`의 helperText 문자열.

그 결과 **두 칸은 helperText가 범위를 아예 말하지 않았습니다.** 「Session 요약 (개월)」은 요약의 뜻만, 「Aggregation (개월)」은 무기한의 뜻만 적었습니다. 읽는 사람은 저장을 눌러 400을 받은 뒤에야 1~120을 읽었습니다.

이제 다섯 칸이 모두 자기 범위를 칸 아래에 먼저 적습니다.

| 칸 | 칸 아래에 늘 보이는 안내 |
|---|---|
| Raw Event (개월) | `1~120개월` |
| Session 요약 (개월) | `1~120개월 · Raw Event 삭제 후에도 유지되는 요약` |
| Aggregation (개월) | `1~1200개월 · 비워 두면 무기한. …` |
| Realtime (시간) | `1~168시간 · 현재 적용되지 않습니다. …` |
| Debugger / Dead Letter (일) | `1~90일` |

기존 설명 문장은 **그대로 두고 범위만 앞에 붙였습니다.** 「Realtime (시간)」의 '현재 적용되지 않습니다'와 「Aggregation (개월)」의 사람 단위 기록 경고는 바뀌지 않습니다.

## 안내와 저장 실패 문장이 같은 상수에서 나옵니다

새 순수 모듈 `web/src/pages/retentionRule.ts`가 범위·라벨·단위를 **화면에서 한 번만** 적습니다. `cidrRule.ts`·`passwordRule.ts`와 같은 자리의 같은 모양입니다.

helperText, 저장 실패 Alert(`describeRetentionError`), 칸의 label이 모두 이 상수를 읽으므로 세 문장이 갈라질 수 없습니다. 범위를 벗어난 값을 넣으면 그 칸 아래가 저장 실패 Alert과 **글자 그대로 같은 문장**이 됩니다.

```
「Raw Event (개월)」 은 1개월에서 120개월 사이로 적으세요.
```

라벨도 모듈이 정하므로, 안내가 「」로 부르는 이름과 화면에 찍히는 이름이 어긋나 Alert이 화면에 없는 칸을 가리키는 일이 구조적으로 생기지 않습니다.

## 비울 수 없는 칸을 지우면 0이 저장되던 것을 막습니다

「Aggregation (개월)」을 뺀 네 칸은 비울 수 없습니다. 그런데 칸을 지우면 `Number("")`가 0을 만들어 입력값이 `0`으로 되돌아오고 그대로 저장을 눌러 서버의 400을 받았습니다. 이제 저장 전에 그 칸이 범위를 말합니다.

정수 판정이 범위 판정보다 앞에 있습니다. 서버의 다섯 필드는 `int`·`*int`라 `1.5`는 범위에 닿기도 전에 JSON 디코딩에서 떨어지는데, `1.5`는 1~120 안이라 범위 판정으로는 잡히지 않습니다.

## 입력을 막지는 않습니다

**서버가 범위의 정본이고 화면은 그 거울입니다.** 그래서 글자 입력을 가로막거나 「보존 정책 저장」 버튼을 닫지 않습니다. 경계값 `120`과 빈 「Aggregation (개월)」은 그대로 실려 가며, 전송되는 요청 본문은 바뀌지 않습니다(`{"raw_event_months":120,…,"aggregation_months":null,…}`). 화면이 서버보다 좁아지면 서버가 받아 줄 값을 넣을 방법이 없어집니다.

## SDK 테스트가 상위 경로의 Node에 가려지지 않습니다

`sdk/package.json`의 `test`가 맨 `node`였습니다. npm은 lifecycle 스크립트의 PATH에 상위 디렉터리의 `node_modules/.bin`을 모두 앞에 붙이므로, 상위 경로에 node 패키지가 깔린 환경에서는 `npm test`의 `node`가 npm 자신을 돌리는 Node가 아닌 그쪽으로 해석됩니다. 그러면 `../src/index.ts`를 확장자까지 적어 import하는 SDK 테스트가 `ERR_UNKNOWN_FILE_EXTENSION ".ts"`로 떨어집니다.

v0.34.53이 콘솔 쪽을 같은 방식으로 고쳤는데 SDK는 남아 있었습니다. 이제 `${npm_node_execpath:-node}`로 npm이 쓰는 인터프리터를 그대로 씁니다 — npm 없이 셸에서 바로 돌릴 때는 `node`로 되돌아갑니다. 같은 모양의 회귀 가드를 `sdk/test/testCommand.test.mjs`에 두었습니다. 게이트를 느슨하게 한 것은 없고 같은 테스트가 같은 수로 돕니다.

## 확인

- 콘솔: `npm ci`·`npm audit`(취약점 0건)·`npm run lint`·테스트 **248건**·프로덕션 빌드 통과. 보존 정책 범위 판정 테스트 14건이 추가되었습니다(234 → 248건).
- SDK: `npm ci`·`npm audit`(취약점 0건)·typecheck·테스트 **29건**·build 통과. 테스트 명령 회귀 가드 2건이 추가되었습니다(27 → 29건).
- Go: 로컬 PostgreSQL 17을 연결한 `go test -race ./cmd/... ./internal/...`와 `go vet` 통과. 버전 선언·잠금 파일·Compose 이미지 이름의 일치 검사도 포함합니다. 별도 부하 테스트는 `MOMENTO_LOAD_POSTGRES_DSN`을 지정하지 않아 실행하지 않았습니다.
- `govulncheck`: 코드가 호출하는 취약점 0건. 가져오는 패키지 4건·필요 모듈 20건의 비호출 취약점은 별도로 보고되었습니다.
- 기존 Dockerfile의 프로덕션 이미지 빌드 통과. 배포용 아카이브의 로드·기동 검사는 태그 푸시 후 기존 릴리스 워크플로가 수행합니다.
- 순수 테스트에 더해 프로덕션 번들을 headless 브라우저에 올려 다섯 칸을 실제로 채워 확인했습니다. helperText와 저장 실패 Alert이 같은 문장을 쓰고, 범위 밖 입력이 그 칸에만 표시되며 다른 칸으로 번지지 않고, 경계값과 빈 「Aggregation (개월)」이 그대로 전송되는 것까지 36건을 확인했습니다.
- 콘솔 잠금 파일의 의존성 하한 조정은 **하지 않았습니다.** `npm audit`이 이미 취약점 0건이고, 잠금을 매니페스트만으로 재생성해도 `source-map-js` 1.2.2·`js-yaml` 4.3.2가 그대로 나오며, 전체 재생성은 무관한 전이 의존성까지 올려 이번 릴리스의 범위를 넘어섭니다.

## 범위와 배포

제품 동작 변경은 새 모듈 `web/src/pages/retentionRule.ts`, 이를 쓰는 `AdminPage.tsx`의 보존 정책 카드, 범위 문장이 빠져나간 `adminErrors.ts`이며 `web/test/retentionRule.test.mjs`가 이를 고정합니다. 함께 `sdk/package.json`의 테스트 명령과 그 가드가 바뀝니다. 서버·API·데이터베이스 마이그레이션과 보존기간의 허용 범위, 전송되는 요청 본문은 바뀌지 않습니다. 보존 정책을 수정하지 않는 사용자는 새로 할 일이 없습니다.

이번 개선은 릴리스 노트로 안내합니다. 기존과 같이 태그 푸시 후 GitHub Actions가 `momento:v0.34.60`을 빌드하고, 오프라인 아카이브 `momento-v0.34.60.tar.gz`와 `.sha256`을 검증해 Release에 첨부합니다. 설치 절차는 `docs/OFFLINE.md`를 따릅니다.

배포 담당자는 적용 후 「보존 정책」의 다섯 칸이 저장을 누르지 않은 상태에서 각각 자기 범위를 적는지, 범위 밖 값을 넣으면 그 칸만 오류로 표시되는지 확인합니다. 정상 범위의 값이 저장되지 않거나 안내가 다른 칸을 가리키면 확대 적용을 중단하고 이전 `momento:v0.34.59` 이미지로 되돌립니다. 이 세션은 로컬 릴리스 준비만 수행하며 실제 배포와 운영 환경 확인은 수행하지 않습니다.
