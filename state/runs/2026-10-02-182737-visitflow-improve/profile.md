# VisitFlow 프로필 (2026-10-02)
- 목적: 사내 방문 신청·승인·QR 방문증·로비 체크인·알림·감사를 단일 컨테이너로 제공한다.
- 스택: Go 1.24(chi·pgx·go-oidc·excelize), PostgreSQL 14+, React 19·TypeScript·Vite 7·Material UI 7, Vitest 3·Playwright 1.56.
- 기준: HEAD 955a02f, v2.8.12(web/package.json version 도 2.8.12). 이전 프로필의 v2.8.9 기준·"Vitest 60개"·"KeysPage .catch 없음" 을 갱신했다.
- 구조:
  - cmd/visitflow/: 서버 진입점과 임베드 webdist. 기본 스텁과 실제 UI 빌드 구분 필요.
  - internal/app/: REST·MCP·SSE·방문/QR/알림. integration_test.go·lists_test.go 는 실제 PostgreSQL 기반 통합 테스트.
  - internal/platform/: 환경설정·암호화·메일 등 기반 기능.
  - internal/database/: 번호별 SQL 마이그레이션을 파일별 트랜잭션으로 적용한다.
  - web/src/pages/: React 페이지 18개. VisitFormPage 는 일반/현장 신청 공용, ScannerPage·LobbyPage·RosterPage 는 로비 운영, VisitsPage 는 목록·상세·취소·QR 재발급.
  - web/src/components/: AdminUI(PageHeader·MetricCard)·AppShell·StatusChip·PasswordChangeGate 5개뿐. 페이지가 대부분의 상태를 직접 들고 있다.
  - web/src/schedule.ts·visitors.ts·silentSso.ts: 화면 사전 검사의 순수 함수. 단위 테스트가 붙는 유일한 층.
  - web/e2e/visit-flow.spec.ts: 실제 서버에 로그인·신청·QR 체크인하는 Playwright 회귀 테스트.
  - docs/: USER_GUIDE·ADMIN_GUIDE·API_AND_MCP·ARCHITECTURE, PDF와 화면 이미지. CLAUDE.md·AGENTS.md·로드맵/TODO 문서는 없다(이번 회차 TODO/FIXME grep 0건).
- 빌드·테스트:
  - `go test ./... -count=1`: VISITFLOW_TEST_DSN 없으면 DB 통합이 SKIP 된다(PASS ≠ 실행).
  - `VISITFLOW_TEST_DSN='postgres://…' go test ./... -count=1`: CREATE DATABASE 권한 필요. internal/app 약 55~60초.
  - `go vet ./...`, `go build ./...`, `gofmt -l .`(빈 출력), `git diff --check`.
  - `cd web && npm ci && npm run lint && npm test && npm run build`. `lint`=`tsc -b --pretty false`, `test`=`vitest run`. 직전 기록 79개 통과. node_modules 는 보통 비어 있어 npm ci 가 필요하다.
  - `cd web && npx playwright install --with-deps chromium` 뒤 실제 서버 준비 후 `npm run test:e2e`(VISITFLOW_BASE_URL 기본 http://127.0.0.1:8080). Playwright 자체 webServer 설정 없음. 계정은 VISITFLOW_E2E_ADMIN/VISITFLOW_E2E_PASSWORD(기본 admin/e2e-bootstrap-password).
  - CI test 잡: PostgreSQL 16 + Go test/vet + npm ci/test/build + Docker build. 별도 e2e 잡이 실제 dist 임베드·서버 기동·브라우저 테스트까지 수행한다.
  - `docker build -t visitflow:dev .`; release.yml 은 태그로 오프라인 Docker 아카이브를 만든다. 자율 회차에서 변경 금지.
- 관례:
  - 영어 conventional commit(`fix(web)`, `test:`, `chore(release)`), 한국어 UI·가이드. 설정은 DB settings, 주요 환경변수는 POSTGRES_DSN·BOOTSTRAP_ADMIN·BOOTSTRAP_ADMIN_PASSWORD·ENCRYPTION_KEY(Base64 또는 hex 32바이트).
  - 화면 결함은 「순수 함수 하나를 visitors.ts/schedule.ts 에 두고, 안내 문구·버튼 disabled·submit 가드가 그 한 값만 읽게 배선」하는 형태로 고친다(submitBlockReason v2.8.9, repeatCountError v2.8.10, duplicatePhoneErrors v2.8.11).
  - 로드 실패는 「이름 붙은 loadX + refError/refLoading + 닫기 없는 Alert + 다시 불러오기 버튼」(v2.8.8, VisitFormPage·ScannerPage·LobbyPage).
  - 가이드는 한 문장만 덧붙이고 PDF 는 재생성하지 않는다.
- 위험 구역:
  - auth/session/OIDC·keys·개인정보 암호화·migrations·settings·server·감사 경계. normalizePhone 은 watchlist 전화 해시 입력이라 변경 주의.
  - web/src/api.ts(61행)는 18개 페이지가 전부 쓰는 공용 fetch 헬퍼 — 시그니처를 바꾸면 블라스트 반경이 저장소 전체가 된다.
  - LobbyPage 의 EventSource 는 `useEffect(..., [])` 로 **한 번만** 구독하고 loadRef 로 최신 load 를 부른다. 필터·검색 변경마다 재구독하면 이벤트가 샌다.
  - ScannerPage 의 scope 필터와 stopCamera cleanup, 빈 lobbyId 계약.
- 자주 깨지는 곳:
  - 사이트 현지 자정 직전 30분에만 깨지던 today-기반 통합 테스트(v2.8.12 에서 visitToday 헬퍼로 두 곳 수정). visitBody 를 쓰는 나머지 약 40곳은 같은 구멍이 남아 있다.
  - TestSelfRegistrationRecordsVisitorConsent 의 `consented_at DESC LIMIT 1` 타이브레이크(2026-09-28 실제 flake 1회).
  - `git checkout --` 로 미커밋 테스트를 잃은 기록 — 되돌리기는 항상 임시 복사본으로. 실제 UI 검증 뒤 cmd/visitflow/webdist 스텁 복원 필수.
  - MUI label 의 필수 표시(thin space + `*`)와 select 의 aria-labelledby, 사이드바의 중복 버튼 이름 때문에 locator 를 실제 DOM 에서 확인해야 한다.
- 검증 함정:
  - `web/vite.config.ts:10` 의 `include: ["src/**/*.test.ts"]` — **`.tsx` 테스트는 조용히 0개로 수집된다.** devDependencies 에 testing-library 계열이 없어 컴포넌트 단위 테스트는 애초에 불가능하다. React state/effect 배선 결함의 1급 증거는 실제 서버 + 실제 Chromium 이다.
  - 이 환경에는 Playwright 번들 chromium 이 없다 — `channel: "chrome"`(/usr/bin/google-chrome)을 쓴다. 8080·5432 가 다른 프로젝트 컨테이너에 잡혀 있어 전용 도커 네트워크 + 호스트 18099 로 띄워야 한다.
  - 저장소 e2e 'registers a site, a lobby and an organization from the admin console' 는 이 환경에서 실패하지만 CI 에서는 통과한다(환경 의존).
  - 오류 경로만 네트워크 수준에서 주입하고 성공 응답은 `route.continue()` 로 실서버 것을 쓸 것. 가짜 객체·소스 문자열 grep 으로 배선을 증명하지 않는다.
  - 실제 Excel·SMTP·Keycloak 인프라 검증은 이 환경에서 수행된 적이 없다.
