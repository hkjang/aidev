이미 로그인한 사람이 `/login` 을 열면 빈 로그인 폼 대신 서버가 곧바로 `return_to`(없으면 `/`)로 보내도록 했습니다.

**로그인한 상태로 `/login` 을 열면 빈 폼이 보였습니다.**

북마크·뒤로가기·이메일 링크로 `/login` 을 다시 열면 `GET /` 의 정적 서빙이 `login.html` 을 그대로 내보내 빈 폼이 떴습니다. 세션이 살아 있는데도 "로그아웃됐나?" 하고 다시 로그인하면 세션이 새로 발급되는 셈이었고, JS 가 세션을 확인하는 것은 자동 로그인(`auto_login`)을 켠 배포뿐이라 그 밖의 설치는 확인 자체가 없었습니다.

이제 `GET /login` 을 별도 핸들러로 두어(더 구체적인 패턴이 이기는 Go 1.22+ `ServeMux` 규칙) 세션 쿠키를 서버가 먼저 봅니다. JS 없이도, 깜빡임 없이, `auto_login` 설정과 무관하게 제자리로 갑니다.

| 상황 | 동작 |
| --- | --- |
| 세션 있음 + `return_to=/saved` | `302 /saved` |
| 세션 있음, `return_to` 없음 | `302 /` |
| 세션 있음 + 밖을 가리키는 `return_to`(`//evil` 등) | `302 /` (`safeReturnTo` 규칙 그대로) |
| 세션 있음 + `return_to=/login`(`/login?…`, `/login/`) | `302 /` (자기 참조 302 루프 방지) |
| 비활성화·강등된 계정의 쿠키 | 세션으로 치지 않아 로그인 폼 |
| 쿠키 없음 | 예전과 같은 로그인 폼(`200`) |

`safeReturnTo` 는 SSO 콜백과 공유하므로 건드리지 않고 읽는 쪽만 더했고, `login.js` 의 세션 확인은 302 사이에 세션이 생기는 경우를 위해 그대로 두었습니다. 관리자 가이드의 자동 로그인 절에 이 동작을 한 단락 적었습니다.

**검증.** `gofmt`/`go vet`/`go test -race ./...` 38개 패키지 통과(새 테스트 7개 — 모두 `New(logger, options)` 실제 라우터에 `options.Sessions.Create` 로 실제 발급한 토큰으로 요청: `return_to` 로 302·없으면 `/`·밖을 가리키면 `/`·`/login` 자기 참조는 `/`·쿠키 없으면 폼·비활성 계정은 폼·잘못된 쿠키는 폼. 구현 전 302 케이스 4개가 200 으로 실패하는 것과 자기 참조 가드를 빼면 `Location="/login"` 으로 실패하는 것을 확인). JS 테스트 12파일 통과. `test/smoke/run.sh` 실제 바이너리+MariaDB+Chromium 브라우저 31페이지 통과 — 하네스에 "로그인한 채로 /login" 절을 더해 실제 서버에 curl 로 세션+`return_to`→`302 …/saved`, 세션→`302 …/`, `//evil`→`302 …/`, 쿠키 없음→`200` 을 확인합니다. 배포 이미지는 `test/smoke/artifact.sh` 로 실제 기동해 healthz/readyz·임베드 정적 자산·로그인·내장 마스터 키 질의·TZ 적용을 확인했습니다.
