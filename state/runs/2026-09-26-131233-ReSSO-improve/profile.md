# ReSSO 프로필 (2026-09-26)
- 목적: 오프라인 단일 바이너리로 운영하는 OIDC SSO 제공자와 사용자·Realm 관리 콘솔. 외부 RP 구현은 포함하지 않는다(이 저장소는 언제나 제공자 쪽이다).
- 스택: Go 1.26, chi v5, PostgreSQL/pgx v5, LDAP, React 19/TypeScript/MUI/React Query/Vite 7, vitest 4; CI Node 22.23.0.
- 구조:
  - cmd/resso: 서버·CLI·예약 LDAP 동기화·유지보수·메일 알림.
  - internal/httpserver: OIDC(oidc.go 1451행)·로그인/세션(auth.go 435행)·미들웨어(middleware.go 314행)·지표(metrics.go 108행)·관리/개인 API·MCP. integration_test.go는 실제 PostgreSQL과 httptest 서버를 쓰는 단일 10897행 파일.
  - internal/store + store/migrations: DB 접근과 자동 SQL 마이그레이션(최신 017_mail_deliveries.sql).
  - internal/oidc, cryptoutil, password, ratelimit: 토큰 발급·검증, 암호화, 비밀번호, 실패 제한.
  - internal/federation, backchannel, mail: LDAP·로그아웃 통지·SMTP. internal/tracking, observability: 방문 추적/CSP·Prometheus·구조화 로그.
  - web/src(React 소스), webui/dist(Go embed 산출물), scripts, docs(운영/사용/호환 정본).
- 빌드·테스트:
  - `eval "$(scripts/test-services.sh)"` 로 PostgreSQL/LDAP/LDAPS 환경변수를 잡고 **같은 셸에서** 테스트한다. 출력이 비면 준비 실패이므로 eval 하지 말 것.
  - `make lint`(golangci-lint v2.13.1 + govulncheck + ESLint --max-warnings 0), `make test`(go test -race ./... + vet + vitest + build, 전체 수 분: httpserver 약 115s / store 약 80s), `make build VERSION=vX.Y.Z`.
  - 단일 테스트: `go test -race ./internal/httpserver -run '^TestIntegration…$' -count=1 -v`.
- 관례: 영문 `fix:`/`feat:`/`docs:`/`release:` 커밋. **HEAD 511778c = v0.9.91**(2026-09-24). 설정은 환경변수 + `platform_settings` 키별 한 행. docs/가 운영·연동 정본이고 README는 개발 참고. 코드 주석이 매우 길고 "왜 이 답을 골랐는가"를 서술형으로 담는다 — 새 코드도 그 밀도를 따라야 한다. CLAUDE.md/AGENTS.md/roadmap/TODO는 저장소에 없다.
- 이 저장소가 반복해 쓰는 설계 관용구(새 과제는 여기에 맞출 것):
  - **"이쪽 장애"와 "진짜 없음"을 절대 같은 답으로 합치지 않는다.** `realmLookupFailed`(oidc.go:60)가 그 판정을 하고 discovery(72)·jwks(132)·authorization(189)·revocation(999)·logout(1155)이 쓴다. userinfo는 `writeUserInfoUnavailable`(oidc.go:855, stage 여섯), introspection은 `recordUnjudgedIntrospection`(oidc.go:979)으로 같은 일을 한다.
  - **조기 거절 금지**(로그아웃): 실패해도 세션을 끝내고 트레일에 남긴다. oidc.go에 두 번 명시.
  - **거절의 이유를 이유 코드로 남긴다**: 로그아웃의 `client_not_named`/`client_unknown`/`client_unavailable`/`uri_not_registered`/`form_unreadable`.
  - **지표 라벨 카디널리티를 고정한다**: `methodLabel`(metrics.go:94)·`routePattern`(:77)이 왜 그런지 주석으로 설명한다. 미검증 입력을 라벨·로그로 그대로 넘기지 않는다.
- 위험 구역: internal/httpserver/auth.go(세션·쿠키·로그인 계약), oidc.go의 토큰·로그아웃 경로, CSRF/API 키 예외(middleware.go의 requireRecentAuthentication·requireSessionOrAPIKey), internal/store/migrations, .github/workflows/release.yaml.
- 자주 깨지는 곳: gofmt 정렬(lint 첫 실행에서 자주 잡힌다), 빌드가 바꾸는 webui/dist/index.html(되돌릴 것), LDAPS bind mount와 CA 경로 불일치, 추측한 HTTP 상태 코드, 유지보수 SQL 문장 순서를 잠근 store 테스트(TestIntegrationTheRetentionSweepSaysOnlyWhatItSkipped).
- 검증 함정:
  - 환경변수가 없으면 연동 테스트가 SKIP인데도 종료 코드는 0이다. SKIP 0을 눈으로 확인할 것.
  - make test는 SKIP 집계용으로 연동 명령을 한 번 더 돌린다(중복 실행).
  - CI verify는 세 서비스를 준비하지만 release.yaml은 PostgreSQL만 준비한다.
  - CI lint는 npm 설치 전에 돌고, 로컬 make lint는 GO_PACKAGES로 vendored Go를 제외한다.
  - Docker는 이 환경에서 실행 가능(2026-09-21 확인). 기존 테스트 컨테이너 재사용만 검증됐고 깨끗한 환경의 신규 생성·삭제는 미검증.
  - 통합 테스트의 로그 단언은 `lockedBuffer`(integration_test.go:6904, 사용처 6982·7203)를 쓴다. 저장소 장애 재현은 테이블 RENAME으로 한다(선례: 로그아웃의 `client_unavailable`).
