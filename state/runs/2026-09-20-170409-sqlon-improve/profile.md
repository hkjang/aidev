# sqlon 프로필 (2026-09-20)
- 목적: PostgreSQL/MySQL/MariaDB/Oracle의 SQL 생성·읽기 실행 가드와 메타데이터, 플릿 관측·진단·승인 기반 DBA 변경 관리를 제공하는 MCP/REST/Web UI 서버.
- 스택: Go 1.25.0 단일 모듈(sqlon), net/http ServeMux, PostgreSQL 메타 저장소 또는 메모리 저장소, embed HTML 27개 및 인라인 JavaScript. 표준 빌드는 pure Go, Oracle은 별도 OCI/godror 빌드.
- 기준: main@57f99b7(v0.1.5). 지난 성공 회차의 DBA actor·SSO 자동로그인·tracking·handoff·mail·MCP OAuth는 현재 코드에 반영되지 않음. 성공 기록과 현재 main을 혼동하지 말 것.
- 구조:
  - cmd/sqlon·internal/app: 서버 부팅, 플래그/env; cmd/jamypg-*는 평가·골든셋/호환 실행 도구.
  - internal/mcp: MCP/REST 라우트, 인증, 관리자·DBA 도구, Web UI와 OpenAPI.
  - internal/meta: 계정·역할·프로파일·grant·설정·세션 및 PG/메모리 저장소.
  - internal/catalog·metasync: JSON 카탈로그와 프로파일별 워크스페이스, 메타데이터 수집.
  - internal/dbconn·engine: 다중 DB 연결·SQL 실행/방언; internal/change: 승인 기반 변경 상태기계.
  - internal/fleet·observability·collector: 플릿·세션·워크로드 수집/조회.
  - data/: JSON 데이터셋; docs/: 가이드·보고서·PDF, docs/reports/: 생성 스크립트/산출물.
  - test/integration·deploy/test: 실제 DB 컨테이너 기반 통합 테스트; scripts/: 빌드·릴리즈.
- 빌드·테스트: `go test ./... -count=1`, `go vet ./...` 이번 정찰에서 모두 통과(mcp 3.577초). 일반 빌드는 `go build ./cmd/sqlon`(이번 미실행). scripts/build.sh는 Windows amd64/Linux amd64·arm64 CGO=0 빌드.
- 통합 검증: `docker compose -f deploy/test/docker-compose.yml up -d --wait` 후 `go test -tags integration ./test/integration -v`; 실제 DB 필요, 이번 미실행. 브라우저 자동 검증은 미확인.
- 관례: 커밋은 feat/fix/docs/release 유형, 한국어·영어 혼용. 설정은 Options/SQLON_* 기본값과 meta.SettingDefs 저장 설정. CHANGELOG.md Unreleased에 기록. PG 마이그레이션은 internal/meta/pg.go의 SQL 배열을 트랜잭션 안에서 순차 실행.
- 문서 상태: CLAUDE.md/AGENTS.md는 저장소 검색에서 발견 못함. Go 소스 TODO/FIXME 검색 결과 없음. docs/README.md·auth.md·rest-api.md·security.md·development.md·profile-catalogs.md가 0바이트. executive_report.md의 로드맵은 v0.1.2 기준이고 admin_guide.md의 SQLite 표기는 PGStore 소스와 다름.
- 위험 구역: auth.go/authapi.go(세션·키·OIDC·nil 사용자 신뢰), meta/pg.go 및 internal/migration(데이터 이동), execguard/changeexecutor(DB 실행), .github/workflows. 이번 과제는 admin.go의 카탈로그 GET 인증 배선에 한정.
- 자주 깨지는 곳: Register는 REST에 전역 withUser를 적용하지 않는다. requireActor는 사용자 반환만 하므로 목록/하위 컨텍스트 전달을 별도로 해야 한다. requireDBA/requireAdmin은 현재 bool만 반환하며 adminAudit에도 actor가 없다.
- 권한 함정: canUseProfileID(nil)은 stdio 로컬 신뢰로 통과하지만 usableProfiles→meta.CanUseProfile(nil)은 거절한다. 따라서 같은 조회 화면에서도 상세는 과다 허용하고 목록은 비게 될 수 있다.
- 검증 함정: newAuthServer/withCookie/doReq로 실제 로그인과 mux를 통과시킬 것. profilecatalog의 단위 테스트만으로 HTTP 인증을 증명할 수 없음. /schemas는 실제 DB에 접근하므로 인증 테스트에서 제한된 로컬 실패 경로와 실제 성공을 구분할 것.
- 검증 함정: 여러 Go 파일에 CRLF, CHANGELOG 줄바꿈 혼재. 전체 gofmt/줄바꿈 정리 금지, 변경 파일만 검사. CI workflow 없음(.github/FUNDING.yml만 존재); README의 CI 표현과 다름. PDF 재생성의 브라우저 환경은 이번 미확인.
