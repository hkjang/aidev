# GoalForge 프로필 (2026-10-09)
- 기준: main@c319962, docs/GUIDE.md v0.55.0. 이전 프로필의 웹훅 결함·로드맵 부재 서술을 현재 코드로 정정.
- 목적: Go 엔진이 프로젝트 목표·작업 순서·검증 증거·완료 판정을 소유하고 AI 세션을 실행 도구로 쓰는 개발 오케스트레이터.
- 스택: Go 1.24.0; modernc SQLite 주력, pgx/PostgreSQL 병존; HTTP API·MCP·Bubble Tea TUI·정적 HTML/CSS/JS 문서 사이트.
- 구조:
  - cmd/goalforge/main.go: CLI·워커 진입점. --db/GOALFORGE_DB 지정 가능, 기본 .goalforge/goalforge.db.
  - internal/mcp/tools.go·server.go: 도구 목록·dispatch·stdio Serve. tools/call 실행 실패는 result.isError이며 RPC error와 구별.
  - internal/api/setup.go: HTTP doctor와 프로젝트 설정. doctor는 환경 진단에 완료 가능성 검사를 추가.
  - internal/diagnostics/readiness.go: 게이트 coverage/proof kind 진단. 실제 covered 조건만 measured로 집계.
  - internal/store/sqlite: 상태·목표·승인·증거 저장; report.go:Activity는 실제 활동 집계와 Since/Until 반환.
  - internal/observer: 무인 공급·실행/병합 승인. automerge의 중복 결정 차단은 ScopedApprovalExists 사용.
  - internal/notify: best-effort 웹훅·전역 반복 억제. 실패 시 자기 예약만 해제하는 수정 머지됨.
  - internal/procctl·internal/testscript: OS별 프로세스 제어·테스트 실행파일 헬퍼. 직접 테스트 파일 없음.
  - internal/model·policy·app·orchestrator·scheduler·standards: 모델/정책/실행/예약/기준. 상세는 이전 프로필 기반.
  - docs/: GUIDE, STANDARDS, SELECTION, acceptance-audit와 정적 사이트. roadmap은 docs/index.html#roadmap에 존재.
- 빌드·테스트:

  - 10/09 실측 go test ./... -count=1 exit 0, 32개 테스트 패키지 통과. sqlite 46.017s, observer 20.863s.
  - go test ./internal/mcp -count=1 exit 0 (0.548s). notify도 전체 실행에서 통과; -count=2/race는 이번 미실시.
  - CLI go run ./cmd/goalforge --db <회차>/assets/scout-mcp.db mcp로 tools/list 및 activity_report 실제 재현, exit 0.
  - 이번 별도 build/vet/tidy 및 Windows/macOS/arm64 실행은 미실시. go run은 CLI 경로를 빌드·실행한 것.
  - ci.yml/release.yml은 ubuntu/windows/macos test 매트릭스; CI 6타깃 릴리즈 빌드, 태그 릴리즈 provenance 발행.

- 위험 구역:
  - observer/autonomy.go·automerge.go 권한 봉투, sqlite 승인/스키마/마이그레이션, API/MCP 인증·session, git merge/push, workflows.
  - AutoApproveMerges에는 DailyLimit 참조가 없고 autonomy.AutoApprove에만 집계가 있음. 승인 집계·감사 설계 없이 규칙 복제 금지.
  - ScopedApprovalExists는 의도적으로 상태 무관. REJECTED/CONSUMED를 제외하면 사람 거절·기존 소비 결정을 뒤집는다.
  - ConsumeScopedApproval은 옛 승인 소비를 StaleApprovalError로 막지만 APPROVED 상태 자체는 유지한다.
- 자주 깨지는 곳:
  - sweepReport는 Acted=false이면 Note도 출력하지 않는다. Note만 넣고 무인 알림이 해결됐다고 하지 말 것.
  - notify 실패 예약 해제는 참조 identity로 자기 것만 지운다. 과거 요청이 새 예약을 지우지 않게 유지한다.
  - dayDuration 비유한 수/오버플로 거절은 이미 머지. 1734년 경계가 모든 데이터를 삭제한다는 옛 기록은 b465e1a에서 정정됨.
  - ParseCriterion 저장 계약과 review 증거 종류 독립성은 이전 회차 테스트가 있다. 이미 해결한 과제를 중복 선정하지 않는다.
- 검증 함정:
  - remote.origin.pushurl=DISABLED 이번 실측. requirePushable 정의가 gitops/app/CLI에 3개이며 remote 이름 단위 프로브 유지.
  - 전체 테스트가 비-verbose여서 이번 skip 수·개별 PostgreSQL 외부 DB 실행 여부는 미확인. ok를 운영 DB 검증으로 읽지 말 것.
  - MCP tools/list가 since=7d를 광고하지만 실제 tools/call은 isError=true. 168h·24h·빈 문자열은 정상; 이번 선정은 예시 교정이다.
  - 성공 응답의 content.text는 다시 JSON이다. ActivityReport의 Since/Until은 대문자 필드; RPC error 유무만 보면 도구 실패를 놓친다.
  - notify 성공 nil은 억제/no-op일 수 있다. 요청 수로 검증하며 실패 해제는 다음 Post만 복구하고 자동 재전송은 보장하지 않는다.
  - docs/index_en.html의 title/일부 본문에는 반복된 손상 문자열, script.js MCP 데모에는 실제와 다른 도구명이 있음. 브라우저 실행은 미확인.
