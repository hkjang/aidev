- 과제: MCP 긴 한 줄 응답 절단 시 UTF-8 글자 경계 보존 (가치 3 / 위험 1 / 작업량 S)
- 왜: `cutAtBoundary`는 이미 바이트로 잘린 `window`를 `runeSafeCut(window, len(window))`에 넘겨 길이 검사에서 그대로 반환하므로 한글·이모지가 중간에서 끊기고 JSON 직렬화 후 `�`로 바뀐다. 원본 문자열에서 안전하게 절단하면 작은 응답 예산에서도 소스 문자가 손상되지 않고 기존 절단 안내와 결과를 읽을 수 있다.
- 수용 기준: 1) 유효한 UTF-8 입력의 긴 단일 행을 어느 바이트 경계에서 절단해도 반환 문자열은 유효한 UTF-8이며, 원문에 없던 U+FFFD가 JSON 응답에 생기지 않는다(2·3·4바이트 문자와 ASCII 혼합, 절단 없는 입력 포함). 2) 기존 섹션/문단/행 경계 선호와 60% 최소 활용 조건, 코드 펜스 닫힘·Truncated 안내·작은 Notes 보존을 유지하며 예산 예약 정책은 이번에 바꾸지 않는다. 3) 함수 회귀 테스트가 수정 전 실패해야 하고, 실제 SQLite fixture → Server.ServeHTTP tools/call(read-file) → handleReadFile → formatFileContent → finishCall → JSON 응답 경로에서도 연속된 maxBytes 값에서 문자가 손상되지 않음을 증명한다. 캐시 미스·히트 모두 확인하고 JSON 디코딩 뒤 utf8.ValidString만 검사하지 말고 U+FFFD 부재와 원문 접두부 일치를 검사한다(JSON 인코더가 오류 바이트를 대체하므로 valid 검사만으로는 놓친다).
- 건드릴 파일: `internal/mcp/budget.go:cutAtBoundary` — 마지막 fallback에서 원본 text와 limit를 runeSafeCut에 넘기는 최소 수정 검토; `internal/mcp/truncation_test.go:TestATruncatedAnswerUsesTheBudgetItWasGiven` 주변 — 긴 단일 행의 다중 바이트 경계를 표 기반으로 회귀 검증; `internal/mcp/server_test.go:TestTruncationKeepsTextValid`, `fixture`, `callAs` — 기존 3000 단일 예산 검사를 연속 예산으로 보강하고 실제 read-file 응답 회귀 추가. `internal/mcp/audit.go:runeSafeCut`, `internal/mcp/tools.go:handleReadFile`, `internal/mcp/format.go:formatFileContent`, `internal/mcp/dispatch.go:finishCall`은 읽고 연결 확인한 파일이며 수정할 필요는 예상하지 않는다.
- 검증 명령: `go test -tags sqlite_fts5 -count=1 ./internal/mcp`; `go test -tags sqlite_fts5 -race ./internal/mcp`; `go test -tags sqlite_fts5 ./...`; `go vet ./...`; `go build -tags sqlite_fts5 ./...`; `gofmt -l internal/mcp`(출력 없어야 성공). 이번 정찰은 `go test -tags sqlite_fts5 ./internal/mcp ./internal/search ./internal/contentsecurity ./internal/manifest`를 실행해 exit 0 확인(mcp/contentsecurity/manifest 캐시, search 1.336s). 전체 suite·race·build·vet는 정찰에서 미실행이며 구현 후 검증 명령이다.
- 위험과 피할 것: auth·store migration·.github/workflows·릴리즈/버전·마스킹·manifest 파서는 건드리지 않는다. 이미 성공 기록이 있는 미머지 작업을 재구현하지 않는다. `runeSafeCut` 공용 계약을 넓히거나 전체 잘린 문자열을 재인코딩하지 말고 잘못된 호출 위치만 수정한다. 응답 예산 320B 예약 부족 및 finishCall 진단 추가 문제는 별도 후보로 남긴다. 소스 복사 실행만으로 완료 판정하지 말고 실제 운영 함수와 HTTP 경로 테스트를 추가한다. 공유 in-memory SQLite fixture를 t.Parallel로 돌리지 않는다.
- 차선 후보: mcp.cacheKey가 호출자 ACL 슬라이스를 변경하지 않도록 복사 (가치 2 / 위험 1 / S) — `cache.go:cacheKey`가 `principalACLs` 반환값을 제자리 정렬한다. `args.go:principalACLs`와 `search/service.go:WithUnrestricted`는 비관리자의 p.ACLPrincipals 원본을 반환한다. cache.go에서만 복사 후 정렬하고 fixture/callAs로 비관리자의 역순 ACL 입력 보존·순서가 다른 동일 집합의 캐시 히트·권한 회수 무효화를 검증한다. auth/search 구현은 변경하지 않는다.
