# v0.71.6 — 제목이 겹쳤다는 이유로 통째로 사라지던 생각

v0.69.0이 공간을 **문서**로 내보내는 길을 냈고, v0.71.3은 그 옆에 오래 있던 Markdown
내보내기가 문서가 아니라 **백업**이라고 적었습니다. 백업인 이유는 v0.65.0부터
umm이 **자기가 쓴 파일을 다시 읽어 들이기** 때문입니다. v0.71.5는 이름에 든 줄바꿈
하나가 그 파일을 통째로 못 읽게 만들던 것을 고쳤습니다.

그 파일은 끝에 두 절을 붙입니다 — `## Connections`와 `## Lines of thinking`. 공간이
어떻게 이어져 있는지, 무엇을 따라가 보고 있는지의 목록입니다. 그런데 가져오기는
이 둘을 **제목만 보고** 알아봤습니다.

```ts
if (exportSections.has(title)) continue;
```

"Connections"는 생각에 붙이기 아주 흔한 제목입니다. 가져오기 자신의 주석도 다른
자리에서 그렇게 적어 두고 있었습니다 — *an ordinary thing to title a thought*.
umm의 파일 안에서 그 제목은 **사람의 생각과 내보내기의 목록을 구별해 주지
못합니다.**

```
    사람이 쓴 생각의 제목:  Connections

            전                              후
    ━━━━━━━━━━━━━━━━━━━━━━━━    ━━━━━━━━━━━━━━━━━━━━━━━━
    목록으로 읽힘               생각으로 읽힘  ✔
    ↓  산문에서 연결이          ↓
       하나도 안 나옴           제목·본문·id·좌표 그대로
    절이 통째로 버려짐          그리로 그어진 연결도 그대로
    생각이 복원에서 사라짐
    그 생각으로 그어져 있던
      연결도 함께 사라짐
```

## 한 생각이 사라지면 그 생각으로 그어진 선도 사라집니다

목록으로 읽힌 절은 산문에서 연결을 하나도 뽑아내지 못한 채 **통째로 버려집니다.**
생각이 복원에서 없어지는 것이 첫 번째 손해입니다.

두 번째가 더 넓습니다. 버려진 절의 `- id:`는 **등록되지 않습니다.** 그러면 그
생각을 가리키던 연결들은 전부 **답할 생각이 없는 id**를 부르게 되고, 그래서 그 선들도
함께 사라집니다. 사람이 가장 다시 쓸 법한 제목 하나가 가장 비싼 값을 치르던
자리입니다.

## 차이는 이미 파일에 적혀 있었습니다

형식을 바꿀 필요는 없었습니다. **내보내기가 그 차이를 이미 쓰고 있기** 때문입니다.

```
    생각 절                      닫는 두 절
    ━━━━━━━━━━━━━━━━━━━━━━━━━    ━━━━━━━━━━━━━━━━━━━━━━━━━
    ...본문...                   - `id` --related--> `id` — 이유
    - id: `...`                  - **되돌리기 실험** — adopted: ...
    - type: `thought`
    - source: `user`               ↑ 마지막 줄이 연결이거나 갈래.
    - canvas: `40, 80`               메타데이터로 끝나는 일이 없음
      ↑ 언제나 이 목록으로 끝남
```

그래서 **절의 꼬리가 판정합니다.** 마지막 비어 있지 않은 줄이 메타데이터면 그것은
사람의 생각이고, 아니면 내보내기의 목록입니다. v0.71.5가 id·좌표·색을 읽어 내는
바로 그 꼬리라서, 판정에 새 표식이 필요하지 않습니다.

```ts
function describesTheSpace(title: string, content: string): boolean {
  if (!exportSections.has(title)) return false;
  const lines = content.split('\n');
  for (let at = lines.length - 1; at >= 0; at -= 1) {
    const line = lines[at].trim();
    if (line === '') continue;
    return !exportMetadata.test(line);
  }
  return true;
}
```

메타데이터를 일부만 가진 생각도 — 옛 내보내기이거나 재시도 초안으로 다시 쓰인
것이거나 — `- id:` 한 줄이면 생각입니다. **형식은 바뀌지 않습니다.** 이미 누군가의
디스크에 있는 백업 파일은 전과 똑같이 복원됩니다. 남의 Markdown은 애초에 이 규칙이
닿지 않는 자리에 있습니다.

## 검증

시험 2개를 새로 넣었습니다. 옛 판정(`return exportSections.has(title)`)으로 되돌리면
둘 다 실패하는 것을 확인했습니다.

- `restores a thought titled like one of the export sections` — `Connections`와
  `Lines of thinking`을 제목으로 쓴 생각 둘이 제목·본문·id·좌표 그대로 돌아오는지,
  그러면서 파일 끝의 진짜 두 절은 여전히 목록으로 읽히는지
- `restores a section-titled thought that carries only its id` — 꼬리에 `- id:`
  하나뿐인 절도 생각인지
