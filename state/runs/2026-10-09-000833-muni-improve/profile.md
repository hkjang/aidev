- 자주 깨지는 곳:
  - 문서 형식 reader/writer 차이와 수제 픽스처, lazy Tiptap 참조(이전 기록).
  - ZIP 문서는 ORDER BY d.folder_id NULLS FIRST,d.title,d.id, 폴더는 ORDER BY name,id와 순서 슬라이스를 사용한다.
  - entryKey는 strings.ToLower. folderPaths.claimed와 uniqueEntryName.used는 별도 맵이다.
  - 고정 목록.md는 used에서만 예약되고 claimed에서는 예약되지 않음: 이번 선택은 루트 목록.md 폴더와 안내 파일 충돌의 최소 수정.
  - 임의 파일/폴더 충돌과 가상 휴지통/사용자 휴지통 폴더 충돌은 아직 별건. 폴더 생성은 이름 중복을 금지하지 않는다.
  - 10/08 기록의 HWPX 수정 e503055는 현재 pinned base에 미반영. import_attachments.go 네 truncateRunes 호출이 남지만 이미 수행된 과제로 재선택 금지.
  - DOCX pageFurniture는 이미 문구 없이 200룬 제한, 긴 머리말 회귀에는 hwpx.Build를 사용(이전 기록, 이번 writer 미재검증).
- 검증 함정:
  - MUNI_TEST_DSN 없으면 live SKIP, CI에서는 FAIL. liveServer가 테스트 계정 행을 삭제하므로 전용 DB만 사용한다.
  - liveServer는 admin 문서를 일괄 삭제하지 않는다. workspace_export의 folderNamed/documentInFolder에는 자기 ID cleanup이 이미 있다.
  - CI는 PostgreSQL 및 Go·프런트 build/unit을 실행; Playwright는 미실행이며 기본 외부 서버 8080 필요.
  - ZIP 이름 집합은 파일/디렉터리 접두사 충돌을 잡지 못한다. 이번 합성 ZIP 목록.md/하위.md + 목록.md는 Linux 추출 시 IsADirectoryError; 실제 HTTP 재현은 미확인.
  - 동률 배정 회귀는 이름→본문 대응을 비교해야 하며 정확히 한 행 재작성으로 순서를 흔든다(이전 회차).
  - Windows/macOS 실제 압축 해제는 미확인. 정적 근거·합성 ZIP·실제 라우트 검증을 구별할 것.
