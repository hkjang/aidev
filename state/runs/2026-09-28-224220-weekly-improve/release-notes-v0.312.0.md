# v0.312.0 — Confluence 자동 수집 상태가 실패한 질의를 답으로 내놓지 않고, 탭이 그 실패를 문구로 말합니다

## 조회에 실패한 카드가 "아무 문제 없습니다" 라고 말했습니다

- `GET /api/v1/admin/confluence/sync/status` 는 네 번 읽습니다. 그런데 **바로 위의 동기화 상태 질의 하나만** 오류를 검사했고, 아래 세 읽기 — 진단 목록과 매핑·미매핑 사용자 수 — 는 오류를 **통째로 버렸습니다**(`errorRows, _ := a.db.Query`, `_ = a.db.QueryRow(count …)` 두 번).
- 버려진 자리에 남는 값이 하필 **화면이 낼 수 있는 가장 안심되는 답**이었습니다: 진단 **0건**(`진단 없음`), 매핑 **0명**, 미매핑 **0명**.
- 그래서 진단 표를 읽지 못하는 바로 그때 화면은 **"실패가 없다" 고 말했습니다.** 표가 사라진 것과 표가 비어 있는 것을 관리자가 구분할 방법이 **없었습니다** — v0.310.0 이 "가득 찬 표는 '진단이 이것뿐' 으로 읽힌다" 고 고친 그 카드에서, 이번에는 **읽지 못한 표가 '진단이 없다' 로** 읽혔습니다.

## 읽지 못했으면 읽지 못했다고 답합니다

- 세 읽기 모두 위의 질의와 **같이 `500 QUERY_FAILED`** 로 답합니다. 카드가 말할 수 있는 것은 조회에 성공한 상태뿐이고, 실패한 조회에는 **돌려줄 숫자가 없습니다**.
- 조용히 건너뛰던 **`errorRows.Scan(...) == nil`** 과 한 번도 보지 않던 **`rows.Err()`** 도 검사합니다. 행 하나를 못 읽는 것도, 순회 도중 끊기는 것도 이제 답이 되지 않습니다.
- 단 **잘림 판정으로 루프를 `break` 한 경우에는 `rows.Err()` 를 보지 않습니다.** 그 중단은 v0.310.0 이 21번째 행을 읽고 일부러 멈추는 것이며, 의도한 중단을 오류로 읽으면 잘린 표가 통째로 500 이 됩니다.
- **응답 필드·질의·`LIMIT limit+1` 잘림 계약·OpenAPI 는 그대로입니다.** 성공하는 조회의 답은 v0.311.0 과 한 글자도 다르지 않습니다.

## 거절이 영원히 도는 스피너로 끝나지 않습니다

- 이 거절이 그대로 도착하면 `ConfluenceTab` 의 `load()` 가 거부되고 `status` 가 `undefined` 로 남아, 탭은 **아무 말도 하지 않는 스피너**가 됩니다. 500 을 정직하게 돌려준 대가가 화면에서는 무한 로딩입니다.
- 같은 파일의 **감사 로그 탭이 이미 쓰는 관례**(`errorText` + 실패 문구 + `다시 시도`)를 그대로 따랐습니다. 관리자는 무엇이 실패했는지 읽고 다시 누를 수 있습니다.
- **10초 폴링의 `.catch(()=>undefined)` 는 일부러 그대로 뒀습니다.** 한 번의 일시적 실패로 멀쩡한 카드를 오류 화면으로 바꾸는 쪽이 더 나쁩니다. 대신 멈춘 카드가 오래된 숫자를 나이 표시 없이 계속 보여 주는 문제는 남아 있으며, `연속 실패` 와 `마지막 갱신 시각` 중 무엇을 말할지 먼저 정하는 다음 회차의 몫으로 적었습니다.
- 관리자 가이드 **3.6** 이 이 탭의 실패 문구를 함께 적습니다.

## 검증

새 시험 `TestTheConfluenceCardRefusesToAnswerWithAFailedQuery` 가 고치기 전 코드에서 **먼저 실패하는 것을 확인**했습니다 — `status with confluence_sync_errors unreachable = 200 {… "recentErrors":[], "mappedUsers":0 …}, want 500 QUERY_FAILED instead of a card that reads as a healthy one`, 그리고 `user_external_accounts` 하위도 `200 … "mappedUsers":0,"unmappedUsers":0` 으로 함께 실패했습니다(표에는 진단이 실제로 1건 들어 있었습니다). 재현은 이 저장소의 기존 관례(`audittrail_test.go` 의 `ALTER TABLE … RENAME TO …_hidden`)대로 표를 잠시 치우고, 되돌린 뒤 카드가 다시 답하는 것까지 확인합니다. 진단 행은 직접 INSERT 하지 않고 프로덕션 쓰기 경로 `recordConfluenceError` 로 만들었습니다.

실제 PostgreSQL(`pgvector/pgvector:pg16`) 위에서 전체 Go 테스트와 `go vet`·`gofmt`·`go build`, 가드·OpenAPI·쪽넘김·모달·버전 검사, 프런트엔드 173개 시험과 `tsc -b`·프로덕션 빌드를 통과했습니다. 탭의 실패 문구 자체는 이 저장소에 `AdminPage` 를 렌더하는 프런트 시험이 없어 **타입 검사와 빌드까지만** 확인했고 렌더링 시험으로 증명하지 않았습니다.

## 업그레이드

마이그레이션도, 새 환경변수도, 설정 키의 변경도 없습니다. 응답에 늘어난 칸도 사라진 칸도 없습니다 — **조회가 성공할 때 이 API 의 답은 v0.311.0 과 같습니다.** 달라지는 것은 조회가 실패할 때뿐이며, 그때 200 대신 `500 QUERY_FAILED` 가 갑니다. 이 경로를 읽는 외부 클라이언트가 있다면 **0 을 정상값으로 읽던 코드가 이제 오류를 받습니다** — 그것이 이 릴리즈가 고치는 것입니다. 기존과 같이 PostgreSQL 을 백업한 뒤 v0.312.0 이미지를 올리면 됩니다.
