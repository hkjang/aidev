# VisitFlow 프로필 (2026-09-20)
- 목적: 사내 방문 예약·승인·QR 방문증·로비 체크인·알림을 단일 컨테이너로 제공하는 방문 관리 시스템.
- 스택: Go 1.24(go.mod), chi·pgx·go-oidc·excelize 2.9.1, PostgreSQL 14+, React 19·TypeScript·Vite·Material UI 7, vitest·Playwright.
- 기준: main@8d3994b, v2.8.3. README·최근 git log 30건·문서·테스트·CI 확인. CLAUDE.md/AGENTS.md/별도 로드맵·TODO 파일과 TODO/FIXME 검색 결과는 없음.
- 구조:
  - cmd/visitflow/: 서버 진입점과 임베드 webdist. 저장소의 기본 webdist는 실제 프런트 빌드와 구분해야 함.
  - internal/app/: HTTP 핸들러·미들웨어·MCP·SSE·백그라운드 처리. visits.go가 방문 생성 및 전화 정규화, import.go가 CSV/XLSX 미리보기.
  - internal/app/import_test.go: 단위 파서 테스트와 newTestEnv/실제 라우터 기반 HTTP 업로드 테스트.
  - internal/app/integration_test.go: newTestEnv가 테스트마다 DB 생성·정리. do/doWithContext 요청 데드라인 사용.
  - internal/platform/: 환경 설정·메일 발송·암호화 기반 기능.
  - internal/database/: DB 연결/마이그레이션; migrations/NNNN_*.sql, 현재 HEAD 최신은 0014_tracking.sql.
  - web/src/: 화면·공통 컴포넌트·타입·vitest; web/e2e/: 실제 서버 Playwright; web/screenshots/: 가이드 캡처.
  - docs/: USER_GUIDE·ADMIN_GUIDE(Markdown/PDF), API_AND_MCP·ARCHITECTURE, assets/guide 캡처.
- 빌드·테스트: 루트 `go test ./... -count=1`, `go vet ./...` 정찰에서 통과. VISITFLOW_TEST_DSN 미설정으로 DB 통합은 SKIP.
- 빌드·테스트: `cd web && npm ci && npm run lint && npm test && npm run build`; 이번 프런트 실행 미확인. lint는 ESLint가 아니라 tsc -b.
- 빌드·테스트: CI는 Go 테스트/vet → npm ci/test/build → Docker 빌드, 별도 e2e 잡. 명시적인 npm run lint 단계는 없음(기존 프로필 수정).
- 빌드·테스트: DB 통합은 CREATE DATABASE 권한 필요. CI DSN은 postgres://visitflow:visitflow@127.0.0.1:5432/visitflow?sslmode=disable. 과거 회차 전체 통합 약 45~57초, 이번 측정 없음.
- 빌드·테스트: `docker build -t visitflow:dev .`; e2e는 실제 서버·DB·Chromium 준비 후 `cd web && npm run test:e2e`(상대적으로 오래 걸림). CI가 web/dist를 cmd/visitflow/webdist로 복사해 임베드한다.
- 관례: 최근 커밋 영어 conventional, 릴리즈 chore(release). 한국어 UI/문서. settings 표의 키를 검증하고 SQL 번호별 트랜잭션 마이그레이션으로 기본값을 추가.
- 관례: 오류는 writeError의 HTTP 상태·snake_case 코드·한국어 메시지. 현재 메일 설정은 smtp.*; mail.*는 미머지 브랜치에만 있음.
- 위험 구역: auth.go(세션·OIDC), keys.go 및 암호화, migrations/, settings.go·server.go, 개인정보·감사. normalizePhone은 전화 해시 입력이라 가져오기 수정 목적으로 바꾸지 말 것.
- 위험 구역: origin/auto/2026-09-16-1212(메일, 0015)와 origin/auto/2026-09-18-0533(MCP OAuth, 0016)는 HEAD에 미머지. auth/settings/server/admin/mail·통합 테스트·설정/키 화면·관리자/API 문서 중첩을 주의.
- 갱신 사항: MCP 브랜치 715a242의 mcpOAuthProvider는 issuer별 in-flight 채널과 요청 취소, 잠금 밖 discovery를 이미 구현했다. 해당 보류 과제는 재구현하지 않는다(main에는 아직 없음).
- 자주 깨지는 곳: 과거 변이 복구에 git checkout -- 파일을 사용해 미커밋 변경을 두 번 잃음. 미머지 브랜치와 충돌 주의. SSE는 httptest 컨텍스트 종료가 없으면 영구 대기 가능.
- 검증 함정: Go 테스트의 PASS는 DB 통합 실행을 보장하지 않음. uploadImport는 env.handler.ServeHTTP를 직접 호출하므로 do 헬퍼의 데드라인이 자동 적용되지 않음.
- 검증 함정: excelize GetRows는 표시 서식을 적용한다. 지수 서식으로 잘린 전화도 normalizePhone이 지수의 숫자까지 세어 7자리 이상이면 경고 없이 통과할 수 있음(이번 실제 워크북으로 재현).
- 검증 함정: 실제 Excel 앱·Keycloak·SMTP·Momento·브라우저는 이번 정찰에서 미확인. PDF 생성 도구는 README상 저장소 밖 aidev/tools/guide/md2pdf.mjs이며 실제 실행 가능 여부 미확인.
