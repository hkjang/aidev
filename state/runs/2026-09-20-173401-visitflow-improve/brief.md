- 과제: CSV·XLSX 가져오기에서 복원하지 못한 지수 표기 전화번호의 경고 누락 수정 (가치 3 / 위험 1 / 작업량 S)
- 왜: `importPhone`은 자릿수가 잘린 지수 값을 원문 그대로 반환하지만 `visitorInputsFromRows`는 `normalizePhone(phone)`의 길이만 검사하여 `1.0123E+09`(숫자 7개), `1.01234568E+09`(숫자 11개)를 경고 없이 미리보기에 올린다. 복원 실패한 지수 표기에는 행 번호와 수정 방법을 안내해 사용자가 잘못된 전화번호를 제출하기 전에 알아볼 수 있게 한다.
- 수용 기준: 1) CSV 및 XLSX 미리보기에서 복원 후에도 지수 표기로 남은 전화번호는 숫자 개수에 관계없이 한국어 경고가 나오고 전화번호 원문은 보존된다. 예: `행 3: 휴대전화가 지수 표기로 남아 정확한 번호를 확인할 수 없습니다. 원본 번호를 확인하고 텍스트 형식으로 다시 입력하세요`; 단순히 표시 서식만 바꾸면 복구된다고 안내하지 않는다. 2) `1012345678` 및 `1.012345678E+09`는 종전처럼 `01012345678`로 복원되고 이름·동의가 정상일 때 경고가 없으며, 0 접두사·하이픈·공백·국제번호·회사 열과 100명 제한은 변하지 않는다. 3) 파서 테스트와 실제 excelize 워크북→multipart HTTP preview 응답 테스트가 잘린 값의 원문 보존·경고·행 번호 및 정상 복원 값 무경고를 함께 증명한다. 제목/빈 행 아래 헤더에서도 행 번호를 보존하고, 지수 전화 전용 경고와 같은 원인의 일반 전화 경고는 중복하지 않되 이름 누락·동의 누락 경고는 유지한다.
- 건드릴 파일: `internal/app/import.go:visitorInputsFromRows` — 이미 계산한 `phone := importPhone(...)`에 대해 기존 `importScientific` 패턴으로 지수 표기가 남았는지 검사하고 경고를 구성한다; `importPhone`의 보수적인 복원 계약은 유지하고 잘린 값이 항상 기존 경고에 걸린다는 주석만 바로잡는다. `internal/app/import_test.go:TestImportPhoneRestoresLeadingZeroFromNumericCells`, `TestVisitorImportAcceptsExcelExports`, `uploadImport`, `importedVisitors` — 회귀 케이스와 실제 CSV/XLSX 업로드 검증을 추가한다(기존 테스트 이름은 유지해도 됨). `docs/USER_GUIDE.md:협력사 열 명을 한 번에 신청하기` — 필요시 전용 경고와 원본 재확인 방법 한 문장만 추가; PDF 재생성은 이번 필수 범위 아님.
- 검증 명령: 저장소 루트에서 `go test ./internal/app -run 'TestImport|TestVisitorImport' -count=1 -v`, `go test ./... -count=1`, `go vet ./...`. HTTP 검증은 PostgreSQL의 CREATE DATABASE 권한이 있는 테스트 계정으로 `VISITFLOW_TEST_DSN`을 설정하고 `go test ./internal/app -run '^TestVisitorImportAcceptsExcelExports$' -count=1 -v`, 이어 `go test ./... -count=1`을 실행한다. CI 예시 DSN은 `postgres://visitflow:visitflow@127.0.0.1:5432/visitflow?sslmode=disable`; 해당 서버가 존재할 때만 사용한다. DSN 없이 HTTP 테스트의 SKIP을 통과로 기록하지 않는다.
- 위험과 피할 것: `normalizePhone`은 검색·개인정보 해시 입력이므로 수정 금지. 복원 허용 범위를 넓히거나 잘린 자릿수를 0으로 채우거나 XLSX RawCellValue로 우회하지 않는다. REST/MCP 방문 생성의 공통 유효성 검사·인증·마이그레이션·워크플로·메일/MCP 미머지 브랜치 파일은 이번 범위 밖이다. 경고는 수정 안내이며 제출 차단을 보장하는 변경이 아니다. 새 응답 필드나 UI 배선은 불필요: `VisitFormPage.tsx:importVisitors`가 기존 `warnings`를 `setImportWarnings`로 받아 Alert에 표시한다(5건 이후는 건수 요약). 감사 details에는 전화 원문이나 경고 원문을 추가하지 않는다. 변이 확인 후 `git checkout -- 파일`로 미커밋 작업을 날리지 않는다.
- 차선 후보: 가져오기 미리보기에서 인식된 헤더 행 번호·무시된 열 이름 안내 — 1순위가 구현 시작 시 이미 해결된 경우에만 선택; `importHeaders`/`importHeaderRow`/`previewVisitorImport`와 `VisitFormPage.tsx:importVisitors`를 연결하고 기존 visitors/warnings 응답 호환성을 유지한다.
