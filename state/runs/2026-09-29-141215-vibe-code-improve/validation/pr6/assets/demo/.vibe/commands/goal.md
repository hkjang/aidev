---
description: 장기 목표를 기준으로 자율 개발을 이어가는 persistent goal loop
---

사용자가 `/goal <목표 설명>` 형태로 요청하면 아래 자율 목표 루프를 시작하거나 이어가세요.

핵심 원칙:
1. 목표를 한 번 정하면 매 턴마다 목표 달성에 직접 기여하는 다음 작업을 스스로 선택합니다.
2. 긴 작업은 작은 단계로 쪼개고, 각 단계마다 구현 -> 검증 -> 기록 순서로 진행합니다.
3. 대화 컨텍스트가 길어져도 이어갈 수 있도록 파일 기반 상태를 남깁니다.
4. 사용자가 중단시키지 않는 한, 분석만 하지 말고 실제 개발/수정/검증까지 진행합니다.

## 시작 절차

1. 워크스페이스 루트에 아래 디렉터리가 없으면 생성합니다.
   - `.vibe-code/goals/`
   - `.vibe-code/sessions/`
   - `.vibe-code/checkpoints/`
2. 사용자 입력에서 목표 설명을 추출합니다.
3. 목표 설명을 kebab-case slug로 정리하고 새 목표 파일을 만듭니다.
4. 목표 설명이 없고 `.vibe-code/goals/current.md`가 있으면 그 파일을 읽고 이어서 진행합니다.
5. 새 목표를 시작할 때는 `current.md`를 새 목표 파일로 갱신하고, 이전 current가 있으면 그대로 보존합니다.

## 파일 규칙

- 목표 파일:
  - `.vibe-code/goals/<YYYY-MM-DD-HHmm>-<slug>.md`
- 현재 목표 포인터:
  - `.vibe-code/goals/current.md`
- 세션 handoff:
  - `.vibe-code/sessions/<YYYY-MM-DD-HHmm>-handoff.md`
- 중간 체크포인트:
  - `.vibe-code/checkpoints/<YYYY-MM-DD-HHmm>-<slug>.md`

## 목표 파일 템플릿

아래 구조를 사용하세요.

```md
# 목표: <사용자 목표 한 줄 요약>

상태: active
작성일: <ISO 또는 로컬 시각>
마지막 갱신: <ISO 또는 로컬 시각>
목표 파일: .vibe-code/goals/<YYYY-MM-DD-HHmm>-<slug>.md

## 목표
<사용자 요청을 구현 중심으로 다시 정리한 설명>

## 완료 기준
- [ ] 사용자가 기대한 핵심 기능 동작
- [ ] 관련 테스트/빌드/검증 통과
- [ ] 문서 또는 사용법 반영

## 현재 상태
- 지금 단계: <discovery|implementation|verification|polish>
- 다음 행동: <가장 바로 할 일>
- 마지막 검증: <없음 또는 최근 검증 결과>

## 작업 큐
### Now
- [ ] 바로 수행할 작업

### Next
- [ ] 이어서 할 작업

### Done
- [x] 완료된 작업

## 결정 로그
- <시각> - <어떤 판단을 했는지>

## 변경 로그
- <시각> - <수정 파일/기능 요약>

## 검증 로그
- <시각> - <실행한 명령과 결과>

## 중단/재개 노트
<다음 세션이 바로 이어받을 수 있는 메모>
```

## 작업 루프

목표를 시작하거나 이어받았다면 아래를 반복하세요.

1. 목표 파일의 `현재 상태`, `작업 큐`, `완료 기준`을 읽고 지금 해야 할 한 가지 작업을 고릅니다.
2. 코드/문서/설정을 실제로 수정합니다.
3. 가능한 범위에서 즉시 검증합니다.
4. 목표 파일의 `변경 로그`, `검증 로그`, `작업 큐`, `현재 상태`를 업데이트합니다.
5. 아직 목표가 끝나지 않았다면 사용자의 추가 지시를 기다리기보다 다음 작업을 이어서 진행합니다.

## Handoff 규칙

아래 상황이면 handoff 파일을 만듭니다.
- 큰 작업 단위를 마쳤을 때
- 컨텍스트가 길어져 다음 세션으로 넘기는 편이 안전할 때
- 검증 대기나 외부 입력 대기가 생겼을 때

handoff 파일 템플릿:

```md
# Session Handoff

목표: <현재 목표>
시각: <timestamp>

## 현재 상태
- 완료한 것:
- 남은 것:
- 마지막 검증:

## 다음 바로 할 일
1. ...
2. ...

## 참고 파일
- path/to/file

## 주의사항
- ...
```

다음 세션은 `/goal 이어서`로 시작하고, 이 파일의 "현재 상태"와 "작업 큐"부터 읽습니다.

## 응답 방식

- 매 턴 너무 긴 설명보다, 무엇을 진행 중인지 짧게 알리고 바로 구현으로 들어갑니다.
- 목표와 무관한 대규모 리팩터링은 피합니다.
- 사용자가 명시적으로 멈추라고 하기 전에는 목표 달성까지 밀고 갑니다.
- 매 의미 있는 변경 뒤에는 목표 파일 기록을 남깁니다.

## 첫 응답 템플릿

새 목표를 시작할 때는 아래 형식으로 시작하세요.

```md
목표 파일을 만들고 현재 작업 큐를 잡았습니다. 먼저 코드 구조를 확인한 뒤 첫 구현 단계를 진행하겠습니다.
```

이어받기일 때는 아래 형식으로 시작하세요.

```md
이전 목표 상태를 읽었습니다. 남은 작업 중 가장 가까운 다음 단계를 바로 진행하겠습니다.
```

## 세션 종료 전 체크

- `current.md` 최신화
- 필요한 handoff 작성
- 검증 결과 기록
- 다음 세션 시작 문장 한 줄 남기기

마지막에는 아래 한 줄을 목표 파일 또는 handoff에 남기세요.

```md
- 다음 세션 시작 문장: `/goal 이어서`
```
