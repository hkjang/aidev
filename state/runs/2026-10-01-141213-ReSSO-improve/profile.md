# ReSSO 프로필 (2026-10-01)
- 목적: 오프라인 단일 바이너리 OIDC SSO 제공자 + 사용자·Realm 관리 콘솔. RP 구현은 포함하지 않는다(언제나 제공자 쪽).
- 스택: Go 1.26, chi v5, PostgreSQL/pgx v5, LDAP, React 19/TypeScript/MUI/React Query/Vite 7, vitest 4; CI Node 22.23.0.
- 구조:
  - cmd/resso: 서버·CLI·예약 LDAP 동기화·유지보수·메일 알림.
  - internal/httpserver: oidc.go(OIDC 전 Endpoint, **1571행**)·auth.go(로그인·세션, 435행)·middleware.go·metrics.go(119행)·server.go(`New(data, logger, trustedProxyCIDRs, metrics)`, `Server.Metrics()`:80)·admin/personal/mcp/tracking. integration_test.go는 실제 PostgreSQL + httptest를 쓰는 단일 **11829행** 파일.
  - internal/store + store/migrations: DB 접근과 자동 SQL 마이그레이션(최신 017_mail_deliveries.sql). store/oidc.go에 코드·refresh token 계열(`RedeemAuthorizationCode`:145·`RotateRefreshToken`:251·`InspectRefreshToken`:348).
  - internal/oidc(pkce.go·tokens.go), cryptoutil, password, ratelimit / federation, backchannel, mail / tracking, observability(`NewRegistry`·`Counter`·`Add`·`WritePrometheus`).
  - web/src(React), webui/dist(Go embed 산출물), scripts, docs(운영·사용·호환 정본).
- 빌드·테스트:
  - `eval "$(scripts/test-services.sh)"` 로 PostgreSQL/LDAP/LDAPS 환경변수를 잡고 **같은 셸에서** 테스트. 출력이 비면 준비 실패이므로 eval 하지 말 것.
  - `make lint`(golangci-lint v2.13.1 + govulncheck + ESLint --max-warnings 0), `make test`(go test -race ./... + vet + vitest + build; httpserver 약 110~125s / store 약 80s), `make build VERSION=vX.Y.Z`.
  - 단일: `go test -race ./internal/httpserver -run '^TestIntegration…$' -count=1 -v`.
- 관례: 영문 `fix:`/`feat:`/`docs:`/`release:` 커밋. **HEAD 8604422 = v0.9.96**(2026-09-29). 설정은 환경변수 + `platform_settings` 키별 한 행. docs/가 운영·연동 정본, README는 개발 참고. 코드 주석이 매우 길고 "왜 이 답을 골랐는가"를 서술형으로 담는다 — 새 코드도 그 밀도를 따른다. CLAUDE.md/AGENTS.md/roadmap/TODO는 없다.
- 이 저장소가 반복해 쓰는 설계 관용구(새 과제는 여기에 맞출 것):
  - **"이쪽 장애"와 "진짜 없음"을 같은 답으로 합치지 않는다.** 일곱 회차 연속 주제. 판정 헬퍼: `realmLookupFailed`(oidc.go:60)·`userLookupFailed`(oidc.go:90)·`writeUserInfoUnavailable`(oidc.go:968, stage 여섯)·`recordUnjudgedIntrospection`(oidc.go:1095, 답은 200 active=false 유지).
  - **호출자 문제는 400, 이쪽 문제는 500 `server_error`**(token Endpoint; docs/ADMIN_GUIDE.md:570). revoke만 503 `temporarily_unavailable`(RFC 7009 §2.2.1). userinfo는 401 대신 500. authorization은 500 + `resso_authorization_errors_total{stage}`.
  - **조기 거절 금지**(로그아웃): 실패해도 세션을 끝내고 트레일에 남긴다.
  - **거절의 이유를 이유 코드로**: 로그아웃의 `client_not_named`/`client_unknown`/`client_unavailable`/`uri_not_registered`/`form_unreadable`.
  - **지표 라벨 카디널리티 고정**: `methodLabel`·`routePattern`(metrics.go:88·105) 주석이 왜인지 설명한다. 미검증 입력을 라벨·로그에 넘기지 않는다. 인증 없이 도달 가능한 거절(401/400)은 세지 않는다 — operations.md:91의 `auth_time` 사고가 선례.
  - **계약이 다른 경로를 하나로 통합하지 않는다**: 같은 `InspectRefreshToken` 실패가 refresh 그랜트/introspection/revocation에서 각각 500/200/503을 내는 것은 의도다.
- 지표 계열 전체(metrics.go:13-56): requests·request_duration·tokens_issued·**token_errors{grant_type}**·login_attempts·client_auth_failures·**introspection_errors{stage}**·**userinfo_errors{stage}**·**authorization_errors{stage}**·silent_authentications{result}·logout_notices·federation_sync. `errors_total` 계열 넷은 이제 모두 존재한다.
- 위험 구역: auth.go(세션·쿠키·로그인 계약), oidc.go의 토큰·로그아웃 경로, middleware.go의 CSRF/API 키 예외, internal/store/migrations, .github/workflows/release.yaml.
- 자주 깨지는 곳: gofmt 정렬(lint 첫 실행), 빌드가 바꾸는 webui/dist/index.html(되돌릴 것), LDAPS bind mount와 CA 경로 불일치, 추측한 HTTP 상태 코드, 유지보수 SQL 문장 순서를 잠근 store 테스트(TestIntegrationTheRetentionSweepSaysOnlyWhatItSkipped).
- 검증 함정:
  - 환경변수가 없으면 연동 테스트가 SKIP인데도 종료 코드는 0이다. `make test` 끝의 "integration test(s) did not run" 경고 유무를 눈으로 확인할 것.
  - make test는 SKIP 집계용으로 연동 명령을 한 번 더 돌린다(중복 실행, 약 2분).
  - CI verify는 세 서비스를 준비하지만 release.yaml은 PostgreSQL만 준비한다. CI lint는 npm 설치 전에 돌고, 로컬 make lint는 GO_PACKAGES로 vendored Go를 제외한다.
  - 로그 단언은 `lockedBuffer`(integration_test.go:7287, 사용처 여섯). 지표는 `observability.NewRegistry()`를 `New(data, logger, nil, metrics)`에 넘기거나, **`New`가 nil이면 스스로 등록기를 만들므로**(server.go:64-68) `srv.Metrics()`로 읽어도 된다(v0.9.96이 증명). `Registry.Add`는 등록되지 않은 이름을 조용히 버린다.
  - 저장소 장애 재현은 테이블 RENAME으로 한다(선례 2898·3700·7144·8092·10414 — `users`·`realms`·`clients`·`refresh_tokens`·`user_roles`/`user_client_roles`). **`t.Cleanup` 또는 즉시 복구 필수** — 빠지면 뒤따르는 테스트가 전멸한다. RENAME으로 도달할 수 없는 지점도 있다(같은 테이블을 더 앞에서 읽는 호출이 먼저 잡히는 경우 — `RotateRefreshToken`이 그 예).
  - 코드 교환 테스트는 `/auth` 302의 `Location`에서 코드를 채굴한다(선례 integration_test.go:1174-1202, PKCE 포함). 코드 수명 90초(store/oidc.go:152-157).
  - Docker는 이 환경에서 실행 가능(2026-09-21). 기존 컨테이너 재사용만 검증됐고 깨끗한 환경의 신규 생성·삭제는 미확인.
- 최근 완료(반복 금지): userinfo_errors{stage}(eb3972d, v0.9.96), refresh 토큰 조회 장애 500(99c05e2, v0.9.95), 계정 조회 장애 500(9ac4615, v0.9.94), Realm 조회 장애 500(b762ea8, v0.9.93), CORS 조회 실패 기록(5b260c7, v0.9.92), 로그아웃 form_unreadable(87f4ce9, v0.9.91), 로그아웃 리다이렉트 드롭 이유(ee75261, v0.9.90).
