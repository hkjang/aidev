IdP 에 이미 로그인한 사람이 DartFly 로그인 화면을 거치지 않고 바로 들어오게 했고, 성공 응답에 실려 나가던 드라이버 오류 원문을 걸렀습니다.

**IdP 세션이 있으면 자동 로그인 (SSO `auto_login`)**

Keycloak 등 OIDC 공급자에 세션이 살아 있는 사람이 DartFly 를 열면, 로그인 화면을 그리기 전에 IdP 로 `prompt=none` 을 보내 조용히 로그인합니다(OIDC 표준의 silent authentication). 세션이 없으면 IdP 가 `login_required` 를 돌려주는데, 그것은 실패가 아니라 평범한 대답이므로 오류 없이 로그인 화면으로 보냅니다.

| 상황 | 동작 |
| --- | --- |
| IdP 세션 있음 | 로그인 화면 없이 바로 들어옴(깊은 링크는 `return_to` 로 그 자리에 돌아감) |
| IdP 세션 없음 | 평소 로그인 화면 |
| 스스로 로그아웃 | 다시 로그인할 때까지 자동 시도 안 함 |
| 저장소를 읽지 못하는 브라우저(사생활 보호 모드) | "이미 시도했다"로 쳐 막히는 쪽으로 실패 |

무한 리다이렉트는 세 겹으로 막습니다. (1) `sessionStorage` 에 한 탭 세션에 한 번만 시도한 표시, (2) 스스로 로그아웃하면 억제하고 다시 세션이 생기면 해제, (3) 콜백이 거절을 받으면 `/login?sso=none` 으로 보내 주소에도 표시. `return_to` 는 `/` 로 시작하고 `//` 로 시작하지 않는 같은 출처 경로만 받습니다.

관리 화면 SSO 설정에 **IdP 세션이 있으면 자동 로그인**(`auto_login`)을 두었고 기본은 **꺼짐**입니다. 서버는 이 설정이 꺼져 있으면 `?prompt=none` 이 붙어 와도 평범한 로그인으로 바꾸므로, 기본 설치에서는 아무것도 달라지지 않습니다. `df_sso_config` 에 `auto_login` 컬럼이 더해집니다 — 새 설치는 CREATE TABLE 로, 기존 설치는 기동 시 컬럼이 없을 때만 ALTER 로 얻습니다(실제 MariaDB 에서 두 경로 모두 확인). 설정 변경 감사 기록에도 `auto_login` 이 남습니다. 설정과 동작은 관리자 가이드(`docs/ADMIN_GUIDE.md`)에 적었습니다.

**성공 응답에 실리던 드라이버 오류 원문**

오류 응답은 `writeProblem` 안에서 걸러지지만, 오류를 성공 응답의 필드에 담는 곳들은 그 길을 지나지 않아 원문이 그대로 화면까지 나갔습니다. 대시보드의 DB 상태 위젯이 그랬습니다 — 대상 DB 주소뿐 아니라 사내 DNS 서버 주소까지 드러났습니다.

| | 이전 |
| --- | --- |
| DB 상태 | `dial tcp: lookup no-such-db.invalid on 10.255.255.254:53: no such host` |
| DB 상태 | `dial tcp 127.0.0.1:59999: connect: connection refused` |

응답으로 나가는 여섯 자리(대시보드 DB 상태, SQL 검증, 마스킹 미리보기, AI 스트림 세 곳)를 같은 거름망으로 지나가게 했습니다. 같은 자리가 새로 생기는 것을 막으려고 AST 로 서버 패키지를 훑어 `err.Error()` 가 거름망 없이 응답으로 나가는 호출을 찾는 테스트를 넣었습니다. 대시보드 고침만 되돌리면 이 테스트가 그 줄을 정확히 짚는 것을 확인했습니다.

**검증**: gofmt · go vet · `go test -race ./...` 38개 패키지 통과, JS 테스트 12건 통과. 배포 이미지를 실제 MariaDB 와 함께 띄워 healthz/readyz · 임베드 정적 자산 · 로그인 · 내장 마스터 키로 질의 실행 · TZ 적용까지 확인했습니다.
