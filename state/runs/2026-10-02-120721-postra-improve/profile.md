# postra 프로필 (2026-10-02)
- 목적: 개인·사내 POP3/IMAP/SMTP 메일 수집·검색·분석·작성·승인 발송과 AI·팀 업무를 REST/CLI/MCP/React 로 제공하는 자체 호스팅 서비스. 확인 베이스 main@1d382aa, v0.25.1(이전 프로필의 v0.23.9 는 폐기).
- 스택: Go(go.mod 1.25.0 계열, CI 툴체인 1.26.x; 로컬 실행은 이전 회차 기준 go1.26.7), SQLite/pgx PostgreSQL·pgvector, React 19/TypeScript/Vite, Vitest·Playwright, Node >=22.12.
- 구조:
  - cmd/postra: 서버·CLI 진입점. cmd/postra-contracts: API 계약 생성·`-check`.
  - internal/domain: 엔티티·포트. `inbound_error.go` 가 이제 핵심 — `InboundError{Stage,Command,Class,Code,Elapsed,Timeout}`, `WrapInbound`(안쪽 단계가 이김), `ClassifyInbound`, `InboundRejected{Code}`(원문 금지, RFC 5530/3206 토큰만), `TemporaryRefusal`, `AuthError`. `job.go` 에 `SyncDiagnostic`.
  - internal/application: `sync.go`(679줄, runSync·ingestOne·fetchRaw), `sync_diagnostics.go`(599줄, 한국어 요약 조립 + 읽기 시 재검증), `app.go`(dialInbound), 계정·설정·OIDC·승인·워커.
  - internal/adapters/{pop3(381줄+테스트 652줄),imap(791줄+테스트 1161줄, mailbox.go),smtp,ai,mailparse}.
  - internal/adapters/{persistence,pgstore,secretstore,objectstore}; internal/transport/{httpapi,mcpserver,spa}; internal/platform; internal/mailrender.
  - web/ React 소스, api/ 생성 계약, docs/(SYNC_DIAGNOSTICS.md 포함), docs/releases/.
- 빌드·테스트: `go build ./...`; `go vet ./...`; `go test -race ./...`(전체 수 분). 이번 정찰 실측: `go test -race -count=1 -timeout=180s ./internal/adapters/pop3/` → ok 3.206s.
- 빌드·테스트: `go run ./cmd/postra-contracts -check`(읽기 전용 계약 검사). `make lint` = lint-format(gofmt) + lint-security(gosec v2.28.0 -severity medium -exclude-dir=scripts). `make test` 는 전체 race.
- 빌드·테스트: 프런트는 `cd web && npm ci --no-audit --no-fund`, `npm run typecheck`, `npm test`, `npm run build`; 프런트 변경은 `internal/transport/spa/assets` 재생성 필요(CI 가 드리프트를 잡는다).
- 관례: 영어 conventional commit + 본문에 사유, `Co-Authored-By: Claude …`. 릴리즈는 자산 재빌드 → 버전 범프 → docs/releases 노트 → 주석 태그 → GH Actions.
- 관례: 어댑터 동작은 손으로 만든 대역 없이 `net.Listen("tcp","127.0.0.1:0")` 스크립트 서버 + 실제 `Dialer`/실제 DialOptions 로 증명한다.
- 관례: 프로토콜 상한은 근거 주석이 붙은 상수(`maxListBytes` 32MiB, `listLineOverhead` 2+16, IMAP `maxLineBytes` 1MiB·`maxResponseBytes` 8MiB·`maxResponseLiterals` 64)와 정상 경로 실측 테스트를 함께 둔다.
- 관례: 진단 문자열은 한국어이며 메일 서버 원문을 절대 담지 않는다 — 단계·분류 레이블, 숫자, 허용된 RFC 응답 코드만. 새 텍스트를 늘리기보다 필드를 바르게 채운다.
- 위험 구역: OIDC·browser_auth·session·MCP OAuth/DCR·DB migrations·SecretStore/KEK·승인 토큰·.github/workflows·spa/assets.
- 위험 구역: SMTP DATA 후 응답 유실은 Uncertain 으로 두고 자동 재발송 금지(이전 기록 기반, 이번에 SMTP 코드는 미열람).
- 위험 구역: IMAP IDLE 와 동기화가 계정당 **동시에 한 연결만** 쓰도록 1d382aa 가 고쳤다(서버의 계정당 연결 제한 때문). IDLE/워치 코드를 건드릴 때 두 번째 연결을 다시 만들지 말 것.
- POP3 현황(이번에 client.go 전체를 읽고 확인): `readList` 는 maxListBytes 로 묶였다. `retrBody`(:321)는 무제한 `bytes.Buffer` 이고 루프 **안** 에 `s.deadline()` 이 있어 `.` 없는 RETR 이 워커를 붙잡는다. `Retrieve`/`Top` 은 `WrapInbound(..., 0, ...)` 로 경과 0 을 넘기고 `Top` 은 동사를 "RETR" 로 적는다. 모든 세션 메서드가 `ctx` 를 받고도 쓰지 않는다. `Top` 은 프로덕션 호출자 없음.
- POP3 현황: `loginFailure` 는 비일시적 `InboundRejected` 만 `AuthError` 로 감싼다 — 타임아웃·끊김·[IN-USE]/[LOGIN-DELAY]/[SYS/TEMP] 는 credential_error 가 아니다. 인사말은 connect 예산, 명령은 commandTO.
- 미병합 영역: 04b15be / PR #22(POP3 MaxMessageBytes). 사람 반려 여부 **미확인** — 이번 회차 `gh` 호출이 승인되지 않았다. 확인 전에 같은 접근 재제출 금지.
- 자주 깨지는 곳: 브랜치 성공과 main 반영 혼동(`git merge-base --is-ancestor` 로 확인). 러너 세션 중단을 Actions 릴리즈 실패로 오인하지 않기. locked 워크트리는 러너 wt_reset 이 복구하며 정찰은 작업 트리를 고치지 않는다.
- 검증 함정: PG 검사는 `POSTRA_TEST_PG`+pgvector, 브라우저 검사는 Chromium 필요 — 전체 Go 성공만으로 이들이 돌았다고 하지 않는다.
- 검증 함정: README `govulncheck @latest` 와 CI `@v1.6.0` 불일치(이전 기록, 이번 미확인). CI 에 포맷 검사가 없고 `make lint-format` 이 별도.
- 검증 함정: 서버 핸들러 종료/timeout 은 클라이언트 EOF 와 다르다. 실제 읽기 결과를 채널로 단언하고 cleanup 이 먼저 닫아 거짓 통과시키지 않게 한다.
- 검증 함정: 60초 기본 commandTO 를 기다리는 테스트는 `CommandTimeoutSec` 를 작게 준 DialOptions 로 줄인다(테스트 타임아웃 회피).
