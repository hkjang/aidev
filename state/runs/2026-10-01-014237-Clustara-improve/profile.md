# Clustara 프로필 (2026-10-01)
- 목적: 폐쇄망 Kubernetes 운영 허브 — 멀티 클러스터 수집·장애/보안/용량/비용 분석·승인 액션·LLM/MCP 프록시·Mattermost 알림.
- 스택: Go 단일 모듈 `clustara`(go.mod 1.25), net/http, 기본 SQLite(modernc)·PostgreSQL 지원, 선택 ClickHouse, 인라인 바닐라 JS 한국어 SPA(`internal/proxy/admin_ui.go`). CI 워크플로 없음(`.github` 는 FUNDING.yml 뿐) — 로컬 게이트가 전부.
- 구조:
  - `cmd/` — clustara(서버)·clustara-cli·clustara-agent·api-surface-audit.
  - `internal/proxy/` — HTTP mux(`server.go:Routes`)와 admin_* 핸들러, `admin_ui.go` SPA, MCP/SSO·Mattermost(`mattermost.go`)·DW 조립. 가장 큰 패키지이자 대부분의 회차가 여기서 끝난다.
  - `internal/analyzer/` — 순수 분석 함수와 단위 테스트(rca.go·security.go·capacity.go·cost.go·workload.go·node_monitoring.go).
  - `internal/store/` — SQLStore. `sqlstore.go` 가 DDL, `k8s.go` 가 인벤토리/이벤트/리비전 조회, `k8s_meta.go` 가 알림 dedup·네임스페이스 소유.
  - `internal/kube/`, `internal/collector/` — K8s 객체 변환(`InventoryFromObject`)·수집·exec. `internal/action/` — 승인 영향도.
  - `docs/` — ADMIN_GUIDE·USER_GUIDE·K8S_OPERATIONS_HUB 가 정본. K8S_PHASE2_PLAN.md·ARCHITECTURE_MODULES.md 는 오래됐으니 코드 우선.
- 빌드·테스트: `go test ./internal/proxy -run '<패턴>' -count=1`(좁게, 1~2s) → `gofmt -l <손댄 파일>` → `go build ./...` → `go vet ./...` → `go test ./... -count=1`(전체 약 80s, proxy 단독 약 60~75s). 이번 정찰에서 `go test ./internal/proxy -run 'NotifyScan|K8sNotify' -count=1` → `ok 1.333s` 실행 확인.
- 관례: 영어 `fix(scope)`/`feat(scope)` 커밋, 릴리즈는 별도 `chore: release vX`. 런타임 설정은 DB 플래그(`SetFlag`/`flagValue`)와 설정 레지스트리·환경변수. SQLite/PG 호환 bind·`CREATE TABLE IF NOT EXISTS`. 코드 주석은 영어(결함의 배경을 서술체로 길게 적는 것이 이 저장소 스타일), UI 문구는 한국어. 테스트에서 조정해야 하는 상수는 패키지 `var` 로 뺀다(`k8s_notify.go:143 notifyScanBudget` 가 선례).
- 위험 구역: `proxy/server.go:currentAccessClaims`·`mcp_oauth.go`·`keycloak*.go` 인증, `analyzer/policy.go` Deny 게이트, `store/sqlstore.go` DDL, DW fact 스키마. `analyzer/security.go:restrictedProfileViolations` 는 포스처 표와 `enforce_pss_restricted` 게이트 공용이라 파급이 넓다.
- 자주 깨지는 곳:
  - 전 클러스터 입력을 namespace/name/nodeName 단독으로 조인·dedup 하던 경로는 v0.9.285~0.9.287 과 5b98765 로 대체로 정리됐다.
  - **조회 창(window) 계약**이 현재의 주 결함군이다: 어떤 경로는 잘림을 보고하고(`/admin/k8s/security`, notify scan 인벤토리) 어떤 경로는 조용히 자른다.
  - 부수효과 순서(전달 판정 전에 dedup 창을 claim)는 v0.9.288 에서 고쳤다.
- 검증 함정:
  - **스토어 하드 상한**(2026-10-01 신규 확인): `store/k8s.go:1082 boundedLimit(value, fallback, max)` — 이벤트 max **500**(k8s.go:684), 리비전 max **1000**(k8s.go:1213), 인벤토리 max **10000**(k8s.go:583). 호출자가 2000 을 요청해도 조용히 깎인다. 따라서 인벤토리에서 쓴 "상한+1 요청으로 잘림 감지" 트릭은 events·revisions 에 복사되지 않는다.
  - `mattermostConfig` 스냅샷은 15초 캐시(`mattermostSnapshotTTL`) — 테스트에서 플래그를 바꾸면 `server.invalidateMattermostCache()` 필수.
  - Mattermost 전송은 `go func` 비동기 — httptest webhook 수신은 채널+`time.After`, 미전송 증명은 `select ... default`.
  - proxy 테스트 표준 배선: `openTestStore(t)`(t.TempDir SQLite) + `store.NewAsyncLogger` + `NewServer(testConfig(...))`(스케줄러 비활성) + `httptest.NewServer(server.Routes())` + `postJSON`. `s.db` 는 구체 타입이라 조회 오류 주입 지점이 없다(대역 만들지 말 것).
  - 빈 `ClusterID` 는 wildcard 가 아니라 독립 식별자다. 기존 분석기 fixture 는 대개 단일 클러스터라 교차 오염을 못 잡는다.
  - `internal/proxy/docs_reference_test.go`·`release_gate_test.go` 가 docs 의 API 경로·버전 마커를 검사한다 — 무관한 문서/버전 편집 금지. gofmt 는 수정한 파일에만.
  - 스캔 응답 테스트는 키 단위 조회(`out["truncated"] != true`)를 쓰고 맵 전체 비교를 하지 않는다 — 응답에 필드를 더해도 기존 테스트는 깨지지 않는다.
  - SQLite·httptest 통과는 실 PostgreSQL·실 Kubernetes·Keycloak·ClickHouse·브라우저 검증을 대신하지 않는다(모두 상시 미확인).
- 정찰 범위(2026-10-01 회차): `git log -12`, `internal/proxy/k8s_notify.go` 전문, `internal/store/k8s.go` 의 ListK8sInventory/ListK8sEvents/ListK8sRevisions/boundedLimit, 이벤트·리비전 호출자 전수 grep, 테스트 파일 목록. base main@ffaeb11(v0.9.292), 작업 트리 변경 없음.
