# postra 프로필 (2026-09-21)
- 목적: 개인·사내 POP3/IMAP/SMTP 메일을 수집·검색·작성·발송하고 AI·팀 업무를 REST/CLI/MCP/React로 제공하는 자체 호스팅 서비스. 확인 베이스 main@0356555, v0.23.1.
- 스택: Go 모듈 go 1.25.0, toolchain go1.26.6(CI 1.26.6; 이번 로컬 실제 1.26.7); SQLite/pgx PostgreSQL·pgvector; React 19/TypeScript/Vite, Vitest/Playwright; Node >=22.12.
- 구조:
  - cmd/postra: 단일 서버·CLI; cmd/postra-contracts: API 계약 생성/-check.
  - internal/domain: 엔티티·포트·SecretHandle·발송/수신 옵션.
  - internal/application: 계정·수집·발송·승인·설정·OIDC·작업/리더 워커 유스케이스.
  - internal/adapters/{pop3,imap,smtp,ai,mailparse}: 외부 프로토콜; smtp/client_test.go는 실제 TCP 릴레이, pop3는 테스트 없음.
  - internal/adapters/{persistence,pgstore,secretstore,objectstore}: DB·비밀·MIME/첨부 저장.
  - internal/transport/{httpapi,mcpserver,spa}: HTTP/MCP·OAuth 프록시·임베드된 React 자산.
  - internal/platform: config·crypto·tracking·telemetry 등 공용 기능.
  - web/: React 소스·npm 잠금 파일; api/: 생성 계약; docs/: 가이드·설계·releases/.
- 빌드·테스트: `go build ./...`, `go vet ./...`, `go test -race ./...`(전체 수 분 가능); `make test`는 race 테스트만 실행하며 build/vet는 포함하지 않음.
- 빌드·테스트: `go run ./cmd/postra-contracts -check`; `cd web && npm ci --no-audit --no-fund && npm run typecheck && npm test && npm run build`.
- 빌드·테스트: `make build`는 프런트 설치/빌드 후 바이너리 생성. `make build-offline`은 GOPROXY=off/GOTOOLCHAIN=local, 사전 모듈·도구 캐시 필요.
- 보안 검사: `go run github.com/securego/gosec/v2/cmd/gosec@v2.28.0 -severity medium -exclude-dir=scripts ./...` 이번 정찰 exit 0·Issues 0. 현재 lint 타깃은 없음(이번 구현 과제).
- 이번 검증: `go test -race ./internal/adapters/smtp ./internal/adapters/pop3` SMTP 캐시 통과/POP3 no test files; `gofmt -l ./cmd ./internal` 빈 출력. 전체 Go·프런트·PostgreSQL·브라우저는 이번 미실행.
- 관례: 최근 커밋 영어 conventional, 일부 과거 한국어. 설정 카탈로그·환경 바인딩과 비밀 참조 사용; SQLite/PostgreSQL 이중 스키마 유지. 문서는 docs/·릴리즈 docs/releases/.
- 관례: React 변경 후 internal/transport/spa/assets 재생성·커밋 필수; CI가 미추적 파일까지 git status로 검사. gosec 예외는 근거 있는 #nosec만 허용.
- 위험 구역: application/oidc*.go·transport/httpapi/browser_auth.go 및 auth/session, mcpserver OAuth/DCR, persistence/pgstore 마이그레이션, secretstore·KEK·승인 토큰, workflows, spa/assets.
- 위험 구역: SMTP DATA 이후 응답 유실은 Uncertain으로 자동 재발송 금지. main의 SMTP는 dial 이후 데드라인 없음; 이전 회차 수정은 review-pending이며 아직 이 베이스에 없음.
- 자주 깨지는 곳: notifymail/handoff 성공 기록과 main 상태 혼동. 이번에도 internal/web/src에 구현 없음; 별도 브랜치 cherry-pick 재시도 금지.
