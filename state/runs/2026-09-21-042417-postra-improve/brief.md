- 과제: Makefile에 CI 고정 버전의 gosec·읽기 전용 포맷 검사 타깃 추가 (가치 3 / 위험 1 / 작업량 S)
- 왜: main@0356555의 Makefile에는 보안 검사 타깃이 없고 README의 로컬 gosec 예시는 @latest여서 CI의 v2.28.0과 다르게 검사한다. v0.23.0의 gosec 실패가 후속 PR까지 막았던 이력을 바탕으로, 한 명령으로 동일 버전·검사 범위를 실행하고 실패를 그대로 전달해 푸시 전 결함 발견을 쉽게 한다.
- 수용 기준: 1) 저장소 루트에서 `make lint`가 포맷 검사와 `go run github.com/securego/gosec/v2/cmd/gosec@v2.28.0 -severity medium -exclude-dir=scripts ./...`를 실행하고 현재 베이스에서는 성공한다. `lint-format`, `lint-security`를 각각 실행할 수 있게 하고 `.PHONY`에 등록하며 기존 기본 타깃 build 및 모든 기존 타깃의 동작을 보존한다. 2) 포맷 검사는 최소 cmd/·internal/ 아래 Go 파일을 읽기만 하며 위반 경로를 출력하고 nonzero를 반환한다(단순 gofmt -l 자체는 위반에도 0이므로 출력 유무를 검사해야 함). gofmt 실행 오류도 숨기지 않으며 gosec 탐지·실행 실패 역시 성공으로 삼키지 않는다. 검사 중 소스·go.mod/go.sum·번들에 변경이 없어야 한다. 3) 실제 Make 타깃을 정상 트리에서 실행하고, 격리된 임시 복제본에서 포맷 위반 Go 파일 및 실제 gosec medium+ 지적을 각각 만들어 해당 타깃이 실패하는 것을 입증한다. 대역 실행파일이나 소스 문자열 검사만으로 입증하지 않는다. 임시 입력은 지우고 원본 git status가 그대로임을 확인한다. README의 gosec @latest 예시는 새 타깃으로 바꾸고, 최초 실행에 도구/모듈 다운로드가 필요할 수 있음과 lint가 전체 CI를 대체하지 않음을 설명한다.
- 건드릴 파일: `Makefile`의 GO/NPM 변수·.PHONY·test 주변 — lint/lint-format/lint-security 타깃 추가(기존 첫 기본 타깃을 바꾸지 말 것); `README.md`의 「CI · 공급망 보안 (§20.3)」/「로컬에서도 동일 검사 실행」 — gosec 실행 안내를 Make 타깃과 일치시킬 것. `.github/workflows/ci.yml`의 gosec/Install gosec/Scan은 읽기 전용 기준이다. 이 과제는 Go 함수 변경이 없다. 차선 근거로 실제 읽은 함수는 `internal/adapters/pop3/client.go`의 Dialer.Dial, session.List/UIDL/Retrieve/Top/Delete/Quit/retrBody, `internal/adapters/smtp/client_test.go`의 fakeRelay, recorded, selfSigned이다.
- 검증 명령: 정찰에서 실행 완료: `go run github.com/securego/gosec/v2/cmd/gosec@v2.28.0 -severity medium -exclude-dir=scripts ./...` → exit 0, 138 files, Issues 0; `gofmt -l ./cmd ./internal` → 빈 출력; `go test -race ./internal/adapters/smtp ./internal/adapters/pop3` → SMTP 통과(캐시), POP3 [no test files]. 구현 후 새 명령: `make lint-format`, `make lint-security`, `make lint`, `make -n test`, `git diff --check`, `git status --porcelain` 및 위 수용 기준의 실제 임시 입력 실패 검증. 새 Make 타깃은 아직 없으므로 정찰에서 실행한 것으로 기록하지 말 것. 프로젝트 전체 회귀가 러너에서 요구되면 `go build ./...`, `go vet ./...`, `go test -race ./...`, `go run ./cmd/postra-contracts -check`를 사용한다(이번 정찰에서는 전체 미실행).
- 위험과 피할 것: auth/session·migrations·.github/workflows·Go 런타임 코드·프런트/번들·의존성 버전은 건드리지 않는다. 전역 GOBIN/PATH/config를 덮어쓰거나 go install로 기존 전역 바이너리를 교체하지 말고 버전 지정 go run을 사용한다. SARIF 파일을 생성할 필요는 없으며 CI와 맞춰야 하는 것은 버전·severity·exclude-dir·패키지 범위이다. 검사 우회를 위한 규칙 제외나 #nosec 추가 금지. gofmt는 -w 없이 검사만 한다. 셸의 명령 치환 실패가 test/echo 뒤에 가려지지 않도록 한다. 로컬 go는 1.26.7이고 CI는 1.26.6이므로 완전 동일 환경이라고 주장하지 않는다. SMTP 타임아웃은 지난 회차 review-pending이며 현재 베이스에 없지만 재구현·cherry-pick하지 않는다.
- 차선 후보: POP3 실제 TCP 어댑터 회귀 테스트 — 1순위가 이미 구현되어 있거나 성립하지 않을 때만 선택(가치 2 / 위험 1 / M). `internal/adapters/pop3/client_test.go` 하나에서 127.0.0.1 net.Listen 서버를 통해 실제 Dialer.Dial과 세션 메서드로 무인증/USER·PASS/AuthError, LIST·UIDL·RETR의 dot-unstuffing·DELE·QUIT을 검증한다. SMTP의 recorded/cleanup 패턴만 참고하고 공용 픽스처 리팩터링은 하지 않는다. 우선 평문 프로토콜 범위로 45분을 지키고 production client.go는 수정하지 않는다. 검증은 `go test -race -count=3 -timeout=60s ./internal/adapters/pop3`.
