release: ReSSO v0.9.97

`cd web && npm test` had been failing at worker startup, and 26 of the 29 test
files were never collected, so the run that gates every merge exited 1 on a
tree whose tests were all sound. The error was TypeError:
webidl.util.markAsUncloneable is not a function, thrown out of
undici/lib/web/cache/cachestorage.js:20 by way of the module-load-time
require("undici") in jsdom/lib/api.js:12. Neither web/package.json nor
web/package-lock.json had moved since v0.9.92, so the dependency set was not
what changed: what changed was which Node the test runner got.

npm, when it runs a script, prepends the node_modules/.bin of every ancestor
directory of the cwd to PATH. A `node` npm package at version 20.19.2 was
installed into a home-level node_modules on 2026-09-30, which created a
.bin/node symlink there, and node_modules/.bin/vitest is a shebang script —
#!/usr/bin/env node — so it resolved that shim and vitest ran on Node 20.19.2
rather than the 22.23.x this project pins. worker_threads.markAsUncloneable was
added in Node 22.10.0; under Node 20 undici assigns undefined to
webidl.util.markAsUncloneable, and jsdom throws the moment its environment is
loaded in a worker. jsdom 30.0.1 declares engines ^22.22.2 || ^24.15.0 ||
>=26.0.0, so Node 20 was never a Node it supports.

Every script in web/package.json now puts the directory of npm's own Node at
the front of PATH. $npm_node_execpath is the node executable running npm, which
npm sets for every script, and ${npm_node_execpath%/*} is its directory — POSIX
parameter expansion, no subshell. The bin shims are still resolved from the
local node_modules/.bin exactly as before; the only thing pinned is the
interpreter they pick up. build is wrapped in sh -c so the prefix covers vite
build as well as tsc --noEmit rather than just the first command.

No dependency or lockfile edit was made: undici 8.10.0 is not at fault and
downgrading it would have hidden a wrong-Node problem rather than fixed it, and
npm ci installs the same tree it did before. The Node pin in the workflows
stays at 22.23.0, test.pool in vite.config.ts is untouched, and no test
assertion was changed — the runtime was broken, not the tests. No engines field
was added either: the lockfile records none for the root package, so it would
pull in a regeneration for a field that only warns and would not have caught
this, npm itself having been on the right Node the whole time.

Nothing that runs in production changed. Only the script lines of
web/package.json differ, so the bundle, the server's behaviour, its responses,
its log lines and its metrics are all as they were. Stamps the version in the
Makefile, console package metadata and both compose files, with no schema or
configuration changes.
