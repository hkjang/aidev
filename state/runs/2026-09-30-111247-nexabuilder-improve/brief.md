- 과제: 수정 과제 — PR #46 의 CI 실패를 증거로 종결(코드·워크플로 원인 아님)하고, 휴지통에 넣은 목록의 `/app/*` 런타임 화면 8개가 그대로 열리는 `RuntimeUiController` 의 soft-delete 누락을 한 헬퍼로 고친다 (가치 3 / 위험 2 / 작업량 S)

- 왜: 같은 값(`NexaListDef.deletedAt`)을 읽는 다른 여섯 경로 — `NexaUiService.requireLiveList`, `DataAdapterService.queryList`, `ListExportController.resolveExportable`, `ListInlineEditController`, `BulkListController.resolveTarget`(PR #43), `ReportService.generate`(PR #44) — 는 전부 400 `List not found: {listId}` 로 거부하는데, `RuntimeUiController` 의 8개 `/app/{view}/{listId}` 화면만 `listRepository.findById(listId).orElseThrow(...)` 로 끝나 `deletedAt` 을 **전혀 보지 않는다**(8군데 모두 같은 3줄이 복제돼 있다). 운영자가 목록을 휴지통에 넣어 관리 화면·그리드·내보내기·리포트에서 모두 사라진 뒤에도 그 URL 을 북마크한 사용자에게는 제목까지 박힌 화면이 계속 열린다. 데이터 피드는 이미 막히므로 표는 비지만, 화면이 200 으로 열리고 `pageTitle` 로 목록 제목이 노출되는 것 자체가 "휴지통에 넣으면 사라진다" 는 계약과 어긋나고, 8군데 복제 때문에 앞으로 추가되는 뷰마다 같은 누락이 재발한다.

- 수용 기준:
  1) 휴지통에 넣은 목록(`deleted_at` 이 채워진 `NexaListDef`)으로 `GET /app/list/{id}`·`/app/kanban/{id}`·`/app/calendar/{id}`·`/app/tree/{id}`·`/app/map/{id}`·`/app/pivot/{id}`·`/app/gantt/{id}`·`/app/chart/{id}` 를 부르면 **살아 있지 않은 목록과 같은 응답**(`IllegalArgumentException` → `GlobalExceptionHandler:handleIllegalArgument` 가 접는 400)이 나오고, 어떤 경로도 200 + 목록 제목을 돌려주지 않는다. 8경로 전부를 한 테스트에서 루프나 `@ParameterizedTest` 로 덮을 것.
  2) 살아 있는 목록의 같은 8경로는 **수정 전과 똑같이 200** 이고 뷰 이름·`pageTitle`·`listId` 모델 속성이 그대로다(기존 `KanbanViewIntegrationTest`·`CalendarViewIntegrationTest`·`TreeViewIntegrationTest`·`MapViewIntegrationTest`·`PivotViewIntegrationTest`·`GanttViewIntegrationTest`·`ChartViewIntegrationTest` 가 이미 200 을 단언하므로 **그 파일들을 고치지 말고 그대로 통과**해야 한다 = 회귀 가드).
  3) 권한 거부(`ScreenPermissionService.canView == false` → `AccessDeniedException` → 403 + 감사 행)의 기존 동작이 유지된다. 휴지통 검사는 **권한 검사보다 앞**에 있어 휴지통 목록은 403 이 아니라 400 이 된다(다른 여섯 경로와 같은 순서 — `BulkListController.resolveTarget` 이 직전 회차에 이 순서로 고정됐다).
  4) 테스트는 "살아 있는 목록은 200, 같은 목록을 휴지통에 넣으면 400" 을 **같은 픽스처로 연속 단언**해 픽스처가 정말 이 컨트롤러 경로를 지난다는 것을 증명할 것(살아 있는 단언 없이 400 만 보면 목록이 애초에 없어서 400 인 것과 구분되지 않는다).

- 건드릴 파일 (프로덕션 **1개**):
  - `src/main/java/com/nexabuilder/web/controller/RuntimeUiController.java` — 8개 핸들러(`list:25`, `kanban:50`, `calendar:70`, `tree:91`, `map:111`, `pivot:130`, `gantt:149`, `chart:167`)가 각각 복제한 `findById(...).orElseThrow(...)` + `session.getAttribute("nexabuilder.user")` + `screenPermissions.canView(user,"LIST",listId)` 3블록을 private 헬퍼 하나(예: `requireViewableList(String listId, HttpSession session)` → `NexaListDef` 반환)로 뽑고, 그 헬퍼 안에서 `orElseThrow` **직후·`canView` 보다 앞**에 `getDeletedAt() != null` 이면 다른 여섯 경로와 **글자 단위로 같은** `new IllegalArgumentException("List not found: " + listId)` 를 던진다(이번 정찰이 `NexaUiService.requireLiveList:59-66` 을 직접 읽어 확인한 바로 그 두 줄 — `deletedAt` 은 `String`(`NexaListDef:134-135`, `@Column(name="deleted_at", length=20)`)이므로 `isBlank()` 같은 추가 판정을 넣지 말고 `!= null` 만 쓸 것. `GlobalExceptionHandler:92-95` 의 `handleIllegalArgument` 가 `ResponseEntity.badRequest().body(ApiResponse.error(ex.getMessage()))` 로 접는 것도 확인했다). 각 핸들러는 `var list = requireViewableList(listId, session);` 한 줄로 줄고 그 아래 `model.addAttribute(...)`·`return "runtime/..."` 는 **한 글자도 바꾸지 않는다**.
  - `src/test/java/com/nexabuilder/api/RuntimeUiSoftDeleteIntegrationTest.java` (신규) — 픽스처는 `PivotViewIntegrationTest.seedListWithPivot()` 과 `DataAdapterListSoftDeleteIntegrationTest` 의 목록 시드 형태를 따르고 세션 `User` 는 `PivotViewIntegrationTest` 와 같은 방식(`sessionAttr("nexabuilder.user", u)`)으로 넣는다. 휴지통 전환은 **실제 `NexaListRepository`** 로 `deletedAt` 을 채워 저장한다(직접 SQL UPDATE 나 목 금지) — `DataAdapterListSoftDeleteIntegrationTest:151` 이 쓰는 형태 그대로 `list.setDeletedAt("20260922000000"); listRepository.save(list);` (문자열 타임스탬프, `yyyyMMddHHmmss`).

  - **`.github/workflows` 를 한 줄도 건드리지 말 것.** PR #46 의 CI 실패는 이 저장소의 코드도 워크플로도 아니다 — 이번 브랜치에서 `git diff --stat master...` 와 `git diff --stat master... -- .github/ build.gradle.kts settings.gradle.kts gradle/` 가 **둘 다 빈 출력**임을 이번 정찰이 직접 실행해 확인했고, 빌드·CI 설정을 건드린 최신 커밋은 2026-09-28 의 버전 범프 `c446d24`(그 위 `ee7f786` = PR #36 은 CI 를 통과해 머지됐다)다. 원인은 2026-09-30-010003 셰퍼드 회차의 **인증된** `gh api .../jobs` 주석("The job was not started because recent account payments have failed or your spending limit needs to be increased", `steps: []`)과 2026-09-30-065545 회차의 공개/비공개 상관(PUBLIC 6곳 분 단위 success vs PRIVATE 2곳 3~9초 failure)으로 증명된 비공개 저장소 Actions 과금 차단이다. 이 세션도 `gh` 미인증이라 **잡 로그 본문은 미확인**으로 남긴다 — 추정을 사실로 쓰지 말고, 재시도·`continue-on-error`·타임아웃 완화·재제출·cherry-pick 을 하지 말 것.

  - **`/app/form/{formId}` 핸들러(`:181`)는 범위 밖.** `formRepository` 를 쓰는 다른 엔티티이고 `NexaUiService.formDefinition` 의 `includeInactive` 계약과 얽혀 있어 같은 회차에 넣으면 증거가 흐려진다(`ideas.json` 에 별 항목으로 남아 있다). 헬퍼 추출도 목록 8개에만 적용할 것.
  - **기존 7개 뷰 테스트 파일을 수정하지 말 것** — 그것이 "살아 있는 목록은 그대로 200" 의 회귀 가드다. 기대값을 고쳐 통과시키는 것은 금지.
