# Momento v0.34.62 — 배포되는 바이너리를 Go 1.26.9가 만듭니다

Momento를 설치해 운영하는 담당자와 공급망 점검을 받는 조직을 위한 보안 유지보수 릴리스입니다. 화면과 API의 동작은 달라지지 않습니다. 달라지는 것은 **이 릴리스의 이미지를 컴파일한 Go 버전**이며, 그에 따라 표준 라이브러리 권고 10건이 산출물에서 사라집니다.

## 표준 라이브러리 권고 10건으로 `govulncheck`가 막혀 있었습니다

`govulncheck`가 `net/http`·`net/textproto`·`crypto/tls`에 올라온 권고를 보고 실패하고 있었습니다.

| 항목 | 값 |
|---|---|
| 권고 | `GO-2026-6603`·`6605`·`6607`·`6608`·`6609`·`6610`·`6611`·`6612`·`6613`·`6617` |
| 영향받는 패키지 | `net/http`, `net/textproto`, `crypto/tls` (모두 Go 표준 라이브러리) |
| 발견된 버전 | `go1.26.7` |
| 고쳐진 버전 | `go1.26.9` |

지목된 것이 서드파티 의존성이 아니라 **표준 라이브러리**이므로, 올릴 대상은 `go get`으로 갱신할 패키지가 아니라 toolchain 자체였습니다. `go.mod`의 `toolchain`을 `go1.26.7`에서 `go1.26.9`로 올렸습니다.

이 실패는 특정 기능 변경이 만든 것이 아니라 권고가 공개된 시점에 묶인 것입니다. 이전 릴리스 `v0.34.61`의 트리를 그대로 검사해도 같은 10건이 보고됩니다.

## `go.mod`만 올리면 운영자에게 가는 바이너리는 그대로입니다

Go 버전은 두 곳에 적혀 있고, CI가 읽는 것은 그중 하나뿐입니다.

- `go.mod`의 `toolchain` — `actions/setup-go`가 읽는 값이고, 따라서 CI의 `govulncheck`가 측정하는 값입니다.
- `Dockerfile`의 `FROM golang:…` — **릴리스 이미지의 바이너리를 실제로 컴파일하는** 값입니다.

CI는 이미지 빌드 단계 전까지 Dockerfile의 toolchain으로 컴파일하는 일이 없습니다. 그래서 `go.mod`만 올리면 **CI는 녹색이 되지만 배포되는 바이너리는 여전히 `golang:1.26.7`이 만든 것**이고, 권고가 짚은 코드가 그대로 실려 나갑니다. 이번 릴리스는 두 선언을 함께 `1.26.9`로 올렸습니다.

그 반쪽 수정을 막는 회귀 테스트 `internal/version/toolchain_test.go`가 추가되었습니다. 판정 기준은 「toolchain이 최신인가」가 아닙니다 — 그런 기준은 읽히지 않은 채 숫자만 갱신되기 쉽습니다. 기준은 **「두 선언이 일치하는가」**이며, 다음에 누군가 한쪽만 고쳤을 때에만 실패합니다.

언어 버전 지시자 `go 1.26.0`은 요구 최소 버전이고 이번 권고와 무관하므로 그대로 두었습니다.

## 확인

- Go: 로컬 PostgreSQL 17을 연결한 `go test -race -count=1 ./cmd/... ./internal/...`와 `go vet ./cmd/... ./internal/...` 통과. 서비스·콘솔·SDK 버전 및 Compose 이미지 이름 일치 검사, 새 toolchain 일치 검사를 포함합니다. 별도 부하 테스트는 `MOMENTO_LOAD_POSTGRES_DSN`을 지정하지 않아 실행하지 않았습니다.
- `govulncheck`: **코드가 호출하는 취약점 0건**(이전에는 표준 라이브러리 10건으로 실패). 가져오는 패키지 4건·필요 모듈 20건의 비호출 취약점은 별도로 보고되었습니다.
- SDK: `npm ci`·`npm audit`(취약점 0건)·typecheck·테스트 **29건**·build 통과.
- 콘솔: `npm ci`·`npm audit`(취약점 0건)·`npm run lint`·테스트 **259건**·프로덕션 빌드 통과. 이번 릴리스에 콘솔 코드 변경은 없어 테스트 수는 그대로입니다(259건). 빌드의 500 kB 초과 청크 경고는 남아 있습니다.
- 프로덕션 이미지 빌드 통과. 수정이 산출물까지 닿는지 추론하지 않고 측정했습니다 — 빌드한 이미지에서 바이너리를 꺼내 `go version`으로 확인한 결과 **`go1.26.9`**입니다.
- 빌드한 이미지를 PostgreSQL 17과 함께 기동해 마이그레이션·`/health/ready`·버전 응답(`0.34.62`)·콘솔 서빙·부트스트랩 로그인을 확인했습니다. 배포용 아카이브 자체의 로드·checksum·기동 검사는 태그 푸시 후 기존 릴리스 워크플로가 수행합니다.

## 범위와 배포

변경된 파일은 `go.mod`, `Dockerfile`, 새 테스트 `internal/version/toolchain_test.go` 세 개와 버전 선언입니다. 서버·API·콘솔의 동작, 요청 본문, 데이터베이스 마이그레이션, 설정 항목은 바뀌지 않습니다. `.github/workflows/*.yml`은 한 줄도 바뀌지 않았습니다. **사용자가 새로 할 일은 없고, 화면에서 달라지는 것도 없습니다.**

이번 개선은 Tier 3로 릴리스 노트에만 안내합니다. 기존과 같이 태그 푸시 후 GitHub Actions가 `momento:v0.34.62`를 빌드하고, 오프라인 아카이브 `momento-v0.34.62.tar.gz`와 `.sha256`을 로드·기동 검증한 뒤 Release에 첨부합니다. 설치 절차는 `docs/OFFLINE.md`를 따릅니다.

배포 담당자는 확대 적용 전에 프로필 메뉴의 버전이 `0.34.62`로 보이는지, `/api/v1/version`이 같은 값을 답하는지, 로그인과 이벤트 수집이 평소대로 동작하는지 확인합니다. 컴파일러 버전 변경은 기능이 아니라 산출물 전체에 영향을 주므로, 첫 적용 후 24시간 동안 **수집 오류율과 5xx 응답**을 평소 수준과 비교합니다. 평소 대비 상승이 확인되면 확대 적용을 중단하고 배포 담당자가 이전 `momento:v0.34.61` 이미지로 되돌립니다. 이 세션에서는 실제 배포와 운영 환경 확인을 수행하지 않습니다.
