# 수리 요약 — PR #14 (커밋 23a78df)

1. **Host 로 만든 aud (재현됨: 임시 테스트로 200 tools/list 확인)** — `mcpResource` 의 r.Host 폴백을 제거. `active()` 가 `Resource != ""` 도 요구하므로 resource·public_url 이 모두 비면 토큰 거부(기존 세션 경로 401)·메타데이터 404·WWW-Authenticate 없음. `putSetting` 은 enabled=true 저장 시 400 "set general.public_url or mcp.oauth.resource first"(같은 쓰기의 resource 는 인정). `TestWithoutAResourceIdentifierNoTokenIsAccepted` 가 Host/X-Forwarded-Host 4조합 401, 메타데이터 404, 저장 400 을 단언. 문서·UI 문구의 "요청 Host 로 만듭니다" 도 삭제.
2. **oauthProvider 락 안 discovery** — 락은 map 조회/등록만. 첫 호출자가 요청 ctx 로 discovery, 나머지는 `done` 채널 또는 자기 ctx 를 기다림. 실패는 30초(`oauthDiscoveryRetry`) 캐시, 요청 취소로 끝난 discovery 는 `abandoned` 로 표시해 캐시하지 않음. JWKS 는 go-oidc 가 이미 background ctx + client 로 분리하므로 WithoutCancel 불필요. `TestDiscoveryRunsOncePerIssuerAndOutsideTheLock`(race 로 검증).
3. **거절 로그 미검증·request_id 없음** — `middleware.RequestID` 를 라우터에 추가, 340행 warn 에 `request_id`. 테스트는 `New(...)` 를 bytes 버퍼 slog 로 다시 만들어 나쁜 토큰 10건 + audience 거절 각각에 대해 `error=` 의 원문("token is expired", "before the nbf", "issued by a different provider", "HS256", "none", "failed to verify signature", "typ=ID", "cnf present", "sub empty", "not accepted")과 비어 있지 않은 `request_id=` 를 같은 줄에서 단언. request_id 를 빼면 11건 실패함을 확인.
- 검증: `go test -race ./cmd/... ./internal/...`(DSN 설정) 통과, `go vet` 통과, `web npm test` 100/100. 첫 전체 실행에서 `TestHeavyQueriesStayLinearAtScale` 가 한 번 시간 기준으로 실패했으나 원본 HEAD 에서도 같은 타이밍 테스트이며 재실행·단독 실행 모두 통과(무관한 flake). `web npm run lint` 는 로컬에 eslint 미설치라 못 돌림(TS 변경은 문자열·주석뿐).
