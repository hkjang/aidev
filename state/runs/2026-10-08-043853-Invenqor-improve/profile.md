# Invenqor 프로필 (2026-10-08)
- 목적: Rust Agent가 호스트·프로세스·소프트웨어를 수집해 Go Server로 보내고 React 콘솔·REST·MCP로 IT 자산을 관리한다.
- 기준: 이번 체크아웃 main@ab7c89b, v0.2.45. 이전 기록보다 현재 소스가 우선한다.
- 스택: Rust 1.85 Agent, Go 1.25.14(chi·go-oidc·pgx·modernc sqlite), PostgreSQL 기본/명시적 SQLite 폴백, React 19·TypeScript·Vite 7·Vitest.
- 구조:
  - `src/`, `tests/`, `Cargo.toml`: Agent 수집·전송·업데이트와 Rust 테스트.
  - `server/cmd/invenqor-server`: 서버 진입점. `server/internal/httpapi`: REST·MCP·콘솔 핸들러와 실제 라우터 테스트.
  - `server/internal/{querydsl,storage,storagetest,auth,apikeys,ingest,softwarecatalog,mail,tracking,updates,agents,audit}`: DSL·DB·인증·수집·운영 서비스.
  - `server/migrations/{postgres,sqlite}`: 두 SQL 방언의 같은 순번 마이그레이션. PostgreSQL 자산/관계 id는 UUID, SQLite는 TEXT(이전 확인 기록).
  - `web/src`: 관리 콘솔. build 스크립트가 React 빌드와 `scripts/sync-embedded.mjs`를 실행해 `server/internal/webui/dist`를 갱신.
  - `openapi.yaml`: 공개 계약. `docs/`: 역할별 Markdown·PDF·릴리즈 노트·GitHub Pages HTML 홈페이지.
  - `scripts/`: PostgreSQL 검증·패키징·e2e·문서 생성. `.github/workflows/ci.yml`: 두 DB·web·Rust·의존성 감사·e2e.
- 빌드·테스트:
  - `cd server && go test ./... && go vet ./...`; `go build ./cmd/invenqor-server`; `gofmt -l .` 빈 출력 확인.
  - 좁은 검증: `cd server && go test ./internal/httpapi/ -run 'Relation' -count=1` — 이번 실측 통과 6.202초, 기존 잘못된 confidence=0→1 기대값도 포함.
  - 루트 `POSTGRES_CONTAINER=<회차고유이름> POSTGRES_PORT=<빈포트> ./scripts/test-postgres.sh -run 'Relation' -count=1`; 스크립트 확인, 이번 실행 안 함.
  - `cd web && npm ci && npm test && npm run build`; 빌드 뒤 루트 `git diff --exit-code -- server/internal/webui/dist`가 CI 검사.
  - `npx --yes @redocly/cli@2.47.0 lint openapi.yaml`; `cargo fmt --all -- --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --all-targets`.
  - Rust 크로스 빌드·Linux/Windows e2e는 장기 CI 작업. 이번 정찰에서는 실행하지 않음.
- 관례: 한국어 fix/build/chore 커밋과 별도 릴리즈. 설정은 DB settings/관리 API. 마이그레이션은 두 방언 함께 유지. 일반 수정에 버전·PDF 재생성을 섞지 않는다.
- 위험 구역: auth/session/OIDC/API key, migrations, merge/split 트랜잭션·감사, workflows, 임베드 UI 산출물. 정찰은 저장소 수정·커밋 금지.
- 자주 깨지는 곳:
  - PostgreSQL JSONB LIKE·파라미터 타입 추론·대소문자·UUID와 SQLite의 차이. SQLite 성공만으로 PostgreSQL을 보장하지 않는다.
  - `assets.go:712 canonicalUUID`는 36자 하이픈 UUID를 소문자로 정규화. merge/split·상세/수정/삭제/복원/history/relations·관계 생성/삭제에 적용됨.
  - `classification.go:425 reviewProposedRelation`에도 canonicalUUID 적용 완료(e2df1f1). 이전 프로필의 미점검 상태는 폐기한다.
  - `assets.go:622 createAssetRelation` 범위 [0,1] 검사는 구현됨(0d4c691). 명시적 0→1 후처리는 남음 — 이번 과제, 완료 전까지 해결로 보지 말 것.
  - `mcp.go:693 mcpAssetGet`, `:773 mcpAssetRelations`는 asset_id를 SQL에 직접 전달. users/api_keys/agents의 URLParam도 있으나 하위 서비스 검증은 미확인.
  - merge의 missingAssetID 오류만 rollback 선행. 이후 tx 오류→internalError는 SQLite 단일 연결 교착 위험, 실제 Runtime 실패 재현 수단 미확인.
  - `assetHistory:536`·`assetRelations:574`는 rows.Err() 검사 없음. 관계 조회는 LIMIT 없고 valid_from도 apiTime 미적용(실제 날짜 JSON 결함 미확인).
  - 관계 삭제 `deleteAssetRelation:675`는 부모 assetID 조건 없이 relationID만으로 UPDATE. 부모를 양 끝점 중 하나로 볼 정책·잘못된 부모 요청 재현 필요.
  - 테스트 헬퍼는 같은 패키지 기존 함수를 재사용: relationValidationClient/Assets/Body, relationConfidenceBody, relationConfidence, createdRelationID, assertRelationResponse, countRows, errorCode.
- 검증 함정:
  - `storagetest.Open` 기본 SQLite, INVENQOR_TEST_POSTGRES_DSN 지정 시 테스트별 PostgreSQL schema(이전 프로필 확인). 실제 배선은 server.Handler().ServeHTTP.
  - 콘솔/외부 REST는 같은 핸들러여도 둘 다 테스트. relationValidationClient의 외부 키는 현재 relations.write만 있어 GET 검증에는 relations.read가 추가로 필요.
  - `web/src/operationsPages.tsx:1291-1294`에 관계 생성 폼이 존재하며 confidence:1을 POST한다. 이전 프로필의 '삭제만 한다'는 설명은 잘못됨. :1287은 신뢰도를 백분율로 표시.
  - 감사 after_json은 요청 구조체에서 생성된다. 값 누락을 JSON 디코딩의 숫자 기본값 0으로 오인하지 말고 필드 존재·실제 숫자도 검증한다.
  - PostgreSQL 스크립트는 지정 이름의 기존 컨테이너를 먼저 삭제한다. 반드시 회차 고유 이름과 확인한 빈 포트를 사용한다. 이번 제안 포트 55548의 가용성은 미확인.
  - ci.yml은 push/PR이며 schedule 없음. Dependabot 파일 없음, GitHub 서버 측 설정은 미확인.
  - **기록/체크아웃 불일치**: 10/07 기록에 성공한 Liquid 수정·가드는 ab7c89b에 없다. `scripts/check-docs-liquid.sh` 없음, CI 가드 없음, docs/RELEASE_NOTES_v0.2.45.md:150에 문제 구문 유지. 이미 시도한 과제를 다시 선택하지 말고 해당 변경의 실제 병합 상태 확인부터.
  - Pages는 저장소 CI와 별도 배포였다는 과거 실패 기록이 있다. docs/의 Liquid 구문은 코드 블록 안이어도 발행에 영향. 빌드 초록만으로 발행을 보장하지 않는다.
  - docs/index.html의 USER_GUIDE.md 링크는 이번 실제 curl GET에서 HTTP 200(.html도 200). 404라는 기존 추측은 기각. 모든 링크 정상이라는 뜻은 아님.
  - 이번 실행은 SQLite Relation suite뿐. PostgreSQL·전체 Go·vet·web/Rust 및 현재 Pages 배포 결과는 미확인.
