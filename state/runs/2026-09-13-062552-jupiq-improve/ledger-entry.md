- 요약: jupiq에는 `internal/auth/oidc.go`(go-oidc, 암호화된 state 쿠키, PKCE)와 `/api/v1/auth/oidc/{config,login,callback}` 경로가 이미 있었으므로 캠페인 대상이다. releasedock을 참조해 이 저장소의 구조에 맞게 만들었다 — `auth.oidc` 설정에 `auto_login`(기본 꺼짐, 설정 검증의 허용 필드·bool 필드·store 기본값에 추가)을 두고, `/auth/oidc/config`가 `auto_login`을 함께 내려 주며, `oidcLogin`이 `?prompt=none`을 받되 `SilentLoginAllowed(cfg, requested)`가 `enabled && auto_login`일 때만 `prompt=none`을 인가 URL에 붙이고(아니면 조용히 평범한 로그인) state 쿠키에 `silent` 표시를 남긴다. 콜백은 `error=` 질의가 오면 `OIDCRefusal`로 쿠키의 `silent`와 `return_to`를 읽어 `/login?sso=none`(조용한 시도) 또는 `/login?sso=error`(그 외)로 302하고 쿠키를 지운다 — 쿠키를 읽지 못하거나 state가 다르면 조용한 시도가 아니었던 것으로 쳐서 `sso=error`, 어느 쪽이든 브라우저는 다시 시도하지 않는다. 조용한 거절은 감사·로그를 남기지 않고(세션 없는 방문자마다 실패 기록이 쌓이지 않게), 다른 제공자 오류만 Warn 로그. 프런트는 `web/src/auth/silentSso.ts`에 규칙을 모았다: `sessionStorage`의 '한 탭 세션에 한 번'·'스스로 로그아웃' 표시(읽기 예외는 '이미 시도했다'로 취급), 주소의 `sso=none|error` 표시, `/login`·`/api/`·`/mcp`·`/healthz`·`/readyz`·`/momento/` 경로 제외, `return_to`는 `/`로 시작하고 `//`·`/\`로 시작하지 않는 값만. `RequireAuth`가 세션 확인이 끝난 뒤 사용자가 없고 조건이 맞으면 `/login`으로 보내는 대신 `window.location.assign`(최상위 이동, iframe 아님)으로 `/api/v1/auth/oidc/login?prompt=none&return_to=…`에 한 번 보내고 그 사이 스피너를 유지한다. `AuthContext.logout`이 요청 전에 억제 표시를 남기고 사용자가 생기면 두 표시를 지운다. `LoginPage`는 전체 페이지 리다이렉트로 잃는 `location.state.from` 대신 `return_to` 질의를 읽어 깊은 링크를 유지하고 `sso=error`에만 안내를 띄운다. 관리자 설정 OIDC 카드에 `자동 로그인(Silent SSO)` 스위치를 넣었고 OpenAPI의 login/callback 설명·파라미터를 갱신했다. 테스트는 Go 9개(`SilentLoginAllowed` 4경우, `OIDCRefusal`의 silent/interactive/읽기 실패 6경우, `LoginPathAfterRefusal` 6경우, 콜백 핸들러의 none/error/fail-closed 5경우/code 없는 정상 경로 유지, 설정 검증 bool 강제)와 프런트 14개(`silentSso` 규칙 8개, `RequireAuth` 6개: 한 번 시도·표시 있으면 미시도·재시도 없음·기본 설치 무변화·로딩 중 미시도·세션 있으면 미시도)이며, 저장소 읽기 예외를 '아직 안 했다'로 바꾼 변형에서 테스트가 실제로 실패하는 것을 확인했다. 관리자 가이드 4.4절에 동작 설명, 6.4절에 증상 3줄, 7.4절 설정 항목을 더하고 공용 md2pdf로 PDF를 다시 구웠다(20→21쪽). `gofmt -l`, `go vet ./...`, `go test -race ./...`, `scripts/check-version.sh`, `scripts/check-screenshots.mjs`, `npm run
