- 과제: 달력 날짜 검증 v.day 의 윤년·월말·범위 계약을 회귀 시험으로 고정 (가치 3 / 위험 1 / 작업량 S)
- 왜: `packages/core/src/util/validate.ts:233` 의 `v.day` 는 결재·근태·재무 거의 모든 라우트가 날짜를 받는 유일한 관문인데 시험이 한 건도 없다(`packages/core/src/__tests__/` 전체에 `v.day` 문자열이 없음을 확인). 지금 동작은 올바르게 읽히므로 결함 수정이 아니라 계약 고정이며, 세 겹 가드(형식 정규식 → ISO 왕복 → 2000~2100 범위) 중 하나가 나중에 느슨해지면 `2026-02-30` 같은 날짜가 DB 로 내려간다.
- 수용 기준:
  1) `packages/core/src/__tests__/domain.test.ts` 에 `v.day` 케이스 표가 추가되어, 통과 입력은 입력 문자열을 그대로 돌려주고 거절 입력은 `AppError`(`parseOne` 이 던지는 validation_failed)를 던지는 것이 확인된다.
  2) 세 겹 가드가 각각 시험에 걸린다는 것을 변이로 증명한다 — ① `validate.ts:240` 의 `d.toISOString().slice(0, 10) !== value` 조건을 임시로 지우면 `2026-02-30`·`2026-04-31`·`2023-02-29` 케이스가 실패하고, ② `:244` 의 `year < 2000 || year > 2100` 줄을 지우면 `1999-12-31`·`2101-01-01` 케이스가 실패해야 한다. 두 변이 모두 `git checkout -- packages/core/src/util/validate.ts` 로 되돌린 뒤 전원 통과를 재확인한다(변이 결과는 보고서에 실제 vitest 출력으로 적는다).
  3) 프로덕션 코드 변경 0파일. `npm run check` 와 `npm run build` 통과.
- 건드릴 파일 (프로덕션 0개 · 시험 1개):
  - `packages/core/src/__tests__/domain.test.ts` — 파일 끝(현재 마지막 블록은 `describe('입력 검증: 금액·정수·소수', …)`, 252행)에 `describe('입력 검증: 달력 날짜 v.day', …)` 를 덧붙인다. **import 추가 불필요** — 24행에 `import { parse, parseOne, v } from '../util/validate.js'`, 16행에 `AppError` 가 이미 있다(직접 열어 확인).
  - 바로 위 252~301행의 금액 검증 블록과 **같은 형태로 쓸 것**: 통과/거절 목록을 상수 배열로 두고 `it.each(REJECT)('v.day 가 %j 를 거절한다', (raw) => { expect(() => parseOne(v.day({ label: '발행일' }), raw, 'issued_on')).toThrow() })`, 통과는 `expect(parseOne(v.day({ label: '발행일' }), raw, 'issued_on')).toBe(raw)`. 거절 문구 확인은 한 건만 — `try/catch` 로 `expect(e).toBeInstanceOf(AppError)`, `code === 'validation_failed'`, `fieldErrors?.issued_on` 이 `'2026-02-30'` 에서는 `'날짜가 올바르지 않습니다'`, `'2101-01-01'` 에서는 `'범위를 벗어났습니다'`, `'2026-1-1'` 에서는 `'YYYY-MM-DD'` 를 담는지 본다(세 가드가 서로 다른 문구를 내는 것이 `validate.ts:237/241/244` 에서 읽힌다 — 실행으로 확인할 것).
  - (프로덕션 파일은 건드리지 않음. `validate.ts` 는 수용 기준 2) 의 변이 확인 때만 임시로 고치고 반드시 되돌린다.)
- 케이스 표 (이 값들을 그대로 쓸 것 — 내가 소스를 읽고 고른 경계다):
  - 통과(반환값 == 입력): `'2024-02-29'`(윤년), `'2000-02-29'`(400년 윤년·범위 하한 연도), `'2000-01-01'`(범위 하한), `'2100-12-31'`(범위 상한), `'2026-01-31'`, `'2026-04-30'`, `'2026-12-31'`
  - 거절(throw): `'2023-02-29'`(평년 2월 29일), `'2100-02-29'`(100년 비윤년), `'2026-02-30'`, `'2026-04-31'`, `'2026-13-01'`, `'2026-00-10'`, `'2026-01-00'`, `'2026-01-32'`, `'2026-1-1'`(0 패딩 없음), `'20260101'`(구분자 없음), `'1999-12-31'`(범위 하한 미달), `'2101-01-01'`(범위 상한 초과), `'2026-01-15T00:00:00Z'`(시각 포함), `' 2026-01-15'`(앞 공백 — `v.day` 는 trim 하지 않는다), `''`, `20260115`(숫자 타입), `null`, `undefined`
  - **미확인(중요)**: 위 표는 `validate.ts` 소스를 읽고 고른 경계이고, 이 세션에서는 `node -e` 실행이 권한에 막혀 `new Date('…T00:00:00Z')` 의 실제 판정을 돌려 보지 못했다. `'2100-02-29'`·`'2026-13-01'`·`'2026-00-10'`·`'2026-01-00'`·`'2026-01-32'` 는 형식 정규식(`/^\d{4}-\d{2}-\d{2}$/`)을 통과하고 ISO 왕복 조건에서 걸릴 것으로 읽었지만 실행 확인은 하지 않았다. 구현자는 표를 먼저 돌려 보고, 기대와 다른 칸이 있으면 **시험 기대값을 실제 동작에 맞추고 그 사실을 보고서에 적을 것**(프로덕션 동작을 바꾸지 말 것). 어느 가드에 걸리든 거절되면 수용 기준 1) 은 충족이다.
  - 통과 목록 중 `'2000-02-29'`(400년 윤년)과 거절 목록의 `'2100-02-29'`(100년 비윤년)은 윤년 규칙 세 갈래를 다 덮기 위한 짝이다 — 둘 중 하나만 넣지 말 것.

- 위험과 피할 것:
  - **`validate.ts` 의 동작을 고치지 말 것.** 이번 과제는 계약 고정이다. 읽다가 `v.day` 를 넓히거나 좁히고 싶어지면 아이디어로만 남기고 이번 회차에는 손대지 말 것. 특히 `' 2026-01-15'` 를 trim 해서 통과시키는 "개선" 은 금지 — 호출부가 공백을 보내는지 확인되지 않았고, 운영자 지시는 넓히기 금지다.
  - 직전 세 회차가 모두 `validate.ts`·`format.ts`·`nav.ts` 를 건드렸다. 같은 파일의 **다른** 검증기(`v.instant`, `v.string`/`v.text` 길이, `v.bool`)는 이번 범위가 아니다 — 시험 표에 끼워 넣지 말 것.
  - 보호 경로(`auth/*`, `routes/sso.ts`, `db/migrations`, `.github/workflows`)는 건드리지 않는다. 이 과제는 거기까지 갈 일이 없다.
  - 시험 케이스 표를 공용 모듈로 빼지 말 것 — 워크스페이스 경계를 넘는 import 는 tsc 가 워크스페이스별로 돌아 깨진다(프로필의 검증 함정).
  - 변이 확인 때 `validate.ts` 를 임시 수정한 뒤 **되돌리는 것을 잊지 말 것**. 작업 트리에 남으면 프로덕션 변경 0파일이 깨진다.
- 차선 후보: KST 일 경계 `kstDateKey`·`minuteStart` 의 쿼터 창 계약 시험 (가치 3 / 위험 1 / 작업량 S) — `packages/core/src/util/time.ts` 는 시험이 0건이고 `packages/core/src/quota.ts` 가 일일 쿼터 리셋 키로 `kstDateKey`, 분당 쿼터 창으로 `minuteStart` 를 쓴다(grep 으로 이 두 함수의 유일한 소비처임을 확인). `2026-03-14T14:59:59.999Z`→`'2026-03-14'`, `2026-03-14T15:00:00Z`→`'2026-03-15'`(KST 자정 = UTC 15:00) 경계와 `minuteStart` 의 초·밀리초 절삭을 못 박는다. 주의: 같은 파일의 `kstWindowOn`·`overlaps`·`isoDay`·`formatKst`·`backoffMs` 는 `quota.ts` 도 쓰지 않는 미사용 표면이라 시험 가치가 낮다 — 쓰지 않는 함수까지 표를 늘리지 말 것.
