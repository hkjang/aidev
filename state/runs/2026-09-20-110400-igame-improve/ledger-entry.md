- 요약: `unlockAchievement`(internal/api/content.go)는 `JOIN game_sessions gs ON gs.game_id=a.game_id`로 업적과 세션을 묶는데, 관리자 화면("게임별·포털 공통 업적 조건을 관리합니다")이 만들 수 있는 게임 없는 업적은 `game_id`가 NULL이라 어떤 세션과도 매치되지 않아 `client_unlockable`을 켜 두어도 항상 `403 achievement_not_unlockable`이었다 — 클라이언트가 업적을 해금하는 유일한 경로라 그런 업적은 만들 수는 있어도 쓸 수 없었다. 조인 조건을 `(a.game_id IS NULL OR gs.game_id=a.game_id)`로 바꿔 게임에 묶인 업적은 종전대로 그 게임 세션에서만, 포털 공통 업적은 어느 게임 세션에서든 해금되게 했고 `client_unlockable`·본인 세션·토큰 해시·세션 상태 조건은 그대로다. 검증은 진짜 배선으로 했다: 새 `internal/api/achievements_pg_test.go`(IGAME_TEST_DSN 규약, 3개)가 실제 `Router()`를 httptest로 띄워 세션 쿠키로 `POST /games/{slug}/sessions`로 진짜 세션을 만들고 `POST /me/achievements`를 보내 (1) 공통 업적이 다른 게임 세션에서 201, 재요청 200, `/me/achievements`에 등장, (2) 게임 A 업적은 B 세션에서 403·A 세션에서 201, (3) server_rule 업적·잘못된 토큰·모르는 세션은 403임을 확인한다. 고치기 전 (1)이 403으로 실패(Red)했고, 조인을 `ON true`로 풀어 버린 변형에는 (2)가 실패해 가드가 작동함을 확인했다. docker `postgres:17-alpine`으로 `internal/api` PG 테스트 전체 통과(`-race -count=3` 반복 포함), `gofmt -l`·`go vet`·`go build ./...`·`go test`·`go test -race` 전체(cmd/internal/migrations), `scripts/check-release-contract.sh` 통과. docs/api.md의 해당 endpoint 행에 해금 규칙을 적었다. 프런트엔드·SDK는 건드리지 않아 npm 쪽(`make deps`/lint/web 테스트)은 돌리지 않았다.
