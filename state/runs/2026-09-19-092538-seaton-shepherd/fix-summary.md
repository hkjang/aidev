# 수리 요약 (커밋 517bd11, PR #30)

1. **aud 허용값이 Host 로 만들어짐(맞는 지적, 재현함)** — `enabledValues(idp,nil)` + `Host: other-app.intra` + `aud=["https://other-app.intra/mcp"]` 로 `verifyMCPAccessToken` 이 통과하는 것을 임시 테스트로 확인. `resource(r)`/Host fallback 을 삭제하고 대상 검사·메타데이터 `resource`·`WWW-Authenticate` 의 metadata URL 을 모두 `cfg.Resource` 설정값에서만 만든다. `verifyMCPAccessToken`/`oauthPrincipal` 에서 `*http.Request` 인자를 아예 뺐다. `validate()` 는 Enabled 일 때 Resource 를 필수로, `active()` 는 Resource 가 비면 꺼진 것으로 본다. 지적의 "Resource **또는** Audiences" 보다 한 단계 엄격하게 Resource 필수로 한 이유: RFC 9728 은 메타데이터 `resource` 가 REQUIRED 이고 MCP 클라이언트는 그 값을 서버 URL 과 대조하므로, Audiences 만으로는 Host 없이 그 문서를 만들 수 없다(Audiences 는 여전히 선택 호환 경로). 새 테스트 `TestHostHeaderDoesNotBecomeAcceptedAudience`(검증기 직접 + 라우터 경유, Host/X-Forwarded-Host 조작 두 가지) 추가, `TestProtectedResourceMetadata` 의 "비어 있으면 프록시 주소" 단언을 "Host 가 무엇이든 설정값" 으로 교체, validation 테이블에 "리소스 없이 켜기 → 거절" 추가. UI(`mcpOAuth.ts` active/problem, helperText), e2e, ADMIN_GUIDE(md/html) 의 "비우면 요청 주소로" 문구를 같이 고쳤다.
2. **뮤텍스 잡은 채 discovery(맞는 지적)** — `oauthProviders.byIssuer` 를 `*oauthDiscovery{done, provider, err, failedAt}` 로 바꿔, 뮤텍스 안에서는 엔트리 조회/등록만 하고 discovery 는 goroutine 에서 `context.Background()+10s` 타임아웃 + `http.Client{Timeout:10s}`(`oidc.ClientContext`) 로 돌린다. 같은 issuer 동시 요청은 `done` 을 함께 기다리고(singleflight, x/sync 직접 의존 추가 없이), 요청 ctx 취소 시 즉시 돌아온다. 실패는 `failedAt` 으로 30s 음성 캐시. `TestDiscoveryFailureIsNotAnInvalidToken` 을 호출 횟수 세는 fake IdP 로 바꿔 두 번째 요청이 IdP 를 안 두드리는 것·TTL 뒤 재시도·취소 응답을 고정하고, `TestDiscoveryIsSharedAndOffTheMutex` 로 IdP 가 멎은 동안 뮤텍스가 비어 있고 동시 4건이 discovery 1회임을 고정했다.
3. **거절 로그에 request_id 없음(맞는 지적)** — `refuseMCPToken` 의 Warn/Error 두 분기 모두에 `middleware.GetReqID(r.Context())` 를 `request_id` 로 추가. `TestRefusedTokenGetsChallengeAndLoggedCause` 가 `request_id=` 가 비어 있지 않은 값으로 있는지 단언(실제 값 예: `HOST/IeHuWe7lwW-000001`), 503 경로 테스트도 같은 단언.
4. 검증: `go test ./...`, `go vet ./...`, `go test -race ./internal/app/`, `web: npm test`(104 통과), `npm run lint`(tsc), `npm run build` 모두 통과. e2e 는 Docker/DB 가 필요해 로컬에서 돌리지 못했다 — 수정한 e2e 케이스(리소스 없이 켜기 → 400 "리소스 식별자")는 서버 validate 순서(issuer → mcp 범위 → resource)에 맞춰 기존 noIssuer/noMCP 단언이 그대로 유지되게 했다.
5. 수리 노트는 `journal.md`(같은 디렉터리, `$JOURNAL_FILE` 이 비어 있어 새로 만듦) 끝의 `## 수리 노트` 에 있다.
