# Quantoss 프로필 (2026-09-20)
- 목적: 토스증권 Open API 로 국내(KR)·미국(US) 종목을 자동 매매하고(실거래/모의), 백테스트·스윙/라오어 모의 실행기로 전략을 전진 검증하며 GitHub 이슈·Pages 대시보드·텔레그램으로 기록·알림하는 단일 바이너리 Go 에이전트.
- 스택: Go 1.26, 외부 의존은 `github.com/coder/websocket` 하나. DB 없음 — `data/` 아래 JSONL/JSON 파일(저널·자산곡선·일봉 캐시·토큰 캐시). 프런트는 `docs/` 정적 GitHub Pages(JSON 읽는 대시보드).
- 구조:
  - `cmd/quantoss/` — 단일 CLI. main.go(agent/backtest/optimize/paper 등) + research_*.go + swingrun/laoerrun + copilot/doctor/verify.
  - `internal/config` — `.env`(`QUANTOSS_*`, `TOSS_*`) → Config, `ForMarket(KR|US)`, `Validate`(config.go:650, `pos`/`nonNeg` 헬퍼).
  - `internal/toss` — 토스 REST/WS 클라이언트. `Client` 는 `NewClient` 로만 생성(운영 코드). `request()` 가 5회 재시도(network/429/5xx → 패키지 함수 `backoff()` 실제 `time.Sleep` 1·2·4·8·16s, 401 → 토큰 재발급). 토큰 캐시 `data/.token.json`. 테스트는 token_test.go·ws_test.go 만.
  - `internal/engine`·`broker`·`risk`·`strategy`·`indicators` — 분봉 실시간 매매 루프, 2단 매도(지정가→시장가)+서버 손절 예약(`reguard`), 전략 Registry. broker 테스트는 `httptest` 서버 + 진짜 `toss.Client`(`sell_test.go:95`).
  - `internal/swing`(runner/laoer)·`backtest`·`exitlab`·`selection`·`evaluation` — 일봉 스윙/라오어 시뮬레이션과 모의 실행기(`PoolFn/DailyFn/BarsFn` 주입 가능).
  - `internal/agent`·`github`·`report`·`notify`·`journal` — 실시간 루프, GitHub 이슈/파일 커밋, 리포트·대시보드 JSON, 텔레그램/슬랙, 저널 JSONL.
  - `internal/universe`·`yahoo`·`catalyst`·`fundamentals`·`stockinfo`·`ontology` — 종목 풀·일봉 수집·공시(DART)·펀더멘털.
  - `internal/zz_dbg` — 운영자 디버그 스크래치. 2026-09-18 부터 `//go:build zzdbg` 태그로 `go test ./...` 에서 제외(`[no test files]`).
  - `scripts/` — run.sh/boot.sh/lab.sh/check_dashboard.sh/quantoss.service. `.github/workflows` 없음, `scripts/check.sh` 없음.
- 빌드·테스트: `go build ./...` · `go vet ./...` · `gofmt -l .` · `go test -count=1 ./...` — 2026-09-20 기준 ~35s, 그중 31.8s 가 `internal/broker` `TestSellUnknownResultIsResolvedBeforeNewOrder`(toss 5xx 백오프 실제 대기). `-race` 통과 이력.
- 관례: 커밋 메시지 한국어 한 줄(자동 커밋 `live.json: 실시간 현황`·`report(live/…)` 가 로그 대부분). 설정은 `.env` 환경변수만, 마이그레이션 없음. 문서는 README.md(한국어) + `docs/reports/research/`, `reports/`. nil 필드는 "nil 이면 기본값" 지연 초기화 패턴(toss limiter, notify http).
- 위험 구역: `internal/broker`(Sell 2단 매도·`reguard` — 이중 매도/유령 예약 이력), `internal/toss` 토큰(`ensureToken`/캐시 — 같은 키로 두 프로세스면 서로 무효화), `internal/swing/runner.go`(잦은 재작성, 충돌), `internal/config.ForMarket` 전략 우선순위.
- 자주 깨지는 곳: 가격 포맷 `%.0f`(US 종목 — `market.FormatPrice/Money`), 구조체 리터럴 클라이언트의 nil 필드 패닉, 스윙 실행기 "마지막 봉만 판정" 가정.
- 검증 함정: 이전 과제서가 "나머지 <5초" 라 적었으나 실측 35s — go test 캐시(`-count=1` 없이)를 본 것. 시간 단언은 반드시 `-count=1` 로. `internal/zz_dbg` 는 `-tags zzdbg` 로만 컴파일되며 실토스·DART API·운영자 절대경로에 의존 — 라이브 에이전트 실행 중 돌리지 말 것. `.github/workflows` 추가는 푸시 토큰 `workflow` 스코프 미확인이라 회차 유실 위험.
