# v0.310.0 — Confluence 진단 표가 20건에서 잘렸다는 사실을 말하고, 실패 수를 화면에 보여 줍니다

## 가득 찬 진단 표는 "진단이 이것뿐" 으로 읽힙니다

- `confluence_sync_errors` 는 최신 **500건**까지 남습니다(`recordConfluenceError`). 그런데 `GET /api/v1/admin/confluence/sync/status` 는 그중 **`LIMIT 20`** 만 읽었고, 응답에는 **잘렸다는 표시가 없었습니다**.
- 그래서 실패가 **40건** 난 동기화에서 관리자가 보는 것은 꽉 찬 20행짜리 표 하나입니다. 스무 개를 읽고 고쳤는데 사유가 그대로인 실패가 스무 개 더 남아 있다는 것을 **알 길이 없었습니다** — 표가 가장 필요한 동기화일 때 표가 가장 조용했습니다.
- 같은 카드의 **`실패` 수는 화면에 아예 없었습니다.** 관리자 가이드 3.6 은 이 탭이 실패 수를 보여 준다고 이미 적어 두었지만, `pagesFailed` 는 응답에만 있고 `AdminPage.tsx` 에는 **한 번도 등장하지 않았습니다**.

## 21번째 행 하나로 답합니다

- 응답에 **`recentErrorsTruncated: boolean`** 이 생겼습니다. 표에 담지 못한 진단이 더 남아 있으면 `true` 입니다.
- 질의는 여전히 **한 번**입니다. `LIMIT` 에 `confluenceRecentErrorLimit+1`(=21)을 보내고, **21번째 행은 목록에 넣지 않은 채 존재만 읽습니다** — 그 행이 있느냐가 답의 전부이므로 COUNT 질의를 따로 더하지 않았습니다. v0.308.0 이 발송 기록에서 쓴 것과 같은 방식입니다.
- 스캔 루프는 머리에서 `len(errorsView)==limit` 을 보고 멈추므로 **`recentErrors` 는 여전히 20건**입니다. 이 칸이 늘어난 것뿐이고 목록은 v0.309.0 과 같습니다.
- **총건수는 싣지 않았습니다.** 몇 건이 더 있는지는 관리자가 쓸 수 있는 숫자가 아니고, 전체 건수를 돌려주면 이 목록에 없는 쪽 넘김을 약속하는 셈이 됩니다.
- `ORDER BY created_at DESC` 에 **`, id DESC`** 를 더했습니다. 같은 순간에 적힌 진단들이 20번째와 21번째 자리를 **번갈아 차지하는 것**을 막습니다 — 같은 상태를 두 번 읽었을 때 빠지는 행이 달라지면 안 됩니다.
- 잘리지 않았으면 이 칸은 **생략합니다**. 항상 있는 칸은 화면이 항상 찍는 문장이 되고, 그러면 아무 말도 하지 않게 됩니다.
- `20` 은 `confluenceRecentErrorLimit` 상수 하나가 되었습니다. 쪽 크기와 `+1`, 그리고 멈추는 조건이 **같은 숫자를 읽습니다**.

## 화면과 문서

- `자동 수집 상태` 카드에 **`실패` 칸**이 생겼습니다(`pagesFailed`). 가이드가 약속한 숫자가 처음으로 화면에 있습니다.
- `최근 동기화 진단` 카드는 `recentErrorsTruncated` 일 때만 표 아래에 한 문장을 답니다 — `최신 20건만 표시합니다. 이전 진단이 더 남아 있습니다.`. 카드 노출 조건(`recentErrors.length>0`)은 그대로입니다.
- 관리자 가이드 **3.6** 을 고쳤습니다. 이 표는 오류만이 아니라 매핑 누락 같은 **알림도 함께** 담으므로 문구를 `오류` 에서 `진단` 으로 바꾸고, `실패` 칸은 **마지막 동기화 1회**의 Page 실패 수라서 누적되는 진단 건수와 **다른 숫자**라고 적었습니다. 두 값을 같은 것으로 읽으면 표가 비어 있는데 실패가 3이라는 화면을 고장으로 오해합니다.

## 검증

새 시험 `TestTheOperatorLearnsTheDiagnosisTableIsCutOff` 가 고치기 전 코드에서 `recentErrorsTruncated=<nil>, want true` 로 **실패하는 것을 먼저 확인**한 뒤 통과했습니다. 같은 시험이 반대 방향도 증명합니다: 정확히 20건인 표의 응답에는 이 칸이 **없습니다**. 진단 행은 직접 INSERT 하지 않고 프로덕션 쓰기 경로인 `recordConfluenceNotice`·`recordConfluenceError` 로 만들었습니다. 실제 PostgreSQL(`pgvector/pgvector:pg16`) 위에서 전체 Go 테스트와 `go vet`·`gofmt`·`go build`, 가드·OpenAPI·쪽넘김·모달·버전 검사, 프런트엔드 160개 시험과 `tsc -b`·프로덕션 빌드를 통과했습니다. 표 아래 문장과 `실패` 칸 자체는 이 저장소에 관리자 설정 화면을 렌더하는 프런트 시험이 없어 **타입 검사와 빌드까지만** 확인했고 렌더링 시험으로 증명하지 않았습니다.

## 업그레이드

마이그레이션도, 새 환경변수도, 설정 키의 변경도 없습니다. `recentErrorsTruncated` 는 **늘어난 칸 하나**이고 잘리지 않으면 아예 없으므로, 이 칸을 모르는 옛 화면도 v0.309.0 과 똑같이 읽습니다. `recentErrors` 는 같은 상태에 같은 20건을 돌려줍니다. 기존과 같이 PostgreSQL 을 백업한 뒤 v0.310.0 이미지를 올리면 됩니다.
