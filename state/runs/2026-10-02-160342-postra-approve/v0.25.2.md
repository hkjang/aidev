# Postra v0.25.2 — 의존성 보안 갱신과 브라우저 테스트 인터프리터

운영 동작을 바꾸지 않는 유지 보수 릴리즈입니다. **OpenTelemetry 를 v1.45.0 으로 올려 govulncheck 권고 `GO-2026-6505` 를 해소**하고, 저장소를 내려받은 개발자 기계에서 `npm test` 가 엉뚱한 Node 로 실행되어 실패하던 문제를 고쳤습니다. 기능 변경, 새 설정 키, 새 환경변수, DB 마이그레이션은 **없습니다**.

## 의존성 보안 갱신

- `go.opentelemetry.io/otel`·`otel/sdk`·`otel/trace`·`otel/exporters/otlp/otlptrace`(및 `otlptracehttp`)·`otel/metric` 을 **v1.44.0 → v1.45.0** 으로 올렸습니다. 이 갱신으로 govulncheck 가 보고하던 `GO-2026-6505` 가 사라집니다.
- 함께 올라간 간접 의존성: `go.opentelemetry.io/proto/otlp` v1.10.0 → v1.11.0, `github.com/go-logr/logr` v1.4.3 → v1.4.4, `google.golang.org/genproto/googleapis/{api,rpc}` 2026-08-03 스냅샷.
- 추적(Trace) 내보내기 설정과 OTLP 엔드포인트 동작은 그대로입니다. 호출하는 API 가 바뀌지 않아 애플리케이션 코드 수정은 없습니다.

## 브라우저 테스트 인터프리터

- `cd web && npm test` 가 49개 중 48개 스펙 파일에서 `TypeError: webidl.util.markAsUncloneable is not a function` 로 실패하는 경우가 있었습니다. 원인은 테스트 코드가 아니라 **인터프리터**입니다: npm 은 스크립트를 실행하기 전에 상위 모든 `node_modules/.bin` 을 PATH 앞에 붙이고, 체크아웃 상위에 설치된 무관한 `node` 패키지가 npm 자신이 쓰는 인터프리터를 가립니다. vitest 의 `#!/usr/bin/env node` 셔뱅이 그 가려진 쪽(Node 20)을 집었고, jsdom 의 undici 가 Node 22.10 이상에서만 있는 `worker_threads.markAsUncloneable` 을 찾다 스펙 파일마다 죽었습니다. 오류 메시지는 Node 도, 필요한 버전도 말해 주지 않았습니다.
- `web/scripts/engine-node.mjs` 가 vitest 진입점을 실행하면서 **실행 중인 인터프리터를 `package.json` 의 `engines.node`(>=22.12)와 비교**합니다. PATH 가 가린 경우 `npm_node_execpath`(개발자가 고른, npm 이 실제로 쓰는 인터프리터)로 자신을 다시 실행하고, 그마저 범위를 벗어나면 **두 버전을 함께 적어** 실패합니다. 지원되는 인터프리터에서는 조용히 통과하므로 CI 동작은 바뀌지 않습니다.
- **스펙을 건너뛰거나 제외하거나 약화시키지 않았습니다.** 426개 테스트 전부 그대로 실행되고 통과해야 합니다.
- `web/scripts` 가 생기면서 드러난 두 번째 결함도 고쳤습니다. Tailwind v4 의 자동 콘텐츠 탐지가 그 디렉터리를 훑어 **주석의 평범한 영어 단어를 유틸리티 클래스로 만들었습니다** — "shadow" 하나가 `.shadow` 규칙을 만들어 배포 스타일시트를 2 KB 늘리고 모든 청크 해시를 바꿨습니다. `web/src/styles.css` 에 `@source not "../scripts"` 를 추가해 빌드 도구를 스타일시트에서 떼어 냈고, 그 결과 다시 빌드한 번들이 커밋된 자산과 바이트 단위로 같습니다.

## 검증

- 전체 Go race 테스트, `go vet`, `gofmt`, `go mod tidy` 무변경, canonical API 계약 검사(`postra-contracts -check`)
- `govulncheck ./...` — 취약점 0건(호출 경로 기준)
- `gosec -severity medium` — 지적 0건, 141개 파일
- 브라우저: `npm run typecheck`, `npm test` 50개 파일 426개 테스트 통과, `npm audit --omit=dev --audit-level=high` 0건
- `npm run build` 후 `internal/transport/spa/assets` 변화 없음 — 태그에 담긴 `/app` 번들이 최신임을 확인(릴리즈 워크플로가 같은 검사를 다시 합니다)
- 가려진 Node 20.19.2 환경에서 `engines.node` 미달을 감지해 npm 의 인터프리터(22.23.1)로 재실행하는 경로를 실제로 통과

## 업그레이드 및 호환성 주의사항

DB 마이그레이션, 새 설정 키, 새 필수 환경변수가 없습니다. 실행 파일 또는 컨테이너 이미지를 교체한 뒤 재시작하면 끝입니다. 되돌릴 때도 v0.25.1 로 그대로 내려갈 수 있습니다.

- v0.25.1 의 "계정당 인바운드 연결 하나"와 `mail.idle_enabled`, v0.25.0 의 동기화 실패 진단은 바뀌지 않았습니다.
- 운영에 영향을 주는 변경은 의존성 갱신뿐입니다. 추적을 내보내고 있다면 수집기 쪽 OTLP 설정은 그대로 두어도 됩니다.
- 브라우저 테스트 변경은 **개발 환경에만** 해당합니다. 배포 산출물에는 `web/scripts` 가 들어가지 않습니다.
- `web` 에서 작업한다면 Node 22.12 이상이 필요합니다. 그보다 낮은 인터프리터가 PATH 앞에 있으면 테스트가 이제 그 사실과 필요한 버전을 함께 알려 줍니다.
