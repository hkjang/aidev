(3) `app.status_changed` — 관리자가 다른 사람의 앱 상태를 바꾸면(대개 게시 내림) 소유자에게; 없으면 소유자는 사용자 불평으로 알게 된다. kanpic의 공유·댓글·멘션·워치는 이 앱에 없고, "앱 정보가 바뀜" 같은 것은 메일감이 아니라 넣지 않았다. 시끄러움 방지: actor는 언제나 제외(등록자가 검토자여도, 소유자가 스스로 보관해도 조용), 검토자+팀장 겹침은 주소로 dedupe, 이메일 없는 계정은 건너뜀, 종류별 스위치 `mail.notify_<이벤트>`. 배경 발송: `Notify`는 queued 행을 남기고 goroutine으로 보내며(2초 뒤 한 번 재시도, `context.WithoutCancel`) 켜져 있지만 호스트가 없으면 dial 없이 failed 행에 이유를 적는다. 검증: `internal/mail` 테스트 12개(loopback 가짜 SMTP로 실제 세션 — 헤더 인코딩·dot-stuffing은 net/smtp DotWriter에 맡겨 kanpic의 이중 stuffing을 피함·AUTH는 사용자 이름이 있을 때만, 설정 파싱·왕복·`Values()`에 비밀번호 없음, JSON에 비밀번호 없음, Validate 경계 10건, 꺼짐이면 아무것도 안 함, 미설정이면 failed+이유, 배경 발송이 요청보다 먼저 끝남과 2회 시도 실패 기록, actor·주소 없음·중복 제거, 이벤트 스위치, SendNow 성공·실패 양쪽 기록, 저장된 비밀번호 복호화), 임시 postgres:16-alpine으로 `TestPostgreSQLMailIntegration`(새 DB는 꺼짐·passwordSet false, 시험 발송은 꺼짐이면 409, 저장 응답에 비밀번호 없음·DB 행은 암호문·비밀번호 없이 재저장해도 유지·호스트 없이 켜면 422, 시험 발송이 가짜 릴레이에 도착하고 릴레이가 본 AUTH PLAIN이 복호화된 비밀번호, 등록→검토자에게만·반려→소유자에게만·관리자 보관→소유자·소유자 본인 보관→없음, 기록 5건 모두 sent+앱 id 참조, 죽은 릴레이로 등록 요청이 2초 안에 201·failed 2회 시도·시험 발송 502, 꺼진 이벤트는 기록도 없음), React 테스트 2건(비밀번호 칸은 비어 있고 "설정됨"만·저장 본문에 password 없음·스위치 상태, 시험 발송과 기록 표). `gofmt`·`go vet`·`go test -race`(CI 패키지 목록; DSN 있는 전체 실행에서 기존 `TestPostgreSQLHTTPPolicyIntegration`만 실패했는데 로그인 rate limit 창이 분 단위로 맞춰져 있어 -race 아래 bcrypt 6회가 분 경계를 넘으면 6번째가 429 대신 401이 되는 기존 타이밍 결함으로, 단독 재실행도 같은 자리에서 실패하고 메일 변경과 무관하며 CI는 DSN이 없어 건너뛴다), `npm run lint`·`npm test`·`prettier --check`, `make screenshots`(admin-mail 캡처 2장 + 사이드바 항목이 늘어난 관리자 캡처 갱신)·`check-offline-assets.sh`·`check-env-contract.sh`·`check-docs.sh`·`go build`, 공용 md2pdf.mjs로 ADMIN_GUIDE.pdf 재생성. 커밋 746e0a0. 실제 사내 릴레이(postra)로의 도착은 이 환경에 릴레이가 없어 loopback 가짜 SMTP로 대신했다(표준 검증 항목 중 유일하게 남은 것).
