# v0.308.0 — 발송 기록 표가 50건에서 잘렸다는 사실을 말합니다

## 가득 찬 표는 "최근 14일이 이것뿐" 으로 읽힙니다

- v0.307.0 은 `GET /api/v1/admin/mail/deliveries` 가 **자르기 전에** 종류·상태로 거르게 해서, 좋은 한 주가 덮고 있던 실패를 표 위로 끌어올렸습니다. 그런데 응답에는 여전히 **잘렸다는 표시가 없었습니다** — 목록은 `LIMIT 50` 이고 14일 창 안의 행은 그보다 훨씬 많을 수 있는데, 운영자가 보는 것은 그냥 꽉 찬 표 하나입니다.
- 꽉 찬 표와 "창 안에 딱 50건이 있는 표" 는 화면에서 구별되지 않습니다. 앞의 것을 뒤의 것으로 읽으면 **더 좁혀야 한다는 것을 알 길이 없습니다** — 종류·상태 select 가 생긴 뒤에도 그렇습니다. 고른 조건에 맞는 행이 50건을 넘으면 같은 오독이 그대로 남고, 조건을 하나 더 거는 대신 "이게 전부" 라고 결론지어 버립니다.

## 51번째 행 하나로 답합니다

- 응답에 **`truncated: boolean`** 이 생겼습니다. 조건을 적용한 뒤에도 창 안의 행이 50건을 넘으면 `true` 입니다.
- 질의는 여전히 **한 번**입니다. `LIMIT` 에 `50+1` 을 보내고 **51번째 행은 목록에 넣지 않은 채 존재만 읽습니다** — 그 행이 있느냐가 답의 전부이므로 COUNT 질의를 따로 더하지 않았습니다.
- **총건수(`total`)는 싣지 않았습니다.** 몇 건이 더 있는지는 운영자가 쓸 수 있는 숫자가 아닙니다 — 할 수 있는 일은 좁히는 것뿐이고, 전체 건수를 돌려주면 이 목록에 없는 쪽 넘김을 약속하는 셈이 됩니다.
- 잘리지 않았으면 이 칸은 **생략합니다**(`omitempty`). 그래야 화면의 문장이 상시 문구가 되지 않습니다.
- `ORDER BY`·14일 창·`UNION` 집계·`INVALID_FILTER` 계약은 **건드리지 않았습니다**. v0.307.0 과 같은 조건에는 같은 50건이 같은 순서로 돌아옵니다.

## 화면과 문서

- 관리자 화면의 `주간보고 메일 발송` 카드는 `truncated` 일 때만 표 아래에 한 문장을 답니다 — `최근 50건만 보여 줍니다 — 이보다 오래된 발송이 최근 14일 안에 더 있으니 종류·상태로 좁혀 보세요`. 50 을 화면에 박지 않고 **받은 행 수를 읽으므로** 서버가 쪽 크기를 바꾸면 문장도 따라갑니다.
- `docs/openapi.yaml` 에 새 칸과 그것이 왜 생략되는지를, 관리자 가이드 **3.7** 에 문장이 보이면 한 번 더 좁히라는 한 줄을 적었습니다.

## 검증

새 시험을 만들지 않고, 이미 창 안에 **57건**을 넣고 있던 기존 시험 `TestTheOperatorCanPickTheFailuresOutOfAGoodWeek` 를 늘렸습니다 — 고치기 전 코드에서 `truncated=<nil>, want true` 로 **실패하는 것을 먼저 확인**한 뒤 통과했습니다. 같은 시험이 반대 방향도 증명합니다: 1건으로 좁힌 `?status=FAILED` 응답에는 `truncated` 가 **없습니다**. 실제 PostgreSQL(`pgvector/pgvector:pg16`) 위에서 전체 Go 테스트와 `go vet`·`gofmt`·`go build`, 가드·OpenAPI·쪽넘김·모달·버전 검사, 프런트엔드 160개 시험과 `tsc -b`·프로덕션 빌드를 통과했습니다. 표 아래 문장 자체는 이 저장소에 관리자 설정 화면을 렌더하는 프런트 시험이 없어 타입 검사와 빌드까지만 확인했습니다.

## 업그레이드

마이그레이션도, 새 환경변수도, 설정 키의 변경도 없습니다. `truncated` 는 **늘어난 칸 하나**이고 잘리지 않으면 아예 없으므로, 이 칸을 모르는 옛 화면도 v0.307.0 과 똑같이 읽습니다. 기존과 같이 PostgreSQL 을 백업한 뒤 v0.308.0 이미지를 올리면 됩니다.
