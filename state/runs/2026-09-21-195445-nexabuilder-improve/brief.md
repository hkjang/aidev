- 과제: GET /api/v1/data/lists/{listId}도 휴지통 목록의 행 조회를 차단하고 어댑터 목록 경로의 회귀 테스트를 추가한다 (가치 3 / 위험 2 / 작업량 S)
- 왜: DataAdapterService.queryList는 findById만 사용하여 deletedAt이 설정된 목록도 SQL/엔티티 조회로 넘기며, 앞선 회차에서 수정한 builder 데이터·정의·내보내기와 판정이 다르다. 기존 NexaUiService.requireLiveList를 재사용하면 이 별도 GET 경로도 같은 400 JSON 계약으로 막고 재발을 검증할 수 있다.
- 수용 기준: 1) 존재하지 않는 목록과 deletedAt이 null이 아닌 목록은 GET /api/v1/data/lists/{id}에서 HTTP 400, JSON success=false, message="List not found: <id>"를 반환하고 Rows를 내보내지 않는다. SQL 기반과 엔티티 기반 모두 조회 분기 전에 판정한다. 2) 정상 목록은 기존 대소문자를 포함한 {"Rows":[...],"totalCount":N} 형식을 유지하고 GET 쿼리 파라미터의 페이징·정렬·필터가 유지된다. 3) 실제 H2/MockMvc 테스트로 정상 엔티티 목록의 행 값·총 개수·페이징/필터, 정상 SQL 목록, 두 종류 목록의 삭제 후 차단 및 존재하지 않는 ID를 검증한다. 삭제 테스트는 같은 픽스처가 삭제 전에는 200이었음을 확인하고, 구현 전에는 200 대 400 불일치로 실패해야 한다.
- 건드릴 파일: src/main/java/com/nexabuilder/core/data/DataAdapterService.java:queryList 및 생성자 의존 필드 — NexaListRepository 대신 NexaUiService를 주입하고 첫 조회를 requireLiveList(listId)로 대체. listRepository는 이 클래스에서 queryList 한 곳에서만 사용한다. src/test/java/com/nexabuilder/api/DataAdapterIntegrationTest.java — 기존 6개 테스트(엔티티 4, 필드 1, 코드 1)를 보존하고 목록 시나리오와 UUID 격리 픽스처를 추가. src/main/java/com/nexabuilder/core/ui/NexaUiService.java:requireLiveList — 필요하면 호출자 Javadoc만 보완, 판정 자체는 변경하지 않는다.
- 검증 명령: 저장소 루트에서 `sh ./gradlew --no-daemon test --tests 'com.nexabuilder.api.DataAdapterIntegrationTest' --tests 'com.nexabuilder.api.BuilderListDataSoftDeleteIntegrationTest' --tests 'com.nexabuilder.api.ListExportIntegrationTest'`; 이후 `sh ./gradlew --no-daemon cleanTest test`; `sh ./gradlew --no-daemon bootJar -x test`. gradlew는 git 모드 100644이므로 실행 비트 변경 없이 sh로 실행한다.
- 위험과 피할 것: auth/session/permission, migrations, .github/workflows와 HTTP 404 전환은 범위 밖. active=false를 삭제와 혼동하지 않는다(requireLiveList는 deletedAt만 검사). queryEntity/queryCodes·SQL 실행·페이징 알고리즘은 그대로 둔다. 특히 BuilderListDataSoftDeleteIntegrationTest.seedList를 복사할 때 .pageSize(10) 등을 반드시 지정한다: NexaListDef.pageSize는 Integer이고 queryList의 parse(..., int) 호출에서 null 언박싱 문제가 별도로 있다. 이 문제를 이번 패치에 섞지 않는다. NexaUiService 및 그 직접 서비스 의존 필드에 DataAdapterService 역참조가 없고, 전체 src/main 검색에서 주입자는 DataAdapterController뿐이다. 그래도 새 주입 후 Spring 통합 테스트 부팅으로 순환 의존 여부를 최종 확인한다. @DirtiesContext 추가나 시드 목록 수정 금지, UUID 픽스처를 사용한다. SQL 픽스처는 SqlMetadataRepository에 고유 sqlId와 sqlText를 저장하고 같은 테스트용 테이블을 조회하면 된다. SQL 행 키는 엔티티 경로와 달리 소문자 정규화하지 않으므로 이 변경에서 키를 통일하지 않는다.
- 차선 후보: DataAdapterService.queryList의 nullable pageSize 기본값 처리 — 위 삭제 문제가 이미 다른 변경으로 해결되어 1순위가 성립하지 않을 때만 선택. NexaListDef.pageSize=null이어도 parse가 의도한 기본 100을 쓰도록 한 곳에서 처리하고, 실제 목록 GET 200 및 기본 페이지 제한을 검증한다(가치 3 / 위험 1 / S). 현재 정찰에서는 null 언박싱 코드 경로만 확인했고 HTTP 500은 실행 재현하지 않았다.
