# nexabuilder 프로필 (2026-09-27)
- 목적: 엔티티·폼·목록·워크플로 메타데이터로 업무 화면을 만드는 Spring Boot 로우코드 플랫폼과 관리 콘솔.
- 스택: Java 21, Spring Boot 4.1.1, Gradle 8.14.3 Kotlin DSL, JPA/JdbcTemplate, Liquibase XML, 기본 H2와 외부 DB 프로필, Thymeleaf/Bootstrap/htmx/jQuery 4+migrate/jqWidgets/ECharts, Groovy, POI 5.3.0/OpenPDF 3.0.5. 현재 버전 v1.24.0(master@7f168ac).
- 구조:
  - `core/ui` — NexaUiService: `listDefinition`(entityMapFor 로 entityId null 허용), `listData`, `formDefinition`, `requireLiveList`/`requireLiveEntity`. `requireLiveList(listId)` 가 존재+deletedAt 판정의 **단일 게이트**로 listDefinition·listData·ListExportController.resolveExportable·DataAdapterService.queryList 네 경로가 공유한다. 폼만 formDefinition 안에 인라인 판정으로 남아 있다(150-158).
  - `core/data` — DataAdapterService: jqxgrid용 `{Rows,totalCount}`. `parse(Map,Integer)` 가 `pagenum`/`pagesize` 를 클램프(하한 0, 상한 `MAX_PAGE_SIZE=1000`, fallback 100). `executeEntityBacked` 는 DB 페이징(`SqlPagination.limitOffset`), `executeSqlBacked` 는 전체 행을 받아 `lowerCaseKeys`→`applySort`→`applyPaging(subList)` 로 자바 페이징. **두 백엔드 모두 응답 키를 소문자로 통일한다**(2026-09-27 에 SQL 쪽 정렬).
  - `core/entity` — EntityService(동적 DML/조회), SchemaDdlService(DDL), RecordSet(`getRows()` 는 **unmodifiableList**). `EntityService.list(table, filters, offset, limit)` 은 filters 맵의 **모든 키**로 `WHERE k = :k` 를 만들고 `sanitizeIdentifier` 정규식 `^[a-zA-Z_][a-zA-Z0-9_]*$` 이 선행 밑줄을 통과시킨다 — 프로토콜 파라미터를 걸러 넣지 않으면 SQL 문법 오류가 된다.
  - `core/sql` — SqlExecutor(executeQuery/executeDml/executeRawQuery, `resolveSql` 은 @Cacheable, 페이징 API 없음), SqlPagination 의 DB별 LIMIT/OFFSET.
  - `core/*` — permission, auth, session, audit, llm/ai, menu, report, version 등 도메인 서비스.
  - `api/controller`·`api/dto` — REST와 ApiResponse. GlobalExceptionHandler: IllegalArgumentException→400, AccessDenied→AccessAuditHandler, AI 쿼터→429. **`DataAccessException` 계열 핸들러는 없다 → SQL 오류는 500.**
  - `web/controller`·`resources/templates`·`resources/static` — 서버 화면. `templates/runtime/` 에 list(jqxgrid) + 대체 뷰 7종(kanban/tree/calendar/pivot/gantt/map/chart). 7종 전부 `POST /api/v1/builder/lists/{id}/data` 에 `{_offset,_limit}` 을 보내고 `valueOf(row,field)`(literal→UPPER→lower)로 행을 읽으며 fetch 실패를 `catch (e)` 로 삼킨다.
  - `resources/db/migration` — Liquibase 001~079 XML + changelog-master.xml. 027이 목록/폼/엔티티 `deleted_at` 추가.
  - `src/test` — SpringBootTest/MockMvc/H2 통합 테스트 중심, 592건 통과(2026-09-27 기준).
- 빌드·테스트: `sh ./gradlew --no-daemon test`(**gradlew 가 100644 라 sh 경유 필수**), 단일 `--tests 'com.nexabuilder.api.X'`, 전체 강제 `--no-daemon cleanTest test`(수 분, 테스트 힙 2g), 패키징 `--no-daemon bootJar -x test`. 자율 회차의 정찰 단계에서는 gradlew 실행이 샌드박스 승인 대상이라 못 돌 수 있다(2026-09-24 에 실제 차단) — 실패 재현은 구현 단계에서 할 것.
- 관례: Lombok 생성자 주입. 테스트 픽스처는 UUID 8자 접미사·정리 없음. 커밋은 한국어 `type(scope): …합니다`, 버전 커밋/PR merge 는 영어. Liquibase 새 XML 은 changelog-master 에 include. 설정은 application.yml + nexa_config 런타임 설정.
- 위험 구역: `core/auth`·`core/session`·`infra/security`·`core/permission`, `db/migration`, `.github/workflows`, workflow 의 비동기 감사·종료 경합. `RecordSet`/`SqlExecutor` 는 내보내기·Groovy·워크플로·대시보드가 공유하므로 계약 변경 금지. Jackson2JsonConfig:57 에 [removal] 경고(Jackson 3 이전은 별도 L).
- 자주 깨지는 곳: `@DirtiesContext` 를 붙이면 컨텍스트 재생성으로 시간·힙·비동기 종료 경합이 악화(2026-09-17). **같은 값을 읽는 경로가 여럿이라 한 곳만 고치면 구멍이 남는 패턴이 6회차 연속 반복**(목록 soft-delete 4경로 → 엔티티 soft-delete → SQL 목록 키 대소문자 → 이번의 `_offset`/`_limit`). 새 판정·새 파라미터를 다룰 때는 그 값을 읽는 리더를 전부 세고 단일 헬퍼/단일 규약으로 모을 것. webjar 버전 고정 URL 404, jQuery 4 에서 migrate 제거 시 jqWidgets 오류.
- 검증 함정: CI 는 chmod 후 gradlew 직접 실행 + setup-java Temurin21, foojay 가 누락 JDK 다운로드. CI 는 test+bootJar, CodeQL 은 public 저장소에서만. `/api/v1/data/*` 는 성공 시 `{Rows,totalCount}`, 실패 시 `{success,message}` 로 **봉투가 다르다**. `/api/v1/builder/**` 는 `ApiResponse` 봉투(`data`/`total`). `NexaListDef.pageSize` 는 nullable, fallback 100 을 `NexaUiService.listData` 와 `DataAdapterService.parse` 가 공유한다. 페이지 파라미터 이름이 경로마다 다르다 — `/data/*` 는 `pagenum`/`pagesize`, `/builder/lists/{id}/data`·`/entities/{id}/rows` 는 `_offset`/`_limit`. H2 는 `SELECT id, name` 에 `ID`/`NAME` 을 주고 음수 OFFSET 을 거절한다(둘 다 실행 확인). PDF 한글 글리프는 환경 폰트 의존. 외부 서비스 의존 테스트 유무는 미확인.
