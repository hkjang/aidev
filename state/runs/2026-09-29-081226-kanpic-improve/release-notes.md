# v0.258.0

## 메일 서버가 응답을 멈춰도 취소된 작업이 연결을 붙들지 않습니다

메일 서버가 TCP 연결을 받아 준 뒤 첫 인사나 EHLO 응답을 보내지 않으면,
kanpic 의 발송과 연결 확인은 응답을 계속 기다렸습니다. 호출자가 정한 시한이
지나거나 작업을 취소해도 이미 열린 소켓에는 그 취소가 전달되지 않았습니다.
연결에 성공했다는 이유로, 끝나야 할 작업이 끝나지 않는 문제였습니다.

이제 `Deliver` 와 `Verify` 는 첫 인사부터 세션 종료까지 호출자 컨텍스트를
감시하고, 시한 만료나 취소가 오면 실제 TCP 소켓을 닫습니다. 따라서 응답을
기다리던 작업도 오류를 반환하며 정리됩니다. 성공한 경우와 실패한 경우 모두
취소 감시 콜백을 해제하거나 실행 중인 콜백이 끝날 때까지 기다립니다.

처음부터 TLS 를 사용하는 연결도 같은 원칙을 따릅니다. 연결뿐 아니라 TLS
handshake 에도 호출자 컨텍스트가 적용되어, 상대가 handshake 를 멈춘 상태에서
취소해도 계속 기다리지 않습니다.

## 관리자와 알림을 받는 분에게 달라지는 점

응답하지 않는 SMTP 릴레이를 확인하거나 그 릴레이로 발송할 때, 호출자가 정한
시한과 취소가 연결 이후에도 효력을 갖습니다. 정상 릴레이로 보내는 메일의
수신자·제목·본문은 달라지지 않습니다.

`Config.Timeout` 의 기존 연결 제한 의미, TLS 인증서 검증과 AUTH 정책은
유지합니다. 브라우저 요청이 끝나도 알림 준비와 전송을 이어 가도록 서비스에서
취소를 분리한 동작도 유지합니다. 탭을 닫는 행위가 곧바로 모든 알림 발송을
취소한다는 뜻은 아닙니다.

서버가 메일을 받은 뒤 완료 응답만 유실되는 경우의 중복 재시도 가능성은
기존과 같습니다. 이번 변경이 이미 전달된 메일을 회수하거나 재전송 여부를
새로 판단하지는 않습니다.

## 확인

- 실제 로컬 TCP 연결에서 `Deliver`/`Verify` × greeting/EHLO/TLS ×
  시한 만료/명시적 취소의 12사례를 검사했습니다. 구현 단계에서 수정 전
  12실패 → 수정 후 통과, 구현 원복 시 다시 12실패를 확인했습니다.
- 릴리즈 준비에서 `go test ./...`, `go test ./internal/mail -race -count=2`,
  `go vet ./...`, `go build ./...`, `gofmt -l ./cmd ./internal ./pkg`,
  `scripts/check-release-docs.sh`, `scripts/check-commit-identities.sh` 와
  `git diff --check` 를 실행했습니다.
- 러너가 보존한 구현 커밋 `de77d56` 의 GitHub CI 결과에서 `test` 와
  `commit-identity` 작업의 성공을 확인했습니다. 웹·DB 통합·브라우저 E2E 는
  이번 릴리즈 세션에서 별도로 재실행하지 않았습니다.
- 운영 TLS 릴레이 및 STARTTLS·DATA·QUIT 정지의 개별 회귀는 미실행입니다.
  세션 전체가 같은 원본 소켓의 취소 감시를 사용하도록 구현했습니다.

## 올리실 때

v0.257.0 에서 올라오시는 분은 이미지를 바꿔 다시 띄우시면 됩니다.
마이그레이션이나 새 설정은 없고, 필수 환경 변수는 계속 `POSTGRES_DSN` 입니다.

운영 적용은 먼저 한 인스턴스에서 연결 확인과 시험 메일 발송을 확인한 뒤
확대하십시오. 정상 릴레이 연결이나 시험 발송이 실패하면 운영 담당자가 확대를
중단하고 v0.257.0 이미지로 되돌릴 수 있습니다. 데이터 스키마는 바뀌지 않습니다.
적용 직후와 다음 날 발송 실패·지연 문의를 확인하고, 시한을 넘겨 멈춘 SMTP
작업이 다시 발생하는지 살펴보십시오.

## 오프라인 설치

이 릴리즈는 웹 자산과 서버 바이너리를 포함한 Docker 이미지 아카이브로 제공됩니다.

```bash
sha256sum -c kanpic-v0.258.0.tar.gz.sha256
gzip -dc kanpic-v0.258.0.tar.gz | docker load
docker run --rm -p 8080:8080 \
  -e POSTGRES_DSN='postgres://kanpic:password@postgres.internal:5432/kanpic?sslmode=require' \
  kanpic:v0.258.0
```

- 필수 런타임 환경 변수: `POSTGRES_DSN`
- Redis 및 외부 인터넷 연결: 불필요
- 관리자 초기 로그인을 보호하려면 `BOOTSTRAP_ADMIN_ID`와 `BOOTSTRAP_ADMIN_PASSWORD`를 함께 지정합니다.
- 무결성 검증 파일: `kanpic-v0.258.0.tar.gz.sha256`
