# v0.264.0

## 분수 서식에 자리 기호를 길게 적어도 격자가 멈추지 않습니다

분수 서식은 값을 소수가 아니라 분수로 적습니다 — 2.75 는 `# ?/?` 로
"2 3/4" 입니다. 빗금 뒤의 자리 기호 개수가 분모를 몇 자리까지 허락할지
정합니다(`# ??/??` 는 두 자리, 99 까지).

분모를 고르는 자리는 1 부터 허락된 분모까지 **하나씩 모두 재어** 가장 덜
어긋나는 것을 고릅니다. 그래서 자리 기호 개수가 그대로 칸 하나를 그리는
비용입니다. 그런데 이 상한이 아홉 자리까지 열려 있었고, 아홉 자리는 분모
999,999,999 — 칸 하나에 10억 번입니다.

| 자리 기호 | 재는 분모 | 칸 하나에 걸리는 시간 |
| --- | --- | --- |
| `??????/??????` (여섯) | 999,999 | 2ms |
| `???????/???????` (일곱) | 9,999,999 | 15ms |
| `????????/????????` (여덟) | 99,999,999 | 151ms |
| `?????????/?????????` (아홉) | 999,999,999 | 1.5초 |

이 서식이 붙은 칸이 **하나** 있으면 서버의 `TEXT()` 가 1.5초를 썼고, XLSX
에서 그런 서식을 그대로 읽어 온 칸도 같았습니다. 더 눈에 띄는 쪽은
격자입니다. 화면의 분수 서식은 `web/src/lib/cellFormat.ts` 가 같은 규칙을
거울로 두고 그리므로, 같은 루프가 **브라우저 메인 스레드**에서 돌아 칸
하나 때문에 그리드 전체가 멎었습니다.

이제 자리 기호를 **여섯 개까지만** 셉니다. 일곱 개를 적든 아홉 개를 적든
여섯 자리 분모까지만 재므로, 칸 하나의 비용이 1.5초에서 2ms 로 내려갑니다.

## 일곱 자리 이상을 적은 서식은 적히는 분수가 달라집니다

좁히는 변경이므로 출력이 바뀌는 자리가 있습니다. **어떤 분모로도 떨어지지
않는 값**(무리수)은 자리를 넓힐수록 조금 더 가까운 분수가 나오므로, 여섯
자리에서 멈춘 분수가 적힙니다.

| 값 | 서식 | 전 | 이제 |
| --- | --- | --- | --- |
| π | `# ?????????/?????????` | `3 192583/1360120` | `3 51669/364913` |
| √2 | `# ???????/???????` | `1 470832/1136689` | `1 195025/470832` |
| 1/3 | `?????????/?????????` | `1/3` | `1/3` |
| 0.3125 | `?????????/?????????` | `5/16` | `5/16` |
| 3.14159 | `# ?????????/?????????` | `3 14159/100000` | `3 14159/100000` |
| e | `# ?????????/?????????` | `2 286565/398959` | `2 286565/398959` |

달라지는 쪽도 분수 서식이 보여 주려던 것과는 거리가 멉니다 —
`3 192583/1360120` 과 `3 51669/364913` 은 둘 다 "읽을 수 있는 분수" 가
아닙니다. 어긋남으로 보면 π 는 전에 10⁻¹³ 안쪽, 이제 10⁻¹¹ 안쪽입니다.

**짧은 분수나 유한 소수로 적히는 값은 한 글자도 바뀌지 않습니다.**
1/3·0.3125·3.14159 처럼 여섯 자리 안에서 정확히 떨어지는 값은 상한을
좁혀도 같은 분수를 찾고, e 처럼 여섯 자리에서 이미 가장 가까운 분수에
닿은 값도 그대로입니다.

**자리 기호를 여섯 개 이하로 적은 서식은 전혀 영향을 받지 않습니다.**
엑셀 기본 서식 12·13 번(`# ?/?`, `# ??/??`)을 포함해 실제로 쓰이는 분수
서식은 모두 이쪽입니다.

## 그 밖에 바뀌는 것은 없습니다

- **마이그레이션도, 새 설정도 없습니다.** 저장된 셀 값과 서식 문자열은 그대로
  남고, 달라지는 것은 그 서식으로 **그릴 때 적히는 글자**뿐입니다.
- **분모를 못 박은 서식(`?/8`, `# ??/16`)은 손대지 않았습니다.** 그런 서식은
  분모를 재지 않고 적힌 수를 그대로 쓰므로 이번 상한과 무관합니다.
- 근사 분수를 고르는 알고리즘, 같은 만큼 어긋날 때 분모가 작은 쪽을 고르는
  규칙, 1e15 를 넘는 값은 분수로 적지 않는 규칙(`maxFractionValue`),
  0.99 를 `# ?/?` 로 적을 때 정수 자리로 올리는 처리, 음수 부호 처리는 한
  줄도 바뀌지 않았습니다.
- 날짜 서식의 빗금(`m/d/yyyy`)은 전과 같이 분수로 읽지 않습니다.
- **Go 와 TypeScript 를 같은 수로 함께 고쳤습니다.** 두 파서는 저장소 관례대로
  거울로 두고 통합하지 않았고, 상한은 양쪽에 `maxFractionPlaces`·
  `MAX_FRACTION_PLACES` 로 이름을 붙여 서로를 가리키는 주석을 달았습니다.
  `testdata/cell-formats.json` 이 둘이 같은 글자를 적는지 계속 붙잡습니다.

## 확인

- 서버의 `formatValue` 를 직접 불러, 자리 기호를 여섯·일곱·여덟·아홉 개
  적은 네 서식이 **같은 글자**를 내는지 값 다섯 개로 못 박았습니다. 같은
  검사가 칸 하나에 1초를 넘기면 실패합니다 — 상한이 그대로 칸 하나의
  비용이기 때문입니다. 이 검사는 0.03초에 통과합니다.
- 기다리는 글자는 여섯 자리 상한을 손으로 적어 둔 것이라, 상한을 다시
  움직이면 시간뿐 아니라 이 글자가 걸립니다.
- 격자 쪽도 같은 글자를 `web/src/lib/cellFormat.test.ts` 에서 못 박아, 두
  구현이 갈라지면 어느 쪽이든 실패합니다.
- 표에 적은 시간은 분모를 재는 루프만 떼어 내 이 기계에서 상한별로
  측정한 값입니다(여섯 2ms, 일곱 15ms, 여덟 151ms, 아홉 1.516초). π 의
  "전" 글자도 같은 측정에서 나온 `3 192583/1360120` 입니다.
- 분수 서식을 보던 기존 검사 18 행은 모두 그대로 통과합니다.
- 릴리즈 준비에서 `go build ./...`, `go vet ./...`,
  `go vet -tags=integration ./internal/...`,
  `gofmt -l ./cmd ./internal ./pkg`, `go test ./...`(테스트가 있는 19개
  패키지 전부 통과, 실패 없음), `go test ./internal/formula -race
  -count=1`, `npm ci && npm test`(74개 파일 520개 테스트 전부 통과),
  `npm run build`, `scripts/check-release-docs.sh`,
  `scripts/check-commit-identities.sh` 를 실행했습니다.
- DB 통합 테스트와 브라우저 E2E 는 이번 릴리즈 준비에서 다시 돌리지
  않았습니다. 변경은 서식 문자열의 자리 기호를 세는 상한 한 줄이 Go 와 TS
  양쪽에 있는 것이고, SQL·스키마·화면 구성은 손대지 않았습니다. 이 둘은
  태그를 올린 뒤 CI 에서 돌아갑니다.

## 올리실 때

v0.263.0 에서 올라오시는 분은 이미지를 바꿔 다시 띄우시면 됩니다.
마이그레이션이나 새 설정은 없고, 필수 환경 변수는 계속 `POSTGRES_DSN`
입니다.

올리기 전에 따로 보실 것은 없습니다. 자리 기호를 일곱 개 이상 적은 분수
서식을 쓰신 통합문서가 있다면 그 칸에 적히는 분수가 위 표처럼 달라지지만,
저장된 값과 서식은 그대로이므로 상한을 되돌리면 전 글자로 돌아옵니다.

운영 적용은 먼저 한 인스턴스에서 확인한 뒤 확대하십시오. 올린 뒤 분수
서식이 붙은 통합문서를 열어 격자가 바로 그려지는지, 그 칸의 분수가 전과
같이 읽히는지 보십시오. 여섯 자리 이하 서식에서 글자가 달라졌다면 되돌릴
신호입니다 — 운영 담당자가 확대를 중단하고 v0.263.0 이미지로 되돌릴 수
있습니다. 스키마도 설정도 바뀌지 않으므로 되돌린 뒤의 동작은 전과
같습니다.

## 오프라인 설치

이 릴리즈는 웹 자산과 서버 바이너리를 포함한 Docker 이미지 아카이브로 제공됩니다.

```bash
sha256sum -c kanpic-v0.264.0.tar.gz.sha256
gzip -dc kanpic-v0.264.0.tar.gz | docker load
docker run --rm -p 8080:8080 \
  -e POSTGRES_DSN='postgres://kanpic:password@postgres.internal:5432/kanpic?sslmode=require' \
  kanpic:v0.264.0
```

- 필수 런타임 환경 변수: `POSTGRES_DSN`
- Redis 및 외부 인터넷 연결: 불필요
- 관리자 초기 로그인을 보호하려면 `BOOTSTRAP_ADMIN_ID`와 `BOOTSTRAP_ADMIN_PASSWORD`를 함께 지정합니다.
- 무결성 검증 파일: `kanpic-v0.264.0.tar.gz.sha256`
