## 2026-09-16
- 선택: Silent SSO 캠페인(silent-sso-2026-09) 제공자 쪽 — RP의 `prompt=none` 루프를 이 서비스에서 볼 수 있게 답변별 카운터와 거절 로그를 두고, RP 구현 규칙과 `auto_login`이 어디 있는지를 문서에 적기 (가치 3 / 위험 1 / 작업량 S)
- 결과: 성공 (커밋 f292349)
- 요약: 09-13 회차의 판단은 그대로다 — ReSSO는 이 캠페인의 **제공자 쪽**이고 상류 issuer·콜백·discovery 조회 같은 RP 코드가 한 줄도 없어(이번에도 `git log`와 grep으로 확인, 그 뒤 세 커밋은 메일·비밀번호 재확인·팔레트) 표준의 `auto_login`·`sessionStorage` 표시·`/login?sso=none`은 여기 둘 곳이 없고, 캠페인 규칙에 따라 identity brokering을 새로 만들지 않았다. 다만 "이 저장소에 OIDC가 없다"는 문장은 ReSSO에 글자 그대로는 맞지 않는다 — ReSSO는 캠페인의 RP 스무 개가 `prompt=none`을 **보내는 상대**이고, 표준이 "이 일의 전부"라고 부르는 무한 루프는 RP 하나가 고장 나면 **제공자에서만 한눈에 보인다**. 그런데 지금까지는 어디에도 보이지 않았다: `prompt=none`의 두 답(코드·`login_required`)이 모두 302라 `resso_http_requests_total`에는 정상 Redirect로, 접근 로그에는 `status=302`로만 남아, 브라우저가 두 호스트 사이를 Redirect 속도로 오가는 루프가 이 서비스가 publish하는 모든 신호에서 바쁘게 잘 도는 Endpoint와 같았다. 그래서 같은 모양의 계열 셋(`resso_token_errors_total`·`resso_introspection_errors_total`·`resso_authorization_errors_total`)이 있는 방식 그대로 `resso_silent_authentications_total{result="code"|"login_required"}`를 더했다(고정 카디널리티 둘, 코드 발급은 `prompt=none`일 때만 센다). 계열에 client 라벨을 두지 않는 대신 거절 한 건에 로그 한 줄(`a silent authentication found no session to reuse`, `client_id`·`remote_ip`·`trace_id`)을 남겨 어느 RP인지 찾게 했다 — 루프는 한 `remote_ip`에서 같은 `client_id`가 초당 여러 번인 모양이다. 세션을 **읽지 못한** 요청은 여전히 `server_error`로 답하고 이 계열이 아니라 `resso_authorization_errors_total{stage="sso_session"}`에 센다 — 거절이 아니고, RP는 `login_required`를 "로그아웃했다"로 읽기 때문이다(표준의 "실패가 아니라 평범한 답"이 성립하려면 진짜 실패는 다른 답이어야 한다). 문서: `docs/compatibility.md`에 «RP가 silent SSO를 구현할 때» 절(제공자가 하는 것 셋, 루프 방지 장치와 `auto_login`은 RP 쪽이라는 것과 그 이유 — 제공자가 `prompt=none`을 무시하면 OIDC Core 3.1.2.1 위반, 최상위 이동을 써야 하는 이유는 ReSSO가 `frame-ancestors 'none'`이라는 것), `docs/operations.md` 경보 목록에 급증 읽는 법, README 지표 표 한 줄, `docs/ADMIN_GUIDE.md` 5-1에 «로그인 화면 없이 들어가기 (silent SSO)» 소절(캠페인이 요구한 `auto_login` 항목 — **ReSSO가 아니라 각 서비스에 있고 기본 꺼짐**이라는 것, 콘솔 자체는 같은 쿠키라 설정 없이 이미 그렇게 동작한다는 것, 루프를 보는 자리와 고칠 곳)과 장애 대응 표에 "화면이 깜빡이며 로그인 화면이 뜨지 않는다" 행. 검증: 새 연동 테스트 `TestIntegrationSilentAuthenticationsAreCountedByTheirAnswer`가 대화형 인가 둘은 세지 않음 → 세션 없는 `prompt=none`이 `state` 실은 `login_required`로 1 → 세션 있는
