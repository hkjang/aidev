# sqlon 프로필 (2026-09-22)
- 목적: 다중 DB의 SQL 생성·읽기 실행 가드, 플릿 관측·진단·승인 기반 DBA 변경을 MCP/REST/Web UI로 제공한다.
- 스택: Go 1.25.0, net/http ServeMux, 메모리/PostgreSQL 메타 저장소, embed HTML·인라인 JavaScript; Oracle은 OCI/godror 별도 빌드.
- 기준: main@57f99b7(v0.1.5). 이전 actor·카탈로그 인증·async TTL·tracking/handoff/mail/MCP OAuth 성공 수정은 현재 기준에 미통합. 과거 성공만 보고 재구현하지 않는다.
- 구조:
  - cmd/sqlon·internal/app: CLI·서버 부팅·Options/환경변수.
  - internal/mcp: MCP·REST·embed Web UI·인증·DBA API.
  - internal/meta: 사용자·세션·키·프로파일 권한·설정의 메모리/PG 저장소.
  - internal/catalog·metasync: JSON 카탈로그·검증·메타데이터 수집.
  - internal/dbconn·engine: 연결·SQL 실행·DB 방언, internal/change: 승인 변경 상태기계.
  - internal/fleet·observability·collector: 플릿·세션·워크로드 수집과 진단.
  - data/·docs/·docs/reports/: 데이터셋·가이드·중복 Markdown/생성 문서.
  - test/integration·deploy/test·scripts/: 실제 DB 통합 검증·테스트 컨테이너·빌드/릴리즈.
- 빌드·테스트: 이번 `go test ./... -count=1` 통과(mcp 3.659초), `go vet ./...` 통과. `sh scripts/build.sh`는 CGO=0 Windows amd64/Linux amd64·arm64 빌드(이번 미실행).
- 통합 검증: `docker compose -f deploy/test/docker-compose.yml up -d --wait` 후 `go test -tags integration ./test/integration -v`; 실제 PG/MySQL/MariaDB 필요(이번 미실행). race·브라우저 검증 미실행.
- 관례: feat/fix/docs/release 및 한영 혼용 커밋, Options/SQLON_*·meta 설정, CHANGELOG Unreleased. PG 마이그레이션은 internal/meta/pg.go에 포함.
- 문서 상태: 저장소 CLAUDE.md/AGENTS.md 없음. Go TODO/FIXME 검색 없음. docs/README.md 및 auth/rest-api/security 등 다수 0바이트. 세 가이드와 로드맵은 v0.1.2 기준.
- 문서 불일치: 관리자 가이드의 프로파일 생성 예는 POST /api/fleet/instances지만 현 라우트는 GET만 존재; 실제 생성은 POST /api/db-profiles. 감사 암호화 주장의 전체 런타임 검증은 미확인.
- 위험 구역: mcp/auth.go·authapi.go·meta 인증/세션, meta/pg.go 및 migration, execguard/changeexecutor, workflows. nil 사용자 로컬 신뢰 규칙을 전역으로 바꾸지 않는다.
- 자주 깨지는 곳: Register는 REST에 전역 withUser를 적용하지 않음. requireActor는 사용자 반환, requireAdmin/requireDBA는 bool. canUseProfileID(nil)의 로컬 신뢰와 meta.CanUseProfile(nil)의 거절 차이.
- 이번 선택: dbapi.go:upsertProfileMeta는 PUT에서 visibility 생략을 private으로 저장하고 manage 수임자 명시 변경 검사도 생략한다. 소스 확인, 신규 HTTP 재현은 미실행. 생성 기본값은 유지하고 수정 때만 기존 값을 보존하도록 과제 작성.
- 검증 함정: newAuthServer→실제 로그인→Register mux→doReq·withCookie로 생성/grant/수정/목록을 통과해야 함. MemStore/PGStore 모두 visibility를 저장하며 응답과 제3자 목록도 함께 검증해야 함.
- 검증 함정: integration 태그 테스트는 일반 go test에서 제외. .github에는 FUNDING.yml만 있어 README의 CI 설명과 다름. 다수 CRLF·CHANGELOG 혼합 줄바꿈 때문에 전체 gofmt/줄바꿈 변환 금지.
- 스킬 제한: 요청한 pmo/technology 3개 스킬을 제공 도구·로컬 경로·리소스에서 찾지 못함. 해당 고유 절차/형식 미확인.
