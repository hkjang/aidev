# AgentHub 프로필 (2026-10-09)
- 목적: 사용자별 격리 AI 런타임과 자동 작업을 정책·승인·DLP·감사로 통제하는 사내 플랫폼.
- 스택: Go 1.25(chi, pgx, OIDC, OpenTelemetry), PostgreSQL, React/TypeScript/Vite, Kubernetes, Node/Playwright. CI Node 22.
- 구조:
  - cmd/: control-plane·worker·runtime-proxy·offline 진입점.
  - internal/api/: REST·관리자·런타임 게이트웨이, catalog.go 라우트 선언, tracking.go CSP/보고/추적 주입.
  - internal/store/: PostgreSQL 저장·마이그레이션·감사·알림·메일 큐.
  - internal/execution/, internal/mail/: 작업/이벤트 전달과 SMTP 큐.
  - internal/runtimecfg/, internal/operator/: 런타임 설정과 Kubernetes 리소스.
  - internal/dlp/, internal/tracking/: 내용 검사, 추적 스니펫/CSP/위반 기록.
  - web/src/: 콘솔. AdminSettings.tsx와 trackingLimits.ts에 추적 상한 안내·카운터.
  - web/scripts/: 브라우저 e2e·Node 단위 회귀·가이드 촬영. guide-settings-check.mjs가 네 전역 설정 백업/복원.
  - deploy/, scripts/, runtime-images.json: 배포·이미지 검증과 sourcePaths/버전 계약.
  - docs/: 관리자/사용자 가이드 md/PDF·architecture.md·decisions/. 저장소 CLAUDE.md·AGENTS.md·roadmap/TODO 파일 발견 못 함.
- 빌드·테스트: 이번 실제 실행 `cd web && node --test scripts/*.test.mjs` 147건 pass, fail/skip 0; `node --test scripts/guide-settings-check.test.mjs`·`node --check scripts/guide-shots.mjs`도 통과(web 기준).
- 빌드·테스트: CI `go test -race ./cmd/... ./internal/...`; web `npm ci && npm run lint && npm run test:sso && npm run build`; 이미지 `bash scripts/release-catalog-images.sh check-versions`; kustomize/compose 검사. 이번 Go·빌드·CI 전체 미실행.
- 빌드·테스트: DB live는 격리 AGENTHUB_TEST_DSN/암호화 키 필요, 없으면 skip(이전 프로필). 과거 병렬 오염 때문에 `go test -race -p 1 ./cmd/... ./internal/...` 권장. 실제 DB·클러스터·브라우저 이번 미검증.
- 관례: HEAD 6af55c3, v0.261.0. 영어 conventional prefix + 한국어 설명 커밋. 설정은 system_settings JSON + 별도 secret, docs에 가이드.
- 관례: 마이그레이션은 internal/store/migrations(이번 상세 절차 미재확인). auth·세션·마이그레이션·workflow는 작은 자율 개선 대상에서 제외.
- 관례: runtime-images.json의 sourcePaths에 web 없음(이번 전체 매니페스트 확인). cmd/runtime-proxy·internal/dlp·internal/policy는 base 입력이므로 BASE_VERSION 연동 검토 필요.

- 위험 구역: auth.go·mcpoauth.go·세션 게이트웨이·internal/store/migrations·.github/workflows.
- 위험 구역: 가이드 촬영은 전역 policy/dlp/sessionGateway/tracking을 임시 덮어쓴다. withGuideSettings는 백업 전부 완료 후 작업하고 네 복원을 모두 시도하며 원래 작업 오류를 우선한다.
- 위험 구역: guide-shots:captureTracking의 CSP 보고 fetch만 timeout 누락(이번 선택 과제). 실제 호출부+실함수+로컬 HTTP에서 20ms 설정/120ms 대기에도 복원 미진행 재현. 브라우저·DB 검증은 아님.
- 위험 구역: captureTracking finally는 추적 위반 전체 DELETE. 서버 clearTrackingViolations는 전체 Forget이며 개별 삭제 라우트 없음.
- 위험 구역: 감사 details는 원문 그대로 저장/출력된다. DLP 검출 원문 금지, 식별자만 기록. 정책 actor=task.OwnerID; SCMTokenFor 자격증명만 agent.OwnerID.
- 자주 깨지는 곳: 전역 설정 백업/복원·API 응답 래퍼·촬영 스크립트 배선·runtime 이미지 버전 누락.
- 자주 깨지는 곳: 추적 상한 작업은 완료: 허용 출처 300룬/64개/4096룬, 스니펫 8192바이트·출처32개/1024룬, 제공자 출처300룬·전체URL1024룬·ID200룬.
- 자주 깨지는 곳: 10/07 UI 안내도 완료. trackingLimits.ts는 서버 splitHosts의 다섯 구분자와 Go TrimSpace 문자 집합을 맞춘다(3097118). JS 일반 whitespace/trim으로 바꾸면 어긋난다.
- 자주 깨지는 곳: 입력 maxLength는 UTF-16 단위여서 4바이트 문자를 서버 룬 계산보다 엄격하게 제한한다. 스니펫 출처 파서를 프런트에 복제하지 않는다.
- 자주 깨지는 곳: pagePolicy의 출처 3회 증폭, 16KiB는 전체 헤더 보장 아님(이전 확인). 기존 저장값을 읽는 캐시는 Validate를 재적용하지 않는다(이전 확인).
- 검증 함정: CI test:sso는 silent-sso.test.mjs 하나만 실행, 나머지 네 Node 회귀 파일은 명시 실행 필요. 과거 144건에서 현재 147건으로 늘었다.
- 검증 함정: guide-settings-check.test.mjs는 실제 source를 requestTimeoutMs부터 if(problems.length) 전까지 잘라 실행한다. 기존 captureTracking은 대역이어서 CSP fetch는 검증하지 않는다.
- 검증 함정: Node AbortSignal.timeout 자체는 이벤트 루프를 붙잡지 않는다. 지연 회귀는 별도 interval 또는 열린 서버와 finally 정리가 필요하다.
- 검증 함정: 관리자 HTTP/DB 저장 증명에는 관리자 세션+CSRF+live DB 필요. validateSetting 같은 직접 함수 호출만으로 저장 성공/거절을 증명하지 말 것.
- 검증 함정: buildinfo 과거 커밋 재생 테스트는 순차. 이전 측정에서 느린 원인은 Windows 9p gitdir였고 jq 캐시는 기각됨. 최적화 가설을 성능 측정 없이 재제안하지 말 것.
- 미확인: 이번 실제 배포·외부 서비스·PDF 재생성 절차·전체 Go 품질 상태. 코드와 커밋은 변경하지 않았다.
