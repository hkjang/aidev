# ReSSO 프로필 (2026-09-28)
- 목적: 오프라인 단일 바이너리 OIDC SSO 제공자 + 사용자·Realm 관리 콘솔. RP 구현은 포함하지 않는다(언제나 제공자 쪽).
- 스택: Go 1.26, chi v5, PostgreSQL/pgx v5, LDAP, React 19/TypeScript/MUI/React Query/Vite 7, vitest 4; CI Node 22.23.0.
- 구조:
  - cmd/resso: 서버·CLI·예약 LDAP 동기화·유지보수·메일 알림.
  - internal/httpserver: oidc.go(OIDC 전 Endpoint, 약 1500행)·auth.go(로그인·세션)·middleware.go·metrics.go·server.go(`New(data, logger, trustedProxyCIDRs, metrics)`)·admin/personal/mcp/tracking. integration_test.go는 실제 PostgreSQL + httptest를 쓰는 단일 11000행 이상 파일.
  - internal/store + store/migrations: DB 접근과 자동 SQL 마이그레이션(최신 017_mail_deliveries.sql). oidc.go에 refresh token 계열(InspectRefreshToken:348·RotateRefreshToken·RollbackRefreshRotation·RevokeRefreshToken).
  - internal/oidc, cryptoutil, password, ratelimit / federation, backchannel, mail / tracking, observability(`NewRegistry`·`WritePrometheus`).
  - web/src(React), webui/dist(Go embed 산출물), scripts, docs(운영·사용·호환 정본).

- 이 저장소가 반복해 쓰는 설계 관용구(새 과제는 여기에 맞출 것):
  - **"이쪽 장애"와 "진짜 없음"을 같은 답으로 합치지 않는다.** 이것이 최근 다섯 회차의 주제다. 판정 헬퍼: `realmLookupFailed`(oidc.go:60, 호출자 일곱 — discovery 103·jwks 163·authorization 220·token 475·revocation 1069·logout 1225·CORS middleware.go:117), `userLookupFailed`(oidc.go:90, 호출자 둘 — 534·597, 지표까지 센다), `writeUserInfoUnavailable`(stage 여섯), `recordUnjudgedIntrospection`(introspection, 답은 200 active=false 유지).
  - **호출자 문제는 400, 이쪽 문제는 500 `server_error`**(token Endpoint; docs/ADMIN_GUIDE.md:570). revoke만 503 `temporarily_unavailable`인데 RFC 7009 §2.2.1의 근거가 있어서다. `invalid_grant`는 RP에게 "네 토큰은 죽었다"는 뜻이므로 읽지도 못한 grant에 쓰면 살릴 수 있던 세션이 버려진다.
  - **조기 거절 금지**(로그아웃): 실패해도 세션을 끝내고 트레일에 남긴다.
  - **거절의 이유를 이유 코드로**: 로그아웃의 `client_not_named`/`client_unknown`/`client_unavailable`/`uri_not_registered`/`form_unreadable`.
  - **지표 라벨 카디널리티 고정**: `methodLabel`·`routePattern`(metrics.go) 주석이 왜인지 설명한다. 미검증 입력을 라벨·로그에 그대로 넘기지 않는다. 라벨 이름의 뜻을 넘는 값을 추가하지 않는다(`resso_token_errors_total`은 `grant_type` 하나 — 그랜트를 읽기 **전**의 실패는 일부러 세지 않는다).
  - **계약이 다른 경로를 하나로 통합하지 않는다**: 같은 `InspectRefreshToken` 실패가 refresh 그랜트/introspection/revocation에서 각각 다른 답(500/200/503)을 내는 것은 의도다.
- 위험 구역: auth.go(세션·쿠키·로그인 계약), oidc.go의 토큰·로그아웃 경로, middleware.go의 CSRF/API 키 예외, internal/store/migrations, .github/workflows/release.yaml.

- 검증 함정:
  - 환경변수가 없으면 연동 테스트가 SKIP인데도 종료 코드는 0이다. `make test` 끝의 "integration test(s) did not run" 경고 유무를 눈으로 확인할 것.
  - make test는 SKIP 집계용으로 연동 명령을 한 번 더 돌린다(중복 실행, 약 2분).
  - CI verify는 세 서비스를 준비하지만 release.yaml은 PostgreSQL만 준비한다. CI lint는 npm 설치 전에 돌고, 로컬 make lint는 GO_PACKAGES로 vendored Go를 제외한다.
  - 통합 테스트의 로그 단언은 `lockedBuffer`(integration_test.go:7287, 사용처 다섯). 지표 단언은 `observability.NewRegistry()`를 `New(data, logger, nil, metrics)`에 넘기고 `metrics.WritePrometheus(&sb)`로 읽는다(선례 2199·2229) — `nil`을 넘긴 서버는 등록기를 읽을 수 없다.
  - 저장소 장애 재현은 테이블 RENAME으로 한다(선례 2898·3700·7144·8092, `users`·`realms`). `refresh_tokens`는 자기 참조 FK 하나뿐(001_initial.sql:168)이라 RENAME이 안전하다. **`t.Cleanup` 복구 필수** — 빠지면 뒤따르는 테스트가 전멸한다.
  - Docker는 이 환경에서 실행 가능(2026-09-21). 기존 컨테이너 재사용만 검증됐고 깨끗한 환경의 신규 생성·삭제는 미확인.
