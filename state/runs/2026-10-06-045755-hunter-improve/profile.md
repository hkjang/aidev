- 검증 함정:
  - 툴체인 버전 드리프트가 실제 실패 원인이 된다. `npm test` 의 pass 개수를 실측할 것 — 0건 실행을 통과로 읽지 말 것.
  - `web/node_modules` 는 새 워크트리에 **없다**. 순수 `.test.mjs` 는 node_modules 없이도 돌지만 `typecheck`/`build` 와 Mantine 동작 실측은 `npm ci` 필수.
  - `go test -run` 에 걸리는 testApp 기반 테스트는 `HUNTER_TEST_DSN` 없으면 SKIP 이다. SKIP 을 통과로 세지 말 것.
  - `validateScope` 벡터를 쓸 때 `expires_at` 은 반드시 미래로(`expires.After(time.Now())`). 과거 값은 형식과 무관한 이유로 거절되어 판정을 오염시킨다.
  - CI Verify 순서: `npm ci && npm test && npm run build` → 자산 복사 → 원본 검증 → `go vet` → `go test -race`(DSN 주입) → `go build` → 라이선스 수집 → `bash -n`/`py_compile`/`check-docs` → `docker build`.
  - **샌드박스 차이**: 정찰 세션에서 `node`·`go run`·`gh` 가 권한 거부된 적이 있고, 복합 셸 파이프라인(`sed 's/…/'`, heredoc)도 거부된다. 정찰 과제서의 런타임 주장은 구현 환경에서 먼저 재확인할 것.
