# Qurio 프로필 (2026-09-26)
- 목적: 오프라인 사내망용 AI SQL 워크벤치·데이터 카탈로그. 승인·감사·MCP/REST API 를 제공한다.
- 기준: main 계보 `1ad4e50` (chore: release Qurio v1.4.5), VERSION 파일 `1.4.5`. 이전 프로필(2026-09-22)의 기준 88a90a2 / 1.4.2 는 폐기.
- 스택: Go(go.mod 1.26.6), pgx/v5·PostgreSQL 17, pure-Go Oracle 드라이버, React 19·TypeScript·Mantine·Vite·TanStack Query, Vitest·Playwright.
- 구조:
  - `cmd/qurio` — 실행·시간별 정리 루프·설치/마이그레이션 통합 테스트(`TestIntegrationDatabaseMigrations` 가 사실상의 테스트 DB bootstrap).
  - `internal/httpapi` — 라우팅·쿠키/세션·OIDC 콜백·설정·프로필·SPA 제공.
  - `internal/oidcauth`, `internal/mcpoauth` — 웹 OIDC 및 MCP OAuth 리소스 서버(RFC 9728).
  - `internal/store` — PostgreSQL 설정·계정·키·승인·감사 영속화.
  - `internal/domain/{dbexec,legacy,sqlsafe}` — DB 연결·SQL 정책·실행·스키마 탐색.
  - `internal/{legacyapi,platformapi,runtimeapi,agentapi,intelligenceapi}` — 기능별 API. `internal/authzread` 는 민감 GET 가드.
  - `internal/{jobs,backup,integrations,authn,cryptox,config,runtimeenv,version}` — 배경 작업·백업·연동·보조.
  - `internal/webui/dist` — Go 임베드 SPA 자산(SPA 변경 시 재빌드·재복사 필요).
  - `migrations` — 새 번호만 추가, 기존 SQL 수정 금지. `web` — SPA/Vitest/Playwright. `docs` — architecture/requirements/legacy-compatibility/guides.
  - **`internal/mail` 은 존재하지 않는다**(3c5da14 는 이 계보에 없음). mail 전제 과제는 전부 무효.
- 빌드·테스트: `make build`(npm ci→SPA 빌드→임베드 복사→Go 빌드, 느림); `make lint`(a432f3f 이후 `check-go-format`(gofmt 읽기 전용) → go vet → 웹 tsc); `make test-go`; `make test-web`; `make test-e2e`(브라우저 필요·느림). 통합 테스트는 `-tags=integration` 이며 일반 `go test ./...` 에서 제외된다.
- 관례: 영어 conventional commits(UI/가이드 문자열은 한국어 포함). 런타임 환경변수는 `POSTGRES_DSN`·`BOOTSTRAP_ADMIN`·`BOOTSTRAP_ADMIN_PASSWORD`·`ENCRYPTION_KEY` 네 개, 나머지 설정은 DB(`qurio_settings`). 저장소에 AGENTS.md·CLAUDE.md·roadmap·TODO/FIXME 없음. `docs/requirements.md` 가 버전 추적표.
- 위험 구역: `internal/httpapi`(인증/세션), `internal/oidcauth`·`internal/mcpoauth`, `internal/store/api_key_rate.go`, `internal/agentapi`, `migrations`, `.github/workflows`(ci.yml·release.yml). 감사·로그에는 스크럽 이전 원문을 넣지 않는다(식별자만).
- 자주 깨지는 곳:
  - 로그인 뒤 목적지를 `LoginPage.tsx` 와 `App.tsx PublicOnly` 두 경로가 각각 계산한다 — 한쪽만 고치면 react-router 7 의 `startTransition` 커밋 순서 때문에 다른 쪽이 덮어쓴다. PR #18 이 이 영역에서 닫혔다.
  - 통합 테스트 픽스처 정리: `defer pool.Close()` 가 `t.Cleanup(DELETE…)` 보다 먼저 실행되어 정리가 조용히 죽는다. 522f0e5 가 `internal/store` 4곳만 고쳤고 **저장소 전체에 아직 52곳의 `defer pool.Close()` 가 남아 있다**(runtimeapi 11, legacyapi 11, intelligenceapi 8, agentapi 4, httpapi 4, store 4, backup 3, integrations 3, jobs 2, domain/legacy 2, platformapi 1 …).
- 검증 함정:
  - CI(`ci.yml:29-31`)·release 는 PostgreSQL 17 에 `POSTGRES_DSN`·`QURIO_INTEGRATION_DSN`·`QURIO_TEST_POSTGRES_DSN` **세 env 를 같은 폐기 DB** 로 지정하고 bootstrap 후 `go test -race -p=1 -tags=integration ./...` 를 돌린다. 그래서 한 테스트가 남긴 행이 다른 테스트에 보인다.
  - **CI 는 `make lint` 를 호출하지 않는다** — Makefile 에 검사를 더해도 CI 검사가 되지는 않는다.
  - `internal/domain/dbexec` 만 `QURIO_TEST_POSTGRES_DSN` 전용(9a9577b): 미설정이면 Skip, 연결 오류는 Fatal. 나머지 통합 테스트는 여전히 `POSTGRES_DSN`/기본 55432 를 읽고 연결 오류를 Skip 한다(세 관례가 공존).
  - dbexec 픽스처는 `public` 고정명과 pg_catalog 함수·캐스트를 CREATE/DROP 하므로 전용 폐기 DB·`-p=1` 직렬 실행이 필요하다.
  - 로컬에서 포트 55432 를 다른 세션이 점유하는 일이 실제로 있었다(2026-09-20) — 충돌하면 55433 으로.
  - release 는 Oracle 실서비스도 기동, 일반 CI 는 PostgreSQL 만. 릴리즈·빌드 경로를 건드리면 릴리즈까지 통과를 확인해야 한다.
