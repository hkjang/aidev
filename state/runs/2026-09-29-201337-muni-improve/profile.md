  - `export.go`: `renderExport`/`exportFile`/`safeFilename`(308)/`cutFilenameRunes`(335)/`extValueEscape`/`urlPathEscape`/`fullHTML`/`renderHTML`. `safeFilename` 은 문서 내려받기·발표자료·워크스페이스 ZIP 이름·ZIP 항목 이름·폴더 세그먼트 다섯 경로가 공유 — 본문을 바꾸면 파급이 넓음. `safeFilename` 은 `/ \ CR LF NUL` 만 치환하므로 `: * ? " < > |` 는 남는다(Windows 미확인 후보).
  - ★ **Content-Disposition 다섯 자리의 escape·ext-value 는 이제 통일됨**(export.go:61 / presentations.go / import_attachments.go:652 / handoff.go / workspace_export.go:129 모두 `filename*=UTF-8''extValueEscape(...)`). 남은 차이는 **ASCII fallback 문자열뿐**이고, 그중 `import_attachments.go:652` 만 `filename="attachment"` 라 확장자가 없다. 수신 쪽 파서는 `internal/handoff/handoff.go` 의 `filenameOf`(= `mime.ParseMediaType`).
  - `ai.go:238` `truncateRunes(value,max)`: 넘치면 `"\n[…문서 컨텍스트가 길어 일부 생략됨…]"` 를 덧붙인다. **DB 저장 값의 길이 상한에도 아직 쓰이고 있음** — 제목 240(`import_attachments.go:121`, `handoff.go:230`), 첨부 이름 240(`import_attachments.go:183,312,570`), 편집기에 돌려주는 제목(`:329`), 머리말/꼬리말 200(`:174,330,331`), mail_deliveries(`mail.go:91,98`). 파일 이름 쪽은 `cutFilenameRunes` 로 이미 분리됐다.
  - `import_attachments.go`: `parseUpload`/`importDocument`/`importIntoDocument`/`storeImportedDocument`/`uploadAttachment`/`downloadAttachment`. `upload.titleInBody` 가 .md/.html/.htm/.docx 신규 가져오기에서 참.
  - `import_markdown.go`: `dropLeadingTitle` 은 확정 제목과 **정확히** 같은 첫 level-1 heading 만 제거. `splitTableRow` 는 끝 파이프를 TrimSuffix 하지 않음.
