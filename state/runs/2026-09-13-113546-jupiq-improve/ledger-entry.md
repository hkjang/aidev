- 요약: `GET /api/v1/auth/oidc/login`은 누구나 부를 수 있고 부를 때마다 `oidc.NewProvider`로 제공자 Discovery 문서를 받아 오므로 익명 요청 하나가 Keycloak으로 가는 요청 하나로 증폭됐고, 로컬 로그인만 `loginLimiter`로 막고 있었다. 보류 메모대로 `loginLimiter` 재사용을 먼저 검토했으나 실패만 세는 3키 구조라 맞지 않아, 키별 고정 창에서 요청 수를 세는 `requestLimiter`(`internal/api/request_limiter.go`)를 따로 두고 IP별 분당 120회(releasedock과 같은 값, silent SSO가 탭 세션마다 한 번씩 정상 호출하는 점을 감안)로 제한했다 — 막힌 요청은 창을 늘리지 않고 지도는 `loginLimiter`와 같은 규칙으로 1만 항목에서 잘라 낸다. 이 경로는 fetch가 아니라 브라우저 이동으로만 닿으므로 JSON 429는 날것으로 보이기 때문에, 제공자를 부르지 않고 `/login?sso=limited`(return_to 동반, `auth.LoginPathRateLimited`)로 302하고 state 쿠키를 굽지 않으며, 로그인 화면이 "SSO 로그인 요청이 너무 많습니다" 안내와 비상 관리자 계정을 보여 주고 `silentSso.ts`가 이 표시도 none·error와 같이 재시도 억제로 취급한다. 테스트는 Go 4개(`requestLimiter` 창 계산·막힌 요청이 창을 늘리지 않음·다른 주소 독립·상한 도달 시 만료/최고령 축출, 저장소 없는 Server에서 상한 초과 요청이 설정 조회 전에 302되고 쿠키가 없음, `LoginPathRateLimited` 3경우)와 프런트 3개(`sso=limited` 억제, 로그인 화면 안내 표시/`sso=none`은 무안내 — Alert 목이 message를 버려 목을 고쳤다)를 더했고, OpenAPI 설명·관리자 가이드 4.4/6.4/7.3절(리버스 프록시 뒤에서는 프록시 주소로 합산되는 한계 명시)을 갱신하고 공용 md2pdf로 PDF를 다시 구웠다(21쪽 유지, 표지 부제 동일). 겸사겸사 다섯 회차째 보류돼 있던 "로그인 리미터 `succeeded`가 ip 키를 의도적으로 유지" 항목을 별도 커밋으로 주석 한 줄과 테스트 하나로 마무리했다. `gofmt -l`, `go vet ./...`, `go test -race ./...`, `scripts/check-version.sh`, `scripts/check-screenshots.mjs`, `npm run lint`, `npm run build`, `npm test`(20파일 81개) 모두 통과했고 `web/dist`는 커밋 전에 제거했다. 실제 Keycloak 연동 확인은 이번에도 환경상 하지 못했으나 이 변경은 제공자 호출 이전 단계에서만 동작한다.
