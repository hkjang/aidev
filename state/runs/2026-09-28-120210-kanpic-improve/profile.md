- 자주 깨지는 곳: 같은 자료를 읽는 문(업로드·IMPORTDATA·클립보드·타이핑)을 한쪽만 바꾸는 것. 계산용 파서(formula.DecimalNumber)·파일 파서(delimited.Number)·표시 숫자 파서를 무조건 통합하지 않는다. b52a394 는 CellTypeUnset 에 15자리 제한을 넣은 변경을 되돌렸다. **메일에서도 같은 모양이 나왔다 — 봉투(`Rcpt`)와 헤더(`compose`)가 같은 주소를 다르게 읽는다(2026-09-28 정찰이 와이어로 재현, 미수정).**
- 숫자 계약 요약: delimited.Number = DecimalNumber + 앞자리 0 가드 + 16자리 초과 가드. XLSX CellTypeNumber 는 이미 실수라 가드 금지. parseScalar 는 trim 없음(" 12" 는 글자), IMPORTDATA 는 TrimSpace 후 수 — 남은 어긋남. 웹 decomposeNumberText 에도 같은 꼴의 앞자리 0 가드가 있고(v0.253.0) cellEntry.ts 가 타이핑 문을 spreadsheetNumber 에 맡긴다(v0.254.0).
- 인코딩: ToUTF8 는 BOM UTF-8/UTF-16LE/BE 만 변환, 나머지는 그대로. 홀수 끝 바이트 버림, 고립 surrogate U+FFFD. parseCSV 는 변환 직후 UTF-8 유효성을 보고 #VALUE! 로 거절(0a21ce7). UTF-32 지원·휴리스틱 추측 금지.
- 메일 계약: 줄 앞 점 이스케이프는 `client.Data()` 의 net/textproto dot writer 몫이고 `normalizeBody` 는 CRLF 정규화·끝 `\r\n` 보장만 한다(c0ab986). `Notify` 는 `context.WithTimeout(context.WithoutCancel(ctx), 10s)` 로 요청 취소를 떼어 내고(4e4d1d5), 실제 전송은 `deliver` 가 제 Background 컨텍스트로 두 번 시도한다. `SendNow` 는 이벤트 게이트를 일부러 무시한다(관리자 테스트 버튼).
