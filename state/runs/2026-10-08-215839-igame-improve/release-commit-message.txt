feat: release igame v0.7.32

Ships as a patch release the public catalog paging fix landed since v0.7.31.
listGames now orders by name and then unique id. PostgreSQL/Router tests
pin the explicit order of tied names, name priority, active/q/category/favorite
filters, page envelopes and paging after an already viewed game's description
is updated. Implementation evidence records Red-to-Green and failure of both
tests when only the id tiebreak is removed. This is not a snapshot guarantee
across inserts, deletes or sorting/filter changes. Play history and score
moderation lists remain outside the change. No schema migration is introduced.

Moves VERSION, the Compose image tag and the web and SDK package versions
together as the release contract requires, updates the Korean README release
note and versioned documentation, and rebuilds the two enterprise manuals for
v0.7.32. Photographed guide provenance and separately published guide PDFs are
retained. RealmGuard content 0.3.1 and Defense Series content 0.4.0 are unchanged.

Validated with make check-contract, make lint, make test, make test-race,
make build including the offline bundle check, PostgreSQL 17 make test-db
(api 34.450s / database 1.982s), both npm dependency audits, govulncheck v1.6.0,
make docs-pdf and git diff --check. The two catalog PostgreSQL tests also pass
five times each under the race detector (6.578s), with no skips. No test schemas
remain and pgcrypto was preserved before removing this session's disposable
DB container. Node audits report zero vulnerabilities; the Go scan reports no
reachable vulnerabilities and three uncalled module advisories.

The tag-triggered workflow will build and verify the offline image and SBOM,
run the live-service and browser gates, and publish the single archive.
Those deployed-service checks have not run locally. No remote publication is
performed by this release preparation.
