## KCB Cutover Dashboard v1.18.0

이번 판은 **활동 가져오기 검증의 상한 경계 7건을 회귀 테스트로 고정**합니다. 공유 검증기 `validateActivityImport`가 이미 적용하던 ID·상황판 제목·활동 개수 제한과 제목의 앞뒤 공백 제거 규칙을 테스트로 명시했습니다. 유지보수 중 제한값이나 반환값, 오류 경로가 달라지는 경우를 잡기 위한 변경입니다.

**사용자 기능이나 업로드 허용 범위는 바뀌지 않습니다.** v1.17.0 대비 변경은 `lib/activityData.test.ts` 한 파일의 테스트 7건 추가이며, UI·API·저장 형식·의존성 변경은 없습니다. 기존 동작을 확인하는 테스트 보강이므로 기능 결함 수정이나 실패 테스트의 성공 전환을 의미하지 않습니다.

### 테스트 보강
- **활동 ID 120자 허용 / 121자 거절**: 허용한 ID가 반환값에 보존되고, 초과 시 `activities[0].id` 경로 오류 한 건으로 거절되는지 확인합니다.
- **상황판 제목 100자 허용 / 101자 거절**: 허용한 제목이 반환값에 보존되고, 초과 시 `dashboardTitle` 경로 오류 한 건으로 거절되는지 확인합니다.
- **제목 앞뒤 공백 제거 후 100자 허용**: 원본 문자열에 공백이 붙어 있어도 공백을 제거한 제목으로 검증하고 반환하는 기존 규칙을 확인합니다.
- **고유 ID를 가진 루트 활동 5,000개 허용 / 5,001개 거절**: 허용한 목록의 개수와 첫·마지막 ID를 보존하고, 초과 시 `activities` 경로 오류 한 건으로 거절되는지 확인합니다.

거절 사례는 실제 검증기가 던진 `ActivityImportValidationError`와 정확한 단일 오류 경로를 검증합니다. 기존의 120자 부모 아래 하위 추가 회귀 테스트와 자기참조 오류 두 건 계약도 유지됩니다.

### 검증
- `npm ci --no-audit --no-fund` — 잠금 파일 기준 설치 성공.
- `npm run lint` 및 `tsc --noEmit --incremental false` — 통과.
- `npm run test:unit` — **108개 통과**, 실패·건너뜀 0개(이전 101개 + 신규 7개).
- `npm run build` — Next.js 16.3.3 프로덕션 빌드 통과.
- `npm run test:e2e` — **41개 통과**. 첫 실행에서는 세션의 격리된 홈 디렉터리에 Chromium이 없어 브라우저 실행에 실패했으며, 설치된 동일 버전 브라우저 경로를 `PLAYWRIGHT_BROWSERS_PATH`로 지정한 전체 재실행이 통과했습니다. 소스와 테스트 설정은 변경하지 않았습니다.
- `docker build -t cutover:v1.18.0 .` — 기존 Dockerfile로 빌드 성공. 이 이미지의 `/`, `/pc`, `/admin`, `/api/activities` 응답이 모두 `200`이며 API의 활동 배열도 확인했습니다.
- `docker save cutover:v1.18.0 | gzip` — 아래 배포 자산 생성. gzip 무결성과 아카이브의 이미지 태그·레이어를 확인했습니다.
- `git diff --check` — 통과. 기존 `MODULE_TYPELESS_PACKAGE_JSON` 및 색상 환경변수 경고는 유지됩니다. 의존성 audit와 운영 환경 배포 검증은 수행하지 않았습니다.

### 배포
폐쇄망 배포 자산은 기존과 같은 Docker 이미지 압축 파일입니다.

```bash
docker load < cutover-v1.18.0.tar.gz
```

기존 운영 환경변수·포트·`cutover-data` 볼륨 설정을 유지하고 이미지 태그를 `cutover:v1.18.0`으로 바꾸어 실행합니다. 데이터 마이그레이션은 없습니다. 되돌려야 하면 같은 설정과 볼륨으로 `cutover:v1.17.0` 이미지를 다시 실행할 수 있습니다.

이 릴리즈는 테스트 보강이 필요한 개발·유지보수 담당자를 위한 변경이며, 운영 사용자에게 새 조작이나 설정을 요구하지 않습니다. 로컬 검증과 자산 준비를 완료했으며 원격 게시·운영 반영은 후속 배포 절차에서 수행합니다.
