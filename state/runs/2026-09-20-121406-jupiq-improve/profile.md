# jupiq 프로필 (2026-09-20)
- 목적: JupyterHub·Kubernetes 자원을 한 화면에서 보고 서버 시작·정지·승인 흐름을 관리하는 관리 콘솔(오프라인망 반입용 단일 Docker 이미지로 배포).
- 스택: Go 1.26(net/http 표준 mux, go-oidc), PostgreSQL 14+(마이그레이션은 `migrations/` SQL, 기동 시 자동 적용), React+TypeScript+Vite(`web/`, vitest), OpenAPI(`openapi/openapi.yaml`).
- 구조:
  - `cmd/jupiq` 진입점 / `internal/api` HTTP 핸들러·라우트(server.go)·설정 검증·helpers.go(apiError/queryInt/listSort)·login_limiter·request_limiter / `internal/auth` 세션·OIDC(auth.go, oidc.go — silent SSO 포함)
  - `internal/store` PostgreSQL 조회(pageBounds가 page/page_size 보정; 통합 테스트는 `JUPIQ_INTEGRATION_TEST_DSN` 있을 때만) / `internal/collector` 주기 수집 / `internal/integration` JupyterHub·K8s 클라이언트(SafeHTTPClient·ValidateEndpoint: loopback·metadata 차단)
  - `internal/analytics` 방문 추적 스니펫·CSP nonce / `internal/secure` 암호화 / `internal/config` 환경변수 / `internal/version`
  - `web/src` SPA(auth/silentSso.ts, 관리자 설정 탭) / `docs/` USER_GUIDE.md·ADMIN_GUIDE.md(정본)+PDF(공용 md2pdf) / `scripts/` check-version.sh, check-screenshots.mjs, capture-screenshots.mjs, build-image.sh, package-offline.sh, verify-offline.sh, offline-smoke-test.sh, npm-audit-retry.sh
  - **main@52fb7f9(v1.7.1)에 없는 것**: `internal/mail`·마이그레이션 014(브랜치 auto/2026-09-16-0552 미머지), `internal/auth/mcp_oauth.go`·`authtest`(auto/2026-09-17-2243 미머지), `internal/auth/oidc_provider.go` Discovery 캐시(auto/2026-09-17-0513 미머지). 회차 기록의 09-16·09-17 요약은 이 브랜치들 얘기이며 main 기준으로 과제를 고를 때 그 코드를 전제하지 말 것.
- 빌드·테스트: `make lint`(check-version + check-screenshots + go vet + npm lint), `make test`(go test ./... + npm test), `make build`, `make package`/`verify`. `make test-integration`(DSN 없으면 exit 1 + 안내), `make release-check`(release.yml 71~86행과 같은 순서: mod verify→vet→govulncheck→test→통합→screenshots→npm ci/audit/lint/test/build, 수 분). `go test ./internal/api/`는 DSN 없이 0.03초.
- 관례: 커밋 메시지 한국어 `type: 설명`(feat/fix/test/ci/docs/build). 설정은 `settings` 테이블의 JSON 문서(auth.oidc, analytics 등), 비밀값은 `secrets`(`allowedSettingsSecretKeys`). 새 기능 기본값은 꺼짐. 오류 응답은 `apiError(w,r,status,code,msg)` → `{"error":{"code","message","request_id"}}`, 메시지는 한국어. 릴리즈는 VERSION + `v*.*.*` 태그(check-version.sh 가 여러 파일 버전 일치 검사). 가이드 캡처는 manifest 로 관리(check-screenshots.mjs).
- 위험 구역: `internal/auth/*`(세션·OIDC — fail-closed, 계정 자동 생성 금지), `migrations/`, `.github/workflows/*`, 설정 검증(잘못 넓히면 SSRF 방어 무력화), `internal/integration` SafeHTTPClient/ValidateEndpoint. 미머지 브랜치 셋이 `core_handlers.go`·`server.go`·`settings` 검증을 넓게 건드리므로 그 파일의 대규모 재배치는 머지 충돌을 만든다.
- 자주 깨지는 곳: Go mux 등록 충돌(메서드 없는 패턴과 `GET /` 충돌로 기동 panic 전례), docs PDF 가 .md 와 어긋난 채 남는 것, VERSION 올릴 때 check-version.sh 가 여러 파일을 함께 요구. OpenAPI 계약 테스트(`openapi_contract_test.go`)가 등록 경로↔문서 일치를 검사하므로 라우트를 더하면 문서도 같이.
- 검증 함정: 통합 테스트는 DSN 없으면 조용히 skip(`go test`만 보면 통과처럼 보임) — `make test-integration`은 실패로 알려 줌. 실제 Keycloak·SMTP 는 환경에 없음. 러너 환경에서 `awk`·`sort -t`·`uniq -f` 같은 파이프 명령은 승인 필요 → `go test`/`grep`/`sed`만으로 한 번에 검증하고 명령 수를 줄일 것(`hold: budget`으로 끊기기 쉬움).
