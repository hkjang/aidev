관리자 변경 이력 화면의 실행 감사 탭에서, 늦게 도착한 응답이 다른 탭·다른 페이지 화면을 덮어쓰던 문제와 기록이 줄어든 뒤 빈 페이지에 갇히던 문제를 고쳤습니다.

**먼저 누른 것이 나중에 이겼고, 빈 페이지에는 나갈 단추가 없었습니다.**

관리자 변경 이력 화면은 탭 네 개(실행 감사·저장 결과·스키마·데이터)와 검색, 페이지 이동을 한 화면에서 씁니다. 그런데 요청마다 순번이 없었습니다. 실행 감사 100건을 불러오는 중에 데이터 탭으로 옮기면, 늦게 도착한 실행 감사 응답이 이미 그려진 데이터 탭 화면을 실행 감사 표로 덮어썼습니다. 실패 응답도 같은 방식으로 새 탭의 안내 문구 자리에 자기 오류 문구를 썼습니다. 페이지 이동 단추를 연달아 누르면 늦게 온 이전 페이지가 새 페이지를 덮어썼고, 화면에 보이는 카운트는 다른 페이지 것이었습니다.

두 번째 결함은 같은 함수 안에 있었습니다. `loadExecutions` 는 받은 목록이 비면 이동 바를 붙이기 전에 빠져나갔습니다. 보존 정책이 돌거나 기록이 지워져 총건수가 줄어든 뒤 3페이지에 머물러 있으면, 화면에는 `301-300 / 총 20건` 처럼 범위가 뒤집힌 카운트와 "이 페이지에 기록이 없습니다."만 남고 `← 이전` 단추가 아예 없었습니다. 남은 20건을 보려면 탭을 바꿔 돌아오는 수밖에 없었습니다.

이제 `load()` 가 요청마다 순번을 매기고, 각 로더는 응답을 그리기 전에 자기가 아직 최신 요청인지 확인합니다. 페이지 이동 단추도 `loadExecutions()` 를 직접 부르지 않고 `load()` 를 거치므로 클릭끼리도 보호됩니다. 빈 페이지에 닿으면 서버가 준 `total` 로 마지막 페이지를 계산해 곧바로 그 쪽으로 한 번만 다시 부릅니다 — 한 페이지씩 물러나는 방식은 여러 페이지가 한꺼번에 사라진 경우 물러난 페이지도 비어 그대로 갇힙니다. 물러날 곳이 없을 때만 기존 안내 문구를 보이고, 목록이 비면 카운트의 시작값을 `0` 으로 떨어뜨려 범위가 뒤집히지 않습니다.

| 상황 | 이후 동작 |
| --- | --- |
| 실행 감사 응답이 오는 중에 다른 탭으로 이동 | 늦게 온 응답은 버려지고 새 탭 화면이 유지됨 |
| 실행 감사 요청이 실패한 뒤 다른 탭으로 이동 | 오류 문구가 새 탭을 덮지 않음 |
| 이동 단추를 연달아 눌러 이전 페이지 응답이 늦게 옴 | 마지막으로 누른 페이지가 그려진 채 유지됨 |
| 총 20건만 남은 뒤 3페이지에서 '다음 →' | `1-20 / 총 20건`, 20행, `페이지 1 / 1`, 이동 바 유지 |
| 기록이 아예 없는 1페이지 | 기존 안내 문구 그대로 |
| 저장 결과 삭제 후 목록 갱신 | `load()` 를 거쳐 순번이 올라감 |
| 서버 API·응답 형식 | 변화 없음 (`ListExecutionAudit` 가 이미 limit·offset 을 클램프하고 total/offset 을 돌려줍니다) |

**검증.** 새 `test/js/admin-history.test.mjs` 11개(그중 6개는 구현 전 실패를 먼저 확인했습니다 — `늦게 온 이전 페이지가 최신 페이지를 덮어썼습니다`, `빈 페이지에서 한 페이지 물러나 다시 부르지 않았습니다`, `1-0 / 총 50건` 같은 역전 카운트)를 포함해 `go test -race ./...` 38개 패키지, `go vet ./...`, `gofmt -l .` 무출력, `go build ./cmd/dartfly` 가 모두 통과했습니다. `go test -run TestBrowserModuleTests ./internal/webui` 에서 `admin-history.test.mjs` 가 Skip 없이 PASS 하는 것도 출력으로 확인했습니다. 여기에 실제 바이너리와 실제 MariaDB·Chromium 으로 감사 기록 350건을 심어 3페이지까지 이동한 뒤 보존 정리로 20건만 남기고 '다음 →' 을 눌러, 고치기 전의 `301-300 / 총 20건` + `← 이전` 단추 0개(갇힘)와 데이터 탭이 실행 감사 표로 덮이는 것을 재현하고, 고친 뒤 `1-20 / 총 20건`·20행·`페이지 1 / 1`·이동 바 유지와 데이터 탭 유지를 확인했습니다. `DF_SMOKE_REQUIRE_BROWSER=1 bash test/smoke/run.sh` 31페이지도 통과했습니다. 릴리스 이미지는 `deploy/build-release.sh` 가 `test/smoke/artifact.sh` 로 기동 점검(healthz/readyz, 임베드 정적 자산, 로그인, 내장 마스터 키 질의, TZ)까지 마친 것입니다.

프로덕션 변경은 `internal/webui/js/admin-history.js` 한 파일이고 서버는 그대로입니다.
