# 수리 요약 (시도 2)

- 지적 1 은 맞다. 재현했다: 비평가의 입력에서 사용자가 쓴 문단 네 개가 사라지고 본문이 "- 끝입니다." 한 줄만 남았다.
- 다만 비평가가 제안한 한 줄(백틱 info string 에 백틱이 있으면 거절)로는 비평가 자신의 재현 입력이 안 고쳐진다 — "``` 로 감싸면 …" 의 fence 뒤에는 백틱이 없고 CommonMark 로도 유효한 펜스다. 그래서 더 좁혔다: fenceOf 는 info string 에 공백이나 백틱이 있으면 "" 를 돌려준다(펜스를 여는 줄의 info string 은 언어 이름 한 낱말). 펜스를 놓치면 그 줄이 불릿으로 남을 뿐(이 변경 전 동작)이고, 없는 펜스를 열면 페이지 뒷부분이 사라지므로 분류기를 좁히는 방향만 택했다. 물결 펜스도 같은 이유로 같이 좁혔다(같은 증상을 낸다).
- 지적 2 도 반영: 경고가 "코드 블록 %d개(%d줄)는 가져오지 않았습니다" 로 못 가져온 줄 수를 말한다(펜스 두 줄은 문장부호로 보고 사이의 줄만 센다).
- 검증: `make test` exit=0 (go test -race ./... 25 패키지 ok·FAIL 없음, go vet, 웹 typecheck·build). 기존 펜스 테스트 5개 그대로 통과. 회귀 테스트 2개 추가(문장형 세 가지 + 줄 수 단언). 커밋은 이 브랜치 위 새 커밋 feadb11 하나, push 안 했다.
