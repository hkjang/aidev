  - internal/config·secure·id — 설정·암호화·UUID.

  - make build — npm 래퍼+웹 빌드+자산 복사+Go 빌드; make docker — 전체 이미지 빌드(오래 걸림).
  - CI는 go test -race, npm ci, vitest, vite build, docker build. release.yml은 v*.*.* 태그에서 Docker 이미지·오프라인 tar·GitHub Release 생성.

- 자주 깨지는 곳:
  - 9/24 orbitAt 포함 규칙·memory_count 시험은 verify 실패 후 main에 없음. timetravel_db_test.go에는 Range/Links/EarliestAt 3개 테스트만 있다. 기록의 성공 문구만 믿지 말 것.
  - 9/21 OrbitPage 조기 반환·orbitRange first_met은 no-change 반복, 원인 미기록. 같은 접근 재선택 금지.
  - getOrbit/별도 orbitAt/recalculateRelationship이 지표를 각각 읽는다. queryMemoriesLimit은 REST·MCP·AI 공유.
  - AI relationshipContext의 첫 사람 조회와 기억의 dataKeyVersion 모두 ErrNoRows 가능. 이를 한꺼번에 사람 없음으로 매핑하면 내부 키 오류가 숨는다.
  - openapi.go는 /orbit만 리터럴이고 나머지는 operation(). 의도된 구조로 확장 리팩터 금지.
- 검증 함정:
  - CI에는 postgres가 없어 DB 시험 SKIP. DB 변경은 DSN으로 실제 PASS 확인 필수.
  - openTestStore는 store.Open(ctx,dsn,nil), Bootstrap 미사용. seedUser/seedPerson/seedRelationship 재사용 가능; 사용자 삭제 FK cascade 정리.
  - AI 시험의 settings 행은 전역이므로 기존 행 백업·복원, 병렬 금지. encrypted_value=''이고 기억 0건이면 nil Vault로 정상 맥락 조회 가능.
  - 사람 시드에 relationships 행이 없으면 orbitAt/relationshipContext의 JOIN에서 누락됨.
  - people.first_met만 date, 다른 시각은 timestamptz. time.Time 비교는 Equal 사용.
  - nil-store 시험은 입력 가드 검증용. AI는 readSetting이 먼저 실행되므로 존재 여부 오류 재현에는 실제 DB가 필요함.
  - 웹 streamAI는 비-2xx JSON을 APIError로 표시하므로 서버의 SSE 시작 전 404를 처리할 수 있음(코드 확인, 브라우저 실행 미확인).
  - Vitest는 jsdom과 src/test/setup.ts 사용. 과거 기록상 MUI Slider pointer/hasPointerCapture, OrbitCanvas ResizeObserver 스텁 필요.
  - npm run lint는 eslint devDependency가 없음. CI도 lint 미실행. Docker/Make는 설치 래퍼를 쓰고 CI는 직접 npm ci.
  - docs/cru-manual.md 일부 API 설명 차이는 이전 프로필 기록(이번 재검증 안 함); 실제 server.go 라우팅이 정본.
