Kkiit v0.4.11 — 관리자 사용자 수정 저장 실패 안내 수정

v0.4.10 이후 들어온 수정 하나를 담는다.

- `updateAdminUser`(`admin_users.go`)가 `UPDATE users SET
  status, display_name` 의 모든 오류를 `err != nil ||
  tag.RowsAffected() == 0` 한 덩어리로 묶어 404 `user_not_found` 로
  돌려주던 것을 고친다. 같은 파일 `resetAdminUserMFA` 는 이미 500 과
  404 를 갈라 놓고 있어 파일 안에서 비대칭이었고, 조사 화면에서 그
  계정을 보고 있는 관리자가 상태·표시 이름을 바꾸려는 순간 "사용자를
  찾을 수 없습니다." 라는 안내를 받아 계정이 사라진 줄 알게 됐다.
  저장 실패를 500 `user_save_failed` "사용자 정보를 저장하지
  못했습니다." 로 가르고 `RowsAffected()==0` 만 404 로 남긴다. 성공
  경로의 세션 폐기·`AccountReactivated` 통지·`s.audit` 는 건드리지
  않았다. 버릴 PostgreSQL 16 에 붙는 통합 테스트로 404 를 먼저
  재현한 뒤 고쳐 통과시켰고, 임시 프로브로 실패 경로의 오류가
  `*pgconn.PgError{Code:"22021"}`(`display_name` 의 NUL 거절)이며 그
  행이 실제로 존재하는데도(`row_exists=true`) 문장이 아예 실행되지
  않아 `rows=-1` 인 것을 확인한 뒤 프로브를 제거했다. 분기를 두
  방향으로 변이시켜(항상 500 / 항상 404) 각각 다시 실패하는 것도
  확인했다. 프런트는 이미 `error.message` 를 그대로 띄우므로 `web/`
  과 `internal/ui/dist` 는 건드리지 않았고, `openapi.yaml` 의
  PATCH /admin/users/{id} 응답에 400·404·500 을 더해 실제 동작과
  맞췄다.

버전 표기(VERSION·compose·web/package·openapi·README)를 0.4.11 으로 올린다.

gofmt · go build · go vet · go test, web lint · test · build 전부 통과.
버릴 PostgreSQL 16 으로 `make test-integration` 도 통과(85.6초).
웹 테스트 10건은 node 22 에서 통과한다 — 이 기계의 npm 이 PATH 에
끼워 넣는 node 20.19.2 shim 은 `--test` 의 글롭도 TypeScript 타입
스트리핑도 지원하지 않아 0건으로 멈춘다. 저장소 스크립트는 그대로 두었다.
