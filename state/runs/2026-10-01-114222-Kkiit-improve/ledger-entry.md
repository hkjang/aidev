- 선택: 관리자 사용자 수정(PATCH /admin/users/{id})의 DB 저장 실패를 404 "사용자를 찾을 수 없습니다." 가 아니라 500 으로 알리기 (가치 3 / 위험 2 / 작업량 S)
- 결과: 성공
- 요약: `updateAdminUser`(admin_users.go:71-75)가 `UPDATE users SET status,display_name` 의 모든 오류를 `err != nil || tag.RowsAffected() == 0` 로 묶어 404 `user_not_found` 로 돌려주어, 조사 화면에서 그 계정을 보고 있는 관리자가 상태·표시 이름을 바꾸려는 순간 계정이 사라진 줄 알게 됐다 — 같은 파일 `resetAdminUserMFA`(:157-166)가 이미 500/404 를 갈라 놓았으므로 파일 안에서 비대칭이었다. 저장 실패를 500 `user_save_failed` "사용자 정보를 저장하지 못했습니다." 로 가르고 `RowsAffected()==0` 만 404 로 남겼으며, 성공 경로의 세션 폐기·`AccountReactivated` 통지·`s.audit` 는 손대지 않았다. 검증: 실제 라우터 + 버릴 PostgreSQL 16(docker 29.7.2)으로 HTTP→DB 왕복 통합 테스트를 먼저 실패시킨 뒤 수정해 통과시켰고, 임시 프로브로 실패 경로의 오류가 `*pgconn.PgError{Code:"22021", Message:"invalid byte sequence for encoding \"UTF8\": 0x00", Where:"unnamed portal parameter $3"}` 이면서 `row_exists=true`·`rows=-1`(문장이 아예 실행되지 않음)인 것을 눈으로 확인한 뒤 프로브를 제거했다. 분기를 두 방향으로 변이시켜(항상 500 → `status=500 want=404`, 항상 404 = 원본 → `status=404 want=500`) 각각 다시 실패하는 것을 확인했다. 깨끗한 DB(DROP/CREATE)로 `go test ./cmd/... ./internal/...` 전체 통과(httpapi 87.1초, 통합 실제 실행), 새 테스트 단독 `-v` 로 `--- PASS`(SKIP 아님), `go vet ./cmd/... ./internal/...` 무결, `gofmt -l cmd internal` 무출력, 웹 테스트 10건 통과. 프로덕션 파일 1개(admin_users.go) + 테스트 1개 + 문서 1개(openapi.yaml 의 patch 응답에 `'400'`·`'404'`·`'500'` 추가).
