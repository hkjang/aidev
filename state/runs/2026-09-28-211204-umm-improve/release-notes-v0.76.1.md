# v0.76.1 — 다른 공간은 언제나 지금으로 열립니다

v0.70.0 이 공간을 **지나간 시점으로 되감아 보는** 길을 냈습니다. 되감기는 한 공간의 한 순간에 속합니다.
그런데 되감은 채로 공간 메뉴에서 다른 공간을 열면, 그 순간이 따라갔습니다. 새 공간은 **오늘의 생각**을
보여 주면서 **어제 날짜의 배너**를 달고, 바꿀 수 없고, 다른 사람의 변경도 받지 못했습니다.

```
    "우리 팀" 을 하루 전으로 되감은 채 → 공간 메뉴 → "회고" 로 이동

            전                                        후
    ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━    ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    화면의 생각   회고의 지금 것            화면의 생각   회고의 지금 것
    배너          "9월 27일의 공간입니다"   배너          없음
    편집          막힘 (읽기 전용)          편집          됨
    협업자의 변경 안 들어옴                 협업자의 변경 들어옴
```

배너만 틀린 것이 아니라, **사실이 아닌 한 줄 아래에 오늘 데이터가 놓여 있었습니다.**

## 공간 메뉴는 새로고침이 아닙니다

주소창에 공간 주소를 직접 쳐 넣거나 새로고침으로 옮기면 이 일은 일어나지 않았습니다. 브라우저가 화면을
통째로 다시 그리면서 되감기 상태도 함께 버려지기 때문입니다.

공간 메뉴는 그렇지 않습니다. 클라이언트 라우팅이라 React 상태가 그대로 살아 있고, 캔버스가 공간이 바뀐 것을
알아차리는 곳은 `params.spaceId` 를 보는 effect 하나뿐입니다. 그 effect 는 **자리**(어디로 확대해 두었는지)는
비웠지만 **시점**은 그대로 들고 있었습니다.

되감기 값 하나가 세 가지를 한꺼번에 쥐고 있습니다.

- **배너** — 지금 보고 있는 시각을 말합니다. 새 공간에서는 옛 공간의 시계를 읽었습니다
- **읽기 전용** — `rewind !== undefined` 가 모든 쓰기 경로가 읽는 단 하나의 스위치입니다. 지나간 화면을 고칠 수
  없게 하는 장치가, 지나가지 않은 공간을 잠갔습니다
- **이벤트 스트림** — 되감은 화면은 실시간 변경을 받으면 안 되므로 막혀 있습니다. 새 공간에서도 막힌 채라
  협업자가 무엇을 써도 도착하지 않았습니다

## 고침은 그 effect 안의 한 줄입니다

공간이 바뀌었다고 판정한 **그 자리에서만** 시점을 지금으로 되돌립니다.

```tsx
if (params.spaceId && params.spaceId !== activeSpace) {
  setActiveSpace(params.spaceId);
  setViewportKnown(false);
  setRewind(undefined);
}
```

가드 **안**이라는 점이 전부입니다. 밖으로 나가면 같은 공간에서 되감기를 켜는 순간 곧바로 꺼져 기능 자체가
죽습니다. 새 공간의 생각을 다시 불러오는 일은 추가하지 않았습니다 — 이미 있는 effect 가 시점이 바뀌면 다시
돕니다.

같은 공간에 머무는 동안의 되감기는 전과 똑같습니다. 되감고, 보고, **지금으로** 로 돌아오는 길에 달라진 것은
없습니다.

## 검증

증명은 실제 서버 바이너리 + 실제 PostgreSQL 17 + 브라우저를 지나는 end-to-end 시험입니다. 이 배선은 손으로
만든 대역으로는 구조적으로 볼 수 없습니다.

`web/e2e/space-rewind.spec.ts` 에 시험 1개를 새로 넣었습니다. 반드시 **공간 메뉴**로 옮깁니다 —
`page.goto` 는 전체 새로고침이라 상태가 버려져 결함이 재현되지 않습니다.

```
✓ 두 공간을 API 로 만들고 각각에 생각을 하나씩 — 어느 쪽도 열린 적 없음
✓ 첫 공간을 하루 전으로 되감아 배너 · 읽기 전용 문구 확인
✓ 공간 메뉴로 두 번째 공간 이동 (클라이언트 라우팅)
✓ 배너 없음 · 되감기 단추 aria-pressed="false" · 읽기 전용 문구 없음
✓ 캡처 바에 실제로 생각을 써서 서버에서 돌아오는 것까지
```

고치기 전 코드에서 같은 시험이 `Expected: 0 / Received: 1` 로 거짓 배너를 잡는 것을 확인했고, 같은 실행에서
새 공간의 **현재** 생각 단언은 통과했습니다 — 거짓 배너 아래 오늘 데이터가 있었다는 증거입니다. v0.70.0 이
넣은 기존 되감기 시험도 그대로 통과합니다.

Go 코드는 건드리지 않았습니다.
