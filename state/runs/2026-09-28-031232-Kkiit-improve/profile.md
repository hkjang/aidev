# Kkiit 프로필 (2026-09-28)
- 목적: 사람·기업·AI Agent 의 전문 서비스를 주문·납품·구매확정·정산으로 잇는 오프라인 운영 가능 마켓플레이스.
- 기준: main@22549f9, v0.4.8. (이전 프로필의 "v0.4.4" 는 낡았다.) MCP OAuth 는 이 체크아웃에 구현·설정·카드가 없다.
- 스택: Go 1.26 · net/http(`mux.HandleFunc("METHOD /path/{id}", …)`) · pgx/v5 · PostgreSQL 16+, React 19 · TypeScript 5.9 · MUI 7 · Vite 8; 웹 번들을 Go embed.
- 구조:
  - cmd/kkiit: 프로세스와 서버·워커 시작/종료 배선.
  - internal/httpapi: 총 19,016줄 60여 파일. router.go 가 라우트 정본, 핸들러는 도메인별 파일(coupons/reports/webhooks/discovery/organizations/admin_users/finance …), 통합 테스트도 같은 패키지.
  - internal/database/migrations: 번호 SQL. 001_initial.sql(users/roles), 002_marketplace_extensions.sql(portfolios 13, webhooks 328 …). 시작 시 advisory lock 안에서 자동 적용.
  - internal/worker: Outbox·메일·웹훅·위험·정산·신뢰 점수 배경 처리.
  - internal/config·cryptox·password: 환경 설정·비밀 암호화·비밀번호.
  - internal/ui/dist: 추적되는 embed 번들. 검증용으로 빌드할 수는 있으나 **산출물 커밋 금지**.
  - web/src: React 페이지; AdminPage.tsx 에 승인 등 관리자 기능.
  - docs: USER_GUIDE/ADMIN_GUIDE(md·pdf), architecture.md, mcp.md, openapi.yaml, 캡처.
- 빌드·테스트: `go test ./cmd/... ./internal/...` · `go vet ./cmd/... ./internal/...` · `gofmt -l cmd internal`(무출력) · `npm --prefix web test`(10건).
  - 통합: `make test-integration KKIIT_TEST_DSN=postgres://…` — 전용 폐기 DB 필수, timeout 300s, `internal/httpapi` 만 80~100초.
  - 전체: `make check`(gofmt·Go test/vet·npm ci·lint·test·build) — 설치 시간이 들고 추적 dist 가 바뀔 수 있다. `make build` 는 웹 빌드 후 bin/kkiit.
- 관례: 커밋은 `fix:`/`feat:`/`chore:`/`docs:` + 한국어 설명, 릴리스는 `Kkiit vX.Y.Z`. 가변 정책은 `system_settings` JSONB, 비밀은 ENCRYPTION_KEY 로 암호화. 오류 응답은 `writeError(w, status, code, 한국어 메시지)` 한 곳으로 나가고 프런트는 `error.message` 를 그대로 띄운다 — 서버만 고쳐도 안내가 바뀐다.
- 설정: 필수 POSTGRES_DSN / BOOTSTRAP_ADMIN / BOOTSTRAP_ADMIN_PASSWORD / ENCRYPTION_KEY, 선택 SHUTDOWN_DRAIN_SECONDS(기본 5, 0~120, 오류 시 5). README 와 Config 주석의 표현이 불일치(미해소).
- 위험 구역: httpapi/auth.go·middleware.go·identity.go(인증/RBAC), orders.go·finance.go(원장), database/migrations(번호 충돌), .github/workflows/release.yml(배포). admin_users.go 는 계정 상태·세션 폐기를 함께 건드려 준위험.
- 자주 깨지는 곳 / 지금 열려 있는 결함군:
  - **DB 오류와 "없음" 을 한 줄로 묶는 패턴**이 internal/httpapi 에 26곳 남아 있다(`if err != nil || tag.RowsAffected() == 0`). 최근 4회차 중 3회차가 이 계열을 하나씩 갈라 릴리즈했다(coupons 298/327, reports 80). 남은 곳: organizations 256, events 104, coupons 350, admin_users 72, reports 291, identity 110, discovery 196/211, mcp 409, webhooks 175/195, finance 101, keys 174 등.
  - 과거 040 마이그레이션 중복, captured/succeeded 결제 상태 불일치, Momento 다중 응답의 보안 헤더·Set-Cookie 유출 — 이미 처리된 접근을 반복하지 말 것.
  - docs/openapi.yaml 의 응답 코드 누락이 계속 쌓인다(PUT /me/webhooks/{id} 에 '400'·'500' 없음, POST /reports 에 '404' 없음). openapi_test.go 가 경로만 비교해 못 잡는다.
- 검증 함정:
  - DSN 없이 Go 테스트가 통과하는 것은 통합 검증이 아니다(통합은 SKIP 된다).
  - `integrationServer` 는 실제 Handler·DB·워커를 연결하고 전역 `apiUnderTest` 를 쓴다 — **테스트 병렬화 금지**.
  - 통합 테스트 클라이언트는 `newClient(t, server.URL)` → `register(name)` → `do(method, path, body, expectedStatus)` 이고 응답 맵을 돌려준다(integration_test.go:225-233 이 본보기).
  - `text` 컬럼에 NUL 바이트를 넣으면 PostgreSQL 이 SQLSTATE 22021 로 거절한다 — 저장 실패 분기를 HTTP 로 증명할 때 쓰는 유일하게 실측된 수법(2026-09-27 확인).
  - 프런트 테스트는 silentSso.test.ts 10건뿐이라 관리자 UI 배선을 증명하지 않는다.
  - CI(release.yml)는 v* 태그에서 Docker 빌드·archive 재로드·Release 만 하고 make check·DB 통합 단계가 없다. Docker Node 24.18.0 / Go 1.26.0, 로컬은 Go 1.26.7 / Node 22.23.1 에서 통과 확인 — 최소 빌드 버전 미확인.
  - 캡처 스크립트(guide-screenshots.mjs)는 시드·설정 쓰기를 하므로 루프백 폐기 인스턴스에서만.
  - 이번 회차에 `docker version` 은 승인 거부로 막혀 가용성 재확인 실패 — 지난 4회차에서는 29.7.2 였다.
