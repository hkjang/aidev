# v0.75.0 — 로그인 화면 없이 들어오고, 파일 없이 넘기고, 정책을 풀지 않고 셉니다

이번 회차는 관리자가 **켜기 전까지 아무것도 달라지지 않는** 것 셋입니다. 셋 다 기본값이
꺼져 있거나 비어 있고, 새로 설치한 곳은 v0.74.1 과 똑같은 화면을 냅니다.

## Keycloak 이 이미 아는 사람은 로그인 화면을 보지 않습니다

Keycloak 에 로그인해 둔 사람도 umm 을 열면 로그인 화면을 만났고, SSO 버튼을 한 번 더
눌러야 했습니다. 관리자가 **자동 로그인**(`oidc.auto_login`, 기본 꺼짐)을 켜면 브라우저는
로그인 화면을 그리기 전에 `prompt=none` 으로 Keycloak 에 먼저 갑니다. 세션이 있으면 화면
하나 없이 **열었던 깊은 링크 그 자리로** 들어오고, 없으면 평소의 로그인 화면입니다.

숨은 iframe 이 아니라 **최상위 이동**입니다. 서드파티 쿠키가 막힌 브라우저에서도 동작하고,
Keycloak 의 프레임 허용 여부와 무관합니다.

### 이 변경의 전부는 "다시 시도하지 않는 것"입니다

`prompt=none` 은 세션이 없으면 `login_required` 로 답합니다. 그것은 오류가 아니라 평범한
대답이고, 그 대답을 받고 또 시도하면 브라우저는 Keycloak 과 umm 사이를 끝없이 오갑니다.
그래서 시도를 막는 장치가 세 겹입니다.

| 겹 | 장치 | 풀리는 때 |
| :--- | :--- | :--- |
| 1 | 한 탭 세션에 한 번만 (`sessionStorage`) | 새 탭 |
| 2 | 스스로 로그아웃했으면 시도하지 않음 | 다시 세션이 생길 때 |
| 3 | 콜백이 거절을 받으면 `/login?sso=none` 으로 보내 주소에 표시 | 그 주소를 떠날 때 |

브라우저 저장소를 **읽을 수 없으면 "이미 시도했다"로 칩니다.** "아직 안 했다"로 읽는
것이 곧 루프이기 때문입니다.

서버는 `auto_login` 이 꺼져 있는 동안 `?prompt=none` 이 붙어 와도 조용히 평범한 로그인으로
바꿉니다. 리다이렉트가 시작되는 자리는 관리자 설정에 묶여 있어야 하고, 누구든 주소에 글자를
붙여 흐름을 바꿀 수 있어서는 안 됩니다.

## 방문 추적 스니펫을 붙이되, 정책은 그대로

어느 화면이 실제로 쓰이는지는 사내 앱마다 제각각 세고, 답은 어디에도 모이지 않았습니다.
이제 설정 화면의 **방문 추적**(`analytics`, 기본 꺼짐)에서 스니펫을 받습니다. 사내 수집기
**Momento** 가 첫 자리입니다 — 데이터가 밖으로 나가지 않는 유일한 선택지이고, 기본으로
umm 자신의 `/momento` 경로를 거치므로 정책에 외부 출처가 아예 등장하지 않습니다. GA4 ·
GTM · Matomo · 붙여 넣은 스니펫이 뒤를 잇습니다.

### 스니펫은 작은 부분입니다

umm 은 `script-src` 를 응답마다 다른 nonce 와 `'strict-dynamic'` 으로 잠가 둡니다. 스니펫을
그냥 붙이면 브라우저가 **조용히** 막고, 관리자는 텅 빈 대시보드를 보며 이유를 모릅니다.

```
    전                                     후
    ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━    ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    <script src="…/gtag.js">              <script nonce="<이 응답의 값>" src="…/gtag.js">
      ↓ nonce 없음 → 거절, 콘솔에만 남음     ↓ script-src 의 nonce 와 같음 → 실행
    수집기: 비어 있음                       connect-src · img-src 에 스니펫이 쓰는 출처만
                                            report-uri /csp-report
```

- 스니펫의 **모든** `<script>` 태그에 그 응답의 nonce 가 붙습니다. 태그를 찾는 접기는
  ASCII 만 접습니다 — `ToLower` 는 `İ` 와 켈빈 기호에서 바이트 위치를 옮겨 nonce 가 태그
  이름 안에 들어갑니다
- 그 응답의 정책에는 스니펫이 실제로 쓰는 출처만 `script-src` · `connect-src` · `img-src` 에
  더해집니다. 도구별 출처는 umm 이 알고, 붙여 넣은 스니펫은 코드 안의 `http(s)://…` 를 읽습니다
- **`'unsafe-inline'` 은 절대 넣지 않습니다.** 추적을 끄면 정책은 바이트 그대로 원래 값입니다
- API · 자산 · `/admin` 아래 화면(`include_admin` 없이)은 평범한 정책 그대로입니다

브라우저가 그래도 거절한 것은 남습니다 — 출처와 지시어 단위로, 최대 100개, 추적이 켜진 동안만,
이 인스턴스의 메모리에. 설정 화면에서 한 줄마다 **허용 목록에 더하기** 한 번입니다. Momento
프록시는 나가는 길에 umm 의 세션 쿠키와 `Authorization` 을 지우고, 추적을 끄는 순간 닫힙니다
(404).

## 공간을 다른 서비스로 넘기는 데 파일이 필요 없습니다

생각은 umm 의 캔버스에서 시작해 muni 의 문서가 되고 ptium 의 슬라이드가 되어 weekly 의
보고로 들어갑니다. 형식은 이미 맞았습니다 — umm 은 Markdown 을 쓰고 나머지는 읽습니다.
없던 것은 **손**이었습니다. 단계마다 누군가 파일을 내려받아 다시 올렸습니다.

umm 은 사내 표준(`HANDOFF-STANDARD.md`)의 **보내는 쪽**이며 그것뿐입니다. `markdown` 을
보내고 아무것도 받지 않으므로 받는 경로도, 보낼 수 없는 형식의 버튼도 없습니다.

```
    캔버스 ── 내보내기 ▸ 다른 서비스로 보내기 ▸ Ptium
       │
       ├─ POST /api/v1/handoff/claims  {resource, format}   (로그인, 승인 게이트)
       │     ← 201  claim · source · filename · content_type · bytes · expires_at
       │
       └─ 새 창: https://ptium.intra/handoff?source=<umm>&claim=<표>
                    │
                    └─ GET <umm>/api/v1/handoff/claims/<표>   (로그인 없음, 한 번)
                          ← 문서 차례 Markdown, 그리고 표는 지워짐
```

- 표는 256비트, **5분**, **한 번**. 그 사람이 읽을 수 있는 공간 하나에 묶이고, 다른 내보내기와
  같은 검사와 같은 승인 게이트를 지납니다
- 문서는 공간의 **문서 차례**입니다 — 그래프가 놓은 순서의 문장, id 와 좌표가 있는 백업이
  아닙니다. 표를 발급하는 순간 만들어 표와 함께 저장하므로(마이그레이션 029, `handoff_claims`)
  받아 가는 바이트는 `bytes` 가 알린 그대로입니다
- 저장되는 것은 표의 다이제스트뿐입니다. 한 번 쓰임은 행을 돌려주는 `DELETE` 한 문장이라
  두 수령자가 경쟁해도 문서는 하나만 나갑니다. 쓴 표 · 만료 · 미발급은 모두 같은 404 입니다
- 접근 로그는 경로의 표 자리를 `{claim}` 으로 가려 찍고, 감사 로그는 공간이 나갔다는 사실만
  적으며, 발급 응답은 새 비밀을 실은 다른 응답처럼 압축에서 제외됩니다
- 새 창은 **클릭 안에서** 먼저 열고 표가 오면 서비스로 향하게 합니다. 오지 않으면 닫습니다.
  팝업 차단기가 거절할 것이 없습니다

어디로 보낼 수 있는지는 관리자의 목록입니다 — 설정 절 `handoff`, 기본 **비어 있음**, 새
화면 **다른 서비스로 보내기**에서 이름 · 오리진(스킴과 호스트만, 경로·중복 거부) · 받는
형식을 적습니다. 목록이 비어 있으면 캔버스에 메뉴 자체가 없습니다.

## 운영자가 알아야 할 것

- 마이그레이션 둘: `028_analytics_settings`(추적 설정 씨앗, 꺼짐) · `029_handoff_claims`(표
  저장). 둘 다 down 스크립트가 있습니다
- 관리자 가이드에 **부록 2-1**(자동 로그인) · **부록 10**(방문 추적) · **부록 11**(다른
  서비스로 보내기)이 더해졌고, OpenAPI 문서에 handoff 경로 셋이 올랐습니다
- 받는 서비스 쪽 허용 목록에는 umm 의 `source` — **일반 → 공개 URL** 의 오리진 — 를 그쪽 표기와
  정확히 같게 적어야 합니다

## 확인한 것

```
✓ auto_login 꺼짐: ?prompt=none 이 붙어도 평범한 로그인
✓ 켜짐: 세션 있으면 깊은 링크로, 없으면 /login?sso=none 한 번, 그 뒤 시도 없음
✓ return_to 는 / 로 시작하고 // 로 시작하지 않는 경로만
✓ 추적 꺼짐: 소스에 스니펫 없음, 정책에 report-uri 없음, /momento 404
✓ 켜짐: 모든 <script> 에 그 응답의 nonce, 세 지시어에 스니펫의 출처만, 관리 화면은 제외
✓ 다시 끄면 정책은 바이트 그대로
✓ 목록 비면 메뉴 없음 · pptx 만 받는 대상은 안 보임 · 경로 있는 오리진 400
✓ 표 발급 201, 비압축, 감사 로그에 표 없음, 다이제스트로 저장
✓ 쿠키 없이 한 번 수령, 이름·바이트 일치 · 두 번째/만료/미발급 404 · 남의 공간엔 행 없음
```

redeem 을 `DELETE … RETURNING` 에서 `SELECT` 로 되돌리면 "spent 200 / expired 200" 두 단언이
떨어지는 것을 확인했습니다.

## 하지 않은 것

- **받는 쪽.** 표준의 형식 표에서 umm 이 맡은 칸은 보내기뿐입니다. `/handoff` 경로와 source
  허용 목록은 받는 서비스의 몫입니다
- **두 서비스를 실제로 띄운 확인.** 이 환경에 받는 서비스가 없어 통합 시험의 쿠키 없는
  `GET` 으로 대신했습니다
- 정책이 차단한 출처의 기록은 **인스턴스별 메모리**입니다. 인스턴스가 여럿이면 관리자가 보는
  목록은 어느 인스턴스에 닿았느냐에 따라 다릅니다 — 표준대로이지만 적어 둡니다
- 로그인 화면의 SSO **버튼**은 아직 `return_to` 없이 시작합니다. 깊은 링크에서 버튼으로
  로그인하면 `/` 로 돌아옵니다
