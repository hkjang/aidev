# 이룸검수 (client.irumx.app) 프로필 (2026-10-07)
- 목적: 외주 개발의 작업 범위·추가 작업·납품 검수를 개발업체와 고객이 함께 확인하고 발행본·승인 기록을 고정하는 멀티테넌트 SaaS.
- 기준: main@155a4ee, package.json v0.9.0. 이전 프로필(v2 중심)보다 문의 자동화·보유 기간 파기·하자·CSV·운영자 도구가 추가돼 갱신.
- 스택: TypeScript, Node >=22.12.0; React 19·Vite 8·React Router 8·TanStack Query; Cloudflare Workers·Hono 4; D1·Drizzle 0.45; 비공개 R2; Better Auth 이메일 OTP; Resend; Playwright 1.63.
- 구조:
  - src/client/pages/ — 프로젝트·요청·범위·납품·검수·파일·고객·업체·운영자·문의·상품·공개 문의 화면.
  - src/client/components/, lib/, styles/ — UI·댓글·결정·아이콘, API·타입·포맷, 디자인 토큰·스타일.
  - src/worker/ — app/index 진입, routes의 프로젝트/승인/파일/문의/intake/공개 경로 등; access/auth 권한·인증.
  - src/worker/services/ — 승인·파일·메일/outbox·보완·파기·보수 기간·요청 알림·문의 처리. db/는 D1 스키마/접근.
  - src/shared/ — domain.ts 역할·상태·공유 정책, kakao.ts 순수 붙여넣기 파서, inquiry.ts 문의 규칙(현재 AI 미연결).
  - migrations/ — 0000~0006 SQL 및 meta; 고정 트리거, 보유 기간, 보완, 알림, 문의 데이터 확장.
  - tests/ — kakao/guard/domain 단위, api-* API, ui-* 브라우저, shots, mock-resend.mjs와 API 헬퍼.
  - scripts/ — 글꼴·빌드 점검·로컬 DB·관리자·배포·백업 복구·화면 캡처.
  - docs/ — architecture/spec-coverage/operations/deploy/privacy/qa/inquiry, spec/inquiry-automation.md(단계별 미구현 항목 포함).
- 빌드·테스트:
  - npm ci → npm run check → npm run build → npm test. build는 글꼴/타입/Vite/산출물 점검으로 시간이 걸림; 전체 시험도 장시간 가능.
  - npm test -- --project=unit tests/kakao.spec.ts; npm test -- --project=desktop tests/ui-flow.spec.ts.
  - Playwright unit도 전역 webServer 실행: mock Resend :8799, db-local로 D1 초기화 후 wrangler :8798; dist 필요; workers:1.
  - ui-flow.spec.ts는 serial이고 앞 시험이 뒤 시험의 pm/pid를 준비하므로 -g로 뒷 시험만 실행하면 안 됨.
  - npm run shots(SHOTS=1), npm run backup-drill -- --local .wrangler/test-state, npm run admin -- ..., npm run deploy.
  - README/docs/qa.md는 101개 통과·210장 캡처를 기록하지만 이번 정찰의 전체 실행 결과는 아님.
  - 이번 환경 Node v22.23.1, node_modules 없음. npm run check 실제 결과 tsc: not found(127). 의존성 설치/빌드/Playwright 미실행.
  - 순수 kakao.ts는 node --experimental-strip-types --input-type=module로 직접 import 가능(정찰에서 확인, 정식 시험 대체 아님).
- 관례: 한국어 커밋 제목·문서·파일 머리 규칙 주석. wrangler.jsonc vars 및 비밀값 설정; 마이그레이션은 Drizzle 생성+수동 트리거 SQL. 요구사항 대응과 QA는 docs/.
- 위험 구역:
  - auth.ts/access.ts, domain 권한표: OTP·세션·기본 거부, 승인자만 결정. 역할 확대 주의.
  - services/approvals.ts 및 migrations: 결정·대상 상태·이력·outbox를 D1 batch로 묶고 선점 장치로 동시성 보호. 발행본/결정 불변.
  - services/files.ts: 비공개 R2·내용 기반 검사·PDF 실행 요소 차단. 완화 시 보안 회귀 필요.
  - services/purge.ts 및 보유 기간 SQL: 실제 삭제와 트리거 복구. 문의 개인정보·공개 링크도 민감.
  - wrangler.jsonc·배포 스크립트는 운영 리소스 연결. .github/workflows는 현재 없지만 보호 경로로 취급.
- 자주 깨지는 곳: 대체된 승인 링크·후속 id 연결; 시험의 Cron 200 오판; 백업 표 목록 누락/옛 트리거 복원; URL 검색 상태 경합(docs/qa.md).
