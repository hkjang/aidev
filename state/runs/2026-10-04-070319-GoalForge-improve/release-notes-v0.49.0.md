## 고친 것
- **리뷰 게이트가 빌드·테스트 요구를 대신하던 것**: 증거 종류의 강약 사다리에서 `review` 가 `build` 와 같은 칸에 있어, `@build` 를 요구한 완료 조건이 `review` 게이트의 통과만으로 MET 이 되었습니다. 반대 방향도 열려 있어 `@review` 조건이 빌드·여정 통과로 충족됐습니다. 리뷰는 사람 또는 모델의 **판단**이고 GoalForge 에서 판단을 내리는 쪽은 보통 그 코드를 쓴 구현 세션이므로, 아무것도 빌드되지 않은 상태에서 런이 자기 작업을 스스로 인증하고 목표가 완료로 보고되는 경로였습니다. `review` 를 `security`·`performance` 와 함께 사다리 밖으로 옮겨, 이 세 종류는 양방향 모두 자기 자신만 충족시킵니다.

## 알아 두실 것
- **행동을 좁히는 변경입니다.** `@build` 나 `@test` 를 요구한 완료 조건을 `review` 게이트로 측정해 온 프로젝트가 있다면, 그 조건은 MET 에서 `WRONG_KIND` 로 바뀝니다. 의도한 조임이며, 바뀌는 쪽은 애초에 증명되지 않은 것을 완료로 보고하던 조건입니다. 해당 조건에는 실제 `build`/`test` 게이트를 붙여 주세요.
- **종류를 요구하지 않는 완료 조건은 이전과 완전히 동일하게 동작합니다.** 기존 프로젝트가 갑자기 미충족이 되지 않습니다.
- `goalforge verify gate add` 가 받는 종류는 그대로 일곱 개입니다(`build`, `integration`, `journey`, `performance`, `review`, `security`, `test`). 종류가 사라지거나 늘어나지 않습니다.
- 판정이 어긋나는 자리는 `goalforge doctor` 의 `proof kind` 검사에서 미리 보입니다 — 사전 진단과 사후 판정이 같은 함수를 지나므로 둘의 답이 갈리지 않습니다.

자세한 배경은 `docs/GUIDE.md` 의 증거 종류 절을 보세요.

고치기 전에 세 소비 경로(정책 함수·실제 SQLite 저장소의 완료 판정·`doctor` 준비도)의 테스트를 먼저 써서 실패를 확인했고, 수정 뒤 전 패키지 테스트가 통과합니다. 플랫폼별 실행 파일과 SHA256SUMS 를 첨부했습니다. 각 산출물의 출처는 다음으로 검증할 수 있습니다:

```
gh attestation verify goalforge_v0.49.0_linux_amd64.tar.gz --repo hkjang/goalforge
```
