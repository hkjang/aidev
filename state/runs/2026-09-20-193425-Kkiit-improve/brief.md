- 과제: 승인 정책 카드에서 적용 조건을 바로 확인하기 (가치 3 / 위험 1 / 작업량 S)
- 왜: `web/src/pages/AdminPage.tsx:ApprovalAdmin`은 API가 반환한 `conditions`를 편집 폼에서만 사용하고 정책 카드에는 이름·resource_type·우선순위만 표시한다. 카드에 조건을 표시하면 운영자가 정책마다 편집창을 열지 않고 적용 대상을 구분할 수 있다.
- 수용 기준: 1) `/admin/approvals`의 각 정책 카드에 저장된 최소·최대 금액, 서비스 유형, 판매자 등급, 품질 점수 조건을 읽기 쉬운 한국어로 표시한다. 금액은 천 단위 구분과 원 단위로 표시하고 `min_amount`는 이상, `max_amount`는 이하, `quality_score_below`는 미만으로 표현한다. 0은 누락하지 않으며 빈 배열은 제한으로 표시하지 않는다. 품질 점수 미산정 상품도 해당 조건에 매칭되는 현재 서버 동작을 안내한다. 유효 조건이 없는 일반적인 `{}` 정책에는 ‘조건 없음 · 모든 상품에 적용’을 표시한다. 2) 생성·편집 저장 후 다시 로드한 카드와 편집 폼의 값이 일치하며 활성 전환·삭제·대기 요청 검토는 기존대로 동작한다. 좁은 화면에서는 조건이 줄바꿈되고 조작 버튼을 가리지 않는다. 알 수 없는 키나 잘못된 값이 있을 때 그것을 정상 조건처럼 해석하거나 무조건 ‘모든 상품’으로 단정하지 않는다(간단한 ‘일부 조건 확인 필요’ 안내면 충분). 3) 버릴 수 있는 실제 서버·DB에서 실제 정책 API/화면으로 `{}`, `min_amount:0`, 금액 양쪽 경계, 복수 service_types/seller_levels, quality_score_below:0 및 일반 임계값을 저장하고 실제 렌더된 카드와 편집창을 확인한다. 저장→GET→카드→편집→저장 경로를 증거로 남긴다. 문자열 소스 검색이나 독립 포맷터 테스트만으로 화면 배선이 검증됐다고 하지 않는다.
