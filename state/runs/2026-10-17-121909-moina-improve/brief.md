- 과제: `admin.go` 의 `storage_error` 500 출구 25곳을 `writeStorageError` 로 이관한다 (가치 3 / 위험 1 / 작업량 M)

- 왜: `admin.go` 는 이제 `httpapi` 에서 `storage_error` 500 출구가 가장 많이 남은 파일(25곳, 확인: `grep -c 'writeError(w, http.StatusInternalServerError, "storage_error"' admin.go` = 25)인데 전부 `err` 를 버려, message 가 중복("사용자 목록을 불러올 수 없습니다" 2곳·"콘텐츠 목록을 불러올 수 없습니다" 2곳·"콘텐츠를 삭제할 수 없습니다" 2곳·"신고 목록을 불러올 수 없습니다" 2곳·"역할 정책을 불러올 수 없습니다" 2곳·"역할 정책을 저장할 수 없습니다" **5곳**·"감사 로그를 불러올 수 없습니다" 2곳)인 탓에 운영자가 500 을 보고도 어느 쿼리가 거절됐는지 구분할 수 없습니다. 같은 파일의 `resolveReport`·`adminResetPassword` 는 v0.1.42 에서 이미 `writeStorageError` 로 옮겨져 있어 **한 파일 안에서 계약이 반쪽**입니다. 이관하면 `handler`·`cause_type`·`pg_code` 가 `request_id` 와 함께 남습니다.

- 수용 기준:
  1) `admin.go` 의 `writeError(w, http.StatusInternalServerError, "storage_error", …)` 가 **0곳**(`grep -c` 로 확인), 대신 `writeStorageError(w, r, "<감싼 함수 이름>", <err>, "<원래 message>")` 25곳.
  2) **응답 불변**: status 500 · `code:"storage_error"` · message 문자열이 한 글자도 바뀌지 않음. `git show HEAD:backend/internal/httpapi/admin.go` 와 작업 트리의 한글 문자열 리터럴 multiset 을 비교해 **HEAD 에만 있는 리터럴 0개**임을 출력으로 보일 것(2026-10-05/10-06 회차가 쓴 방법). 늘어난 리터럴이 생겼다면 왜 생겼는지 적을 것(이번 과제는 제어 흐름 분할이 **필요 없다** — 아래 참고).
  3) `handler` 인자는 수기로 적지 말고 `^func ` 경계에서 **감싼 함수 이름을 기계적으로 유도**해 치환하고, 같은 유도를 다시 돌려 25개 호출 전부 mismatch 0 임을 보일 것. 정찰이 확인한 매핑(HEAD 줄번호 → handler): 38 `adminStats` · 55,63 `adminListUsers` · 108 `adminCreateUser` · 174 `adminUpdateUser` · 240,250 `adminListPosts` · 273 `adminUpdatePost` · 292 `adminDeletePost` · 333,342 `adminListReports` · 419,429 `adminListRoles` · 483,489,494,499,506 `adminPutRoles` · 523,534 `adminListAudit` · 545 `adminListKeys` · 564,585,604 `adminUpdateKey` · 618 `adminRevokeKey`.
  4) 테스트가 증명해야 하는 것: **실제 admin 핸들러 경로**(production wiring `store.Open → New → Handler()`)에서 저장 실패 500 이 났을 때 운영자 로그에 `"error_code":"storage_error"`·`"handler":"adminUpdatePost"`·`"cause_type":"*pgconn.PgError"`·`"pg_code":"P0001"` 와 `request_id` 가 남는다. **고치기 전에 먼저 red 를 관측**하고, 같은 red 출력에서 **응답 단언(500 + `storage_error` + 원래 message)은 통과**해야 한다(= red 의 원인이 응답이 아니라 없는 관측성임이 분리된다).

- 건드릴 파일 (프로덕션 **1개** + 테스트 1개):
  - `backend/internal/httpapi/admin.go` — 위 25곳을 `writeStorageError` 로. **네 곳은 넘길 `err` 가 없다**: `adminListPosts:250`·`adminListReports:342`·`adminListRoles:429`·`adminListAudit:534` 가 `if rows.Scan(...) != nil {` 형태로 오류를 **인라인에서 버린다**. `if scanErr := rows.Scan(...); scanErr != nil {` 로 바꿔 `scanErr` 를 넘길 것. 같은 loop 안에 Query 의 `err`(이 지점에서는 **nil**)가 아직 scope 에 있으므로 그것을 넘기면 `cause_type:"<nil>"`·`pg_code:""` 가 찍힌다 — 이 회차가 없애려는 바로 그 "원인 없는 500" 이다. `adminListUsers:63` 은 이미 `user, scanErr := scanUserRow(rows)` 라 `scanErr` 를 그대로 넘기면 된다. `adminPutRoles:489/494/499` 는 `if _, err := tx.Exec(...); err != nil` 로 shadow 된 `err` 가 있어 그대로 넘기면 된다.
