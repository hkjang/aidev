SQL 기반 목록 어댑터 응답 키 수정 릴리즈 (#33):
  #33 같은 URL `GET /api/v1/data/lists/{id}` 의 두 백엔드가 응답 키 규약이
    달랐던 것 — `DataAdapterService.executeEntityBacked` 는 `lowerCaseKeys`
    를 거치는데 `executeSqlBacked` 는 `SqlExecutor` 원본 행을 그대로 `Rows`
    로 내보냈다. 드라이버는 SQL 이 쓴 대소문자를 그대로 보고하므로(H2 는
    `SELECT id, name` 에 `ID`/`NAME` 을 준다 — 테스트 실행으로 확인) jqxgrid
    가 `columnsJson` 의 소문자 `field` 로 찾는 키와 어긋나 셀이 전부 비었음
  #33 같은 원인이 정렬에서는 더 크게 터졌음 — `applySort` 는 `rows.sort(...)`
    로 제자리 정렬을 하는데 `RecordSet.getRows()` 는
    `Collections.unmodifiableList` 를 돌려주므로 `sortdatafield` 를 주면
    조용한 no-op 이 아니라 `UnsupportedOperationException` → 500 이었다.
    즉 SQL 기반 목록은 헤더를 한 번 클릭하면 그리드가 에러로 죽었음
  #33 기존 `lowerCaseKeys` 헬퍼를 `applySort` 앞에 한 번 통과시켜 둘을 같이
    고침 — 키가 소문자가 되는 동시에 우리가 소유한 가변 리스트 복사본이 되어
    제자리 정렬이 가능해진다. 호출 순서는 `lowerCaseKeys` → `total` →
    `applySort` → `applyPaging`, 프로덕션 파일은 `DataAdapterService` 1개
  #33 `SqlExecutor`/`RecordSet` 은 건드리지 않음 (`listData`·내보내기 3종·
    Groovy 플러그인이 공유) — `applySort` 에 "제자리 정렬이므로 호출자가
    소유한 리스트를 넘겨야 한다" 는 Javadoc 만 덧붙였다
  #33 계약 변화: 따옴표로 대소문자를 고정한 별칭(`SELECT name AS "userName"`)
    을 쓰는 SQL 정의는 이 URL 에서 키가 `username` 으로 나간다. 마이그레이션에
    그런 정의는 없고 Postgres/MySQL 은 따옴표 없는 식별자를 이미 소문자로
    주므로 그 환경에서는 no-op; `totalCount`·성공 봉투·엔티티 백엔드 응답 불변
  #33 `SqlBackedListDefinitionIntegrationTest` 2건 추가 — 수정 전 단독 실행에서
