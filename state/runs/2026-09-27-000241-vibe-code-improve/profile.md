# vibe-code 프로필 (2026-09-28)

- 목적: VS Code 확장. 한국어 기본의 "바이브 코딩" 도구로, 채팅 워크스페이스 위에 목표(`/goal`) 기반 자율 개발 루프, 계획 보드, 검증 러너, 명령 실행 감사, 사용량/비용 대시보드를 얹는다. 현재 **1.4.3** (base main@b30117e).
- 스택: TypeScript(ES2022, commonjs, `strict`), esbuild 번들, vitest 3, Node 20. DB 없음 — 상태는 워크스페이스의 `.vibe-code/` 아래 markdown + JSONL. 웹뷰는 `webview-ui/`(원본 소스 확보 불가), 코어는 `vendor/extension.core.js` 로 벤더링(수정 금지).
- 구조:
  - `src/extension.ts` → `src/activation.ts` 가 feature 등록을 모두 호출.
  - `src/features/*.ts` — 기능 한 개당 파일 한 개(goals, plans, plan-codelens, verification, checkpoints, command-audit, usage, vibe-coders-proxy, tree, status-bar, goal-lint, goal-metrics, goal-loop, goal-health, goal-catalog, journal-summary …). 각 파일이 `register*(host: CoreHost)` 를 내보내고 그 안에서 `vscode.commands.registerCommand` 를 한다.
  - `src/core/hooks.ts`, `src/core/host.ts` — 벤더 코어 접점. 훅은 `beforeCore`, `mergeLocaleOverrides`, `onCommand` 셋뿐(`vendor/PATCHES.md`).
  - `src/util/markdown.ts`(188줄) — 상태 파일의 **유일한 섹션 파서/에디터**. `section`/`subsection`/`hasSection`/`writeSection`/`matchLine`/`setLine`/`touchPlan`/`taskLines`/`countChecks`/`isTaskLine`/`toggleCheckbox`/`moveTaskToSection`. v1.4.3 부터 읽기는 `normalizeEol` 로 LF 정규화, 편집은 `detectEol`+`restoreEol` 로 원본 줄바꿈 복원.
  - `src/util/kst.ts`(Asia/Seoul 날짜·스탬프), `src/util/semver.ts`.
  - `src/features/workspace.ts` — `.vibe-code/` 경로 해석(`ensureWorkspacePaths`)과 감사 기록(`writeAudit`)의 단일 관문.
  - `tests/unit/` — vitest 10개 파일, 70 tests. `vscode` 는 `tests/unit/vscode-stub.ts` 로 alias(`vitest.config.mts`). `tests/extension-host/` 는 Windows PowerShell 전용.
  - `docs/` — 한국어. `improvement-roadmap.md` 가 사실상 백로그.
- 빌드·테스트: **워크트리에 `node_modules` 가 없다 — `npm ci` 부터.** 이어서 `npm run check`(= `typecheck`(tsc --noEmit) + `test`(vitest run) + `build`(esbuild))가 CI 가 돌리는 것. 단일 파일은 `npx vitest run tests/unit/<file>.test.ts`. `npm run vsix` / `verify` / `smoke:vscode` / `test:extension-host` 는 PowerShell 전용이라 리눅스에서 안 돈다.
- 관례: 커밋은 영어 conventional commit(`feat:`, `fix:`, `chore:`), 본문은 한국어 요약. 사용자에게 보이는 문자열·주석·문서는 한국어, 코드 식별자는 영어. 설정은 `package.json` 의 `contributes.configuration` + `package.nls.json`/`package.nls.ko.json` 의 `%키%` 쌍 — 세 곳을 같이 고친다. 마이그레이션 개념 없음(상태는 파일). **정착된 패턴: vscode 의존 명령 콜백에서 순수 함수를 export 로 뽑아 실제 템플릿 문자열·실제 임시 디렉터리로 vitest 검증**(v1.4.1 checkpoints, v1.4.2 archiveDonePlans, v1.4.3 markdown 이 모두 이 형태).
- 위험 구역:
  - `src/features/checkpoints.ts` — 파괴적 명령 직전 스냅샷. 임시 index 기반 `read-tree`→`add -A`→`write-tree`→`commit-tree`. 작업 트리·stash 스택을 건드리면 사고.
  - `src/core/hooks.ts` + `vendor/extension.core.js` — 훅 계약이 깨지면 확장 전체가 죽는다. 벤더 번들 수정 금지.
  - `src/features/command-audit.ts` / `writeAudit` — 감사 로그에 명령 원문 외(출력·파일 내용·키)를 넣지 말 것.
  - `src/features/vibe-coders-proxy.ts`(356줄, 테스트 0) — provider 프로파일을 덮어쓴다. 저장/복원 경로를 깨지 말 것.
  - `.github/workflows/ci.yml`, `scripts/*.ps1`, `release/` — 릴리즈 경로.
- 자주 깨지는 곳(회차 3회 기준):
  - `src/util/markdown.ts` 의 섹션 재조립. `writeSection(text, name, lines)` 는 섹션 본문을 **통째로 교체**하므로, 호출자가 `taskLines()`/`lines()` 로 걸러 넘기면 걸러진 줄이 파일에서 사라진다(`plans.ts` advance, `markdown.ts` moveTaskToSection, `verification.ts` 검증 로그 — 세 곳 모두 이 형태).
  - 같은 값을 읽는 경로가 여럿이라 한쪽만 고치면 어긋난다: 체크리스트 판정이 `countChecks`(들여쓰기 불가) / `taskLines`(trim 후 허용) / `isTaskLine` 원문 호출(plan-codelens) 로 세 갈래.
  - `section()` 은 본문을 trim 해 돌려주므로 빈 섹션은 `""` 이고 `"".split("\n")` 은 `[""]` — 그대로 쓰면 빈 줄이 끼어든다.
- 검증 함정:
  - `dist/` 는 git 에 없고 런타임 자산은 릴리즈 VSIX 에서 복원(`scripts/restore-dist-assets.mjs`). CI packaging job 은 릴리즈 자산이 없으면 조용히 건너뛴다.
  - 테스트는 `vscode` 스텁 위에서 돈다. 스텁에 없는 API 를 import 시점에 건드리면 깨진다 — 함수 본문 안에서만 쓸 것.
  - 시간은 Asia/Seoul 고정(`src/util/kst.ts`). 로컬 타임존 의존 단정 금지.
  - 확장 호스트 테스트·VSIX 검증은 Windows 전용이라 리눅스 CI `check` job 이 보지 못한다.
  - `.vibe-code/*.md` 가 CRLF 로 내려올 수 있다(사용자 Windows 체크아웃). 새 파서·편집 경로는 CRLF 입력으로도 테스트할 것.
