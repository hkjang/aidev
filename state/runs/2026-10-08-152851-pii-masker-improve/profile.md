- 자주 깨지는 곳:
  - 업로드 잘못은 processing_failed/400/재시도 불가, 업스트림 좌표 잘못은 masking_failed/502/재시도 가능. service.mapError가 *RegionPlacementError와 maskingFailedError를 처리한다.
  - PDF에 없는 페이지도 이제 placementError로 분류(main@19b4426). PDF page 크기가 없으면 여전히 일반 오류여야 한다(TestMaskPDFFileBlamesTheDocumentForAPageWithoutDimensions).
  - 이미지 페이지 검사 누락은 현재 미해결: MaskImageFile(:494)은 모든 page를 첫 이미지에 그림. 이번 정찰에서 PNG page 3 동기 200/completed, 비동기 completed/download_url로 실제 재현; 선택 과제서 참조.
  - 선언 MIME vs 실제 바이트: 출력 인코딩은 선언 MIME, 업스트림 전송 사본은 실제 내용 기준 PNG. 두 계약을 함께 바꾸지 않는다.
  - MaskValue는 룬 수 보존 필요. 원문과 동일한 규칙 결과를 전부 숨기는 폴백이 반영되어 있음. 좌표 부분 마스킹 정렬이 의존한다.
  - config 오버플로 수정은 envInt 전면 변경 대신 호출 지점별 전용 헬퍼를 쓰는 패턴을 유지했다.
- 검증 함정:
  - startAppServerWithUpstream(integration_test.go:1893)은 config를 직접 조립하지만 app.New와 실제 httptest 리스너를 통과한다. Load 회귀는 실제 config.Load 결과를 사용해야 한다.
  - buildMultipartBody(:1942)는 contentType을 무시하고 application/octet-stream을 보내므로 스니핑으로 통과한다. 선언 MIME을 보내려면 buildMultipartBodyWithFilenameParam(:1969).
  - missingPageUpstream(:1692)은 page 3, 정상 안쪽 좌표 (40,20)-(200,60)을 반환한다. 기존 동기/비동기 missing-page 회귀는 PDF만 검사한다(:1704/:1736).
  - collectMaskRegionsRecursive(engine.go:107)는 미지정/0을 page 1로 바꾼다. extractPageNumberFromMap(:765)은 음수도 받아들이지 않아 0으로 반환한다. PDF 직접 호출의 page 0 거절 테스트를 HTTP 생략 거절로 해석하지 말 것.
  - 이미지 page 1/생략의 HTTP 정상 성공은 이번 실제 cmd 서버 실행으로 확인. 직접 MaskImageFile의 page 0도 현행 코드에서는 검사 없이 처리되므로 호환성상 보존 권장.
  - GOARCH=386 go test -count=1 ./internal/document는 이번 실행에서 실패 확인: TestValidateImageDimensionsRejectsPixelBomb(:22), :35에서 dimension overflow를 해상도 제한 오류로 예상하여 실패. 프로덕션은 파일을 거절하고 있다.
  - historyLimit 최대 100은 응답 길이만 제한한다. Store.List 전체 clone/정렬 메모리 비용까지 제한한다는 이전 기록은 잘못됨.
  - normalized 좌표 테스트가 placeRegion만 직접 검증하는 점에 주의. buildSubRegionsFromBBox의 폭 1 보정이 수집 이후 단위를 바꾸는지는 신규 후보이며 실제 출력 재현 미확인.
  - t.Setenv 테스트 병렬화 금지. 내장 mock은 임의 page/field를 반환하지 않으므로 오류 회귀는 직접 만든 HTTP upstream handler 사용.
  - PDF 픽스처 createBlankPDF와 masking.blankPDF는 별도 패키지에 있다. Docker 빌드·Windows Rename 동작은 계속 미확인.
- 현재 기준: main@19b4426(제공 기록상 v1.0.37). 이전 프로필의 기준 커밋·함수 위치·386 미확인 상태·HTTP page 생략 설명을 정정했다.
