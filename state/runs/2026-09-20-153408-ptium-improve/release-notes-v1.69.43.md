# Ptium 1.69.43

## 시트에서 숨겨 둔 행과 열이 표에 들어왔습니다

엑셀 시트는 행과 열을 숨깁니다 — 필터로 걸러 낸 행, 접어 둔 그룹, 수식이 찾아보는
코드 열. 사람이 보는 화면에는 없지만 파일에는 `hidden="1"` 로 그대로 있고, xlsx 가져오기는
그 표시를 읽지 않았습니다. 숨긴 시트는 이미 빼고 알려 주면서, 시트 **안의** 숨긴 것은
그대로 표에 넣었습니다.

가장 눈에 띄는 경우가 이것입니다. 라벨 한 열 + 숫자 한 열은 차트가 되고, 그 옆에 숫자
보조 열 하나를 숨겨 두었다면 —

```
화면:   지역 | 매출              → 세로 막대 차트
파일:   지역 | 매출 | (숨긴) 비중   → 3열 표
```

차트를 기대한 시트가 표로 넘어왔고, 왜 그런지 화면에서는 보이지 않았습니다. 필터를 건 시트는
걸러 낸 행이 다시 살아나 표가 길어졌습니다.

이제 `<row hidden>` 과 `<cols><col min max hidden>` 을 읽어, 숨긴 행은 빼고 숨긴 열은
각 줄에서 **잘라 냅니다** — 빈칸으로 두면 표 가운데 빈 열이 남으므로. 그리고 슬라이드를
쓴 시트에만 한 줄로 알립니다.

```
지역별의 숨긴 행 2개와 열 1개는 가져오지 않았습니다
```

세는 것은 화면에서 숨길 만한 것만입니다 — 셀이 있는 행, 보이는 행에 값이 쓰인 열.
엑셀은 열을 시트 끝까지 한 범위(`min="5" max="16384"`)로 숨기므로, 그것을 "열 16380개"
로 세지 않고 범위를 펼치지도 않습니다. 열 C 부터 40억까지 숨긴 여섯 셀짜리 시트도 그리드
너비만큼만 봅니다.

숨긴 행·열을 잘라 낸 뒤에도 슬라이드의 출처는 **시트 위의 자리**입니다. 남은 칸 수로
계산하면 열 B·C 를 숨긴 시트의 출처는 실제로 A 와 D 인데 `A1:B3` 이라 적혀, 비고를
읽어 온 열이 숨긴 코드 열이라고 말하게 됩니다. 이제 남은 행·열이 시트의 몇 번째였는지를
함께 들고 다니며, 출처는 시트가 세는 대로 `A1:D3` 으로 적습니다.

숫자 파서 · `allNumeric` · `gridOf` 의 시그니처는 손대지 않았습니다 — 그리드에 넣는
입력만 바뀌었습니다. `docs/USER_GUIDE.md` 의 xlsx 행에 숨긴 시트·행·열을 가져오지 않는다는
한 마디를 더했습니다.

## 지키는 장치

`internal/docs/sheetconcealed_test.go` 의 여섯 검사가 봅니다 — 숨긴 행이 표에서 빠지고
순서와 경고가 맞는지, 숨긴 열 범위가 모든 줄에서 잘려 A 와 D 가 붙고 출처가 시트대로인지,
끝까지 숨긴 범위가 메모리를 쓰지 않는지, 보조 열을 숨기면 같은 시트가 `::table` 에서
`::columns` 로 바뀌는지를 `Read()` 끝까지 통과한 `Source` 로, 행과 열이 한 줄 경고로 묶이는지,
전부 숨긴 시트가 이전처럼 "읽을 표가 없습니다" 인지. 고치기 전 코드에서 전부 실패하는 것을
확인한 뒤 고쳤습니다. 숨김 없음 · `hidden="0"` · 범위 없음은 경고 0건입니다.
