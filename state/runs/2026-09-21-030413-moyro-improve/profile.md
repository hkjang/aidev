# moyro 프로필 (2026-09-21)
- 목적: Mattermost v4 API 호환 채팅에 승인·작업·자동화·지식·MCP를 통합한 자체 호스팅 협업 앱.
- 스택: Go 1.27.0(go.mod), chi, pgx v5, PostgreSQL / React 18·TypeScript·Vite 8·Redux·MUI / Vitest·Playwright / Docker.
- 구조:
  - `server/cmd/moyro`: 서버 진입점; `server/cmd/fakeoidc`: 테스트 IdP.
  - `server/internal/httpapi`: compat_* `/api/v4`, native_* `/api/moyro/v1`, router.go 라우팅.
  - `server/internal/sidebar`, `channels`, `posts`, `workitems`, `automations`, `reminders`: 도메인 서비스/워커.
  - `server/internal/store`: DB 풀 및 migrations; 현재 main의 마지막은 **000017_custom_emoji_name_reuse**. 이전 프로필의 000018 표기는 부정확.
  - `server/internal/mail`은 main에 없음. 별도 internal/email과 혼동 금지; 메일 캠페인 성공 기록만으로 머지됐다고 보지 말 것.
  - `server/internal/pluginhost` → `rpcbridge`: 서버 플러그인; `webapp/src/plugins/runtime.ts` → registry.ts: 웹 확장.
  - `server/internal/ws`: 실제 hub 및 audience resolver; `oidcauth`, `mcpserver`, `tracking`: 인증 연계·MCP·방문 추적.
  - `webapp/src/api`, `features`, `components`: API 클라이언트와 UI; `webapp/e2e`: Playwright.
  - `docs`: USER_GUIDE/ADMIN_GUIDE Markdown+PDF 정본·OpenAPI·사이트; `scripts`: 검증·배포·캡처.
- 빌드·테스트: `server/`에서 `go test ./...`, `go vet ./...`; DB 포함은 테스트 DSN을 MOYRO_TEST_POSTGRES_DSN에 설정 후 `go test -race -p 1 ./...`(수 분). `webapp/`: `npm ci`, `npm test`, `npm run typecheck`, `npm run build`. 루트: `bash scripts/check-source-sizes.sh`, `node scripts/verify-pages.mjs`. 브라우저 전체 검증/이미지 빌드는 비용 큼.
- 이번 정찰 검증: `go test -count=1 ./internal/sidebar ./internal/httpapi`와 소스 크기 검사 통과. DSN 미설정으로 DB 테스트 skip; 웹·전체 Go·실제 DB 검증 미실행.
- 관례: 최근 커밋은 영어 feat:/fix:/test:/docs:/release:. writeError의 기존 오류 ID·API 모양 보존. 컬렉션 본문은 decodeCollectionBody/tooManyBatchItems. 설정은 관리자 저장 JSON과 네 가지 부트스트랩 환경변수. migrations baseline 수정 금지.
- 위험 구역: principal/auth/oidcauth/native_mcp_oauth, store/migrations, .github/workflows; ws 재연결·허브 단일 소유, 플러그인 훅 순서 결정성. generated JS/dist/node_modules 편집 금지.
- 자주 깨지는 곳: preferences/reminders/presence 옛 auto 브랜치가 로컬에 존재(반려 여부 미확인); auth/membership 오류 삼킴; 서비스 오류를 일괄 400/404 처리; 서로 다른 응답·이벤트 경로가 같은 값을 다르게 전송.
- 검증 함정: CI는 PostgreSQL 15/16 전체 DB 테스트와 PG16 플러그인 fixture 검사. 로컬 DSN 없으면 DB 테스트가 skip되므로 초록만으로 통합 통과 주장 금지. -p 1 유지. 테스트 DB는 일회용 전용 사용; 현재 55432는 다른 프로젝트 사용 중.
- 검증 함정: 일부 httpapi 테스트는 newOperationsTestDB로 임의 스키마 격리·정리. CI는 별도 실제 플러그인 archive 변수도 제공하며 미제공 시 관련 검증 공백이 생김.
- 검증 함정: web tsconfig.node.json은 e2e도 검사. 과거 @types/node 유입에 따른 useDraft.test.tsx Timeout/number 오류는 Go 변경과 무관했던 사례. Windows npm은 CLAUDE.md의 절대 경로 사용.
- 최신 개선: UpdateMany는 일괄 카테고리 갱신을 단일 tx로 처리; getSidebarCategory는 writeSidebarError로 404/500 분리 완료. 재정렬 핸들러는 아직 입력 배열을 응답·이벤트에 그대로 실음.
