- 과제: `USER_GUIDE.md` 의 `.md`·`.txt` 표 한 칸에 쌓인 마크다운 규칙을 별도 절로 빼고, 빠진 규칙(펜스 코드 블록)을 채우기 (가치 3 / 위험 1 / 작업량 S)
- 왜: `docs/USER_GUIDE.md:276` 의 `| .md · .txt |` 한 칸이 다섯 회차에 걸쳐 여섯 규칙·약 560자가 되어 2열 표 안에서 읽을 수 없다(열어서 확인). 게다가 실제로 도는 규칙 하나가 가이드에 아예 없다 — 펜스 코드 블록(``` / ~~~)은 슬라이드로 가져오지 않고 "코드 블록 N개(M줄)는 가져오지 않았습니다" 경고를 내는데(`server/internal/docs/prose.go:375~379`), `docs/USER_GUIDE.md` 전체에 "코드 블록" 이라는 말이 한 번도 없다(Grep 확인). 규칙을 한 절로 모으면 사용자가 읽을 수 있고, 다음 회차들이 표 칸을 또 늘리지 않고 그 절에 한 줄을 더하면 된다.

- 수용 기준:
  1) `docs/USER_GUIDE.md:276` 의 `.md` · `.txt` 칸이 다른 칸들과 비슷한 한 문장(100자 안쪽)으로 줄어들고, 규칙 설명이 아니라 새 절로 가는 링크만 남는다. **표에 규칙을 남겨 두지 말 것** — 두 군데에 같은 규칙을 적으면 정본이 둘이 되고 다음 회차가 한쪽만 고친다.
  2) 새 `###` 절(제안: `### 마크다운·텍스트 파일을 읽는 규칙`, `docs/USER_GUIDE.md:280` 뒤·`### 회사 소개처럼…`(282) 앞)이 지금 코드가 실제로 하는 규칙을 빠짐없이 적는다. 각 항목을 아래 "코드에서 확인된 규칙" 과 대조해 쓰고, **코드에서 확인하지 못한 규칙은 쓰지 말 것**(예: setext `---` h2·들여쓰기 코드 블록·`\|`·`- > 인용`·인라인 `**굵게**` 는 아직 처리하지 않는다 — "안 되는 것" 으로 쓸지는 구현자 판단, 쓰려면 코드로 확인하고 쓸 것).
  3) 표 칸의 링크가 실제로 그 절로 간다(같은 문서 안 앵커). 한국어 제목의 GitHub 앵커 규칙(소문자화·공백→`-`·`·` 같은 기호 제거)을 모르겠으면 제목을 기호 없는 말로 정해 앵커를 단순하게 만들 것 — 예: `### 마크다운과 텍스트 파일을 읽는 규칙` → `(#마크다운과-텍스트-파일을-읽는-규칙)`.
  4) `cd server && go test -count=1 ./internal/docs` 가 통과한다. 특히 `told_test.go:16 TestEveryFormatReadIsAFormatSaid` 는 `docs/USER_GUIDE.md` 안에 `` `.md` ``·`` `.txt` `` 같은 코드 표시 확장자 문자열이 **그대로 남아 있어야** 통과한다(이 테스트가 이 과제의 유일한 자동 가드다 — 표 칸을 줄이면서 `` `.md` · `.txt` `` 문자열을 지우면 red).
  5) 코드는 한 줄도 바뀌지 않는다(`git diff --stat` 에 `server/` 가 없다).

- 코드에서 확인된 규칙(이번 정찰이 `prose.go` 를 열어 확인한 것만. 절에 쓸 내용의 근거):
  - `#` 제목 → 슬라이드, `-`/`*`/`•` 등 목록 → 요점, 선두 `|` 로 시작하는 파이프 표 → 표(`prose.go:220`, `257~292`, `listmarker.go:13`).
  - 제목은 `#` 1~6개이고 그 뒤가 공백/탭이거나 줄 끝일 때만(`atxHeading`) — `#출시`·`#1 우선순위…` 는 요점으로 남는다.
  - 닫아 쓴 `## 분기 요약 ##` 는 뒤 `#` 을 떼지만 `# C# 도입` 은 글자로 남는다(`atxHeading` 의 `TrimRight` + 앞 글자가 공백일 때만).
  - 수평선 `---`·`***`·`___`·`- - -` 는 슬라이드에 남지 않고 경고도 없다(`isThematicBreak`, `prose.go:270~280`).
  - 맨 위 `---` … `---` YAML 머리말은 슬라이드로 만들지 않는다(`frontMatterLines`, `prose.go:309`). 짝이 안 맞거나 첫 줄이 `키:` 모양이 아니면 아무것도 건너뛰지 않는다.
  - 인용 `> 문장` 은 `>` 를 떼고 내용만 남으며, 인용 안의 `#` 제목·목록·표 행은 그 블록으로 읽힌다(`withoutQuoteMarker` + 재귀, `prose.go:225~256`). `>` 만 있는 줄은 빈 줄이다.
  - **가이드에 없던 것**: ``` 또는 ~~~ 로 감싼 코드 블록은 가져오지 않고, 몇 블록 몇 줄을 못 가져왔는지 경고로 알려 준다(`prose.go:300~301`, `375~379`). 닫히지 않은 ``` 한 줄은 문서를 삼키지 않고 그 뒤를 평소대로 읽는다(`prose.go:340~357`) — 이 "삼키지 않는다" 까지 쓸지는 구현자 판단(사용자가 알아야 할 것은 앞의 경고 쪽이다).
  - `.markdown` 확장자도 같은 규칙으로 읽힌다(`docs.go:81` — 프로필 기록, 이번 정찰 미확인).
