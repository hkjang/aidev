**로그인 화면이 "이쪽이 끝내지 못한 시도"를 틀린 비밀번호와 같은 붉은 줄로 보이고 있었습니다.** `POST /api/v1/auth/login`의 평범한 `500 internal_error`(저장소나 디렉터리가 답하지 않음)와 연결 실패(status 0 — 재시작 중이거나 호스트에 닿지 않음)는 이 서비스가 시도를 **끝내지 못한** 것입니다: 계정에는 아무것도 기록되지 않았고, 주소창의 request token도 소진되지 않았습니다. 그런데 화면은 이 둘을 틀린 비밀번호와 같은 붉은 줄 한 줄로 보였습니다 — "안 됐다"로만 읽히고 언제·어디서 다시 할지 말하지 않아, 검사된 적도 없는 비밀번호를 다시 치거나 RP로 돌아가 새 request token을 받아 와서는 같은 장애를 다시 만나게 했습니다. 500이 실어 보낸 Trace ID도 버리고 있었습니다: 가이드는 "계속되면 관리자에게 알리세요"라고 하는데, 전할 값이 없는 유일한 로그인 답이었습니다. v0.9.85가 두 500을 code로 갈라 놓았으니 이번에는 남은 쪽에 제 지시를 줍니다.

### 수정

- **이쪽이 끝내지 못한 시도에는 노란 알림과 다음에 할 일을 보입니다.** challenge를 읽지 못했을 때의 500이 이미 갖고 있던 알림과 대칭으로, 「계정에는 아무것도 기록되지 않았고 로그인 요청도 그대로 남아 있으니, 연결한 서비스에서 다시 시작하지 말고 잠시 후 이 화면에서 다시 시도하세요」를 띄우고 **폼은 그대로 둡니다** — 같은 폼이 출구이기 때문입니다. 500이 Trace ID를 실어 왔으면 함께 보입니다(연결 실패는 이쪽에 닿지 않은 요청이라 Trace ID가 없습니다).
- **판정은 `status === 0 || status >= 500`에서 소진된 요청의 답(`authorization_code_failed` 등)을 뺀 것입니다.** 429는 500 아래라 자체 카운트다운이 그대로이고, 리버스 프록시의 502/503도 같은 부류로 들어옵니다 — `ErrorAlert`가 status 0·429·5xx만 재시도 대상으로 보는 기준과 같습니다. `account_mismatch`·소진된 요청·잠금 경고의 알림은 손대지 않았고, `authorization_code_failed`는 반대 지시(RP로 돌아가기)를 그대로 유지합니다.
- **request token 없는 콘솔 로그인은 "연결한 서비스" 문장을 뺀 같은 알림입니다** — 잘못 갈 곳이 없기 때문입니다.
- 백엔드는 달라지지 않았습니다.
- 사용자 가이드 「막혔을 때」의 `로그인을 처리하지 못했습니다.` 행에 `서버에 연결하지 못했습니다.`를 합치고 "애플리케이션으로 돌아가지 마세요 · `trace:` 값을 전달(연결 실패에는 없음)"을 적었습니다. `docs/operations.md`의 login POST 답 표 첫 행에 status 0을 더하고, 화면이 그 행에 무엇을 띄우는지와 status 0은 이쪽에 닿지 않아 Trace ID도 로그도 없다는 것(재시작·리버스 프록시·네트워크를 볼 것)을 적었습니다.

### 확인

- 페이지 테스트 셋 — RP 요청의 `500 internal_error`(trace 있음), RP 요청의 status 0(fetch가 `TypeError`를 던짐, trace 없음), 콘솔 로그인의 500 — 각각에 안내 문구·"기록되지 않았다" 문구·RP 문장의 유무·메시지가 한 번만 보임(붉은 줄 중복 없음)·trace 유무·RP 복귀 안내 없음·잠금 경고 없음·폼 활성을 고정하고, **수정 전 페이지에서 셋 다 실제로 실패하는 것을 확인**했습니다.

### Upgrade notes

달라지는 곳은 로그인 화면 하나입니다: 평범한 `500 internal_error`와 연결 실패(status 0)에 붉은 줄 대신 **노란 안내와 다음에 할 일**을 보이고, 500의 `trace:` 값을 함께 보입니다. 응답도, 상태 코드도, 저장되는 데이터도 전과 같고 **마이그레이션도 설정 변경도 없습니다.** 지원 창구에는 「로그인을 처리하지 못했습니다」·「서버에 연결하지 못했습니다」를 본 사용자를 **애플리케이션으로 돌려보내지 말고** 잠시 후 같은 화면에서 다시 시도하게 하고, 함께 보이는 `trace:` 값이 있으면 받아 두라고 알리시면 됩니다(`docs/operations.md`). 되돌릴 때 이전 이미지도 그대로 동작합니다.
