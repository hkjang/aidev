fix: release the MCP SSO settings outage reporting fix for v0.2.31

MCP SSO(OAuth)를 켜는 설정 저장이 OIDC 설정 읽기 실패를 "MCP SSO(OAuth)를 켜려면
Keycloak OIDC 연결이 켜져 있고 Issuer URL이 있어야 합니다"로 보고하던 문제를 고친 PR
#53 을 릴리즈합니다. `updateSettings`(resource_handlers.go:751)가 `mcp.oauth.enabled`
를 켜는 요청에서 저장 시점 검사 `requireOIDCForMCPOAuth` 의 **모든** 오류를 400
`mcp_oauth_requires_oidc` + `err.Error()` 로 내보냈습니다. 그 헬퍼(mcp_oauth.go:390)는
`ErrNotFound` 가 아닌 저장소 오류를 원문 그대로 올리므로, PostgreSQL 이 흔들리는 순간
관리자는 이미 올바른 설정 화면으로 되돌려 보내지고 **pgx 원문(DSN·SQLSTATE)이 응답
body 의 message 로 그대로 나갔습니다** — 이 저장소가 `storeError`·
`assertNoDriverDetail` 로 곳곳에서 막아 둔 바로 그 누출입니다. 같은 PR 은 패키지 수준
sentinel `errMCPOAuthNeedsOIDC` 로 설정 거절 하나만 표시하고, 핸들러가 `errors.Is` 로
나머지를 `s.storeError` 로 보내 500 `internal_error` + 마스킹된 문구와 `error`·
`request_id` 를 가진 ERROR 한 줄이 남게 했습니다(프로덕션 파일 2개: sentinel 1개 +
분기 1개 + seam 교체 1줄). 거절 동작은 바이트 단위로 그대로입니다. OIDC 설정을 한 번도
저장하지 않은 경우(`store.ErrNotFound`), OIDC 를 끈 경우, 켰지만 Issuer URL 이 빈 경우는
모두 여전히 400 `mcp_oauth_requires_oidc` 와 기존 한국어 문구이며, `requireOIDCForMCPOAuth`
의 "같은 요청에 담겨 온 값 우선" 판정과 `Active()`/`InactiveReason()`, MCP 리소스 식별자
결정 순서, `WWW-Authenticate` 범위는 한 글자도 바뀌지 않았습니다. 저장 시점 검사가
저장소를 직접 부르던 한 줄(`s.store.OIDCConfig`)은 같은 패키지의 기존 설정 로더 seam
`s.loadOIDCConfig` 로 바꿨습니다 — nil-폴백이 같은 저장소 호출로 접히므로 프로덕션
동작은 동일하고, 이것이 없으면 store 가 nil 인 하네스에서 패닉이라 이 경로를 DB 없이
증명할 수 없었습니다. 같은 PR 은 실제 라우트 래퍼
`requestID(requireRoles(updateSettings,"admin"))` 왕복으로 장애 1개·거절 3개, 네 경우의
상태 코드와 code 를 고정하는 회귀 테스트를 추가했고, 500 케이스는 본문에 DSN·호스트명·
`SQLSTATE` 가 없고 ERROR 가 정확히 한 줄 남는 것까지 못박았습니다.

기존 패치 릴리스와 같은 방식으로 버전 파일, 문서 프로파일과 CHANGELOG 를 v0.2.31 로
갱신했습니다. 캡처 출처는 실제로 찍은 v0.2.9 를 유지합니다. 두 가이드 PDF 는 v0.2.30 과
같은 이유로 표지가 `v0.2.18` 인 채로 남았습니다. 지금까지 쓰던 변환기(Markdown 표지
템플릿 + HeadlessChrome 인쇄)가 저장소에 없어 같은 판형으로 다시 구울 수 없었고, 다른
템플릿으로 바꿔 굽는 것은 릴리스 절차 밖의 변경이라 기존 파일을 그대로 두고 CHANGELOG
