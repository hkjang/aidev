- 자주 깨지는 곳:
  - **sqlsafe 의 PostgreSQL 별칭/CTE 컬럼 목록 면제**: 토큰 모양만 보고 면제하면 fail-open 이 된다 — 440aa9f(`)` 뒤), 89b3e76(`=(` 인접), e1af783(점 표기), 7cda7f5(WITH ORDINALITY), 433a183(비수식 별칭) 다섯 번 같은 뿌리로 고쳤다. 새 면제는 `fromItemContext`(894)로 FROM 문맥을 요구하고 판단 불가 시 fail-closed 여야 한다. `postgresAliasColumnList` 의 **`AS` 분기(~772)는 지금도 FROM 문맥 없이 무조건 면제**한다(악용 질의 미확인으로 방치 중).
  - **성능(선재)**: `appendUnique`(192) 사유 누적이 **서로 다른 사유 개수**에 대해 quadratic — 2026-10-06 실측: 서로 다른 이름 2000/4000/8000/16000개 = pg 8/20/89/233ms·oracle 5/21/87/228ms, **같은 이름 16000번은(바이트가 더 큰데도) 14ms**. 요청 한도 그대로 1,048,562B(이름 88,304개) = **pg 10.93s / oracle 10.95s**, 사유 7,318,122바이트. 무한 카디널리티 자리는 pg 473(함수)·499(cast)·444(문자열 상수)와 oracle 1096(함수), 그리고 `AnalyzeDialect` 병합 루프 131-133 — **두 계층이 각각 절반씩**(16000개 합 250ms = 118ms + 128ms). `fromItemContext`·`postgresCTEColumnList` 의 WITH 추적은 이미 memo 로 닫혀 있다(5d8a1b5).
  - **미머지 커밋이 반복된다**: a8f0775(pool.Close 순서), 12223b0(`-count=1` + ci_workflow_test.go), 3bf8799(Oracle WITH CTE 면제) 가 main 에 없다 — 3bf8799 는 이번 회차에 `oracleReadOnlyViolations` 가 `postgresCTEColumnList` 를 호출하지 않음으로 재확인. 과제서를 쓸 때 **심볼·파일 존재를 base 에서 직접 확인**할 것.
  - 로그인 뒤 목적지를 `LoginPage.tsx` 와 `App.tsx PublicOnly` 두 경로가 각각 계산한다 — 한쪽만 고치면 react-router 7 `startTransition` 커밋 순서로 다른 쪽이 덮어쓴다. PR #18 이 이 영역에서 닫혔다.
  - 통합 테스트 픽스처 정리: `defer pool.Close()` 가 `t.Cleanup(DELETE…)` 보다 먼저 실행돼 정리가 조용히 죽는다(직전 집계 53곳/31파일; 2026-10-06 미재확인).
  - `intelligenceapi/credential_race_integration_test.go:236` 이 **같은 폐기 DB 2회차 실행에서만** `qurio_secrets_check`(23514) 위반으로 깨진다(1회차·단독·DB 재생성 후 통과). CI 는 매번 새 DB 1회라 녹색.
  - `web/src/components/AdminAskOriginalLauncher.test.tsx:110` 이 **전체 스위트 실행에서만** ~1/3 확률로 깨진다(role "option" 미발견). 단독 실행·CPU 부하·응답 지연으로는 재현되지 않는다.
- 검증 함정:
  - CI(`ci.yml`)·release 는 PostgreSQL 17 에 `POSTGRES_DSN`·`QURIO_INTEGRATION_DSN`·`QURIO_TEST_POSTGRES_DSN` **세 env 를 같은 폐기 DB** 로 지정하고 bootstrap 후 `go test -race -p=1 -tags=integration ./...` 를 돌린다. 한 테스트가 남긴 행이 다른 테스트에 보인다.
  - **그 통합 실행에 `-count=1` 이 없다**(ci.yml:63, release.yml:99). `actions/setup-go` 캐시가 GOCACHE(테스트 결과 캐시)를 보존하므로 게이트가 DB 를 검증하지 않고 녹색이 될 수 있다. 같은 잡의 표적 `go test` 4곳은 모두 `-count=1` 이 있다.
  - **CI 는 `make lint` 를 호출하지 않는다** — Makefile 에 검사를 더해도 CI 검사가 되지는 않는다. `ci.yml` 의 test 잡에는 `timeout-minutes` 도 없다(기본 360분).
  - `internal/domain/dbexec` 만 `QURIO_TEST_POSTGRES_DSN` 전용(미설정 Skip, 연결 오류 Fatal). 나머지는 `POSTGRES_DSN`/기본 55432 를 읽고 연결 오류를 Skip 한다(세 관례 공존).
  - dbexec 픽스처는 `public` 고정명과 pg_catalog 함수·캐스트를 CREATE/DROP 하므로 전용 폐기 DB·`-p=1` 직렬 실행이 필요하다.
  - 로컬 포트 55432/55433/55439/55482/55492/55502/55517/55601 이 과거 점유된 사례가 있다 — 비어 있는 포트를 고르고 컨테이너는 반드시 제거.
  - release 는 Oracle 실서비스도 기동(`TestOracleLive`), 일반 CI 는 PostgreSQL 만. **이 환경에는 Oracle 인스턴스가 없어 Oracle 은 게이트 판정 수준까지만 증명 가능하다.**
  - sqlsafe 변경은 단위 테스트만으로 부족하다 — base 파일과 수정본에서 현실 질의 70건+ × 2방언 판정을 덤프해 diff 하고 "새로 막히는 질의 0건"·"판정 불변" 을 보이는 것이 이 저장소의 확립된 증명 방식이다.
  - SQL 입력 상한은 `1<<20`: `runtimeapi/sql.go:50`·`124`·`274`, `domain/mcpserver/server.go:274`. 성능 과제는 이 한도에서 재는 것이 외삽보다 낫다.
  - 이 환경의 bash 는 heredoc(`<<EOF`)과 일부 복합 명령을 거부한다 — 파일 생성은 Write 도구로 할 것.
