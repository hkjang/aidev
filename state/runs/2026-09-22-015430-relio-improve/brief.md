- 과제: 가이드 캡처의 Chrome 경로를 실제 실행 가능 파일로 선택하고 API 호출 전에 검사하기 (가치 2 / 위험 1 / 작업량 S)
- 왜: `scripts/guide/screenshots.mjs:46`의 `.find(Boolean)`은 세 경로가 모두 문자열이므로 Chrome 설치 여부와 무관하게 `/usr/bin/google-chrome`만 고르며, `main()`은 로그인과 데모 데이터 생성 뒤 `capture()`에서야 브라우저를 실행한다. 실행 가능한 후보를 순서대로 선택하고 실패를 API 호출 전에 알리면 Chromium만 설치된 환경의 캡처가 가능해지고 브라우저 부재 상태에서 불필요한 데이터·설정 변경을 피한다.
- 수용 기준: 1) `RELIO_GUIDE_CHROME` 지정 시 해당 경로를 우선 검사하고, 잘못된 명시 경로는 자동 폴백 없이 경로와 설정 변수명을 포함하는 오류로 종료한다(자격증명 출력 금지). 미지정이면 기존 세 후보 순서를 유지하되 일반 파일이며 실행 권한이 있는 첫 후보를 사용하고, 아무 후보도 없으면 같은 안내로 종료한다. 2) 실제 CLI에서 경로 검사 실패는 `login()`·`seed()`·`withRateLimitLifted()` 이전에 발생하여 로컬 HTTP 관찰 서버가 받은 요청이 0건이어야 한다. 기존 disposable 확인과 필수 환경 변수 검증은 유지한다. 3) Node 내장 테스트와 실제 임시 파일/권한을 사용해 첫 후보 없음→둘째 선택, 비실행 파일·디렉터리 건너뜀, 명시 경로 우선, 잘못된 명시 경로 및 후보 전부 없음 실패를 증명한다. 별도 자식 프로세스로 실제 screenshots.mjs를 실행하고 유효한 필수 환경값·존재하지 않는 RELIO_GUIDE_CHROME·실제 HTTP 서버를 사용해 비정상 종료와 요청 0건을 증명한다. fs/puppeteer/fetch 대역이나 소스 문자열 검사는 증거로 쓰지 않는다. 4) 헤더의 “never changes a global setting / nothing to restore”를 실제 일시적 rate limit 변경·finally 복원 동작과 맞추고, 관리자 가이드 실행 예에 선택적 RELIO_GUIDE_CHROME과 조기 오류 안내를 적는다.
- 건드릴 파일: `scripts/guide/screenshots.mjs`: chromePath 초기화, main, capture — 경로 선택을 main의 첫 API 호출 전에 완료하고 capture의 executablePath에 전달; 헤더 주석 정정. `scripts/guide/browser-path.mjs`(신규 제안): 실제 fs 검사만 하는 작은 resolveChromePath 함수, 테스트용 후보 인자는 내부 함수 인자만 허용(새 운영 환경 변수 불필요). `scripts/guide/browser-path.test.mjs`(신규 제안): 실제 임시 파일·실제 CLI/HTTP 서버 검증. `scripts/guide/package.json`: 기존 screenshots 명령 유지, Node 내장 test 명령 추가. `docs/ADMIN_GUIDE.md`: 435행 이후 캡처 실행 안내에 경로 선택 규칙 보완.
- 검증 명령: 현재 존재하며 정찰에서 통과한 명령은 `node --check scripts/guide/screenshots.mjs`, `npm --prefix web test`(11건), `go test ./...`이다. 구현 후 `npm --prefix scripts/guide ci --no-audit --no-fund`, `node --test scripts/guide/browser-path.test.mjs`(위 신규 파일), `node --check scripts/guide/screenshots.mjs`, `git diff --check`를 실행한다. 새 test 스크립트를 추가하면 `npm --prefix scripts/guide test`도 같은 테스트를 실행하도록 한다. 가이드 의존성 설치·실제 Chrome 캡처는 정찰에서 미실시; 경로가 실행 가능해도 라이브러리 부족 등 launch 성공까지 보장하지는 않는다.
- 위험과 피할 것: auth, migrations, .github/workflows 및 앱 API는 변경하지 않는다. 기존 withRateLimitLifted의 변경 전 값 조회와 finally 복원을 그대로 보존하고 새로운 전역 설정 변경을 넣지 않는다. 가이드 전체 캡처/PDF 재생성, 브라우저 자동 다운로드, PATH 탐색 확장, 공용 테스트 프레임워크 도입은 제외한다. 명시 경로 실패를 다른 브라우저로 숨기지 않는다. 테스트 HTTP 서버와 임시 파일은 반드시 정리한다. 이 환경에는 첫 Chrome 후보가 실제 존재하므로 “현재 머신에서 캡처 실패 재현”은 미확인이다; 첫 후보가 없을 때 잘못 선택되는 것은 식 자체에서 확인했으며 임시 파일 테스트로 증명할 것.
- 차선 후보: Makefile의 `make test`에 기존 프런트 결정 테스트 실행 포함 — 현재 go test/go vet/npm ci/typecheck만 실행하고 `npm test` 11건은 누락한다. CI/workflows는 변경하지 않고 typecheck 뒤 `npm test`를 실행하도록 하며, `make test` 출력에서 실제 Node 11건 실행을 확인한다.

구현 순서·추정: 선택 함수/실제 파일 테스트 10분 → CLI 연결 및 실제 HTTP 무요청 회귀 테스트 12분 → 주석·가이드 5분 → 검증 8분, 예비 10분(총 45분). 의존성 설치가 막히면 설치 성공으로 보고하지 말고 차선의 실행 가능성을 판단한다. 경로 확인만으로 Chrome 완전 기동 검증을 주장하지 않는다.
대안 판단: 감사 rows.Err 및 metadata 검색은 실제 PostgreSQL 재현 준비가 필요하고, 프록시/페이징은 계약·권한 영향이 커 이번 저위험 회차에서 제외했다. 이미 진행한 JSON 413, 인증, MCP OAuth, gofmt CI 변경은 기반에 없더라도 재선택하지 않았다.
