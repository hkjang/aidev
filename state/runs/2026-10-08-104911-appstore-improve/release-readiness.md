# AppStore v2.11.17 릴리즈 준비 기록

- 적용 스킬: marketing:product-launch, technology:release-and-deployment. Skill 호출 도구가 없어 headcount의 두 SKILL.md 및 references/sources.md 원문을 읽었다. 이번 작업은 앱 마켓 등록, 광고 주장, 라이선스 심사가 아니므로 해당 외부 권위 자료를 적용할 사안은 없다.
- 등급: Tier 3 개선. 대상은 앱을 등록하거나 수정하는 기존 소유자이며, 저장 결과와 고정 완료 예고가 어긋나던 혼란을 줄인다. 새 고객군·요금·패키지·별도 홍보 캠페인은 없다. 외부 공지는 기존 릴리즈 노트로 한정한다.
- 날짜: 2026-10-08 머지 후 검증이 모두 통과한 로컬 소스를 준비한다. 날짜보다 테스트, 버전 일치, 문서 및 PDF 완성을 우선한다.
- 지원 안내: 완료는 저장과 첨부 문서 적용 완료를 뜻한다. 현재 상태가 초안이면 내 앱에서 상태와 다음 단계를 확인한다. 완료 화면이 게시나 보안 심의 승인 성공을 보장하지 않는다. 저장·문서 적용 실패 시 성공 안내를 표시하지 않는 것을 테스트한다. 실제 서비스의 승인 정책과 문서 업로드 재시도 구조는 이번 변경 범위 밖이다.
- 준비 확인: 사용자 가이드에 현재 상태와 내 앱 이동을 설명한다. 무인 세션에서 외부인의 첫 사용 검증과 영업·지원 인력 브리핑은 수행할 수 없으며 수행했다고 주장하지 않는다. 실제 라우터·번들의 desktop/mobile E2E로 첫 등록 경로를 확인한다.
- 릴리즈 경계: 현재 detached HEAD에서 기존 형식의 커밋과 annotated tag만 작성한다. 원격 배포·공지·푸시는 러너/기존 CI 책임이다. 태그 워크플로가 Linux/AMD64 이미지를 한 번 만들고 archive 검증 및 동일 이미지의 offline smoke 후 tar.gz 하나와 SHA-256 포함 영문 GitHub Release를 게시한다. 따라서 로컬 assets=[] 및 github_release=false이다.
- 배포 시 중단 기준: 기존 CI의 build/load/offline smoke 중 하나라도 실패하면 게시를 중단한다. 배포 후 저장 실패 또는 서버 저장 응답과 완료 상태 불일치가 1건이라도 재현되면 배포 담당 운영자가 확산을 중단하고 이전 v2.11.16 이미지로 롤백한다. schema 변경은 없다. 실제 운영 배포와 운영 지표 관찰은 이 세션에서 실행하지 않는다.
- 후속 확인 제안: 배포 담당 운영자가 게시 후 7일 동안 등록·수정 관련 문의와 처음 10회의 성공 저장에서 완료 상태/목록 상태 일치 여부를 확인한다. 목표는 확인한 10회 모두 일치 및 잘못된 즉시 게시 안내 0건이다. 이는 사전 판단 기준이며 실측 결과가 아니다. 외부 메시지나 일정을 생성하지 않았다.
