# Momento v0.34.61 — 「JSON Schema」 칸이 저장 전에 구문 오류를 알려 줍니다

콘솔 **관리 → Event Schema**에서 이벤트 속성 규격을 작성하는 관리자를 위한 개선입니다. v0.34.57이 저장 실패 뒤의 안내를 한국어로 바꿨다면, 이번에는 같은 안내를 저장 버튼을 누르기 전에 칸 아래에서 읽을 수 있습니다.

## 저장을 눌러야 깨진 JSON이라는 것을 알았습니다

「JSON Schema」는 여러 줄을 직접 입력하는 칸인데, 「저장」 버튼은 사이트와 이벤트 이름이 있는지만 확인했습니다. `{"properties": }`처럼 구문이 깨진 값을 넣어도 버튼은 열려 있었고, 누른 뒤 뮤테이션 안의 `JSON.parse(form.schemaText)`가 실패해야 안내가 나왔습니다. 이때는 요청 자체가 만들어지지 않아 서버로 보내지지도 않았습니다.

이제 입력 중에 같은 `JSON.parse`로 구문을 확인합니다. 잘못된 JSON이면 칸을 오류로 표시하고 「저장」을 비활성화하며, 아래 문장을 바로 보여 줍니다.

> 「JSON Schema」 칸의 내용이 올바른 JSON 이 아닙니다. 중괄호·대괄호의 짝과 쉼표 위치를 확인하고, 키와 문자열 값은 겹따옴표로 감싸세요. 규격을 비워 둘 때는 {} 로 적습니다.

새 순수 모듈 `web/src/pages/schemaTextRule.ts`의 `JSON_SCHEMA_RULE`을 칸 아래 안내와 `describeEventDefinitionError`의 저장 실패 Alert이 함께 읽습니다. 오류 안내의 문구는 유지하면서 보여 주는 시점을 앞당겼습니다.

## 빈 칸과 올바른 JSON은 이렇게 보입니다

| 입력 | 칸 아래 안내와 저장 상태 |
|---|---|
| `{"properties": }`, `{"a":1,}` 등 깨진 JSON | 한국어 구문 안내, 오류 표시, 저장 비활성화 |
| 빈 칸 또는 공백만 있는 값 | 규격이 비었다는 안내와 `{}` 사용 안내, 오류 색 없이 저장 비활성화 |
| `{"properties": {}}`, `{}` 등 올바른 JSON | 평상시 설명 표시, 사이트·이벤트 이름 조건을 충족하면 저장 가능 |

평상시 설명은 「속성 규격을 JSON 으로 적습니다. 비워 둘 때는 {} 로 적으세요.」입니다. 잘못된 입력을 고치면 구문 때문에 닫혀 있던 저장 버튼이 다시 열립니다.

검사 대상은 **JSON 구문**입니다. `null`·배열·문자열·숫자도 `JSON.parse`가 받아들이면 이번 검사에서는 통과합니다. 저장 요청을 서버가 받아 줄지는 기존 서버의 타입·규격 검증이 결정합니다. 예를 들어 배열은 구문상 올바르더라도 서버에서 거절될 수 있으므로, 이 안내가 모든 JSON Schema의 유효성을 보장하는 것은 아닙니다.

## Go 의존성 갱신도 포함합니다

`golang.org/x/text`를 v0.39.0에서 v0.41.0으로 올려 `GO-2026-6629`로 실패하던 `govulncheck`를 해결한 변경을 포함합니다. `golang.org/x/sync`도 v0.21.0에서 v0.22.0으로 갱신되었습니다.

## 확인

- 콘솔: `npm ci`·`npm audit`(취약점 0건)·`npm run lint`·테스트 **259건**·프로덕션 빌드 통과. JSON 구문 판정과 안내 상수 공유 회귀 테스트 11건이 추가되었습니다(248 → 259건). 빌드의 500 kB 초과 청크 경고는 남아 있습니다.
- SDK: `npm ci`·`npm audit`(취약점 0건)·typecheck·테스트 **29건**·build 통과.
- Go: 로컬 PostgreSQL 17을 연결한 `go test -race -count=1 ./cmd/... ./internal/...`와 `go vet ./cmd/... ./internal/...` 통과. 서비스·콘솔·SDK 버전 및 Compose 이미지 이름 일치 검사도 포함합니다. 별도 부하 테스트는 `MOMENTO_LOAD_POSTGRES_DSN`을 지정하지 않아 실행하지 않았습니다.
- `govulncheck`: 코드가 호출하는 취약점 0건. 가져오는 패키지 4건·필요 모듈 20건의 비호출 취약점은 별도로 보고되었습니다.
- 기존 Dockerfile의 프로덕션 이미지 빌드 통과. 배포용 아카이브의 로드·기동·버전·콘솔·로그인 검사는 태그 푸시 후 기존 릴리스 워크플로가 수행합니다.

## 범위와 배포

콘솔 동작 변경은 `schemaTextRule.ts`, 이를 사용하는 `AdminPage.tsx`의 Event Schema 카드, 안내 상수를 공유하는 `adminErrors.ts`입니다. 서버·API 동작과 요청 본문, 데이터베이스 마이그레이션은 바뀌지 않습니다. 이벤트 규격을 편집하지 않는 사용자는 새로 할 일이 없습니다.

이번 개선은 Tier 3로 릴리스 노트에 안내합니다. 기존과 같이 태그 푸시 후 GitHub Actions가 `momento:v0.34.61`을 빌드하고, 오프라인 아카이브 `momento-v0.34.61.tar.gz`와 `.sha256`을 로드·기동 검증한 뒤 Release에 첨부합니다. 설치 절차는 `docs/OFFLINE.md`를 따릅니다.

배포 담당자는 확대 적용 전에 Event Schema 카드에서 깨진 JSON과 빈 칸이 저장을 막는지, `{}`로 고치면 안내가 평상시 설명으로 돌아오고 저장되는지 확인합니다. 첫 적용 후 24시간 동안 구문 안내 관련 문의와 정상 규격의 저장 실패 여부를 확인하며, 정상 규격 저장 실패가 1건이라도 재현되면 확대 적용을 중단하고 원인을 확인합니다. 이번 변경에 따른 회귀이면 배포 담당자가 이전 `momento:v0.34.60` 이미지로 되돌립니다. 이 세션에서는 실제 배포, 운영 환경 확인, 별도 사용자의 첫 사용 검증을 수행하지 않습니다.
