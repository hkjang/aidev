  - internal/api: 라우팅·핸들러·SPA·리미터·설정 검증. helpers.go(decodeJSON 2MiB 제한/queryInt/queryIntOrReject/pageQuery/listSort), auth_handlers.go(login·me·meUpdate `PATCH /api/v1/auth/me`·changePassword), mail_handlers.go(발송 기록·시험 발송).
  - internal/mail: config.go(설정 파싱·Validate·`validAddress`/`ValidAddress` — '@' 위치와 공백·제어문자만 보는 느슨한 검사), mail.go(SMTP), message.go(이벤트별 Notification), service.go(Notify 배경 발송·SendNow).
  - internal/auth: 세션·OIDC·silent SSO. oidc.go:311이 claim의 name/email/department를 그대로 `store.UpsertOIDCUser`로 넘긴다. internal/secure: 비밀값 암호화.
  - internal/store: users.go(UpsertOIDCUser 185·189행, UpdateProfile 221행 — **users.email을 쓰는 곳은 이 둘뿐**, Seed는 email을 넣지 않는다), sort.go, search.go(GlobalSearch·searchPattern), store.go(pageBounds 195행), mail.go(MailSettings·UserEmails·UsersWithGlobalPermission·ListMailDeliveries·ExpiringAPIKeys).
  - migrations/: 기동 시 적용 SQL 001~014, advisory lock. `users.email text NOT NULL DEFAULT ''`(001:10).
  - internal/integration(SafeHTTPClient SSRF 방어), internal/collector(주기 수집·Hub 상태 전이 메일·만료 임박 키 안내).
  - web/src/api/client.ts, web/src/hooks/useList.ts, web/src/pages/(PersonalPage=개인 프로필·API 키, SettingsPage=메일 알림 카드). docs/USER_GUIDE.md·ADMIN_GUIDE.md(+PDF) 정본. openapi/openapi.yaml.
- 빌드·테스트: `make deps` → `make lint` → `make test` → `make build`. 프런트는 `npm --prefix web ci / run lint / test / run build`.
  - 통합: `export JUPIQ_INTEGRATION_TEST_DSN=…` 뒤 `make test-integration`(= `go test -count=1 -p=1 -run Integration ./internal/store ./internal/api`). DSN 없으면 make가 안내 후 exit 1.
  - 릴리스: `make release-check`(go mod verify·vet·govulncheck·test·DB 통합·스크린샷·npm ci/audit/lint/test/build). 수 분·네트워크 필요.
  - 오늘 실측: `go test -count=1 ./internal/api ./internal/store` = ok(api 0.046s, store 0.006s, DSN 없어 통합은 skip).
- 관례: 한국어 `type: 설명` 커밋. 주석도 한국어로 "왜"를 적는다. VERSION은 여러 파일 정합(scripts/check-version.sh). 설정 JSON은 settings, 비밀은 secrets 암호화. API 오류는 error.code/message/request_id(예: invalid_json·invalid_query·invalid_recipient).
- 위험 구역: internal/auth/, migrations/, .github/workflows/, 설정 검증·SafeHTTPClient(SSRF), 목록 쿼리의 dataAccessSQL/countAccessSQL(인자 번호를 밀면 권한이 샌다), 메일 발송 경로(자격증명 평문 금지 규칙이 mail.go:credentialsAllowed).
- 자주 깨지는 곳: openapi.yaml의 인용 누락(695591e), 가이드 MD/PDF·표지 버전 불일치, VERSION 다중 일치, Go mux 경로 충돌. 러너 예산 홀드는 코드 결함이 아님.
- 검증 함정:
  - DSN 없이 `go test ./...`는 통합이 전부 skip되므로 DB 관련 수정의 증거가 될 수 없다. `-v`로 SKIP 수를 반드시 확인.
  - 일부 통합 테스트는 비loopback IPv4가 없으면 skip(= 통과처럼 보임).
  - CI는 PostgreSQL 16, release 통합은 14, offline smoke 16.
  - `store.Seed`는 users.email을 넣지 않는다 — 수신자 관련 테스트는 주소를 명시적으로 채울 것.
  - 프런트 자원 수명은 실제 Response·ReadableStream으로 증명할 것(대역·소스 문자열 단언 금지).
  - 실제 Keycloak·실제 SMTP 릴레이 E2E는 계속 미검증(메일은 가짜 Sender와 단위 테스트만).
