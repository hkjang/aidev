# Invenqor Server·Agent v0.2.46 릴리즈 노트

릴리즈 일자: 2026-10-08
호환 Agent: v0.2.46 (Linux·Windows)

이번 릴리즈는 **Server 의존성 감사와 문서 사이트 빌드의 실패를 고칩니다.**
Server의 간접 의존성 `golang.org/x/text`를 `v0.40.0`에서 `v0.41.0`으로
갱신하고, 이전 릴리즈 노트의 SQL 예제가 GitHub Pages의 Liquid 구문으로
해석되지 않도록 고쳤습니다. API·데이터베이스 스키마·콘솔·Agent의 기능은
v0.2.45 소스와 같습니다.

저장소에는 v0.2.45 릴리즈 커밋이 있지만, 이번 작업에 제공된 GitHub Release
목록의 최신 공개 버전은 v0.2.44입니다. 버전을 되돌리거나 기존 릴리즈 커밋을
다시 쓰지 않고 다음 패치인 v0.2.46을 준비합니다. v0.2.44에서 갱신하는 운영자는
함께 포함된 [v0.2.45 변경과 호환성 안내](RELEASE_NOTES_v0.2.45.md)도
확인하십시오. 여기에는 관계 심사 API의 UUID 검증과 콘솔 빌드 의존성 갱신이
포함됩니다.

## 1. Server 의존성 감사를 막던 버전을 갱신했습니다

사람이 승인한 변경은 `server/go.mod`의 `golang.org/x/text` 간접 의존성을
`v0.41.0`으로 올립니다. `server/go.sum`에는 이 버전과 함께 해석된
`golang.org/x/mod v0.38.0`, `golang.org/x/tools v0.48.0`의 체크섬이
반영됩니다. 애플리케이션의 Go 소스나 API 계약은 이 변경에서 바뀌지 않습니다.

기존 Server를 운영하는 관리자가 대상입니다. 새 의존성을 포함한 Server
이미지로 교체해야 적용되며, 기존 Agent를 먼저 교체할 필요는 없습니다.

## 2. 릴리즈 노트 때문에 문서 사이트 전체가 빌드되지 않던 문제를 고쳤습니다

v0.2.45 노트의 SQL 예제에 있던 중괄호와 퍼센트 문자의 연속을 Liquid가
템플릿 시작으로 해석했습니다. SQL의 같은 의미를 유지하는 문자열 연결
표현으로 바꾸어 GitHub Pages가 문서를 렌더링할 수 있도록 했습니다.

`scripts/test-pages-build.sh`는 고정된 GitHub Pages 빌드 이미지로 전체
문서를 빌드하고, 시작 페이지와 문제를 일으켰던 릴리즈 노트가 생성됐는지
검사합니다. 과거 노트의 설명과 SQL 조건의 의미는 유지됩니다.

## 검증

- **Server.** `go test ./...`가 SQLite fallback과 PostgreSQL 17에서
  통과했습니다. `go vet ./...`와 `go build ./cmd/invenqor-server`도
  통과했습니다.
- **의존성 감사.** Go 1.25.14에서 실행한 `govulncheck ./...`는 호출 가능한
  취약점 0건을 보고했습니다. 요구 모듈 안에는 호출하지 않는 취약점 4건이
  별도로 보고되므로, 의존성 전체에 알려진 취약점이 없다는 뜻은 아닙니다.
  `cargo audit`와 `npm audit --omit=dev --audit-level=high`도 통과했습니다.
- **콘솔.** `npm ci`, `npm test`(150건), `npm run build`가 통과했고,
  `server/internal/webui/dist`는 체크인된 파일과 같습니다.
- **OpenAPI.** 고정 버전 `@redocly/cli@2.47.0 lint openapi.yaml`이 오류 없이
  통과했습니다. 경고 6건은 남아 있습니다.
- **Agent.** `cargo fmt --all -- --check`,
  `cargo clippy --all-targets -- -D warnings`, `cargo test --all-targets`
  (105건)가 통과했습니다. 기존 `scripts/build-release.sh`로 Linux
  x86_64·aarch64와 Windows x86_64의 릴리즈 바이너리를 빌드했고, Linux
  x86_64 바이너리의 `--version`이 0.2.46임을 확인했습니다.
- **문서와 패키지.** 기존 스크립트로 PDF 5종을 다시 만들고 로컬 `file://`
  링크가 없음을 확인했습니다. GitHub Pages 전체 문서 빌드와 Helm 차트 및
  배포용 `.tgz`의 lint·template 검사가 통과했습니다. 버전 참조 12곳과
  현재 가이드의 버전도 일치합니다.
- **검증 범위.** 실제 Windows 러너의 E2E와 운영 클러스터 배포는 이 로컬
  세션에서 실행하지 않았습니다. Windows 네이티브 검증과 레지스트리 게시를
  완료한 것으로 간주하지 마십시오.

## 호환성과 배포

- **데이터베이스 마이그레이션이 없습니다.** v0.2.45 이후 테이블·열·저장
  형식은 바뀌지 않았습니다.
- **API와 Agent 설정·전송 프로토콜은 같습니다.** 버전 표기는 Server·Agent·
  콘솔·OpenAPI·Helm·오프라인 Compose·가이드에서 0.2.46으로 맞춥니다.
- **신규 기능을 위한 배포가 아닙니다.** Server 의존성과 배포 문서의 유지보수
  릴리즈이며, 기존 Agent는 순차적으로 갱신할 수 있습니다.
- **배포 확인.** 운영 담당자는 먼저 시험 인스턴스에서
  `/api/v1/system/info`의 버전, 로그인, 기존 Agent의 heartbeat와 수집 데이터
  반영을 확인한 뒤 적용 범위를 넓히십시오. 이 세션에서는 원격 배포를 하지
  않으므로 실제 운영 확인이나 사용자 채택이 완료됐다고 보고하지 않습니다.
- **중단과 복구.** 위 확인 항목 중 하나라도 실패하거나 새 오류로 수집이
  중단되면 운영 담당자가 확대 적용을 중단하고 배포 전 보관한 이미지와 설정으로
  복구하십시오. 이전 이미지로 돌아가면 이번 의존성 갱신도 되돌아갑니다.
- **배포 후 확인.** 첫 24시간 동안 운영 담당자는 시험 인스턴스의 버전 확인,
  로그인, 수집 반영 세 항목이 모두 정상인지와 관련 문의를 확인하십시오.
  실제 운영 수치와 후속 검증 결과는 운영 환경에서 별도로 기록해야 합니다.
