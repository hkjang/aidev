# AgentHub 프로필 (2026-10-05)
- 목적: 사용자별 격리 AI 런타임과 자동 작업을 정책·승인·DLP·감사로 통제하는 사내 플랫폼.
- 스택: Go 1.25(chi, pgx, go-oidc, OpenTelemetry), PostgreSQL, React/TypeScript/Vite, Kubernetes, Node/Playwright. CI Node 22.
- 구조:
  - cmd/: control-plane·worker·runtime-proxy·offline 진입점.
  - internal/api/: REST·관리자·런타임 게이트웨이. server.go/catalog.go 라우팅, routes.go 설정 검증, tracking.go CSP/추적 주입·프록시.
  - internal/store/: PostgreSQL 저장·마이그레이션·감사·알림·메일 큐.
  - internal/execution/, internal/mail/: 작업/이벤트 전달과 SMTP 큐.
  - internal/runtimecfg/, internal/operator/: 런타임 설정과 Kubernetes 리소스.
  - internal/dlp/, internal/tracking/: 내용 검사, 추적 스니펫/CSP/위반 기록.
  - web/src/: 콘솔(AdminSettings.tsx 에 추적 설정 폼). web/scripts/: 브라우저 e2e, Node 단위 회귀, 가이드 촬영.
  - deploy/, scripts/: 배포/이미지 검증. runtime-images.json: 이미지 sourcePaths·버전 계약.
  - docs/: ADMIN_GUIDE·USER_GUIDE(md/PDF), architecture.md, decisions/. CLAUDE.md·AGENTS.md·roadmap/TODO 파일은 없고 TODO/FIXME 주석도 검색되지 않는다.
- 빌드·테스트: 이번 정찰 실제 실행 — `go test ./internal/tracking ./internal/api` 통과(tracking cached, api 1.767s).
- 빌드·테스트: CI `go test -race ./cmd/... ./internal/...`; web `npm ci && npm run lint && npm run test:sso && npm run build`; 이미지 `bash scripts/release-catalog-images.sh check-versions`, kustomize/compose 검사. 이번 회차 전체 CI·web 명령 미실행(web/node_modules 없음).
- 빌드·테스트: DB live 테스트는 격리 `AGENTHUB_TEST_DSN` + 암호화 키가 필요하고 DSN 없으면 skip 한다. DSN 없이 돌릴 때는 과거 병렬 오염 기록 때문에 `-p 1` 권장. 이번 DB/live·브라우저·클러스터·Keycloak·SMTP 미검증.
- 관례: 영어 conventional prefix 뒤 한국어 설명 커밋, trailer 없음. 산문 주석으로 "왜" 를 길게 명시한다. 설정은 system_settings JSON 키 + 별도 secret.
- 관례: HEAD 2b26248, v0.259.0.
- 관례: `internal/tracking`·`internal/api`·`web` 은 runtime-images.json 의 어떤 sourcePaths 에도 없다(이전 회차들이 매니페스트를 직접 읽어 확인) → 이 둘만 건드리면 BASE_VERSION 상향 불필요. 반대로 cmd/runtime-proxy·internal/dlp·internal/policy 는 base sourcePaths 라 버전 연동 확인이 필요하다.
- 관례: 추적 설정의 과대 입력은 **잘라 저장하지 않고 거절**한다 — 관리자가 읽어 낸 값은 그가 쓴 값이어야 한다. 길이는 룬 단위로 세며 바이트와 구별한다.
- 위험 구역: auth.go·mcpoauth.go·세션 게이트웨이·internal/store/migrations·.github/workflows. 정찰은 과제 대상에서 제외한다.
- 위험 구역: 설정 쓰기의 공통 지점은 `tracking.Settings.Validate`. `routes.go:validateSetting` 과 `api/tracking.go:allowTrackingOrigin` 이 저장 전에 그것을 부른다. `Validate` 의 `if !s.Enabled`(282행) **앞** 검사만 비활성·미선택에도 적용된다.
- 위험 구역: `pagePolicy` 는 `PolicySources` 의 출처를 img-src·connect-src·script-src 세 지시문에 join 하므로 n 룬이 3n 으로 증폭한다. `originOf` 는 scheme://Host 만 반환한다.
- 위험 구역: `cachedTrackingSettings` 는 5초 캐시로 읽고 `Normalized` 만 부른다 — 기존 저장값에 `Validate` 를 다시 적용하지 않으므로 이미 저장된 과대 값은 수리되지 않는다.
- 위험 구역: `serveIndex`(api/tracking.go:140) 가 `injectSnippet(page, settings.Snippet(nonce), …)` 로 모든 추적 페이지 본문에 스니펫을 넣는다. 무인증 CSP 보고 등록과 런타임 게이트웨이 입력은 외부 문자열이다.
- 자주 깨지는 곳: API 응답 래퍼와 촬영 스크립트 접근 경로 불일치, 전역 설정 백업/복원, runtime 이미지 버전 누락.
- 자주 깨지는 곳: 이미 해결된 상한 — DLP 보고 512룬, CSP 위반 문자열 절단, 허용 출처 항목 300룬·세미콜론 거절, 목록 64개/4096룬, 한 번 클릭 허용 단일 출처, 스니펫 출처 32개/1024룬, **제공자 출처 300룬(6a7c0f1, v0.259.0)**.
- 자주 깨지는 곳: 아직 열린 비대칭 — 제공자 분기가 **렌더링하는** 스니펫의 크기(`MomentoSiteID`·`MeasurementID`·`MatomoSiteID` 와 두 URL 의 **전체** 길이)에는 상한이 없다. 붙여 넣은 스니펫만 `MaxSnippetBytes`=8KiB 로 묶여 있다. `dlp.tool` 의 direction enum 은 여전히 미정.
- 자주 깨지는 곳: 16KiB 는 전체 헤더 **보장이 아니다**. 현재 테스트는 최대 스니펫+목록이 ASCII 15921룬/바이트, 한국어 33513바이트, 4바이트 문자 42309바이트임을 명시한다.
- 자주 깨지는 곳: `Sources.all` 은 중복을 거르지만 `pagePolicy` 는 그것을 쓰지 않는다. 기존 테스트가 중복 출처를 기대한다.
- 검증 함정: CI `test:sso` 는 silent-sso.test.mjs 하나만 실행한다. 나머지 세 Node 회귀 파일(합계 130건)은 로컬 `cd web && node --test scripts/*.test.mjs` 로만 검증된다.
- 검증 함정: `guide-settings-check.test.mjs` 는 실제 소스를 `requestTimeoutMs` 부터 `  if (problems.length)` 앞까지 잘라 vm 에서 실행한다. 그 앵커 밖 코드는 검증되지 않고, 앵커 줄을 고치면 테스트 슬라이스가 함께 움직인다.
- 검증 함정: Node `AbortSignal.timeout` 타이머는 이벤트 루프를 붙잡지 않아 멈춤 회귀 하니스는 별도 interval 로 유지한다.
- 검증 함정: 관리자 API 는 관리자 세션 + CSRF 가 필요하다. `validateSetting`·`decodeTrackingSettings` 단위 호출 통과를 **실제 HTTP/DB 저장의 증명으로 쓰지 말 것**.
- 검증 함정: DSN 이 없을 때 과거 회차들은 `docker run --rm -d -p 55447:5432 postgres:16-alpine` 로 일회용 DB 를 띄워 live 를 실제로 돌렸다. 가능하면 같은 방법을 쓸 것.
- 검증 함정: 소스 주석은 현 동작을 정확히 반영해야 한다. cbbc4fb·c9fa51f 가 "제공자는 무제한" 과 룬/바이트 혼동을 바로잡았다 — 상한을 더할 때 관련 주석도 같이 고칠 것.
- 검증 함정: TrackingForm 은 스니펫 8KiB 바이트 카운터만 보여 준다. 허용 목록·스니펫 출처·제공자 상한 안내는 없고 `AdminSettings.tsx:167` 의 measurement id 입력에는 `maxLength` 도 없다(이번 직접 확인).
