# pii-masker 프로필 (2026-09-21)
- 목적: PDF/PNG/JPG의 PII 영역을 Upstage 호환 추론으로 찾아 마스킹 파일을 제공하는 동기·비동기 HTTP API와 내장 Playground.
- 스택: Go 1.25.0, gorilla/mux, pdfcpu, x/image, vendor 고정 의존성; DB 없이 job.json/입력/출력 파일 저장; 단일 HTML UI, Docker/Compose.
- 구조:
  - cmd/pii-masker/main.go — 환경 설정, SIGINT/SIGTERM, App.Run.
  - internal/app — 서비스 배선, HTTP 시간 제한과 graceful drain, 보존 스위퍼 시작.
  - internal/config — PII_MASKER_* 환경변수 Load/정규화. config_test.go는 시간 제한 테스트 3개.
  - internal/httpapi — routes/업로드/이력/GET·HEAD 결과 스트리밍, documentResponse의 no-store/nosniff, static/index.html UI.
  - internal/service — ProcessSync 슬롯, CreateJob/startJobRunner/runJob 비동기 슬롯, Shutdown/draining, 오류 매핑, 보존 관리.
  - internal/jobs — Store 메모리 맵과 디스크; job.json.tmp→Rename 기록, load 중단 처리/고아 삭제, DeleteExpired.
  - internal/upstage — 요청·인증·allow-host·리다이렉트 검사, 응답 8MB 상한, 연결 검사·오류/디버그 진단.
  - internal/document 및 internal/masking — 첨부 정규화, 이미지/PDF 렌더, PII 정책/좌표 해석; internal/core 공용 메타데이터.
  - internal/mock — 테스트/데모 추론 서버; scripts — PowerShell smoke/export와 Docker archive 실행 도구.
- 빌드·테스트: go test -count=1 ./..., go vet ./..., go build ./...를 이번 정찰에서 통과. gofmt -l ./cmd ./internal로 형식 확인 가능. go test -race -count=3 ./internal/jobs ./internal/httpapi는 이번 변경 권장(이번 정찰 미실행, 일반 테스트보다 느림).
- 관례: 영어 명령문 커밋과 PR 병합, 한국어 README·오류 메시지/영어 코드 주석 혼용. 환경변수 설정, 스키마 마이그레이션 없음. README가 정본; CLAUDE.md, AGENTS.md, docs/, 로드맵, .github CI 파일은 이 checkout에서 발견되지 않음. vendor 제외 TODO/FIXME 검색 결과 없음.
- 위험 구역: upstage 인증/allow-host, service draining/WaitGroup, jobs.load의 RemoveAll, HTTP 업로드 상한. PDF는 검은 사각형 오버레이이며 텍스트 레이어 원문 제거는 지원하지 않음(README 명시).
- 자주 깨지는 곳: 사용자 제공 실패/롤백 기록 없음. 상태·UpdatedAt·결과 경로를 여러 계층에서 다루므로 조회/이력/다운로드를 함께 검증할 것. 완료 기록 없이 잔여 output_*가 있으면 현재 재기동 후 failed인데도 다운로드됨(이번 선택 과제, 아직 미수정).
- 검증 함정: CI 없음. HTTP 통합은 실제 httptest 리스너와 app.New 배선을 사용하고 외부 Upstage 없이 mock 서버로 실행. startAppServerWithConfig customize는 app.New보다 먼저 실행되어 디스크 재기동 fixture 주입 가능. 상태 fixture는 실제 Store.load를 통과시킬 것.
- 검증 함정: config의 t.Setenv 테스트는 병렬화 금지. 권한 실패는 root 환경에서 chmod만으로 유도되지 않을 수 있으므로 디렉터리 충돌 등 사용. Windows에서 Rename/테스트 동작은 이번 정찰 미확인. 의존성 갱신·Docker 실행은 이번에 검증하지 않음.
- 현재 기준: main@e2528ae, 최근 기록 30개 확인. job.json 원자적 기록과 결과 HEAD 지원은 완료됐으므로 다시 선택하지 않는다.
