## KCB Cutover Dashboard v1.19.0

이번 판은 **부모 행을 찾을 수 없는 작업이 상황판·전광판·관리 화면 세 곳 모두에서 통째로 사라지던 것** 을 고칩니다. 화면에 트리를 그리는 `buildTree` 는 각 행의 `parentId` 로 부모를 찾아 그 아래에 붙여 왔는데, **부모를 못 찾은 행은 어디에도 붙이지 못한 채 그냥 버렸습니다.** 파일에는 분명히 들어 있는 작업이 세 화면 어디에도 나오지 않았고, 관리 화면 목록에도 없으니 **관리자가 그 행을 지우거나 고칠 방법도 없었습니다.**

**업로드로 들어온 파일에서는 일어나지 않던 문제입니다.** 가져오기 검증(`validateActivityImport`)이 막아 주기 때문입니다. 문제가 드러나는 경로는 **복구 절차(ADMIN_GUIDE 5.4 `docker cp`)로 `activity.json` 을 직접 넣는 경우** 입니다. 이 경로는 검증을 지나지 않으므로, 부모 행이 빠진 파일이 그대로 들어올 수 있었습니다.

**데이터가 지워진 적은 없습니다.** 버려진 것은 화면에 그리는 단계뿐이고 파일 내용은 그대로였습니다. 고친 것은 **그 데이터가 화면까지 도달하게 만든 것** 입니다.

### 버그 수정

- **부모 행이 없는 작업이 화면에서 빠지던 것 수정**: `parentId` 가 가리키는 부모 행이 파일에 없으면, 그 행을 버리지 않고 **최상위로 올려서** 보여 줍니다. 이제 상황판·전광판·관리 화면에 모두 나오고, 관리 화면에서 지우거나 옮길 수 있습니다.
- **순환 참조로 어느 최상위에서도 닿지 않던 작업 수정**: 서로가 서로의 부모로 얽혀 어떤 최상위 행에서도 닿을 수 없는 행들도 같은 방식으로 최상위로 올립니다. 트리를 그리는 단계에서 순환이 끊기므로 화면이 무한 재귀로 멈추지 않습니다.
- **`id` 없는 행 한 줄이 화면 전체를 무너뜨리던 것 수정**: `id` 가 없는 행만 건너뜁니다. 이전에는 그런 행 하나가 `TypeError` 를 일으켜 화면 전체가 뜨지 않았습니다.

### 동작이 달라지는 곳

- **같은 `id` 가 두 번 들어 있는 파일**: 이전에는 같은 행이 화면에 **두 번** 그려졌고, 이제는 **한 번만** 그려집니다. 파일에 중복이 있다는 사실 자체를 관리자에게 알리지는 않습니다.
- **최상위로 올라간 행의 들여쓰기**: 승격된 행의 `level` 값은 일부러 그대로 두었습니다. 따라서 들여쓰기 없이 상위 자리에 표시됩니다.

### 바뀌지 않는 것

- **업로드 허용 범위와 검증 상한은 그대로입니다.** `validateActivityImport` 의 ID·제목·개수 제한은 손대지 않았습니다.
- **저장·API·인증·메일·추적·배포·의존성 변경은 없습니다.** 상태 전파와 통계 집계 규칙(ADMIN_GUIDE 4.3, USER_GUIDE 3.1)도 문서화된 계약 그대로입니다.
- **읽기 단계에 검증을 넣지 않았습니다.** `readActivityData` 에 검증을 걸면 살아 있는 훈련이 통째로 읽기 실패로 바뀔 수 있어, 화면에 그리는 단계에서만 처리했습니다.

### 검증

- 단위 테스트 **113건 통과**(이번 판에서 5건 추가), 타입 검사·lint·빌드 통과.
- E2E **50건 통과**(이번 판에서 2건 추가). 추가된 2건은 부모 행이 빠진 파일을 직접 넣고, 해당 작업이 상황판에 보이는지와 관리 화면에서 지워지는지를 확인합니다.
- 수정만 되돌리면 그 E2E 2건이 다시 실패하는 것을 확인해 원인과 수정이 맞물리는지 검증했습니다.

### 변경 파일

프로덕션 코드 `lib/treeUtils.ts` 한 파일, 그리고 테스트와 가이드 문단입니다.

### 설치

폐쇄망 서버에는 첨부된 `cutover-v1.19.0.tar.gz` 를 올린 뒤 ADMIN_GUIDE 2.3 과 같은 방법으로 교체합니다.

```bash
docker load -i cutover-v1.19.0.tar.gz
```

데이터는 `/app/data` 볼륨에 있으므로 컨테이너를 교체해도 상황판은 그대로 남습니다. 데이터 형식은 바뀌지 않았으므로 **기존 `activity.json` 을 그대로 쓰면 되고, 되돌릴 때도 별도 작업이 필요 없습니다.**
