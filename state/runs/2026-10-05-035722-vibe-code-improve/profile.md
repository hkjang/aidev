# vibe-code 프로필 (2026-10-05)
- 목적: VS Code에서 한국어 기본 AI 코딩·목표 자율 루프·계획·검증·감사·사용량 관리를 제공한다.
- 스택: TypeScript ES2022/commonjs/strict, esbuild, Vitest 3, VS Code API; DB 없이 Markdown/JSONL 상태 파일.
- 현재 기준: HEAD 51148a2, v1.4.6. 2026-10-01 예산 알림 KST 날짜 수정(#16)은 main에 반영됐다.
- 구조:
  - src/extension.ts → src/activation.ts: 자체 기능 등록; src/features/: goals/plans/verification/usage 등.
  - src/features/verification.ts: extractCommand, runShellCommand, runAndRecord, gitChangedFiles, readProjectInfo, suggestTestCommands, 명령 등록.
  - src/util/markdown.ts: 목표/계획 공통 파서·편집기, LF/CRLF 보존 헬퍼.
  - src/features/workspace.ts: workspaceRoot, ensureWorkspacePaths, writeAudit; .vibe-code/ 상태 경로.
  - src/util/kst.ts: KST 날짜·시각. 감사 파일명과 일지 날짜의 공통 규칙.
  - src/core/, vendor/extension.core.js: 코어 연결 및 벤더 번들; 임의 수정 금지.
  - tests/unit/: 현재 11개 테스트 파일 + vscode-stub.ts. tests/extension-host/: 실제 확장 호스트 검사.
  - vitest.config.mts: tests/unit/**/*.test.ts 포함, vscode를 공유 스텁으로 alias. 이전 프로필의 .ts 확장자 표기는 틀렸다.
  - scripts/: esbuild 및 Windows PowerShell 패키징/검증; docs/: 유지보수·소스 분석·목표 워크플로·로드맵.
- 빌드·테스트:
  - Node engines는 정확히 20.19.2. npm ci 뒤 npm run check = typecheck + test + build.
  - 집중 검사: npx vitest run tests/unit/verification.test.ts (신규 Git 파서 테스트는 verification-git.test.ts 예정).
  - node --check dist/extension.js 및 node --check dist/extension.core.js.
  - 정찰 실측: Node 22.23.1 / Vitest 3.2.7에서 11 files / 85 tests 통과(12.06초). Node 20 및 표준 npm run check는 이번에 미실행.
  - 이 워크트리에 node_modules 없음. 원 checkout의 설치 도구를 읽기만 하고 회차 validation/vitest.config.mjs로 원본 테스트를 실행했다(정확한 명령은 brief.md).
  - npm run vsix / verify / smoke:vscode / test:extension-host는 Windows PowerShell 및 런타임 자산 필요; 이번 Linux 정찰 미확인.
- 관례: 영어 conventional prefix + 한국어/영어 요약. 설정은 package.json과 package.nls*.json 동시 관리; 상태 파일은 별도 DB 마이그레이션 없이 편집.
- 문서: readme.md/readme.ko.md와 docs/. 저장소 내부 CLAUDE.md/AGENTS.md는 파일 목록 검색에서 찾지 못했다.
- 위험 구역: vendor/, src/core/, .github/workflows/, scripts/*.ps1, release/; 체크포인트의 Git index·refs·stash, provider 전역 설정, 감사 원문·비밀 유출.
- 자주 깨지는 곳:
  - 공통 Markdown 정규식의 \s*는 줄바꿈까지 먹는다. sectionLines→section.trim은 첫 줄 들여쓰기를 없앤다.
  - moveTaskToSection은 transform(line.trim())로 이동 항목의 들여쓰기를 없앤다. 기존 계약과 충돌하는 변경은 신중히 분리한다.
  - readRecentAudit는 여전히 slice(-days), readCommandHistory는 slice(-7). 이미 제출된 수정과 중복 구현 금지.
  - exitCode 누락, LF-only 일지/목표 append 문제도 기존 미머지 변경과 겹친다. 예산 날짜 키만 현재 main에서 해결 확인.
  - Git porcelain 줄 파서는 한글 escape·공백·화살표 경로를 손상시킨다. 이번 선정 과제는 verification.ts의 NUL 구분 파싱.
  - 추천 명령의 shell 인용 문제는 별도 미해결 후보다. Git 경로 파싱 수정만으로 실행 안전성까지 해결됐다고 하지 않는다.
- 미머지 상태: 로컬 origin/auto의 HEAD 미포함 ref는 10개(2026-09-29-1232 ~ 2026-10-01-0842). 원격 PR 상태/개수는 이번에 조회하지 않아 미확인.
  - 충돌 파일: markdown.ts, goal-lint.ts, plans.ts, journal.ts, goals.ts, handoff-on-exit.ts, goal-metrics.ts, journal-summary.ts, command-audit.ts.
  - base 대비 diff 경로 대조에서 verification.ts는 충돌 없음. 공유 스텁은 수정하지 않는 원칙 유지.
- 검증 함정:
  - CI는 ci.yml 하나. Ubuntu check 후 Windows package. assets의 continue-on-error와 found 조건 때문에 녹색 CI가 패키징 성공을 보장하지 않는다.
  - 과거 결제/한도 annotation은 이번 원격 실패 원인의 재확인이 아니다. 현재 GitHub connector는 목록에 있지만 인증·CI 상태는 미조회.
  - npm run build는 런타임 자산 부족을 경고해도 성공한다. 빌드 통과와 VSIX 검증을 구분한다.
  - Node 런타임을 대상 node_modules에 설치하면 npm ci가 지운다. 별도 경로 런타임 사용.
  - 임시 Git 테스트는 실제 git init과 로컬 설정을 사용하고 전역 설정을 바꾸지 않는다. TMPDIR가 상위 Git 저장소 안이면 GIT_CEILING_DIRECTORIES도 지정한다.
  - 실제 fs/Git 및 프로덕션 reader를 연결한 검증 선호. 손조립 Task/CoreHost/provider/Git 출력으로 배선을 입증하지 않는다.
  - 새 export가 필요하면 동작을 보존해 먼저 노출하고, 기존 동작의 AssertionError를 얻어야 한다. 심볼 없음 오류는 결함 재현이 아니다.
  - 워크트리 간 stash 공유: 실제 작업 저장소에서 git stash 금지. 정찰은 저장소 코드·커밋을 변경하지 않는다.
