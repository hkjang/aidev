## 2026-09-08
- 선택: CSP 헤더가 버릴 허용 Origin을 저장 단계에서 거부 (가치 4 / 위험 1 / 작업량 S)
- 결과: 성공
- 요약: 서비스 설정의 `allowed_frame_origins`·`allowed_connect_origins`는 관리자 화면에서 "한 줄에 하나"짜리 자유 텍스트로 편집되는데 `validateSetting`이 이 두 목록을 전혀 검사하지 않았고, 실제로 읽는 쪽인 `cspOrigin`(api.go)은 스킴과 호스트만 남기고 읽지 못하는 값은 조용히 버린다. 그래서 `games.corp.local`처럼 스킴 없이 적은 주소가 아무 경고 없이 저장돼 화면에는 허용된 것처럼 나열되지만 Content-Security-Policy 헤더에는 한 번도 실리지 않아, 외부 호스트 게임 프레임이 계속 막히는데 관리자는 이유를 알 수 없었다(같은 화면의 play window 문제와 같은 부류). `serviceOrigin` 헬퍼를 두어 두 목록의 모든 항목이 호스트만 가리키는 절대 HTTP(S) 주소인지 검사하고 어긋난 항목을 그대로 인용해 거부하며, 바로 위에서 같은 규칙을 손으로 쓰고 있던 `public_url` 검사도 이 헬퍼로 통일했다(그 결과 예전에 통과하던 `https://user:pw@host` 형태의 자격증명도 거부된다). 런타임 `cspOrigin`은 그대로 두어 이미 저장된 값의 동작은 바뀌지 않는다. 검증: `internal/api/admin_test.go`에 통과·거부 양쪽과 "통과한 값은 반드시 `cspOrigin`을 지난다"는 불변식을 확인하는 테스트 2개를 추가했고, 새 검사를 제거하면 실제로 실패함을 확인했다. `gofmt -l`, `go vet ./cmd/... ./internal/... ./migrations/...`, `go build ./...`, `go test`·`go test -race` 전체 통과. 웹 테스트/린트는 이 워크트리에 `web/node_modules`가 없어(오프라인) 실행하지 못했고, 변경은 Go 파일 3개뿐이라 프런트엔드 소스에 닿지 않는다.
- 보류 아이디어: (1) `rankings`의 `group=department|team` 분기가 privacy 설정을 읽기 전에 응답을 써서 `show_department`가 꺼져 있어도 부서·팀 이름과 집계 점수를 그대로 내준다 — 같은 함수의 individual 분기는 `item["department"]`를 막고 있고 `defense.go:1746`은 아예 403을 내므로 의도는 명확하다(직접 확인). (2) `putOIDCSetting`/`putAISetting`이 기존 값을 읽는 `s.setting` 오류를 버려서, DB 일시 장애 중 저장하면 봉인된 client secret이 빈 문자열로 덮인다 — 화면은 항상 빈 secret을 보내므로 이 경로가 정상 경로다. (3) `playAllowed`의 무시된 오류 3곳(catalog.go:401·420·427)이 전부 허용 방향으로 fail-open 해, DB 부하 중 근무시간·일일 제한이 조용히 사라진다. (4) 관리자 비밀번호 재설정(`updateUser`)이 대상 사용자의 `auth_sessions`를 지우지 않아 탈취된 세션 쿠키가 최대 12시간 살아남는다 — 본인 변경 경로인 `changePassword`는 이미 다른 세션을 모두 지운다.
