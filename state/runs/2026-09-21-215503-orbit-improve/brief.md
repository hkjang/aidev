- 과제: 과거 Orbit 조회가 실패하거나 비어 있어도 시간 여행 탐색과 ‘현재로’ 복귀 유지 (가치 3 / 위험 1 / 작업량 M)
- 왜: `OrbitPage`는 `error` 또는 `nodes.length === 0`이면 `TimeTravel`보다 먼저 반환하므로 과거 조회 실패 후에는 같은 시점 재시도만 가능하고, 빈 응답에서는 신규 사용자 안내로 바뀌어 날짜 선택과 현재 복귀가 사라진다. 시간 여행 조작부를 결과 상태와 독립적으로 유지하면 일시적인 조회 실패나 빈 과거 결과에서도 새로고침 없이 현재 관계로 돌아올 수 있다.
- 수용 기준: 1) 현재 데이터와 earliest_at을 받은 뒤 실제 슬라이더로 과거를 선택해 500 응답을 받으면 오류·‘다시 시도’와 날짜 조작부·‘현재로’가 함께 보이며, ‘현재로’를 누르면 at 없는 /api/v1/orbit 요청이 나가 성공 시 현재 화면이 복구된다. ‘다시 시도’는 기존 선택 시점의 at을 유지한다. 2) 같은 흐름에서 과거 응답 nodes=[]이면 ‘이 시점에 표시할 관계가 없습니다’처럼 과거 전용 안내를 보여 주고 날짜 선택·현재 복귀를 유지한다. 현재 시점의 nodes=[]는 기존 ‘당신의 우주를 만들어볼까요?’와 ‘첫 사람 추가하기’ 동작을 유지한다. 3) 실제 OrbitPage → TimeTravel → api → fetch 배선을 통과하는 회귀 테스트로 오류/빈 결과 각각의 현재 복귀 및 현재 빈 상태를 검증한다. 기존 코드에서 복귀 버튼 부재로 실패하고 수정 후 통과해야 한다. 순수 분기 함수·소스 문자열 검사·주입한 nodes/setState만으로 대체하지 않는다.
- 건드릴 파일: `web/src/pages/OrbitPage.tsx:OrbitPage` — error/empty 조기 반환과 TimeTravel 배치를 최소 수정하여 과거 상태의 탐색을 유지한다. `web/src/pages/OrbitPage.test.tsx`(신규) — 실제 페이지와 시간 여행 UI의 회귀 테스트. `web/src/components/TimeTravel.tsx:TimeTravel`, `web/src/components/StateViews.tsx:ErrorView/EmptyView`, `web/src/api.ts:api`, `web/src/AuthContext.tsx:AuthProvider`, `web/src/theme.ts:theme`는 읽어 확인한 재사용 대상이며 원칙적으로 수정 불필요.
- 검증 명령: 저장소 루트 `go test ./...`; 웹 의존성 준비 `cd web && npm ci --no-audit --no-fund`; 집중 검사 `cd web && npm run test -- --run src/pages/OrbitPage.test.tsx src/components/TimeTravel.test.tsx`; 전체 웹 검사 `cd web && npm run test -- --run`; 웹 빌드 `cd web && npm run build`. 정찰에서는 Go 테스트만 실제 통과(캐시); 웹 node_modules가 없어 웹 명령 실행 결과는 미확인이다. 명령은 package.json 및 CI에 존재하는 실제 스크립트이며 집중 검사 파일은 이번에 생성한다.
- 위험과 피할 것: auth/session, migrations, .github/workflows, 서버 SQL은 수정하지 않는다. 직전 no-change 과제인 first_met 시작일 확대나 이미 완료된 orbitRange 최적화를 다시 하지 않는다. createLatestGuard의 성공/실패 양쪽 최신 요청 검사와 슬라이더 커밋 때만 요청하는 동작을 유지한다. rediscover 분리·요청 취소·페이지 구조 전면 개편은 범위 밖이다. 과거 빈 결과에 현재의 신규 등록 CTA나 오래된 캔버스를 보여 주지 않는다. 로딩/오류에서 이전 nodes가 남는 구조를 고려해 현재 데이터가 과거 결과인 것처럼 보이지 않게 한다.
- 차선 후보: Time Travel API 계약을 openAPI·API.md·guide.md에 문서화 — 위 증상이 현 코드에서 재현되지 않을 때만 선택. `internal/server/openapi.go:openAPI/operation`, `internal/server/data.go:getOrbit`, `internal/server/timetravel.go:parseOrbitAt/writeOrbitAt/orbitRange`를 기준으로 at 형식·400·현재 earliest_at(nullable)·과거 historical/at 및 earliest_at 미포함을 기록하고 실제 openAPI 핸들러 JSON 응답을 검사한다. 미래 거부 정책을 새로 만들지 않는다.

구현 순서·견적(45분 상한): 재현 테스트 15분 → 페이지 분기 최소 수정 10분 → 전체 웹 테스트/빌드 10분 → 실패 대응 여유 10분. npm 설치·환경 준비 시간이 길면 범위를 확장하지 말고 미검증 항목을 명시한다.

테스트 구성 안내: `web/vitest.config.ts`는 jsdom과 `src/test/setup.ts`를 사용하며 afterEach cleanup이 이미 있다. 실제 ThemeProvider(theme), MemoryRouter, AuthProvider와 OrbitPage를 렌더한다. 손으로 만든 api/TimeTravel/Promise 대역으로 배선을 우회하지 말고 node:http의 임시 로컬 서버(listen 127.0.0.1:0)에서 JSON/500을 반환하여 실제 fetch와 Response를 사용한다. Node fetch의 상대 URL 문제는 테스트 한정으로 URL만 해당 서버 origin에 결합하고 원래 fetch에 전달한다. AuthProvider가 호출하는 /public/config, /me, /personal/preferences와 페이지의 /rediscover도 응답해야 한다. 서버가 받은 URL로 at 포함/미포함을 검사하고 종료 시 연결·서버를 정리한다. 이 테스트 서버 구성 자체는 아직 실행하지 않아 미확인이다.

MUI 슬라이더 입력은 `web/src/components/TimeTravel.test.tsx:sliderRoot/dragTo/release`에 이미 있는 실제 pointer 이벤트 방식을 참조한다(buttons:1 및 마지막 onChange 좌표가 중요). jsdom에 없는 포인터 캡처·크기·ResizeObserver는 환경 보완만 허용한다. 실제 OrbitCanvas를 유지하면서 getContext가 null인 jsdom 환경을 명시하면 그리기 effect는 이미 조기 반환한다(픽셀 검증을 주장하지 않는다). 복귀는 ‘지금의 우주’와 실제 ‘관계 우주 지도’ DOM 및 요청 URL로 검증한다. 전역 보완과 fetch는 테스트 후 원복하며 Date만 고정하고 HTTP 타이머는 실제로 둔다.
