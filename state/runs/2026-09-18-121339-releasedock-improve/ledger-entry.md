- 요약: 이 저장소는 사용자별 계정(`users`, `oidc_subject`)과 hand-rolled Keycloak OIDC 웹 로그인(`oidc.go`, go-oidc 없음)이 있고 `/mcp` 는 `withPermission("mcp.use")` 뒤에서 `rdk_` 키와 세션만 받았으므로 표준을 그대로 적용했습니다. 새 파일 `backend/internal/server/mcpoauth.go` 하나에 (1) RFC 9728 메타데이터(`/.well-known/oauth-protected-resource` 와 `…/mcp`, 인증 없음, 맨 JSON, `Access-Control-Allow-Origin: *`, 꺼져 있으면 404), (2) `/mcp` 401 에만 붙는 `WWW-Authenticate: Bearer realm="ReleaseDock", resource_metadata=…`(거부된 토큰이면 `error="invalid_token"`), (3) 토큰 검사(JWKS 서명 RS/PS/ES 만·`HS*`/`none` 거부, `iss`, `exp`/`nbf`/`iat` 60초 여유, `typ=ID` 거부, `cnf` 거부, `sub` 필수, 대상 = `aud` 에 리소스 식별자 또는 `aud`/`azp` 가 `mcp.oauth.audience` 에 있음 — 거부 메시지에 본 `aud`/`azp` 와 적을 값을 넣음), (4) 계정 매핑(`oidc_subject=issuer|sub`, 없으면 `auth_source='oidc'` 계정의 username — 로컬 계정은 이름이 같아도 안 열림, 계정 생성·비활성 부활·role 승격 없음)을 두었습니다. `withAuth` 에서 같은 Bearer 헤더를 `rdk_` 접두사 → 키, JWT 모양이고 경로가 `/mcp` → OAuth, 그 외 → 기존 401 로 갈랐고, OAuth 주체는 `ViaAPIKey=true` 로 만들어 `Principal.Has`·`sessionCanMutatePersonalKeys`·`canManageTargetCredential`·`attenuateDelegatedAuthority` 네 게이트(grep 으로 전수 확인)를 키와 똑같이 지납니다. 범위는 관리자 천장 `mcp.oauth.scopes` 가 정하고, 토큰 `scope` 에 이 앱의 권한 코드가 실려 오면 교집합, 교집합이 비면 빈 목록 대신 거부합니다(`Principal.Has` 는 키형 주체의 빈 scope 를 "없음"으로 읽어 승격 위험은 없지만 조용한 잠금이 되므로). 설정은 표준 키 이름 그대로(`mcp.oauth.enabled/resource/audience/scopes`) `oidc_settings` 에 컬럼 4개를 더한 마이그레이션 025 로 두고(020·021 이 같은 방식) `oidc.issuer_url`·`allow_insecure_endpoints` 를 재사용했으며, 리소스 식별자는 설정값 → 일반 설정 공개 URL + `/mcp` → 요청 origin(마지막 수단) 순입니다. `PUT /api/v1/admin/settings/oidc` 는 리소스 URL 형식(`/mcp` 로 끝, HTTPS 아니면 내부 평문 허용+사설 호스트만)·허용 대상 한도·범위가 `permissions` 표에 있고 `mcp.use` 포함·켤 때 issuer 와 리소스 식별자 존재·discovery 성공을 **모두 검사한 뒤 단일 UPDATE** 로 저장하고, 켜져 있지만 조건을 잃은 설치는 꺼진 것처럼 동작하며 이유를 로그에 남깁니다. 거부는 한 곳(`withAuth`)에서 `MCP OAuth token rejected reason=<실패한 검사>` 로 로그하고 토큰 원문은 기록하지 않습니다. JWKS 는 5분 캐시, 모르는 kid 는 10초에 한 번만 재조회. 관리 화면 Keycloak OIDC 카드에 스위치·리소스 식별자·허용 대상·범위·읽기 전용 MCP/메타데이터 주소를 두고, `GET /api/v1/auth/config` 에 `mcpOAuth` 를 실어 개인 키 페이지에 "키 없이 SSO 로 연결" 안내를 띄웠습니다. 문서는 `docs/ADMIN_GUIDE.md`·`docs/MCP.md` 둘 다 없어 정본 하나(`docs/MCP.md`: 사용자 절 + 설정 표·Keycloak 클라이언트/Audience 매퍼 표·curl 확인·거부 메시지별 조치 표)를 만들고 README 에서 링크했으며, 문서의 동작 약속을 문장 단위로 코드와 대조해 한 곳(inactive 로그 문구)을 고쳤습니다. 검증: 가짜 IdP(httptest, RSA+EC 실제 키, discovery·JWKS 서빙)로 진짜 JWT 를 서명해 `Handler()` 프로덕션 배선을 통과하는 스키마 격리 통합 테스트 6건 + 순수 단위 테스트 5건(`mcpoauth_test.go`) — 꺼짐이면 404/도전 헤더 없음/토큰이 키 전용 때와 같은 본문으로 거부, 켜면 두 메타데이터 경로·REST 401 에 도전 없음, Audience 매퍼 경로·`azp` 목록 경로·ES256 통과, 천장 밖 쓰기 도구 거부, 토큰으로 REST 거부, 다른 앱 토큰 거부 메시지에 aud/azp/고칠 값, 만료·nbf·다른 issuer·다른 키·HS256·typ=ID·cnf·sub 없음·미등록·비활성·이름 같은 로컬 계정·천장 밖 scope 각각 거부되고 로그에 원인이 찍히며 users 행 수 불변, 설정 저장 거부 6종에서 저장값 불변과 정상 저장 후 read-back·메타데이터·auth/config 반영. 세션 전용 도커 PostgreSQL 16 으로 `TEST_POSTGRES_DSN` 을 채워 backend `gofmt`/`go vet`/`go test ./...`(기존 키·MCP 테스트 포함 전부 통과), runner `go test ./...`, `npx tsc -b --noEmit`, `npm test -- --run`(90건), `npm run build` 를 통과했고 `web/dist` 는 커밋 전에 지웠습니다. 실제 Keycloak·실제 MCP 클라이언트 연결은 이 세션 환경에 없어 하지 못했고(표준 검증 항목 중 유일하게 미확인), PATCH `/api/v1/admin/oidc`(옛 JSON API)는 새 컬럼을 건드리지 않아 값을 보존만 합니다.
