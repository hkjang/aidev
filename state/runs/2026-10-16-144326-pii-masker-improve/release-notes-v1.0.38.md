## 페이지 비율 좌표로 부분 마스킹할 때 `200 completed`를 돌려주면서 좌상단 1픽셀만 칠하던 문제 수정

규칙이 값의 일부만 가리는 필드는 추론 엔드포인트가 보낸 bounding box를 글자 비율대로 잘라낸 서브리전으로 덮습니다. `buildSubRegionsFromBBox`는 그렇게 자른 구간이 한 단위보다 얇으면 `endX = startX + 1`로 넓혀 왔는데, 이 "1"은 좌표가 **픽셀·페이지 포인트**라는 전제에서 나온 값입니다. 값이 전부 `0~1`인 페이지 비율 박스에 같은 보정을 걸면 페이지 전체 폭을 더하는 셈이어서, 서브리전이 단위 정사각형 밖으로 밀려났습니다.

그러면 `placeRegion`의 정규화 판정이 깨져 좌표가 문서 단위로 다시 해석됩니다. 결과는 두 가지였고, 둘 다 잘못된 보고입니다.

- 박스가 낮으면 `502 masking_failed`(`retryable:true`)로 거절했습니다. 응답에는 잘못이 없는데 쓸 수 없는 좌표라고 보고한 셈입니다.
- 박스가 조금 높으면 **`200 completed`로 성공을 보고하면서 좌상단 1픽셀만 칠한 출력**을 돌려줬습니다. 가려야 할 이름은 그대로 읽히는데 호출자는 마스킹이 끝났다고 믿게 되는, fail-closed 원칙이 가장 크게 깨지는 경우입니다.

이제 하이라인 보정은 **애초에 정규화 박스가 아니었던** 좌표에만 걸립니다.

- `internal/masking/engine.go`의 `buildSubRegionsFromBBox`가 원본 바운즈를 `isNormalizedBox`로 한 번 확인하고, 정규화 박스면 폭 보정을 건너뜁니다. 페이지 비율 박스는 `0~1` 안에 그대로 남아 `placeRegion`이 같은 단위로 읽습니다.
- 보정을 건너뛰어도 빈 영역이 나오지는 않습니다. `ComputeMaskedRuneSpans`는 열린 스팬만 닫으므로 `span[1] > span[0]`이 항상 성립해, 정규화 박스도 폭이 있는 영역을 돌려줍니다.
- 너무 얇아진 영역을 최소 한 단위까지 넓히는 일은 `placeRegion`이 문서 단위로 스케일한 **뒤에** 이미 하고 있습니다. 그래서 픽셀·포인트 좌표의 하이라인 동작과 `placeRegion`·`isNormalizedBox`·`minPlacedSize`·오류 문구는 전부 그대로입니다.

검증은 결과 PNG의 검은 픽셀 경계 상자를 전수 스캔하는 `POST /v1/mask` 회귀로 했습니다. 프로덕션 배선(config 조립 → `app.New` → 실제 리스너 → upstage 클라이언트 → `CollectMaskRegions` → 렌더러)을 그대로 지나며, 정규화 `(0.1,0.1)-(0.7,0.3)` → `(120,20)-(199,59)`, 정규화 `(0.1,0.1)-(0.7,0.7)` → `(120,20)-(199,139)`, 픽셀 대조군 `(40,20)-(280,140)` → `(120,20)-(199,139)`를 단언합니다. 좌표를 하나씩 찍어보는 대신 경계 상자 전체를 보므로 좌상단만 칠하는 출력은 통과할 수 없습니다.

변경은 프로덕션 파일 1개(`internal/masking/engine.go`, 조건 한 줄 + 주석), 테스트 2개 파일, README 한 문장입니다. `go test -count=1 ./...`, `go test -race ./internal/masking ./internal/httpapi`, `go vet ./...`, `go build ./...`, `gofmt`가 모두 통과합니다.
