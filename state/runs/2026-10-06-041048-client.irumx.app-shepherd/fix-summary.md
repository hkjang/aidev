# 수리 요약 (46bc6d2)

지적 4개 모두 node 로 재현해 맞음을 확인했다. 원인은 하나: `parseKakao` 가 첫 머리줄 앞에 모르는 줄이 있으면 `return null` 로 **포기**해 입력이 `parseList`(글머리표 아닌 줄 전부 버림)·`parseParagraphs`(문단마다 4000자 컷)로 떨어진 것.
고친 방법: 포기하지 않고 그 앞 블록을 `author`·`at` 이 빈 **머리 메시지(index 0)** 로 남긴다 — 카톡 파싱을 그대로 유지하므로 세 시나리오 모두 main 보다 **더** 많이 보존한다(소개1줄+카톡: list 2개 → kakao 5개 / 긴 내보내기: 4,044자 → 9,150자·121개 / `truncated` 거짓 경고 없음). `EXPORT_HEADER` 는 줄 전체 앵커(`/^(?:.{0,40}님과\s*카카오톡\s*대화|저장한 날짜\s*:.*)$/`)로 묶고 **맨 앞 두 줄에서만** 보게 해 '아래 카카오톡 대화 확인 부탁드립니다' 안내 한 줄이 머리말로 오인되던 원래 결함도 없앴다. 덧붙여 메시지 하나가 4000자로 잘릴 때도 `truncated` 를 켜 조용한 손실을 없앴다.
시험: `tests/kakao.spec.ts` 에 입력의 모든 비어 있지 않은 줄이 결과에 남았는지 재는 `droppedLines()` 를 넣고 약속을 직접 단정하게 했다(지적 3). 고치기 전 새 시험 4개가 바로 그 이유로 실패(red)하는 것을 보고 고쳤다.
검증: `npm run build`(tsc 3개 + verify-build) 통과, `npm test` **52 passed** (exit 0) — 고친 소스로 다시 빌드한 뒤 돌렸다. README·docs/qa.md 의 시험 수(49→52, kakao 12→15)도 맞췄다.
