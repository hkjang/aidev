## Relio v1.11.20 — 정책을 풀지 않고 붙이는 사내 방문자 분석, 그리고 v1.11.19 이후의 수정 전부

사내 수집기 **Momento** 가 방문자 분석 공급자 목록의 첫 자리에 들어갑니다. 같은 오리진 프록시(`/momento`)를 켜면 브라우저에는 외부 출처가 하나도 보이지 않으므로 `script-src 'self'` 를 출하 상태 그대로 둔 채 추적이 동작합니다 — 정책을 넓힐 수 없는 환경에서도 붙일 수 있습니다.

함께, 이미 Keycloak 세션을 가진 방문자를 로그인 화면 없이 들여보내는 **자동 로그인**(기본 꺼짐), 관리자 화면의 `system.timezone` 을 서버가 실제로 읽게 되어 **새벽 0시 ~ 9시 사이 날짜가 하루 어긋나던** 문제, 딜 건강도의 "금액 급감"·"성공확률 급락" 규칙이 **창을 무시하고 1년치를 보던** 문제, IPv6 링크 로컬 주소에서 온 요청의 **감사 이벤트가 통째로 버려지던** 문제, 새 체크아웃에서 `go build` 가 실패하던 문제를 고쳤고, 이미지에 OCI 라벨을 붙였으며, 사용자·관리자 가이드를 실제 화면 캡처로 다시 썼습니다.

## 1. Momento 와 같은 오리진 프록시

### 1-1. 붙여 넣는 스니펫이 아니라 검증된 값에서 생성되는 태그

Momento 의 추적기는 `<script async src=".../tracker.js" data-site-id=... data-environment data-contract-version>` 태그 하나입니다. 다른 공급자와 마찬가지로 관리자 화면에서 사이트 ID 와 수집기 주소를 입력하면, 서버가 검증된 값으로 로더(`/analytics.js`)를 생성합니다. 붙여 넣은 JavaScript 를 받지 않으므로 nonce 도 `'unsafe-inline'` 도 필요 없고, 관리자 권한이 모든 사용자 세션의 스크립트 실행 권한이 되지 않습니다.

```go
attributes := map[string]string{"data-environment": "prd", "data-contract-version": "1"}
for name, value := range p.ScriptAttributes {
    attributes[name] = value
}
attributes["data-site-id"] = p.SiteID
```

`data-environment` 는 스크립트 속성으로 바꿀 수 있지만(스테이징 수집기는 `stg`), 사이트 ID 는 덮어쓸 수 없습니다.

### 1-2. 프록시를 켜면 정책에 외부 출처가 등장하지 않는다

새 Momento 공급자는 **같은 오리진 프록시 사용** 이 기본으로 켜져 있습니다. 켜져 있으면 로더가 `/momento/tracker.js` 를 로드하고 `data-endpoint="/momento"` 를 주며, 서버의 `httputil.ReverseProxy` 가 `/momento/*` 를 수집기로 넘깁니다. 브라우저 입장에서는 전부 같은 출처이므로 `script-src` 와 `connect-src` 는 출하 상태 그대로입니다.

프록시는 다음을 보장합니다.

- 나가는 요청에서 `Cookie`·`Authorization`·`X-CSRF-Token` 을 뗍니다. 브라우저는 같은 출처 요청마다 세션 쿠키를 붙이므로, 그대로 넘기면 모든 방문자의 Relio 세션이 수집기로 건너갑니다.
- 돌아오는 응답에서 `Set-Cookie` 와 정책 헤더(`Content-Security-Policy`, `Strict-Transport-Security` 등)를 뗍니다. 수집기가 Relio 출처에 쿠키를 심거나 미들웨어가 붙인 정책에 자기 것을 덧붙일 수 없습니다.
- GET/HEAD/POST/OPTIONS 만 통과시키고, 본문은 256 KB 까지, 수집기가 10초 안에 답하지 않으면 502 — 페이지가 분석 때문에 기다리는 일은 없습니다.
- 업스트림은 정책과 같은 캐시 스냅샷에서 읽습니다. 공급자를 끄면 헤더에서 빠지는 순간 `/momento` 도 404 가 되고, 아무것도 켜지 않은 설치에서는 처음부터 404 입니다.

프록시를 끄면 이전처럼 수집기 출처가 `script-src`/`connect-src` 에 추가됩니다. 프록시 플래그는 Momento 에만 의미가 있으며, 다른 공급자에 실려 오면 거부하는 대신 조용히 꺼집니다.

### 1-3. 관리자 가이드 3.5 절

설정 방법, 정책을 풀지 않는 이유, 프록시의 동작, 차단된 요청 목록, 그리고 `502`(Relio 서버에서 수집기로 닿지 않음)와 `404`(켜진 Momento 공급자가 없음)의 구분을 관리자 가이드에 적었습니다.

## 2. Keycloak 세션으로 조용히 로그인

OIDC 공급자 설정에 **자동 로그인**(`auto_login`, 기본 꺼짐)이 생겼습니다. 켜면 브라우저는 로그인 화면을 그리기 전에 `prompt=none` 왕복을 한 번 시도하고 — iframe 이 아니라 최상위 이동으로 — 원래 가려던 딥 링크로 돌아옵니다.

`prompt=none` 은 페이지를 그리지 않습니다. 즉시 코드를 돌려주거나 `login_required` 로 돌아오는데, 후자는 정상적인 답이며 여기서 재시도하면 브라우저가 영원히 튕깁니다. 그래서 재시도를 여러 층에서 막습니다.

- 시도는 브라우저가 떠나기 전에 탭 세션(`sessionStorage`)에 한 번 기록되고, 저장소를 읽을 수 없으면 "이미 시도함" 으로 칩니다.
- 의도적인 로그아웃은 세션이 다시 생길 때까지 시도를 억제합니다.
- 거절된 조용한 시도는 콜백이 `/login?sso=none` 으로 보내 주소 자체가 표식을 갖습니다.

서버는 관리자 설정이 켜져 있는 동안에만 `prompt=none` 을 붙이므로 주소창에서 흐름을 바꿀 수 없고, `return_to` 는 같은 출처의 애플리케이션 경로만 받습니다 — API·MCP·로그인 경로는 거부합니다.

## 3. 관리자 화면의 시간대를 서버가 읽는다

### 3-1. 아무도 읽지 않던 `system.timezone`

관리자 화면은 첫 마이그레이션부터 Asia/Seoul·UTC·Asia/Tokyo 를 제안했지만, 저장된 값을 읽는 Go 코드가 없었습니다. 현재 시각에서 파생되는 모든 날짜는 프로세스 시계 — 컨테이너에서는 UTC — 에서 왔습니다. 서울 기준 00:00 ~ 09:00 사이에 그 시계는 아직 어제입니다. 08:00 에 만든 계약은 `C-<어제>` 로 번호가 붙고, 견적도 마찬가지, 고객의 소리 내보내기 파일명도 어제, 명시 날짜 없이 인식된 매출은 어제로 떨어지고, "오늘" 큐는 오늘 마감인 다음 행동을 어제 자정과 비교해 지연이라고 보고했습니다.

`internal/platform/timezone` 이 설정을 `*time.Location` 으로 풀어 30초 캐시합니다. 관리자가 바꾸면 재시작 없이 적용되고 계약 번호 하나에 설정 조회가 들지 않습니다. 읽을 수 없는 설정은 이미 들고 있던 시간대를 유지하고, 쓸 수 없는 값은 UTC 가 아니라 Asia/Seoul 로 되돌아갑니다. 시간대 DB 는 바이너리에 내장되어 베이스 이미지의 tzdata 에 의존하지 않습니다.

### 3-2. D-day 도 그 달력으로 센다

`expected_close_date` 와 `end_date` 는 DATE 열이라 pgx 가 UTC 자정으로 돌려주는데, "지금" 은 시각을 가지고 있습니다. 엔진은 `calendarDays` 로 이를 알고 있었지만 날것의 시각을 넘겨 UTC 달력으로 셌습니다. 이틀 남은 계약이 "만료 D-3" 으로 나오고, 자정에 마감을 넘긴 딜은 9시간 뒤에야 보고됐습니다. `crm.opportunityHealth` 와 `intelligence.DealHealth` 는 DATE 를 시각과 직접 비교해 **오늘 마감인 모든 딜이 자정 1초 뒤부터 `CLOSE_DATE_OVERDUE`** 였습니다.

신호 함수는 이제 시각과 함께 달력 날짜를 받습니다. 경과 시간 답(단계 정체, 마지막 연락 이후 일수)은 계속 시각을 읽습니다 — 기간은 어느 시간대에서나 같기 때문입니다. 중복 제거 키는 (유형, 대상)에서 오므로 움직이지 않고, 제목과 근거의 일수만 바뀝니다.

### 3-3. 행을 열기 전에 시간대를 읽는다

`ListOpportunities` 는 `s.DB.Query` 와 `defer rows.Close()` 뒤에서 시간대를 조회했습니다. 첫 커넥션을 쥔 채 같은 풀에 두 번째 커넥션을 요구하는 형태라, 캐시가 만료되는 순간 `MaxConns` 개의 페이지가 동시에 오면 각자 행 커넥션을 쥐고 두 번째 Acquire 를 기다리며 클라이언트가 끊을 때까지 멈춥니다. 조회를 쿼리 앞으로 옮겨 "페이지당 하나의 날짜, 페이지당 하나의 설정 조회" 를 그대로 지킵니다.

## 4. 딜 건강도 — 창을 지키는 규칙, 한 번만 읽는 사실

### 4-1. 90일 창이 무시되던 두 규칙

시드된 "금액 급감"(`AMOUNT_DROP`)과 "성공확률 급락"(`PROBABILITY_DROP`)은 임계값 JSON 에 `"days": 90` 을 선언하고 관리자 콘솔은 그 값을 편집하게 하지만, 아무것도 그것을 읽지 않았습니다. 두 규칙은 조회가 돌려준 1년치 이력 전체를 훑었습니다. 열 달 전에 금액이 깎이고 그 뒤 안정된 딜이 영원히 "금액 급감" 으로 남았고, 콘솔에서 창을 좁혀도 아무것도 바뀌지 않았습니다.

```go
widest = math.Max(widest, windowDays(rule.Threshold, dropWindowDays))
```

이제 두 규칙은 창 안의 변경만 세고, 이력 조회는 어느 규칙이든 요구하는 가장 넓은 창까지 거슬러 올라가므로 1년보다 넓은 창이 조용히 잘리지 않습니다. 창을 정할 수 없는 값(0, 음수, 숫자가 아님)은 규칙을 끄는 대신 시드된 기본값으로 돌아갑니다. 규칙 분기는 `evaluateHealthRule` 이라는 (규칙, 사실) 의 순수 함수로 빠져 나와, 여덟 가지 규칙 유형과 임계값 전부를 DB 없이 검사합니다.

### 4-2. 대시보드 하나에 1,200 번 왕복하던 조회

`DealsAtRisk` 와 `Coaching` 은 파이프라인의 열린 딜 200건 각각에 `DealHealth` 를 호출했습니다. 한 번이 여섯 왕복 — 기회, 규칙, 담당자 역할, 단계 제한, 이력, 스냅샷 쓰기 — 이라 대시보드 하나에 약 1,200 번이었고, 모든 딜에 같은 규칙을 200번 읽었습니다.

`healthOf` 가 집합 전체를 한 번에 점수화합니다. 규칙·담당자 역할·단계 제한·이력은 집합당 한 번 읽고, 기회 행은 목록 조회가 이미 돌려준 것을 쓰고, 스냅샷은 한 배치로 나갑니다. 두 대시보드와 단일 딜 `DealHealth` 가 같은 길을 지나므로 서로 어긋날 수 없고, 집합이 한 시각을 공유하므로 한 대시보드의 두 딜이 다른 날 기준으로 판단되지 않습니다. 점수 계산은 `scoreDealHealth` 라는 순수 함수로 분리되어 합계·위험 등급·추천 중복 제거·닫힌 딜 지름길을 DB 없이 검사합니다.

## 5. 감사 이벤트가 주소 때문에 버려지던 문제

클라이언트 주소를 저장하는 모든 호출자는 `httpx.ClientIP` 를 `::inet` 캐스트에 그대로 바인딩하는데, `ClientIP` 는 `net.SplitHostPort` 가 준 것을 그대로 돌려줬습니다. PostgreSQL 은 존이 붙은 주소를 거부하므로, IPv6 링크 로컬(`[fe80::1%eth0]:52000`)로 들어온 피어는 `ip` 열만 잃는 것이 아니라 **문장 전체가 실패**했습니다. 감사 이벤트는 로그 한 줄만 남기고 버려졌고 — `LOGIN_FAILED` 포함 — `auth.Login` 에서는 같은 값이 세션 INSERT 를 실패시켜 그 클라이언트는 아예 로그인할 수 없었습니다. 주소가 없는 피어(Unix 소켓의 `@`)도 같았습니다.

`ClientIP` 는 이제 존을 떼고, IPv4 매핑 형식을 풀어 듀얼 스택 리스너에서 한 클라이언트가 로그인 리미터와 감사 로그에서 같은 키가 되게 하며, 주소가 아닌 것에는 `""` 를 돌려줘 기존 `NULLIF` 가 행을 무너뜨리는 대신 NULL 로 저장합니다.

`nullableJSON` 은 인코더 오류를 버리고 `nil` 을 돌려줘, json 이 거부하는 페이로드(NaN 으로 읽힌 숫자, 순환)가 SQL NULL 로 들어갔습니다. 그 행은 "무엇이 바뀌었다" 고만 말하고 "어떻게" 는 잃어, 페이로드가 없는 이벤트와 똑같이 읽혔습니다. 이제 실패가 그 자리에 기록됩니다.

## 6. 빌드와 이미지

### 6-1. 새 체크아웃에서 `go build` 가 되게

`internal/webui` 의 `//go:embed dist/*` 는 gitignore 된 React 빌드 결과물을 요구해, 새 체크아웃에서 `npm run build` 전에는 `go build ./...` 가 "pattern dist/\*: no matching files found" 로 실패했습니다. 앵커 파일 `internal/webui/dist/README` 하나를 커밋해 패턴이 항상 맞게 했습니다. Vite 가 빌드마다 출력 디렉터리를 비우므로 같은 파일이 `web/public/` 에도 있어 그대로 복사되며, 빌드 뒤에도 체크아웃이 깨끗합니다. 두 사본이 어긋나거나 앵커가 추적에서 빠지면 `assets_test.go` 와 `check-static-assets.sh` 가 실패합니다. 서버는 이 파일을 제공하지 않습니다 — 점이 들어간 경로만 에셋으로 찾기 때문입니다.

### 6-2. 이미지에 OCI 라벨

떠 있는 이미지만 보고는 어느 버전·어느 커밋으로 만든 것인지 알 수 없었습니다. 빌드 인자로 이미 바이너리에 새기던 버전·커밋·빌드 시각을 마지막 스테이지에서 다시 선언해(ARG 는 스테이지를 넘지 않습니다) `org.opencontainers.image.{title,description,source,version,revision,created}` 여섯 개로 붙입니다.

```bash
docker image inspect relio:v1.11.20 --format '{{index .Config.Labels "org.opencontainers.image.revision"}}'
```

## 7. 실제 화면으로 다시 쓴 가이드

사용자 가이드와 관리자 가이드는 v1.6.0 시절의 ASCII 목업 개요였고, 관리자 가이드는 두 벌(`ADMIN_GUIDE.md`, `admin-guide.md`)이었습니다. 이제 사용자 가이드는 로그인 → 첫 고객 → 첫 딜 → 모든 화면 → 자주 하는 작업 → 서버가 보내는 정확한 오류 문자열 순으로, 관리자 가이드는 구성 요소, 릴리즈 자산에서 그대로 붙여 넣을 수 있는 설치, `internal/config` 에서 읽은 4개 환경변수 계약, 마이그레이션에서 읽은 DB 저장 설정 목록, 역할, 상태·관리 엔드포인트, 백업·복원·업그레이드·롤백, 증상 → 로그 메시지 → 조치 표 순으로 씁니다. `docs/assets/guide` 의 캡처는 이 소스를 compose 로 띄워 가짜 데이터를 채우고 헤드리스 Chrome 으로 찍은 실제 1440×900 화면이며, 전략 고객 계획 패널은 데이터가 채워진 상태로 담겼습니다. PDF 를 다시 구웠습니다.

## 8. 적용

마이그레이션 두 개가 기동 시 자동으로 적용됩니다.

| 마이그레이션 | 내용 | 기존 행 |
| --- | --- | --- |
| 013 | `oidc_providers.auto_login`(기본 false), `oidc_login_states.silent`·`return_to` | 변경 없음 — 자동 로그인은 꺼진 채 시작 |
| 014 | `analytics_providers` 의 provider CHECK 를 `MOMENTO` 포함으로 재정의, `same_origin_proxy`(기본 false) | 변경 없음 — 기존 공급자는 이전과 같은 정책을 만듦 |

기본 상태에서 바뀌는 동작은 없습니다. 자동 로그인과 Momento 는 관리자가 켜기 전까지 존재하지 않고, `/momento` 는 켜진 Momento 공급자가 없는 한 404 입니다. 시간대는 `system.timezone` 에 저장된 값을 따르며 기본은 Asia/Seoul 입니다 — 지금까지 UTC 로 번호가 붙은 계약·견적은 그대로 두고, 새로 만드는 것부터 설정된 달력을 씁니다. 딜 건강도의 신호 중복 제거 키는 바뀌지 않으므로 이미 열린 신호가 중복으로 다시 생기지 않습니다.

이 릴리즈의 업그레이드 검증은 v1.11.19 이미지에서 v1.11.20 이미지로 수행됩니다.
