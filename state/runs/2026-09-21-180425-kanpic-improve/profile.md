- 자주 깨지는 곳: 같은 자료의 업로드/IMPORTDATA/격자 규칙을 한쪽만 변경하는 것. 모든 파서가 같은 계약은 아니므로 무조건 통합하지 않는다.
- 중요 수정 이력: b52a394는 XLSX CellTypeUnset에 15자리 제한을 적용했다가 되돌렸다. 엑셀 raw 2.2000000000000002는 이미 실수이므로 수로 남겨야 한다. HasSignificantLeadingZero 뒤 DecimalNumber 사용, CellTypeNumber에도 파일 숫자 길이 제한 적용 금지.
- 현재 CSV 계약: parseScalar는 unguard→Boolean→Number, trim 없음. IMPORTDATA parseCSV는 원문 Boolean→TrimSpace 후 Number→실패 시 원문. 719aec5로 불리언 일치 작업은 완료됐으며 공백·아포스트로피·빈칸 차이는 테스트로 보존한다.
- 인코딩 계약: ToUTF8는 BOM UTF-8/UTF-16LE/BE를 변환하고 나머지는 그대로 둔다. fromUTF16는 홀수 끝 바이트를 버리고 고립 surrogate를 U+FFFD로 복구한다. UTF-32 지원 추가·휴리스틱 추측 금지.
- 현재 인코딩 공백: 업로드 parseDelimited는 변환 후 utf8.Valid 검사, IMPORTDATA parseCSV는 검사 없음. 이번 정찰에서 HTTPS→Resolve의 invalid UTF-8/UTF-32LE/BE 성공 및 JSON U+FFFD 치환, 동일 바이트 업로드 거절을 재현. 이번 과제는 parseCSV에 변환 후 검사 추가(아직 미구현).
- 캐시 주의: 원격 HTTP 장애는 최대 30초, parseCSV 결과는 현재 cache_seconds를 따른다. 이번 인코딩 검사로 생기는 #VALUE!도 캐시 수명 변경 없이 둔다.
- 검증 함정: CI는 Go1.26/Node24/Postgres17, -tags integration, 실제 서버 E2E까지 실행. 로컬 go test만으로 DB/웹을 검증했다고 하지 않는다. E2E 일부는 전역 설정을 바꾸므로 workers=1; 버려도 되는 배포 사용.
- 검증 함정: 테스트 helper에서만 루프백/자체 서명 TLS를 허용한다. production 정책을 바꾸어 테스트를 통과시키지 않는다. 러너 hold: budget은 저장소 실패가 아니다.
