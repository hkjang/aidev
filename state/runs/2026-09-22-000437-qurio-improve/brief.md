- 과제: make lint에 읽기 전용 Go 포맷 검사 연결 (가치 2 / 위험 1 / 작업량 S)
- 왜: Makefile의 lint는 go vet와 프런트 TypeScript 검사만 실행하므로 gofmt 불일치가 있어도 성공할 수 있다. 현재 모든 Go 소스가 정렬되어 있는 시점에 실패를 반환하는 검사를 붙이면 불필요한 포맷 변경과 리뷰 잡음을 조기에 막을 수 있다.
- 수용 기준: 1) 새 .PHONY 타깃 check-go-format이 cmd, internal, migrations, scripts 아래 Go 파일(테스트 및 integration 태그 파일 포함)을 읽기 전용으로 검사하며 정상 상태에서는 0을 반환한다. 2) 포맷 불일치가 있으면 해당 경로와 수정 안내를 출력하고 nonzero로 종료하며 파일을 수정하지 않는다; gofmt 자체의 구문 오류도 실패로 전파한다. 3) make lint가 이 검사를 실제로 실행하고 실패를 전달하며 기존 go vet·웹 lint/typecheck를 유지한다. 4) 실제 make와 gofmt를 실행하는 임시 복사본 검증으로 정상 통과, 각 루트의 미정렬 Go 파일 실패, 구문 오류 실패, 검사 전후 파일 해시 불변을 증명한다(소스 문자열 검사나 gofmt 대역은 불가). 5) make help에 검사 타깃을 표시하고 README Development에 검사/수정 방법을 간략히 설명한다.
- 건드릴 파일: Makefile:.PHONY/help/check-go-format(신설)/lint — 현재 Bash 셸을 유지하고 lint의 선행 조건으로 읽기 전용 검사 연결; README.md:Development — 검사 명령과 선택적 gofmt 수정 방법 설명. 짧은 recipe로 충분하면 새 스크립트/테스트 프레임워크를 만들지 않는다.
