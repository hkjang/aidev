저장 결과를 빠르게 바꿔 선택할 때 이전 결과의 SQL·표·작업 단추가 남거나 늦게 도착한 응답이 현재 선택을 덮어쓰던 문제를 고쳤습니다.

**다른 결과를 눌렀는데 이전 결과를 복사하거나 삭제할 수 있었습니다.**

`/saved`에서 A를 본 뒤 B를 선택하면 B를 불러오는 동안에도 A의 내용과 작업 단추가 남았습니다. A와 B의 응답 순서가 뒤집히면 마지막으로 선택한 결과와 상세 내용이 달라질 수도 있었습니다.

이제 새 결과를 선택하는 즉시 이전 상세와 작업 단추를 비우고, 마지막 선택의 성공·실패만 화면에 반영합니다. 목록 강조도 상세 응답 대신 선택한 ID를 따릅니다.

| 상황 | 이후 동작 |
| --- | --- |
| A를 보다가 B 선택 | A의 SQL·표·작업 단추를 즉시 비우고 B 로딩 표시 |
| B 선택 뒤 A 응답 도착 | 늦은 A의 성공·실패 모두 무시 |
| 현재 선택 조회 실패 | 이전 내용을 남기지 않고 실패 표시 |
| A 삭제 중 B 선택 | A만 삭제하고 B의 선택·상세 유지 |
| 삭제 단추 연속 클릭 | 진행 중 중복 삭제 요청 방지 |
| 삭제 전 시작한 같은 결과 조회가 늦게 도착 | 삭제된 상세를 다시 표시하지 않음 |

실제 `saved.js` 이벤트를 실행하는 DOM/API 대역 회귀 테스트 11개를 추가했습니다. Go race 테스트·vet·포맷 검사·빌드와 전체 JS 테스트, 실제 바이너리의 Chromium 31페이지·편집기 스모크 및 배포 이미지 점검을 통과했습니다.

저장 API의 응답 순서와 삭제 경합은 대역으로 검증했습니다. 실제 저장 데이터를 삭제하는 종단 검증은 실행하지 않았습니다. 서버 API·인증·마이그레이션 변경은 없습니다.

오프라인 배포용 `dartfly-v2.72.0.tar.gz`와 SHA-256 체크섬을 제공합니다.
