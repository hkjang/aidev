## KCB Cutover Dashboard v1.13.0

### 버그 수정
- **작업 편집(✎)을 열 때 그 사이 바뀐 제목·시간이 옛 값으로 되돌아가는 것 수정**: 관리 화면(`/admin`)의 작업 트리는 **1초마다 서버 데이터를 다시 읽어** 행에 보이는 제목·시간을 최신으로 유지합니다. 그런데 행의 편집 입력란에 담기는 값은 **그 행이 화면에 처음 그려진 순간에 한 번만** 채워졌고, 폴링으로 값이 갱신되어도 다시 채워지지 않았습니다.
  - 그래서 **관리 화면을 열어 둔 채** 다른 관리자가 같은 작업의 제목·시간을 바꾸거나 누군가 `activity.json` 을 업로드하면, **행에는 새 값이 보이는데 ✎ 로 열린 입력란에는 옛 값이 들어 있었습니다.** 겉보기로는 구분할 방법이 없었습니다.
  - 그 상태에서 다른 곳을 고치고 💾 를 누르면, 입력란에 남아 있던 **옛 제목·시간이 그대로 저장되어 다른 사람의 변경을 조용히 되돌렸습니다.** 저장은 오류 없이 성공하므로 **되돌아갔다는 사실이 화면에 전혀 드러나지 않았고**, 다음 폴링에서 값이 옛것으로 돌아간 것만 남았습니다.
  - 이제 **✎ 를 누르는 순간 입력란이 그 행의 현재 값으로 다시 채워집니다.** 편집을 열면 항상 최신 제목·시간이 보이고, 그대로 저장해도 남의 변경을 덮지 않습니다.
  - 저장 성공·취소(✕)·저장 실패 시 입력값을 남겨 두는 기존 동작(v1.9.0)은 그대로입니다.

### 알려진 동작
- **입력란을 열어 둔 뒤** 들어온 외부 변경은 여전히 내가 저장하는 값이 덮습니다(마지막 저장이 이김). 편집 중에 입력란 내용이 저절로 바뀌면 입력하던 내용을 잃기 때문에 일부러 그대로 두었으며, 같은 내용을 `docs/ADMIN_GUIDE.md` 4.4 에 적었습니다. 이번 수정은 **편집을 여는 시점**의 값이 최신임을 보장합니다.

### 검증
- 새 e2e 2건이 가짜 대역 없이 **같은 브라우저 컨텍스트에서 실제 "다른 관리자" 변경을 서버에 넣고**, 폴링으로 행에 반영된 것을 확인한 뒤 ① 편집 입력란의 값이 최신인지 ② 그대로 저장했을 때 서버에 남은 값이 최신 그대로인지를 확인합니다(`e2e/admin-edit-stale.spec.ts`). 저장 결과 판정에는 폴링을 쓰지 않습니다.
- 전체 검사 통과: 타입 검사, 린트, 단위 테스트 95건, 프로덕션 빌드, e2e 25건.
