## KCB Cutover Dashboard v1.10.0

### 버그 수정
- **작업이 하나도 없을 때도 관리 화면에서 작업을 추가**: 지금까지 관리 화면(`/admin`)의 **최상위 작업 추가 버튼은 트리 항목 안에만 있었습니다.** 최상위 행에 붙은 `같은 레벨 추가` 버튼이 유일한 진입점이었으므로, 항목이 하나도 없으면 **그 버튼을 걸 자리도 함께 사라졌습니다.** 새로 설치한 직후나 작업을 전부 지운 뒤의 관리 화면은 **아무 버튼도 없는 빈 화면**이었고, 관리자가 작업을 다시 만들 수 있는 길은 `activity.json` 파일을 만들어 업로드하는 것뿐이었습니다.
  - 이제 **`최상위 작업 추가` 버튼이 트리 목록 안에 항상 보입니다.** 항목이 몇 개든, 하나도 없든 관계없이 화면에서 바로 새 최상위 작업을 만들 수 있습니다.
  - 트리가 비어 있으면 `등록된 작업이 없습니다` 안내를 함께 보여 줘, 화면이 비어 있는 것이 **오류가 아니라 아직 작업이 없는 상태**임을 알 수 있습니다. 작업이 하나라도 생기면 안내는 사라집니다.
  - 새 버튼은 별도의 요청 경로를 만들지 않고 v1.9.0 이 한곳으로 모은 저장 함수(`submitActivityChange`)를 그대로 씁니다. 따라서 인증 만료(`401`), 저장 검증 실패(`400`), 파일 쓰기 오류(`500`) 는 **기존과 똑같이 화면 상단 붉은 배너**에 나오고, `401` 이면 로그인 화면으로 되돌아갑니다.

### 문서
- `docs/ADMIN_GUIDE.md` 4.2 에 새 `최상위 작업 추가` 버튼을 반영했습니다. 함께, v1.9.0 에서 한 번으로 줄어든 **삭제 확인창을 아직 두 번으로 적고 있던 설명**을 현재 동작에 맞게 고쳤습니다.

### 배포
폐쇄망 배포 절차는 이전과 같습니다. 첨부된 `cutover-v1.10.0.tar.gz` 를 서버로 옮긴 뒤:

```bash
# 1. 이미지 로드
docker load -i cutover-v1.10.0.tar.gz

# 2. 컨테이너 실행
docker run -d -p 3000:3000 \
  -e USER_PASSWORD=1234 \
  -e ADMIN_PASSWORD=admin1234 \
  -e AUTH_SECRET=운영환경용-충분히-긴-임의문자열 \
  -v cutover-data:/app/data \
  --name cutover-app \
  --restart always \
  cutover:v1.10.0
```

데이터 구조 변경은 없습니다. 기존 `cutover-data` 볼륨의 `activity.json` 을 그대로 쓰며, v1.9.0 에서 바로 올릴 수 있습니다.
