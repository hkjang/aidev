- 선택: STLS/STARTTLS 핸드셰이크 직전에 서버가 미리 보낸 평문 바이트를 감지해 업그레이드를 거부 (가치 3 / 위험 2 / 작업량 M)
- 결과: 성공
- 요약: POP3 `Dial`(client.go:92-104)과 IMAP `Dial`(client.go:78-90)이 업그레이드 응답 직후 리더를 새로 만들어(`textproto.NewConn(tconn)` / `bufio.NewReader(tconn)`) 서버가 핸드셰이크 전에 밀어 넣은 평문을 옛 버퍼와 함께 조용히 버렸다 — 주입은 삼켜지고 규약 위반이 어디에도 남지 않았다(STARTTLS command injection, CVE-2011-0411 / 2021 "NO STARTTLS"). TLS 는 클라이언트 우선이라 업그레이드 승인 응답 뒤의 서버 바이트는 곧 규약 위반이므로, 승인 응답과 `tls.Client` **사이**에 버퍼 잔량을 보고(pop3 `s.text.R.Buffered()` — `textproto.Conn` 이 임베드한 `Reader.R` 이 exported 라는 것을 컴파일로 확인했다, imap `s.r.Buffered()`) 0 이 아니면 `conn.Close()` 후 "server sent N bytes before TLS handshake" 로 dial 을 실패시킨다. 두 곳 모두 근거 주석에 "클라이언트 우선" 과 "버퍼 도달분만 보이는 best-effort(커널 in-flight 는 못 본다)" 를 적었고 과장된 보증은 쓰지 않았다. SMTP 는 `net/smtp` 의 `c.StartTLS` 라 리더 접근이 불가해 손대지 않았다(범위 밖). 프로덕션 파일 2개. 검증: 손으로 만든 대역 없이 `net.Listen("tcp","127.0.0.1:0")` 스크립트 서버 + 실제 `Dialer` 로 양쪽 어댑터에 같은 서버 모양을 물려 (주입) dial 실패 + 서버 핸들러가 EOF 로 끝나는 것(=클라이언트가 닫았음)을 채널로 단언, (정상) 여분 바이트 없는 업그레이드는 dial 성공 + `session.conn` 이 `*tls.Conn` + POP3 `UIDL`/`LIST` 와 IMAP 열거가 TLS 위에서 값까지 일치. 변이 검증으로 두 검사의 조건을 뒤집으면 주입 테스트 2개만 실패하고 정상 경로 테스트와 나머지 전부 통과함을 확인한 뒤 원복했다. `go test -race -count=3 ./internal/adapters/pop3/ ./internal/adapters/imap/`(ok 7.699s / 11.604s), `go build ./... && go vet ./...`, `go test -race -count=1 ./...`(실패 0), `make lint`(gosec v2.28.0 Files 138 Issues 0), `go run ./cmd/postra-contracts -check`(exit 0), `git diff --check`, `git status --porcelain internal/transport/spa/assets` 비어 있음. `retrBody`·`readList`·`maxListBytes`·IMAP 프레이밍 상수·`readLine`/`readLineNoReset` 의 데드라인 정책·설정 키·문서·워크플로는 손대지 않았다. 외부 PostgreSQL·브라우저·프런트 빌드는 실행하지 않았다.
- 실패 재현: `--- FAIL: TestPOP3STLSInjectedPlaintextRefusesUpgrade (0.01s) / client_test.go:202: Dial accepted a server that injected plaintext before the STLS handshake` 그리고 `--- FAIL: TestIMAPStartTLSInjectedPlaintextRefusesUpgrade (0.01s) / client_test.go:1125: Dial accepted a server that injected plaintext before the STARTTLS handshake` — 같은 실행에서 정상 업그레이드 테스트 2개는 PASS 였으므로 픽스처가 아니라 프로덕션 경로의 결함이다.
