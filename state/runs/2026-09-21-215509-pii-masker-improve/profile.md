# pii-masker 프로필 (2026-09-21)
- 목적: PDF/PNG/JPG의 PII 영역을 Upstage 호환 추론으로 찾아 마스킹 파일을 제공하는 동기·비동기 HTTP API와 내장 Playground.
- 스택: Go 1.25.0, gorilla/mux, pdfcpu, x/image, vendor 고정 의존성; DB 없이 job.json/입력/출력 파일 저장; 단일 HTML UI, Docker/Compose.
- 구조:
  - cmd/pii-masker/main.go — 환경 설정과 서버 실행 진입점.
  - internal/app — 실제 서비스·HTTP 배선, graceful drain, 시간 제한, 보존 스위퍼.
  - internal/config — PII_MASKER_* Load/정규화. config_test.go는 서버 timeout 테스트 3개.
  - internal/httpapi — 업로드/상태/이력/GET·HEAD 결과 스트리밍, no-store/nosniff, static/index.html UI.
  - internal/service — 동기·비동기 슬롯, draining/WaitGroup, 오류 매핑, 추론·마스킹 실행.
  - internal/jobs — 메모리 맵과 디스크 기록, job.json.tmp→Rename, 중단·고아 처리, 보존 삭제.
  - internal/upstage — 인증/allow-host/리다이렉트 검사, 8MB 응답 상한, 연결 검사, 진단 문자열.
  - internal/document 및 internal/masking — 첨부 정규화, 이미지/PDF, PII 정책·좌표; internal/core 공용 메타데이터.
  - internal/mock — 로컬 추론 mock; scripts — PowerShell smoke/export, Docker archive 실행.
- 빌드·테스트: 이번 정찰에서 go test -count=1 ./..., go vet ./..., go build ./... 통과. gofmt -l ./cmd ./internal로 형식 확인 가능. race 테스트는 이번 미실행.
- 관례: 영어 명령문 커밋과 PR 병합, 한국어 README·오류/영어 코드 주석 혼용. 환경변수 설정, DB 마이그레이션 없음. README가 정본.
- 문서·CI: checkout에서 CLAUDE.md, AGENTS.md, docs/, 로드맵, .github CI 파일 발견되지 않음. vendor 제외 TODO/FIXME 검색 결과 없음. Docker 빌드는 Go 1.25.0/CGO_ENABLED=0/-mod=vendor, 런타임 alpine appuser.
- 위험 구역: upstage 인증/allow-host, service draining/WaitGroup, jobs.load의 RemoveAll, 업로드 상한. PDF는 사각형 오버레이이며 텍스트 레이어 제거는 지원하지 않음(README).
- 자주 깨지는 곳: 사용자 제공 실패/롤백 기록 없음. 상태·UpdatedAt·결과 경로는 저장소/조회/이력/다운로드 여러 계층에 걸쳐 검증해야 한다.
- 현재 동작: 완료 기록만 output 경로를 복구하고 조회·이력·다운로드는 completed && OutputPath 비어 있지 않음 조건. 이전 프로필의 미완료 잔여 파일 다운로드 결함은 해결됨. job.json 원자적 기록과 결과 HEAD도 완료.
- 남은 문제: truncateString이 바이트 절단해 한글을 손상. 이번 실제 바이너리+로컬 HTTP 업스트림에서 연결 점검·mask 오류 detail 및 성공 debug.body의 U+FFFD를 재현. 이번 과제이며 아직 미수정.
- 검증 함정: HTTP 통합은 startAppServerWithUpstream→app.New→httptest 실제 리스너 사용, 외부 Upstage 없이 실행. startAppServerWithConfig customize는 app.New 전에 실행되어 디스크 fixture 주입 가능.
- 검증 함정: JSON 인코더는 잘린 UTF-8을 유효한 U+FFFD로 치환하므로 JSON 유효성만으로 진단 손상을 검출하지 못함. engine.debug.response는 JSON 문자열이라 한 번 더 디코딩해야 body 검사 가능.
- 검증 함정: service.process의 upstream 오류 경로는 빈 result.ResponseDebug를 직렬화함. 오류 디버그 전달 개선은 UTF-8 과제와 별개. RawBody는 완전한 추론 원문, ResponseDebug.Body는 잘린 표시용 복사본.
- 검증 함정: t.Setenv 테스트 병렬화 금지. 권한 오류는 root chmod 대신 파일/디렉터리 충돌로 유도. Windows Rename, Docker 실행, 의존성 갱신은 이번 미확인.
- 현재 기준: main@3487570, git log -30 확인. 저장소 변경·커밋 없음. 요청된 pmo/technology 세 스킬은 도구·로컬 검색에서 미발견으로 형식 미확인.
