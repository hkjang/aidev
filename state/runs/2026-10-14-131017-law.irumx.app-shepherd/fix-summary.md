# 수리 결과 — 고치지 않았고 커밋도 없다 (PR #5, ffd2bf6)

- **지적("CI check=failure")은 사실이나 원인 귀속이 틀렸다.** 코드 결함이 아니라 GitHub Actions 결제/지출한도 차단이다. 근거: 잡이 **3초**에 끝났고 실패 로그가 **비어 있다**(steps 미실행). 이 워크플로는 `apt-get install postgresql-client-17` + `npm ci` 만으로도 3초를 못 맞춘다. 같은 저장소의 앞선 회차(110037)가 `gh api .../check-runs/annotations` 로 받은 원문이 `The job was not started because recent account payments have failed or your spending limit needs to be increased. Please check the 'Billing & plans' section in your settings` 이고 이번 신호와 정확히 같다. 이번 세션도 gh 미인증·저장소 비공개(익명 API 404)라 주석 **직접 재조회는 못 했다**.
- 워크플로를 고쳐 통과시키는 것은 금지이므로 **코드·워크플로 한 줄도 바꾸지 않았다**(워킹트리는 ffd2bf6 과 동일, `git status` 비어 있음). 결제 차단이 풀린 뒤 같은 커밋으로 CI 재실행만 하면 된다.
- **코드 결백은 CI 전 단계를 로컬에서 끝까지 돌려 증명했다**(docker `law-irumx-dev`, postgres:17-alpine, 55460 — CI 와 같은 포트·비밀번호): `npm ci` → `npm run check` 통과(lint **0 errors**/646 warnings = 기준선, typecheck 3 워크스페이스, vitest **6 files/103 tests**) → `npm run build` → `ci-env.mjs` → migrate(13건) → **rls-probe 통과** → 서버 기동 → **e2e 27/27** → 빈 DB 재생성 후 **acceptance 26/26**(AT-26 포함). 앞선 두 회차가 미검증으로 남긴 후반 단계까지 전부 초록이다.
- **이 변경이 실제로 구멍을 막는지도 대조로 확인**했다(매번 빈 DB + `AT-26` 단독): 빈 로그 파일 → main 은 **PASS**(공허 통과), HEAD 는 **FAIL**. 없는 경로 → main 은 ENOENT 로 뒤 네 검사를 건너뛴 채 FAIL, HEAD 는 그 자리에서 FAIL. 진짜 server.log → **PASS**. 즉 단언은 느슨해지지 않았고 의도한 방향으로만 조여졌다.
- **여전히 확신 없는 곳**: ① 로컬에는 psql/pg_dump 가 없고 sudo 도 없어 `LAW_PG_ADMIN_URL` 을 **비우고** harness 의 docker 분기로 돌렸다 — CI 가 쓰는 psql 바이너리 분기는 미검증(이 diff 가 건드리지 않는 부분). ② 처음 돌린 acceptance 가 24/26 이었는데, AT-17/AT-19 실패는 **한 모의 공급자 프로세스에 acceptance 를 두 번 돌려 남은 장애 주입 상태** 때문이었다(재기동 후 1회 실행 = 26/26, CI 도 1회만 돌린다) — 코드 문제가 아니라고 판단했으나 다른 설명이 있을 가능성은 남는다.
