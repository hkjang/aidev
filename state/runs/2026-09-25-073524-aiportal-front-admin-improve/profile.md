- 자주 깨지는 곳:
  - 목록 화면의 "조회 중/조회했다" 판정. `items.length` 로 판단하면 query 가 바뀐 뒤 이전 사용자의 행이 남고(15e032f), `snapshot != null` 로 판단하면 결과 0건 탭이 매번 재조회된다(f29e2df). 정답은 화면별 `tabLoaded` 플래그이며, `initialLoading = tabLoading && !tabLoaded` / `refreshing = tabLoading && tabLoaded` 패턴을 6개 화면이 공유한다(9aac9de).
  - 늦게 도착한 이전 응답. `createRequestGuard` 티켓 없이 쓰면 재조회·탭 전환에서 덮어쓰기가 난다(1709f01, f3016f9, 15e032f 가 모두 이 계열). early-return 가지에서 `ticket.isLatest()` 검사를 빠뜨리는 실수가 남아 있다(ContentAccessView.loadRules 의 UUID 검증).
  - 조회 조건을 요청 시점에 `v-model` 상태에서 직접 읽는 패턴 — 제출하지 않은 입력이 페이지 이동·새로고침에 새어 든다(2026-09-25 회차 과제).
  - 외부 aidev 러너의 스킬 전달 결함을 겨냥한 과제는 6회 연속 no-change 였다 — 앱 회차에서 고를 수 없다.
