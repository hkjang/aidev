- 자주 깨지는 곳:
  - sweepReport는 Acted=false면 Note도 출력하지 않는다. Note를 추가했다고 무인 알림이 되었다고 말하지 말 것.
  - Post는 allow 뒤 HTTP를 시도하며 오류 해제가 없다. 실패 복구 시 오래된 요청이 새 예약을 삭제하지 않게 해야 한다.
  - dayDuration의 비유한 수 거절은 이미 머지됐다. b465e1a는 이전 회차의 '1734년 경계가 데이터를 전부 삭제' 주장을 정정: 오래된 경계는 0건 보고, 소실 주장은 틀림.
  - ParseCriterion 구문과 Store.SetGoal kind 유효성 정책은 별개. 기존 계약 테스트를 중복 선정하지 않는다.
- 검증 함정:
  - 현재 remote.origin.pushurl=DISABLED 실측. gitops/app/CLI requirePushable 정의가 3곳. 환경 프로브는 remote 이름으로 수행해야 하며 실제 회귀를 skip으로 덮지 않는다.
  - notify 전역 상태는 -count=1 통과로 격리를 증명할 수 없다. 같은 이벤트 반복 호출이 성공해도 nil은 억제/no-op일 수 있어 서버 요청 수를 확인해야 한다.
  - notify 반복 억제 해제는 다음 Post 시도만 복구한다. 단발 COMPLETED 알림의 자동 재시도/전달 보장이 아니다.
  - notify/api 기간 파서는 time.ParseDuration 사용. 직전 float→Duration 결함으로 일반화하지 말 것.
  - MCP activity_report 도구 설명은 7d를 예로 들지만 구현은 time.ParseDuration이라 불일치. 신규 차선 후보.
  - PostgreSQL 테스트 실행 출력은 ok지만 외부 DB 접속 여부/개별 skip은 이번 미확인. 테스트 통과를 운영 DB 검증으로 읽지 말 것.
