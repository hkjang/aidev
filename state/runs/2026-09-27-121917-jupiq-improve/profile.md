- 관례: 한국어 `type: 설명` 커밋. 주석도 한국어로 "왜"를 적는다. VERSION은 여러 파일 정합(scripts/check-version.sh). 설정 JSON은 settings, 비밀은 secrets 암호화. API 오류는 error.code/message/request_id(invalid_json·invalid_query·invalid_recipient).
  - **질의 상한 관례**: 비정수·음수는 API에서 400 `invalid_query`(queryIntOrReject), 상한 초과는 store가 조용히 **상한으로 자른다**(pageBounds:195의 200, GetUserDetail:132의 100). openapi.yaml이 그 상한을 `maximum`으로 문서화한다. 상한 초과를 기본값으로 떨어뜨리는 곳(mail.go:120·resource_usage.go:230·metrics.go:724)은 이 관례에서 벗어난 것 — 2026-09-27 과제 대상.

- 검증 함정:
  - DSN 없이 `go test ./...`는 통합이 전부 skip되므로 DB 관련 수정의 증거가 될 수 없다. `-v`로 SKIP 수를 반드시 확인.
  - 일부 통합 테스트는 비loopback IPv4가 없으면 skip(= 통과처럼 보임).
  - CI는 PostgreSQL 16, release 통합은 14, offline smoke 16.
  - `store.Seed`는 users.email을 넣지 않는다 — 수신자 관련 테스트는 주소를 명시적으로 채울 것.
  - 프런트 자원 수명은 실제 Response·ReadableStream으로 증명할 것(대역·소스 문자열 단언 금지).
  - 실제 Keycloak·실제 SMTP 릴레이 E2E는 계속 미검증(메일은 가짜 Sender와 단위 테스트만).
