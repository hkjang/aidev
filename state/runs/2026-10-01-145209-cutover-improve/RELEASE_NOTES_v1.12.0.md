## KCB Cutover Dashboard v1.12.0

### 버그 수정
- **인식할 수 없는 활동 변경 요청을 조용한 "저장 성공" 대신 오류로 거부**: 관리 화면(`/admin`)의 활동 변경 저장(`PUT /api/activities`)은 요청 본문을 **네 가지 형태**로만 알아듣습니다 — `activities` 배열 통째로, `action: add`/`delete`/`move`, 그리고 `targetId` + `newStatus` 조합입니다. 그런데 **이 네 가지 중 어느 것에도 맞지 않는 요청이 오면 오류를 내지 않았습니다.** 서버는 아무 변경도 적용하지 않은 채 **현재 데이터를 그대로 다시 저장하고 `200` 과 새 `lastUpdated` 를 돌려주었습니다.**
  - v1.9.0 이 만든 오류 배너는 `res.ok` 만 검사하므로(`submitActivityChange`), 이런 응답은 **성공과 구분되지 않았습니다.** 요청이 잘못되어 **아무것도 바뀌지 않았는데도 화면에는 오류가 전혀 보이지 않았고**, 관리자는 저장이 반영된 것으로 믿게 됩니다. 저장 시각만 갱신되어 **"방금 저장됨"** 처럼 보이는 것이 유일한 흔적이었습니다.
  - 이제 어느 변경 형태에도 맞지 않는 요청은 **`400` 과 함께 거부**됩니다. 응답은 기존 검증 실패와 같은 모양(`{ error, code }`)이며 코드는 `UNSUPPORTED_ACTION` 입니다. 관리 화면은 이 `error` 문구를 **화면 상단 붉은 배너**에 그대로 보여 줍니다.
  - 거부된 요청은 **저장된 활동 목록과 `lastUpdated` 를 전혀 건드리지 않습니다.** 알아듣지 못한 요청이 저장 시각을 갱신해 "무언가 저장됐다"는 잘못된 신호를 남기는 일이 없어집니다.
  - 상황판 제목만 바꾸는 `{ dashboardTitle }` 단독 요청은 **변경 분기가 없는 것이 정상이므로 그대로 `200`** 입니다. 빈 작업 목록(`{ activities: [] }`)으로 트리를 비우는 것도 v1.10.0 과 똑같이 동작합니다.

### 호환성
- `PUT /api/activities` 를 직접 호출하는 외부 스크립트가 있다면, 지금까지 **조용히 `200` 을 받던 잘못된 본문이 이제 `400` 을 받습니다.** 응답 코드만 보고 성공을 판정하던 호출부는 이 변경으로 **비로소 실패를 인지**합니다. 위에 적은 네 가지 정상 형태와 `{ dashboardTitle }` 단독 요청의 동작은 바뀌지 않았으므로, 관리 화면을 통한 사용에는 영향이 없습니다.

### 검증
- 새 e2e 5건이 실제 서버를 상대로 **거부 응답의 `error` 문구와 저장 내용·`lastUpdated` 불변**을 확인하고, `{ dashboardTitle }` 단독·빈 배열 요청이 `200` 으로 남는 것을 함께 고정합니다(`e2e/admin-put-contract.spec.ts`).
- 전체 검사 통과: 타입 검사, 린트, 단위 테스트 95건, 프로덕션 빌드, e2e 23건.

### 배포
- 폐쇄망 배포용 Docker 이미지: `cutover-v1.12.0.tar.gz`
  ```bash
  docker load -i cutover-v1.12.0.tar.gz
  docker run -d -p 3000:3000 \
    -e USER_PASSWORD=1234 \
    -e ADMIN_PASSWORD=admin1234 \
    -e AUTH_SECRET=운영환경용-충분히-긴-임의문자열 \
    -v cutover-data:/app/data \
    --name cutover-app \
    --restart always \
    cutover:v1.12.0
  ```
