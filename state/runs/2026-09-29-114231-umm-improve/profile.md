# umm 프로필 (2026-09-29)
- 목적: 생각을 공간 캔버스에 붙이고 연결·갈래로 묶어 협업하고 Markdown 백업·문서 차례·발표로 내보내는 도구.
- 기준: main@2e1f29a, VERSION 및 web/package.json 0.76.1. 이전 프로필의 메일 구현 존재 주장은 현재 트리와 달라 정정한다.
- 스택: Go 1.26.0(toolchain go1.26.7), PostgreSQL 17, React 19/TypeScript/Vite/Mantine/React Flow; Vitest와 Playwright.
- 구조:
  - cmd/umm: 서버 진입점. internal/httpapi/: REST 핸들러·라우팅·정적 웹, 실제 DB HTTP 통합 시험.
  - internal/store/: PostgreSQL 접근·첨부·발표 출처·handoff 저장. migrations/: 순차 SQL과 down/ 역방향; 현재 마지막 기능 번호 029.
  - internal/presentation/: Compile·Service.compile·WriteSource·WriteOutline, 그룹·부 구성 및 Ptium 연계.
  - internal/auth/: 세션·OIDC. web/src/lib/silent-sso.ts와 LoginPage.tsx: 자동/수동 로그인 복귀 경로.
  - internal/analytics/: 선택적 추적. internal/mail/ 및 internal/store/mail.go는 현재 없음(이전 회차 기록과 main 구분).
  - web/src/pages/CanvasPage.tsx: 캔버스 상태·공간 전환·되감기·자리 기억. web/src/api.ts: 요청 및 오프라인 큐.
  - web/src/lib/: 순수 모듈 및 시험; web/e2e/: 브라우저 통합 시험. docs/: 가이드·OpenAPI·릴리즈 기록.
- 빌드·테스트:
  - go test ./internal/presentation -count=1: 정찰 실행 PASS(0.032초), DB 불필요.
  - POSTGRES_DSN=<격리 PostgreSQL 17 DSN> go test -p 1 ./...: CI 표준, DB 통합 포함하여 수 분. go vet ./...; go build ./cmd/...
  - DSN 없이 HTTP 통합 시험은 SKIP한다. 정찰에서 TestPreviewWorksBeforePtiumIsConnectedIntegration의 SKIP 확인. PASS 표시만으로 실행됐다고 판단하지 말 것.
  - npm --prefix web run typecheck; npm --prefix web run lint; npm --prefix web test; npm --prefix web run build; node web/scripts/check-i18n.mjs
  - cd web && npx playwright test <인접 spec>: 실제 바이너리/웹 번들/DB 필요. UMM_BASE_URL과 UMM_E2E_COMMAND로 지정; 전체는 느림.
  - scripts/check-version.sh; scripts/migrate-dry-run.sh(마이그레이션 검증, DB 필요).
- 관례: 최근 커밋은 영어 동작 설명 문장, 릴리즈는 Release vX.Y.Z. 개선 회차는 버전을 올리지 않는다. 이전 프로필의 Co-Authored-By 금지 관례 유지(이번 별도 정책 원문은 미확인).
- 설정: DB app_settings 절과 관리자 UI, 환경 구성은 internal/config/. 가이드 정본은 docs/USER_GUIDE.md 및 ADMIN_GUIDE.md; PDF와 오래된 종합 매뉴얼은 최신 내용과 차이 가능.
- 위험 구역: internal/auth/(SSO 루프/복귀 경로), migrations/(번호 충돌), .github/workflows/와 릴리즈, 비밀 설정 암호화·감사 기록, CSP nonce 처리. 요청 없는 변경 금지.
- 자주 깨지는 곳: Markdown 가져오기 절 경계(PR #149 반려 접근 반복 금지); 서로 다른 파일 이름 처리 계약; 캔버스 클라이언트 이동의 상태 잔존. 공간 전환 rewind 초기화는 0.76.1에서 해결됨.
- 검증 함정:
  - CI는 DB를 공유하는 패키지 간 app_settings 충돌 때문에 go test -p 1 사용. Makefile test-go는 아직 go test ./...이므로 로컬 동작 차이 있음.
  - 현재 docker ps에 umm-test-pg/umm-e2e-pg 없음. 이전 DSN을 살아 있는 것으로 가정하거나 다른 프로젝트 DB를 임의 사용하지 말 것.
  - Playwright workers=1, CI에서만 retries=1. 이전 WSL 전체 실행 SEGV 보고는 이번 미재현; 실패 spec 격리 재실행으로 제품 결함과 구분.
  - page.goto는 전체 새로고침이라 React 라우팅 상태 누수 시험을 대신하지 못한다.
  - 외부 Ptium/AI/Keycloak 실서비스 검증은 이번 미실행. 실제 store/라우터를 쓰고 손으로 만든 대역만으로 결함을 증명하지 말 것.
- 발견 정정: LoginPage 수동 SSO도 ssoLoginUrl(returnTo)로 깊은 링크 보존. 공백 제목은 compile에서 fallback을 놓치지만 Compile이 trim하므로 현재 서비스에서 SlideSources만 한 칸 밀린다는 설명은 부정확.
- 조사 범위: CLAUDE.md 및 별도 로드맵 파일은 검색에서 발견하지 못함. README 앞부분·docs 허브·최근 git log 30개·CI·테스트 구성과 선택 후보 주변을 읽었고 전체 코드 품질을 전수 판정하지 않았다.
