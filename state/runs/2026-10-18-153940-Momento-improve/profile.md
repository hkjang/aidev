- 빌드·테스트:
  - `make verify` (964f507 신설): ci.yml `test` job 의 다섯 명령을 **같은 글자·같은 순서**(Go `-race` → `go vet` → `govulncheck` → sdk → web)로 돌린다. 느리다(수 분, npm ci 포함).
  - `make test`: 빠른 루프용. `-race`·`govulncheck`·`npm ci`·`npm audit` 가 **없다** — 로컬 녹색 ≠ CI 녹색. 의도된 차이이고 `buildgates_test.go` 가 `verify` 쪽만 ci.yml 과 짝지어 지킨다.
  - CI(ci.yml `test` job, `run:` 단계 **6개**): go test -race → go vet → govulncheck → (sdk) npm ci && npm audit && typecheck && test && build → (web) 같은 다섯 → `docker build`.
  - CI 는 `postgres:17-alpine` 서비스를 띄우고 `MOMENTO_TEST_POSTGRES_DSN` 을 env 로 준다.
  - 정찰 실측(2026-10-18): `go test ./internal/httpapi/` → `ok … 0.055s`(벽시계 약 9초, 대부분 컴파일). 그 외(race·npm·audit·govulncheck·Docker)는 이번 미실행.
- 관례: 한국어 conventional commit(`fix(httpapi): …`), 릴리즈는 `release: vX.Y.Z`; 환경변수와 DB settings 로 설정; 문서는 docs/. **긴 "왜" 주석을 코드에 남기는 문화** — 새 모듈·가드 테스트도 그 형식을 따른다(`normalizeCIDR`:802-819 가 모범). 드리프트는 "최신인가" 가 아니라 "두 선언이 일치하는가" 로 가드한다.
