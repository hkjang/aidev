# kanpic 프로필 (2026-09-27)
- 목적: 온프레미스·폐쇄망용 웹 AI 스프레드시트와 데이터 협업을 제공한다.
- 스택: Go 1.26(module kanpic), PostgreSQL/pgx·excelize; React 19·TypeScript·Vite·zustand·React Query; Vitest/jsdom·Playwright; Docker 배포.
- 구조 (internal/ 20개 패키지 — 이전 프로필이 빠뜨린 6개를 이번에 확인):
  - cmd/api — 서버 진입점; internal/httpapi — REST·MCP·handoff 핸들러.
  - internal/workbook·collaboration — 워크북 저장·작업·협업; internal/auth·apikey — 인증·인가.
  - internal/formula — 수식 계산·TEXT·셀 서식; DecimalNumber 는 계산용 숫자 규칙.
  - internal/delimited — Delimiter·ToUTF8·Number·Boolean 공통 파일 규칙(파일→칸 값의 정본).
  - internal/importexport — CSV/TSV/XLSX 업로드·내보내기; internal/external — 원격 수식·SSRF·캐시.
  - internal/handoff — 문서 교환·단일 사용 claim; internal/integration — 실제 PostgreSQL 통합 테스트.
  - **internal/mail** — SMTP 전송(mail.go)·MIME 조립(message.go)·알림 문구와 수신자(service.go)·설정(config.go). mail_test.go 에 in-process 가짜 relay(`startRelay`/`fakeRelay`, 와이어 transcript·DATA 본문 기록)가 있어 실제 net/smtp 배선으로 검증할 수 있다. service.go 에 테스트 없음.
  - **internal/ai** — 에이전트·게이트웨이·의도·예산·이력. agent_service.go·service.go 에 직접 테스트 없음.
  - **internal/analytics**(analytics·violations), **internal/automation**(schedule·service), **internal/presentation**(deck·particle·ptium provider), **internal/observability**, internal/settings, internal/database, internal/buildinfo.
  - web/src/pages — 홈·편집기·관리; components/CanvasGrid.tsx·workers/paste.worker.ts — 격자 붙여넣기 배선; web/src/lib — clipboard/materializePaste·clipboardHtml·spreadsheetNumber·cellEntry(타이핑 문)·compareLists.
  - testdata — Go/TS 공용 JSON 5종: cell-formats·incoming-number·numeric-text·sort-order·validation-dates. migrations — 번호별 SQL; docs — 가이드/PDF·로드맵·릴리즈.
- 빌드·테스트: `go test ./...`(18+패키지) · `go vet ./...` · `go build ./...` · `gofmt -l ./cmd ./internal ./pkg`. 좁히려면 `go test ./internal/mail -run TestDeliver -v` 처럼 패키지+-run.
- 웹 검증: `cd web && npm ci && npm run lint && npm test && npm run build`(설치·빌드 시간 필요, node_modules 가 없을 때가 많다).
- 통합 검증: `POSTGRES_DSN=postgres://... go test -tags=integration ./internal/...`(실제 DB 필요).
- 브라우저 검증: 서버를 먼저 띄운 뒤 `cd web && npm run test:e2e`(기본 http://localhost:8080, Playwright 가 서버를 띄우지 않음). 일부 E2E 가 전역 설정을 바꾸므로 workers=1·폐기 가능한 배포.
- 릴리즈 검사: `./scripts/check-release-docs.sh` · `./scripts/check-commit-identities.sh HEAD`. 문서 PDF 는 `scripts/generate_pdf.js`(web/node_modules/playwright-core 필요).
- 관례: 한국어 fix/feat/docs 커밋. 규칙의 **이유**를 주석에 길게 적는다(왜 이 값을 글자로 두는가 등) — 새 코드도 그 관례를 따를 것. 서버 필수 환경 POSTGRES_DSN, 나머지는 internal/settings·관리자 콘솔. 번호순 SQL. 사용자에게 보이는 규칙을 바꾸면 docs 가이드와 PDF 를 함께 갱신.
- 위험 구역: internal/auth·apikey·handoff, migrations, .github/workflows, internal/external 의 SSRF·허용 목록, internal/mail 의 TLS/AUTH(`tlsConfig` 의 SkipVerify·`loginAuth`). 테스트의 루프백·자체 서명 TLS 허용을 운영으로 옮기지 않는다.
- 자주 깨지는 곳: 같은 자료를 읽는 문(업로드·IMPORTDATA·클립보드·타이핑)을 한쪽만 바꾸는 것. 계산용 파서(formula.DecimalNumber)·파일 파서(delimited.Number)·표시 숫자 파서를 무조건 통합하지 않는다. b52a394 는 CellTypeUnset 에 15자리 제한을 넣은 변경을 되돌렸다.
- 숫자 계약 요약: delimited.Number = DecimalNumber + 앞자리 0 가드 + 16자리 초과 가드. XLSX CellTypeNumber 는 이미 실수라 가드 금지. parseScalar 는 trim 없음(" 12" 는 글자), IMPORTDATA 는 TrimSpace 후 수 — 남은 어긋남. 웹 decomposeNumberText 에도 같은 꼴의 앞자리 0 가드가 있고(v0.253.0) cellEntry.ts 가 타이핑 문을 spreadsheetNumber 에 맡긴다(v0.254.0).
- 인코딩: ToUTF8 는 BOM UTF-8/UTF-16LE/BE 만 변환, 나머지는 그대로. 홀수 끝 바이트 버림, 고립 surrogate U+FFFD. parseCSV 는 변환 직후 UTF-8 유효성을 보고 #VALUE! 로 거절(0a21ce7). UTF-32 지원·휴리스틱 추측 금지.
- 외부 호출 오류 코드: 설정 읽기 실패·external.enabled 꺼짐·호출 수 초과·호스트 거절은 모두 `#N/A`(fetcher.go:124,130,136,158,171). `#VALUE!` 는 399 의 CSV 읽기 실패뿐. **docs/ADMIN_GUIDE.md:785 가 이것과 어긋나 있다(미수정).**
