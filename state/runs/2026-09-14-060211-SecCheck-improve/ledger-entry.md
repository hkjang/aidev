- 요약: 이 저장소는 이미 `notification` 행(`email_enabled`·`smtp_host`·`smtp_tls_mode`·`from`…)과 `SEND_EMAIL` 작업 큐 워커, 사용자별 수신 설정·일일 요약, 테스트 발송을 갖고 있어 표준의 1(배경 발송)·3(사용자 명부 없음)은 이미 만족했고 2(발송 기록)·4(비밀번호)·5(시끄러움)·설정 키 이름이 어긋나 있었다. 새 패키지 `internal/mail` 이 표준의 키 그대로인 `mail` 행(`enabled`·`smtp_host`·`smtp_port`·`security`·`skip_tls_verify`·`username`·`password`·`from_address`·`from_name`·`base_url`·`timeout_seconds`·`digest_hour`·`notify_*`)을 읽고(`Load` 는 옛 행 이름 `setting:notification` 으로 봉인된 비밀번호도 열어 다음 저장까지 이어 준다), `Send` 가 `auto`(릴레이가 STARTTLS 를 알리면 쓰고 아니면 평문)·`none`·`starttls`·`tls` 를 협상하며 제목을 RFC 2047 로 인코딩하고, `Record`/`List` 가 `mail_deliveries` 에 시각·이벤트·수신자·제목·`SENT/FAILED/SKIPPED`·시도 횟수·오류를 남긴다(본문 열 없음). **고른 이벤트와 이유**: 기준은 "오지 않으면 누군가 손해를 보거나 새로고침한다" — ① `notify_turn` 내 차례(REVIEW_SUBMITTED·REVIEW_ASSIGNED·REVIEW_TRANSFERRED·ITEM_ASSIGNED·APPROVAL_PENDING·CHANGE_REQUEST·CHANGE_DONE·FOLLOW_UP_REPORTED — 내가 다음 일을 해야 심의가 움직인다), ② `notify_decision` 결과(APPROVED·REJECTED·REVIEW_CANCELLED·APPROVAL_WITHDRAWN·FOLLOW_UP_DONE — 요청자는 오픈 일정을 걸고 기다린다), ③ `notify_deadline` 기한(CHANGE_REQUEST_DUE·FOLLOW_UP_DUE·OPEN_DATE_NEAR·REVIEW_STALLED·API_KEY_EXPIRING — 놓치면 손해), ④ `notify_failure` 장애(JOB_QUEUE_STALLED·JOB_FAILED·STORAGE_LOW·EVIDENCE_UNREADABLE·EVIDENCE_INFECTED·AUDIT_CHAIN_BROKEN·ACCOUNT_LOCKED — 운영자가 조치해야 풀린다); COMMENT_ADDED(열어 볼 때 읽는 대화)·API_KEY_REVOKED(쓰는 순간 스스로 알림)는 종에만 두었고, 카탈로그의 모든 유형이 스위치 아래거나 명시된 종 전용이어야 하는 테스트를 두었다. 스위치는 `*bool` 로 두어 릴레이 필드만 보낸 API 저장이 스위치를 모두 꺼 버리지 않게 했다(통합 테스트가 잡음). 자기 알림: 세션 미들웨어가 `store.WithActor` 로 행위자를 ctx 에 넣고 `notifyTx` 가 수신자=행위자면 메일 작업을 만들지 않고 `emailed_at` 을 찍어 요약에서도 뺀다 — 단 장애 묶음은 예외(검증 버튼을 눌러 체인 실패를 찾은 관리자도 받아야 하며 기존 감사 테스트가 이를 요구했다). 워커는 `SEND_EMAIL` 마다 결과를 기록하고 주소 없음·꺼짐·유형 꺼짐·설정 미비는 재시도 없이 `SKIPPED` 로 남기며 요약도 스위치가 켜진 유형만 모은다. 관리 API: `PUT /admin/settings/mail`(`password` 는 암호화 열로만, 응답·감사·JSON 에 없음)·`POST /admin/settings/mail/test`(그 자리에서 보내고 기록)·`GET /admin/mail/deliveries`(상태 필터·요약). 마이그레이션 036 은 `mail` 행을 꺼짐으로 심고 옛 `notification` 행에 호스트가 있었을 때만 값과 `general.base_url` 을 옮긴 뒤 옛 행과 `general.base_url` 을 지우며 `mail_deliveries` 를 만든다(정기 점검이 `retention_days` 로 정리, 5-5 표 갱신).
