- 과제: curl 자격증명 마스킹 시 명령어와 앞쪽 옵션을 보존 (가치 2 / 위험 1 / 작업량 S)
- 왜: 기준 커밋 cf3b598의 Sanitize는 `curl -u admin:Passw0rd https://api.company/v1/health`를 ` -u [REDACTED] https://api.company/v1/health`로 반환해 문서의 명령어 자체를 지운다. 사용자명·비밀번호만 치환하면 비밀은 계속 숨기면서 색인 및 read-file이 반환하는 예제의 명령어·옵션·URL을 보존할 수 있다.
- 수용 기준: 1) 위 입력은 정확히 `curl -u [REDACTED] https://api.company/v1/health`가 되고 `curl --silent --user admin:Passw0rd https://api.company/v1/health`는 정확히 `curl --silent --user [REDACTED] https://api.company/v1/health`가 된다(finding=credential_assignment). 2) 인증 값 외 앞뒤 텍스트·탭·줄바꿈·URL을 보존하고 실제 비밀번호는 남지 않는다; 인증 없는 curl 및 다른 프로그램의 -u는 그대로이며 재차 Sanitize해도 출력이 같다. curlUserRE 패턴 변경으로 Revision이 기준 edeca363cffe와 달라져 기존 색인 정책 지문에 반영된다. 3) 실제 Sanitize 전체 출력 비교 회귀 테스트가 수정 전 실패/수정 후 통과하고, 실제 SQLite store와 search.New(...).ReadFile을 통과하는 인덱스 fallback 테스트에서 명령어·URL 보존과 비밀 비노출을 확인한다. 기존 줄 수 보존 테스트도 유지한다.
- 건드릴 파일: `internal/contentsecurity/sanitize.go:curlUserRE, Sanitize, Revision` — 매치 전체 중 curl부터 인증 플래그 뒤 공백까지를 캡처·복원하고 사용자명:비밀번호 부분만 치환. 기존 탐지 범위(인용 없는 -u/--user, 200자 제한)를 넓히지 않는다. `internal/contentsecurity/credential_shapes_test.go:TestCredentialShapesAnInstallationActuallyHolds, TestOrdinaryContentIsLeftAlone, TestMaskingNeverChangesTheLineCount` — 기존 curl 사례가 kept=api.company만 검사하므로 전체 출력 비교를 새 테이블 테스트로 추가. `internal/search/service_test.go:TestReadFileServesIndexedAndUnindexedFiles, TestFileToolsDefaultToRepositoryDefaultBranch` — 실제 SQLite fixture 패턴을 참고한 별도 회귀 테스트; 원격 대역 대신 소스 미설정 상태의 저장 청크를 ReadFile로 읽어 Origin=index와 최종 Content를 검증한다. 생산 search/indexer 코드는 변경할 필요 없다.
- 검증 명령: `go test -tags sqlite_fts5 ./internal/contentsecurity ./internal/mcp`; `go test -tags sqlite_fts5 ./internal/indexer ./internal/search`; 수정 뒤 `go test -tags sqlite_fts5 -race ./internal/contentsecurity ./internal/search`; `gofmt -l ./internal/contentsecurity ./internal/search`; 최종 `go test -tags sqlite_fts5 ./...` 및 `go vet ./...`(CI에 존재하는 명령, 전체 검증은 수 분 예상).
- 위험과 피할 것: auth·store migration·workflows·의존성·버전 파일은 건드리지 않는다. 과거 성공한 ${VAR} 예외(10c1853), Authorization 줄바꿈(82adfbb), MCP OAuth(82421f5)가 이 기준 트리에 없으나 재구현·체리픽하지 않는다. 미래 병합에서 curl 콜백의 캡처 번호가 바뀌면 placeholder 판정 위치와 함께 맞춰야 한다. 단순 치환문 변경만으로 끝내면 Revision이 바뀌지 않으므로 prefix 캡처를 패턴에 추가하는 방향을 권장한다. finding 심각도 정책·따옴표/등호 형태·여러 -u 처리·셸 파서 도입은 별개 과제다. 원문 자격증명을 로그/감사 증거로 남기지 않는다.
