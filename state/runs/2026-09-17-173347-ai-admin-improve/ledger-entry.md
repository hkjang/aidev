## 2026-09-17
- 선택: Keycloak 액세스 토큰으로 /mcp 인증하는 OAuth 2.1 리소스 서버 (캠페인 mcp-oauth-2026-09) (가치 4 / 위험 2 / 작업량 M)
- 결과: 성공
- 요약: 이 저장소는 사용자별 계정(`app_user`, `oidc_issuer`/`oidc_subject` 바인딩)과 Keycloak OIDC 웹 로그인, `/mcp`의 개인 키(`aia_`) 인증을 모두 갖고 있어 캠페인 대상이며, `/.well-known/oauth-protected-resource`는 없었다. MCP-OAUTH-STANDARD.md와 weekly 참조 구현(mcpoauth.go·authenticate)을 이 저장소 구조(설정 카탈로그·`system_setting`·chi·go-oidc 캐시·`auth.Principal`)에 맞춰 옮기고 postra의 엄격 항목(typ=ID·cnf·nbf 거부, 서명 알고리즘 제한, jwks_uri가 issuer와 같은 host, JWKS 재요청 초당 1회 제한)을 더했다. **고른 것과 이유**: (1) 설정 자리는 시스템 설정 카탈로그의 새 `mcp` 그룹 — 표준 키 이름 그대로(`mcp.oauth.enabled/resource/audience/scopes`, 기본 꺼짐, 시드로 자동 삽입되어 새 설치는 아무것도 달라지지 않음)이되 `audience`·`scopes`는 이 저장소의 `oidc.scopes`처럼 문자열 목록(tags UI)이다. (2) 리소스 식별자 출처는 `mcp.oauth.resource` → 없으면 기존 `general.public_url` + `/mcp`이며 **요청 `Host`로는 만들지 않는다** — 표준이 마지막 수단으로 허용하지만 대상 검사의 기준값을 요청 헤더에서 만드는 것은 검사를 무력화하므로, 둘 다 비면 켜져 있어도 조용히 꺼진 것처럼 동작하고 상태 카드에 이유를 보여 준다. (3) 대상 검사는 프롬프트 그대로 "aud에 리소스 식별자, 또는 aud·azp가 `mcp.oauth.audience`에 있음"만이며 weekly처럼 `oidc.client_id`(웹 confidential 클라이언트)를 암묵적으로 허용하지 않는다 — 웹 로그인용 토큰이 MCP를 열지 않도록. (4) 계정 매핑은 `sub`로 `(oidc_issuer, oidc_subject)` 바인딩된 활성 계정만 찾고 `preferred_username` 대체 조회는 두지 않았다(이 저장소는 웹 로그인이 subject로만 묶으므로 이름 충돌로 로컬 계정이 SSO 주체에 붙는 일을 막기 위해). (5) 발급자 discovery/JWKS 실패는 이 저장소의 `writeAuthFailure` 규약대로 401이 아니라 503 `auth_unavailable`. (6) SSO 주체는 `AuthMethod="oauth"`로 `ScopeBound()` 헬퍼를 통해 키와 같은 `mcp:tools`·`admin:write` 문을 지나고, scope는 `mcp.oauth.scopes`를 `key_scope` 활성 목록으로 거른 값이다. 전송 방식은 바꾸지 않았고 OAuth 토큰은 `mcpAuthenticate`에서만 받으며 REST의 `authenticate`는 손대지 않았다. 관리 화면에 MCP SSO 탭(스위치·리소스 식별자·허용 대상·scope, `GET /api/v1/mcp/oauth/status`로 저장된 설정의 실제 동작과 복사 가능한 MCP URL·메타데이터 URL), 관리자 가이드 3.6절(설정 표·Keycloak 공개 클라이언트/Audience 매퍼 설정·curl 확인·거부 메시지별 조치)·장애 대응 항목·PDF 재생성, docs/mcp.md "키 없이 SSO로 연결하기", api.md, security.md, OpenAPI를 갱신했다. 검증: 가짜 IdP(실제 RSA 키로 JWT 서명, discovery·JWKS 서빙)를 둔 PostgreSQL 통합 테스트 `TestMCPAcceptsKeycloakTokensForRegisteredAccountsOnly`(꺼짐 기본값→404·평범한 401·토큰도 거부, 켜져도 issuer/리소스 없으면 꺼진 듯 동작, 발급자 불통 503, 맨 JSON 메타데이터와 CORS, 401의 `resource_metadata`와 REST 401 불변, 등록 계정 `tools/list` 열림·계정 미생성, 토큰의 REST 3경로 거부, 다른 앱 토큰 거부 메시지에 aud/azp/고칠 값, `mcp.oauth.audience`에 azp 적으면 통과, 만료·nbf·다른 issuer·타 키 서명·typ=ID·cnf·sub 없음·HS256·쓰레기 각각 거부, 미등록 subject·비활성 계정 거부와 계정 수 불변, 토큰 scope claim이 권한을 넓히지 못함·관리자 scope로 열림·빈 scope면 거부, 명시적 리소스 식별자, SSO 켜고 끈 뒤 키 흐름 불변)와 단위 표 테스트 5개를 추가했고, 대상 검사를 제거하면 통합·단위 테스트가 실제로 실패하는 것을 확인한 뒤 복구했다.
