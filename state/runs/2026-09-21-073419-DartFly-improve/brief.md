- 과제: 저장 결과·워크스페이스 TSV 복사의 수식 방지와 숫자 타입 처리 일치 (가치 4 / 위험 1 / 작업량 M)
- 왜: `/saved`의 TSV 클릭 핸들러는 문자열을 그대로 복사해 수식 방지가 없고, 워크스페이스는 `String(v)` 뒤에 `spreadsheetSafe`를 호출해 숫자 -5까지 `'-5`로 바꾸며 두 화면 모두 헤더는 보호하지 않습니다. 기존 문자열 전용 보호 규칙을 두 복사 경로의 셀·헤더에 함께 적용하면 같은 결과를 어디서 복사하든 문자열은 안전하게 붙여 넣고 숫자는 숫자로 유지할 수 있습니다.
- 수용 기준: 1) 두 화면에서 문자열 `=1+1`, `+1`, `-5`, `@SUM(1)`, 공백 뒤 수식은 작은따옴표를 정확히 한 번 붙이며 숫자 -5는 `-5`, NULL은 빈 칸, 일반 문자열·불리언은 기존 표현을 유지한다. 위험한 컬럼명도 같은 보호를 받고, 헤더·값의 탭/CR/LF는 공백으로 바뀌어 TSV 행·열 구조를 깨지 않는다. 이미 작은따옴표로 시작하는 값은 중복 보호하지 않는다. 2) 같은 SQL의 실제 실행 결과와 저장 후 다시 연 결과의 TSV가 일치하고, 화면 셀 표시·저장 JSON·JSON/Markdown 복사에는 작은따옴표를 추가하지 않는다. 워크스페이스의 현재 정렬/필터 적용과 이전 회차의 상세 선택·삭제 경합 방지를 유지한다. 3) 실제 바이너리+MariaDB+Chromium에서 로그인→SQL 실행→TSV 클릭→실제 클립보드 읽기, 같은 SQL 저장 API→/saved에서 선택→TSV 클릭→실제 클립보드 읽기를 통과하는 회귀가 수정 전 실패·수정 후 성공한다. 숫자 -5와 문자열 '-5'를 같은 결과에 넣어 구분을 검증하고 위험한 헤더도 포함한다. helper 단위 테스트나 소스 문자열 검사는 보조일 뿐 완료 증거로 삼지 않는다.
- 건드릴 파일: `internal/webui/js/dialect.js:spreadsheetSafe` 인접 — 기존 보호 함수의 계약은 유지하고 필요하면 타입을 보존해 검사한 뒤 TSV 문자열로 만드는 작은 공용 셀 함수 추가; `internal/webui/js/app.js:copyTsvBtn 클릭 핸들러/currentRows` — 헤더·값에 동일 변환 적용, currentRows의 정렬/필터는 유지; `internal/webui/js/saved.js:tsvBtn 클릭 핸들러` — 같은 함수 import 및 헤더·값 처리; `test/js/dialect.test.mjs` 또는 기존 `test/js/copyformats.test.mjs` — 숫자/문자열/NULL/공백/제어문자 단위 사례; `test/smoke/editor.py:main` — 기존 실제 로그인·편집기·DB 선택 배선을 이용해 두 복사 경로 브라우저 회귀 추가(필요하면 작은 함수로 분리). `test/js/saved.test.mjs:page`는 import를 제거하는 기존 대역이므로 새 helper import 때문에 깨지면 실제 helper를 로드하도록 최소 보정하되 이것만으로 입증하지 않는다.
