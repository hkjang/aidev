# v0.74.1 — 내보내기가 자르는 자리에서만 자르고, 끝나는 자리에서 멈춥니다

v0.65.0부터 umm은 **자기가 쓴 Markdown 백업을 다시 읽어 들입니다.** v0.71.5는 이름 속
줄바꿈을, v0.71.6은 `Connections`라는 제목의 생각이 통째로 사라지던 것을 고쳤습니다.
이번에는 그 파일을 **자르는 규칙**입니다.

가져오기는 umm의 파일도 남의 Markdown과 똑같이 잘랐습니다 — 모든 제목에서, 모든
`---`에서. 그런데 내보내기 안에서 그 표식들은 거의 언제나 **사람이 쓴 말**입니다.
붙여 넣은 `### 배경`, 두 문단 사이의 `---`. 그래서 생각 하나가 여러 조각으로 돌아왔고,
메타데이터 목록은 마지막 조각에만 붙어 있었습니다.

```
    내보내기 속 생각 하나:        ## 붙여 넣은 생각
                                  ### 배경
                                  왜 이 결정을 했는지
                                  - id: `f254…`
                                  - canvas: `120, 240`

            전                              후
    ━━━━━━━━━━━━━━━━━━━━━━━━    ━━━━━━━━━━━━━━━━━━━━━━━━
    "붙여 넣은 생각"  (id 없음)    "붙여 넣은 생각"        ✔
      ↓ 새 격자, 기본 색,           본문에 ### 배경 그대로
        갈래 없음                  id · 좌표 · 색 · 갈래 그대로
    "배경"           (id 있음)     그리로 그어진 연결도 그대로
    그 생각으로 그어진 연결은
      답할 id 가 없어 사라짐
```

## 배너 뒤에서는 내보내기의 표식 두 개만 자릅니다

내보내기가 쓰는 자르는 표식은 둘뿐입니다 — 생각마다 `## `, 그리고 다른 내보내기의
배너를 이고 오는 `# `. 배너 절이 닫히는 순간부터 **그 둘에서만** 자릅니다. 배너 위에
사람이 타이핑한 글은 전처럼 일반 규칙으로 읽습니다.

## 내보내기는 끝나기도 합니다

가져오기 화면은 고른 파일들을 `---`로 이어 붙이고, 그 뒤에 오는 것은 **누구의 Markdown이든**
될 수 있습니다. 앞선 시도(PR #149)는 배너 뒤를 파일 끝까지 내보내기 규칙으로 읽어, 내보내기
뒤에 붙은 일반 파일을 통째로 삼켰습니다 — 노트 셋이 앞 생각의 본문 한 덩어리로.

파일 사이의 `---`와 생각 속의 `---`는 똑같이 생겼습니다. 다른 것은 **그 앞 줄**입니다.

```
    생각 속의 ---                  파일 사이의 ---
    ━━━━━━━━━━━━━━━━━━━━━━━━━    ━━━━━━━━━━━━━━━━━━━━━━━━━
    앞의 절반                      - id: `…`
                                   - canvas: `10, 20`
    ---                            
      ↑ 앞 줄이 산문               ---
                                     ↑ 앞 줄이 메타데이터
    뒤의 절반                      # 노트 A
```

내보내기는 자기가 쓰는 모든 절을 **자기만의 마지막 줄**로 닫습니다 — 생각은 메타데이터
목록으로, 닫는 두 절은 연결 항목이나 갈래 항목으로 — 그리고 그 뒤에 `---`를 쓰는 일이
없습니다. 그러니 그런 줄 다음의 `---`는 이음매이고, 거기서부터 다시 일반 규칙입니다. 다음
배너가 나올 때까지.

```ts
if (insideExport) {
  if (thematicBreak.test(line) && endsExport(current)) {
    flush();
    insideExport = false;
    continue;
  }
  if (startsExportSection(lines, index)) flush();
  current.push(line);
  continue;
}
```

검토하고 택하지 않은 것 둘. 내보내기에 **끝 표시**를 넣는 것 — 이미 받아 둔 백업에는
없으니 결국 같은 규칙이 필요하고, Go 형식 변경까지 끌고 옵니다. 이어 붙일 때 **다른
구분자**를 쓰는 것 — 손으로 붙여 넣는 경로를 못 덮습니다. **형식도 구분자도 그대로입니다.**
디스크에 있는 백업은 전과 똑같이 복원됩니다.

## 메타데이터는 꼬리에서만 읽습니다

전에는 절 전체에서 `- id:`를 찾았고 첫 번째가 이겼습니다. 본문이 자기네 번호를 두고
`- id: \`ours-2024-11\``이라고 적어 두면 그것이 생각의 id가 되고, 진짜 id는 보이지 않았고,
그 생각으로 그어진 연결은 전부 답할 이름이 없는 곳을 가리켰습니다. 이제 목록은
**절의 꼬리에서 따로 떼어** 읽습니다.

## 릴리즈 뒤 main CI를 두 번 떨어뜨린 e2e

v0.74.0 머지 커밋의 main CI가 'End-to-end tests'에서 본 실행·재시도 모두 같은 이유로
실패했습니다 — `canvas › summarises the canvas when zoomed out past reading distance`.
릴리즈 워크플로 자체는 v0.73.0·v0.74.0 모두 성공했습니다.

테스트는 빈 공간을 먼저 열고 28개를 POST했습니다. 그동안 이벤트 스트림이 앞의 몇 개를
캔버스에 실었고, 열림 fit이 그 몇 개(6개, zoom 0.67)에 맞춰졌고, v0.73.0의 **자리 기억**이
그 fit을 이 사람의 자리로 적어 두어 reload 뒤 28개에 fit하는 대신 그 시야를 복원했습니다.
요약 임계(0.45) 위라 포스트잇이 그려집니다. 빠른 기계에서는 fit 전에 노트가 다 도착해서
통과했고, CI에서는 두 번 다 아니었습니다.

테스트의 전제는 "이미 가득 찬 공간에 도착했을 때 보이는 것"입니다. 그래서 노트를 API로
먼저 넣고 공간을 **한 번만** 엽니다. 워크플로도 단언도 건드리지 않았습니다.

```
    CPU 6배 스로틀(CDP)         전 4/4 실패  →  후 4/4 통과
    스로틀 없이                 canvas · canvas-place · export-round-trip 18개 통과
```

## 검증

vitest 8개를 새로 넣었습니다(리뷰어의 재현 입력 그대로 포함). main 코드로는 4개가
실패하는 것을 확인했습니다.

- `comes back whole when its body holds a heading` / `… a horizontal rule` — 본문 속
  `### 배경`과 `---`가 생각을 쪼개지 않는지
- `does not take an id out of its body` — 본문의 `- id:`가 생각의 id가 되지 않는지
- `still tells two exports apart when the last thought of the first has none` — 앞 파일이
  메타데이터로 끝나면 `---`가 이음매인지
- `reads the plain file by the general rules again` / `does not read the plain file as part
  of the export` — 내보내기 뒤에 붙은 일반 파일이 노트 셋으로 돌아오는지, 그 안의
  `Connections`가 목록이 아니라 노트인지
- `finds the seam after the connections and the lines of thinking` — 닫는 두 절 뒤에서도
  이음매를 찾는지
- `reads typed text, an export and a plain file each by their own rules` — 타이핑 · 내보내기
  · 일반 파일 순서로 이어 붙여도 구간마다 제 규칙인지

남는 유일한 모호함: 본문 마지막 줄이 `- id: \`x\`` 꼴이고 바로 `---`가 오는 경우. 끝
표시 없이는 남습니다(v0.71.6의 보류 항목과 같은 뿌리).

Go 코드는 변경 없음. tsc · oxlint/Prettier · i18n 1000키 · vitest 166개 ·
`go vet ./...` · `go test ./...` · `scripts/check-version.sh` 통과.
