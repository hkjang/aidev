- 자주 깨지는 곳:
  - **2026-09-24 의 `orbitAt` DB 테스트(하위 시험 10개, `seedRelationship`·`seedOrbitPerson`·`setFirstMet`·`seedMemory`)는 verify 실패로 main 에 없다.** 회차 기록이 "성공" 이라 해도 main 을 직접 grep 해 확인할 것 — 지금 `orbitAt` 테스트는 0 개다.
  - 2026-09-21 회차 두 번이 연속 no-change(OrbitPage 조기 반환, orbitRange 의 first_met). 원인 미기록 — 사람이 볼 때까지 그 두 과제는 다시 고르지 않는다.
  - 같은 값을 읽는 경로가 여럿이다: `data.go:getOrbit`(현재)과 `timetravel.go:orbitAt`(과거)이 거의 같은 SELECT 를 각자 갖고, `recalculateRelationship` 이 또 다른 365일 창으로 같은 지표를 만든다. 실제로 응답 계약도 이미 어긋나 있다 — `getOrbit` 만 `earliest_at` 을 담는다.
- 검증 함정:
  - CI 는 postgres 없이 돈다 → DB 테스트는 CI 에서 늘 SKIP 이고 초록으로 보인다. DB 변경은 로컬에서 DSN 을 주고 직접 돌려야 한다.
  - `openTestStore` 는 `store.Open` 만 쓰고 `Bootstrap` 은 쓰지 않는다. 정리는 `seedUser` 의 `t.Cleanup` 이 users 행을 지워 FK cascade 로 한다.
  - `orbitAt` 은 `JOIN relationships` 라 relationships 행이 없는 사람은 결과에 아예 없다. 시드할 때 놓치기 쉽다.
  - `time.Time` 비교는 `==` 가 아니라 `.Equal()`. `people.first_met` 만 `date`, 나머지 시각은 `timestamptz`.
  - 핸들러 테스트에 사용자를 넣는 방법: `req.WithContext(context.WithValue(req.Context(), userContextKey, User{ID: "u1"}))` (`data_test.go:20`). 검증이 DB 앞에서 끝나는지 보려면 `&Server{store: nil}` — DB 를 타면 nil 패닉으로 드러난다.
  - `web/vitest.config.ts` 는 jsdom, `src/test/setup.ts` 가 afterEach cleanup. MUI 9 Slider 는 pointer 이벤트·`buttons:1`·`hasPointerCapture` 스텁이 필요하고, OrbitCanvas 는 ResizeObserver 가 필요하다.
  - `npm run lint` 는 eslint 가 devDependencies 에 없어 실패한다. CI 도 lint 를 돌리지 않는다.
  - `docs/cru-manual.md` 의 일부 API 설명은 코드와 다르다. API 는 실제 핸들러를 정본으로 삼는다.
  - npm 레지스트리 일시 장애가 예전에 릴리즈를 죽였다. Dockerfile·`make web` 은 이제 `scripts/npm-install.sh` 재시도 래퍼를 쓰지만 `ci.yml` 은 여전히 맨 `npm ci` 다.
