없는 계정·비활성 계정에 API 키를 발급하려는 요청을 발급 전에 거부하도록 바로잡은 패치 릴리스입니다.

- `createKey`가 관리자가 보낸 `userId`를 검증하지 않고 데이터베이스에 맡기던 문제 해결. 없는 계정 id는 `api_key.user_id` 외래 키 위반으로 500 `key_create_failed`가 되었고, `locked`·`disabled` 계정에는 아무도 쓸 수 없는 키가 발급됐으며, 고권한 키 워크플로가 켜져 있으면 승인 요청으로 접수된 뒤 검토자가 승인할 때 이유 없이 500 `approval_execution_failed`로 실패했습니다
- 키를 만들거나 승인 요청을 생성하기 전에 대상 계정을 한 번 확인합니다. 없는 계정은 404 `user_not_found`, 비활성 계정은 409 `user_not_active`(details의 `status`에 현재 상태)로 거부하며, 이 경우 승인 요청도 남지 않습니다
- 요청이 승인을 기다리는 동안 대상 계정이 삭제되거나 비활성화되면 최종 승인은 409 `key_target_unavailable`로 중단되고 요청은 대기 상태로 남아, 검토자가 반려하거나 계정 상태를 복구한 뒤 다시 승인할 수 있습니다. 계정 조회 자체가 실패한 경우는 상태 충돌이 아니라 500으로 유지합니다
- 분류 표 테스트와 PostgreSQL 통합 테스트(없는 계정 404, 비활성 409·키 없음, 활성 201, 워크플로가 켜진 상태의 비활성 409·승인 요청 0건, 대기 중 비활성화 → 승인 409·pending 유지·키 없음)로 검증
- `docs/api.md`에 다른 사용자에게 키를 발급할 때의 대상 계정 확인 계약을 명시
