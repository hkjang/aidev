# ReSSO 프로필 (2026-09-27)
- 목적: 오프라인 단일 바이너리 OIDC SSO 제공자 + 사용자·Realm 관리 콘솔. RP 구현은 포함하지 않는다(언제나 제공자 쪽).
- 스택: Go 1.26, chi v5, PostgreSQL/pgx v5, LDAP, React 19/TypeScript/MUI/React Query/Vite 7, vitest 4; CI Node 22.23.0.
- 구조:
  - cmd/resso: 서버·CLI·예약 LDAP 동기화·유지보수·메일 알림.
  - internal/httpserver: oidc.go 1451행(OIDC 전 Endpoint)·auth.go 435행(로그인·세션)·middleware.go 354행·metrics.go 108행·admin/personal/mcp/tracking. integration_test.go는 실제 PostgreSQL + httptest 서버를 쓰는 단일 11058행 파일.
  - internal/store + store/migrations: DB 접근과 자동 SQL 마이그레이션(최신 017_mail_deliveries.sql).
  - internal/oidc, cryptoutil, password, ratelimit / federation, backchannel, mail / tracking, observability.
  - web/src(React), webui/dist(Go embed 산출물), scripts, docs(운영·사용·호환 정본).
- 빌드·테스트:
  - `eval "$(scripts/test-services.sh)"` 로 PostgreSQL/LDAP/LDAPS 환경변수를 잡고 **같은 셸에서** 테스트. 출력이 비면 준비 실패이므로 eval 하지 말 것.
  - `make lint`(golangci-lint v2.13.1 + govulncheck + ESLint --max-warnings 0), `make test`(go test -race ./... + vet + vitest + build; httpserver 약 110~120s / store 약 80s), `make build VERSION=vX.Y.Z`.
  - 단일: `go test -race ./internal/httpserver -run '^TestIntegration…$' -count=1 -v`.
- 관례: 영문 `fix:`/`feat:`/`docs:`/`release:` 커밋. **HEAD 955ef7a = v0.9.92**(2026-09-26). 설정은 환경변수 + `platform_settings` 키별 한 행. docs/가 운영·연동 정본, README는 개발 참고. 코드 주석이 매우 길고 "왜 이 답을 골랐는가"를 서술형으로 담는다 — 새 코드도 그 밀도를 따른다. CLAUDE.md/AGENTS.md/roadmap/TODO는 없다.
- 이 저장소가 반복해 쓰는 설계 관용구(새 과제는 여기에 맞출 것):
  - **"이쪽 장애"와 "진짜 없음"을 같은 답으로 합치지 않는다.** `realmLookupFailed`(oidc.go:60)가 그 판정을 하고 discovery(72)·jwks(132)·authorization(189)·revocation(999)·logout(1155)·CORS(middleware.go:117)가 쓴다. userinfo는 `writeUserInfoUnavailable`(855, stage 여섯), introspection은 `recordUnjudgedIntrospection`(975)이 같은 일을 한다.
  - **조기 거절 금지**(로그아웃): 실패해도 세션을 끝내고 트레일에 남긴다.
  - **거절의 이유를 이유 코드로**: 로그아웃의 `client_not_named`/`client_unknown`/`client_unavailable`/`uri_not_registered`/`form_unreadable`.
  - **지표 라벨 카디널리티 고정**: `methodLabel`·`routePattern`(metrics.go) 주석이 왜인지 설명한다. 미검증 입력을 라벨·로그에 그대로 넘기지 않는다. 라벨 이름의 뜻을 넘는 값을 추가하지 않는다(`resso_token_errors_total`은 `grant_type` 하나).
  - **호출자 문제는 400, 이쪽 문제는 500 `server_error`**(token Endpoint; docs/ADMIN_GUIDE.md:570). revoke만 503 `temporarily_unavailable`인데 그것은 RFC 7009 §2.2.1의 근거가 있어서다.
- 위험 구역: auth.go(세션·쿠키·로그인 계약), oidc.go의 토큰·로그아웃 경로, middleware.go의 CSRF/API 키 예외, internal/store/migrations, .github/workflows/release.yaml.
- 자주 깨지는 곳: gofmt 정렬(lint 첫 실행), 빌드가 바꾸는 webui/dist/index.html(되돌릴 것), LDAPS bind mount와 CA 경로 불일치, 추측한 HTTP 상태 코드, 유지보수 SQL 문장 순서를 잠근 store 테스트(TestIntegrationTheRetentionSweepSaysOnlyWhatItSkipped).
- 검증 함정:
  - 환경변수가 없으면 연동 테스트가 SKIP인데도 종료 코드는 0이다. `make test` 끝의 "integration test(s) did not run" 경고 유무를 눈으로 확인할 것.
  - make test는 SKIP 집계용으로 연동 명령을 한 번 더 돌린다(중복 실행).
  - CI verify는 세 서비스를 준비하지만 release.yaml은 PostgreSQL만 준비한다. CI lint는 npm 설치 전에 돌고, 로컬 make lint는 GO_PACKAGES로 vendored Go를 제외한다.
  - 통합 테스트의 로그 단언은 `lockedBuffer`(integration_test.go:6901, 사용처 6982·7203·9479). 저장소 장애 재현은 테이블 RENAME으로 한다(선례 2898·3700·7144·8092) — 되돌리는 cleanup 필수.
  - Docker는 이 환경에서 실행 가능(2026-09-21). 기존 컨테이너 재사용만 검증됐고 깨끗한 환경의 신규 생성·삭제는 미확인.
