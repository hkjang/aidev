# seaton 프로필 (2026-09-28)
- 목적: 사무실 도면 위 좌석을 편집하고 직원을 배정·검색하는 오프라인 우선 SeatOn 서비스.
- 스택: Go 1.24.0 모듈 / chi v5·pgx v5·go-oidc v3·excelize / PostgreSQL 14+(CI 는 16-alpine) / React 19·TypeScript·MUI v7·Vite·Vitest 3·Playwright·react-router-dom.
- 구조:
  - `cmd/seaton/`: 서버 진입점. Docker 빌드에서 프런트 dist 를 임베드.
  - `internal/app/`: HTTP 핸들러 전부. `server.go`(라우터 — 인증 그룹 / `requireSeatManager` 그룹이 중첩), `auth.go`(세션·CSRF·OIDC·returnTo), `seats.go`, `maps.go`, `employees.go`(조직+직원+가져오기), `dashboard.go`, `grid.go`, `detection.go`, `vlm.go`, `mcp.go`·`mcpoauth.go`, `keys.go`, `settings.go`, `sync.go`, `tracking.go`, `openapi.go`.
  - `internal/database/`: pgx pool 과 `migrations.sql` — 시작 시 적용, 별도 버전 마이그레이션 도구 없음.
  - `internal/platform/`(환경변수·설치별 암호화 키), `internal/tracking/`(nonce·스니펫·CSP).
  - `web/src/App.tsx`: 라우팅과 `Protected`/`Manager` 가드(`admin/*` 는 `Manager`). `web/src/auth.tsx`: 세션·config·조용한 SSO.
  - `web/src/pages/`: 9개 화면. `web/src/lib/`: 화면 규칙 + 짝 단위 테스트 10쌍(`seats`·`silentSso`·`seatMapLink`·`employeeExport`·`format`·`users`·`color`·`mapView`·`tracking`·`mcpOAuth`).
  - `web/e2e/`: 실서버 Playwright 18 spec + `helpers.ts`·`seed.mjs`·`global-setup.ts`·`guide-shots.mjs`.
  - `docs/`: Markdown 정본과 생성 HTML/PDF·캡처. `scripts/`: 문서 생성·이미지 릴리즈.
- 빌드·테스트:
  - `go test ./...` / `go vet ./...` / `gofmt -l .` — Go 테스트는 analyzer·auth·mcpoauth·tracking·vlm 뿐이고 **DB 를 붙인 테스트 하네스가 없다**(핸들러 SQL 은 단위 테스트로 증명 불가).
  - `cd web && npm ci && npm run lint && npm test && npm run build` (`lint` = `tsc -b --pretty false`, `test` = `vitest run` — 현재 142건, `build` = `tsc -b && vite build`).
  - E2E: `docker build -t seaton:e2e .` → PostgreSQL 16 과 함께 기동 → `cd web && E2E_BASE_URL=… E2E_USERNAME=admin E2E_PASSWORD=… npx playwright test [spec]`. 준비 포함 수 분~10분+, workers=1.
  - `python3 scripts/build-docs.py <이름>` 으로 해당 HTML 만 생성. PDF 는 aidev 공용 md2pdf.
- 관례: 커밋 메시지는 한국어 `feat:`/`fix:`/`docs:`/`test:`/`chore:` 접두. CLAUDE.md/AGENTS.md 없음, TODO/FIXME 없음. 설정은 `POSTGRES_DSN`·`BOOTSTRAP_ADMIN`·`BOOTSTRAP_ADMIN_PASSWORD` 로 시작하고 기능 설정은 settings 테이블. 오류 계약은 `{error:{code,message}}`.
- 관례: **값 규칙은 `web/src/lib/` 한 파일에 두고 읽는 쪽·쓰는 쪽이 모두 import 한다.** 09-26·09-27 세 회차가 이 처방으로 닫혔다(`silentSso.ts`, `seatMapLink.ts`, `employeeExport.ts`).
- 현재 기준: main@7502f82 (v1.4.11). 좌석 구역 지정·배정 해제 단추·좌석 상세 소속/지정구역 분리·로그인 returnTo·좌석맵 URL 상태·직원 CSV 내보내기는 모두 머지되어 **더는 결함이 아니다**.
- 계약 메모: `GET /api/v1/employees` 는 `q`·`organizationId`·`status`(active|leave|retired)·`assignment`(assigned|unassigned)·`limit`(≤500, 기본 100)을 받고 `total` 은 주지 않는다(`employees.go:60-83`). `GET /api/v1/organizations` 는 인증만 요구(`server.go:82`).
- 계약 메모: `seats.go` createSeat 는 organizationId 미지정 시 null/생략(빈 문자열 금지), updateSeat 는 빈 문자열이 해제·null/생략이 보존. `Seat.organizationName` 은 지정 구역, `employeeOrganizationName` 은 실제 직원 소속이고 색은 직원 소속 우선.
- 계약 메모: OIDC 는 `/api/v1/auth/oidc/start?returnTo=&prompt=` → oidc_states → callback. 서버가 `safeReturnTo` 로 양쪽 검증(`auth.go:299-301,442-445`). 클라이언트 짝은 `web/src/lib/silentSso.ts`.
- UI 메모: MUI v7 `Select` 는 `inputProps={{ "aria-label": … }}` 로 접근 가능한 이름이 붙고 `getByRole("combobox", { name })` 로 잡힌다 — `UsersPage.tsx:260` ↔ `admin.spec.ts:150` 이 통과 중인 실제 증거. 이름 없는 Select 는 `filter({ hasText })` 로 집을 수밖에 없다(`employee-export.spec.ts:52-55`).
- 씨드 메모: `web/e2e/seed.mjs` 는 조직 3개(개발팀·영업팀·인사팀), 직원 10명(개발6·영업2·인사2)을 만들고 **전원에게 좌석을 배정**하며 앞줄 좌석 5개에 개발팀 구역을 지정한다(영업팀 직원 1명이 섞여 "구역 불일치" 도 검증된다). 도면은 하나뿐 — 도면 선택 분기는 vitest 로만 증명할 수 있다.
- 위험 구역: `internal/app/auth.go`(세션·CSRF·OIDC·권한), `mcpoauth.go`·MCP 범위 검사, `internal/database/migrations.sql`(시작 시 적용), `internal/tracking/` CSP 와 도면 PDF 렌더링, `.github/workflows`(릴리즈 경로 — 운영자 규칙상 릴리즈까지 통과 확인 필요).
- 자주 깨지는 곳: E2E 가 좌석·배정을 복구하지 않으면 뒤 테스트가 연쇄로 깨진다(`helpers.restoreSeat` 는 좌표만 복구 — 구역은 finally 에서 별도 PATCH). `helpers.ts:14` 는 로그인 뒤 경로가 `/login` 으로 시작하지 않을 때까지 기다리므로 로그인 리다이렉트를 바꾸면 전부 멎는다.
- 자주 깨지는 곳: 같은 값을 두 경로가 따로 읽어 어긋난 전례가 반복된다(좌석 상세 '조직' vs 도면 색, '구역 불일치' 문구의 seatSpeech/seatOrgDetail 이중 정의, CSV 열 이름 vs 가져오기 파서). 위의 `web/src/lib/` 관례로 닫을 것.
- 자주 깨지는 곳: 목록 핸들러 다수가 `if rows.Scan(...) == nil` 로 오류를 삼키고 루프 뒤 `rows.Err()` 를 보지 않는다(`employees.go:22/78`, `seats.go:36`, `maps.go:27/72/126`, `keys.go:28`, `mcp.go:113/127/153`). 올바른 꼴은 `grid.go:150-158`.
- 검증 함정: Go 단위 테스트 통과는 UI/DB 배선을 증명하지 않는다. 실제 기능은 Docker 이미지 + PostgreSQL + 브라우저로 보고, **변경 전 이미지(`git archive` → `seaton:e2e-before`)에서 새 spec 이 붉은 것을 먼저 확인**하는 역검증이 최근 성공 회차 네 번(09-23·24·26·27)의 공통 방식이다.
- 검증 함정: `tracking`·`mcp-oauth` spec 7~8건은 수집기 호스트·가짜 Keycloak 미기동으로 **원래 실패한다**. 매 회차 구전으로 판정해 왔다 — 변경 전 이미지에서도 같은 수가 실패함을 함께 적을 것.
- 검증 함정: CI/Docker 는 Node 24, 로컬은 v22.23.1. Go 는 모듈·Docker 1.24, 로컬 go1.26.7.
- 검증 함정: `compose.yaml` 은 외부 DB 를 전제하고 이미지를 빌드하지 않는다. Playwright 기본 URL 은 127.0.0.1:18781, CI 는 8080이며 `globalSetup` 은 서버를 띄우지 않고 실서버를 시드한다. CI E2E 는 `--network host`(브리지로 돌릴 땐 `E2E_COLLECTOR_HOST` 와 `--add-host` 필요).
