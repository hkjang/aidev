(2) 리소스 식별자: `mcp.oauth.resource` → 비면 `PUBLIC_BASE_URL`+`/mcp`(handoff·mail 이 이미 쓰는 공개 주소) → 둘 다 없으면 **Host 헤더로 만들지 않고** 꺼진 것처럼 동작하며 저장 시점에 거절한다(postra 방식; 표준이 Host 를 "마지막 수단" 으로만 허용해 아예 뺐다). 식별자는 `/mcp` 로 끝나야 저장된다. (3) 인증 체인: `/mcp` 는 이제 별도 체인(dev → 세션 → **`mcpoauth.Authenticator`** → API 키)을 타고 웹 로그인용 `OIDCAuthenticator`(계정 upsert · role 승격) 는 `/mcp` 에서 빠졌다 — 지금까지는 OIDC 가 켜진 배포에서 realm 의 아무 토큰이나 `/mcp` 와 REST 를 열고 계정을 만들었다. 새 인증기는 서명(RS/ES/PS, `HS`·`none` 거절)·`iss`·`exp`·`nbf`·`typ=ID`·`cnf`·`sub` 를 보고, 대상은 `aud` 에 리소스 식별자 **또는** `aud`/`azp` 가 `mcp.oauth.audience` 에 있어야 하며(웹 클라이언트 ID 는 자동 허용 안 함, 표준 그대로), 거절 메시지에 본 `aud`/`azp` 와 고칠 값을 넣는다(`auth.Refusal` 타입: 클라이언트용 문장 + 원인, 원인은 MCP 미들웨어의 새 `OnError` 로 `authentication failed … path=/mcp` 에 남는다 — 이전엔 MCP 인증 실패가 로그에 전혀 안 남았다; 캠페인 규칙대로 소스로 확인한 뒤 가이드에 적었다). 계정은 새 `store.GetUserBySubject` 로 이미 등록된 것만 찾고(웹 로그인이 `sub` 로 등록하므로 이메일 매칭은 하지 않음), 없으면 "웹으로 먼저 로그인", 정지면 거절, role 은 계정 행에서. 범위는 `mcp.oauth.scopes`(키 어휘, 관리자 범위 불가) + 자동 `mcp:use`, 토큰 `scope` 가 이 어휘를 실어 오면 교집합; `allowScope` 가 `mcp_oauth` 도 키처럼 범위를 강제한다.
