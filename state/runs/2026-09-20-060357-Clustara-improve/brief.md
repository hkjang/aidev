- 과제: SEC-01 Pod Security 결과에 `cluster_id` 가 없어 UI YAML 딥링크가 빈 클러스터로 가고, DW security_finding·notify scan 이 전 클러스터 실행에서 요청 파라미터의 빈 cluster_id 를 쓰는 결함 3종 (가치 3 / 위험 1 / 작업량 S)
- 왜: `analyzer.PodSecurityResult`(internal/analyzer/security.go:65) 는 Namespace/Kind/Name/Level/Violations 만 있고 ClusterID 가 없는데, 관리 UI 의 Pod Security 표(internal/proxy/admin_ui.go:13460-13462)는 이미 `p.cluster_id` 를 읽어 `k8sYamlChangeLink` 를 만들고 있어 전 클러스터 보기(`/admin/k8s/security` 는 cluster_id 선택 파라미터)에서 모든 행의 YAML/토폴로지 링크가 빈 cluster_id 로 나간다 — v0.9.282 에서 rbacDiffEntry 에 같은 결함을 고친 것과 동일한 모양. 같은 뿌리로, `k8sSecurityRows`(admin_k8s_dw.go:64-82)는 finding 이 이미 가진 `f.ClusterID`(SecFinding, v0.9.278 이후) 를 무시하고 요청의 `clusterID` 를 모든 행에 적어, cluster_id 없이 `/admin/k8s/dw/sink` 를 돌리면 change/event/workload_health 행은 실제 클러스터를 갖는데 security_finding 행만 `cluster_id=""` 로 적재되어 `/admin/k8s/dw/report?cluster_id=X` 의 `AND cluster_id = 'X'` 필터에서 보안 행이 통째로 사라진다; `handleK8sNotifyScan`(k8s_notify.go:103-143) 도 dedup 키 `clusterID+"|"+dedupKey`·`GetK8sNamespaceOwner(clusterID, ns)`·`k8sDeepLink(..., clusterID, ...)` 전부 요청 파라미터를 써서 전 클러스터 스캔이면 두 클러스터의 동명 워크로드가 하나로 dedup 되고 딥링크·담당팀 라우팅이 빈 클러스터로 간다.
- 수용 기준:
  1) `PodSecurityResult` 에 `ClusterID string \`json:"cluster_id,omitempty"\`` 가 추가되고 `classifyPodSecurity` 가 `it.ClusterID` 를 채운다 — `/admin/k8s/security` 응답의 `pod_security[].cluster_id` 가 인벤토리 항목의 클러스터와 같다(단일 클러스터 요청에서도 채워짐; 기존 UI 코드가 그대로 동작).
  2) `k8sSecurityRows` 가 RBAC/Images/Secrets/Network 행은 `f.ClusterID`, pod_security 행은 `p.ClusterID` 를 쓰고, 그 값이 비어 있을 때만 요청의 `clusterID` 로 폴백한다 — cluster_id 없이 sink 하면 각 security_finding 행이 자기 클러스터를 갖는다.
  3) `handleK8sNotifyScan` 의 `notify` 클로저가 finding 별 cluster 를 받아 dedup 키·namespace owner 조회·딥링크에 그 값을 쓴다(비어 있으면 요청 clusterID 폴백). RCA 후보(`analyzer.RCACandidate` — ClusterID 필드 유무는 미확인, 있으면 같이 넘기고 없으면 요청 clusterID 유지).
  4) 테스트: (a) analyzer — 두 클러스터의 동명 Deployment 를 `AnalyzeSecurity` 에 넣어 `PodSecurity[i].ClusterID` 가 각각 채워짐. (b) proxy `TestK8sFactRowBuilders` 확장 또는 신규 — SecFinding{ClusterID:"dr"}·PodSecurityResult{ClusterID:"dr"} 를 `k8sSecurityRows(ts, "", sec)` 로 넘겨 행의 `cluster_id=="dr"` 이고, `k8sSecurityRows(ts, "c1", {ClusterID:""})` 는 `"c1"` 폴백. 고치기 전 코드에서 (a)(b) 가 실패함을 확인해 노트에 적을 것. (c) 가능하면 notify scan 종단 테스트 — 기존 테스트 인프라(`newTestServer` 류, k8s_notify_test.go 는 순수 함수만 테스트 중이라 핸들러 픽스처는 미확인)로 두 클러스터 privileged Pod 를 넣고 Mattermost webhook 을 httptest 로 받아 두 건이 모두 전송되고 각 링크에 자기 cluster_id 가 있는지 확인. 픽스처가 없으면 (c) 는 생략하고 노트에 적는다 — 대역 주입으로 대체하지 말 것.
