# PR #12 fix summary (commit 808124a on the PR branch)

- **Reproduced all three findings**: a throwaway test showed `GET /momento/../admin/secret` (and `%2e%2e`) reaching the upstream as `/base/../admin/secret`; `'unsafe-inline'` / `*` passed the `tracking.allowed_hosts` validator and appeared in `script-src`; `handleAllowTrackingHost` built on `trackingConfig()`, which returns an empty config on a failed `SettingsMap` read.
- **Proxy** (`tracking_handlers.go`): new `momentoProxyPath` rejects (404) any `/momento/*` path that `path.Clean` would rewrite (`..`, `.`, `//`), and `RawPath` is rebuilt from the checked path so encoded dots cannot bypass it; `TestMomentoProxyStaysUnderCollectorBase` covers literal/encoded traversal plus legitimate paths.
- **Allow click** (`tracking_handlers.go`, `server.go`): split `readTrackingConfig` (returns the error) from `trackingConfig` (page-render fallback); the handler now answers 503 `settings_unavailable` on a read failure instead of persisting only the new origin, and a per-process `sync.Mutex` serialises the read-modify-write so two concurrent clicks cannot drop each other (cross-instance races would need a store-level CAS; not added to keep the change inside the PR's scope). Test `TestAllowTrackingHostRefusesToBuildOnFailedRead` uses a pool on a closed port.
- **allowed_hosts validation** (`settings_handlers.go`, `tracking.go`): replaced `stringLimit(4096)` with `trackingAllowedHosts`, which accepts only `http(s)://host[:port]` (optional `*.` label, ≤100 entries) and refuses keywords, bare `*`, scheme sources, paths, userinfo; `SplitHosts` exported so validator and policy builder read the list identically. Both `PUT /admin/settings` and the allow click go through this spec. Docs updated to state the accepted format and the proxy's `..` refusal.
- **Verification**: `go build ./...`, `go vet -tags=integration ./...`, `go test ./...`, and `go test -race -p=1 -tags=integration` on `internal/httpapi` + `internal/tracking` all pass; gosec/govulncheck were not installed locally and were not run. No web files touched, so the npm suite was not rerun.
