# v0.266.0

## 두 목록 비교에서 `'Bob''s Data'!A1:B2` 처럼 적은 시트 이름을 찾습니다

편집기의 **두 목록 비교**는 지금 자리의 자료 덩어리와 사람이 적어 주는
범위를 견줍니다. 다른 시트를 견주려면 시트 이름 뒤에 느낌표를 붙여
`장부!A1:C100` 처럼 적습니다. 이름에 빈칸이 있으면 따옴표로 감싸는 것이
스프레드시트의 버릇이고, 감싼 안쪽의 작은따옴표는 **두 번 적어** 한 개를
나타냅니다 — `Bob's Data` 라는 시트는 `'Bob''s Data'` 입니다.

이 표기는 kanpic 이 스스로 가르치는 표기입니다. 수식에서 시트를 가리킬 때
`internal/formula/reference.go` 가 이름을 적을 때 `'` 를 `''` 로 적고,
`structure.go` 의 `quotedQualifier` 가 읽을 때 되돌립니다. 그런데 비교
범위를 읽는 자리만 **바깥 따옴표만 벗기고 안쪽을 되돌리지 않았습니다.**
그래서 수식 바에서 본 그대로 적으면 시트 이름이 `Bob''s Data` 로 나왔고,
그런 이름의 시트는 없으므로 입력이 거절됐습니다.

```
시트!A1:C100 꼴로 적어 주세요. 시트 이름이 맞는지도 확인하세요.
```

범위도 시트 이름도 맞게 적었는데 거절되므로, 받으신 쪽에서는 무엇이
틀렸는지 알 길이 없었습니다.

| 적으신 범위 | 전 | 이제 |
| --- | --- | --- |
| `'Bob''s Data'!A1:B2` | 거절 | `Bob's Data` 시트의 A1:B2 |
| `'O''Brien'!A1:B2` | 거절 | `O'Brien` 시트의 A1:B2 |
| `Bob's Data!A1:B2` | 전에도 됐습니다 | 그대로 |
| `A''B!A1:B2` | `A''B` 시트 | 그대로 |
| `''!A1:B2` | 거절 | 그대로 거절 |

따옴표로 **감싼 경우에만** 안쪽을 되돌립니다. 감싸지 않은 이름은
`quotedQualifier` 와 마찬가지로 글자 그대로가 시트 이름이므로,
`A''B` 라는 이름의 시트를 적는 길이 막히지 않습니다. 따옴표 없이
`Bob's Data!A1:B2` 로 적던 길도 전과 똑같이 됩니다 — 그 길은 전에도
거절되지 않았고, 이번 변경이 지나가지 않습니다.

## 그 밖에 바뀌는 것은 없습니다

- **마이그레이션도, 새 설정도 없습니다.** 서버 코드와 SQL·스키마는 한 줄도
  손대지 않았습니다. 바뀐 것은 웹 쪽에서 "시트!범위" 한 줄을 나누는
  함수뿐입니다.
- **Go 쪽 수식 파서는 손대지 않았습니다.** `internal/formula` 는 전부터
  `''` 를 제대로 되돌렸습니다. 이번 변경은 웹 입력을 그 규칙에 맞춘
  것입니다.
- **마지막 느낌표에서 자르는 규칙은 그대로입니다.** 이름에 느낌표가 든
  시트(`1분기!실적`)를 고르는 길이 전과 같습니다.
- **빈 이름은 그대로 거절합니다.** `''!A1:B2` 처럼 따옴표 안이 빈 입력은
  전과 같이 받지 않습니다.
- 비교 결과를 내는 쪽(키 읽기, 한쪽에만 있는 행, 중복·빈 칸 세기)과 범위를
  읽는 `parseFilterRange` 는 한 줄도 바뀌지 않았습니다. 기존 검사
  스무 개가 그대로 통과합니다.

## 아직 남아 있는 것

비교 대화상자가 미리 채워 주는 범위는 시트 이름을 **따옴표로 감싸지
않습니다.** 그래서 시트 이름 자체가 따옴표로 시작하고 끝나는 드문
경우(`'q1'` 이라는 이름)에는 미리 채워진 값이 감싼 이름으로 읽혀 시트를
못 찾습니다. 이번 릴리즈로 달라진 것이 없는, 전부터 있던 자리입니다 —
감싸 적는 쪽을 웹에서 만들려면 Go 의 `sheetQualifier` 와 같은 규칙을
웹에도 두어야 하고, 그것은 표기를 정하는 일이라 따로 다룹니다. 그런
이름을 쓰고 계시면 미리 채워진 값 대신 손으로 `'''q1'''!A1:C100` 처럼
감싸 적으시면 찾습니다.

## 확인

- 손으로 만든 대역 없이 **프로덕션 `splitSheetRange` 만** 불러, 감싼
  따옴표 안의 `''`·감싸지 않은 `''`·빈 따옴표 이름을 검사로 못 박았습니다.
- 고치기 전에는 이 검사가 다음과 같이 실패했습니다.

  ```
  FAIL src/lib/compareLists.test.ts > splitSheetRange >
    reads a doubled quote inside the quotes as one quote
  AssertionError: expected 'Bob\'\'s Data' to be 'Bob\'s Data'
    Expected: "Bob's Data"
    Received: "Bob''s Data"
  Tests  1 failed | 20 passed (21)
  ```

  고친 뒤 스물한 개가 통과하고, 바뀐 그 한 자리만 전 판으로 되돌리면
  **정확히 새 검사 한 개만** 같은 출력으로 다시 실패합니다. 새 검사가
  바뀐 경로를 실제로 지난다는 뜻입니다.
- 따옴표 없는 경로를 건드리지 않았다는 증거로, 경계 검사(`A''B`·
  `O'Brien`·빈 이름 `''`)는 **고치기 전에도 통과**했습니다.
- 릴리즈 준비에서 `npm run lint`(tsc -b, 출력 없음), `npm test`(74개
  파일 523개 검사 전부 통과), `npm run build`(성공, 전부터 있던 chunk
  경고만), `go build ./...`, `go vet ./...`,
  `go vet -tags=integration ./internal/...`,
  `gofmt -l ./cmd ./internal ./pkg`(출력 없음), `go test ./...`(테스트가
  있는 19개 패키지 전부 통과, 실패 없음), `scripts/check-release-docs.sh`,
  `scripts/check-commit-identities.sh` 를 실행했습니다.
- **DB 통합 테스트와 브라우저 E2E 는 이번 릴리즈 준비에서 돌리지
  않았습니다.** 준비 환경에 Postgres 와 브라우저가 없었습니다. 변경은
  문자열 한 줄을 나누는 순수 함수이고 API·SQL·화면 코드는 손대지
  않았으므로, 이 둘은 태그를 올린 뒤 CI 에서 돕니다.

## 올리실 때

v0.265.0 에서 올라오시는 분은 이미지를 바꿔 다시 띄우시면 됩니다.
마이그레이션이나 새 설정은 없고, 필수 환경 변수는 계속 `POSTGRES_DSN`
입니다. 웹 자산은 이미지에 함께 들어 있으므로 이미지를 바꾸면 그대로
바뀝니다.

올린 뒤 시트 이름에 작은따옴표가 든 시트를 두 목록 비교에서 수식 바
표기대로 적어 찾히는지 한 번 보시면 됩니다. 되돌리셔도 스키마도 설정도
바뀌지 않으므로 v0.265.0 이미지로 그대로 돌아갑니다 — 돌아간 뒤에는 감싸
적은 이름이 다시 거절됩니다.

## 오프라인 설치

이 릴리즈는 웹 자산과 서버 바이너리를 포함한 Docker 이미지 아카이브로 제공됩니다.

```bash
sha256sum -c kanpic-v0.266.0.tar.gz.sha256
gzip -dc kanpic-v0.266.0.tar.gz | docker load
docker run --rm -p 8080:8080 \
  -e POSTGRES_DSN='postgres://kanpic:password@postgres.internal:5432/kanpic?sslmode=require' \
  kanpic:v0.266.0
```

- 필수 런타임 환경 변수: `POSTGRES_DSN`
- Redis 및 외부 인터넷 연결: 불필요
- 관리자 초기 로그인을 보호하려면 `BOOTSTRAP_ADMIN_ID`와 `BOOTSTRAP_ADMIN_PASSWORD`를 함께 지정합니다.
- 무결성 검증 파일: `kanpic-v0.266.0.tar.gz.sha256`
