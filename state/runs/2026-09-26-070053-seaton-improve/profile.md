# seaton 프로필 (2026-09-26)
- 목적: 사무실 도면 위 좌석을 편집하고 직원을 배정·검색하는 오프라인 우선 SeatOn 서비스.
- 스택: Go 1.24.0 모듈 / chi v5·pgx v5·go-oidc v3·excelize / PostgreSQL 14+(CI 는 16-alpine) / React 19·TypeScript·MUI·Vite·Vitest·Playwright·react-router-dom.
- 구조:
  - `cmd/seaton/`: 서버 진입점. Docker 빌드에서 프런트 dist 를 임베드.
  - `internal/app/`: HTTP 핸들러 전부. `auth.go`(세션·CSRF·OIDC start/callback·returnTo), `seats.go`, `maps.go`, `employees.go`, `dashboard.go`, `grid.go`, `detection.go`(CV), `vlm.go`, `mcp.go`·`mcpoauth.go`, `keys.go`, `settings.go`, `tracking.go`, `openapi.go`.
  - `internal/database/`: pgx pool 과 migrations.sql — 시작 시 스키마 적용, 별도 버전 마이그레이션 도구 없음.
  - `internal/platform/`(환경변수·설치별 암호화 키), `internal/tracking/`(nonce·스니펫·CSP).
  - `web/src/App.tsx`: 라우팅과 `Protected`/`Manager` 가드. `web/src/auth.tsx`: 세션·config·조용한 SSO 기동.
  - `web/src/pages/`: 화면(SeatMapPage·MapsPage·EmployeesPage·SettingsPage·UsersPage·KeysPage·LoginPage 등). `web/src/lib/`: 화면 규칙 + 짝 단위 테스트(`seats.ts`, `silentSso.ts` 등).
  - `web/e2e/`: 실서버 Playwright 18개 spec + `helpers.ts`(로그인·복구), `seed.mjs`, `global-setup.ts`, `guide-shots.mjs`.
  - `docs/`: Markdown 정본과 생성 HTML/PDF·캡처. `scripts/`: 문서 생성·이미지 릴리즈.
- 빌드·테스트:
  - `go test ./...` / `go vet ./...` / `gofmt -l .` — Go 테스트는 analyzer·auth·mcpoauth·tracking·vlm 뿐이고 **DB 를 붙인 테스트 하네스가 없다**(핸들러 SQL 은 단위 테스트로 증명 불가).
  - `cd web && npm ci && npm run lint && npm test && npm run build` (`lint` 는 tsc 타입 검사).
  - E2E: `docker build -t seaton:e2e .` → PostgreSQL 16 과 함께 기동 → `cd web && E2E_BASE_URL=... E2E_USERNAME=admin E2E_PASSWORD=... npx playwright test [특정 spec]`. 준비 포함 수 분~10분 이상, workers=1.
  - `python3 scripts/build-docs.py <이름>` 으로 해당 HTML 만 생성. PDF 는 aidev 공용 md2pdf.
- 관례: 커밋 메시지는 한국어 `feat:`/`fix:`/`docs:`/`test:`/`chore:` 접두. 저장소에 CLAUDE.md/AGENTS.md 없음, TODO/FIXME 없음. 설정은 `POSTGRES_DSN`·`BOOTSTRAP_ADMIN`·`BOOTSTRAP_ADMIN_PASSWORD` 로 시작하고 기능 설정은 settings 테이블. 오류 계약은 `{error:{code,message}}`.
- 현재 기준: main@d81edf2 (v1.4.8). 좌석 구역 지정·배정 해제 단추·좌석 상세의 소속/지정구역 분리(e6f4f70)는 모두 머지되어 **더는 결함이 아니다**.
- 계약 메모: `seats.go` createSeat 는 organizationId 미지정 시 null/생략(빈 문자열 금지), updateSeat 는 빈 문자열이 해제·null/생략이 보존. `Seat.organizationName` 은 지정 구역, `employeeOrganizationName` 은 실제 직원 소속이고 색은 직원 소속 우선.
- 계약 메모: OIDC 로그인은 `/api/v1/auth/oidc/start?returnTo=&prompt=` → oidc_states 테이블 → callback 리다이렉트. 서버가 `safeReturnTo` 로 start·callback 양쪽에서 검증한다(`auth.go:299-301`, `442-445`). 클라이언트 짝은 `web/src/lib/silentSso.ts`.
- 위험 구역: `internal/app/auth.go`(세션·CSRF·OIDC·권한), `mcpoauth.go`·MCP 범위 검사, `internal/database/migrations.sql`(시작 시 적용), `internal/tracking/` CSP 와 도면 PDF 렌더링, `.github/workflows`.
- 자주 깨지는 곳: E2E 가 좌석·배정을 복구하지 않으면 뒤 테스트가 연쇄로 깨진다(`helpers.restoreSeat` 는 좌표만 복구 — 구역은 finally 에서 별도 PATCH). `helpers.ts:14` 는 로그인 뒤 경로가 `/login` 으로 시작하지 않을 때까지 기다리므로 로그인 리다이렉트를 바꾸면 전부 멎는다.
- 자주 깨지는 곳: 같은 값을 두 경로가 따로 읽어 어긋난 전례가 반복된다(좌석 상세 '조직' vs 도면 색·툴팁, '구역 불일치' 문구의 seatSpeech/seatOrgDetail 이중 정의). 값 규칙은 `web/src/lib/` 한 곳에 두고 양쪽이 import 할 것.
- 자주 깨지는 곳: 목록 핸들러 다수가 `if rows.Scan(...) == nil` 로 오류를 삼키고 루프 뒤 `rows.Err()` 를 보지 않는다(`seats.go:36`, `maps.go:27/72/126`, `employees.go:22/78/293`, `keys.go:28`, `mcp.go:113/127/153` 등). 올바른 꼴은 `grid.go:150-158`.
