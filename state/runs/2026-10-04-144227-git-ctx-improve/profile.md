- 자주 깨지는 곳:
  - 포매터(format.go)와 그 출력을 다시 파싱하는 소비자(budget.go 의 `sectionCount`·`cutAtBoundary`·`closeOpenFence`, dispatch.go 의 `retrievalMode`)의 계약 불일치 — 2026-09-28·09-29·10-01·10-03 네 회차가 모두 이 계열이다. 이제 `lineFence` 가 펜스 인식을 공유하지만 **코드 검색의 `#### ` 집계는 일부러 바이트 스캔**이다(대조군 테스트가 그 판단을 고정).
  - 바이트 예산 절단이 UTF-8 문자를 반으로 자름 — mcp·search·source·embedding·vectorstore 다섯 곳에서 각각 고쳤다.
  - 마스킹이 비밀 아닌 내용·개행을 삭제함. 콜백만 바꾸면 Revision 이 같아 구색인 미갱신.
  - 하드코딩된 고정 주기가 테스트 벽시계를 만든다(worker 2s → 고쳐짐, notification 10s → 남음).
  - manifest 파서 확장은 사람 반려 이력 유형.
- 검증 함정:
  - `internal/app` 테스트 시간은 같은 커밋에서도 흔들린다(과거 100~117s). 성능 비교는 반드시 같은 세션에서 두 번 재고, 원인은 되돌림 프로브로 증명할 것.
  - mcp fixture(`server_test.go:22`)와 app fixture 는 공유 in-memory SQLite 이름을 쓰므로 새 테스트에 `t.Parallel()` 금지. 헬퍼: `fixture(t)`, `call(t,s,body)`, `callAs`, `answerText`; app 쪽은 `waitFor(t, 90s, …)`(200ms 폴링, 상한·폴링 건드리지 말 것)·`mcpCall`·`testWorkerPoll`.
  - `s.search` 는 인터페이스가 아닌 구체 타입이라 검색 호출을 스파이할 수 없다. 대역을 억지로 넣지 말고 관측 가능한 단언(감사 행, 응답 텍스트)을 찾을 것.
  - 합성 문자열 테스트가 프로덕션에 없는 모양을 고정해 둔 자리가 있다(`truncation_test.go:57` 은 code-search 히트를 `### ` 로 쓴다 — 실제는 `#### `). 재현은 항상 실제 `ServeHTTP` 왕복으로.
  - `truncation_test.go:31` 은 `budget+responseNoticeBytes` 까지 허용한다 — "응답이 예산을 넘지 않는다"는 고정 계약이 아니다.
  - `encoding/json` 은 U+FFFD 를 이스케이프로 쓴다 — 원문자 검사는 무의미. 히어독은 유니코드 이스케이프를 뭉개므로 테스트 소스는 Write/Edit 로, needle 은 조립할 것.
  - CI 통합은 GIT_CTX_TEST_POSTGRES_DSN·GIT_CTX_TEST_PGVECTOR_DSN·GIT_CTX_TEST_VAULT_URL/TOKEN 필요. 외부 DB·Vault·Docker·실브라우저는 이 환경에서 미검증(`replica_test.go:49` 의 복제 경쟁 테스트는 postgres 없이 SKIP).
  - `govulncheck` 는 로컬 `/home/hkjang/go/bin/govulncheck`(v1.7.0)로 실행 가능하고 CI 와 같은 두 줄을 재현한다. DB 가 매일 갱신되어 코드가 안 바뀐 태그도 갑자기 실패한다.
  - docs/test-plan 의 기본 `go test` 에는 FTS5 태그가 없지만 CI 는 태그 포함 suite 와 별도 build-mode 검증을 돈다.
