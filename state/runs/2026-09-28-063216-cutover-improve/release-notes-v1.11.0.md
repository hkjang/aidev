## KCB Cutover Dashboard v1.11.0

### 품질 개선
- **활동 데이터 저장·업로드 검증 규칙을 단위 테스트로 고정**: 관리 화면(`/admin`)의 활동 변경 저장(`PUT /api/activities`)과 `activity.json` 업로드(`POST /api/activities/import`)는 **서로 다른 화면이지만 같은 하나의 검증 관문**(`validateActivityImport`)을 통과합니다. 이 관문이 고아 항목·순환 참조·중복 id 같은 **깨진 작업 트리가 저장되는 것을 막는 유일한 방어선**인데, 지금까지 이 함수에는 **자동 테스트가 한 건도 없었습니다.** 검증 규칙을 건드리는 변경이 실수로 규칙을 무너뜨려도 아무도 즉시 알 수 없었고, 그 결과는 상황판 전체가 잘못된 트리를 그리는 형태로 뒤늦게 드러납니다.
  - 이제 이 검증 관문의 동작을 **16건의 단위 테스트로 고정**했습니다. 앞으로 검증 규칙이 의도치 않게 바뀌면 코드를 합치기 전에 테스트가 먼저 실패합니다.
  - 고정한 규칙: 정상 입력의 `id`·`parentId`·상황판 제목 **앞뒤 공백 제거**, **빈 작업 목록 허용**(v1.10.0 의 `최상위 작업 추가` 진입점이 이 동작에 의존합니다), 최상위 형식 오류 2종, 관계 오류마다 **어느 항목의 어느 항목이 잘못됐는지 가리키는 위치 정보**, 예전 표기 `진행중` 의 자동 정규화 건수, 오류 목록을 **50건까지만 보여 주고 생략 안내를 붙이는 상한**.
  - 테스트는 실제 `data/activity.json` 을 **읽지도 쓰지도 않습니다.** 운영 데이터와 완전히 분리된 평문 입력만 사용합니다.
- **화면과 API 의 동작은 달라지지 않았습니다.** 이번 릴리즈는 테스트 파일 1개 추가가 전부이며, 관리자와 사용자가 보는 화면·저장 결과·오류 문구는 v1.10.0 과 동일합니다.

### 알려진 사항
- 업로드한 JSON 에서 **어떤 작업이 자기 자신을 부모로 지정**(`parentId` 가 자기 `id` 와 같음)하면, 오류 목록에 `자기 자신을 부모로 지정할 수 없습니다` 와 `순환 참조` 두 문구가 **같은 항목에 대해 두 번** 표시됩니다. 자기참조 검사와 순환 검사가 서로 다른 단계에서 같은 문제를 각각 신고하기 때문입니다. **업로드가 거부되는 결과는 올바르며**, 안내 문구가 한 줄 중복될 뿐입니다. 이번 릴리즈는 현재 동작을 그대로 고정했고, 중복 제거는 다음 릴리즈에서 다룹니다.

### 검증
- 단위 테스트 `95건 / 30 스위트 전부 통과` (v1.10.0 의 79건 + 이번 16건)
- 타입 검사(`tsc --noEmit`) 통과, 린트(`eslint`) 오류 0건, 운영 빌드(`next build`) 성공

### 배포
폐쇄망 서버에서는 첨부된 `cutover-v1.11.0.tar.gz` 를 옮겨 이미지로 불러온 뒤 실행합니다.

```bash
docker load -i cutover-v1.11.0.tar.gz

docker run -d -p 3000:3000 \
  -e USER_PASSWORD=1234 \
  -e ADMIN_PASSWORD=admin1234 \
  -e AUTH_SECRET=운영환경용-충분히-긴-임의문자열 \
  -v cutover-data:/app/data \
  --name cutover-app \
  --restart always \
  cutover:v1.11.0
```

v1.10.0 에서 올라오는 경우 **데이터 변환이나 설정 변경은 필요 없습니다.** 기존 `cutover-data` 볼륨을 그대로 붙이면 됩니다.
