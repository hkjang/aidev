- 과제: 채널 보기 목록·생성·시간대 조회의 멤버십 DB 오류를 403에서 500으로 분리 (가치 2 / 위험 1 / 작업량 S)
- 왜: `compat_wave_handlers_final.go`의 `listChannelViews`, `createChannelView`, `listChannelTimezones`는 `channels.IsMember`의 오류를 버려 저장소 장애를 비멤버의 403으로 응답한다. 세 경로에서 오류를 먼저 처리하면 실제 권한 거부와 서버 장애를 구분하면서 정상 호환 응답을 보존할 수 있다.
- 수용 기준: 1) 세 핸들러 모두 IsMember 오류가 있으면 즉시 HTTP 500과 기존 apiError JSON 형식으로 끝나며 createChannelView의 성공 응답·감사 기록 경로로 진행하지 않는다. 새 500도 기존 오류 ID `api.context.permissions.app_error`를 유지하고 메시지는 고정된 `failed to check channel membership`으로 한다. 2) 정상 조회에서 비멤버와 없는 채널은 기존 403/`not a channel member`, 사용자 없음은 기존 401을 유지한다. 멤버는 목록·시간대 200 `[]`, 생성 201 및 기존 id/channel_id/user_id/create_at/update_at 필드를 유지한다. 3) 세 핸들러 각각에 대해 실제 channels.Service와 PostgreSQL을 거치는 HTTP 회귀 테스트로 401/403/정상 성공/DB 오류 500을 증명한다. 오류 분기만 검사하는 순수 함수 테스트·가짜 IsMember·소스 문자열 검사는 증거로 삼지 않는다. 수정 전에는 장애 사례 세 개가 403으로 실패해야 한다.
- 건드릴 파일: `server/internal/httpapi/compat_wave_handlers_final.go:listChannelViews`(현재 179행), `createChannelView`(200행), `listChannelTimezones`(287행 부근) — `ok, _`를 `ok, err`로 바꾸고 !ok 분기 앞에 동일한 500 조기 반환 추가. `server/internal/httpapi/channel_membership_errors_postgres_test.go`(신규 제안) — 세 프로덕션 핸들러를 실제 서비스에 연결한 표 기반 HTTP 테스트. 참고만 할 파일: `server/internal/channels/service.go:IsMember`(1077행, SELECT EXISTS 결과와 오류를 이미 별도로 반환), `server/internal/httpapi/native_operations_postgres_test.go:newOperationsTestDB`(전용 임의 스키마), `channel_scope_postgres_test.go:invokeChannelScopeHandler`(실제 요청·사용자 컨텍스트·chi 파라미터 구성), `sidebar_handlers_postgres_test.go:TestGetSidebarCategoryReports404OnlyForMissingRows`(실제 테이블 장애 패턴), `router.go`(GET/POST `/api/v4/channels/{channelID}/views`, GET `/api/v4/channels/{channelID}/timezones` 연결 확인).
