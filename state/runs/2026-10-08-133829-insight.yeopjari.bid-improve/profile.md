# 옆자리 인사이트 (insight.yeopjari.bid) 프로필 (2026-10-08)
- 목적: 회사 인증된 직장인과 기업을 연결하는 유료 리서치·제품 테스트 서비스이며 참여자 신원·회사 비공개가 핵심이다.
- 스택: TypeScript ESM, Node >=22, npm workspaces; React 19/Mantine 9/Vite; Postgres(Supabase 서울), Cloudflare Pages/Hyperdrive, cron Worker.
- 구조:
  - packages/core/src: HTTP pipeline/router, auth, routes, domain, settings, quota/audit, util, mail을 가진 공용 코어.
  - apps/server: 로컬 Node 서버와 bootstrap/set-password; apps/web: SPA routes/components/api/state.
  - functions/[[path]].ts: 운영 Pages 어댑터; workers/scheduler: 주기 작업 호출.
  - db/migrations: 0001_schema, 0002_security, 0003_alerts_activity, 0004_totp_replay.
  - packages/core/vendor/postgres: 패치된 postgres.js, Node/CF 사본을 각각 유지한다.
  - scripts: migrate/e2e/screenshots/harness/dev-reset/seed-demo/deploy-pages/smoke-prod/grant-admin 등.
  - engineering: architecture/security/design/performance. docs/, CLAUDE.md, 별도 로드맵 파일은 검색에서 발견되지 않았다.
- 빌드·테스트:
  - 준비 npm ci --no-audit --fund=false; npm run check = eslint + 3개 workspace typecheck + vitest run.
  - npm run test -- packages/core/src/__tests__/rules.test.ts 로 단일 파일 실행; npm run build = web + server.
  - 단위 파일은 rules, vendor-postgres, totp, gateway-role, shared-db-guard 5개. vitest는 packages/**/*.test.ts와 apps/**/*.test.ts 수집, Node 환경, timeout 20초.
  - README는 단위 56개/e2e 172개로 안내한다. 이번 정찰에서는 node_modules 부재로 vitest 실행 실패하여 현재 통과 수 미확인.
  - node scripts/e2e.mjs: 실제 Postgres 16(:55442)·개발 서버(:8789)·가짜 OAuth(:18999) 필요, 느림.
  - node scripts/screenshots.mjs [dir]: 실제 Chromium 필요, README 기준 85장, 느림. CI는 실행 직전에 Playwright Chromium 설치.
  - scripts/dev-reset.sh는 로컬 개발 DB 삭제·재생성 및 서버 재시작: 기존 DB 보존이 필요한 환경에서 실행 금지.
- 관례: 최근 커밋은 한국어 산문 한 줄(버전 머리말도 있음); 테스트 설명은 현재 영문도 많음. 설정 registry.ts/env.ts, 번호 SQL 추가, 설계 문서 engineering/.
- 최근 변경: 현재 cbc8cb5/package 0.1.3. 공유 DB gateway 로그인과 트랜잭션 role 전환, TOTP 재사용/시도 제한 보강, 계정 공용 메일 관문을 도입했다.
- 메일: Pages MAIL 바인딩으로 공용 mail-gateway를 거치며, 바인딩 부재/네트워크 예외 시 직접 Resend. SMTP/console 경로도 있다.
- 위험 구역:
  - auth/*, routes/sso.ts, http/pipeline.ts: session/CSRF/MFA/OAuth PKCE. 회사 이름을 받아오지 않는 계약.
  - db.ts, db/migrations, 배포·마이그레이션 스크립트: 공유 DB 역할/RLS 격리. gateway 연결에 트랜잭션별 서비스 role을 설정하며 운영 로그인 역할 변경 금지.
  - util/crypto.ts, payout_profiles, routes/admin.ts: 보상 수령 정보 봉인 및 열람 감사. 보호 대상 원문을 audit details에 넣지 않는다.
  - quota.ts:windowStart는 DB 유일 키 라벨이므로 변경 금지. retryAfterSeconds의 KST 경계 수정은 이전 회차에 완료.
  - vendor/postgres 및 cf 사본: 임의 업그레이드/통합 금지. Hyperdrive 쿼리 캐시는 RLS 신원 혼선 방지를 위해 OFF.
- 자주 깨지는 곳: 기록상 이전 quota 수정은 성공; 실제 반복 회귀 기록은 없음. npm install이 lockfile peer 표시를 흔든 사례가 있어 ci 사용.
- 검증 함정:
  - 이번 정찰에서는 node 22.23.1/npm 10.9.8 실행 가능: 과거 '실행 자체 승인 불가' 설명은 현재 맞지 않는다. node_modules가 없어 npm run test는 vitest: not found(127).
  - e2e/브라우저/운영 점검은 정찰에서 미실행. 배포·smoke-prod는 저장소 밖 자격 증명이 필요하므로 기본 로컬 검증으로 취급하지 않는다.
  - UI 캐시의 api.cached/prefetch와 time.ts의 kstWindowOn/overlaps/backoffMs는 현재 운영 호출처가 검색되지 않는다. 미사용 유틸 결함을 사용자 영향으로 단정하지 않는다.
  - parseLinks는 URL을 500자로 먼저 잘라 검증한다. 이번 과제는 길이 초과를 거절하도록 좁게 수정하고 실제 저장→조회로 검증하는 것이다.
