과제 안내에 넣은 긴 주소가 중간에서 잘려 저장되는 문제를 고쳤습니다.

## 고친 것

- 기업 담당자가 연구 과제 링크를 저장할 때, 공백·제어 문자를 정리한 주소가 500자를 넘으면
  자르지 않고 `validation_failed`(HTTP 400)로 거절합니다. 500자 주소는 원문 그대로 보존합니다.
- 빈 항목 뒤에 잘못된 주소가 있어도 원래 `task_links` 인덱스로 오류를 알려 줍니다.
  저장이 거절되면 제목·링크를 포함한 기존 연구 상태를 유지합니다.
- 주소가 너무 길다는 오류가 나오면 담당자는 500자 이내의 유효한 주소로 바꿔 다시 저장하면 됩니다.
  기존 저장 데이터의 보정과 `judgeSubmission` 답변 URL 처리는 이번 수정 범위에 포함하지 않습니다.
- `rules.test.ts`의 경계·정규화·오류 인덱스 검사와 e2e의 저장·조회·실패 시 상태 보존 검사를 추가했습니다.
- 0.1.3 이후 이미 합쳐진 메일 변경도 포함됩니다: 계정 공용 메일 관문을 사용하고,
  Resend 한도 초과 시 Cloudflare Email Service로 보내는 경로를 연결했습니다.

  의존성은 바꾸지 않고 lockfile의 애플리케이션 버전만 갱신했습니다.
- 이번 릴리즈에서 `npm run check` — lint, 타입 검사 3개(core·server·web), 5개 파일의 단위 테스트 63개 통과.
- 이번 릴리즈에서 `npm run build` — 웹·서버 번들 통과.

  `wrangler.toml`의 버전을 0.1.4로 맞췄습니다. 배포 스크립트의 버전 일치·공유 Hyperdrive 검사 통과.
- 구현 단계의 제공된 검증 기록: 폐기용 PostgreSQL 16·정식 빌드 서버·게이트웨이 역할 전환 환경에서

- 이번 릴리즈에서 `git diff --check` 통과.

## 배포

운영 배포는 수동입니다: `bash scripts/deploy-pages.sh`

이번 작업은 로컬 릴리즈 커밋과 주석 태그 준비까지입니다. 원격 푸시·업로드·운영 배포와 운영 점검은 실행하지 않았습니다.
배포 담당 hkjang은 배포 후 정상 링크 저장 실패나 주소 절단이 1건이라도 재현되면 확대를 중단하고
직전 배포로 복구 여부를 판단합니다. 기존보다 긴 주소를 거절하는 동작이므로 첫 문의에서 주소 길이와 오류 위치를 확인합니다.
