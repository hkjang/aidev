# VisitFlow 프로필 (2026-09-29)
- 목적: 사내 방문 신청·승인·QR 방문증·로비 체크인·알림·감사를 단일 컨테이너로 제공한다.
- 스택: Go 1.24(chi·pgx·go-oidc·excelize), PostgreSQL 14+, React 19·TypeScript·Vite·Material UI 7, Vitest·Playwright.
- 기준: HEAD 9b66607, v2.8.9. 이전 프로필의 v2.8.7 기준과 미해결 목록·CI 설명을 갱신했다.
- 구조:
  - cmd/visitflow/: 서버 진입점과 임베드 webdist. 기본 스텁과 실제 UI 빌드 구분 필요.
  - internal/app/: REST·MCP·SSE·방문/QR/알림. integration_test.go는 실제 PostgreSQL 기반 통합 테스트.
  - internal/platform/: 환경설정·암호화·메일 등 기반 기능.
  - internal/database/: 번호별 SQL 마이그레이션을 파일별 트랜잭션으로 적용한다.
  - web/src/pages/: React 페이지. VisitFormPage는 일반/현장 신청 공용, ScannerPage·LobbyPage는 로비 운영.
  - web/src/schedule.ts·visitors.ts: 화면 사전 검사의 순수 함수. src/**/*.test.ts가 Vitest 대상.
  - web/e2e/visit-flow.spec.ts: 실제 서버에 로그인·신청·QR 체크인하는 Playwright 회귀 테스트.
  - docs/: USER_GUIDE·ADMIN_GUIDE·API_AND_MCP·ARCHITECTURE, PDF와 화면 이미지.
- 빌드·테스트:
  - `go test ./... -count=1`: 이번 정찰 PASS(app 0.138s). VISITFLOW_TEST_DSN 없어 DB 통합 SKIP.
  - `VISITFLOW_TEST_DSN='postgres://visitflow:visitflow@127.0.0.1:5432/visitflow?sslmode=disable' go test ./... -count=1`: CREATE DATABASE 권한 필요. 과거 기록 약 45~60초; 이번 DB 실행 미확인.
  - `go vet ./...`, `go build ./...`는 README/CI 기반. 이번 정찰 미실행.
  - `cd web && npm ci && npm run lint && npm test && npm run build`. lint는 tsc -b. 현재 node_modules 없음, 이번 정찰 프런트 미실행. 지난 회차 Vitest 60개 통과 기록.
  - `cd web && npx playwright install --with-deps chromium`, 실제 서버 준비 후 `cd web && npm run test:e2e`. VISITFLOW_BASE_URL 기본 http://127.0.0.1:8080.
  - Playwright 자체 webServer 설정 없음. ADMIN/PASSWORD는 VISITFLOW_E2E_ADMIN/VISITFLOW_E2E_PASSWORD(기본 admin/e2e-bootstrap-password).
  - CI test 잡은 PostgreSQL 16 + Go test/vet + npm ci/test/build + Docker build. 별도 e2e 잡은 실제 dist 임베드·Go 빌드·서버 기동·브라우저 테스트까지 이미 수행한다.
  - `docker build -t visitflow:dev .`; release.yml은 태그로 오프라인 Docker 아카이브를 만든다. 이번 과제에서는 변경 금지.
- 관례:
  - 영어 conventional commit(fix(web), chore(release)), 한국어 UI·가이드. 설정은 DB settings, 주요 운영 환경변수는 POSTGRES_DSN·BOOTSTRAP_ADMIN·BOOTSTRAP_ADMIN_PASSWORD·ENCRYPTION_KEY.
  - ENCRYPTION_KEY는 Base64 또는 hex로 표현한 32바이트. README가 openssl rand -base64 32를 안내한다.
  - VisitFormPage:loadReference는 refError/refLoading을 공용 error에서 분리하고 닫기 없는 Alert에 재시도 버튼을 둔다(v2.8.8).
  - visitors.ts:submitBlockReason의 단일 결과를 안내·disabled·submit 가드가 공유한다(v2.8.9). 담당자·체크리스트·차량/장비·동의 차단 이유는 해결됨. 개별 필드 error 표시는 미구현 후보.
  - 순수 검증 함수로 테스트하되 React state/effect 배선 결함은 실제 브라우저에서 확인한다.

  - ScannerPage:scope 필터와 stopCamera cleanup; LobbyPage:loadRef + EventSource 한 번 구독. 기준 정보 복구 때문에 QR 버튼·빈 lobbyId 계약·SSE 수명을 바꾸지 않는다.
  - 미머지 origin/auto/2026-09-16-1212(메일), 2026-09-18-0533(MCP OAuth), 2026-09-21-0654(import 중복 헤더)는 이번 git branch로 재확인. 인접 변경 피할 것.
- 자주 깨지는 곳:
  - TestSelfRegistrationRecordsVisitorConsent는 consented_at DESC LIMIT 1로 host/self 동시각을 구분하지 못한다. 이전 회차 실제 flake 기록, 이번에는 DSN 없어 단독 SKIP.
  - git checkout --로 미커밋 테스트를 잃은 기록: 변이 복원은 임시 백업 사용. 실제 UI 검증 뒤 cmd/visitflow/webdist 스텁 복원 필수.
  - MUI label의 필수 표시와 select aria-labelledby, 사이드바의 중복 버튼 이름 때문에 locator를 실제 DOM에서 확인해야 한다.
- 검증 함정:
  - Go PASS ≠ DB 통합 실행. .tsx 단위 테스트는 Vitest에서 수집되지 않는다. 화면 기준 정보 복구의 이번 브라우저 재현은 미확인.
  - ScannerPage reference-data는 catch 없음, LobbyPage는 catch로 숨김. 그러나 verify/checkin은 ref를 기다리지 않으므로 “스캔 화면 전체가 죽는다”는 이전 표현은 부정확.
  - 로비 필터는 허용 로비가 둘 이상일 때만 표시된다. fixture 한 개로 필터 복구를 판정하면 안 된다.
  - 재시도 성공은 route.continue로 실제 서버 응답을 사용하고 오류 경로만 네트워크 수준에서 주입할 것. 가짜 객체·문자열 검사로 배선을 증명하지 않는다.
  - 이전 기록상 new Date의 잘못된 날짜 롤오버와 excelize 표시 서식에 주의. 실제 Excel·SMTP·Keycloak 인프라 검증은 이번 미실시.
  - 저장소 CLAUDE.md·AGENTS.md·별도 로드맵/TODO 문서 검색 결과 없음. 프로필은 기존 기록 중 재확인하지 않은 내용을 해당 문구로 구분한다.
