- 과제: 액션 센터가 `valid_from > valid_to` 인 거꾸로 된 계약 창(영구히 모든 조회를 막음)을 high 로 보고하게 하기 (가치 3 / 위험 1 / 작업량 S)
- 왜: 쓰기 경로는 `dataWorksAccessWindowOrdered`(internal/proxy/admin_dataworks.go:1782, 호출부 1376)로 거꾸로 된 창을 `400 invalid_access_window` 로 이미 거부하면서 주석에 "an inverted one denies every query for the whole life of the contract while the admin views list it as an active contract" 라고 이유를 적어 뒀다(커밋 `9be6396 fix: reject contract scopes the runtime can never serve`, 쓰기 경로 테스트는 `internal/proxy/admin_dataworks_contract_status_test.go:71`). 그런데 그 검사가 생기기 전에 저장된 행은 그대로 남아 있고, 액션 센터의 계약 루프(admin_dataworks.go:252~295)는 `valid_to` 가 과거이거나 lookahead 안일 때, 또는 두 값 중 하나가 **파싱 불가**일 때만 보고하므로, 두 값 모두 읽히고 `valid_to` 가 lookahead 밖인 거꾸로 된 창(예: `valid_from`=지금+3650일, `valid_to`=지금+3600일)은 `contractScopeActive`(internal/proxy/dataworks_runtime.go, `validFrom.After(now)` 분기)에서 지금 막히고 그 시점이 오기 전에 `valid_to` 가 지나 `contractScopeCanServe` 가 닫히므로 **영구히** `403 contract_scope_inactive` 인데도 운영 화면 어디에도 뜨지 않는다. 고치면 "절대 서빙할 수 없는 계약" 에 대해 쓰기 경로와 운영 화면이 같은 기준을 갖는다.
- 수용 기준:
  1) `status=active` 이고 `valid_from` 이 `valid_to` 보다 늦은 계약 스코프가 액션 센터에서 정확히 1건의 `type=contract_expiring`·`severity=high` 로 나오고 `summary.expiring_contracts` 가 1 이 된다 — 기본 창·`?expiring_within=7d`·`?expiring_within=13w` 세 창 모두에서(이미 죽은 계약이므로 lookahead 와 무관해야 한다).
  2) 같은 계약에 대한 런타임 조회(`POST /v1/data-products/{key}/query`)가 `403` + 에러 코드 `contract_scope_inactive` 임을 같은 테스트가 확인한다(= 보고 대상이 실제로 죽은 계약이라는 근거).
  3) 다음은 0건을 유지한다(느슨해지는 쪽·시끄러워지는 쪽 둘 다 없음): 정상 창(`valid_from` < `valid_to`, 둘 다 lookahead 밖 → 런타임 200), `valid_from` 이 빈 값, `valid_to` 가 빈 값, `valid_from == valid_to`(같은 순간은 거꾸로가 아니다 — 쓰기 경로도 `After` 만 거부하므로 통과시킬 것), `status=draft`, `status=revoked`.
  4) `GET /admin/dataworks/products/{key}/contract-scopes` 와 `GetContractScope` 의 `valid_from`·`valid_to` 원문(공백 포함)이 변하지 않고, 액션 JSON 의 `valid_from`·`valid_to` 도 재포맷 없이 원문 그대로다 — 판정에만 한 번 trim 한 지역 값을 쓴다(저장소 관례: 1e9045a, 36c665c).
  5) 프로덕션 파일(`admin_dataworks.go`)만 되돌린 상태에서 새 테스트의 inverted 사례만 실패하고 기존 ActionCenter/AccessWindow 테스트는 전부 통과함을 실행으로 확인한다(수정 전 `go test ./internal/proxy/ -run 'ActionCenter|AccessWindow'` 는 현재 green: 2.726s).
