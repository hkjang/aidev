fix: release the session token revocation warning for v0.2.25

로그아웃과 토큰 폐기가 실패해도 아무 흔적이 남지 않던 문제를 고친 PR #47을
릴리즈합니다. `logout`(auth_handlers.go:106)·`oidcLogout`(oidc.go:380)·
`baoRevokeSelf`(openbao.go:267) 세 자리가 `RevokeToken`의 반환값을 `_ =`로 버려,
저장소가 흔들려 폐기가 실패해도 응답은 `204`·`302`로 나가고 같은 토큰이 TTL이
끝날 때까지 계속 `withAuth`를 통과했습니다. 관리자가 "로그아웃했는데도 살아 있는
세션"을 로그의 단서 하나 없이 보게 되던 자리입니다. `sessionRevoker` seam
하나(기존 nil-폴백 관례)와 `revokeSessionTokenOrLog(r, token, source)` 헬퍼를
server.go에 넣어 세 자리를 모아, 실패할 때 `logger.Warn("세션 토큰 폐기 실패",
error·source·request_id)`만 남기며 세션 토큰 값은 남기지 않습니다. 상태 코드,
쿠키 만료, 리다이렉트 위치, `baoResponse` 본문과 `withAuth` 판정은 계약이라 그대로
두었습니다(프로덕션 파일 4개, 각 1~8줄). 같은 PR은 실제
`s.requestID(s.withAuth(http.HandlerFunc(s.logout)))` 왕복으로 세 경로 각각에서
경고가 정확히 한 줄 남고 로그 버퍼 어디에도 세션 토큰이 찍히지 않는 것, 성공
경로에서는 경고가 남지 않는 것을 고정하는 회귀 테스트를 추가했습니다.
`RevokeToken`의 오류 종류로는 분기하지 않습니다.

기존 패치 릴리스와 같은 방식으로 버전 파일, 문서 프로파일과 CHANGELOG를
v0.2.25로 갱신했습니다. 캡처 출처는 v0.2.9를 유지합니다. 두 가이드 PDF는
v0.2.24와 같은 이유로 표지가 `v0.2.18`인 채로 남았습니다. 지금까지 쓰던
변환기(표지 템플릿 + HeadlessChrome 인쇄)가 저장소에 없어 같은 판형으로 다시
구울 수 없었고, 다른 템플릿으로 바꿔 굽는 것은 릴리스 절차 밖의 변경이라 기존
파일을 그대로 두고 CHANGELOG에 적었습니다. 본문 Markdown은 갱신했습니다.
./scripts/verify.sh 전체(Go test·vet·gofmt, 웹 테스트 59개·lint·build,
문서·Compose)가 통과했습니다. 이미지 빌드·스모크·브라우저 E2E·번들 생성 및
게시 작업은 태그 푸시 후 release.yml이 수행합니다.
