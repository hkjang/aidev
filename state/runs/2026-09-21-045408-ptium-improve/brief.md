- 과제: XLSX 인라인 서식 문자열의 텍스트 조각을 합쳐 셀 내용 손실 막기 (가치 4 / 위험 1 / 작업량 S)
- 왜: `worksheet.Rows.Cells.Inline`은 `xml:"is>t"`만 읽고 `gridOf`의 `inlineStr` 분기는 그 값만 사용하므로 `<is><r><t>국내</t></r><r><t> 매출</t></r></is>`처럼 나눠 저장된 글자는 빈 셀이 된다. 공유 문자열에서 이미 하는 것처럼 서식 조각의 글자를 순서대로 합치면 표 머리글·행 라벨·본문이 보존되고 같은 텍스트가 저장 방식 때문에 다른 덱이 되는 일을 막는다.
- 수용 기준: 1) 실제 ZIP/XML XLSX를 `docs.Read`로 읽었을 때 인라인 `<r><t>` 여러 개가 순서대로 합쳐져 머리글·본문·라벨에 나타나고, 조각 경계의 내부 공백과 XML 엔티티가 보존된다(예: `국내` + ` 매출` → `국내 매출`, `R&amp;D` → `R&D`); 기존 셀 전체 TrimSpace 정책은 유지한다. 2) 일반 `<is><t>`와 sharedStrings의 `<si><r><t>`로 같은 내용을 저장한 파일은 같은 Source 및 Warnings를 낸다. 서식 메타데이터와 발음 안내 `<rPh><t>`는 본문으로 들어오지 않으며 숨김 처리·출처·셀 위치는 그대로다. 3) 회귀 테스트는 실제 XLSX ZIP → Read → deck.ParseSource를 통과하고, 두 열 차트의 라벨과 Item.Number(예: 조각 `1,` + `200` → 1200), 세 열 표의 텍스트를 확인한다. 현재 코드에서 인라인 rich text 케이스가 먼저 실패하고 수정 뒤 통과해야 하며 plain/shared 대조군과 기존 숨김 테스트가 통과해야 한다.
- 건드릴 파일: `server/internal/docs/workbook.go:worksheet` — 인라인 문자열의 직접 텍스트와 `is>r>t` 조각을 함께 읽을 수 있게 표현; `gridOf` — inlineStr 분기에서 직접 텍스트가 있으면 기존처럼 쓰고 없으면 조각을 빈 구분자로 Join(각 조각을 TrimSpace하지 말 것); `server/internal/docs/sheetrichtext_test.go`(신규 권장) — ZIP 기반 회귀/대조군 테스트. 이미 읽은 `sheetcells_test.go:sheetBook/sheetSource`, `docs_test.go:TestAWorkbookIsReadWithoutALibrary`의 ZIP 생성 방식, `sheetamounts_test.go:chartItem`을 참고한다. sharedStrings 기존 처리와 나머지 프로덕션 파일은 변경할 필요가 없다.
- 검증 명령: 저장소 루트에서 `cd server && go test -race ./...` (정찰에서 실제 실행, 종료 0; 일부 캐시 사용). 빠른 반복은 server 디렉터리에서 `go test ./internal/docs`이며 최종 `go vet ./...`도 수행한다. 후자의 두 명령은 모듈·CI 구성으로 확인했고 정찰에서 별도 실행하지 않았다. 웹 변경이 없으면 npm 설치·빌드는 불필요하다.
- 위험과 피할 것: docs.amountOf/allNumeric, deck.parseNumber/parseBareNumber/chartFields, pptx 렌더러를 손대거나 통합하지 않는다. 서식 보존 기능이 아니라 글자 보존만 구현하며 bold/색을 덱 문법으로 변환하지 않는다. XML의 모든 자손 t를 긁으면 rPh가 섞이므로 정확히 r>t만 읽는다. 행 r 좌표, 병합 셀, 열 상한, ZIP 전체 메모리 제한을 함께 고치지 않는다. auth·db/migrations·.github/workflows·VERSION·릴리즈 노트·PDF도 범위 밖이다. 테스트는 함수에 만든 구조체만 주입하거나 Go 소스 문자열을 검사하는 방식으로 대신하지 않는다.
- 차선 후보: XLSX 생략된 행의 실제 r 좌표를 출처에 반영 — 현재 onScreen의 at.rows가 XML 행 순번을 기록하고 worksheet.Rows.Reference를 쓰지 않는 문제가 남아 있다. `gridOf`에 빈 행을 대량 생성하지 말고 placement 매핑만 바꾸는 과제로 제한한다(가치 3 / 위험 2 / 작업량 M). 다만 1순위가 이미 해결됐거나 유효한 입력으로 실패하지 않는 것으로 밝혀질 때만 전환한다.

구현 순서와 예산: ZIP 회귀/대조군 테스트 작성 및 실패 확인 10분 → worksheet/gridOf 국소 수정 10분 → 전체 Go 테스트·vet와 diff 점검 15분 → 예비 10분, 합계 45분. 복잡한 커스텀 XML 디코더나 외부 의존성이 필요해지면 범위를 재검토한다.

확인 근거와 한계: `Read`의 .xlsx 라우팅, `readWorkbook`의 sharedStrings 조각 Join, `worksheet`/`gridOf`의 inlineStr 분기를 직접 읽었다. 신규 rich-text XLSX로 실행하는 재현은 정찰에서 미실시이며 빈 셀 결과는 소스에 근거한 판단이다. 실제 Excel/LibreOffice 출력 파일과 화면은 미확인이다. 전체 Go 테스트의 DB 관련 검증은 PTIUM_TEST_DSN 없는 경우 스킵하므로 DB 검증을 주장하지 않는다.
