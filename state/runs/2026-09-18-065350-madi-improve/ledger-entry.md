## 2026-09-18
- 선택: MCP OAuth(Keycloak SSO 액세스 토큰으로 /mcp 열기) — RFC 9728 메타데이터·401 도전·토큰 검증·계정 매핑 [캠페인 mcp-oauth-2026-09] (가치 5 / 위험 2 / 작업량 M)
- 결과: 성공
- 요약: madi는 사용자별 계정과 Keycloak OIDC 웹 로그인(`identity_links` provider=oidc)이 이미 있어 표준대로 리소스 서버만 구현했다. 새 `internal/server/integrations_mcp_oauth.go`가 (1) `GET /.well-known/oauth-protected-resource`와 `…/mcp`에서 인증 없이 맨 JSON(resource, authorization_servers=[oidc_issuer], bearer_methods_supported, scopes_supported, `Access-Control-Allow-Origin: *`, 꺼지면 404; 리소스 경로와 다른 접미사는 404)을 내고, (2) `s.auth` 미들웨어의 401(형식 오류·토큰 거부·자격 없음)에 `/mcp`·`/api/v1/mcp`에서만 `WWW-Authenticate: Bearer realm="madi", resource_metadata="…"`(거부한 토큰이면 `error="invalid_token"`)를 붙이며, (3) `tokenPrincipal`(같은 Bearer 헤더를 가르는 자리)에서 `madi_` 접두사가 아니고 JWT 모양이며 MCP 경로(또는 MCP 핸들러가 REST로 디스패치한 요청의 컨텍스트 표식)일 때만 go-oidc 로 검사한다 — 캐시된 provider(issuer당 5분, `context.WithoutCancel`, jwks_uri 같은 출처 검사, 리다이렉트 없음·1MB 상한·JWKS 재요청 1회/초 전송기), 서명 RS/ES/PS만(HS256 거부), iss·exp·nbf, `typ` 이 Bearer 가 아니면(ID) 거부, `cnf` 거부, sub 필수, 대상은 aud∋리소스 또는 aud/azp∈`mcp_oauth_audience`(웹 client_id 자동 허용 안 함)이고 거부 메시지에 본 aud/azp 와 적을 값·매퍼에 넣을 리소스를 담는다. 계정은 `identity_links`(oidc, 같은 issuer, sub)로 이미 연결된 활성 `kind='user'` 만 찾고 없으면 "먼저 웹으로 로그인" 거부, 생성·복구·role 승격 없음. 설정 자리는 madi 관례대로 평면 키 `mcp_oauth_enabled`(기본 꺼짐)·`mcp_oauth_resource`(비면 `site_url`+`/mcp`, Host 헤더 미사용)·`mcp_oauth_audience`(공백 구분)·`mcp_oauth_scopes`(배열, 기본 읽기 3개)이며 `oidc_enabled`·`oidc_issuer`를 재사용하고, 저장 시 `validateMCPOAuthSettings` 가 OIDC 미구성·잘못된 리소스 URL·경로·따옴표 대상·빈 천장을 400 으로 거부한다. OAuth 주체는 `TokenID=""`(api_keys uuid 컬럼에 쓰이므로)·`ScopeRestricted=true`·새 필드 `OAuthSubject` 로 표현해 키와 같은 `hasIntegrationScope`/`integrationScopeAllowed` 문을 타며, 기존 `p.TokenID=="" && !ScopeRestricted → 무제한` 분기를 소스에서 확인해 천장(`mcp_oauth_scopes ∩ allowed_key_scopes`)이 비거나 토큰 scope 와의 교집합이 비면 빈 슬라이스를 돌려주지 않고 명시적으로 401 거부한다(복원된 옛 설정으로 천장이 빈 경우도 DB 직접 갱신으로 검증). 키·쿠키 중 하나를 요구하던 세 자리(`knowledgeActorTx` 커밋 백스톱, `packagePrincipal`, `documentQuerySession`)에 OAuth 분기를 더해 같은 토큰을 다시 검증한다. 미들웨어의 `errors.As(err,&refused)` 분기에서 `slog.Warn("mcp oauth token refused", reason, cause)` 가 실제로 호출됨을 테스트가 캡처 로거로 확인한다(만료·nbf·issuer·서명·HS256·typ·cnf·대상·scope 각각). 관리 화면 SSO 탭에 카드(스위치·리소스 식별자·MCP 주소/메타데이터 주소 복사·허용 대상·권한 체크박스), `/api/v1/public` 에 `mcp_oauth_enabled/resource`, 개인 키 페이지에 "키 없이 SSO로 연결" 절, docs/admin-guide.md(설정 표·Keycloak 클라이언트/Audience 매퍼 4단계·curl 확인·거부 메시지별 조치 표)와 docs/api-guide.md 사용자 절, manuals HTML 재생성. 검증: `gofmt`/`go vet ./...`/`go build`, 새 단위 테스트(기본값·리소스/메타데이터 URL·천장 절단·설정 검증 12건·JWT 모양·경로 판정), 실제 PostgreSQL 컨테이너로 새 `TestPostgresMCPOAuthTokens`(꺼짐=404·키 오류 문구 동일·헤더 없음, 저장 검증 400 4건, 메타데이터 2경로+오경로 404, MCP 401 도전/REST 401 무도전, 미등록 sub 거부·계정 미생성, 가짜 IdP 로 실제 웹 OIDC 로그인 후 토큰으로 initialize/tools/list(읽기만)/search ACL/get_document/쓰기 도구 닫힘, 같은 토큰으로 REST·키·관리 API 401, 외부 대상 거부 메시지·로그, azp/aud 허용 목록 통과, 만료·nbf·issuer·서명·HS256·ID·cnf·sub·scope 불일치 거부+로그, scope 교집합, 빈 천장 거부, 비활성 계정, 키 그대로 동작, 끄면 원상) 와 기존 키/MCP·OIDC·설정·백업 통합 테스트 `-race` 통과, `npm run build`(tsc), `node scripts/build-docs.mjs`, 전체 비DB `go test ./...` 통과. 커밋 af8e021. `node tests/docs.mjs` 는 이 임시 홈에 Playwright Chromium(1243)이 없어 실행하지 못했다(문서 변경은 두 가이드 본문 추가뿐). 실제 Keycloak·실제 MCP 클라이언트 연결은 이 환경에서 확인하지 못했다. 리소스 서버 스타일 선택 이유: 설정 자리는 관리 화면 설정(settings jsonb)에 평면 키로(다른 모든 설정과 동일), 리소스 식별자 출처는 `site_url`(SSO 콜백에도 쓰는 공개 주소)로 정했다. OAuth 주체에는 키의 분당 호출 제한이 없다(Keycloak 토큰 수명이 상한).
