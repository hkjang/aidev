## KCB Cutover Dashboard v1.9.0

### 버그 수정
- **관리자 활동 변경 실패를 화면에 표시**: 지금까지 관리 화면(`/admin`)의 활동 변경 요청(`PUT /api/activities`)은 **서버 응답을 전혀 검사하지 않았습니다.** 인증 만료(`401`), 저장 검증 실패(`400`), 파일 쓰기 오류(`500`) 로 저장이 거부돼도 관리자에게는 **아무 오류도 보이지 않았고**, 1초 주기 SWR 폴링이 곧바로 이전 값을 덮어 써 넣어 **잠깐 바뀌었다가 되돌아가는** 모습만 남았습니다. 관리자는 저장이 된 것인지 안 된 것인지 알 수 없었습니다.
  - 흩어져 있던 6곳의 `PUT` 을 `submitActivityChange()` 한 곳으로 모아 `res.ok` 를 검사합니다. 실패하면 서버가 준 `error` 문구를 **화면 상단 붉은 배너**에 남기고, 응답에 문구가 없으면 `변경 사항을 저장하지 못했습니다. (HTTP <코드>)` 로 알립니다.
  - `401` 이면 기존 동작대로 세션을 지우고 **로그인 화면으로 되돌립니다.**
  - 서버에 연결조차 못 한 경우(네트워크 단절)도 같은 배너로 알립니다. 이전에는 이때도 조용히 넘어갔습니다.
  - 상태 변경·항목 수정·삭제·이동·추가, 그리고 상황판 제목 편집까지 모든 변경 경로가 같은 처리를 거칩니다.
- **저장에 실패하면 편집 입력을 닫지 않음**: 인라인 편집에서 저장을 눌렀을 때 실패해도 입력창이 닫혀 **입력하던 값이 그대로 사라졌습니다.** 이제 `handleSave` 가 저장 결과를 기다려 실패면 편집 상태를 유지하므로, 오류 배너를 읽고 **같은 입력값으로 다시 시도**할 수 있습니다. 상황판 제목 편집도 성공했을 때만 닫힙니다.
- **삭제 확인창 중복 제거**: 하위 항목 하나를 지울 때 확인창이 **두 번** 떴고, 두 번째 창(`app/admin/page.tsx`)의 문구는 `tree.map` 의 **최상위 노드 제목**을 가리켜 **실제로 지우는 항목과 다른 제목**을 보여 줬습니다. 지우는 노드를 정확히 아는 `ActivityTree` 쪽 확인창 하나만 남겨, 확인창은 **한 번만** 뜨고 **지우려는 항목의 제목**을 보여 줍니다.

### 검증
- `e2e/admin-save-failure.spec.ts` 5건 신규 — Playwright `page.route` 로 실제 `fetch` 경로에 `500`·`401` 을 주입해, 폴링 결과가 아니라 **`PUT` 응답과 화면 메시지**로 판정합니다. 수정 전 실패(확인창 2건·둘째가 최상위 제목·배너 없음)를 먼저 확인한 뒤 통과를 확인했습니다.
- `npm run lint` 오류 0, `npx tsc --noEmit` 통과, `npm run test:unit` 79건 통과, `npm run test:e2e` 16건 통과, `npm run build` 통과.

### 배포
폐쇄망 배포는 이전과 같습니다.

```bash
docker load -i cutover-v1.9.0.tar.gz

docker run -d -p 3000:3000 \
  -e USER_PASSWORD=1234 \
  -e ADMIN_PASSWORD=admin1234 \
  -e AUTH_SECRET=운영환경용-충분히-긴-임의문자열 \
  -v cutover-data:/app/data \
  --name cutover-app \
  --restart always \
  cutover:v1.9.0
```

데이터 구조 변경이 없으므로 `cutover-data` 볼륨을 그대로 붙이면 되고, 별도 마이그레이션 절차는 없습니다. v1.8.0 으로 되돌려야 할 경우 이전 이미지로 컨테이너만 다시 띄우면 됩니다.
