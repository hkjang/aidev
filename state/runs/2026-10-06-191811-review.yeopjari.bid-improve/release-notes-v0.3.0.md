v0.3.0: 사설·루프백 주소 링크 차단, 무쿠키 응답의 DB 왕복 0회

- 링크 안전 판정(`isSafeLink`)이 주석대로 동작한다: 전에는 `169.254.169.254` 와
  `metadata.google.internal` 두 호스트만 걸러 `127.0.0.1`·`10.x`·`192.168.x`·
  `[::1]`·`localhost` 가 모두 통과했다. 판정을 루프백·링크로컬·사설 3대역·
  fc00::/7·unspecified·IPv4-mapped IPv6(`::ffff:a.b.c.d`)·`localhost` 라벨
  접미사·점 없는 호스트로 넓히고 주석을 코드와 맞췄다. 회원·공급사·관리자가 넣는
  주소 10개 호출부가 모두 이 함수를 지난다
- 호스트 비교는 접두사 문자열이 아니라 점 라벨 단위로 한다 — `10.notion.com`·
  `localhost.example.com`·`172.200.0.1`(사설 아님) 같은 정상 주소는 그대로 통과
- 로그인 상태 확인: 세션 수명 설정을 세션 쿠키가 있을 때만 읽는다. v0.2.0 배포
  뒤에도 무쿠키 `/api/v1/auth/session` 이 문장 1개(~150ms)였던 원인으로,
  파이프라인이 세션 유무를 보기 전에 설정을 읽었고 인스턴스별 설정 스냅숏(10초)은
  낮은 트래픽에서 대부분 만료돼 있었다. 운영 점검도 세 번 모두 0문장이어야 통과
- 검증: `npm run check`(lint + 타입 + 단위 테스트) 97항목, `npm run build`,
  실제 PostgreSQL 대상 종단 시험 139항목 전부 통과. VERSION 과 wrangler.toml
  `REVIEW_VERSION` 일치 확인
