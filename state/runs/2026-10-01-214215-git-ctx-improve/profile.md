# git-ctx 프로필 (2026-10-01)
- 목적: 사내 GitLab·Bitbucket 코드와 문서를 색인해 ACL 을 지키는 MCP/REST 개발 컨텍스트와 관리 콘솔을 제공한다.
- 기준: HEAD `f1de053`(main, PR #42 머지), 최신 릴리즈 v0.77.20. 2026-09-25 프로필의 기준(ad093d9/v0.77.16)은 낡았으므로 이 줄로 대체.
- 스택: Go 1.25.0/toolchain go1.26.6; SQLite(FTS5)·PostgreSQL, 선택적 pgvector/Milvus/OpenSearch·Vault, Keycloak OIDC, 바닐라 JS, Docker/Kubernetes.
- 구조:
  - cmd/git-ctx — 진입점; internal/version — 릴리즈 버전.
  - internal/contentsecurity — Sanitize·Revision(규칙 변경 시 지문이 바뀌어 재색인).
  - internal/indexer — 수집·청킹·정책·재색인 지문.
  - internal/search — ACL 검색·원격 소스·ReadFile·ExportContext·의존성 분석(`cutAtRuneBoundary`, `WithUnrestricted`).
  - internal/mcp — dispatch.go(요청 처리·감사 INSERT), tools.go(도구 핸들러), format.go(응답 마크다운), budget.go(응답 예산·절단·펜스 닫기), cache.go, args.go.
  - internal/app·auth — HTTP·OIDC·키·세션·관리 API(mcpadmin.go 가 mcp_calls 를 읽어 콘솔에 표시).
  - internal/store — SQLite/PostgreSQL 스키마·migration; test/store — 빌드 모드 교차·구버전 업그레이드.
  - internal/calltrace — 단계별 추적(mcp_call_steps).
  - web·test/web — 관리 콘솔·계약 테스트. docs — requirements·configuration·operations·test-plan·openapi·릴리즈 노트.
  - scripts·.github/workflows — 버전 동기화·오프라인 패키지·CI·릴리즈.
- 빌드·테스트: `go build -tags sqlite_fts5 ./...`; `go vet ./...`; `go test -tags sqlite_fts5 ./...`(수 분, `./internal/app` 혼자 ~100~120초); `-race ./...` 는 더 오래.
- 빠른 검증: `go test -tags sqlite_fts5 -count=1 ./internal/mcp`(이 회차 단일 테스트 0.02s 실측). 형식: `gofmt -l ./cmd ./internal` 출력이 비어야 함. JS: `node --check web/app.js`; `for f in test/web/*.test.js; do node "$f"; done`.
- 관례: 영어 `fix(scope): …` / `release: vX.Y.Z` 커밋. 카테고리별 JSON 설정, store 가 migration 관리. scripts/verify-version-sync.sh·scripts/release.sh, 문서는 docs. 저장소 내부 CLAUDE.md·AGENTS.md·roadmap 없음, TODO/FIXME 없음.
- 위험 구역: internal/auth·app 인증/세션/ACL, internal/store migration·백업 복원, .github/workflows·릴리즈 scripts, internal/version 및 연결 문서.
- 자주 깨지는 곳:
  - 마스킹이 비밀 아닌 내용·개행을 삭제함. 콜백만 바꾸면 Revision 이 같아 구색인 미갱신.
  - 바이트 예산 절단이 UTF-8 문자를 반으로 자름 — mcp·search·source·embedding·vectorstore 다섯 곳에서 각각 고쳤다(계약이 갈라질 자리).
  - 포매터(format.go)와 그 출력을 다시 파싱하는 소비자(budget.go 의 `sectionCount`·`cutAtBoundary`·`closeOpenFence`, dispatch.go 의 `retrievalMode`)의 계약이 어긋남 — 2026-09-28·09-29 펜스 길이 2건이 이 계열이고, `#### ` 히트 집계가 남아 있다.
  - manifest 파서 확장은 사람 반려 이력 유형.
- 검증 함정:
  - mcp fixture(`server_test.go:22`)는 공유 in-memory SQLite 이름을 쓰므로 새 테스트에 `t.Parallel()` 금지. 헬퍼: `fixture(t)`, `call(t,s,body)`, `callAs`, `answerText`.
  - `s.search` 는 인터페이스가 아닌 구체 타입이라 검색 호출을 스파이할 수 없다. 대역을 억지로 넣지 말고 관측 가능한 단언(감사 행, 응답 텍스트)을 찾을 것.
  - 합성 문자열 테스트가 프로덕션에 없는 모양을 고정해 둔 자리가 있다 — `truncation_test.go:57` 은 code-search 히트를 `### ` 로 쓴다(실제는 `#### `). 재현은 항상 실제 `Server.ServeHTTP` 왕복으로.
  - `internal/mcp/truncation_test.go:31` 은 `budget+responseNoticeBytes` 까지 허용한다 — "응답이 예산을 넘지 않는다"는 고정 계약이 아니다.
  - `encoding/json` 은 U+FFFD 를 원문자가 아니라 `�` 이스케이프로 쓴다 — 원문자 검사는 항상 통과하는 무의미한 단언. 히어독은 테스트 소스의 유니코드 이스케이프를 뭉개므로 Write/Edit 로 쓰고 needle 은 조립할 것.
  - CI 통합은 GIT_CTX_TEST_POSTGRES_DSN·GIT_CTX_TEST_PGVECTOR_DSN·GIT_CTX_TEST_VAULT_URL/TOKEN 필요. 외부 DB·Vault·Docker·실브라우저는 이 환경에서 미검증. govulncheck 는 취약점 DB 가 매일 갱신되어 코드가 안 바뀐 태그도 갑자기 실패할 수 있다.
  - docs/test-plan 의 기본 `go test` 에는 FTS5 태그가 없지만 CI 는 태그 포함 suite 와 별도 build-mode 검증을 돈다.
- 저장소 위생: 루트에 추적된 디버그 산출물 `c.txt`·`server.log` 가 남아 있다.
