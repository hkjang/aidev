# ReSSO 프로필 (2026-10-08)
- 목적: 오프라인 단일 바이너리 OIDC SSO 제공자와 사용자·Realm 관리 콘솔. RP 구현은 포함하지 않는다.
- 스택: Go 1.26/toolchain go1.26.7, chi v5, PostgreSQL/pgx v5, LDAP, React 19/TypeScript/MUI/React Query/Vite 7/vitest 4, CI Node 22.23.0.
- 구조:
  - cmd/resso: 서버·CLI·유지보수·예약 작업·메일 알림(main.go의 warnExpiringAPIKeys 포함).
  - internal/httpserver: OIDC·인증·관리·개인·MCP 라우트. oidc.go 1864행, integration_test.go 13699행(행 번호는 이후 이동 가능).
  - internal/store: DB 접근·세션·코드/refresh 회전, migrations/의 자동 SQL 마이그레이션.
  - internal/oidc: PKCE·서명·토큰 생성/검증; federation: LDAP 및 TLS 연동.
  - internal/backchannel·mail·tracking·observability 등: 통지·추적·관측.
  - web/src: React UI; webui/dist: Go embed 빌드 산출물.
  - scripts: 실제 Docker 테스트 서비스 준비·smoke·릴리즈. docs: 운영/호환/LDAP 및 사용자·관리자 정본.
- 빌드·테스트:
  - `test_env="$(scripts/test-services.sh)" && eval "$test_env"` 후 같은 셸에서 테스트한다. `eval "$(...)"` 단독은 내부 실패를 숨길 수 있다.
  - `make lint`: golangci-lint v2.13.1 + govulncheck + ESLint. `make test`: go test -race ./... + vet + vitest + build, 통상 수분.
  - `make build VERSION=vX.Y.Z`. full make test는 SKIP 집계 때문에 Go 연동 테스트를 한 번 더 실행한다.
  - 이번 실행: `bash -n scripts/test-services.sh` 통과. 정상 준비 후 `go test -race ./internal/federation -run '^TestDirectoryOverTLSRequiresACertificateItCanVerify$' -count=1 -v` PASS(1.131s), SKIP 없음.
  - 이번 정찰은 full make lint/make test 미실행. 이전 회차의 전체 검증 통과는 현재 새 실행 결과와 구분할 것.
- 관례: 영문 fix:/feat:/docs:/release: 커밋. HEAD 8ef825f=v0.9.102. 설정은 환경변수+platform_settings. 저장소에 CLAUDE.md/AGENTS.md/roadmap/TODO 파일은 이번 검색에서 없고 TODO/FIXME 본문 검색도 결과 없음.
- 문서: README는 개발·연동 참고, USER_GUIDE/ADMIN_GUIDE는 화면 가이드 정본. 운영 진단은 docs/operations.md, LDAP 개발은 docs/user-federation.md.
- 위험 구역: httpserver/auth.go·oidc.go·middleware.go(인증/토큰/CSRF), store/migrations, .github/workflows/release.yaml. 낮은 위험 과제는 이 경로를 피한다.
- 설계 관용구: “실제로 없음”과 “조회 실패”를 가른다. token 500, revoke 503, introspection 200 active=false, userinfo 500 등 Endpoint별 계약을 공통 오류 처리로 통합하지 않는다.
- 미검증 client_id/grant_type/Secret/code/verifier를 지표 라벨·감사 detail에 넣지 않는다. 취소된 호출은 오류 지표·Limiter 예산을 올리지 않는다.
- ErrFamilyNotRevoked는 ErrTokenReuse/ErrCodeReuse 양쪽 폐기 실패를 표현. 코드 재사용 실패에는 원래 code를 함께 반환해야 감사 actor FK가 유효하다(uuid 값이지 포인터가 아니다).
- 자주 깨지는 곳: gofmt, 빌드가 변경하는 webui/dist/index.html, LDAPS bind mount/CA 경로, 추측한 HTTP 상태, 유지보수 SQL 순서를 고정한 테스트.
- 검증 함정:
  - 서비스 환경변수가 없으면 연동 테스트가 SKIP인데 go test exit 0. 실제 PASS/실행 여부를 확인한다. make 출력의 레시피 문자열은 실제 SKIP 경고와 구별한다.
  - CI verify는 세 서비스를 scripts/test-services.sh로 준비한다. release.yaml은 PostgreSQL만 준비한다.
  - npm이 조상 node_modules/.bin의 Node 20을 고른 사례가 있다. web/package.json의 npm_node_execpath PATH 고정을 유지하고 의존성 오류로 단정하지 않는다.
  - Registry는 표본 없는 계열에도 HELP/TYPE을 출력한다. 지표 부재는 이름이 아니라 샘플 행으로 검사한다.
  - 로그 동시 읽기는 integration_test.go의 lockedBuffer. PostgreSQL 장애 주입은 테이블/컬럼 RENAME + 즉시 복구 + t.Cleanup 선례 사용. 도달 가능성은 실제 HTTP/store 경로로 증명한다.
  - 코드 재사용 UserByID의 ErrNotFound는 계정 삭제 시 코드도 CASCADE 삭제되므로 해당 분기에 도달하지 않는다. 불가능한 상태를 억지로 만들어 테스트하지 않는다.
- 최신 정정: UpdateUser의 비활성화 세션 종료 테스트가 없다는 과거 프로필은 틀렸다. store/integration_test.go:3589 TestIntegrationDisablingAnAccountSignsItOutForGood가 세션/refresh 폐기·알림·재활성화 비복원·반복 종료를 이미 검증한다. 새 과제로 선택 금지.
