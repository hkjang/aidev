- 과제: 감사 CSV의 선행 탭·CR 셀을 기존 수식 셀과 동일하게 중화 (가치 2 / 위험 1 / 작업량 S)
- 왜: `internal/server/audit_events.go:safeCSVCell`은 첫 문자가 `=+-@`일 때만 작은따옴표를 붙여 선행 탭(0x09)·CR(0x0D)이 있는 값은 그대로 CSV로 내보낸다. 같은 중화 규칙을 두 제어문자에도 적용하고 실제 HTTP 내보내기 결과를 검증하면 기존 CSV 방어의 빈틈을 작은 변경으로 줄일 수 있다.
- 수용 기준: 1) 첫 문자가 `=`, `+`, `-`, `@`, `\t`, `\r`인 셀에는 작은따옴표 하나를 앞에 붙이고 원문 나머지를 보존한다. 빈 문자열·한글·일반 문자열·이미 작은따옴표로 시작하는 문자열과 문자열 중간의 탭/CR은 바꾸지 않는다. 2) 실제 PostgreSQL → `New(...).Handler()` → 인증된 `GET /api/v1/audit/events/export` → `streamAuditCSV` 경로에서 actor 이름과 이벤트 문자열 및 details의 stage/reason이 같은 규칙으로 중화된다. HTTP 200, CSV Content-Type, UTF-8 BOM, 13열 헤더, 정상 셀 보존을 확인하며 DB 원문과 JSON 감사 조회 응답은 변경하지 않는다. 3) 표 테스트가 여섯 위험 접두사와 정상/빈/인용/쉼표/줄바꿈 값을 검증하고, 통합 테스트가 BOM 제거 후 `encoding/csv.Reader`로 실제 응답을 파싱해 셀 값을 비교한다. 탭·CR 처리만 제거했을 때 새 테스트가 실패해야 한다.
- 건드릴 파일: `internal/server/audit_events.go:safeCSVCell` — 기존 선행 문자 집합에 탭·CR만 추가; `internal/server/server_test.go:TestSafeCSVCell` — 현재 `=HYPERLINK` 한 사례를 표 테스트로 확장; `internal/server/audit_export_integration_test.go`(신규 제안):`TestAuditExportNeutralizesControlPrefixes` — 실제 DB와 프로덕션 라우트를 지나는 회귀 테스트; `docs/api.md` 감사 이벤트 절(현재 315행) — 선행 `=+-@`·탭·CR에 작은따옴표를 붙이는 계약을 한 줄로 명시.
- 검증 명령: 저장소 루트에서 `go test -count=1 ./...`, `make lint`. 전용 폐기 가능한 PostgreSQL DB를 가리키는 `TEST_POSTGRES_DSN` 설정 후 `go test -v -count=1 ./internal/server -run 'TestSafeCSVCell|TestStreamAuditCSV|TestAuditExportNeutralizesControlPrefixes'`, 이어서 `go test -race -count=1 ./...`. 새 통합 테스트가 PASS인지 확인하고 SKIP을 증거로 삼지 않는다. 정찰에서는 앞의 두 명령만 실제 실행하여 통과했다(Go 1.26.7); DSN·Keycloak issuer 미설정이라 통합 테스트는 실행되지 않았다. 새 테스트 이름은 제안이며 현재 존재하지 않는다.
- 위험과 피할 것: auth·migrations·workflow·CI·VERSION·CHANGELOG·내장 UI 산출물은 수정하지 않는다. TrimSpace로 검사 대상을 바꾸거나 모든 공백/제어문자 정책을 넓히지 않는다. CSV quoting과 수식 중화는 다르므로 writer의 quoting에만 기대지 않는다. 기존 `audit_export_test.go:stubAuditRows`만 확장한 결과를 통합 증거로 쓰지 않는다. DB 원문을 수정하거나 스크럽 전 내용을 새 감사 details에 복제하지 않는다. 테스트가 DROP SCHEMA를 사용하므로 공유/운영 DSN 금지, `t.Parallel()` 금지. 특정 스프레드시트 제품에서의 실제 수식 실행 여부는 미확인이며 이번 수용 범위는 서버가 생성하는 셀 내용이다.
- 차선 후보: 사용자 목록의 동일 created_at에 대한 페이지 순서 고정 — `internal/server/users.go:listUsers`의 `ORDER BY u.created_at DESC`에 `u.id DESC` 타이브레이커를 붙이고, 같은 생성 시각의 사용자들이 페이지 간 중복·누락 없이 정해진 순서로 반환되는지 실제 DB/HTTP로 확인(가치 2 / 위험 1 / S). 1순위 누락이 이미 해결됐거나 요구가 성립하지 않는 경우에만 선택한다.

구현 순서와 예산(총 45분): 계약/기존 테스트 확인 5분 → 실패하는 표·통합 테스트 작성 15분 → 최소 수정·API 문서 5분 → 검증 10분 → 예비 10분. 전용 DB 준비가 지연되면 기존 테스트 환경을 재사용하되 폐기 가능한 DB임을 확인한다. DB가 없어도 완료로 판정하지 말고 미검증 범위를 기록한다.

통합 테스트 구현 근거: `users_query_integration_test.go:TestListUsersRejectsOverlongQuery`의 database.Open → Migrate → Seed → secrets.New → New.Handler 구성과 `db_error_integration_test.go:signIn`, `sessionCredentials.do`를 재사용할 수 있다. `001_ai_admin.sql`의 audit_event에는 action/resource_id/request_id와 details JSONB, actor FK가 있다. 파라미터 SQL로 합성 이벤트를 넣고 고유한 q(예: csv-control-regression)로 해당 이벤트만 조회해 로그인·export 자체 감사 이벤트를 제외한다. actor의 display_name도 합성 값으로 설정해 JOIN 투영을 함께 검증한다. `stage`/`reason`은 SQL에서 JSON 텍스트로 꺼낸다. `streamAuditCSV`는 13개 셀 모두에 safeCSVCell을 호출하므로 동일한 함수에서 고치면 된다. `listAuditEvents`의 대응 필드도 원문인지 비교해 중화가 CSV 출력에만 적용됨을 확인한다.
