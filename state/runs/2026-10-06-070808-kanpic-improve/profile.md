# kanpic 프로필 (2026-10-06)
- 목적: 온프레미스·폐쇄망용 웹 AI 스프레드시트와 데이터 협업을 제공한다.
- 스택: Go 1.26(module `kanpic`), PostgreSQL/pgx, excelize; React 19·TypeScript·Vite·zustand·React Query; Vitest/jsdom·Playwright; Docker.
- 구조:
  - `cmd/api`·`internal/httpapi`: 서버 진입점, REST/MCP, 자동화·사용자 가져오기 등 핸들러. `automations.go` 가 `automation.ErrInvalid` → 400 + `err.Error()` 를 `message` 에 싣는다.
  - `internal/workbook`·`collaboration`: 워크북 저장과 협업. `internal/auth`·`apikey`: 인증·인가.
  - `internal/formula`·`delimited`·`importexport`·`external`: 계산, 공통 파일 규칙, CSV/TSV/XLSX, 원격 수식(IMPORTDATA).
  - `internal/automation`: `schedule.go`(cron 파서 `ParseSchedule`→`parseCronField`→`cronValue`, `Next`, `matchesDay`, `cronAliases`), `service.go`(실행·`next_run_at`).
  - `internal/mail`: `mail.go` 전송/검증/연결, `message.go` MIME, `service.go` 수신자/기록/재시도, `config.go` 설정.
  - `internal/observability/logs.go`: `persistentHandler` — 콘솔과 DB(`system_logs.attributes`)에 같은 값을 적는다(`addAttribute`/`attributeValue`).
  - `internal/handoff`, `migrations`(번호별 SQL), `internal/integration`(실제 DB 통합), `internal/ai·analytics·presentation·settings`.
  - `web/src/pages·components·lib·workers`: 화면, 격자, 값/서식 규칙, 붙여넣기 작업자. `testdata`: Go/TS 공용 픽스처. `docs`: 가이드·PDF·로드맵·릴리즈.
- 빌드·테스트:
  - `go test ./internal/automation -count=1` (이번 실행 `ok 0.014s`), `go test ./...`, `go vet ./...`, `go build ./...`, `gofmt -l ./cmd ./internal ./pkg`(출력 없어야 함).
  - `./scripts/check-release-docs.sh`, `./scripts/check-commit-identities.sh HEAD`.
  - 웹: `cd web && npm ci && npm run lint && npm test && npm run build` (설치·빌드 시간 필요).
  - 통합: `POSTGRES_DSN=postgres://... go test -tags=integration ./internal/...` (DB 필수). 브라우저: 서버 기동 후 `cd web && npm run test:e2e`.
- 관례: 커밋은 한국어 `fix/feat/docs(scope): …`. 필수 환경변수 `POSTGRES_DSN`, 나머지는 관리자 콘솔/`internal/settings`. 주석은 "왜" 를 적는다. 사용자에게 보이는 규칙이 바뀌면 `docs/*_GUIDE.md` + 해당 PDF 재생성 동반. 오류 문구는 패키지 감시 오류(`ErrInvalid` 등)로 래핑해 핸들러가 상태 코드를 고른다.
- 위험 구역: `internal/auth`·`apikey`·`handoff`, `migrations`, `.github/workflows`; `external` 의 SSRF/허용 목록; `mail` 의 TLS/AUTH 정책. 테스트의 루프백·자체 서명 허용을 운영 경로로 옮기지 않는다. 이미 **저장된** cron 식·일정을 더 엄하게 거절하는 변경은 재시작 때 기존 일정을 깨뜨릴 수 있다.
- 자주 깨지는 곳: 목적이 다른 파서(계산·파일·표시·키 비교)를 한쪽만 고쳐 두 경로가 같은 입력을 다르게 읽는 것. 입력 경로 숫자 규칙의 무리한 통합. 같은 패키지를 연속 회차로 골라 회귀 원인을 구분하기 어려워지는 것(automation 10-02·10-03, mail 09-28·09-29).
- 검증 함정: CI 는 Go1.26·Node24·Postgres17 에 DB 통합과 서버 기동 후 E2E 까지 돈다 — 로컬 Go 통과가 웹·DB·브라우저 검증은 아니다. 샌드박스가 `go run`·`go mod tidy`·`cd A && B` 형태를 승인하지 않을 수 있다(`go test`·`git`·`sed`·`grep` 은 통과). PDF 바이트 안의 ASCII 검색은 서브셋 폰트 때문에 증거가 되지 못한다 — 인쇄 직전 DOM `innerText` 로 확인한다.
- 문서: `README` VERSION, `docs/USER_GUIDE.md`(cron 별칭 목록 1604행 부근), `docs/ADMIN_GUIDE.md:785` 의 외부 호출 오류 코드 안내는 실제 정책과 어긋난 자리가 남아 있다(`#VALUE!` vs `#N/A`). `ROADMAP_PLAN.md` 는 2026-07-31 장기 계획이라 현 미구현 목록이 아니다.
