Kkiit v0.4.12 — 가입 저장 실패 안내 수정

v0.4.11 이후 들어온 수정 하나를 담는다.

- `register`(`auth.go`)가 `INSERT INTO users` 와 `INSERT INTO user_roles`
  의 모든 오류를 409 `account_exists` "이미 사용 중인 아이디 또는
  이메일입니다." 한 덩어리로 묶던 것을 고친다. 아이디·이메일을 아무도 쓰고
  있지 않은 방문자가 저장 실패마다 "이미 사용 중" 안내를 받아 아이디를
  바꿔 가며 다시 시도하게 됐고, 역할 INSERT 는 새 uuid 를 써서 애초에
  중복일 수 없는데도 같은 안내로 나갔다. 가입은 새 계정이 들어올 유일한
  문이라, 지난 다섯 회차가 coupons·reports·webhooks·discovery·admin_users
  에서 갈라 온 계열 가운데 값이 가장 크게 남아 있던 사례다. 중복(23505)만
  409 로 남기고 나머지는 500 `registration_failed` "가입을 완료하지
  못했습니다."(같은 핸들러의 기존 문구를 그대로 재사용, 새 문구 없음)로
  가르고, 기존 `isUniqueViolation`(`coupons.go`)을 이동·변경 없이
  재사용했다. 버릴 PostgreSQL 16 에 붙는 통합 테스트로 409 를 먼저 재현한
  뒤 고쳐 통과시켰고, 임시 프로브로 실패 경로의 오류가
  `*pgconn.PgError{Code:"22021"}`(`display_name` 의 NUL 거절)이고
  `isUnique=false` 임을 확인한 뒤 프로브를 제거했다. 분기를 두 방향으로
  변이시켜(중복 분기 무력화 → 500, 모든 오류를 중복 취급 → 409) 각각 다시
  실패하는 것도 확인했다. 테스트는 실패 응답이 사용자 행을 남기지 않는
  것과 같은 아이디로의 재시도가 성공하는 것, 진짜 중복이 여전히 409 인
  것까지 함께 고정한다. `user_roles` INSERT 실패 분기는 HTTP 로 만들 경로가
  없어 코드 검토까지만 했다. 프런트는 이미 `error.message` 를 그대로
  띄우므로 `web/` 과 `internal/ui/dist` 는 건드리지 않았고, `openapi.yaml`
  의 POST /auth/register 응답에 핸들러가 실제로 내는 400·403·409·500·503 을
  더해 실제 동작과 맞췄다 — 종전에는 201 뿐이었다.

버전 표기(VERSION·compose·web/package·openapi·README)를 0.4.12 으로 올린다.

gofmt · go build · go vet · go test, web lint · test · build 전부 통과.
버릴 PostgreSQL 16 으로 `make test-integration` 도 통과(80.6초).
웹 검사 3종은 선언·CI 버전인 node:24.18.0 컨테이너에서 돌려 lint 무결,
테스트 10건 통과, build 성공을 확인했다 — 이 기계의 npm 이 PATH 에 끼워
넣는 node 20.19.2 shim 은 `--test` 의 글롭을 지원하지 않아 0건으로 멈춘다.
저장소 스크립트는 그대로 두었다. build 가 다시 쓴 `internal/ui/dist` 는
HEAD 로 되돌려 이번 커밋에서 제외했다.
