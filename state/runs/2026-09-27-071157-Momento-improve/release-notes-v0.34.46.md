# Momento v0.34.46 — 행도 없고 「결과가 없습니다」도 없는 표가 남았습니다

## 뒤쪽 페이지에 있다가 결과가 줄면 표가 비었습니다

표는 현재 페이지를 **자기 상태로** 들고 있고, 보여 줄 행의 수는 **검색어와 재조회로 줄어듭니다.**

`DataTable` 은 `filtered.slice(page * pageSize, …)` 로 자르면서 `page` 를 범위 안으로 끌어오지 않았습니다. `Math.min` 으로 clamp 한 것은 **화면에 표시되는 페이지 번호**뿐이었습니다.

그래서 4페이지(`76–100 / 100`)를 보던 중 일치가 5건으로 줄면, 잘라낸 배열은 **빈 배열**이 됩니다. 그런데 「결과가 없습니다」 안내문은 필터 결과가 **아예 없을 때만** 나옵니다.

남는 것은 **머리글만 있는 표** 입니다 — 행도 없고, 왜 없는지 말해 주는 문장도 없습니다.

## 그리고 빠져나올 수 없는 경우가 있었습니다

페이지를 0으로 되돌리는 effect 는 `[query, rows.length]` 에 걸려 있고, **렌더·페인트 뒤에** 돕니다.

- **검색을 친 직후** — effect 가 한 박자 늦게 도니 빈 표가 **한 프레임 깜빡입니다.**
- **행 수가 그대로인 채 내용만 바뀐 재조회** — 기간을 바꾸어 다시 불러왔는데 건수가 우연히 같으면, `query` 도 `rows.length` 도 바뀌지 않아 effect 가 **아예 돌지 않습니다.**

두 번째가 나쁩니다. 결과가 10건 이하이면 페이지 이동 컨트롤도 사라지므로, 앞 페이지로 **돌아갈 방법 자체가 화면에 없습니다.** 검색어를 지우기 전까지 표는 비어 있습니다.

## 자르기 전에 페이지를 범위 안으로 끌어옵니다

새 순수 모듈 `web/src/components/tablePaging.ts` 의 **`clampPage(page, pageSize, total)`** 하나를 둡니다. 계산이 한 곳에 있으니 **세 사용처가 같은 값을 읽습니다** — `slice`, `TablePagination` 의 페이지 번호, 기본 `rowKey` fallback.

- 행이 없거나 `pageSize` 가 0 이하이면 **첫 페이지**를 돌려줍니다. 나눌 수 없어 마지막 페이지가 `Infinity` 가 되는 경우를 호출자가 만나지 않습니다.
- 표시용 번호와 실제로 자르는 위치가 **더 이상 갈라지지 않습니다.** 갈라짐 자체가 이 결함이었습니다.

**손대지 않은 것**: effect 의 의존성 배열(행을 의존성에 넣으면 불필요한 페이지 리셋을 부릅니다), Empty 분기, 10건 임계, `onPageChange`·`onRowsPerPageChange`, CSV 내보내기. 프로덕션 파일은 **두 개**입니다.

`DataTable` 은 콘솔 전반에서 **62곳**이 쓰므로, 표가 있는 화면은 모두 같은 수정을 받습니다.

## 테스트

`web/test/tablePaging.test.mjs` 가 순수 함수를 순회로 고정합니다. clamp 를 raw `page` 로 되돌리면 6건 중 5건이 실패하고, 순회는 `page=1 pageSize=1 total=1 → 0행` 으로 잡습니다.

순수 함수만으로는 **배선**을 증명하지 못하므로 거기서 멈추지 않았습니다. vite dev 로 **진짜 `DataTable`** 을 실제 React·MUI 로 마운트하고 headless Chrome 으로 결함 시나리오를 그대로 몰았습니다 — 「alpha」 검색 → 4페이지 → 행 수는 100 그대로인 채 내용만 바뀌어 일치가 5건으로 줄어드는 재조회(effect 미발화):

- 수정 전 — `{"rows":0,"first":null,"empty":false,"pager":null}`
- 수정 후 — `{"rows":5,"first":"alpha-0"}`

## 그 밖에

Go 쪽 변경은 없습니다. Database Migration, SDK, API, 환경변수 변경 없음.
