# Momento 프로필 (2026-10-08)
- 기준: main@0beff4c, v0.34.61. 이번 정찰은 코드 변경 없이 실패 로그·과거 파일 재현·현재 보안 검사만 실행했다.
- 목적: 온프레미스에서 이벤트를 직접 수집·보존하고 제품·직원·경험·AI 사용을 분석하는 사내 플랫폼.
- 스택: Go 1.26.0/toolchain 1.26.7, chi·pgx·OIDC, PostgreSQL 17; React 19.1·TypeScript 5.9·MUI 7.3·Vite 7.3·React Query 5.85·echarts 6; TypeScript SDK.
- 구조:
  - cmd/momento — 서버 진입점. internal/httpapi — API·관리·분석 핸들러.
  - internal/service — 수집·Worker·자동화·Maintenance. internal/auth — 역할·인증 정본.
  - internal/database — Open·Migrate. embedded SQL 정본은 internal/database/migrations, 루트 migrations가 아니다.
  - internal/privacy·secret·segment·insight — 개인정보·암호화·세그먼트·인사이트.
  - web/src/pages/AdminPage.tsx — 약 4000줄 관리 화면. 섹션은 ?section=users|sites|retention|networks|schemas 등.
  - web/src/pages/*Rule.ts — 순수 입력 판정; adminErrors.ts — 실패 안내; 새 schemaTextRule.ts가 JSON 구문만 판정한다.
  - web/src/components — 공용 UI; DataTable.tsx는 여러 화면에 영향을 주며 AppShell.tsx가 내비게이션을 담당한다.
  - web/test·sdk/test — node:test로 TypeScript 원본을 직접 읽는다. 순수 .ts의 값 import에는 .ts 확장자가 필요하다. TSX의 Vite import 관례는 다르다.
  - sdk — 브라우저 수집기; docs — 사용자·관리자·오프라인 설치·설계·로드맵; scripts/guide — 화면 캡처·시드.
  - .github/workflows — ci.yml(테스트·보안·이미지), release.yml(태그 이미지·오프라인 smoke·게시), release-reconcile.yml(빠진 릴리즈 보완).
- 빌드·테스트:
  - make test: Go test/vet, SDK typecheck/test, web lint/test/build. 현재 보안 검사·Go race·Docker는 포함하지 않는다.
  - Go CI: go test -race ./cmd/... ./internal/...; go vet ./cmd/... ./internal/...; go run golang.org/x/vuln/cmd/govulncheck@latest ./cmd/... ./internal/...
  - SDK: cd sdk && npm ci && npm audit && npm run typecheck && npm test && npm run build.
  - web: cd web && npm ci && npm audit && npm run lint && npm test && npm run build.
  - make build는 SDK·web·Go 산출물을 쓴다. Dockerfile은 Node 24·Go 1.26.7을 사용한다. DB를 붙인 전체 race·이미지 빌드는 수 분이 걸릴 수 있다.
  - 이번 정찰 실측: 현재 govulncheck·SDK/web npm audit·go test ./internal/version 전부 종료 0. npm ci/전체 테스트/이미지 빌드는 이번 정찰에서 실행하지 않았다.
  - make verify와 make security-check는 이번 과제의 추가 예정 이름이며 아직 존재하지 않는다.
- 관례: 한국어 conventional commit, release: vX.Y.Z. DB settings와 환경변수로 설정한다. 사용자 안내는 adminErrors.ts, 필드 규칙은 순수 모듈에 둔다. docs/가 문서 위치다.
- 위험 구역: internal/auth, internal/httpapi/admin.go·server.go, internal/database/migrations, .github/workflows, docs/openapi.yaml. 서버가 권한·유효성 정본이며 화면이 서버보다 엄격해지지 않게 한다.
- 자주 깨지는 곳:
  - 자동 적재된 verify-failed와 현재 상태가 다를 수 있다. PR #29는 이미 병합되었고 main CI 37702077833·v0.34.61 릴리즈 37702752117이 성공했다.
  - 최근 실패 37687217169는 GO-2026-6629(x/text 0.39→0.41, fcf17ce 해결); 37545738339는 source-map-js npm audit(1.2.1→1.2.2, 97e3063 해결). 같은 원인은 아니다.
  - 두 실패 모두 과거 파일로 로컬 재현했고 현재에서는 통과했다. 고친 의존성을 다시 바꾸거나 감사 게이트를 완화하지 않는다.
  - Makefile:test와 README 개발 절차에 보안 검사가 빠져 있다. 이번 수정 과제는 로컬 검증 진입점을 보완하는 것이다.
  - npm lifecycle PATH가 Node 20을 가릴 수 있어 두 package.json의 test는 npm_node_execpath를 사용한다. lint/build는 재현 없이 건드리지 않는다.
  - 안내 문구를 글자 그대로 단언하는 테스트가 많다. AdminPage 행 번호는 매번 확인한다.
  - 이전 프로필의 '보존 정책 0을 저장 전에 막는다'는 잘못된 설명이다. 실제 RetentionAdmin의 disabled는 !local || save.isPending뿐이다. 범위 밖 숫자는 helperText만 오류이며 저장 요청은 가능하다.
- 검증 함정:
  - MOMENTO_TEST_POSTGRES_DSN 없으면 DB 통합 테스트는 skip한다. 이번 정찰은 DB 동작을 검증하지 않았다. 환경에 PostgreSQL이 없다는 단정도 재확인하지 않았다.
  - CI Node 24, 이번 로컬 Node 22.23.1/npm 10.9.8/Go 1.26.7. web과 SDK에 node_modules가 없었다. npm audit는 committed lock으로 설치 없이 실행 가능했다.
  - npm audit/govulncheck는 네트워크와 실행 시점 advisory에 의존한다. 이번에는 네트워크가 정상이며 신규 취약점은 다음 실행에서 달라질 수 있다.
  - release.yml smoke는 docker save한 archive를 다시 load하고 checksum·ready·버전/commit·콘솔·로그인까지 확인한다. make test를 이것의 대체로 쓰지 않는다.
  - release reconciliation 실패 37363965959·37370594454는 cancelled/steps=null이며 로그 404. 스크립트 결함 원인은 미확인이다.
  - README 기존 개발 블록은 cd ../web 뒤 make docker를 실행한다. 이번 문서 보완 시 서브셸로 루트 작업 디렉터리를 유지한다.
  - prettier는 의존성·CI 게이트가 없고 기존 파일도 실패하므로 새 게이트로 추가하지 않는다.
  - 브라우저 하네스에서 편집 후 같은 탭 재이동은 useUnsavedWarning의 beforeunload로 멈출 수 있다. 사례별 새 탭을 쓴다.
  - auth·audit details에 보호 대상 원문을 넣지 않는다. 테스트·실행 산출물은 커밋 대상에서 제외한다.
