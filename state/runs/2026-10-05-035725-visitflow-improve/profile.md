# VisitFlow 프로필 (2026-10-05)
- 목적: 사내 방문 신청·승인·QR 방문증·로비 체크인·알림·감사를 단일 컨테이너로 제공한다.
- 스택: Go 1.24(chi·pgx·go-oidc·excelize), PostgreSQL 14+, React 19·TypeScript 5.9·Vite 7·Material UI 7, Vitest 3·Playwright 1.56.
- 기준: HEAD 4d982f9 / v2.8.15(web/package.json도 2.8.15). 이전 2026-10-02 프로필의 버전·로컬 e2e·미머지 요청 티켓 설명을 갱신했다.
- 구조:
  - cmd/visitflow/: 서버 진입점 및 임베드 webdist. 기본 스텁과 실제 UI 빌드를 구분한다.
  - internal/app/: REST·MCP·SSE·방문·QR·알림. integration_test.go/lists_test.go는 실제 PostgreSQL 통합 테스트.
  - internal/platform/: 설정·암호화 등 기반 기능. internal/database/: 번호별 SQL 마이그레이션.
  - web/src/pages/: 신청·목록·승인·로비·관리자 페이지. 상태를 각 페이지가 직접 관리한다.
  - web/src/schedule.ts·visitors.ts·silentSso.ts: 순수 함수와 .test.ts 단위 테스트.
  - web/e2e/visit-flow.spec.ts: 실제 로그인·신청·QR·알림 재발송·회사 정책 브라우저 스펙.
  - scripts/local-e2e.sh: 실제 dist 임베드·전용 DB/서버 컨테이너·브라우저·정리. scripts/release-image.sh: 릴리즈 경로.
  - docs/: USER_GUIDE·ADMIN_GUIDE·API_AND_MCP·ARCHITECTURE와 PDF·이미지. CLAUDE.md·AGENTS.md·로드맵/TODO 문서 없음, 대상 소스 TODO/FIXME 검색 0건.

  - `cd web && npm ci && npm run lint && npm test && npm run build`. lint=tsc -b, test=vitest run. 직전 기록 88개; 이번 node_modules 없어 미실행.

- 자주 깨지는 곳:

  - MUI required label의 별표/공백, select aria-labelledby, 중복 버튼 이름은 실제 DOM로 locator 확인.

- 검증 함정:
  - vite.config.ts include는 src/**/*.test.ts만: .tsx 테스트는 수집되지 않고 testing-library도 없다. React 이벤트/상태 배선 증거는 실제 서버+브라우저로 남긴다.
  - tsc references는 src와 vite.config.ts만 포함. e2e/스크린샷 스펙과 Playwright config는 현재 별도 타입 검사되지 않는다.
  - createVisit은 QR URL을 요구하여 승인 대기 방문에 못 쓴다. CONTRACTOR+nda/safetyBriefing은 기존 Go 테스트의 승인 대기 생성 경로다.
  - openVisitDetail은 VF 번호로 방문 목록을 고른다. 승인 목록은 VF 번호를 표시하지 않아 unique purpose 같은 실제 열로 행을 고른다.
  - 오래된 프로필의 admin resources e2e 환경 의존 실패는 새 DB local-e2e에서 통과한 기록이 있다. 오염된 DB/고정 포트를 재사용하지 않는다.
  - VisitsPage 요청 티켓은 성공 원장과 달리 현재 HEAD에 없다. LobbyPage로 같은 접근을 재제출하는 아이디어는 이미 rejected.
  - 실제 Excel·SMTP·Keycloak 검증은 이번 수행하지 않았다. OAuth/SMTP 후속 브랜치 커밋도 아직 HEAD 조상이 아니다.
