# Invenqor 프로필 (2026-10-01)
- 목적: 에이전트(Rust)가 호스트·프로세스·소프트웨어를 수집해 Server(Go)로 보내고, 관리 콘솔(React)·REST·MCP 로 IT 자산 인벤토리를 조회·관리하는 시스템.
- 스택: Agent — Rust 1.85(`src/`, `Cargo.toml`, `tests/`). Server — Go(`server/`, chi 라우터, PostgreSQL 기본 + SQLite 폴백, go-oidc). 콘솔 — React+Vite+TypeScript(`web/`), 빌드 산출물을 `server/internal/webui/dist` 에 체크인해 임베드. 문서 — `docs/*.md` + PDF.
- 구조:
  - `server/cmd/invenqor-server` 진입점. `server/internal/httpapi` 가 REST·MCP·콘솔 핸들러 전부 — `server.go`(라우팅, split 은 434행), `assets.go`(목록·상세·`mergeAssets` 692~777·`splitAsset` 779~854), `mcp.go`, `query.go`, `settings.go`, `auth.go`, `mcp_oauth.go`, `users.go`, `classification.go`, `software_inventory.go`.
  - `server/internal/querydsl` Query DSL → SQL(postgres bool 로 방언 분기), `storage`(Runtime, Mode, LIKE 헬퍼, SQLite 는 `SetMaxOpenConns(1)`), `storagetest`, `auth`(계정·OIDC·TOTP), `apikeys`, `ingest`, `softwarecatalog`, `mail`, `tracking`, `updates`, `agents`.
  - `server/migrations/{postgres,sqlite}/NNN_*.sql` 두 방언(현재 009 까지). postgres 쪽은 `assets.id`·`asset_sources.id`·`asset_sources.asset_id` 가 UUID 열, sqlite 폴백은 TEXT — 형식이 틀린 id 가 방언별로 다르게 동작하는 원인.
  - `web/src` 콘솔, `web/scripts/sync-embedded.mjs` 가 dist 를 server 로 복사. `scripts/` 릴리즈·PDF·캡처·`test-postgres.sh`·e2e.
  - `openapi.yaml` 공개 계약(`openapi_routes_test.go` 가 라우터와 대조), `docs/API_MCP_GUIDE.md` 의 MCP 도구 표는 `mcp_tool_docs_test.go` 가 소스와 대조.
- 빌드·테스트: `cd server && go test ./... && go vet ./... && gofmt -l .`(SQLite, 수십 초, gofmt 는 빈 출력이어야 함) + `go build ./cmd/invenqor-server`. `scripts/test-postgres.sh`(docker postgres:17-alpine, 수 분 — 기본 포트 55432 가 점유돼 있을 수 있어 포트 지정 필요). `cd web && npm ci && npm test && npm run build`(build 뒤 `git diff --exit-code -- server/internal/webui/dist` 가 비어야 CI 통과). Rust: `cargo fmt --check`, `cargo clippy --all-targets -D warnings`, `cargo test --all-targets`(오래 걸림). `npx @redocly/cli@2.47.0 lint openapi.yaml`.
- 관례: 커밋 메시지는 한국어 문장형(`fix: …`, `feat: …`, `build: …`, `chore: release vX`). 릴리즈는 별도 회차(`docs/RELEASE_NOTES_vX.md`, 버전 범프·PDF 재생성을 구현 회차에서 하지 않음). 설정은 `settings` 표 행(`mail.*`, `mcp.oauth.*`)과 전용 관리 API. 테스트 헬퍼는 패키지 공용 — `newRuntime`/`testServer`/`authenticateInitialAdmin`/`performAuthenticatedJSON`(`admin_test_helpers_test.go:84`)/`insertSoftwareTestAsset`(`software_inventory_test.go:133`)/`countRows`(`asset_merge_validation_test.go:39`). 같은 이름을 새 파일에 다시 정의하면 컴파일이 깨진다.
- 위험 구역: `httpapi/auth.go`·`auth/`(세션·OIDC·API key, `authenticateAPIKey` 는 `/mcp` OAuth 분기 포함), `migrations/`(두 방언 동시 유지), `mergeAssets`/`splitAsset`(트랜잭션·`asset_changes`·`audit_logs` 기록), `webui/dist`(손으로 고치면 CI 실패), `.github/workflows`.
- 자주 깨지는 곳:
  - SQLite 에서 통과하고 PostgreSQL 에서 깨지는 SQL — JSONB 열에 LIKE(42883), 한 파라미터를 두 열에 재사용(타입 추론 충돌), LIKE 대소문자, 형식이 틀린 UUID(22P02). `attributes_json` 은 방언별 표현(`querydsl/query.go attributeExpressions`). 시간 열은 방언별로 문자열/`time.Time` 이라 `any` + `apiTime()` 로 정규화.
  - **트랜잭션 안에서 `s.internalError` 를 부르면 SQLite 폴백이 교착한다** — `internalError` → `recordDiagnostic` → `DB().ExecContext` 가 새 커넥션을 요구하는데 열린 tx 가 `SetMaxOpenConns(1)` 의 유일한 커넥션을 쥐고 있다. `assets.go:706` 한 곳만 `tx.Rollback()` 선행으로 고쳐졌고(주석 있음) `mergeAssets`·`splitAsset` 의 나머지 지점과 다른 핸들러는 그대로다. 증상은 500 이 아니라 **응답 없음 → 테스트 타임아웃**.
- 검증 함정: 기본 `go test` 는 SQLite 폴백이라 PostgreSQL 결함을 못 본다 → 방언이 걸리는 변경은 반드시 `scripts/test-postgres.sh` 로도 돌릴 것(이 환경에 docker 있음). 실제 Keycloak·실제 MCP 클라이언트는 없음. 테스트는 프로덕션 배선(실제 라우터·실제 Runtime)을 통과해야 하고 손으로 만든 대역으로 결함을 증명하면 반려. 무검증 구역: `POST /api/v1/assets/{assetID}/split` 에 테스트가 0건이다(2026-10-01 확인).
