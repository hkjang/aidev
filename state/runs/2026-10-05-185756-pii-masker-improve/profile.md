# pii-masker 프로필 (2026-10-05)
- 목적: PDF/PNG/JPG의 PII 영역을 Upstage 호환 추론으로 찾아 마스킹 파일을 돌려주는 동기·비동기 HTTP API와 Playground UI.
- 스택: go.mod Go 1.25.0(Dockerfile도 1.25.0), 로컬 toolchain으로 `go test` 통과. gorilla/mux, pdfcpu, x/image(bmp·tiff 포함), vendor 고정. DB 없음 — job.json·입력·출력을 디스크에 보관. 단일 HTML UI, Docker/Compose.
- 구조 (총 10.5k줄, 테스트가 절반):
  - cmd/pii-masker — 진입점.
  - internal/app (app.go 121줄) — HTTP 서버 배선, graceful drain, 보존 스위퍼 기동.
  - internal/config (config.go 347줄) — PII_MASKER_* Load/정규화. `SupportedMIMEs`는 config.go:155에 하드코딩(application/pdf, image/png, image/jpeg) — 환경변수 없음.
  - internal/httpapi (server.go 483줄, integration_test.go 2268줄) — mask/jobs/history/config/test-connection API, static/index.html UI.
  - internal/service (service.go 766줄) — 동기 슬롯·비동기 runner, draining, 보존 sweeper, 문서 처리. `summarizeFields`(:662)가 FieldEntry를 core.PIISummaryItem으로 옮긴다.
  - internal/jobs (store.go 290줄) — 메모리 맵·job.json 영속/복구, 고아·보존기간 삭제, 전체 clone 후 이력 정렬(`cloneJob` :265).
  - internal/upstage (client.go 821줄) — 인증, allow-host, 리다이렉트 횟수·HTTPS 강등 검사, `prepareUpstreamAttachment`(:336)가 이미지를 PNG로 정규화.
  - internal/document — attachment.go(파일명 sanitize·MIME 판정), image.go(DecodeImage/DetectImageFormat/ValidateImageDimensions, MaxImagePixels=50M).
  - internal/masking — engine.go 818줄(필드 수집·bbox→영역·이미지/PDF 마스킹), policy.go 431줄(규칙별 자리 마스킹 + ComputeMaskedRuneSpans).
  - internal/core/types.go 73줄 — 공용 JSON 계약. internal/mock/upstage.go — 내장 테스트 추론(pdf·png만 지원, :167).
  - scripts — smoke/export/run-from-archive(내용 미확인).
- 빌드·테스트: `go test -count=1 ./...`(8패키지, 1초 내), `go vet ./...`, `go build ./...`, `gofmt -l ./cmd ./internal`(무출력), `git diff --check`. 느린 것 없음. 외부 Upstage 불필요.
- 관례: 영어 명령문 커밋 + PR 머지, 한국어 README가 동작 문서. 환경변수 설정, DB 마이그레이션 없음, CLAUDE.md·docs/·.github CI 없음(이전 정찰 확인, 이번에 반증 없음).

- 자주 깨지는 곳:
  - 선언 MIME vs 실제 내용: 10/03·10/04 두 회차가 연속으로 이 축의 결함을 고쳤다(출력 인코딩, 업스트림 전송 바이트). 세 번째 경로를 건드릴 때는 "응답이 광고하는 것"과 "바이트"와 "업스트림이 받는 것"을 각각 확인할 것.
  - config의 곱셈 오버플로: duration 6건(9/29)·MiB(10/02) 해결. `envInt` 자체는 건드리지 않고 호출 지점만 바꾸는 패턴이 세 회차 연속 채택됐다.
  - 룬 정렬: policy.go의 마스킹 결과는 원문과 룬 수가 같아야 한다(ComputeMaskedRuneSpans policy.go:88). 깨지면 가림 상자가 엉뚱한 글자 위에 그려진다.
- 검증 함정:
  - `startAppServerWithConfig`(integration_test.go:1631)·`startAppServerWithUpstream`(:1637)은 config를 직접 조립한다. Load 관련 회귀는 customize 안에서 실제 `config.Load` 결과를 써야 한다.
  - `buildMultipartBody`(:1686)는 `contentType` 인자를 쓰지 않는다(CreateFormFile → application/octet-stream). 선언 MIME을 실제로 보내야 하면 `buildMultipartBodyWithFilenameParam`(:1713).
  - `t.Setenv` 테스트 병렬화 금지. 기본값 테스트 일부가 외부 환경 영향을 받으므로 신규 테스트는 값을 명시적으로 비운다.
  - 내장 mock은 application/pdf·image/png만 받는다(mock/upstage.go:167). jpeg나 커스텀 필드가 필요하면 직접 만든 handler를 `startAppServerWithUpstream`에 물릴 것.
  - `GOARCH=386 go test ./internal/document`는 `TestValidateImageDimensionsRejectsPixelBomb`에서 실패한다(32비트 PNG 디코더가 dimension overflow를 먼저 반환). 64비트 CI에서는 보이지 않음 — 이번 회차 재실행 미확인, 10/04 기록 기준.
  - `app.orDefault`와 `upstage.httpClient`는 비양수 timeout을 보정하지만 retention·syncQueueWait는 보정 없이 쓴다.
  - Docker 빌드·Windows Rename·32비트 실행 경로는 계속 미확인.
