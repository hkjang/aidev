fix: release jupiq v1.8.6

메일 발송 기록 목록이 알 수 없는 `status`를 조용히 빈 목록으로 답하던 것과, 프런트
`ApiError`가 목록·AI 경로에서만 서버 오류 코드를 잃던 것을 고쳐 릴리스합니다.
schema·설정 변경이 없고 정상 경로의 응답 형식이 그대로이므로 patch를 올립니다.

- `GET /api/v1/mail/deliveries?status=<알 수 없는 값>`이 그 값을 그대로 조건에 넣어
  일치하는 행이 없다는 이유로 200 빈 목록을 돌려주던 문제 — 오타를 낸 호출자가
  "발송 실패가 없다"로 읽습니다. `mail_handlers.go`가 `status`를 `TrimSpace`한 뒤
  빈 값과 `mail.StatusQueued`·`StatusSent`·`StatusFailed`만 통과시키고 나머지는
  400 `invalid_query`로 거부합니다. 통과한 값은 다듬어진 채로 store에 넘어갑니다
- `web/src/api/client.ts`의 `requestList`와 `streamAI`가 오류 봉투의 `error.code`를
  버리고 `ApiError`를 만들던 문제 — 같은 서버 응답인데 `request`로 부를 때만 코드가
  남아 화면이 코드로 분기할 수 없었습니다. 세 경로가 함께 쓰는 `httpError(body,
  status, fallback)`으로 봉투 해석을 한 곳에 모아 코드를 항상 싣습니다. 메시지
  fallback 문구와 status는 경로별로 종전과 같습니다
- 위 HTTP 오류 동작을 `client_http_errors.test.ts`로, 잘못된 status 거부를 실제
  PostgreSQL을 쓰는 `mail_deliveries_integration_test.go`로 덮었습니다. 새 테스트가
  Node 타입을 참조하므로 `web/package.json`에 `@types/node`를 devDependency로 명시해
  `tsc -b`가 환경에 우연히 들어온 타입에 기대지 않도록 했습니다
- migration·설정 변경 없습니다. 유효한 `status`와 모든 정상 응답은 무변경이고,
  `/usage`를 비롯한 다른 handler는 건드리지 않았습니다
