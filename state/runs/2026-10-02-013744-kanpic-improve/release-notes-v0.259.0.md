# v0.259.0

## 격일 일정에 요일을 함께 적으면 이제 그 요일에만 실행됩니다

자동화 일정은 cron 식의 다섯 필드로 적습니다. 그 가운데 **일**과 **요일**
두 필드는 다른 필드와 규칙이 다릅니다. crontab(5) 은 두 필드가 **모두**
날을 제한하고 있을 때만 "어느 한쪽이라도 맞으면 실행" 으로 합치고, 한쪽이
별표여서 아무 날도 걸러내지 않으면 나머지 한쪽만 봅니다.

kanpic 은 "이 필드는 제한하지 않는다" 를 글자가 정확히 `*` 인지로만
판정했습니다. 그래서 `*/2` 처럼 별표에 간격이 붙은 필드가 제한으로
분류됐고, 두 필드가 모두 제한된 것으로 읽혀 OR 로 합쳐졌습니다.

`0 0 */2 * MON` 을 적은 분의 의도는 "격일로 돌다가 월요일인 날" 입니다.
그런데 kanpic 은 이것을 "홀숫날 전부 **또는** 모든 월요일" 로 읽었습니다.
한 달에 두어 번 돌아야 할 일정이 보름 넘게, 요청하지 않은 날에 실행됐습니다.

자동화는 사람이 보고 있지 않을 때 워크북 셀을 직접 바꿉니다. 그래서 잘못된
날의 실행은 화면의 오류가 아니라 **이미 바뀐 값**으로 남았습니다. 되돌리려면
어느 변경이 의도한 실행이었는지를 사람이 가려내야 했습니다.

이제 판정을 필드의 첫 글자가 별표인지로 옮겼습니다. `*` 와 `*/2` 는 둘 다
제한하지 않는 필드가 되고, 일·요일을 합치는 규칙은 crontab(5) 과 같아집니다.

## 어떤 일정이 달라지나

달라지는 것은 일 또는 요일 필드에 `*/N` 을 적고 **다른 한쪽도 함께 제한한**
일정입니다. 실행되는 날이 줄어듭니다.

- `0 0 */2 * MON` — 홀숫날 전부 + 모든 월요일 → 홀숫날인 월요일에만
  (2026-11-09, 11-23, 12-07 … 짝숫날인 11-16 월요일은 돌지 않습니다)
- `0 0 1 * */2` — 1일 + 일·화·목·토 → 1일이면서 일·화·목·토인 날에만
  (2026-11-01 일, 12-01 화 … 금요일인 2027-01-01 은 돌지 않습니다)

`1,*/2` 처럼 별표가 아닌 값이 앞서는 필드는 전과 같이 제한으로 남습니다.
Vixie cron 도 필드 전체의 첫 글자만 보고 같게 판정합니다.

## 그 밖에 바뀌는 것은 없습니다

한쪽 필드만 별표인 일정(`0 0 * * MON`, `0 9 1 * *`)과 두 필드가 모두
목록·범위로 제한된 일정의 실행 날짜는 달라지지 않습니다. 일·요일을 쓰지 않는
분·시·월 필드도 그대로입니다.

목록·범위·간격·요일 이름(`MON`)·일요일 `7` 의 해석, `@daily` 같은 별칭,
서머타임과 윤일 처리, 일정의 시간대 설정은 손대지 않았습니다. 저장된 일정을
다시 적어야 하거나 마이그레이션이 필요한 변경은 없습니다.

## 확인

- 프로덕션 경로인 `ParseSchedule`→`Next` 를 연속 5회 돌려 실제로 반환되는
  시각의 날짜와 요일을 비교하는 표를 더했습니다. 위의 결함 사례 2건과,
  달라지면 안 되는 대조 사례 4건(`0 0 1-31 * MON`, `0 0 * * */3`,
  `* * * * MON`, `0 9 1 * *`)을 같은 자리에 두었습니다. 기대 날짜는 절대
  날짜라 실행 시점의 시계와 무관합니다.
- 릴리즈 준비에서 고친 한 줄만 이전 판정으로 되돌려 다시 실행했습니다.
  결함 사례 2건만 실패하고 대조 사례 4건은 그대로 통과했습니다. 테스트가
  바뀐 경로를 실제로 지난다는 뜻입니다. 되돌린 줄은 복구했습니다.
- `go test ./...`(20패키지 통과), `go test ./internal/automation -count=1`,
  `go vet ./...`, `go vet -tags=integration ./internal/...`, `go build ./...`,
  `gofmt -l ./cmd ./internal ./pkg`, `scripts/check-release-docs.sh`,
  `scripts/check-commit-identities.sh` 를 실행했습니다.
- 새 표는 UTC 로만 돌렸습니다. Asia/Seoul·America/New_York 을 쓰는 기존
  시간대 테스트가 통과하는 것으로만 확인했습니다.
- 웹·DB 통합·브라우저 E2E 는 이번 릴리즈 세션에서 재실행하지 않았습니다.
  변경은 Go 패키지 안쪽 순수 함수 한 곳이고 스키마와 API 응답은 그대로입니다.

## 올리실 때

v0.258.0 에서 올라오시는 분은 이미지를 바꿔 다시 띄우시면 됩니다.
마이그레이션이나 새 설정은 없고, 필수 환경 변수는 계속 `POSTGRES_DSN` 입니다.

올리기 전에 저장된 자동화 일정 가운데 일 또는 요일 필드에 `*/N` 을 쓰면서
다른 한쪽도 제한한 것이 있는지 보아 두십시오. 그 일정은 올린 뒤 실행되는 날이
줄어듭니다 — 지금까지의 잦은 실행에 맞춰 둔 업무가 있다면 일정을 의도대로
다시 적을 기회입니다.

운영 적용은 먼저 한 인스턴스에서 해당 일정의 다음 실행 날짜가 의도대로
나오는지 확인한 뒤 확대하십시오. 다음 실행 날짜가 의도와 다르거나 돌아야 할
일정이 돌지 않으면 운영 담당자가 확대를 중단하고 v0.258.0 이미지로 되돌릴 수
있습니다. 데이터 스키마는 바뀌지 않습니다. 적용 직후와 다음 주에 "일정이
돌지 않았다" 는 문의와 자동화 실행 기록을 함께 확인하십시오.

## 오프라인 설치

이 릴리즈는 웹 자산과 서버 바이너리를 포함한 Docker 이미지 아카이브로 제공됩니다.

```bash
sha256sum -c kanpic-v0.259.0.tar.gz.sha256
gzip -dc kanpic-v0.259.0.tar.gz | docker load
docker run --rm -p 8080:8080 \
  -e POSTGRES_DSN='postgres://kanpic:password@postgres.internal:5432/kanpic?sslmode=require' \
  kanpic:v0.259.0
```

- 필수 런타임 환경 변수: `POSTGRES_DSN`
- Redis 및 외부 인터넷 연결: 불필요
- 관리자 초기 로그인을 보호하려면 `BOOTSTRAP_ADMIN_ID`와 `BOOTSTRAP_ADMIN_PASSWORD`를 함께 지정합니다.
- 무결성 검증 파일: `kanpic-v0.259.0.tar.gz.sha256`
