- 왜: `UiBuilderController.saveList:40-46`(직접 읽어 확인)은 기존 행에서 `regDttm` 만 옮기고 `deletedAt` 은 옮기지 않은 뒤 `listRepository.save(list):53` 으로 통째로 덮어쓴다. 요청 본문에 `deletedAt` 이 없으면 필드는 null 이므로 **`deleted_at` 이 null 로 리셋되어 휴지통 목록이 되살아난다** — 이 저장소가 7회차에 걸쳐 여섯 경로(`NexaUiService.requireLiveList`·`DataAdapterService.queryList`·`ListExportController.resolveExportable`·`ListInlineEditController`·`BulkListController.resolveTarget`·`ReportService.generate`)와 `RuntimeUiController` 8화면·`TrashController.permanentDelete` 에 채워 넣은 soft-delete 안전망이 이 한 POST 로 우회되고, `/admin/trash/restore`(`TrashController:73`)가 유일한 복원 경로라는 전제가 깨진다. 같은 파일 `adminLists:28-30` 이 이미 `findByDeletedAtIsNullOrderByListIdAsc()` 로 휴지통 목록을 빌더 피커에서 숨기므로, 휴지통 listId 로 들어오는 저장은 정상 UI 흐름에서 나올 수 없다.

- 수용 기준:
  1) 살아 있는 목록을 `DELETE /api/v1/admin/lists/{listId}` 로 휴지통에 넣은 뒤 같은 listId 로 `POST /api/v1/admin/lists` 를 하면 **400** + `{"success":false,"message":"List not found: {listId}"}` 가 오고, `listRepository.findById(listId)` 로 다시 읽은 행의 `getDeletedAt()` 이 **여전히 null 이 아니며** 본문에 보낸 새 `listName` 이 **반영되지 않았다**(= 저장 자체가 일어나지 않았다). 삭제 여부·필드 값은 응답 코드가 아니라 **리포지토리 조회로 직접 단언**할 것.
  2) 거부된 요청은 메타데이터 버전 스냅샷을 남기지 않는다 — 즉 거부 판정이 `versionService.recordSnapshot(...)`(`:37-39`) **보다 앞**에 있다. `GET /api/v1/admin/versions?resourceType=<MetadataVersionService.TYPE_LIST 의 실제 값>&resourceId={listId}` 의 항목 수를 거부 POST **앞뒤로** 재어 변하지 않음을 단언한다(절대 개수를 박지 말 것 — 생성 POST 도 스냅샷을 찍는다). 이 단언이 이 환경에서 성립하지 않으면(응답 봉투·resourceType 값이 예상과 다르면) 단언을 버리고 **게이트 위치만** 지키고 그 사실을 보고할 것.
  3) 회귀 가드가 **수정 전에도 초록**이어야 한다(= 픽스처가 정말 `saveList` 를 지난다는 증명): ① 새 listId 로 첫 `POST` → 200 + `$.data.listId` + `regDttm` 이 채워지고 `deletedAt` 은 null ② **살아 있는** 기존 listId 로 두 번째 `POST` → 200 이고 `regDttm` 은 첫 저장 값 그대로 보존되며 `actDttm` 이 채워지고 새 `listName` 이 반영됨 ③ `DELETE /api/v1/admin/lists/{listId}` → 200 + `$.message` 가 `"trashed"` 이고 `getDeletedAt() != null`. (`ApiResponse.ok(String)` 은 `data` 가 아니라 **`message`** 오버로드로 바인딩된다 — 직전 회차에서 실측됨.)
  4) 기존 테스트 `EntityBindingsIntegrationTest`(:99-123, `/api/v1/admin/ui/scaffold` → `DELETE /api/v1/admin/lists/bind-test-list` 순서라 이번 게이트에 걸리지 않음)와 `SqlBackedListDefinitionIntegrationTest`(신규 listId 저장)는 **한 글자도 고치지 않고** 그대로 초록이다.
