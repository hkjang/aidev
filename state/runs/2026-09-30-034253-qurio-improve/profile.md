# Qurio 프로필 (2026-09-30)
- 목적: 오프라인 사내망용 AI SQL 워크벤치·데이터 카탈로그. 승인·감사·MCP/REST API 를 제공한다.
- 기준: main 계보 `3f7cf65` (chore: release Qurio v1.4.9), VERSION `1.4.9`. 이전 프로필(2026-09-26, 1.4.5) 폐기.
- 스택: Go(go.mod 1.26.6), pgx/v5·PostgreSQL 17, pure-Go Oracle 드라이버, React 19·TypeScript·Mantine·Vite·TanStack Query, Vitest·Playwright.
- 구조:
  - `cmd/qurio` — 실행·정리 루프·설치/마이그레이션 통합 테스트(`TestIntegrationDatabaseMigrations` 가 사실상의 테스트 DB bootstrap).
  - `internal/httpapi` — 라우팅·쿠키/세션·OIDC 콜백·설정·프로필·SPA 제공. `internal/oidcauth`·`internal/mcpoauth` — 웹 OIDC 및 MCP OAuth 리소스 서버(RFC 9728).
  - `internal/store` — 설정·계정·키·승인·감사 영속화.
  - `internal/domain/{dbexec,legacy,sqlsafe}` — DB 연결·SQL 정책·실행·스키마 탐색. `sqlsafe.go`(1378행)가 방언별 읽기 전용 게이트.
  - `internal/{legacyapi,platformapi,runtimeapi,agentapi,intelligenceapi}` — 기능별 API. `internal/authzread` 는 민감 GET 가드.
  - `internal/{jobs,backup,integrations,authn,cryptox,config,runtimeenv,version}` — 배경 작업·백업·연동·보조. `internal/webui/dist` — 임베드 SPA 자산.
  - `migrations` — 새 번호만 추가, 기존 SQL 수정 금지. `web` — SPA/Vitest/Playwright. `docs` — architecture/requirements/legacy-compatibility/guides.
  - `internal/mail` 은 존재하지 않는다. mail 전제 과제는 무효.
- 빌드·테스트: `make build`(npm ci→SPA 빌드→임베드 복사→Go 빌드, 느림); `make lint`(`check-go-format`(gofmt 읽기 전용) → go vet → 웹 tsc); `make test-go`; `make test-web`; `make test-e2e`(브라우저 필요·느림). 통합 테스트는 `-tags=integration` 이며 일반 `go test ./...`(28 패키지)에서 제외된다.
- 관례: 영어 conventional commits(UI/가이드 문자열은 한국어 포함). 런타임 환경변수는 `POSTGRES_DSN`·`BOOTSTRAP_ADMIN`·`BOOTSTRAP_ADMIN_PASSWORD`·`ENCRYPTION_KEY` 네 개, 나머지 설정은 DB(`qurio_settings`). AGENTS.md·CLAUDE.md·roadmap·TODO/FIXME 없음. `docs/requirements.md` 가 버전 추적표.
- 위험 구역: `internal/httpapi`(인증/세션), `internal/oidcauth`·`internal/mcpoauth`, `internal/store/api_key_rate.go`, `internal/agentapi`, `migrations`, `.github/workflows`(ci.yml·release.yml). 감사·로그에는 스크럽 이전 원문을 넣지 않는다(식별자만).
- 자주 깨지는 곳:
  - **sqlsafe 의 PostgreSQL 별칭 컬럼 목록 면제**: `postgresAliasColumnList`(sqlsafe.go:751)가 토큰 모양만 보고 면제하면 fail-open 이 된다 — 440aa9f(`)` 뒤), 89b3e76(`=(` 인접), e1af783(점 표기), 7cda7f5(WITH ORDINALITY) 네 번 같은 뿌리로 고쳤다. 새 면제는 반드시 `fromItemContext`(sqlsafe.go:881)로 FROM 문맥을 요구하고 판단 불가 시 fail-closed 여야 한다. 아직 `AS` 분기(771행)와 비수식 별칭 형태가 남아 있다.
  - 로그인 뒤 목적지를 `LoginPage.tsx` 와 `App.tsx PublicOnly` 두 경로가 각각 계산한다 — 한쪽만 고치면 react-router 7 `startTransition` 커밋 순서로 다른 쪽이 덮어쓴다. PR #18 이 이 영역에서 닫혔다.
  - 통합 테스트 픽스처 정리: `defer pool.Close()` 가 `t.Cleanup(DELETE…)` 보다 먼저 실행돼 정리가 조용히 죽는다. **main 기준 54곳 / 32파일 잔존**(legacyapi 10, runtimeapi 11, intelligenceapi 8, agentapi 4, httpapi 4, store 4, backup 3, integrations 3, jobs 2, domain/legacy 2, platformapi 1, cmd 1 …). a8f0775(runtimeapi·intelligenceapi·platformapi 19곳)는 **여전히 미머지**이므로 그 세 패키지는 중복을 피할 것.
- 검증 함정:
  - CI(`ci.yml`)·release 는 PostgreSQL 17 에 `POSTGRES_DSN`·`QURIO_INTEGRATION_DSN`·`QURIO_TEST_POSTGRES_DSN` **세 env 를 같은 폐기 DB** 로 지정하고 bootstrap 후 `go test -race -p=1 -tags=integration ./...` 를 돌린다. 한 테스트가 남긴 행이 다른 테스트에 보인다.
  - **CI 는 `make lint` 를 호출하지 않는다** — Makefile 에 검사를 더해도 CI 검사가 되지는 않는다.
  - `internal/domain/dbexec` 만 `QURIO_TEST_POSTGRES_DSN` 전용(미설정 Skip, 연결 오류 Fatal). 나머지는 `POSTGRES_DSN`/기본 55432 를 읽고 연결 오류를 Skip 한다(세 관례 공존).
  - dbexec 픽스처는 `public` 고정명과 pg_catalog 함수·캐스트를 CREATE/DROP 하므로 전용 폐기 DB·`-p=1` 직렬 실행이 필요하다.
  - 로컬 포트 55432/55433/55439 가 다른 세션에 점유된 사례가 반복됐다 — 비어 있는 포트를 고르고 컨테이너는 반드시 제거.
  - release 는 Oracle 실서비스도 기동, 일반 CI 는 PostgreSQL 만. 릴리즈·빌드 경로를 건드리면 릴리즈까지 통과를 확인해야 한다.
  - sqlsafe 변경은 단위 테스트만으로 부족하다 — base 파일과 수정본에서 현실 질의 50건+ × 2방언 판정을 덤프해 diff 하고 "새로 막히는 질의 0건"·"Oracle 판정 불변" 을 보이는 것이 이 저장소의 확립된 증명 방식이다.
