# Kkiit 프로필 (2026-10-07)
- 목적: 사람·기업·AI Agent 의 전문 서비스를 주문·납품·구매확정·정산으로 연결하는 오프라인 운영 가능 마켓플레이스.
- 기준: main@7cd2c6c, v0.4.15. 2026-10-05 프로필에서 버전·남은 결함 목록만 갱신(스택·구조·명령은 재확인 없이 유지).
- 스택: Go 1.26, net/http, pgx/v5, PostgreSQL 16+; React 19, TypeScript 5.9, MUI 7, Vite 8; 웹 번들은 Go embed.
- 구조:
  - cmd/kkiit: 프로세스·HTTP 서버·워커 시작과 종료.
  - internal/httpapi: router.go 가 라우트 정본; 도메인별 핸들러와 단위/통합 테스트(integration_test.go 한 파일).
  - internal/database/migrations: 번호 SQL, 시작 시 advisory lock 안에서 자동 적용.
  - internal/worker: Outbox·알림·웹훅·위험·정산·신뢰 점수 배경 처리.
  - internal/config·cryptox·password: 환경 설정, 비밀 암호화, 비밀번호.
  - internal/analytics·mail·netguard: 방문 추적, SMTP, 웹훅 주소 정책.
  - web/src: React UI, pages/AdminPage.tsx 에 관리자 기능.
  - internal/ui/dist: 추적하는 embed 번들. 검증 빌드 산출물 커밋 금지.
  - docs: USER_GUIDE/ADMIN_GUIDE(md·pdf), architecture.md, mcp.md, openapi.yaml.
- 빌드·테스트:
  - `go test ./cmd/... ./internal/...` — DSN 없으면 통합 SKIP.
  - `go vet ./cmd/... ./internal/...`, `gofmt -l cmd internal` — 표준 검증.
  - `make test-integration KKIIT_TEST_DSN=postgres://…` — 전용 폐기 DB 필수. timeout 300s, httpapi 실측 82~92초.
  - `npm --prefix web test` — README 요구 Node 24+ 에서 10건. 이 기계의 PATH 에 Node 20 이 끼어들면 글롭이 0건이 된다(저장소 결함 아님, 2026-10-03 기각).
  - `make check` — Go 포맷/test/vet, npm ci/lint/test/build. 설치 시간이 들고 추적 dist 가 바뀔 수 있음.
  - `make build` — 웹 빌드 후 bin/kkiit 생성.
- 관례: fix:/feat:/chore:/docs: + 한국어 설명, 릴리스 커밋은 `Kkiit vX.Y.Z — <한국어 요약>`. 가변 정책은 system_settings JSONB.
  오류는 `writeError(status, code, 한국어 메시지)`, 프런트는 `error.message` 를 그대로 띄운다(= 메시지만 고치면 UI 변경 불필요).
  설정: 필수 POSTGRES_DSN/BOOTSTRAP_ADMIN/BOOTSTRAP_ADMIN_PASSWORD/ENCRYPTION_KEY; 선택 SHUTDOWN_DRAIN_SECONDS(기본 5, 0~120).
  README 실행 계약의 "네 개뿐" 과 Config 주석은 선택 환경변수와 여전히 불일치(2026-10-05 기록, 이번 미재확인).
- 위험 구역: httpapi/auth.go·middleware.go·identity.go(인증/RBAC), orders.go·finance.go(원장), database/migrations(번호 충돌), .github/workflows/release.yml(배포).
- 자주 깨지는 곳:
  - 금액 산술에 상한 검사가 없다. `computeDiscount` 의 퍼센트 곱셈은 2026-10-05 에 고쳤으나 `createOrder` 의 `price += optionPrice`(orders.go:95)는 그대로이고, `validateTalent`(talents.go:263-285)도 음수만 거절한다. 같은 계열을 더 찾을 때는 "int64 누적 + DB CHECK (x >= 0)" 조합을 보라.
  - DB 오류와 부재를 404/409 로 묶는 분기: webhooks·discovery·admin_users·auth(register)·coupons 생성/수정·reports·mcp 는 수정 완료. 남은 8곳(approvals 229, coupons 351, events 104, finance 101, identity 110, keys 183, organizations 256, reports 291)은 파라미터가 uuid·선검증 enum 뿐이라 HTTP 로 DB 오류를 만들 길이 없다 — 이 캠페인은 증거를 댈 사례를 소진했다.
  - pgx `rows.Next()` 루프가 `rows.Err()` 를 보지 않고 Scan 실패를 `continue` 로 삼키는 곳이 있다(예: orders.go:88-100).
  - OpenAPI 응답 코드 누락이 계속 남음. openapi_test.go 는 라우트 경로만 비교하고 응답 코드는 검사하지 않는다.
  - `REQUIREMENT_PENDING` 은 어떤 HTTP 경로로도 도달 불가한 死상태(2026-10-06 확인). pay 가 PAID→READY 를 한 트랜잭션에 커밋한다.
  - AdminPage ApprovalAdmin.save 는 알려진 조건 5개로 재구성 — 알 수 없는 조건 유실 가능. toggle 은 원래 조건 보존.
- 검증 함정:
  - `integrationServer` 는 실제 Handler·DB·Worker 를 연결하고 `apiUnderTest` 전역을 공유 — 테스트 병렬화 금지.
  - 같은 DB 에 `-run Integration` 을 두 번 돌리면 `TestIntegrationMailNotificationsLeaveThroughTheRelay`·`TestIntegrationAgentCanResearchBeforeBuying` 가 실패한다(사전 존재 결함, baseline 에서 재현 확인). 판정은 깨끗한 DB(DROP/CREATE)로.
  - `client.do` 는 `json.Unmarshal(map[string]any)` 로 숫자를 float64 로 읽는다. 큰 정수 검증은 정확히 표현되는 값 또는 pool 로 int64 Scan.
  - 통합 도우미: `operatorClient`(:545), `sellTalent`(:378 — **옵션을 등록하지 않는다**, packages·requirements 만), `newClient.register/do`, `grantRole`, `mcpClient`.
  - NUL text 입력으로 PG 22021 을 만드는 저장 오류 재현 수법은 uuid/enum 만 받는 경로에는 통하지 않는다.
  - release.yml 은 v* 태그에서 Docker 빌드·archive 재로드·GitHub Release 수행, make check/DB 통합 단계 없음.
  - 2026-10-06 확인: Docker 서버 29.7.2 가용, Go 1.26.7. 이번 회차는 순수 읽기로 DB·docker 미사용.
