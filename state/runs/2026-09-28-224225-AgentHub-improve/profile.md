# AgentHub 프로필 (2026-09-28)
- 목적: 사용자별 격리 AI 런타임과 자동 작업을 정책·승인·DLP·감사로 통제하는 사내 플랫폼.
- 스택: Go 1.25(chi, pgx, go-oidc, OpenTelemetry), PostgreSQL, React/TypeScript/Vite, Kubernetes, Playwright/Node 22.
- 구조:
  - cmd/: control-plane·worker·runtime-proxy·offline 진입점.
  - internal/api/: 라우트 등록이 server.go(무인증/게이트웨이 구간)와 catalog.go(관리자·일반 카탈로그)로 나뉜다. routes.go(72KB)·execution.go(54KB)·catalog.go(35KB)가 가장 크다. 설정 PUT 의 검증 분기는 routes.go:1700-1745 의 switch(키별로 decode…Settings + Validate()).
  - internal/store/: PostgreSQL 저장·마이그레이션·감사·메일 큐.
  - internal/execution/, internal/mail/: 자동 실행·이벤트 전달 및 SMTP 큐.
  - internal/runtimecfg/, internal/operator/: 런타임 설정 문서·Kubernetes 적용.
  - internal/dlp/, internal/tracking/: 내용 검사와 방문 추적/CSP 위반 기록(메모리 Recorder, MaxViolations=100).
  - 그 밖에 acp·agentserver·guard·imagecatalog·korean·modelprobe·offlinebundle·policy·quota·runtime*·telemetry·workflow.
  - web/src/: 콘솔. web/scripts/: 브라우저 e2e 40여 개 + Node 회귀 4개(*.test.mjs) + 가이드 촬영.
  - deploy/, scripts/: Kubernetes/offline 배포와 이미지 릴리즈 검사. runtime-images.json: 이미지별 sourcePaths/버전. docs/: ADMIN_GUIDE·USER_GUIDE(md+PDF), architecture.md, decisions/.
- 빌드·테스트: CI 는 `go test -race ./cmd/... ./internal/...`; web 은 `npm ci && npm run lint && npm run test:sso && npm run build`; `bash scripts/release-catalog-images.sh check-versions`; kustomize/compose 검사.
- 빌드·테스트: 값싼 로컬 확인 — `go test ./internal/tracking ./internal/api`(2026-09-28 실행, DSN 없이 ok, api 1.6초), `go test ./cmd/runtime-proxy`, `cd web && node --test scripts/*.test.mjs`, `node --check scripts/<name>.mjs`. `internal/api` 의 비-live 테스트는 DB 없이 `&Server{…}` 를 세워 `server.Handler()` 로 실제 라우터를 통과한다(tracking_test.go 의 trackingServer).
- 빌드·테스트: DB live 에는 격리 AGENTHUB_TEST_DSN 과 base64 32바이트 AGENTHUB_ENCRYPTION_KEY 필요, 패키지 동시 DB 오염 때문에 `-p 1` 권장. DSN 이 없으면 `docker run postgres:16-alpine` 으로 일회용 DB 를 띄운 선례가 있다(2026-09-27). .github/workflows/live-agents.yaml 은 실제 이미지 빌드+실행으로 최대 90분.
- 관례: 한국어 설명 문장 + 영어 conventional 커밋(`fix: …` 뒤 한국어 요약). 주석은 산문체 한두 문단으로 "왜" 를 적는다 — 새 코드도 그 밀도를 맞출 것(본보기: internal/tracking/violations.go:10-33). 설정은 system_settings 의 키별 JSON 행 + 별도 secret 슬롯. 정본 문서는 docs/ 의 대문자 가이드.
- 관례: 현재 main HEAD 2bb1512, VERSION 0.254.0(2026-09-28 릴리즈). BASE_VERSION 은 런타임 base 이미지용으로 별도 — `runtime-images.json` base 항목의 sourcePaths 는 Dockerfile.base·go.mod·go.sum·`cmd/runtime-proxy`·`internal/dlp`·`internal/policy`·deploy/runtime/*.sh 뿐이므로, 그 밖(internal/tracking, internal/api 등)만 바꾸면 BASE_VERSION 상향이 필요 없다.
- 위험 구역: internal/api/auth.go·mcpoauth.go, session gateway, internal/store 마이그레이션, .github/workflows. 변경 전 해당 코드를 직접 읽을 것.
- 위험 구역: internal/api/server.go 의 무인증 구간 — `/runtime-gateway/*`(런타임 토큰)와 `POST /api/v1/tracking/csp-report`(세션·CSRF 없음, 브라우저가 report-uri 로 POST). 이 구간에 들어오는 값은 전부 신뢰할 수 없다. 라우팅은 건드리지 말고 값 정규화만 할 것.
- 위험 구역: 관리자가 넣은 값이 응답 **헤더**가 되는 유일한 경로 — internal/api/tracking.go:101 `pagePolicy()` 가 `tracking.Settings.PolicySources()` 의 문자열을 공백 join 으로 Content-Security-Policy 에 붙인다. 여기로 가는 값의 검사는 `internal/tracking/tracking.go:116 Validate()` 한 곳뿐이고, 그것이 두 쓰기 경로(routes.go:1736 의 설정 PUT, tracking.go:274 의 한 번 클릭 허용)의 공통 지점이다.
- 위험 구역: policy/DLP/runtime-settings PUT 은 실행 중 런타임에 영향을 준다. 설정 스크립트 검증은 격리·폐기 배포에서만.
- 위험 구역: 정책 지점의 행위자는 작업 소유자(task.OwnerID). agent.OwnerID 는 자격증명 조회(SCMTokenFor)에만 맞다.
- 자주 깨지는 곳: API 응답 래퍼와 스크립트의 접근 경로 불일치, 전역 설정 백업/복원, DLP 의 복사된 필드(Category=Agent), 문서의 HTTP 메서드.
- 자주 깨지는 곳: 외부에서 온 문자열을 검사 없이 감사·헤더·로그로 흘리는 계열의 결함이 **경로마다 따로** 존재한다. internal/api/dlp.go 는 2026-09-27 에 512 룬으로, internal/tracking/violations.go 는 2026-09-28 에 `cutRunes`(origin 300 / directive 64 / page 200 룬)로 닫혔다 — 이 둘은 이제 고쳐졌으니 다시 고르지 말 것. 아직 열린 곳: `Settings.AllowedHosts` 의 항목에 길이 상한도 세미콜론 검사도 없다(`splitHosts` 는 공백·쉼표·줄바꿈만 끊는다), 그리고 internal/api/tracking.go:283 의 감사 details `"origin"`.
- 자주 깨지는 곳: `PolicySources()` 안에서 Momento·Matomo 분기는 `originOf()` 를 거치지만 AllowedHosts 루프(tracking.go:305-307)만 거치지 않는다. 같은 값을 읽는 두 경로의 비대칭을 볼 것.
- 검증 함정: runtime-settings GET 은 `{settings:{profiles:[]},suggestions,runtimes,targets}`, PUT 은 `{profiles:[]}`. 일반 설정은 전체 GET body[key] + 키별 PUT `{value:…}`. policy 는 GET/PUT `document`, DLP 는 GET/PUT `settings`.
- 검증 함정: 관리자 API 는 관리자 세션 + CSRF 를 요구하며 API 키로는 안 된다.
- 검증 함정: web/scripts 의 Node 회귀 테스트는 실제 스크립트 소스를 문자열로 잘라 vm 컨텍스트에서 돌린다(guide-settings-check.test.mjs 의 `boundary` 슬라이스). 슬라이스 앵커 밖에 선언을 두면 ReferenceError 가 나고, vm 컨텍스트는 전역을 명시적으로만 받는다.
- 검증 함정: CI 의 `test:sso` 는 silent-sso.test.mjs 한 파일만 돌린다 — guide-settings-check·session-gateway-check·runtime-settings-check 는 어느 npm 스크립트에도 없어 CI 에서 실행되지 않는다.
- 검증 함정: web/node_modules 없음. eslint 는 src 의 TS 만 검사. DSN 없는 Go 성공은 DB 동작의 증명이 아니다.
- 검증 함정: 실물 브라우저 e2e·클러스터·Keycloak·SMTP 는 이 환경에서 미확인. 이전 회차의 성공을 현재 환경의 확인으로 쓰지 않는다.
- 검증 함정: Bash 승인이 명령마다 다르다. 2026-09-28 회차에 `go test ./internal/tracking ./internal/api` 와 `git log`·`grep` 은 통과했으나 임시 `go run` 스크립트와 `bash scripts/release-catalog-images.sh check-versions` 는 승인 거부였다. 한 줄에 `&&` 로 여러 명령을 이으면 거부될 확률이 올라간다 — 한 번에 하나씩 보낼 것. 스크립트 실행이 막히면 매니페스트(runtime-images.json)를 직접 읽어 판정할 수 있다.
- 미확인: CLAUDE.md·AGENTS.md·별도 roadmap·소스 TODO/FIXME 는 저장소 검색에서 발견되지 않았다(2026-09-28 재확인).
