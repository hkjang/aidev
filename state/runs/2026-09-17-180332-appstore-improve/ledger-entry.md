(2) 리소스 식별자 출처: `mcp.oauth.resource` → 시스템 설정의 서비스 접속 URL(`system.siteUrl`, 이미 OIDC redirect URL 을 만드는 그 값) + `/mcp` → 요청 Host(마지막 수단) 순. 저장 시 식별자는 절대 HTTP(S)·자격/쿼리/프래그먼트 없음·`/mcp` 로 끝남을 요구하고, 켤 때는 Issuer 와 (식별자 또는 서비스 URL)이 있어야 422 없이 저장된다. (3) 대상 검사는 프롬프트 그대로 — `aud` 에 식별자, 또는 `aud`/`azp` 가 허용 대상 목록에 있어야 하며 weekly 처럼 웹 로그인 client_id 를 자동으로 받아 주지는 않았다(postra 가 웹 클라이언트와 MCP 클라이언트를 분리하라고 하므로; 필요하면 관리자가 목록에 적으면 된다). 거부 메시지는 본 `aud`/`azp` 와 고칠 값(허용 대상에 더할 azp, 매퍼에 넣을 식별자)을 담는다. (4) 계정 매핑은 `sub` → `GetUserBySubject` 만 쓴다. 웹 로그인이 subject 로 upsert 하므로 정확히 같은 정체성이고, username 으로 되찾으면 bootstrap `admin` 같은 로컬 계정을 Keycloak 의 `preferred_username=admin` 이 가로챌 수 있어 뺐다. 없으면 "먼저 웹으로 로그인", 비활성이면 거부, 계정·권한 생성 없음. (5) 권한은 키와 같은 문 — `mcp.oauth.scopes`(기본 `mcp:read apps:read`) ∩ 활성 key_permission_definitions ∩ 그 사용자의 역할 권한(super_admin 은 사용자 게이트만 통과, `*` 는 절대 안 줌), 토큰 `scope` 에 이 앱 어휘가 실려 오면 교집합만. `Principal.AuthMethod="oauth"` 로 `/mcp` 에서만 받고 REST `Optional` 미들웨어는 손대지 않아 JWT bearer 는 전처럼 무시된다. 구현: `internal/auth/access_token.go`(issuer 별 provider 캐시 + `context.WithoutCancel`, RS/ES/PS 만, JOSE 헤더와 claim 의 `typ=ID` 거부, `cnf` 거부, `sub` 필수), `internal/httpapi/mcp_oauth.go`(순수 `resolveMCPOAuth`, 메타데이터 핸들러 — 맨 JSON·`Access-Control-Allow-Origin: *`·꺼지면 404, `mcpChallenge`, `oauthPrincipal`, `oauthPermissions`), `mcp.Server` 에 `Challenge` 훅과 `AuthError`(거부 사유를 401 본문에), `authenticateMCP` 가 같은 Bearer 헤더에서 `aps_` 면 키·JWT 모양이고 SSO 가 살아 있으면 토큰·아니면 전과 같이 무시. 관리 화면 MCP 카드에 스위치·리소스 식별자·허용 대상·범위·읽기 전용 상태(Issuer, MCP 주소, 메타데이터 주소 + 복사)를 두고 GET /admin/mcp 가 `oauth.status` 를 실어 준다. 키 페이지는 공개 설정의 `mcpOauthResource` 가 있을 때만 "키 없이 SSO 로 MCP 연결하기" 안내.
