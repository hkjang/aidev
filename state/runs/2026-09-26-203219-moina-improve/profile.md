  - `make test`는 `go test ./...`로 **-race 없이** 돌고 CI source는 `-race`를 쓴다. 이 차이를 과제로 두 번 골랐다가 두 번 no-change — 단독 과제로 다시 고르지 말 것.
  - `make image`와 앱+DB 준비 후 `npm test --prefix e2e`는 느림. e2e 순서는 visual → accessibility → smoke.
- 관례: 커밋은 한국어 `feat:`/`fix:`/`test:`/`docs:`/`release:`. 환경변수는 DB DSN·bootstrap ID/비밀번호·암호화 키 4개; 기능 설정은 DB JSON/API camelCase. migration은 새 번호 추가, 과거 checksum 변경 금지.
  - 오류 계약 관례: 저장 실패는 `500 storage_error`, 대상 없음은 `404 not_found`, 상태 충돌은 `409`. 새 message를 만들기보다 같은 파일의 기존 문구를 재사용한다.
  - OpenAPI는 성공 코드만 `responses`에 나열하고 오류 계약은 `description` 문장으로 적는다. 응답 목록을 늘리지 말 것.
  - integration 테스트 관례(`moim_join_postgres_integration_test.go:74~120`이 정본): `MOINA_TEST_POSTGRES_DSN` 없으면 `t.Skip`, `store.Open` → `New(repository, secrets, "vX-test")` → `server.Handler()`, `sessions` 행을 `secrets.HashToken`으로 직접 삽입, 요청에 `X-CSRF-Token` 헤더 + `SessionCookie` 쿠키, `httptest.NewRequest` + `handler.ServeHTTP`. 저장 실패 분기는 대역이 아니라 **테스트 전용 BEFORE INSERT/UPDATE/DELETE 트리거가 sentinel id만 거부**하는 방식으로 재현한다(검증된 기법).
- 위험 구역: httpapi/auth.go·oidc.go·mcp_oauth.go(세션·토큰·권한), store/migrations(영구 데이터), media(LO·quota), securityHeaders/serveSPA(CSP·nonce), .github/workflows/release.yml(정확한 commit CI 성공 요구), server.go의 `decodeJSON`·`pagination` 같은 공유 헬퍼(수십 개 handler가 의존).
- 자주 깨지는 곳: 시각 회귀는 한글 폰트·origin 차이로 전체 불일치 — 공식 Playwright v1.62.1-noble와 127.0.0.1:18080, `MOINA_VISUAL_ONLY`로 범위 제한. 24개 화면이 허용치 0.5% 대비 0.15~0.345%로 아슬아슬하다. 로그인 IP당 5회/5분 제한 주의.
  - PATCH 문서에서 handler만 보고 middleware 403을 지웠다가 3b95053에서 복구 — 인증·CSRF 응답은 handler 코드에 없어도 실재한다.
  - `multipart` part의 `filename=""`는 파일이 아니라 값으로 파싱된다(Go `mime/multipart/formdata.go`).
  - SELECT 실패 분기는 평 PostgreSQL에서 재현 수단이 없다(트리거는 SELECT에 못 걸고 RLS는 공유 테이블 전역 변경). getMoim·getTopic·createReport·joinMoim의 `Scan` 오류 후보가 네 회차째 이 벽에 막혀 있다 — 전용 스키마 테스트 헬퍼가 선행되어야 한다.
