# Invenqor 프로필 (2026-10-05)
- 목적: Rust Agent가 호스트·프로세스·소프트웨어를 수집해 Go Server로 보내고 React 콘솔·REST·MCP로 IT 자산을 관리하는 시스템.
- 스택: Rust 1.85(Agent, Linux/Windows), Go 1.25.14(chi·go-oidc·pgx·modernc sqlite), PostgreSQL 기본/명시적 SQLite 폴백, React 19·TypeScript·Vite 7·Vitest.
- 구조:
  - `src/`, `tests/`, `Cargo.toml`: Agent 수집·전송·업데이트와 Rust 테스트.
  - `server/cmd/invenqor-server`: 서버 진입점. `server/internal/httpapi`: REST·MCP·콘솔 핸들러와 실제 라우터 테스트.
  - `httpapi/assets.go`: assetHistory:536, assetRelations:574, createAssetRelation:622, deleteAssetRelation:654, canonicalUUID:687, assetIDParam:708, merge/split 및 감사. 위치는 main@12ada2f 기준.
  - `server/internal/{querydsl,storage,storagetest,auth,apikeys,ingest,softwarecatalog,mail,tracking,updates,agents,audit}`: DSL·DB·인증·수집과 운영 서비스.
  - `server/migrations/{postgres,sqlite}`: 같은 순번의 두 SQL 방언 유지. PostgreSQL assets/asset_relations ID는 UUID, SQLite는 TEXT.
  - `web/src`: 콘솔. `web/scripts/sync-embedded.mjs`가 React 빌드를 체크인 대상 `server/internal/webui/dist`로 복사.
  - `openapi.yaml`: 공개 API. `docs/`: 역할별 Markdown/PDF·릴리즈 노트. `scripts/`: PostgreSQL 테스트·패키징·e2e·문서 생성.
- 빌드·테스트:
  - `cd server && go test ./... && go vet ./...`; 포맷은 `gofmt -l .` 빈 출력. 빌드는 `go build ./cmd/invenqor-server`(바이너리 생성).
  - 좁은 검증: `cd server && go test ./internal/httpapi/ -run 'AssetRoutes|AssetCollections|Merge|Split|Relation' -count=1` — 10/05 실제 통과, 6.683초.
  - 루트: `POSTGRES_CONTAINER=invenqor-scout-20261005-063728 POSTGRES_PORT=55505 ./scripts/test-postgres.sh -run 'AssetRoutes|AssetCollections|Merge|Split|Relation' -count=1` — 10/05 실제 통과, httpapi 11.853초. 필터 없이 전체 실행 가능(더 오래 걸림).
  - `cd web && npm ci && npm test && npm run build`; 빌드 후 루트 `git diff --exit-code -- server/internal/webui/dist`가 CI 검증. `npx --yes @redocly/cli@2.47.0 lint openapi.yaml`.
  - Rust: `cargo fmt --all -- --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --all-targets`; 크로스 빌드와 Linux/Windows e2e는 CI 장기 작업.
- 관례: 최근 커밋은 한국어 fix/build/chore 및 별도 버전 릴리즈. 설정은 DB settings와 관리 API. migrations 두 방언 동시 유지. 버전·PDF 재생성은 일반 구현 과제에 섞지 않는다.
- 위험 구역: auth/session/OIDC/API key 권한(`httpapi/auth.go`, `auth/`), migrations, merge/split 트랜잭션·감사, `.github/workflows`, 임베드 UI 산출물. 정찰에서는 코드·커밋을 변경하지 않는다.
- 자주 깨지는 곳:
  - PostgreSQL JSONB LIKE·공유 파라미터 타입 추론·LIKE 대소문자·UUID 입력과 SQLite의 차이. 기본 go test 통과만으로 PostgreSQL 동작을 보장하지 못한다.
  - canonicalUUID는 하이픈 있는 36자만 허용하며 대문자를 소문자로 돌린다. 중괄호·32자·urn은 거절한다. merge·split과 상세/수정/삭제/복원/history/relations 조회에 적용 완료; 관계 생성·삭제는 이번 선택 과제로 아직 미구현.
  - SQLite 단일 커넥션에서 열린 tx가 있는 동안 internalError가 진단 DB 쓰기를 하면 교착할 수 있다. merge의 missingAssetID 오류 경로만 rollback 선행; 다른 tx 오류 경로는 여전. 가짜 Runtime으로 검증하지 않는다.
  - 시간 값은 DB별 string/time.Time 차이를 `apiTime`으로 통일하는 관례. 자산 변경 JSON의 식별자는 MCP 조회와 같은 정규형이어야 한다.
  - 같은 패키지 테스트 헬퍼 중복 선언 금지. `newRuntime/testServer`, `authenticateInitialAdmin/performAuthenticatedJSON`, `insertSoftwareTestAsset`, `assetIDSpellings/assetIDResponse`, `countRows`를 재사용.
- 검증 함정:
  - `storagetest.Open`은 기본 SQLite, INVENQOR_TEST_POSTGRES_DSN 지정 시 테스트별 PostgreSQL schema. 실제 라우터는 `server.Handler().ServeHTTP`를 사용한다.
  - 외부 API는 `external_api_test.go:createAPIKeySecret/performWithAPIKey`로 실제 키를 발급해 검증. 콘솔과 외부 관계 생성/삭제는 같은 핸들러를 공유하나 둘 다 테스트할 것.
  - PostgreSQL 스크립트는 지정한 이름의 컨테이너를 먼저 삭제한다. 회차별 고유 이름 필수. 기본 55432는 점유 중이었고 이번 55505는 사용 가능했다. 다른 서비스 컨테이너 재사용·삭제 금지.
  - 10/05 정찰은 좁은 SQLite·PostgreSQL 기존 suite만 실행했다. 신규 잘못된 관계 요청·전체 suite·vet·웹/Rust·실제 Keycloak/MCP 클라이언트는 미검증.
  - CI는 push/PR에서 양 DB·web·Rust·cargo audit·govulncheck·e2e 수행. 일일 schedule은 없고 Dependabot 서버 설정은 미확인.
- 이전 프로필 정정: merge 정규형 검증과 비정규형 테스트는 이미 존재한다. Query DSL은 limit<=0이면 100, >500이면 500으로 적용하고 실효 limit를 응답하므로 관련 보류 항목은 done.
