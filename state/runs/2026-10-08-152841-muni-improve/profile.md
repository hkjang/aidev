- 자주 깨지는 곳:
  - reader/writer 해석 차이, 실제 writer 대신 수제 픽스처, lazy Tiptap 참조(이전 기록).
  - 이름이 ZIP 경로·헤더·DB 값이 되는 곳, SQL 정렬 뒤 Go map 순회로 순서가 다시 사라지는 곳.
  - DOCX와 HWPX를 혼동하지 말 것: docx/import.go:pageFurniture(:711~712)는 패키지 자체의 문구 없는 절단기로 이미 200룬으로 자른다. DOCX 긴 머리말로 HTTP의 AI 문구 결함을 재현할 수 없다.
  - hwpx/hwpx.go:furnitureText(:172)는 문단을 연결할 뿐 길이 제한 없음; hwpx/parts.go:furniture(:436)도 제한 없음. API의 긴 값 회귀에는 hwpx.Build 사용.
- 검증 함정:
  - MUNI_TEST_DSN 없으면 live SKIP(CI에서는 FAIL). 전용 DB만 사용: liveServer가 테스트 계정 행을 지운다. 이번 워크트리는 Chromium 존재.
  - liveServer는 admin이 만든 문서를 일괄 정리하지 않는다. 자기 문서 ID만 검증하고 cleanup을 등록. 현재 DB 잔존 행 수 미확인.
  - CI는 PostgreSQL·Go·프런트 build/unit을 실행하고 Playwright는 실행하지 않는다. Playwright 기본 서버는 외부 8080.
  - ZIP 이름 집합만으로 같은 제목 문서의 배정 비결정성을 잡지 못한다. 이름→본문 대응을 비교하고, 동률 중 정확히 한 행을 재작성해야 재현됨(직전 회차).
  - Linux에서 Windows/macOS 실제 압축해제 충돌은 미확인. ZIP 항목 이름 검사와 OS 실제 증상을 구별.
