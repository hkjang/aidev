# GoalForge 프로필 (2026-10-05)
- 기준: main@96c90ac, 가이드 v0.51.0. 이전 2026-10-03 프로필의 CI/문서 상태가 달라 갱신.
- 목적: 목표·작업 순서·검증 증거·완료 판정은 Go 엔진이 소유하고 AI 세션은 실행 도구로 사용하는 개발 오케스트레이터.
- 스택: Go 1.24.0; SQLite(modernc) 주력, PostgreSQL(pgx) 병존; HTTP API·MCP·Bubble Tea TUI·정적 대시보드. 프런트 빌드 도구 없음(이전 프로필 기준).
- 구조:
  - cmd/goalforge: CLI·워커 진입점. main.go의 goalSet, sweepReport, dayDuration 및 실제 run dispatch 테스트 확인.
  - internal/model: model.go 하나. Criterion·ParseCriterion 등 공통 타입; 10/05에도 [no test files], ParseWindow 없음.
  - internal/observer: 공급·주기·자동 실행/병합 승인. tickProject, AutoApproveMerges 및 테스트 기준선 확인.
  - internal/store/sqlite: 프로젝트·목표·기준·승인 영속화. store.go:SetGoal은 트랜잭션과 kind 검증, operations.go는 증거 종류 판정.

  - internal/mcp·internal/api: 에이전트 및 HTTP 입력/보고 표면. MCP goalSet과 CLI가 동일 ParseCriterion 사용.
  - internal/app·orchestrator·scheduler·planner: 서비스/런·재개/스케줄/작업 계획(이전 프로필 기반, 이번 정밀조사 제외).

- 자주 깨지는 곳:
  - 계산하고 소비하지 않는 보고 값: Tick은 AutoDecisions.Detail/Refused를 담지 않는다. sweepReport는 Acted=false면 Note도 출력하지 않는다.
  - 무인 호출의 멱등성: AutoApproveMerges는 현재 ScopedApprovalExists로 같은 범위의 모든 상태를 재발급하지 않는다. REJECTED/CONSUMED 제외하면 회귀.
  - 09/29 기록의 ParseWindow는 여전히 main에 없다. 성공 기록과 머지 여부를 혼동하지 말 것.
  - review가 객관 증거를 대체하던 문제는 0eb0e17에서 해결됨. 이번 코드도 offLadderKinds에 review 포함.
  - 최근 c0a6a93/95ddad7은 journey 요구와 테스트 러너의 journey 오표시를 다룸; 로그 제목만 확인했으므로 세부 구현은 미확인.
- 검증 함정:
  - git 신원 환경변수와 remote.origin.pushurl=DISABLED가 과거 테스트를 깨뜨림. 프로브는 실제 remote 이름을 지나야 한다. 이번 환경 주입 값은 재확인하지 않음.
  - requirePushable은 gitops/commit_test.go·app/effects_test.go·cmd/goalforge/main_e2e_test.go에 존재. 실제 회귀를 skip으로 덮지 말 것.
  - MCP 도구 실행 오류는 RPC error 대신 result.isError로 나타난다. fixture는 기존 goal을 만들므로 새 목표에 reason 필요.
  - model.ParseCriterion은 구문 파서; 미등록 kind의 유효성은 Store.SetGoal → policy.ValidGateKind에서 거절한다.
  - 이전 샌드박스 명령 승인 제한을 현재 환경 제약으로 단정하지 말 것. 이번에는 승인 차단을 겪지 않음.
