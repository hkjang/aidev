# orbit 프로필 (2026-09-24)
- 목적: 인간관계를 궤도로 시각화하고 교류·기억을 기록하며 승인·AI·MCP 로 활용하는 자체 호스팅 웹 앱.
- 스택: Go(chi v5·pgx v5·go-oidc v3), PostgreSQL, React 19·TypeScript·Vite·MUI 9·Vitest/jsdom. 단일 Go 바이너리에 웹 자산을 내장한다.
- 구조:
  - `cmd/orbit` — 실행 진입점. `internal/webui/dist` — 내장 웹 자산.
  - `internal/server` — 라우팅·인증(auth.go·throttle.go)·사람/교류/궤도(data.go, 약 800줄)·과거 궤도(timetravel.go)·AI(ai.go)·MCP(mcp.go)·승인(workflow.go)·내보내기(export.go)·개인(personal.go)·설정(settings.go)·OpenAPI(openapi.go)·궤도 문법(grammar.go).
  - `internal/server` 테스트: `data_test.go`·`server_test.go`·`grammar_test.go`·`throttle_test.go`(전부 DB 없이 도는 순수/httptest), `timetravel_db_test.go`(실제 postgres opt-in).
  - `internal/store` — pgxpool·embed 마이그레이션 `001_init.sql`~`005_*`·Bootstrap. `store.Open` 이 마이그레이션을 적용한다.
  - `internal/config`·`internal/secure`·`internal/id` — 설정·사용자별 암호화·uuid 생성.
  - `web/src` — 순수 계산 모듈과 그 테스트가 같은 자리에 있다(eclipse/forecast/gravityAssist/orbitGrammar/peopleView/timeTravel/datetimeLocal). `web/src/pages` 9개 화면(테스트 없음), `web/src/components`(OrbitCanvas 916줄, TimeTravel·ErrorBoundary·StateChip·Brand 에만 테스트).
  - `docs` — API.md·ARCHITECTURE.md·guide.md·cru-manual.md·OFFLINE.md.
- 빌드·테스트:
  - `go test ./...` (빠름, 이번 정찰 통과) / `go test -race ./...` / `gofmt -l internal/server` / `go vet ./...`.
  - DB 테스트: `ORBIT_TEST_DATABASE_URL='postgres://…' go test -count=1 -v ./internal/server -run TestOrbit`. DSN 이 없으면 SKIP. docker 와 `postgres:16-alpine` 이미지가 이 기계에 있다(포트 55433·55439·15434 는 다른 세션이 점유 중이니 피할 것). 공유/운영 DB 금지.
  - 웹: `cd web && npm ci --no-audit --no-fund` → `npm run test -- --run` → `npm run build`(tsc -b + vite build). `node_modules` 가 비어 있어 첫 npm ci 가 오래 걸린다. 이번 정찰은 웹 미실행.
  - `make build`(npm ci + 웹 빌드 + 자산 복사 + go build), `make docker`(오래 걸림).
- 관례: 커밋은 한국어 — `feat|fix|perf|chore(scope): 설명`, 릴리즈는 `chore(release): vX.Y.Z` + `VERSION` 파일. 현재 main@88d8955, v0.6.3.
  - 설정은 `settings` 표의 namespace/key/value 행 + 관리 콘솔. 마이그레이션은 `NNN_name.sql` 새 파일(기존 파일 수정 금지). 문서는 `docs/`.
  - 코드 주석이 한국어 산문으로 길고, "왜 이렇게 했는가" 를 적는다. 새 코드도 같은 밀도로 쓴다.
  - CLAUDE.md/AGENTS.md·로드맵·TODO/FIXME 는 없다.
- 위험 구역: `internal/server/auth.go`·`throttle.go`(세션/OIDC/API 키/로그인 잠금), `internal/secure`(사용자별 암호화), `internal/store/migrations`(영구 데이터), `.github/workflows`(배포 권한). 자율 회차에서는 피한다.
- 자주 깨지는 곳:
  - 2026-09-21 회차가 두 번 연속 no-change 로 끝났다(OrbitPage 조기 반환, orbitRange 의 first_met). 원인이 기록되지 않았으니 그 두 과제는 사람이 확인하기 전까지 다시 고르지 않는다.
  - 같은 값을 읽는 경로가 여럿이다: 현재 궤도(`data.go:getOrbit`)와 과거 궤도(`timetravel.go:orbitAt`)가 거의 같은 SELECT 를 각자 갖고 있고, `recalculateRelationship` 은 또 다른 창(365일)으로 같은 지표를 만든다. 한쪽만 고치면 값이 어긋난다.
- 검증 함정:
  - CI 는 postgres 없이 돈다 → DB 테스트는 CI 에서 늘 SKIP 이고 초록으로 보인다. DB 관련 변경은 로컬에서 DSN 을 주고 직접 돌려야 한다.
  - `openTestStore` 는 `store.Open` 만 쓰고 `Bootstrap` 은 쓰지 않는다(관리자 계정·설정 행 부작용 때문). 정리는 `seedUser` 의 `t.Cleanup` 이 users 행을 지워 FK cascade 로 한다.
  - `orbitAt` 은 `JOIN relationships` 라 relationships 행이 없는 사람은 결과에 아예 없다. 시드할 때 놓치기 쉽다.
  - `time.Time` 비교는 `==` 가 아니라 `.Equal()`(pgx 반환값의 위치 정보가 다르다). `people.first_met` 만 `date` 이고 나머지 시각은 `timestamptz` 다.
  - 검증이 DB 앞에서 끝나는지 확인하려면 `&Server{store: nil}` 로 핸들러를 부르면 된다 — DB 를 타면 nil 패닉으로 드러난다(2026-09-22 회차가 쓴 방법).
  - `web/vitest.config.ts` 는 jsdom, `src/test/setup.ts` 가 afterEach cleanup. MUI 9 Slider 는 pointer 이벤트·`buttons:1`·`hasPointerCapture` 스텁이 필요하다. OrbitCanvas 는 ResizeObserver 가 필요하다.
  - `npm run lint` 는 eslint 가 devDependencies 에 없어 실패한다. CI 도 lint 를 돌리지 않는다.
  - `docs/cru-manual.md` 의 일부 API 설명은 현재 코드와 다르다. API 는 실제 핸들러를 정본으로 삼는다.
  - 과거 회차 기록에 나오는 SSO·추적·handoff·메일·MCP OAuth 헬퍼(fakeIDP, newDBServer 등)는 머지되지 않은 브랜치 것이다. main 에 있다고 가정하지 말 것.
