# Ptium 1.69.53

## 해시태그가 슬라이드를 열었고, 문장 하나가 사라졌습니다

마크다운에서 `#` 이 제목이 되려면 **`#` 뒤에 공백**이 있어야 합니다. Ptium 은 줄이 `#` 으로
시작하는지만 보았습니다. 그래서 문단 한가운데 적은 `#출시 #마케팅` 같은 해시태그가 문단을
둘로 자르고, 그 아래 문장을 해시태그 이름의 슬라이드로 끌고 갔습니다.

~~~
올린 것:  # 분기 요약

          매출이 늘었습니다.
          #출시 #마케팅
          비용은 줄었습니다.

이전:  1장 → 분기 요약        - 매출이 늘었습니다.
       2장 → 출시 #마케팅     - 비용은 줄었습니다.
지금:  1장 → 분기 요약        - 매출이 늘었습니다.
                             - #출시 #마케팅
                             - 비용은 줄었습니다.
~~~

더 비싼 쪽은 번호로 시작하는 문장입니다. 제목은 그 글자가 요점으로 다시 나오지 않는
유일한 줄이라, 제목으로 잘못 읽히면 **문장 자체가 덱에서 없어집니다**.

~~~
올린 것:  # 분기 요약

          매출이 늘었습니다.
          #1 우선순위는 출시입니다.

이전:  1장 → 분기 요약                  - 매출이 늘었습니다.
       2장 → 1 우선순위는 출시입니다.   (요점 없음 — 문장이 사라졌습니다)
지금:  1장 → 분기 요약                  - 매출이 늘었습니다.
                                       - #1 우선순위는 출시입니다.
~~~

이제 `#` 이 1~6개이고 그 뒤가 줄 끝이거나 공백일 때만 제목으로 읽습니다. `####### 일곱개`
처럼 일곱 개가 넘는 줄은 어느 단계의 제목도 아니므로 본문에 그대로 남습니다 — 평범한
`.txt` 에서 구분선을 그을 때 쓰는 모양입니다.

## `#제목` 이라고 붙여 쓰던 문서는 달라집니다

의도한 맞바꿈입니다. 공백 없이 `#제목` 이라고 쓰고 제목을 의도한 문서는, 이제 그 줄이
**쓰여 있던 슬라이드의 요점**이 됩니다. 글자가 없어지지는 않습니다. 제목으로 쓰려면 원본에
`# 제목` 처럼 공백 하나를 넣으면 됩니다. 반대쪽 — 해시태그를 제목으로 읽는 쪽 — 은 문서를
쪼개고 문장을 지우므로, 그쪽을 막는 편을 택했습니다.

`# 분기 요약` 같은 정상 제목은 여섯 단계 모두 전과 똑같이 슬라이드를 엽니다. `=` 로 밑줄
그은 제목(1.69.51)도 그대로입니다. `.md` 와 `.txt` 가 같은 리더를 쓰므로 두 확장자에 함께
적용됩니다. 덱 문법(`!source` 등)을 직접 쓰는 덱 원본은 다른 규칙을 쓰며 건드리지
않았습니다. `## 제목 ##` 처럼 뒤에도 `#` 을 붙인 제목에서 뒤쪽 `#` 을 떼는 일은 이번
범위가 아닙니다.

`docs/USER_GUIDE.md` 의 업로드 형식 표에 이 공백 규칙을 한 줄 적었습니다.

## 지키는 장치

`server/internal/docs/markdownhash_test.go` 의 시험 여섯 개가 실제 `Read` 경로로 결과를
글자 단위까지 확인합니다: 해시태그 문단, 사라지던 `#1 …` 문장, 일곱 개 해시, 여섯 단계
제목 전부, 빈 제목 두 경우, 그리고 닫히지 않은 코드 펜스가 줄을 본문으로 되돌릴 때도 같은
규칙이 적용되는지. 구현 단계에서 수정 전 네 개의 실패와 수정 후 통과를 확인했습니다. 여섯
단계 제목과 빈 제목 시험은 수정 전후 모두 통과하며, 바뀌지 말아야 할 것을 고정합니다.
기존 마크다운 시험 파일들은 한 글자도 바뀌지 않았습니다.

릴리즈 준비에서 `make test`(Go race·vet, 웹 typecheck·build), `make build`,
`npm audit --audit-level=high`, 버전 일치 검사와 `git diff --check` 를 통과했습니다.
DB 단위 테스트는 `PTIUM_TEST_DSN` 이 없는 환경에서 건너뛰며, 오프라인 이미지의 최초 실행과
업그레이드는 빌드 스크립트 검사 대상입니다. 웹의 500KB 초과 청크 경고와 개발용 의존성의
moderate 취약점 두 건은 남아 있습니다.

## 설치와 되돌리기

기존 오프라인 설치 절차를 따라 1.69.53 이미지와 함께 제공되는 매니페스트를 사용합니다.
이번 변경에 새 설정이나 데이터베이스 스키마 변경은 없습니다. 배포 담당자는 먼저 시험
환경에서 해시태그가 섞인 `.md` 와 `#` 을 구분선이나 머리말로 쓰는 `.txt` 를 올려, 슬라이드
수와 각 장의 요점을 확인한 뒤 적용 범위를 넓힙니다. 업로드 실패, 있어야 할 제목이 열리지
않음, 또는 본문 누락이 한 건이라도 확인되면 확대를 멈추고 이전 1.69.52 이미지와 해당
버전의 배포 설정으로 되돌립니다. 이 변경은 업로드를 읽는 시점에만 작용하므로, 기존에
저장한 덱은 이 업데이트만으로 다시 작성되지 않습니다. 같은 파일을 다시 올리면 새 규칙으로
읽힙니다.
