# v0.76.7 — 공간 이름에 무엇이 들어 있어도, 내려받은 네 파일의 이름은 같습니다

한 공간은 네 가지로 내려받을 수 있습니다 — Markdown 백업, 차례, 캔버스 그림, PDF. 네 이름은
v0.76.6 이 정리한 **한 공간 이름**에서 나오는데, 그 이름을 파일 이름으로 쓸 때의 규칙은 네 곳이
각각 달랐습니다. 정확히는 **PDF 한 곳만** 파일 이름에 쓸 수 없는 문자를 털어냈고, 나머지 셋은
공간 이름을 그대로 `anchor.download` 에 넣었습니다.

이름에 `/` 나 `:` 가 든 공간 — 날짜나 분기를 이름에 적으면 흔히 그렇습니다 — 을 내려받으면,
그 셋의 이름은 **브라우저가 알아서 고쳤습니다.** 무엇으로 고치는지는 브라우저가 정하므로 umm 이
붙인 이름이 아니게 되고, 네 파일이 같은 공간에서 나왔는데도 이름이 서로 달라집니다.

```
    이름이  2026/Q4: 기획*안  인 공간을 네 가지로 내려받으면

                       전                                 후
    ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━   ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    백업:  umm-2026/Q4: 기획*안.md            umm-2026-Q4- 기획-안.md
           → 브라우저가 고친 이름
    차례:  umm-2026/Q4: 기획*안-차례.md       umm-2026-Q4- 기획-안-차례.md
           → 브라우저가 고친 이름
    그림:  umm-2026/Q4: 기획*안.png           umm-2026-Q4- 기획-안.png
           → 브라우저가 고친 이름
    PDF:   umm-2026-Q4- 기획-안.pdf           umm-2026-Q4- 기획-안.pdf
           → 넷 중 이 하나만 umm 의 이름
```

## 네 곳이 한 규칙에서 이름을 받습니다

파일 이름으로 무엇이 허용되는지는 **한 번만** 정해져야 합니다. 네 번 정하면 그중 셋을 잊게 되고,
실제로 셋이 잊혀 있었습니다. `web/src/lib/download-name.ts` 가 그 한 곳입니다.

```ts
export function downloadFileName(name: string, extension: string, suffix?: string): string {
  const safe = name.replace(/[\\/:*?"<>|]/g, '-');
  return `umm-${safe}${suffix ? `-${suffix}` : ''}.${extension}`;
}
```

`CanvasPage` 의 네 줄이 각자 문자열을 짜던 자리에서 이 함수를 부릅니다. 차례만 접미사를 받고,
접미사는 **부르는 쪽이 번역해서** 넘깁니다(`downloadFileName(activeName, 'md', t('차례'))`) —
한국어 독자는 `-차례`, 영어 독자는 `-outline` 입니다.

털어내는 문자는 **Windows 의 금지 문자 집합**입니다. 세 운영체제 중 가장 좁으므로, 이 함수가
내놓은 이름은 어디에서나 쓸 수 있는 파일 이름입니다. 그 밖은 아무것도 건드리지 않습니다 — 공백,
점, 한글은 사람이 자기 공간에 지어 준 이름의 일부이고, 금지 문자가 없는 이름은 **넣은 그대로**
돌아옵니다.

이름을 다듬거나 빈 이름을 메우는 일은 여기에 없습니다. 그것은 v0.76.6 의 `spaceDisplayName` 이
이미 끝낸 일이고, 이 함수에 오는 이름은 이미 다듬어졌고 이미 기본값이 채워져 있습니다. 한 가지 일을
한 곳에서 합니다.

## 서버의 네 함수와 일부러 합치지 않았습니다

`internal/httpapi` 에도 비슷해 보이는 함수가 넷 있습니다 — `safeFilename`, `dispositionSafe`,
`attachmentDisposition`, `handoffFilename`. 합치지 않았습니다. 그쪽이 답하는 질문은
`Content-Disposition` 헤더가 HTTP 로 무엇을 실어 보낼 수 있느냐이고, 한계를 정하는 것은 파일
시스템이 아니라 **인코딩 규칙**입니다. 닮아 보이기만 하는 두 계약을 하나로 묶으면 둘 중 하나는
틀린 답을 내게 됩니다. 이 함수는 웹 앱이 `anchor.download` 에 적는 네 이름에 대한 것이고, 그
밖의 것에 대한 것이 아닙니다.

## 의존성 감사를 다시 통과합니다

같이 들어간 변경은 `web/package-lock.json` 두 줄입니다. v0.76.6 의 잠금 파일은
`npm audit --audit-level=high` 를 **통과하지 못했습니다** — CI 의 `Frontend dependency audit`
단계가 그것이므로, 제품과 무관하게 빌드가 빨간 상태였습니다.

```
    web/ 에서  npm audit --audit-level=high

            전                                후
    ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━   ━━━━━━━━━━━━━━━━━━━━━━━━
    2 vulnerabilities (1 low, 1 high)  found 0 vulnerabilities
    EXIT=1                             EXIT=0
```

- `source-map-js` 1.2.1 → 1.2.2 — high. 색인된 source-map 구획 오프셋으로 이벤트 루프를 멈출 수
  있습니다(GHSA-68fv-2mgg-jv7q). `vite`/`postcss` 와 `jsdom` 을 거쳐 들어오므로 **빌드와 시험
  도구에만** 있고, 내려받는 이미지에도 번들에도 들어가지 않습니다.
- `dompurify` 3.4.14 → 3.4.16 — DOM XSS 두 건(GHSA-p98j-92pf-mc4p, GHSA-6688-9rhm-gjv2).
  이쪽은 `jspdf` 의 선택 의존성이고 **번들에 실제로 실립니다**(`purify.es` 청크). 캔버스 PDF 는
  HTML 이 아니라 그림을 넘기는 경로라 이 함수들을 타지 않지만, 실려 나가는 코드인 만큼 고쳐진
  판으로 올립니다.

올린 것은 패치 버전 둘뿐입니다. 선언된 의존성 범위(`package.json`)는 **건드리지 않았고**, 다른
패키지는 한 줄도 움직이지 않았습니다.

## 달라지지 않는 것

**저장된 것은 아무것도 바뀌지 않습니다.** 공간 이름도, 그 이름이 데이터베이스에 적힌 모양도
그대로입니다. 이 함수는 내려받기가 브라우저에 건네는 **파일 이름만** 정합니다. 서버도, API 도,
데이터도 v0.76.6 과 같습니다. Go 코드는 0줄 바뀌었습니다.

PDF 로 내려받는 이름은 **전과 똑같습니다.** 넷 중 이미 옳았던 하나였고, 이번 변경은 그것을
나머지 셋에 맞춘 것이 아니라 **나머지 셋을 그것에 맞춘 것**입니다. 이미 PDF 를 받아 둔 사람의
파일 이름이 바뀌는 일은 없습니다.

금지 문자를 **무엇으로 바꾸는지**(`-` 하나로)와 이름 길이는 이번에 정하지 않았습니다. 긴 공간
이름은 여전히 긴 파일 이름이 되고, 운영체제의 길이 한계는 그 한계를 만나는 사람이 생길 때 다룰
문제입니다. 이번 릴리즈는 **네 규칙을 한 규칙으로** 만드는 것까지입니다.

## 검증

시험은 가짜 번역 함수를 쓰지 않고 실제 `i18n/translate` 의 `setLocale`/`translate` 를 들여와
씁니다. 핵심은 첫 시험입니다 — 네 내려받기가 캔버스가 내놓는 순서대로 이름을 만들고, 달라야 하는
부분(확장자와 차례 접미사)을 떼어낸 뒤 **넷이 글자 그대로 같은지** 봅니다. 한 곳만 고치고 세 곳을
두고 오면 이 시험이 떨어집니다.

```
✓ 한 공간의 네 내려받기가 같은 이름을 받는다    2026/Q4: 기획*안 → 2026-Q4- 기획-안 ×4
✓ 파일 이름이 담을 수 없는 문자를 모두 바꾼다   \ / : * ? " < > |  아홉 자 전부
✓ 금지 문자가 없는 이름은 넣은 그대로          생각 공간 · My space · 회고 2026
✓ 접미사는 이름과 확장자 사이에                umm-회고-차례.md · umm-회고.md
✓ 접미사는 읽는 사람의 말로                    ko: -차례 · en: -outline
```

고치기 전에 같은 시험이 실패하는 것을 먼저 확인했습니다. 새 모듈 안에서 전의 방식 — 공간 이름을
그대로 넣는 `` `umm-${name}...` `` — 으로 되돌리면 **2개 실패 / 3개 통과** 입니다:
`expected 'umm-a\b.md' to be 'umm-a-b.md'`(금지 문자), 그리고 네 이름이 같은지 보는 첫 시험.
같은 실행에서 나머지 3개는 통과합니다. 새 시험이 "전부 거절" 로 통과하는 것이 아니라는 증거입니다.

```

✓ 프로덕션 모듈만 되돌리면               2개 실패 / 3개 통과
✓ npm run typecheck                      EXIT=0
✓ npm run lint (oxlint + Prettier)       EXIT=0   All matched files use Prettier code style!
✓ node web/scripts/check-i18n.mjs        EXIT=0   1060개 키

✓ npm run test:offline-queue             EXIT=0
```
