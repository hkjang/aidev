- 위험 구역: SMTP DATA 뒤 응답 유실은 Uncertain, 자동 재발송 금지. IMAP IDLE·동기화의 계정당 한 연결 인계 설계를 유지한다.
- 위험 구역: STARTTLS Buffered()>0 가드·conn.Close·업그레이드 중단은 보안 판정. 현재 양쪽 StageStartTLS로 감싸며 판정 변경 금지.
- 위험 구역: sync.max_message_bytes<=0은 무제한. rawReadLimit과 IMAP maxLiteral·양수일 때만 oversize 검사하는 규약을 유지한다.
- 현재 선택: IMAP ensureIndex가 FETCH 전에 indexed=true를 켜 부분 실패도 캐시한다. runSync의 UIDL 오류→List 폴백이 빈/부분 목록을 성공으로 얻는 경로 확인. 성공 시에만 로컬 누적 인덱스를 커밋하는 1파일 수정 과제. 새 실패 실행·운영 사례는 미확인.
- 새 차선: POP3·IMAP greeting은 connectTO로 기다리지만 오류 Timeout에는 commandTO를 넣는다. 실제 침묵 서버 회귀는 미확인. 기존 syncTiming이 이 값을 그대로 사용한다.
- 보류: POP3 retrBody 무제한 bytes.Buffer+루프별 deadline 갱신은 여전하다. PR #22/04b15be 사람 반려 여부 미확인, 같은 접근 재제출 금지.
- 보류: POP3/IMAP 일반 명령은 ctx를 사용하지 않으며 ensureIndex는 ctx도 받지 않는다. IMAP Idle에는 취소 watcher가 있으므로 모든 메서드가 취소를 무시한다는 표현은 부정확하다.
- 보류: App.tsx는 BrowserTracking을 정적 로드하면서 같은 모듈의 TrackingPage를 lazy import한다. 초기 BrowserTracking은 필요하므로 분리 여부를 판단해야 한다. 이번 빌드 경고는 재실측하지 않음.
- 보류: ListMailboxes·SentMailbox는 별도 파서이고 execRaw가 literal을 별도 보관하므로 리터럴 폴더명은 지원되지 않는다. 운영 사례 없이 파서 통합/확장하지 않는다.
