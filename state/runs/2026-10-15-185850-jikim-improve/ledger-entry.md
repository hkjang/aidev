## 2026-10-15
- 선택: Momento 프록시가 인코딩된 경로(`%2F`·`%2E%2E%2F`)를 디코드해 수집기에 다른 경로로 전달하는 문제 수정 (가치 3 / 위험 2 / 작업량 S)
- 결과: 성공
- 요약: `momentoProxy`(tracking.go:229-234)가 이미 디코드된 `r.URL.Path` 로 바깥 경로를 손으로 조립하고 `RawPath` 를 비워, 브라우저가 한 세그먼트 안에서 escape 한 `%2F` 가 진짜 경로 구분자로 바뀐 채 수집기에 도착했고 `%2E%2E%2F%2E%2E%2F` 는 `../../` 가 되어 운영자가 `momento_url` 에 지정한 경로 접두사(`/base`)를 벗어났다. `Path` 와 `RawPath` 를 짝으로 넣고 경로 조립을 `SetURL` 의 `joinURLPath` 에 맡기도록 두 줄을 바꿨다(프로덕션 1파일 +6/-2줄). 정찰 과제서가 제시한 `url.PathUnescape` 분기는 쓰지 않았다 — `TrimPrefix(r.URL.Path, …)` 와 `PathUnescape(TrimPrefix(r.URL.EscapedPath(), …))` 는 항상 같은 문자열이고, `RawPath` 가 `Path` 의 유효한 인코딩이 아니면 Go 가 조용히 `Path` 를 다시 escape 해 현재 동작으로 degrade 하므로 도달 불가능한 오류 분기를 넣지 않아도 안전하다. 경로 정규화(`..` 제거·거절)는 새 계약이 되므로 넣지 않았다. 검증은 실제 `routes`→`securityHeaders`→`momentoProxy` 를 통과한 요청에서 httptest 수집기의 `r.RequestURI` 로 단정하는 서브테스트 4개(escape 2 + 기존 계약 2)로 했고, `go test ./internal/httpapi/ -run 'Momento|Tracking|CSPReport' -count=1 -v`·`-race -count=5`·`go test ./... -count=1`·`go vet ./...`·`gofmt -l`(출력 없음)·`bash scripts/verify.sh`(exit 0, 프런트 59/59, `검증 완료: jikim v0.2.34`) 전부 통과. 기존 `TestMomentoProxyForwardsWithoutCredentials` 는 손대지 않고 통과한다. 커밋 `f38214d`.
- 실패 재현: `tracking_test.go:474: collector saw "/base/collect/a/b", want "/base/collect/a%2Fb" (inbound /momento/collect/a%2Fb)` / `tracking_test.go:474: collector saw "/base/collect/../../admin", want "/base/collect/%2E%2E%2F%2E%2E%2Fadmin" (inbound /momento/collect/%2E%2E%2F%2E%2E%2Fadmin)` — 수정 전 exit 1, escape 2개만 실패하고 기존 계약 2개(`/collect/v1/events` 바이트 동일, 질의 문자열 `?site=a%2Fb&q=1` 보존)는 처음부터 통과했다. 수정 두 줄만 되돌려 같은 2개가 같은 메시지로 다시 실패하는 것을 확인하고 복원했다.
