# Invenqor Server·Agent v0.2.32 릴리즈 노트

릴리즈 일자: 2026-09-11
호환 Agent: v0.2.32 (Linux·Windows)

이번 릴리즈는 제품 동작을 바꾸지 않습니다. 바뀐 것은 **문서**입니다 — 사용자
가이드와 관리자 가이드는 분량은 충분했지만 화면 캡처가 **한 장도 없어**, 관리
콘솔을 처음 여는 사람이 문장만 읽고 화면을 상상해야 했습니다. 이제 두 가이드는
실제 콘솔을 촬영한 그림 21장을 싣고, 그 그림이 문서·스크립트·저장소 사이에서
어긋나지 않도록 테스트로 고정합니다.

## 1. 두 가이드에 화면 캡처가 한 장도 없었습니다

`scripts/capture-guide-screenshots.mjs`가 임시 디렉터리에 Server를 빌드해
loopback 전용 포트로 띄우고, 가공한 자산·계정·Agent를 채운 뒤 headless Chrome으로
1440x900에서 로그인·대시보드·자산·Query DSL·Agent·감사 로그·운영 설정 등 21개
화면을 촬영합니다. 촬영이 끝나면 Server와 상태 디렉터리는 삭제됩니다.

- **운영 배포를 실수로 촬영할 수 없습니다.** 대상 주소를 환경 변수로 받지
  않으므로, 스크립트가 다른 Server를 찍거나 그 설정을 바꾸는 일이 없습니다.
  `GUIDE_CAPTURE_PORT`로 사용할 포트만 바꿀 수 있습니다.
- **빌드 장비의 이름이 문서에 실리지 않습니다.** Server는 자기 호스트 이름을
  진단 기록과 request ID에 남기므로, 촬영용 Server는 UTS namespace 안에서 띄워
  감사 로그·Server 로그 캡처에 빌드 장비 이름이 나타나지 않게 했습니다.
- **자격 증명은 글자로 남지 않습니다.** 촬영에 쓰는 관리자·사용자 계정의
  비밀번호와 거부용 등록 claim은 실행할 때마다 만들고 어디에도 적지 않습니다.
  로그인 화면은 비밀번호를 입력하기 전에 촬영합니다. Agent 목록에 찍히는 Agent
  버전은 숫자를 박아 두는 대신 `Cargo.toml`에서 읽습니다.

문서 본문도 그림에 맞춰 늘었습니다. **사용자 가이드**에는 로그인부터 첫 자산
확인까지의 "처음 5분", 화면별 사용법과 자주 하는 작업, 용어를 더했습니다.
**관리자 가이드**에는 코드에서 읽은 Server 기동 환경 변수 전수 표(18장), 내장
역할별 권한 표, 운영 설정 화면(19장)과 감사·Server 로그 절, 그리고 캡처를 다시
만드는 절차(20장)를 더했습니다.

## 2. 그림과 문서와 스크립트가 따로 놀 수 있었습니다

스크립트가 촬영하는 화면, `docs/assets/guide/`의 파일, 두 가이드가 싣는 그림은
세 곳이 따로 놀기 쉽습니다 — 화면 이름을 바꾸면 옛 그림이 조용히 남고, 절을
지우면 고아 PNG가 릴리즈마다 실립니다. 빠진 그림은 PDF를 구울 때에야 드러나는데,
그것은 테스트 실행의 일부가 아닙니다.

`TestGuideScreenshotsMatchCaptureScript`(`server/internal/webui`)가 세 목록을
대조해, 어느 하나가 어긋나면 **어떤 이름이 어디에 없는지** 알려 줍니다.

## 3. 두 가이드의 PDF는 공용 가이드 도구로 만듭니다

사용자·관리자 가이드는 그림을 싣고 저장소 간 가이드 표준을 따르므로, 저장소 자체
변환기(`scripts/build-docs.sh`) 대신 공용 도구를 부르는
`scripts/build-guide-pdfs.sh`로 굽습니다. 한 문서를 두 가지 서식으로 굽지 않도록
두 문서는 `build-docs.sh`에서 뺐습니다. 문서 사이 상대 링크는 공용 도구가
처리하지 않아 빌드 경로가 그대로 PDF에 박히므로, 기존 스크립트와 같은 방식으로
공개 문서 URL로 바꾼 뒤 굽고 `file://` 링크가 남지 않았는지 확인합니다.

## 검증

- **테스트가 헛돌지 않는지 확인했습니다.** 스크립트의 화면 하나, 저장소의 PNG
  하나, 가이드의 그림 참조 하나를 각각 어긋나게 만들어
  `TestGuideScreenshotsMatchCaptureScript`가 그 이름을 짚어 실패하는 것을 본 뒤
  되돌렸습니다.
- **PDF를 실제로 구웠습니다.** 두 PDF의 표지 버전, 이미지 XObject 수(사용자
  가이드 12개·관리자 가이드 9개), `file://` 링크 0개를 확인하고, 표지와 첫 그림
  쪽을 렌더링해 캡션과 그림이 깨지지 않았음을 보았습니다.
- `go test ./...`가 전 패키지 통과하고, `go vet`·`go build`·`gofmt`가 통과합니다.
  `sh -n`과 `node --check`로 새 스크립트의 문법을 확인했습니다.
- Agent(Rust)와 콘솔 코드, 공개 계약(`openapi.yaml`)은 이번 릴리즈에서 바뀌지
  않았습니다.

## 호환성

- 데이터베이스 마이그레이션이 없습니다.
- API 응답 형식 변경이 없습니다.
- **동작 변경이 없습니다.** 서버와 Agent의 코드는 버전 문자열 외에 바뀌지
  않았으므로, v0.2.31에서 올라오는 배포는 이미지·패키지 교체만으로 끝납니다.
- 릴리즈 자산의 `USER_GUIDE.pdf`·`ADMIN_GUIDE.pdf`는 그림을 싣게 되어 이전보다
  큽니다(각 4.5MB 안팎).
