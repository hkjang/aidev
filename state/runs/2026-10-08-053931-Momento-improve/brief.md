- 과제: 「JSON Schema」 칸이 저장 전에 JSON 구문 오류를 말한다 (순수 모듈 `schemaTextRule.ts`) (가치 3 / 위험 1 / 작업량 S)
- 왜: 「JSON Schema」 는 다섯 줄 자유 입력인데(AdminPage.tsx:3803-3810) helperText 가 없고 「저장」 은 `disabled={!site || !form.name}`(3815) 로 schemaText 를 **아예 보지 않는다**. 깨진 JSON 으로 저장을 누르면 `mutationFn` 안의 `JSON.parse(form.schemaText)`(3745) 가 던져 요청이 서버에 가지도 **않는데**, 사용자는 그 헛클릭 왕복을 한 번 치른 뒤에야 안내를 읽는다. v0.34.57 이 그 뒤늦은 안내를 한국어로 만들었으니(adminErrors.ts:338-357) 남은 것은 **그 문장을 누르기 전에 보여 주는 것**뿐이다. 이 판정은 클라이언트만으로 완결된다 — 판정자가 서버가 아니라 같은 `JSON.parse` 라서 cidrRule·retentionRule 선례와 달리 '화면이 서버보다 좁아질' 위험이 구조적으로 없다.
- 수용 기준:
  1) 깨진 JSON(`{"properties": }`)을 타이핑하면 「저장」 을 누르지 않아도 칸 아래에 오류 색 + 한국어 안내가 보이고 「저장」 이 닫힌다.
  2) 그 안내가 저장 실패 Alert(`describeEventDefinitionError`) 과 **글자 그대로 같은 문장**을 쓴다 — 두 자리가 같은 상수 하나에서 나오므로 갈라질 수 없다. 문장 글자 자체는 바뀌지 않는다.
  3) 올바른 값(`{}`, `{"properties":{}}`, `null`, `[1,2]`)은 **막지 않고**, V8 영문 표지(`Unexpected token`·`is not valid JSON`·`position`)가 helperText 본문에 0개다(원문을 보이고 싶으면 별도 캡션으로).
  4) 새 순수 테스트가 **항등 스텁**(= 지금 화면처럼 아무것도 막지 않고 helperText 를 비워 두는 구현)에서 실패하고 구현에서 통과한다. 기존 adminErrors 테스트 전부(특히 `test("코드가 붙은 실패는 JSON 구문 안내로 가로채이지 않는다")`, test/adminErrors.test.mjs:986)가 그대로 통과한다.
- 건드릴 파일 (프로덕션 3 + 테스트 1~2):

  - `web/src/pages/AdminPage.tsx` — `SchemasAdmin`(3721~) 안에서 `const schemaJudgement = judgeSchemaText(form.schemaText)` 를 한 번 계산하고, (a) 3803-3810 TextField 에 `error={schemaJudgement.error}` / `helperText={schemaJudgement.blocking ?? <기본 설명>}`, (b) 3815 `disabled={!site || !form.name || !!schemaJudgement.blocking}`. import 는 80행 `describeEventDefinitionError` 옆에 더한다.
  - `web/test/schemaTextRule.test.mjs` (**신규**) — `import { judgeSchemaText, JSON_SCHEMA_RULE } from "../src/pages/schemaTextRule.ts"`(확장자 필수). `cidrRule.test.mjs` 를 모양의 본으로 쓸 것. 더해 `adminErrors.test.mjs` 쪽에 단언 1건 — `describeEventDefinitionError(실제 깨진 JSON 에서 받은 SyntaxError).message` 가 `JSON_SCHEMA_RULE` 를 **포함**한다(두 자리가 한 상수에서 나온다는 증거). 에러는 손으로 만든 `new SyntaxError("...")` 대신 **실제로** `JSON.parse('{"properties": }')` 를 try/catch 해서 잡은 것을 쓸 것.

- 위험과 피할 것:
  - **서버·`internal/httpapi/admin.go`·Go 를 건드리지 말 것.** 이 과제는 화면 안에서 끝난다. 보호 경로(auth/migrations/workflows)는 전부 범위 밖.
  - **`JSON.parse` 가 통과시키는 값을 막지 말 것.** 이번 정찰에서 확인한 것: `upsertEventDefinition` 은 `Schema map[string]any`(admin.go:1401)로 디코드하므로 `[1,2]`·`"hi"`·`5` 는 서버가 400 INVALID_PAYLOAD 로 거절하지만 **`null` 은 통과한다**(nil map → `json.Marshal` 이 `null`, 1413행). 그래서 "객체가 아니면 막는다" 는 규칙은 `null` 에서 화면을 서버보다 좁게 만든다. 이번 회차는 **구문만** 판정하고 타입은 판정하지 않는다 — cidrRule 이 IPv6 본문을 통과시킨 것과 같은 원칙(판정 못 하거나 판정이 서버와 갈릴 수 있는 것은 통과시킨다). 객체 아님을 꼭 알리고 싶으면 `error`·`blocking` 없는 `hint` 로만, 그리고 그것은 **별도 회차**로 미루는 쪽이 낫다.
  - 「저장」 을 닫는 것이 이 칸에서 정당한 이유는 **요청이 만들어지지도 않기 때문**이다. 이것을 다른 칸(`name`·`description`·`validation_mode`·`conversion`)이나 다른 화면의 저장 버튼으로 **일반화하지 말 것** — 거기서는 서버가 판정의 정본이고 화면은 거울이다(운영자 지시).
  - 기존 문장 상수(`UNREADABLE_PAYLOAD`·`LOST_REQUEST`·`PASS_TO_ADMIN`)와 네 `describe*` 함수를 **합치려 하지 말 것**(운영자 지시: 같은 종류의 파서가 여러 경로에 있으면 좁히는 방향으로만 고친다).
  - `npx prettier --check` 를 게이트로 쓰지 말 것 — 저장소에 prettier 의존성·스크립트·CI 단계가 없고 main 의 여러 파일이 이미 실패한다. `gofmt -l` 의 `internal/segment/segment_test.go` 는 늘 뜨는 것이고 CI 가 보지 않는다.
  - `MOMENTO_TEST_POSTGRES_DSN` 이 없으면 Go 통합 테스트가 **조용히 skip** 된다 — 이 과제에는 상관없지만 "Go 테스트 통과" 를 근거로 쓰지는 말 것.
  - `web/dist` 와 /tmp 하네스는 커밋 전에 지우고 `git status` 로 담긴 파일만 남은 것을 확인할 것.
