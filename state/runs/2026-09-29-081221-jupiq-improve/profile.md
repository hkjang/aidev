# jupiq 프로필 (2026-09-29)
- 기준: main@e2e11c1, VERSION 1.8.5. 이전 프로필의 limit·usage 보류 사항은 이미 머지되어 갱신한다.
- 목적: JupyterHub·Kubernetes·Prometheus 자원을 조회하고 서버·승인·권한을 운영하는 오프라인망용 관리 콘솔.
- 스택: Go 1.26.0/toolchain 1.26.7, net/http·go-oidc·pgx/PostgreSQL, React 19·TypeScript 5.9·Vite 7·Ant Design·ECharts, Vitest 3/jsdom, CI Node 22.
- 구조:
  - cmd/jupiq: 진입점·서비스 배선(이번에는 이전 프로필을 계승, 재열람 안 함).
  - internal/api: Server.New·Handler, require 권한 미들웨어, HTTP 핸들러·OpenAPI 계약 검사.
  - internal/store: PostgreSQL 조회·권한 범위·설정·메일 기록·사용량 롤업. store.go의 pageBounds·boundedLimit가 목록 경계를 처리.
  - internal/auth: 세션·OIDC·silent SSO. mcp_oauth.go는 현재 파일 목록에도 없다. internal/secure는 비밀값 암호화.
  - internal/mail: 설정·SMTP·알림. service.go에 Delivery와 StatusQueued/Sent/Failed 정의.
  - internal/integration·internal/collector: 외부 서비스 연결·주기 수집. SSRF 방어에 주의(이전 프로필 계승).
  - migrations/: 기동 시 SQL 적용(이전 프로필 기준 001~014, 이번 SQL 내용 재열람 안 함).
  - web/src: React 화면·API 클라이언트. SettingsPage.tsx의 MailDeliveriesCard는 필터 없이 최근 기록·상태별 summary를 표시.
  - docs/USER_GUIDE.md·ADMIN_GUIDE.md와 PDF가 정본. docs/assets/screenshots/manifest.json은 메일 탭 전용 캡처가 아직 없음. openapi/openapi.yaml은 API 계약.
- 빌드·테스트: README 기준 `make deps` → `make lint` → `make test` → `make build`.
  - 프런트: `npm --prefix web ci`, `npm --prefix web run lint`, `npm --prefix web test`, `npm --prefix web run build`.
  - 정찰 실측: `go test -count=1 ./internal/api ./internal/store` 통과(api 0.045s·store 0.006s), DSN 없는 실행으로 DB 통합은 미검증.
  - DB: JUPIQ_INTEGRATION_TEST_DSN 지정 후 `make test-integration` = `go test -count=1 -p=1 -run Integration ./internal/store ./internal/api`.
  - `make release-check`: 모듈·vet·취약점·Go·DB·스크린샷·npm audit/lint/test/build. 수 분 이상·네트워크 필요. 이번 미실행.
- 관례: 최근 커밋은 주로 한국어 `fix: 설명`, 릴리스 버전 정합은 scripts/check-version.sh. 설정은 settings, 비밀은 secrets 암호화 저장.
  - API 오류는 error.code/message/request_id, 성공 data()는 {data:...}. queryIntOrReject는 비정수·음수를 400 invalid_query로 거부한다.
  - 상한 초과는 상한으로 자른다: pageBounds=200, boundedLimit 적용 메일=200·소비량=500·지표=5000. 세 경로의 기본값 되돌림 문제는 완료되어 재선정 금지.
  - ListMailDeliveries는 status를 strings.TrimSpace하며 비어 있으면 전체. Total·Summary는 status와 무관한 전체 집계다. 이번 과제는 API의 status 허용값 검증만.
  - /usage의 consumption_group_by 응답 추가는 92d05c7에서 완료. project 소비량 스키마 확장은 미실시.
- 위험 구역: internal/auth, migrations, .github/workflows, SSRF 설정 검증, 권한 범위 SQL 인자, SMTP 자격증명 처리. 이번 과제에서 모두 회피 가능.
- 자주 깨지는 곳: OpenAPI YAML 인용, MD/PDF·VERSION 정합, Go mux 경로 충돌(이전 기록 근거). 릴리스/빌드 수정이면 전체 릴리스 검증까지 필요.
- 검증 함정:
  - DSN 없는 go test는 통합 skip을 성공으로 보인다. make test-integration은 DSN 없으면 exit 1; 상세 -v 출력에서 새 테스트 SKIP 여부 확인.
  - CI PostgreSQL 16, release 통합 PostgreSQL 14, offline smoke 16. CI는 Go race 검사도 한다.
  - 일부 Hub 통합은 비loopback IPv4가 없으면 skip(README에 명시). 실제 Keycloak·SMTP E2E는 이번 미검증.
  - 실제 HTTP 테스트 선례: profile_email_integration_test.go의 store.Open·auth.NewService·CreateSession·SecureCookie·New(...).Handler(). settings:read가 필요한 경우 일반 프로필 계정 대신 실제 관리자 역할 필요.
  - DB fixture는 고유 marker·생성 ID로 정리하고 전역 Total을 fixture 개수로 단정하지 않는다. Seed 사용자 email은 별도 필요(이전 기록).
  - fake Store·직접 주입 Principal만으로 배선 결함을 증명하지 않는다. 문자열 grep은 실행 증거가 아니다.
