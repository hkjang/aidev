  - backend/internal/store — pgx 저장소와 migrations/001~013; 시작 시 적용·checksum 검사. `store.ErrNotFound = pgx.ErrNoRows`, `store.IsConflict`.
  - backend/internal/media — PostgreSQL Large Object 스트리밍·quota·정리; analytics — 추적 설정/정책.
  - backend/internal/feed·search·visibility·outbound·secure — 추천·검색·공개 범위·외부 연결 정책·암호화.

- 빌드·테스트: 루트 `make fmt`, `make check`(OpenAPI 120 route 계약·버전·환경변수·문서), `make test`, `make lint`(staticcheck 2025.1.1), `make audit`(govulncheck·npm audit).
  - backend에서 `go test -race -count=1 ./...`, `go vet ./...`. frontend에서 `npm ci && npm run lint && npm test && npm run build`.
  - `make test`는 여전히 `go test ./...`로 **-race 없이** 돌고 CI source는 `-race`를 쓴다. 이 차이를 과제로 두 번 골랐다가 두 번 no-change로 끝났으므로 단독 과제로 다시 고르지 말 것.
  - `make image`와 앱+DB 준비 후 `npm test --prefix e2e`는 느림. e2e 순서는 visual → accessibility → smoke.
- 관례: 커밋은 한국어 `feat:`/`fix:`/`test:`/`docs:`/`release:`. 환경변수는 DB DSN·bootstrap ID/비밀번호·암호화 키 4개; 기능 설정은 DB JSON/API camelCase. migration은 새 번호 추가, 과거 checksum 변경 금지.
  - 오류 계약 관례(최근 3회 릴리즈로 굳어짐): 저장 실패는 `500 storage_error`, 대상 없음은 `404 not_found`, 상태 충돌은 `409`. 새 message를 만들기보다 같은 파일의 기존 문구를 재사용한다.
  - OpenAPI는 성공 코드만 `responses`에 나열하고 오류 계약은 `description` 문장으로 적는 관례다. 응답 목록을 늘리지 말 것.
- 위험 구역: httpapi/auth.go·oidc.go·mcp_oauth.go(세션·토큰·권한), store/migrations(영구 데이터), media(LO·quota), securityHeaders/serveSPA(CSP·nonce), .github/workflows/release.yml(정확한 commit CI 성공 요구).
