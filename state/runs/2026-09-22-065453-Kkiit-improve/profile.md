# Kkiit 프로필 (2026-09-22)
- 목적: 사람·기업·AI Agent의 전문 서비스를 주문·납품·구매확정·정산으로 연결하는 오프라인 운영 가능 마켓플레이스.
- 스택: Go1.26·net/http·pgx/v5·PostgreSQL16+, React19·TypeScript5.9·MUI7·Vite8; 웹 번들을 Go embed.
- 기준: main@ee4c612, v0.4.4. MCP OAuth는 과거 성공 기록과 달리 이 체크아웃에 구현/설정/카드가 없다.
- 구조:
  - cmd/kkiit: 프로세스와 서버·워커 시작/종료 배선.
  - internal/httpapi: router.go, 인증·REST/MCP·거래·승인 및 통합 테스트.
  - internal/database/migrations: 번호 SQL, 시작 시 advisory lock 안에서 자동 적용.
  - internal/worker: Outbox·메일·웹훅·위험·정산·신뢰 점수 배경 처리.
  - internal/config·cryptox·password: 환경 설정·비밀 암호화·비밀번호.
  - internal/analytics·mail·netguard: 추적·SMTP·외부 연결 보호.
  - web/src: React 페이지; AdminPage.tsx에 승인 등 관리자 기능.
  - internal/ui/dist: 추적되는 embed 번들. 변경 검증을 위해 빌드할 수 있으나 회차 규칙상 산출물 커밋 지시 금지.
  - docs: USER_GUIDE/ADMIN_GUIDE(md·pdf), architecture.md, mcp.md, openapi.yaml, 캡처.
  - scripts: 가이드 시드/캡처·오프라인 release/load.
- 빌드·테스트: `go test ./cmd/... ./internal/...`; `npm --prefix web test`; `go vet ./cmd/... ./internal/...`.
- 전체 검사: `make check`는 gofmt 검사·Go test/vet·npm ci·lint·test·build; 설치/빌드 시간 필요하고 추적 dist가 바뀔 수 있다.
- 빌드: `make build`는 웹 설치/빌드 후 bin/kkiit 생성.
- 통합: `make test-integration KKIIT_TEST_DSN=postgres://...` (전용 폐기 DB 필수, timeout300s). 계정·주문을 남기므로 운영 DB 금지.
- 이번 검증: Go1.26.7·Node22.23.1, Go 테스트 통과(일부 캐시), npm test 10개 통과. KKIIT_TEST_DSN 미설정으로 통합 SKIP. lint/build·go vet·브라우저 미실행.
- 관례: fix/feat/chore/docs + 한국어 설명, 릴리스 Kkiit vX.Y.Z; 가변 정책은 system_settings JSONB, 비밀은 ENCRYPTION_KEY 암호화.
- 설정: 필수 POSTGRES_DSN/BOOTSTRAP_ADMIN/BOOTSTRAP_ADMIN_PASSWORD/ENCRYPTION_KEY, 선택 SHUTDOWN_DRAIN_SECONDS(기본5,0~120,오류시5). README와 Config 주석의 네 개 표현이 불일치.
- 위험 구역: httpapi/auth.go·middleware.go·identity.go(인증/RBAC), orders.go·finance.go(원장), database/migrations(번호 충돌), .github/workflows/release.yml(배포).
- 자주 깨지는 곳: 과거040 마이그레이션 중복, captured/succeeded 결제 상태 불일치, Momento 다중 응답 보안 헤더·Set-Cookie 유출. 이미 수정된 접근을 반복하지 말 것.
- 승인 현재 상태: v0.4.4에서 조건 카드와 활성 전환400 수정됨. 배열 조건 검증 부재와 편집 시 알 수 없는 조건/추가 단계 유실 가능성은 남아 있다.
- 검증 함정: DSN 없이 Go test 성공은 통합 검증이 아니다. integrationServer는 실제 Handler·DB·워커를 연결하며 전역 apiUnderTest가 있어 테스트 병렬화 금지.
- 프런트 검증 함정: 기존 npm 테스트는 silentSso.test.ts의10건뿐, 승인 UI 배선을 증명하지 않는다.
- CI: release.yml은 v* 태그에서 Docker 빌드·archive 재로드·Release, make check/DB 통합 검사 단계 없음.
- 런타임 차이: Docker Node24.18.0/Go1.26.0; README Node24+; 로컬22에서 테스트 성공만 확인, 최소 빌드 버전 미확인.
- 캡처: guide-screenshots.mjs는 시드/설정 쓰기를 수행하므로 루프백 전용 폐기 인스턴스에서만 실행. 이번 브라우저·Docker daemon 가용성 미확인.
- 문서/로드맵: 저장소 파일 검색에서 CLAUDE.md·AGENTS.md·별도 roadmap/TODO 파일과 internal/web/src/docs/scripts의 TODO/FIXME 없음.
- 회사 스킬: 요청3개에 해당하는 Skill 도구/로컬 파일을 찾지 못해 절차·반환 형식 미확인. 사용자 정찰 형식으로 기록했다.
