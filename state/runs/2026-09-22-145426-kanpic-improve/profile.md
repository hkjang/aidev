- 자주 깨지는 곳: 같은 자료의 업로드·IMPORTDATA·웹 입력 계약을 한쪽만 변경하는 것. 계산용 파서·파일 파서·표시 숫자 파서를 무조건 통합하지 않는다.
- XLSX 교훈: b52a394는 CellTypeUnset에 15자리 제한을 넣은 변경을 되돌림. 엑셀 raw 2.2000000000000002는 이미 실수이므로 숫자 유지. CellTypeUnset은 앞자리 0 가드 후 DecimalNumber, CellTypeNumber도 파일 숫자 길이 가드 금지.
- CSV 계약: parseScalar는 unguard→Boolean→Number, trim 없음. parseCSV는 원문 Boolean→TrimSpace 후 Number→실패 시 원문. 불리언은 719aec5로 일치, 공백·아포스트로피·빈칸 차이는 테스트로 보존.
- 파일 숫자 경계: Number는 평문 정수/소수에 15자리 가드, 앞자리 0 정수 보존. 지수·.5·5.는 별도 문법. 웹 decomposeNumberText는 서식 숫자도 읽고 지수는 거절하므로 공통 범위만 비교한다.
- 새 확인: 실제 Node 22.23.1로 decomposeNumberText의 15자리 승인/16자리 거절 및 00123→123 확인. 앞자리 0은 서버와 달라 보류 후보로 기록; 브라우저 실제 재현은 미확인.
- 인코딩: ToUTF8는 BOM UTF-8/UTF-16LE/BE를 변환하고 나머지는 그대로. 홀수 끝 바이트는 버리고 고립 surrogate는 U+FFFD. UTF-32 지원·휴리스틱 추측 금지.
- 기록/HEAD 차이: 이번 기준 HEAD 742871c에는 parseCSV의 변환 후 UTF-8 검사 없음. 제공된 이전 회차 기록에는 0a21ce7로 해당 수정 성공이 있으므로 재구현하지 않는다. merge 여부는 미확인.
- 캐시: 원격 HTTP 장애는 최대 30초, 파싱 결과는 cache_seconds. 인코딩 과제와 캐시 수명을 함께 바꾸지 않는다.
