Kkiit v0.4.13 — API 키 IP 제한 입력 오류 안내 수정

v0.4.12 이후 들어온 수정 하나를 담는다.

- `validateKeyInput`(`keys.go`)이 `allowed_cidrs` 를 `net.ParseCIDR`
  하나로만 검사해, 호스트 비트가 켜진 `10.0.0.5/8` 을 통과시키던 것을
  고친다. Go 는 이 입력을 받아들이고 마스크를 적용한 네트워크를 따로
  돌려주지만 `allowed_cidrs` 컬럼의 `cidr` 형은 거절하므로,
  `createMyAPIKey` 의 `$7::cidr[]` 캐스트가 터져 사용자는 자기 주소가
  틀렸다는 안내 대신 500 `key_save_failed` "API 키를 저장하지
  못했습니다." 를 받았다. 어느 필드가 틀렸는지 들을 방법이 없었고, 같은
  함수 위 주석이 선언한 "바른 주소가 아니면 클라이언트 오류" 계약이
  깨져 있었다. `ip.Equal(network.IP)` 로 호스트 비트가 켜진 입력을
  400 `invalid_key_policy`(기존 문구 그대로, 새 문구 없음)로 가르고,
  검증기가 들여다본 트림된 값을 `in.AllowedCIDRs[i]` 에 되써 넣어 저장
  값과 `ipAllowed` 가 읽는 값을 일치시킨다 — 종전에는 트림한 사본만
  검사하고 원문을 INSERT 에 넘겨 `[" 10.0.0.0/8 "]` 도 500 이었다
  (PG `cidr_in` 이 공백을 거절하는 것을 psql 로 확인). 전제는 먼저
  실행으로 증명했다: `net.ParseCIDR("10.0.0.5/8")` 이
  `err=nil, ip=10.0.0.5, net=10.0.0.0/8` 로 통과하는 것과, PG 16 이
  `'10.0.0.5/8'::cidr`·`'2001:db8::1/32'::cidr` 을 `invalid cidr value`
  로 거절하는 것. 버릴 PostgreSQL 16 에 붙는 통합 테스트로 500 을 먼저
  재현한 뒤 고쳐 통과시켰고, 분기를 세 방향으로 변이시켜(새 판정 제거
  → 500, 항상 거절 → 400, 트림 되쓰기 제거 → 500) 각각 다시 실패하는
  것도 확인했다. 테스트는 IPv4·IPv6 양쪽의 거절, 거절된 요청이 행을
  남기지 않는 것, 정상 입력 네 가지가 201 로 저장·조회되는 것, 공백
  섞인 입력의 저장 값이 트림된 값인 것, 회전 경로가 PostgreSQL 이
  돌려준 표기에 걸리지 않는 것까지 함께 고정한다. 인증 경로
  (`middleware.go` 의 `ipAllowed`)는 손대지 않았다 — 들어올 때
  정규화해 두 경로를 맞추는 수정이다. 프런트는 이미 `error.message` 를
  그대로 띄우므로 `web/` 과 `internal/ui/dist` 는 건드리지 않았고,
  `openapi.yaml` 의 POST /me/api-keys 응답에 핸들러가 실제로 내는
  400·500 을 더해 실제 동작과 맞췄다 — 종전에는 201 뿐이었다.

버전 표기(VERSION·compose·web/package·openapi·README)를 0.4.13 으로 올린다.
