# Kkiit 프로필 (2026-10-08)
- 목적: 사람·기업·AI Agent의 전문 서비스를 주문·납품·구매확정·정산으로 연결하는 오프라인 운영 가능 마켓플레이스.
- 기준: main@01e6b8b, v0.4.16. 이전 프로필의 옵션 금액 오버플로 잔존 설명이 현재 코드와 달라 갱신.
- 스택: Go 1.26, net/http, pgx/v5, PostgreSQL 16+; React 19, TypeScript 5.9, MUI 7, Vite 8; 웹 번들은 Go embed.
- 구조:
  - cmd/kkiit: 프로세스·HTTP 서버·워커 시작과 종료. drain→HTTP Shutdown→dispatcher 대기.
  - internal/httpapi: 도메인 핸들러; router.go가 라우트 정본. integration_test.go 및 mail_integration_test.go가 실제 DB 통합 테스트.
  - internal/database/migrations: 번호 SQL, 시작 시 advisory lock 안에서 자동 적용(README·이전 프로필 기준).
  - internal/worker: Outbox·알림·웹훅·위험·정산·신뢰 점수 배경 처리(이전 프로필 유지).
  - internal/config·cryptox·password: 환경 설정·비밀 암호화·비밀번호.
  - internal/analytics·mail·netguard: 방문 추적·SMTP·웹훅 주소 정책(이전 프로필 유지).
  - web/src: React UI; pages/AdminPage.tsx에 관리자 기능.
  - internal/ui/dist: 추적하는 embed 번들. 검증 빌드 산출물 커밋 금지.
  - docs: USER_GUIDE/ADMIN_GUIDE(md·pdf), architecture.md, mcp.md, openapi.yaml.
- 빌드·테스트:
  - `go test ./cmd/... ./internal/...` — 이번 종료 코드 0, 일부 캐시 사용. DSN 없어서 DB 통합 미실행.
  - `go test ./internal/config -count=1 -v` — 이번 3개 PASS. DrainSeconds 경계는 검사하지 않음.
  - `go vet ./cmd/... ./internal/...`, `gofmt -l cmd internal` — 기존 표준 검증; 이번 미실행.
  - `make test-integration KKIIT_TEST_DSN=postgres://…` — 전용 폐기 DB 필수, timeout 300s. 이전 실제 실행 82~93초.
  - `npm --prefix web test` — README Node 24+ 요구. 이전 회차 10건 통과, 이번 웹 미실행.
  - `make check` — Go 포맷/test/vet, npm ci/lint/test/build. 설치 및 추적 dist 변경 가능.
  - `make build` — 웹 빌드 후 bin/kkiit 생성.
- 관례: fix:/feat:/chore:/docs: + 한국어 설명. 릴리스는 Kkiit vX.Y.Z — 한국어 요약.
  - 오류는 writeError(status, code, 한국어 메시지). 프런트가 error.message를 표시(이전 프로필 유지).
  - 필수 POSTGRES_DSN/BOOTSTRAP_ADMIN/BOOTSTRAP_ADMIN_PASSWORD/ENCRYPTION_KEY, 선택 SHUTDOWN_DRAIN_SECONDS.
  - 선택 설정 기본 5초, 정수 0~120. 미지정/파싱 실패/범위 밖은 5. 0도 HTTP·워커 종료 대기는 유지한다.
  - README 실행 계약·Config 주석의 “네 개뿐”이 실제 Load와 불일치. 이번 구현 과제이며 아직 수정 안 됨.
  - 가변 운영 정책은 PostgreSQL system_settings JSONB. compose는 .env를 env_file로 받는다.
- 위험 구역: httpapi/auth.go·middleware.go·identity.go(인증/RBAC), orders.go·finance.go(원장), database/migrations(번호 충돌), .github/workflows/release.yml(배포).
- 자주 깨지는 곳:
  - computeDiscount 퍼센트 곱셈과 createOrder 옵션 가격 합산 오버플로는 각각 10/05·10/07에 수정 완료. 같은 과제를 다시 고르지 말 것.
  - createOrder 옵션 루프는 Scan 실패 continue 및 rows.Err 미검사. 실제 HTTP→DB 실패 재현 수단 미확인.
  - validateTalent의 기본 DeliveryDays는 양수만 검사, 옵션 AdditionalDays는 0~365. 기본 기간 상한의 실제 피해는 미확인.
  - DB 오류/404 혼합의 남은 uuid·enum 입력 경로는 자연 HTTP 실패 증거를 확보하지 못했다(이전 기록).
  - openapi_test.go는 경로 집합만 비교. HTTP 메서드와 응답 코드 검사 없음.
  - payOrder는 PAID→READY를 같은 트랜잭션에서 커밋. REQUIREMENT_PENDING의 HTTP 도달 불가는 이전 회차 조사 결론.
  - ApprovalAdmin.save는 알려진 조건 5개로 재구성, toggle은 원본 조건 보존. 알 수 없는 조건 유실 가능.
  - 요청 구조체 전체를 audit에 넘기는 10곳은 여전함. 원문을 감사 details에 추가하는 해결책 금지.
- 검증 함정:
  - integrationServer는 실제 Handler·DB·Worker와 apiUnderTest 전역 공유 — 테스트 병렬화 금지(이전 기록).
  - 메일 digest 테스트는 같은 DB 재사용뿐 아니라 깨끗한 DB에서도 간헐 실패한 이력이 있다. 이번 원인·재현 미검증.
  - client.do의 map[string]any 숫자는 float64. 큰 정수는 pool로 int64 Scan하거나 정확히 표현되는 값 사용(이전 기록).
  - sellTalent는 옵션을 등록하지 않는다. 옵션 ID는 이전 테스트처럼 DB에서 조회(이전 기록).
  - Node 20이 npm PATH에 끼어들어 테스트 0건이 되는 환경 문제를 저장소 결함으로 다시 고치지 말 것.
  - release.yml은 v* 태그에서 Docker build/archive 재로드/Release만 실행, make check나 DB 통합 단계 없음.
  - 이번 Docker·DB·브라우저 미사용. 기존 주문 통합 테스트 단독 -v에서 DSN 없음 SKIP 확인.
  - 스크린샷 스크립트는 시드·설정 쓰기를 하므로 폐기 루프백 인스턴스에서만 실행(README).
