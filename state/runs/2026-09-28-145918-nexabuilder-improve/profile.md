# nexabuilder 프로필 (2026-09-28)
- 목적: 엔티티·폼·목록·워크플로 메타데이터로 업무 화면을 만드는 Spring Boot 로우코드 플랫폼과 관리 콘솔.
- 스택: Java 21, Spring Boot 4.1.1, Gradle 8.14.3 Kotlin DSL, JPA/JdbcTemplate, Liquibase XML, 기본 H2와 외부 DB 프로필, Thymeleaf/Bootstrap/htmx/jQuery 4+migrate/jqWidgets/ECharts, Groovy, POI 5.3.0/OpenPDF 3.0.5. 현재 버전 v1.25.0(master@a36fd87).
- 구조:
  - `core/ui` — NexaUiService(1186줄): `requireLiveList(listId)`(59-66) 가 존재+deletedAt 판정의 **단일 게이트**로 `listDefinition`·`listData`·`ListExportController.resolveExportable`·`DataAdapterService.queryList` 네 경로가 공유한다. `requireLiveEntity`(88-95) 가 엔티티 쪽 짝. `listDefinition` 은 `entityMapFor(list)` 로 entityId null 을 허용한다. 폼만 `formDefinition` 안에 인라인 판정으로 남아 있다.
  - `core/ui` listData(157-203) — 페이징 계약이 여기 모여 있다: `@RequestBody` 맵의 **복사본**에서 `_offset`/`_limit`(`PARAM_OFFSET`/`PARAM_LIMIT`, 136-137)만 제거해 실제 offset/limit 으로 쓰고, `_limit` 이 없거나 0 이하면 `list.page_size`(null→100)로 fallback 한 뒤 `MAX_FEED_ROWS`(public, 5000)로 클램프한다. SQL 분기는 두 키를 정규화된 값으로 되돌려 `sqlExecutor.executeQuery` 에 넘긴다(자기 페이징 SQL 본문 대비). `intOr`(812) 은 Number·String 둘 다 받는다.
  - `core/data` — DataAdapterService(359줄): jqxgrid용 `{Rows,totalCount}`. `parse(Map,Integer)` 가 `pagenum`/`pagesize` 를 클램프(하한 0, 상한 `MAX_PAGE_SIZE=1000`, fallback 100). `executeEntityBacked` 는 DB 페이징(`SqlPagination.limitOffset`), `executeSqlBacked` 는 전체 행을 받아 `lowerCaseKeys`→`applySort`→`applyPaging(subList)` 로 자바 페이징. 두 백엔드 모두 응답 키를 소문자로 통일한다.
  - `core/entity` — EntityService(동적 DML/조회), SchemaDdlService(DDL), RecordSet(`getRows()` 는 **unmodifiableList**). `EntityService.list(table, filters, offset, limit)` 은 filters 맵의 **모든 키**로 `WHERE k = :k` 를 만들고 `sanitizeIdentifier` 정규식이 선행 밑줄을 통과시킨다 — 프로토콜 파라미터를 걸러 넣지 않으면 SQL 문법 오류(500)가 된다. 모든 행을 `List<Map>` 으로 적재하므로 limit 상한이 곧 메모리 방어다.
  - `core/sql` — SqlExecutor(executeQuery/executeDml/executeRawQuery, `resolveSql` 은 @Cacheable, **페이징 API 없음**), SqlPagination 의 DB별 LIMIT/OFFSET.
  - `core/*` — permission, auth, session, audit, llm/ai, menu, report, version 등 도메인 서비스.
  - `api/controller`(100+개)·`api/dto` — REST와 ApiResponse. GlobalExceptionHandler: IllegalArgumentException→400, AccessDenied→AccessAuditHandler, AI 쿼터→429. **`DataAccessException` 계열 핸들러는 없다 → SQL 오류는 500.**
  - `api/controller/ListExportController`(443줄) — CSV/XLSX/PDF 내보내기 3종. 셋 다 `resolveExportable`(휴지통 400 + `ScreenPermissionService.canView` 403) → `resolveColumns`(columnsJson, hidden 제외) → `readQueryParams`(355, 쿼리스트링 단일값 맵) → `uiService.listData` → `lookup(row,field)`(366, field→UPPER→lower 흡수) 순서. **`readQueryParams` 는 `_limit` 을 넣지 않아 내보내기가 `page_size`(기본 100)로 조용히 잘린다 — 2026-09-28 정찰이 확인한 미수정 결함.**
  - `web/controller`·`resources/templates`·`resources/static` — 서버 화면. `templates/runtime/list.html`(1065줄) 에 jqxgrid + 내보내기 버튼 3개(`downloadExport`:1039, `filterValues()`:372 만 쿼리스트링에 담는다) + 대체 뷰 7종(kanban/tree/calendar/pivot/gantt/map/chart) 진입. 7종 전부 `POST /api/v1/builder/lists/{id}/data` 에 `{_offset,_limit}`(chart/pivot/tree 5000, map/gantt 1000, calendar/kanban 500)을 보내고 `valueOf(row,field)`(literal→UPPER→lower)로 행을 읽으며 fetch 실패를 `catch (e)` 로 삼킨다.
  - `resources/db/migration` — Liquibase 001~079 XML + changelog-master.xml. 027이 목록/폼/엔티티 `deleted_at` 추가.
  - `src/test` — SpringBootTest/MockMvc/H2 통합 테스트 중심, 598건 통과(2026-09-27 기준).
- 빌드·테스트: `sh ./gradlew --no-daemon test`(**gradlew 가 100644 라 sh 경유 필수, chmod 하지 말 것 — CI 는 자체 chmod 스텝을 쓴다**), 단일 `--tests 'com.nexabuilder.api.X'`, 전체 강제 `--no-daemon cleanTest test`(수 분, 테스트 힙 2g), 패키징 `--no-daemon bootJar -x test`. 자율 회차의 정찰 단계에서는 gradlew 실행이 샌드박스 승인 대상이라 못 돌 수 있다 — 실패 재현은 구현 단계에서 할 것.
- 관례: Lombok 생성자 주입. 테스트 픽스처는 UUID 8자 접미사·정리 없음(`seed()` 헬퍼 + `record Fixture` 패턴). 커밋은 한국어 `type(scope): …합니다`, 버전 커밋/PR merge 는 영어. 새 Liquibase XML 은 changelog-master 에 include. 설정은 application.yml + nexa_config 런타임 설정. 주석에 "왜 이 값인가"(예: 5000 vs 1000)를 남기는 관례가 정착했다.
- 위험 구역: `core/auth`·`core/session`·`infra/security`·`core/permission`, `db/migration`, `.github/workflows`, workflow 의 비동기 감사·종료 경합. `RecordSet`/`SqlExecutor` 는 내보내기·Groovy·워크플로·대시보드가 공유하므로 계약 변경 금지. `NexaUiService.listData` 의 `_limit` fallback 은 런타임 그리드 페이징 계약이라 기본값을 올리면 매 요청이 전체 표 읽기가 된다. Jackson2JsonConfig:57 에 [removal] 경고.
- 자주 깨지는 곳: `@DirtiesContext` 를 붙이면 컨텍스트 재생성으로 시간·힙·비동기 종료 경합이 악화(2026-09-17). **같은 값을 읽는 경로가 여럿이라 한 곳만 고치면 구멍이 남는 패턴이 7회차 연속 반복**(목록 soft-delete 4경로 → 엔티티 soft-delete → SQL 목록 키 대소문자 → `_offset`/`_limit` 두 리더 → 내보내기의 `_limit` 미전달). 새 판정·새 파라미터를 다룰 때는 그 값을 읽는 리더를 전부 세고 단일 헬퍼/단일 규약으로 모을 것. webjar 버전 고정 URL 404, jQuery 4 에서 migrate 제거 시 jqWidgets 오류.
- 검증 함정: CI 는 chmod 후 gradlew 직접 실행 + setup-java Temurin21, foojay 가 누락 JDK 다운로드. CI 는 test+bootJar, CodeQL 은 public 저장소에서만. `/api/v1/data/*` 는 성공 시 `{Rows,totalCount}`, 실패 시 `{success,message}` 로 **봉투가 다르다**. `/api/v1/builder/**` 는 `ApiResponse` 봉투(`data`/`total`). 페이지 파라미터 이름이 경로마다 다르다 — `/data/*` 는 `pagenum`/`pagesize`, `/builder/lists/{id}/data`·`/entities/{id}/rows`·내보내기 쿼리스트링은 `_offset`/`_limit`. H2 는 `SELECT id, name` 에 `ID`/`NAME` 을 주고 음수 OFFSET 을 거절한다(둘 다 실행 확인). 내보내기 테스트는 `sessionAttr("nexabuilder.user", …)` 가 필요하다(`resolveExportable` 이 세션에서 User 를 읽는다). PDF 한글 글리프는 환경 폰트 의존(HYSMyeongJoStd-Medium, 없으면 Helvetica 토푸). 외부 서비스 의존 테스트 유무는 미확인.
