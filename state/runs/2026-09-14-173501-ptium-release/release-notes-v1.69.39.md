# Ptium 1.69.39

생각은 umm 의 캔버스에서 시작해 muni 의 문서가 되고, Ptium 의 슬라이드가 되어 weekly 의
보고로 들어갑니다. 지금까지는 단계마다 사람이 파일을 **내려받아 다시 올려야** 했습니다.
사내 서비스가 모두 같은 표준(HANDOFF-STANDARD)을 따르므로, 이번 판은 Ptium 의 몫을
채웁니다 — 덱을 **pptx** 로 보내고, **마크다운 · docx · csv · xlsx · txt** 를 받습니다.
**꺼진 채로 나갑니다** — 허용 목록이 비어 있는 동안 새로 설치한 곳은 이전과 바이트 하나
다르지 않게 움직입니다.

## 1. 덱을 다른 서비스로 보냅니다

편집기의 **내보내기** 대화상자 아래에 **다른 서비스로 보내기**가 생겼습니다. pptx 를
받는 서비스가 목록에 있을 때만 보이고(표준의 형식 표에서는 weekly 뿐입니다), 누르면
Ptium 이 **5분 동안 한 번만** 쓸 수 있는 표(claim)를 발급하고 받는 쪽의
`/handoff?source=…&claim=…` 을 새 창에서 엽니다. 창을 먼저 열고 표를 받은 뒤 `noopener`
로 이동하므로 팝업 차단에 걸리지 않고, 받는 쪽은 여는 창의 손잡이를 갖지 않습니다.

### 표는 자격 그 자체이므로, 어디에도 남기지 않습니다

- `POST /api/v1/handoff/claims` 는 표준의 모양 그대로 응답합니다(201, envelope 없이).
  내보내기와 **같은 권한 · 같은 예산 게이트**를 지나고, pptx 는 **발급하는 그 순간**
  부르는 사람의 권한으로 빌드됩니다. 받으러 오는 서비스는 자기 신원을 들고 오지
  않기 때문입니다.
- `GET /api/v1/handoff/claims/{claim}` 은 **로그인 없이** 한 번 내줍니다. 내주기는
  `DELETE … RETURNING` — 두 번째 요청은 아무것도 찾지 못하고, 5분이 지난 요청도
  마찬가지입니다. 이미 쓰인 표, 지난 표, 없는 표는 **모두 같은 404** 이고, 어느
  쪽인지 말하지 않습니다.
- 표에는 `handoff_claims` 에 **SHA-256 해시만** 남습니다. 요청 로그와 인시던트에는
  경로가 `{claim}` 으로 가려 찍힙니다. 발급할 때 만료된 행을 함께 치우므로 표는 몇
  분어치 이상 쌓이지 않습니다.
- 파일 이름은 RFC 8187 로 붙습니다. 한글 제목이 헤더에서 깨지지 않습니다.

## 2. 다른 서비스의 문서를 받습니다

`/handoff` 는 SPA 의 페이지입니다 — 이 저장소는 브라우저가 PKCE 를 직접 하는 구조라
서버가 착지를 받을 수 없습니다. 페이지가 `POST /api/v1/handoff/receive` 를 **한 번**
부르고, 서버가 원본에서 받아 와 파일을 올린 것과 똑같이 슬라이드로 만든 뒤 편집기로
이동합니다. 어디서 왔는지는 덱의 **브리프 · 도착 시 안내 · 감사 로그**
(`presentation.handoff_receive`, 출처 오리진과 파일 이름)에 남습니다.

### `source` 는 밖에서 들어온 값입니다

받아 온 그대로 요청하면 이 서비스는 네트워크의 아무 주소나 읽어 주는 도구가 됩니다.
그래서:

- 허용 목록에 없는 오리진은 **요청조차 보내지 않고** 거절합니다. 일치는 스킴 · 호스트 ·
  포트까지 **글자 그대로**입니다.
- **리다이렉트를 따르지 않습니다.** 목록의 주소가 다른 곳으로 넘기려 하면 그 자리에서
  끝냅니다.
- **30초와 25MB**(그리고 `generation.max_template_mb`)에서 끊습니다.
- `Content-Type` 이 받는 형식이 아니면 버립니다. 파싱한 미디어 타입으로 보므로 charset
  매개변수는 도움도 방해도 되지 않습니다.

실패는 종류별로 나뉘고, 페이지가 각각을 **한국어 한 문장**으로 말합니다 — 허용된 곳이
아니다, 표가 이미 쓰였거나 5분이 지났다, 다른 주소로 넘기려 했다, 읽지 못하는 형식이다,
너무 크다, 닿지 않았다.

### 로그인이 도중에 끼면 표를 잃지 않습니다

받는 사람이 로그인돼 있지 않으면 `App.tsx` 가 `/login?return_to=` 로 보내고,
`LoginPage` 는 **비밀번호 · dev · SSO 세 경로 모두** 그 주소로 돌아갑니다. 지난 판에
보류해 둔 "SSO 로 계속하기도 깊은 링크" 가 이것으로 함께 풀렸습니다. 자동 로그인(1.69.38)을
켜 두면 화면 없이 이어집니다. 5분 안에 못 돌아오면 "표가 이미 쓰였거나 5분이 지났습니다"
가 나오고, 보낸 쪽에서 다시 보내면 됩니다.

## 3. 관리자가 목록을 적습니다

**관리 → 서비스 설정 → 문서 넘기기** 에 한 줄에 하나씩 `이름=오리진` 을 적습니다
(`handoff.peers`, 기본 **빈 목록**). 저장 즉시 적용되고 재시작이 필요 없습니다.

```
umm=https://umm.intra
muni=https://muni.intra
kanpic=https://kanpic.intra
weekly=https://weekly.intra
```

- 이름이 `umm` · `muni` · `kanpic` · `weekly` · `ptium` 가운데 하나여야 그 서비스가
  **받는 형식**을 압니다. 다른 이름은 받기만 하고 보내지는 않습니다.
- 오리진은 `https://host` 또는 `https://host:port` 꼴이어야 하고, 경로 · 쿼리 · 자격
  증명이 있으면 저장되지 않습니다. 같은 주소를 두 번 적을 수 없고 50줄까지이며, 한
  줄이라도 틀리면 목록 전체가 저장되지 않습니다. 화면과 서버가 **같은 검증**을 합니다.
- `GET /api/v1/handoff/targets` 가 빈 배열이면 보내기 단추는 없습니다.

상대 서비스가 덱을 받아 갈 Ptium 의 주소는 `PUBLIC_BASE_URL` 입니다. 비어 있으면 요청이
들어온 주소(`X-Forwarded-Proto` · `X-Forwarded-Host` 또는 `Host`)를 쓰지만, 리버스
프록시 뒤라면 두는 편이 확실하고 상대 목록의 Ptium 주소와 같아야 합니다.

## 지키는 장치

`internal/handoff` 는 형식 표, `이름=오리진` 파싱과 거절되는 줄, 오리진의 정확한
일치, 그리고 받는 쪽의 모든 경비를 봅니다 — 목록 밖은 요청 0건, 리다이렉트 거부,
크기 · 시간 상한, 미디어 타입, RFC 8187 파일 이름. `internal/httpapi/handoff_test.go`
는 표에 실리는 `source` 가 `PUBLIC_BASE_URL` 또는 요청이 들어온 주소인지, 목록이 빌 때와
pptx 를 받지 않는 서비스뿐일 때 대상이 비는지, 목록 밖 출처가 요청 전에 거절되는지,
실패가 종류별로 응답에서 구분되는지, 내준 표가 **로그에 닿지 않는지**, 틀린 목록이
저장되지 않는지를 봅니다.
`internal/store/handoff_test.go` 는 실제 PostgreSQL 에서 표가 **한 번만, 제때만**
내주어지는지 봅니다. 웹 쪽 `handoff.test.ts` · `handoffpeers.test.ts` 는 주소 해석과
목록 검증입니다.

openapi 에 경로 넷과 스키마 셋이 있습니다. 관리자 안내서에 설정 표 한 행과 3.4 절 —
목록 적는 법, 이름 규칙, `PUBLIC_BASE_URL`, 받는 쪽 규칙, 로그인 흐름, 확인법 — 과
장애 대응 세 행을 넣고 PDF 를 다시 만들었습니다.

아직 하지 못한 것: 실제 두 서비스 사이의 왕복. 상대 서비스가 이 기계에 없어, 이번 판의
검증은 시험과 가짜 peer 로 한 것입니다.
