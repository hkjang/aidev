## 2026-09-18
- 선택: Keycloak 액세스 토큰으로 `/mcp` 열기 — OAuth 2.1 리소스 서버 (캠페인 mcp-oauth-2026-09) (가치 5 / 위험 2 / 작업량 M)
- 결과: 성공
- 요약: 이 저장소는 사용자별 계정과 Keycloak OIDC 웹 로그인(`internal/oidc`, `users.oidc_subject`)이 이미 있어 MCP-OAUTH-STANDARD 를 그대로 붙였습니다. 출발점에 특이점이 하나 있었습니다 — `auth.Service.OIDCValidator` 가 **모든** Bearer 경로(REST 포함)에서 액세스 토큰을 받고 있었는데, 그 검증은 ID 토큰용(`aud` 에 웹 클라이언트 ID 요구, `typ`·`nbf`·`cnf` 미검사, 요청마다 Discovery+JWKS 왕복)이라 실제 Keycloak 26 액세스 토큰(`aud=[account]`)으로는 통과할 수 없는, 문서에도 없는 문이었습니다. 표준대로 그 문을 닫고(`Authenticate` 는 세션·키만, 새 `AuthenticateMCP` 만 JWT 모양의 Bearer 를 검사) `/mcp` 전용으로 다시 만들었습니다. **고른 것과 이유**: (1) 설정 자리는 `system_settings` 의 `mcp` 네임스페이스에 점이 든 키 `oauth.enabled`·`oauth.resource`·`oauth.audience`·`oauth.scopes` — 표시명이 표준의 `mcp.oauth.*` 와 글자 그대로 같아지도록 `validSettingKey` 가 키의 안쪽 점만 허용(네임스페이스는 여전히 점 불가라 `namespace.key` 가 감사·번들에서 모호하지 않음). 발급자·클라이언트 ID·username claim 은 `oidc_providers` 재사용. (2) 리소스 식별자는 `mcp.oauth.resource`, 비면 이미 있는 공개 주소 `system.service_url` + `/mcp`; Host 헤더 추정은 두지 않음(service_url 은 항상 값이 있음). 절대 http(s) URL 이 아니면 켜져 있어도 비활성이고 화면·로그(`mcp oauth is enabled but cannot run`)에 이유가 남음. (3) 이 저장소에 go-oidc 가 없어 손으로 검사: JWKS 서명(RS/ES/PS 만, 키의 공개 `alg` 와 토큰 alg 일치 요구), `iss`, `exp`·`nbf`(60초 허용), payload/header `typ=ID` 거부, `cnf` 거부, `sub`, 그리고 대상 — `aud` 에 리소스 식별자 또는 `aud`/`azp` 가 `mcp.oauth.audience` 에 있어야 하며 웹 클라이언트 ID 는 암묵적으로 허용하지 않음(postra 의 "웹 클라이언트를 재사용하지 않는다"). 거절 메시지에 본 `aud`/`azp` 와 적을 값·매퍼에 넣을 값을 넣고, 모든 거절의 원인은 한 곳(`AuthenticateMCPToken`)에서 `mcp oauth token refused` 로 로그 — 캠페인 규칙대로 소스에서 확인한 뒤 가이드에 "로그에 남는다" 고 적었음. Discovery 10분·JWKS 는 모르는 kid 에서 재조회(초당 1회 제한), `jwks_uri` 는 발급자와 같은 origin 이어야 함. (4) 계정은 `users.oidc_subject = sub AND active` 만 — username 폴백은 두지 않음(로컬 `admin` 과 같은 SSO username 이 그 계정으로 매핑되는 길을 열지 않기 위해). 주체는 `KeyID="sso"`·`KeyScopes=mcp.oauth.scopes`(토큰 `scope` 가 Relio 어휘를 싣고 오면 교집합, `mcp:use` 는 항상)·`KeyChannels=[MCP]` 로 키와 같은 `Has`/`ChannelAllowed` 문을 지남 — 관리자 계정이라도 상한 밖 권한은 없고 REST 채널은 닫힘. (5) 401 은 `Bearer realm="Relio MCP"` 에 활성일 때만 `resource_metadata=` 를 더하고 거부된 토큰이면 `error="invalid_token"` — 한국어 사유는 헤더가 아니라 JSON 본문(RFC 6750 문자 제한). 메타데이터는 `/.well-known/oauth-protected-resource` 와 `…/{resource...}` 두 경로에서 맨 JSON + `Access-Control-Allow-Origin: *`, 꺼져 있으면 404. 화면: 사내 SSO 연결 페이지에 **MCP를 SSO 토큰으로** 카드(스위치·리소스 식별자·MCP 주소·메타데이터 주소·허용 대상·범위, 켜져 있지만 조건이 빠지면 경고), 키 페이지 MCP 안내에 메타데이터가 200 일 때만 나오는 "키 없이 SSO로 연결" 절과 SSO 여부에 따라 갈리는 문제 해결 항목. 문서: ADMIN_GUIDE 3.2 설정 표 4행, 3.3 새 절(리소스 서버 설명·켜지는 조건·검사 항목·Keycloak 클라이언트/Audience 매퍼 4단계·curl 확인·거절 메시지별 조치 표)·장애 대응 2행·보안 항목, docs/api-mcp.md
