- 요약: igame에는 go-oidc 기반 OIDC(`internal/api/auth.go`, `oidc_flows` 테이블)가 이미 있어 캠페인 대상이다. SILENT-SSO-STANDARD.md와 releasedock 참조를 따라 같은 능력을 이 저장소의 구조로 만들었다. 서버: OIDC 설정에 `auto_login`(기본 꺼짐)을 두고, `GET /api/v1/auth/oidc/login?prompt=none`은 그 설정이 켜져 있을 때만 제공자에 `prompt=none`을 전달하며 꺼져 있으면 조용히 평범한 로그인으로 바꾼다(`silentLoginRequested`) — 주소에 붙이는 것만으로 흐름을 바꿀 수 없다. flow 행에 `silent`를 기록하는 마이그레이션 `010_silent_sso.sql`을 더해 콜백이 `error=login_required`를 받으면 그 flow가 silent였을 때만 `302 /login?sso=none[&return_to=…]`로 보내고(return_to는 기존 `safeReturnTo`로 `/`로 시작·`//` 불가), state는 어느 쪽이든 소비해 재생을 막는다; silent가 아닌 flow의 제공자 오류는 종전대로 401. `public/config`는 `oidc_auto_login`을 OIDC 활성+auto_login일 때만 true로 내린다. 클라이언트: 새 `web/src/state/silentSso.ts`가 세 겹 가드를 담는다 — sessionStorage `igame.sso.silentAttempted`(탭 세션당 한 번), 로그아웃 시 `igame.sso.signedOut`(다시 세션이 생기면 해제), 주소의 `sso=none|error` 표시; 저장소를 읽지 못하면 "이미 시도했다"로 친다. `/login`과 `/api/`·`/mcp`·`/healthz`·`/readyz`·`/momento/`에서는 시작하지 않는다. `AuthContext`는 최초 로드에서 `/me`가 401이고 규칙이 허용할 때만 `window.location.assign`(최상위 이동, iframe 아님)으로 한 번 시도하고 loading을 유지해 로그인 화면이 깜빡이지 않게 하며, 로그아웃 전에 억제 표시를 쓰고 로그인/세션 확인 시 지운다. LoginPage는 `return_to` 쿼리를 읽어 깊은 링크로 돌아가고 "사내 SSO로 계속" 버튼에도 return_to를 실어 보낸다. 관리자 화면 OIDC 카드에 "자동 로그인" 스위치와 설명을 넣었다. 검증: `make lint`, `make test`(Go 전체 / SDK 9 / web 241 — 새 web 테스트 12개: silentSso 8·loginDestination 4), `go test -race`, `make test-db`(docker `postgres:17-alpine`, 새 PG 테스트 3개가 가짜 issuer로 login 다리와 refusal 콜백을 실제로 돌림 + DB 없는 규칙 테스트 4개), `make web-build`(오프라인 번들 검사 포함), `scripts/check-release-contract.sh` 통과. 실제로도 띄워 확인했다 — 바이너리 + 가짜 IdP(python, prompt=none에 login_required로 응답)로 관리자 로그인→`PUT /admin/settings/oidc`에 `auto_login:false`→`?prompt=none`이 제공자에 전달되지 않음→`auto_login:true`(secret 비워도 유지)→`oidc_auto_login:true`→silent 시도를 따라가면 `/login?sso=none&return_to=%2Fgames%2Fsnake`에 도착→버튼 로그인은 여전히 prompt 없음→감사 로그 `oidc.update`까지 curl로, 그리고 `scripts/smoke-settings.sh`(설정 왕복·모르는 field 거부 계약) 통과. docs/ADMIN_GUIDE.md(auto_login 항목·장애표), docs/api.md, docs/keycloak.md를 갱신하고 공용 `tools/guide/md2pdf.mjs`로 ADMIN_GUIDE.pdf(19쪽)를 다시 구워 해당 쪽을 렌더해 확인했다. 관리 화면 캡처(`admin-security.png`)는 여전히 v0.7.11 것이라 새 스위치가 보이지 않는다 — 캡처 도구가 파괴적(전용 배포 필요)이라 이번에는 찍지 않았다.
