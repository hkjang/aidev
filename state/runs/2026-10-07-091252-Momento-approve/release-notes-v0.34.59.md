# Momento v0.34.59 — 보존 정책을 저장하다 실패하면 한국어로 무엇을 고칠지 말해 줍니다

콘솔 **관리 → 보존 정책**에서 보존기간을 설정하는 관리자를 위한 개선입니다. 「저장」이 거절되면 고쳐야 할 칸의 이름과 허용 범위를 한국어로 안내합니다.

## 화면에 없는 영문 컬럼명이 오류 안내로 나왔습니다

보존 정책의 다섯 칸은 숫자를 직접 입력합니다. 범위를 벗어난 값을 저장하면 서버는 `INVALID_RETENTION` 코드와 함께 `raw_event_months must be between 1 and 120` 같은 문장을 보냈고, 화면은 `save.error.message`를 그대로 표시했습니다. 읽는 사람이 영문 컬럼명을 보고 어느 칸을 고칠지 찾아야 했습니다.

이제 서버가 거절한 항목을 화면의 이름으로 부릅니다.

| 고칠 칸 | 저장 실패 시 안내하는 범위 |
|---|---|
| Raw Event (개월) | 1개월에서 120개월 |
| Session 요약 (개월) | 1개월에서 120개월 |
| Aggregation (개월) | 비워 두거나 1개월에서 1200개월 |
| Realtime (시간) | 1시간에서 168시간 |
| Debugger / Dead Letter (일) | 1일에서 90일 |

예를 들어 Raw Event 값이 범위를 벗어나면 **「Raw Event (개월)」 은 1개월에서 120개월 사이로 적으세요.**라고 표시합니다. 범위 검사는 기존처럼 서버에서 수행하며, 이번 변경은 저장 실패 후 안내를 바꿉니다.

## 저장 장애는 원인을 단정하지 않습니다

`RETENTION_SAVE_FAILED`로 돌아온 저장 실패에는 한국어 안내를 먼저 보여 주고, 서버 원문은 작은 상세 문구로 남깁니다. 기존 정책을 갱신하는 요청도 같은 저장 경로를 쓰므로 오류를 ‘이미 등록된 정책’이라고 설명하지 않습니다.

`INVALID_RETENTION`이라도 알려진 다섯 컬럼명이 없는 문장은 각 칸의 허용 범위를 확인하도록 안내하고 원문을 상세에 남깁니다. 사이트를 찾을 수 없으면 새로 고침을 권하며, 잘못된 요청 본문과 요청 실패에도 기존 공용 한국어 문장을 사용합니다. 모르는 오류 코드는 서버 메시지로 되돌아갑니다.

## 빌드 의존성도 갱신했습니다

콘솔 잠금 파일의 `source-map-js`를 1.2.1에서 1.2.2로 갱신한 변경을 함께 포함합니다. 보안 감사 결과는 아래 검증 항목에 기록합니다.

## 확인

- 콘솔: `npm ci`·`npm audit`(취약점 0건)·`npm run lint`·테스트 **234건**·프로덕션 빌드 통과. 보존 정책 오류 안내 테스트 11건이 추가되었습니다.
- SDK: `npm ci`·`npm audit`(취약점 0건)·typecheck·테스트 **27건**·build 통과.
- Go: 로컬 PostgreSQL 17을 연결한 `go test -race ./cmd/... ./internal/...`와 `go vet` 통과. 버전 선언·잠금 파일·Compose 이미지 이름의 일치 검사도 포함합니다. 별도 부하 테스트는 `MOMENTO_LOAD_POSTGRES_DSN`을 지정하지 않아 실행하지 않았습니다.
- `govulncheck`: 코드가 호출하는 취약점 0건. 가져오는 패키지 4건·필요 모듈 20건의 비호출 취약점은 별도로 보고되었습니다.
- 기존 Dockerfile의 프로덕션 이미지 빌드 통과. 배포용 아카이브의 로드·기동 검사는 태그 푸시 후 기존 릴리스 워크플로가 수행합니다.

SDK 첫 검사는 npm이 상위 디렉터리의 Node 20을 선택해 `.ts`를 읽지 못했습니다. 이 작업 디렉터리의 무시되는 `node_modules/.bin/node`가 Node 22.23.1을 가리키게 한 뒤 같은 검사를 다시 실행해 통과했습니다. 저장소의 실행 코드와 테스트는 수정하지 않았습니다.

## 범위와 배포

제품 동작 변경은 `web/src/pages/adminErrors.ts`와 `AdminPage.tsx`의 보존 정책 오류 안내, 이를 고정하는 `web/test/adminErrors.test.mjs`입니다. 서버·API·데이터베이스 마이그레이션과 보존기간의 허용 범위는 바뀌지 않습니다. 보존 정책을 수정하지 않는 사용자는 새로 할 일이 없습니다.

이번 개선은 릴리스 노트로 안내합니다. 기존과 같이 태그 푸시 후 GitHub Actions가 `momento:v0.34.59`를 빌드하고, 오프라인 아카이브 `momento-v0.34.59.tar.gz`와 `.sha256`을 검증해 Release에 첨부합니다. 설치 절차는 `docs/OFFLINE.md`를 따릅니다.

배포 담당자는 적용 후 「보존 정책」에서 범위를 벗어난 다섯 입력이 각각 올바른 칸과 범위를 안내하는지 확인합니다. 안내가 다른 칸을 가리키거나 정상 값의 저장이 실패하면 확대 적용을 중단하고 이전 `momento:v0.34.58` 이미지로 되돌립니다. 이 세션은 로컬 릴리스 준비만 수행하며 실제 배포와 운영 환경 확인은 수행하지 않습니다.
