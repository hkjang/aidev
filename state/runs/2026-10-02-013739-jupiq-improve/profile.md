# jupiq 프로필 (2026-10-02)
- 기준: main@92ff88c, VERSION 1.8.7. 2026-09-29 프로필을 계승하고 base·버전·이번 확인 사항만 갱신했다.
- 목적: JupyterHub·Kubernetes·Prometheus 자원을 조회하고 서버·승인·권한을 운영하는 오프라인망용 관리 콘솔.
- 스택: Go 1.26(toolchain 1.26.7), net/http·go-oidc·pgx/PostgreSQL, React 19·TypeScript 5.9·Vite 7·Ant Design·ECharts, Vitest 3/jsdom, CI Node 22.
- 구조:
  - cmd/jupiq: 진입점·서비스 배선.
  - internal/api: 라우터·권한 미들웨어·HTTP 핸들러·OpenAPI 계약 검사. `helpers.go`에 응답 봉투 4개(`writeJSON`·`data`·`list`·`apiError`)와 쿼리 파서(`queryInt`·`queryIntOrReject`)가 모여 있다.
  - internal/store: PostgreSQL 조회·권한 범위·설정·메일 기록·사용량 롤업. 응답 행을 `map[string]any`로 조립해 돌려주는 패턴이 많다.
  - internal/auth: 세션·OIDC·silent SSO, internal/secure: 암호화.
  - internal/mail: SMTP·알림, internal/integration: 외부 연동(prometheus.go의 `validPrometheusSample`이 NaN·Inf·음수·시각 이상 샘플을 거른다), internal/collector: 수집, internal/analytics.
  - migrations/: 기동 시 SQL 적용, 001~014. 013이 resource_usage_hourly(적분 열은 `double precision NOT NULL DEFAULT 0`).
  - web/src/api/client.ts: `request`·`requestList`·`streamAI`·`ApiError`. 세 경로의 성공 계약이 서로 다르고, 오류 생성과 깨진 JSON 처리는 공유된다.
  - web/src/pages: React 화면. docs/USER_GUIDE.md·ADMIN_GUIDE.md(+PDF)가 정본, openapi/openapi.yaml이 API 계약.
- 빌드·테스트: make deps → make lint → make test → make build.
  - 프런트: `npm --prefix web ci` / `test` / `run lint` / `run build`. 집중: `npm --prefix web test -- src/api/client.test.ts`.
  - 이번 실측 없음(Go 테스트 미실행). 지난 회차 실측은 `go test -count=1 ./internal/api ./internal/store` 통과(api 0.060s/store 0.006s).
  - DB: `JUPIQ_INTEGRATION_TEST_DSN` 지정 후 `make test-integration` = `go test -count=1 -p=1 -run Integration ./internal/store ./internal/api`.
  - `make release-check`: 모듈·vet·govulncheck·Go·DB·스크린샷·npm audit/lint/test/build. 수 분 이상·네트워크 필요.
- 관례: 커밋 메시지는 한국어 `fix: …`. 설정은 DB settings, 비밀은 secrets 암호화. 왜 그렇게 했는지를 한국어 주석으로 코드 옆에 남긴다.
  - API 오류는 `error.code`/`message`/`request_id`, 성공은 `{"data":…}`(목록은 `meta`까지). `queryIntOrReject`는 잘못된 정수·음수를 400 `invalid_query`로 거부.
  - `pageBounds` 상한 200. `boundedLimit(limit, fallback, max)` — 메일 200·소비량 500·지표 5000. 상한 과제는 완료, 재선정 금지.
  - mailDeliveries status는 TrimSpace 후 빈 값/queued/sent/failed만 허용(그 밖은 400). Total/Summary는 status와 무관한 전체 집계이고 통합 테스트가 그것을 고정한다.
  - `/usage`는 `consumption_group_by`로 되돌림 그룹을 응답에 드러낸다.
- 위험 구역: internal/auth, migrations, .github/workflows, SSRF 설정 검증, 권한 범위 SQL, SMTP 자격증명.
- 자주 깨지는 곳: OpenAPI YAML 인용, MD/PDF·VERSION 정합, Go mux 라우트 충돌. 빌드·릴리스 경로를 건드렸으면 릴리스까지 확인.
- 검증 함정:
  - DSN 없는 `go test ./...` 성공에는 통합 skip이 포함된다. `make test-integration`은 DSN 없으면 실패한다.
  - CI는 PostgreSQL 16 + `-race`, release 통합은 PostgreSQL **14**, offline smoke는 16.
  - Hub 통합 테스트는 비loopback IPv4가 없으면 skip. 실제 Keycloak/SMTP E2E는 아직 미검증.
  - DB fixture는 고유 marker와 생성 ID로 정리하고, 전역 Total을 fixture 개수로 단정하지 않는다.
  - web/src/test/setup.ts는 jsdom window를 쓴다. 테스트를 node 환경으로 바꾸면 setup을 함께 봐야 한다.
  - client.ts는 모듈 로드 시 `VITE_API_BASE_URL`을 읽는다. 테스트 env는 import 전에 설정하고 복원해야 한다.
  - @types/node가 src 전체에 Node 전역을 깔아, 브라우저 코드의 `process` 사용을 tsc가 놓친다(미해결 보류 항목).
  - 대역 Store나 소스 문자열 검색을 결함 증거로 삼지 않는다. 실제 함수·실제 ResponseWriter·실제 HTTP로 증명한다.
- 이번 발견(2026-10-02 정찰):
  - `internal/api/helpers.go:29 writeJSON`이 `WriteHeader`를 먼저 하고 `json.NewEncoder(w).Encode` 오류를 버린다. 같은 코드를 실제 httptest 서버로 돌려 **200 + `application/json` + 길이 0 본문**과 클라이언트 `unexpected end of JSON input`을 재현했다. `json.Marshal`은 같은 값에서 쓰기 전에 오류를 돌려준다.
  - `writeJSON` 프로덕션 호출자는 7곳(helpers.go 3 + core_handlers.go 1708·1748·1756)뿐이고, SSE 스트리밍(ai_handlers.go)은 쓰지 않는다.
  - NaN이 응답까지 가는 실제 유입 경로는 **확인되지 않았다**: prometheus.go의 `validPrometheusSample`이 수집 입구를 막고, `numberFromAny`(resource_handlers.go:465)의 `"NaN"` 통과는 호출자 9곳이 모두 int64 캐스팅/비교라 응답에 닿지 않는다. 출구(resource_usage.go:272-299, metrics.go:741-746)에는 유한성 가드가 없다.
  - 저장소 변경 없음. 재현은 `/tmp` 임시 모듈에서만 했다.
- 최신 완료: 검색 이스케이프·SSE 정리·OIDC Discovery 캐시·주소 없는 키 알림 제외·email 정규화·limit 상한·consumption_group_by·메일 status 검증·HTTP 오류 error.code 보존·프런트 깨진 JSON → ApiError(v1.8.7).
