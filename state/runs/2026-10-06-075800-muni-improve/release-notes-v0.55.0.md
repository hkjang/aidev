워크스페이스를 ZIP으로 내보낼 때 **제목이 똑같은 문서 둘 가운데 어느 쪽이 어느 파일에 담길지가 요청마다 달라지던 것**을 고쳤습니다. 화면은 바뀌지 않았고, 마이그레이션도 설정 변경도 없습니다.

## 고친 것

### 바뀌지 않은 워크스페이스를 두 번 내려받으면 파일 내용이 서로 바뀔 수 있던 것

문서를 읽는 쿼리의 정렬은 `ORDER BY d.folder_id NULLS FIRST, d.title` 였습니다. 폴더와 제목이 같은 문서들은 이 둘만으로는 서로 구분되지 않으므로 **동률**로 남습니다.

이 동률은 엣지케이스가 아니라 **상례**입니다. 편집기의 새 문서 버튼으로 만든 문서는 제목이 없고, `createDocument`는 그런 문서 전부에 똑같은 `제목 없는 문서`를 줍니다. 그래서 아무도 이름을 바꾸지 않은 워크스페이스에서는 **모든 문서가 서로 동률**입니다.

PostgreSQL은 동률 행을 어떤 순서로 돌려줄지 약속하지 않습니다. `EXPLAIN (ANALYZE)`로 확인한 정렬 키는 둘뿐(`Sort Key: d.folder_id NULLS FIRST, d.title`)이고 방식은 `quicksort` — 안정 정렬이 아닙니다. 정렬에 들어가는 입력 순서는 행이 힙에서 읽힌 순서를 따라가고, 그 순서는 **행이 다시 써질 때마다 움직입니다.**

그 순서에 매달려 있던 것이 셋입니다.

- 이름이 겹치는 항목을 `(2)`로 옮기는 `uniqueEntryName`에 누가 먼저 도착하는지 — 즉 **어느 문서가 `제목 없는 문서.md`를 갖고 어느 문서가 `제목 없는 문서 (2).md`로 밀리는지.**
- 안내 파일 `목록.md`의 각 줄이 그 이름에 적어 주는 **작성자와 수정일.**
- 문서가 2000건을 넘는 워크스페이스에서 **어느 문서가 경계 밖으로 빠지는지.**

| 같은 폴더의 제목 없는 문서 둘 | 첫 번째 내려받기 | 같은 워크스페이스, 두 번째 내려받기 (이전) | (지금) |
| --- | --- | --- | --- |
| 본문이 `가`인 문서 | `제목 없는 문서.md` | `제목 없는 문서 (2).md` — **내용이 옮겨감** | `제목 없는 문서.md` |
| 본문이 `나`인 문서 | `제목 없는 문서 (2).md` | `제목 없는 문서.md` | `제목 없는 문서 (2).md` |

무엇도 편집하지 않았는데 같은 이름의 파일이 다른 문서를 담고, `목록.md`가 적는 작성자도 함께 바뀝니다. 내려받은 ZIP 둘을 비교하거나 앞서 받은 ZIP을 덮어쓰는 사람에게는 **문서가 뒤바뀐 것으로 보입니다.**

이제 정렬이 `ORDER BY d.folder_id NULLS FIRST, d.title, d.id`로 끝납니다. `d.id`는 유일하므로 **어떤 동률도 남지 않고**, 위의 셋이 매달릴 순서가 없어집니다. 바뀐 것은 SQL 한 토큰입니다.

### 바뀌지 않은 것

`uniqueEntryName`·`entryKey`·`safeFilename`, 휴지통 접두사, 2000건 경계, `목록.md`의 형식과 줄 모양, v0.54.0이 고정한 폴더 순회는 **건드리지 않았습니다.** `d.title`이 여전히 앞에 오므로 **제목이 서로 다른 평범한 워크스페이스의 파일 이름과 순서는 한 글자도 바뀌지 않습니다.** 내보내기 형식 `md`·`html`·`txt` 셋이 모두 같은 쿼리를 지납니다.

저장되는 값도 바뀌지 않습니다 — 제목도 문서 내용도 DB에서 손대지 않았으므로 이미 만들어 둔 문서에 다시 손댈 필요가 없습니다. 바뀐 것은 내보낼 때 문서를 읽는 순서뿐입니다.

### 남아 있는 것

- **어느 쪽이 원래 이름을 갖고 어느 쪽이 `(2)`를 받는지는 문서 ID 순서로 정해지며, 그것은 만든 순서가 아닙니다.** `documents.id`는 `gen_random_uuid()`이므로 ID 순서는 사람이 예측할 수 없습니다. 이번 릴리스가 약속하는 것은 **같은 워크스페이스가 매번 같은 배치로 나온다**는 것까지이고, 먼저 만든 문서가 `제목 없는 문서.md`를 받는다는 것은 약속하지 않습니다.
- **제목이 똑같은 문서 둘 자체는 그대로 둡니다.** 문서 생성에는 제목 중복 검사가 없고 이번 변경은 내보내기 쪽 정렬만 손댔습니다. 내려받은 ZIP에서 어느 파일이 어느 문서인지는 여전히 `목록.md`의 작성자·수정일로 확인해야 합니다 — 파일 이름만으로는 알 수 없습니다.
- **폴더 이름 중복 검사(`createFolder`)는 여전히 없습니다.** 이름이 같은 폴더 둘이 ZIP에서 갈리는 것은 [v0.54.0](https://github.com/hkjang/muni/blob/v0.55.0/docs/releases/v0.54.0.md)이 고정했고, 사이드바에서 구분되지 않는 폴더 둘을 만드는 것 자체는 그대로입니다.
- **2000건 경계 자체는 그대로입니다.** 경계 밖으로 빠지는 문서가 요청마다 달라지지 않게 된 것이고, 2000건을 넘는 워크스페이스가 한 번에 다 담기게 된 것은 아닙니다. `목록.md`는 이전과 같이 그만큼만 담았다고 적습니다.

## 검증

- 전용 PostgreSQL 16에서 `go test -count=1 -json ./...`: 하위 테스트 포함 **723 PASS**, 외부 코퍼스·수동 출력 4 SKIP, 실패 0 (v0.54.0의 722건 + 이번 검증 1건). HTTP API 테스트는 SKIP 없이 통과했습니다.
- 실제 라우트로 검증을 추가했습니다: 제목을 주지 않고 문서 넷을 인증 API로 만들어(그래야 제목이 이 테스트가 고른 문자열이 아니라 `createDocument`가 주는 값입니다) 한 번 내려받아 **이름 → 본문 대응**을 기록하고, 그 가운데 **한 행만** `UPDATE documents SET title=title`로 다시 쓴 뒤 열두 번 더 내려받아 대응이 그대로인지 확인합니다. 보고되는 모든 열은 글자 그대로 그대로이므로 **아무것도 바뀌지 않은 워크스페이스**이고, 그래서 ZIP도 바뀌어서는 안 됩니다.
- **항목 이름만 비교하는 검증은 고치기 전에도 통과합니다** — `제목 없는 문서.md`와 `제목 없는 문서 (2).md`는 어느 순서에서도 둘 다 나옵니다. 그래서 새 검증은 이름의 *집합*이 아니라 이름과 본문의 *대응*, 그리고 `목록.md`의 작성자 줄을 봅니다.
- 한 행만 흔드는 것이 중요합니다: 동률 넷을 **순서대로 전부** 다시 쓰면 넷이 같은 상대 순서로 힙 끝에 옮겨가므로 고치지 않은 코드에서도 통과해 버립니다.
- 고치기 전 실패를 이번 릴리스 준비에서 직접 재현했습니다: `, d.id` 한 토큰만 되돌려 다섯 번 돌렸을 때 **네 번 실패**(`download 2 put 본문 가 in "제목 없는 문서.md", but the first download put it in "제목 없는 문서 (2).md"`), 한 번은 통과했습니다 — 힙 순서가 우연히 유지된 경우입니다. 토큰을 되돌려 놓고 **여덟 번 연속 통과**했습니다. 즉 이 검증은 고치기 전에는 확률적으로 실패하고 고친 뒤에는 결정적으로 통과합니다. 비결정성이 문제였으므로 통과 한 번이 아니라 반복이 증거입니다.
- 프런트는 변경하지 않았고, `npm run lint`(`tsc -b`)·`npm test` 42파일·297건·`npm run build`를 그대로 통과했습니다.
- `go vet ./...`, Go 포맷 검사, placeholder 검사, `git diff --check` 통과.
- `CGO_ENABLED=0 go build -trimpath`, Docker 이미지 빌드 통과.
- 브라우저 E2E, 2000건을 넘는 워크스페이스에서의 경계 동작, 실제 운영 배포는 이번 릴리즈 준비에서 실행하지 않았습니다. 배포용 archive는 태그 푸시 워크플로가 생성합니다.

## 업그레이드

기존 DB와 환경변수를 그대로 사용합니다. 이미지를 불러온 뒤 사용하는 Compose 파일의 `image`를 `muni:v0.55.0`으로 지정하세요. 저장소의 예제는 `muni:v0.1.0`을 가리키므로 운영 버전에 맞춰 변경해야 합니다.

```bash
gzip -dc muni-v0.55.0.tar.gz | docker load
# compose.example.yaml의 image를 muni:v0.55.0으로 지정합니다.
docker compose -f compose.example.yaml --env-file .env up -d
```

배포 담당자는 먼저 검증 환경에서 `/healthz`·`/readyz`와 워크스페이스 ZIP 내보내기를 확인한 뒤 운영에 적용하세요. 제목이 서로 다른 평범한 워크스페이스를 내보내 **파일 이름과 `목록.md`가 이전과 한 글자도 다르지 않은지**, 그리고 제목 없는 문서가 둘 이상 있는 워크스페이스를 **두 번 내려받아 같은 이름의 파일이 같은 내용을 담는지** 확인합니다. 두 상태 점검이 실패하거나 평범한 워크스페이스의 파일 이름이 이전과 다르면 배포를 중단하고, 보관한 이전 이미지 태그로 되돌려 같은 Compose 명령을 실행합니다. 이번 변경에 따른 DB 되돌리기는 필요하지 않습니다 — 저장되는 값이 바뀌지 않으므로 되돌리기는 이미지 교체만으로 끝납니다.

배포 후 첫 주에는 워크스페이스 내보내기 관련 문의를 확인합니다. 확인 기준은 제목이 겹치지 않는 워크스페이스의 파일 이름이 0건 바뀌고, 같은 워크스페이스를 두 번 내려받았는데 파일 내용이 서로 바뀌어 있다는 문의가 더 오지 않는 것입니다. 실제 운영 적용과 사후 관찰은 배포 담당자가 수행합니다.

## 오프라인 설치

워크플로가 게시할 릴리스 asset에는 `muni:v0.55.0` Docker 이미지가 포함됩니다.

```bash
gzip -dc muni-v0.55.0.tar.gz | docker load
docker image inspect muni:v0.55.0

# compose.example.yaml의 image를 muni:v0.55.0으로 지정합니다.
cp .env.example .env
# .env의 네 값을 운영 환경에 맞게 변경합니다.
docker compose -f compose.example.yaml --env-file .env up -d
```

애플리케이션이 반드시 필요로 하는 런타임 환경변수는 다음 네 개입니다.

| 환경변수                   | 설명                                 |
| -------------------------- | ------------------------------------ |
| `POSTGRES_DSN`             | PostgreSQL 접속 문자열               |
| `BOOTSTRAP_ADMIN`          | 최초 관리자 아이디 또는 이메일       |
| `BOOTSTRAP_ADMIN_PASSWORD` | 최초 관리자 비밀번호(12자 이상)      |
| `ENCRYPTION_KEY`           | base64로 인코딩한 32-byte master key |

PDF 변환 동작만 조정하는 선택 환경변수가 두 개 있습니다.

| 환경변수               | 기본값    | 설명                                       |
| ---------------------- | --------- | ------------------------------------------ |
| `MUNI_CHROMIUM_PATH`   | 자동 탐색 | PDF Export에 사용할 headless 브라우저 경로 |
| `MUNI_PDF_CONCURRENCY` | `2`       | 동시에 실행할 Chromium 프로세스 수(1~32)   |

## 운영 정보

- 서비스 포트: `8080`
- Liveness: `/healthz`
- Readiness: `/readyz`
- REST API: `/api/v1`
- 공개 링크: `/s/{token}` — 인증 없이 열리는 유일한 화면입니다
- 문서 넘기기: `/handoff?source&claim` (받는 쪽, 세션 필요, 허용 목록의 오리진만) · `/api/v1/handoff/claims/{claim}` (내주는 쪽, 인증 없이 5분짜리 단일 사용 표로만 열립니다)
- 메일 알림: 사내 SMTP 릴레이로 1분마다 배경 발송, 기본 꺼짐 · 발송 기록 `/api/v1/admin/mail/deliveries` (관리자 인증 필요)
- OpenAPI: `/api/openapi.yaml` — 실제 라우트와 일치하며, 테스트가 그것을 지킵니다
- Prometheus: `/metrics` — 관리자 인증 필요
- MCP: `/mcp`
- Momento 프록시: `/momento/*` — 방문 추적을 Momento 로 켜 둔 동안에만 답합니다
- 지원 DB: PostgreSQL 15 이상
- 이미지에는 PDF Export용 Chromium과 Noto CJK 글꼴이 포함되어 있습니다.
