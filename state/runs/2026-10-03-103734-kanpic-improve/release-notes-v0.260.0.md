# v0.260.0

## `@midnight` 과 `@annually` 로도 자동화 일정을 적을 수 있습니다

자동화 일정은 cron 식의 다섯 필드로 적지만, 흔한 주기는 `@daily` 같은
별칭으로 짧게 적을 수 있습니다. kanpic 은 `@hourly`, `@daily`, `@weekly`,
`@monthly`, `@yearly` 다섯 개를 받았습니다.

그런데 Vixie cron 에는 같은 뜻의 별칭이 두 개 더 있습니다. `@midnight` 은
`@daily` 와 같고, `@annually` 는 `@yearly` 와 같습니다. 다른 cron 에서
`@midnight` 을 쓰던 분이 그대로 옮겨 적으면 kanpic 은 일정을 저장하지 않고
거절했습니다.

이제 두 별칭을 받습니다. 지원하는 별칭은 일곱 개입니다.

| 별칭 | 같은 다섯 필드 식 | 뜻 |
| --- | --- | --- |
| `@hourly` | `0 * * * *` | 매시 정각 |
| `@daily`, `@midnight` | `0 0 * * *` | 매일 자정 |
| `@weekly` | `0 0 * * 0` | 매주 일요일 자정 |
| `@monthly` | `0 0 1 * *` | 매월 1일 자정 |
| `@yearly`, `@annually` | `0 0 1 1 *` | 매년 1월 1일 자정 |

별칭은 대소문자를 가리지 않고(`@MIDNIGHT` 도 됩니다), 앞뒤 공백은 털어
냅니다. 전부터 받던 다섯 별칭의 실행 시각은 달라지지 않았습니다.

## 거절할 때 "다섯 필드" 대신 쓸 수 있는 별칭을 알려 드립니다

지원하지 않는 `@별칭` 을 적으면 kanpic 은 이렇게 답했습니다.

```
schedule cron must contain five fields
```

별칭을 적은 분은 다섯 필드 식을 쓴 적이 없습니다. 그래서 이 문구로는 별표나
숫자를 잘못 적었다는 뜻인지, 그 별칭이 지원되지 않는다는 뜻인지 알 수
없었습니다. `@midnight` 처럼 이번에 추가된 별칭도, 앞으로도 지원할 수 없는
`@reboot` 도, 오타인 `@dialy` 도 모두 같은 한 줄로 거절됐습니다.

이제 `@` 로 시작하는 입력이 별칭 목록에 없으면 다섯 필드 검사에 들어가기 전에
쓸 수 있는 별칭을 함께 알려 드립니다.

```
invalid automation: unknown schedule alias "@reboot", supported aliases are
@annually, @daily, @hourly, @midnight, @monthly, @weekly, @yearly
```

REST API 로 자동화를 만들거나 고칠 때도 같은 문구가 그대로 옵니다. 응답은
전과 같이 `400` 과 `invalid_automation` 이고, 달라지는 것은 `message` 의
내용뿐입니다. 별칭 목록은 늘 사전 순으로 나오므로 문구를 그대로 비교하는
도구가 있어도 순서가 흔들리지 않습니다.

다섯 필드 식을 적다가 필드 수가 틀린 경우는 전과 같은 문구로 거절됩니다.
`@` 로 시작하지 않는 입력의 처리는 아무것도 달라지지 않았습니다.

## `@reboot` 은 일부러 지원하지 않습니다

`@reboot` 은 "서버가 시작될 때 한 번" 을 뜻합니다. kanpic 의 일정은 다음 실행
시각을 미리 계산해 PostgreSQL 에 저장하고, 여러 서버 인스턴스가 그 한 시각을
나누어 처리합니다. 서버가 다시 뜨는 시점은 그 방식으로 미리 적어 둘 수 없고,
인스턴스가 여러 대라면 "재시작" 이 어느 대의 재시작인지도 정해지지 않습니다.

그래서 `@reboot` 은 받지 않고, 위의 지원 별칭 안내와 같은 문구로 거절합니다.
서버가 뜰 때 한 번 돌려야 하는 일이 있으면 수동 실행 트리거나 인바운드 웹훅을
배포 절차에서 호출하는 방식을 쓰십시오.

## 그 밖에 바뀌는 것은 없습니다

- **저장된 일정은 그대로 돕니다.** 다섯 필드 식의 해석(목록·범위·간격, 영문
  월·요일 이름, 일요일 `7`), 일·요일 필드를 합치는 규칙, 서머타임과 윤일
  처리, 일정의 시간대 설정은 손대지 않았습니다.
- **마이그레이션은 없습니다.** 스키마와 API 응답의 형태는 그대로입니다.
- 자동화를 저장할 때 kanpic 은 별칭을 펼친 다섯 필드 식을 기록합니다.
  `@midnight` 로 만든 일정은 `0 0 * * *` 로 저장됩니다.

## 확인

- 지원 별칭 일곱 개를 각각, 같은 뜻의 다섯 필드 식과 나란히 프로덕션 경로인
  `ParseSchedule`→`Next` 로 연속 4회 돌려 **실제로 반환되는 시각**이 같은지
  비교하는 표를 더했습니다. 대소문자(`@MIDNIGHT`)와 앞뒤 공백을 넣은 입력도
  같은 표에 두어 아홉 가지를 봅니다. 대역이나 모의 객체는 쓰지 않았습니다.
- 모르는 별칭 세 가지를 거절 문구까지 못 박는 표를 더했습니다. 오류가
  `ErrInvalid` 로 감싸져 있는지(API 가 이것으로 `400` 을 고릅니다), 문구에
  "five fields" 가 **없는지**, 지원 별칭 일곱 개가 **모두** 들어 있는지를
  함께 봅니다.
- 구현 중에 `@midnight`·`@annually` 두 줄만 다시 지워 돌려 보았습니다. 그
  별칭 사례만 실패하고 나머지는 그대로 통과했습니다. 새 표가 바뀐 경로를
  실제로 지난다는 뜻입니다. 지운 줄은 복구했습니다.
- 릴리즈 준비에서 `go build ./...`, `go vet ./...`,
  `go vet -tags=integration ./internal/...`, `gofmt -l ./cmd ./internal ./pkg`,
  `go test ./...`(테스트가 있는 18개 패키지 전부 통과, 실패 없음),
  `go test ./internal/automation -count=1 -run TestSchedule -v`,
  `scripts/check-release-docs.sh`, `scripts/check-commit-identities.sh` 를
  실행했습니다.
- 웹 단위 테스트·DB 통합 테스트·브라우저 E2E 는 이번 릴리즈 준비에서 다시
  돌리지 않았습니다. 변경은 Go 패키지 안쪽 입력 검증 한 곳이고 스키마와 응답
  형태는 그대로입니다. 이 셋은 태그를 올린 뒤 CI 에서 돌아갑니다.
- 사용 설명서(`docs/USER_GUIDE.md`)의 Cron 별칭 설명과 그 PDF 를 이번 변경에
  맞추어 함께 고쳤습니다.

## 올리실 때

v0.259.0 에서 올라오시는 분은 이미지를 바꿔 다시 띄우시면 됩니다.
마이그레이션이나 새 설정은 없고, 필수 환경 변수는 계속 `POSTGRES_DSN` 입니다.

전에 거절당해 적어 두지 못한 일정이 있다면 올린 뒤 다시 적어 보십시오.
이미 저장된 일정은 다시 적을 필요가 없습니다.

운영 적용은 한 인스턴스에서 `@midnight` 로 자동화를 하나 만들어 저장된 식이
`0 0 * * *` 로, 다음 실행 시각이 다음 자정으로 나오는지 확인한 뒤 확대하십시오.
받아야 할 별칭이 여전히 거절되거나 기존 일정의 다음 실행 시각이 달라지면
운영 담당자가 확대를 중단하고 v0.259.0 이미지로 되돌릴 수 있습니다. 저장되는
것은 별칭이 아니라 펼친 다섯 필드 식이므로, 되돌린 뒤에도 새로 만든 일정은
그대로 읽힙니다.

API 의 오류 `message` 문구를 그대로 비교하는 도구를 두셨다면 `@` 로 시작하는
입력에 대한 문구가 달라진 것만 확인해 두십시오. 오류 코드
(`invalid_automation`)와 상태 코드(`400`)는 그대로입니다.

## 오프라인 설치

이 릴리즈는 웹 자산과 서버 바이너리를 포함한 Docker 이미지 아카이브로 제공됩니다.

```bash
sha256sum -c kanpic-v0.260.0.tar.gz.sha256
gzip -dc kanpic-v0.260.0.tar.gz | docker load
docker run --rm -p 8080:8080 \
  -e POSTGRES_DSN='postgres://kanpic:password@postgres.internal:5432/kanpic?sslmode=require' \
  kanpic:v0.260.0
```

- 필수 런타임 환경 변수: `POSTGRES_DSN`
- Redis 및 외부 인터넷 연결: 불필요
- 관리자 초기 로그인을 보호하려면 `BOOTSTRAP_ADMIN_ID`와 `BOOTSTRAP_ADMIN_PASSWORD`를 함께 지정합니다.
- 무결성 검증 파일: `kanpic-v0.260.0.tar.gz.sha256`
