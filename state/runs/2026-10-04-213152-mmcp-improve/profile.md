# mmcp 프로필 (2026-10-04)

- 목적: Keycloak 으로 로그인한 사용자 **본인의 Mattermost 권한**으로 AI 클라이언트(Claude Code·Codex·Cursor)가 채널을 검색·요약하고 승인 후 DM 을 보내게 하는, 오프라인 사내망용 MCP 게이트웨이.
- 스택: Go 1.26 (표준 lib + pgx), PostgreSQL, React 19 + Ant Design 6 + Vite 8 + vitest 5, 단일 바이너리(프런트는 `internal/ui/dist` 로 embed), Docker 배포.
- 구조:
  - `cmd/mmcp/main.go` — 엔트리포인트, `gen-key`·`reset-admin-password` 서브커맨드 포함
  - `internal/server/` — 거의 전부. HTTP 라우팅(`server.go`), MCP over HTTP(`mcp_http.go`), 도구 정의·정책·2단계 승인(`tools.go`), Mattermost 도구 구현(`tools_mm.go` 최대 파일), 관리 API(`admin_api.go`), 개인 공간 API(`me_api.go`), DM(`dm.go`), 신원 매핑(`identity.go`), OAuth AS(`oauth.go`), Keycloak OIDC(`oidc.go`), 설정(`settings.go`), API 키(`keys.go`), 사용자(`users.go`)
  - `internal/mattermost/client.go` — Mattermost REST 클라이언트. **테스트 0개**(base 에 `client_test.go` 없음)
  - `internal/crypto` 봉투 암호화 / `internal/store` + `store/migrations` pgx 풀과 SQL / `internal/logbuf` 링 버퍼 slog 핸들러 / `internal/config` 환경변수 4개 / `internal/buildinfo` ldflags
  - `web/src/{pages/admin,pages/me,components,api}` — 관리 콘솔과 개인 공간. 테스트는 `src/utils/format.test.ts`, `src/App.test.tsx` 2개뿐
  - `docs/` Markdown 가이드 + GitHub Pages 정적 사이트(`scripts/build-docs.mjs` 생성), `scripts/dev/` 시드
- 빌드·테스트:
  - `go test ./...` — 빠름(수초). **Postgres 없으면 통합 테스트는 조용히 skip**
  - `TEST_POSTGRES_DSN=postgres://... go test -race -count=1 ./...` — CI 가 하는 진짜 전체 테스트(`internal/server` 45~50s)
  - `make lint` = `gofmt -l .` 비어 있어야 함 + `go vet ./...` + `./scripts/verify-version.sh`
  - `make test` = `go test ./...` + `cd web && node node_modules/vitest/vitest.mjs run` (Makefile:17)
  - `make build` — `scripts/build-ui.sh` 선행, 오래 걸림. `make docker` / `make package-offline` / `make verify-offline`
- 관례: 커밋 메시지는 **영어 Conventional Commits**(`fix:`, `docs:`, `ci:`), 코드 주석도 영어. 사용자에게 보이는 문자열·에러 메시지·README·docs 는 **한국어**. 설정은 환경변수 4개(`POSTGRES_DSN`, `BOOTSTRAP_ADMIN`, `BOOTSTRAP_ADMIN_PASSWORD`, `ENCRYPTION_KEY`)만이고 나머지는 관리 콘솔 → PostgreSQL(비밀값 암호화). 마이그레이션은 `internal/store/migrations` 의 SQL. **node 도구는 `.bin` 심링크가 아니라 `node node_modules/<pkg>/...` 패키지 경로로 부르는 것이 관례**(`build-ui.sh`, `Makefile`, `ci.yml` 전부) — `web/package.json:10` 만 아직 예외다.
- 위험 구역:
  - `internal/server/oauth.go`·`oidc.go`·`auth.go`·`keys.go` — OAuth 2.1 AS(DCR+PKCE), redirect URI 검증, JWT 검증. `unit_test.go` 가 `validRedirectURI`/`redirectMatches`/`safeNext` 를 못 박고 있다
  - `internal/server/identity.go` — Keycloak `sub` ↔ MM `user_id` 고정. **다른 MM 계정으로 자동 재연결 금지**가 명시적 결정사항(커밋 1144230)
  - `internal/server/tools.go approve()` — 쓰기 도구의 2단계 승인. `argsHash` 로 인자 고정, 조건부 UPDATE 로 원자화. 건드리면 승인 우회 위험
  - `internal/store/migrations` — 되돌릴 수 없음
  - `.github/workflows/release.yml`, `scripts/package-offline.sh`, `VERSION`, `scripts/verify-version.sh` — 릴리즈 경로. 버전 문자열이 README 배지·docs·compose 에 박혀 있어 `verify-version.sh` 가 일치를 강제한다. **참고: release.yml 에는 web/npm 테스트 단계가 없다**(37줄 전문 확인, 2026-10-04)
- 자주 깨지는 곳:
  - **`cd web && npm test` — 이 저장소에서 가장 자주 깨지는 한 곳.** base `b782c5f` 의 `web/package.json:10` 이 `"vitest run"` 으로 `.bin` 심링크 + 기설치를 전제해, `web/node_modules` 가 없는 워크트리에서 `sh: 1: vitest: not found` (exit 127, npm 래퍼 통과 시 exit 1). 2026-10-02·10-03(2회)·10-04 네 회차가 같은 것을 고쳤으나 **머지되지 않아 base 에 그대로 남아 있다** — 다음 회차도 같은 verify-failed 를 맞을 것이다.
  - `internal/logbuf`·`internal/mattermost`·`internal/config` 는 테스트가 없었거나 최근에야 생겼다(그 PR 들도 머지 미확인 — base 에 `logbuf_test.go`·`client_test.go` 없음). 같은 파일명으로 작업하면 중복·충돌 위험.
  - 버전 문자열 중복(README·docs·compose·VERSION)으로 `verify-version.sh` 가 lint 에서 떨어지는 것
  - 같은 값을 읽는 경로가 둘인 자리 — 사람 이름(`oidc.go koreanName` vs `mattermost/client.go DisplayName`), 역할 판정(`User.HasRole` 의 `mcp-*` 함의), 비밀번호 해싱(`main.go resetAdmin` vs `users.go bootstrapAdmin`)
- 검증 함정:
  - **로컬 `go test ./...` 가 `ok ... 0.005s` 면 통합 테스트는 돌지 않았다.** `internal/server/integration_test.go:192` 가 `TEST_POSTGRES_DSN` 없으면 `t.Skip`. 통합 테스트를 실제로 돌렸다는 증거는 `-v` 로 SKIP 0 을 보이는 것.
  - 통합 테스트는 가짜 Mattermost **HTTP 서버**(`integration_test.go:30 fakeMM`, `httptest`)에 실제 `*mattermost.Client` 를 배선한다. 새 테스트도 이 방식을 따를 것 — 손으로 만든 인터페이스 대역은 이 저장소 관례가 아니다.
  - CI 는 Go 테스트 외에 web `tsc -b` + `vite build` + `docker build` 까지 한다. 프런트를 건드리면 타입 빌드가 로컬 vitest 보다 먼저 깨진다.
  - **npm lifecycle 스크립트의 PATH 오염**: npm 은 모든 상위 디렉터리의 `node_modules/.bin` 을 PATH 앞에 붙인다. 2026-10-02~03 세 회차는 `/home/hkjang/node_modules/.bin/node` = v20.19.2 가 바레 `node` 를 가로채 jsdom 30 의 undici 가 `markAsUncloneable` 없음으로 죽는 것을 실측했다. **2026-10-04 확인: 그 경로는 이제 없다**(PATH 의 node 는 v22.23.1). 환경이 회차마다 변하므로 `"${npm_node_execpath:-node}"` 고정은 방어로 유지하되, 그 필요성을 재현 근거로 쓰지는 말 것.
  - `gofmt -l .` 이 lint 의 첫 관문이다. 새 파일을 추가하면 반드시 포맷할 것.
