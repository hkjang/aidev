# Momento 프로필 (2026-10-08)
- 기준: main@0beff4c, v0.34.61. 정찰은 코드·커밋을 변경하지 않는다.
- 목적: 사내 이벤트를 온프레미스로 수집·보존하고 제품·직원·경험·AI 사용을 분석한다.
- 스택: Go 1.26.0/toolchain 1.26.7, chi·pgx·OIDC, PostgreSQL 17; React 19.1.1·TypeScript 5.9.2·MUI 7.3.1·Vite 7.3.6·React Query 5.85.5·echarts 6.1.0; TypeScript SDK.
- 구조:
  - cmd/momento — 서버 진입점; internal/httpapi — 관리·분석·수집 API.
  - internal/service — Worker·자동화·Maintenance; internal/auth — 인증·역할 정본.
  - internal/database/migrations — embedded SQL 정본(루트 migrations와 혼동하지 않는다).
  - internal/privacy·secret·segment·insight — 개인정보·암호화·세그먼트·인사이트.
  - web/src/pages/AdminPage.tsx — 관리 화면; ?section=users|sites|retention|dimensions|networks|schemas 등.
  - web/src/pages/*Rule.ts — 순수 입력 판정; adminErrors.ts — 실패 안내 mapper.
  - web/src/components — 공용 UI; DataTable.tsx 변경은 여러 분석 화면에 영향을 준다.
  - web/test·sdk/test — node:test가 TypeScript 원본을 직접 읽는다.
  - sdk — 브라우저 수집기; docs — 사용자·관리자·설치·설계·로드맵; scripts/guide — 화면 캡처.
  - .github/workflows — ci.yml, release.yml, release-reconcile.yml. 이번 상세 검토는 ci.yml만 수행.
- 빌드·테스트:
  - make test: Go test/vet, SDK typecheck/test, web lint/test/build. 보안 검사·Go race·Docker는 포함하지 않는다.
  - Go CI: go test -race ./cmd/... ./internal/...; go vet ./cmd/... ./internal/...; go run golang.org/x/vuln/cmd/govulncheck@latest ./cmd/... ./internal/...
  - SDK: (cd sdk && npm ci && npm audit && npm run typecheck && npm test && npm run build).
  - web: (cd web && npm ci && npm audit && npm run lint && npm test && npm run build).
  - make build는 SDK/web/Go 산출물을 쓴다. Docker·DB 통합 race는 수 분 이상 걸릴 수 있다.
  - 이번 실측: (cd web && npm test) 259/259 통과, exit 0. npm ci·audit·build·Go·DB·Docker·브라우저는 미실행.
  - make verify/security-check는 존재하지 않는다. 이전 제안은 no-change였고 이번 선택 과제가 아니다.
- 관례: 한국어 conventional commit, release: vX.Y.Z; 환경변수와 DB settings로 설정; 문서는 docs/.
- 위험 구역: internal/auth·admin.go/server.go·internal/database/migrations·.github/workflows·docs/openapi.yaml. 서버가 권한과 유효성 정본이다.
- 자주 깨지는 곳:
  - verify-failed는 현재 상태와 구분한다. 이전 기록의 x/text와 source-map-js 문제는 이미 fcf17ce·97e3063으로 고쳤다; 이번에 감사 재실행은 하지 않았다.
  - Makefile:test에 보안 검사가 없다. web 변경이어도 CI의 Go 취약점·SDK/web audit를 빼먹지 않는다.
  - npm lifecycle PATH가 다른 node를 가릴 수 있어 두 package.json의 test는 npm_node_execpath를 사용한다. lint/build는 재현 없이 바꾸지 않는다.
  - 순수 .ts 값 import에는 .ts 확장자가 필요하며 TSX는 기존 확장자 없는 Vite 관례다.
  - 관리 Alert는 AdminNoticeAlert가 본문/detail을 구분한다. 모르는 코드는 원문 fallback, 500의 원인은 추측하지 않는다.
  - RetentionAdmin은 범위 helperText가 있어도 저장을 차단하지 않는다. Number(빈 문자열)가 0을 만든다는 미해결 문제가 남아 있다.
  - DimensionsAdmin의 저장 Alert는 아직 save.error.message 그대로다. saveDimension은 이름 중복 시 UPDATE하며 이름·키 규칙은 segment.PropertyKeyPattern이 정본이다.
- 검증 함정:
  - MOMENTO_TEST_POSTGRES_DSN 없으면 DB 통합 테스트 skip. DB 서비스 유무와 실제 DB 동작은 이번 미확인.
  - CI Node 24, 로컬 Node 22.23.1/npm 10.9.8. web/node_modules가 없어도 순수 테스트는 통과하지만 lint/build는 설치가 필요하다.
  - npm audit/govulncheck는 네트워크·현재 advisory에 의존한다. 과거 통과를 이번 통과로 적지 않는다.
  - make test는 Docker/offline release smoke 대체가 아니다. 이번에는 릴리즈 워크플로 세부를 재독하지 않았다.
  - README 개발 블록은 cd sdk → cd ../web 뒤 make docker를 실행하게 해 루트 경로를 잃는다. 문서 차선 후보다.
  - prettier는 CI 게이트가 아니다. 기존 안내 문구를 글자 그대로 단언하는 테스트가 많으므로 공통 문구 변경을 피한다.
  - 브라우저 하네스는 편집 뒤 beforeunload에 막힐 수 있어 사례별 새 탭을 쓴다. 실제 하네스 명령은 구현자가 기록한다.
  - docs/ADMIN_GUIDE.md의 API 키 1회 표시/해시만 보관 문장은 README·listMyKeys의 recoverable 기능과 어긋난다; 조건별 계약 검토 후 별도 수정.
  - 민감 원문을 auth/audit에 추가하지 않는다. 빌드·테스트 산출물은 커밋에서 제외한다.
