- 과제: 용량 API에서 AMD·Intel GPU 노드와 요청 수량 누락 수정 (가치 3 / 위험 2 / 작업량 M)
- 왜: `capacity.go:nodePackingAndGPU`는 allocatable과 파드 requests를 `nvidia.com/gpu`로만 세어 AMD·Intel 전용 노드는 `/admin/k8s/capacity`의 `report.gpu`에서 사라지지만, 같은 인벤토리를 읽는 노드 모니터링은 세 공급자를 이미 센다. 용량 집계 한 경로만 바로잡으면 운영자가 보유 GPU와 잔여 수량을 빠짐없이 확인할 수 있다.

근거와 구현 순서 (기준 ef9081b, v0.9.298)

범위는 SCALE-08 용량 출력의 공급자 키 누락에 한정한다. `nodePackingAndGPU`의 allocGPU가 `qtyInt(alloc["nvidia.com/gpu"])`, reqGPU가 NVIDIA 전용 `podRequestGPU` 호출임을 직접 확인했다. `node_monitoring.go:nodeGPUInventory/podGPURequests`는 nvidia/amd/intel 세 키를 이미 합산한다. `admin_k8s.go:handleK8sCapacity`는 AnalyzeCapacity 결과를 그대로 report에 넣고, `admin_ui.go`의 gpuRows는 report.gpu의 세 수량을 직접 표시하며 빈 배열이면 GPU 카드를 만들지 않는다. 브라우저 렌더링과 AMD/Intel 신규 HTTP 실패는 이번 정찰에서 실행하지 않았으므로 미확인이다.

1. [미착수] `admin_k8s_capacity_gpu_test.go`에 최소 HTTP 회귀 테스트를 추가한다. `admin_k8s_node_monitoring_test.go:TestK8sNodeAndGPUOperationsEndpoints`의 `openTestStore`→`store.NewAsyncLogger`→`NewServer(testConfig(...))`→`httptest.NewServer(server.Routes())` 배선을 사용한다. K8s JSON map은 `kube.InventoryFromObject(kind,"v1",obj)`로 변환 후 ClusterID와 고유 ID를 설정해 `UpsertK8sInventory`에 저장한다. 노드 status.allocatable 및 파드 spec.nodeName/containers.resources.requests를 넣는다. AMD/Intel/NVIDIA 각 클러스터에 같은 노드명 worker-1과 같은 파드명을 사용해 합쳐지지 않는지 확인한다. 전 함대·각 cluster_id 요청의 report.gpu를 검사하고 노드 모니터링 응답의 allocatable/requested를 비교한다. 증명: 위 좁은 go test에서 AMD·Intel 행 누락으로 신규 테스트가 실패해야 한다. 체크포인트: 자동 확인, 사람 승인 없음. 이 테스트 추가 단계의 의도된 실패를 기록한 뒤 바로 2단계로 진행한다.
2. [미착수] `nodePackingAndGPU` 안에서 로컬 키 세 개를 정의하고 노드 allocatable과 podContainers가 반환하는 각 컨테이너의 requests를 합산한다. `qtyInt`, `podContainers`, `nodeKey`, 정렬과 Idle 계산은 그대로 이용한다. 기존 비용 전용으로도 쓰이는 `podRequestGPU`와 노드 모니터링 구현은 유지한다. 단위 경계 테스트와 HTTP 회귀를 통과시킨다. 증명: 위 좁은 go test; 체크포인트: 자동 확인, 신규 HTTP 실패가 해결되지 않으면 다음 단계로 넘어가지 않는다.
