# releasedock 프로필 (2026-10-09)
- 목적: 폐쇄망 릴리즈 패키지의 검증·승인·배포·롤백과 단순 파일 업로드·명령 실행·로그 조회를 제공한다.
- 스택: Go 1.26.6(backend/runner 별도 모듈), PostgreSQL/pgx v5, React 19 + TypeScript 5.8 + MUI 7 + Vite 7/vitest 3. 확인 기준 main@da054c9, VERSION 0.5.31.
- 구조:
  - backend/internal/server/ — HTTP/API/auth/OIDC/RBAC/MCP. simple.go는 단순 실행, releases.go는 전체 릴리즈, server.go는 라우트와 스트림 한도(3/user·64/global).
  - backend/internal/localexec/ — API 서비스 계정의 직접 명령 실행. runner의 격리 executor와 다른 신뢰 경계.
  - backend/internal/store/migrations/ — 순번 SQL. runner/ — 작업 큐·Harbor·runtime·격리 executor·롤백.
  - backend/internal/webassets/ — SPA 내장. scripts/·deploy/ — 빌드·패키징·운영.
  - web/src/api/client.ts — API 호출. 쿠키 인증(credentials include), URL helper는 encodeURIComponent로 id를 인코딩한다.
  - web/src/pages/releases/ReleaseDetailPage.tsx — useReleaseLogs와 LogPanel; web/src/pages/simple/ — 배포·실행 목록·상세.
  - web/src/hooks/useAsync.ts — 요청 sequence로 이전 응답을 막지만 id 변경 시 기존 data를 지우지 않는다. 별도 비동기 요청에는 이 보호가 적용되지 않는다.
  - docs/ — architecture.md·simple-mode.md·offline-install.md·quick-deploy.md. 저장소/상위 확인 경로에 CLAUDE.md·AGENTS.md 없음, 로드맵 파일 없음. backend/runner/web/src/docs TODO·FIXME 검색 결과 없음.
- 빌드·테스트:
  - 루트 make test = DB 테스트 경고 → backend go test ./... → runner go test ./... → web npm test -- --run.
  - 웹은 cd web && npm ci 선행. cd web && npm test -- --run, npx tsc -b --noEmit, npm run build를 별도로 실행한다. npm test만으로 타입 검사가 되지 않는다.
  - 정찰 기준선: 산출물 assets/web의 무수정 복사본에서 npm ci와 tsc -b --noEmit 통과. 전체 웹 테스트 149건/13파일 통과(87.02초, Vitest 3.2.7). build/Go/DB 테스트는 이번 정찰에서 미실행.
  - make build/package는 scripts/build.sh·package-release.sh 호출. 전체 소요 시간은 이번에 미측정.
- 관례: 영어 fix:/feat:/test:/chore: 커밋, 한국어 운영 문서·UI. 관리자 API+DB 설정과 최소 bootstrap 환경변수. VERSION은 릴리즈 담당이 변경한다. web/dist 등 산출물 커밋 금지.
- 위험 구역: auth/OIDC/RBAC/session, store/migrations, .github/workflows/release.yml. 단순 명령은 API 계정 권한으로 실행되어 전체 모드 executor와 동일한 격리라고 설명하면 안 된다.
- 현재 로그 계약:
  - 두 모드 모두 /logs(JSON 또는 ?format=text)와 /logs/stream을 제공한다. items[{id,stream,message,createdAt}], lastId, hasMore, after/limit 계약을 공유하며 빈 페이지는 after를 유지한다.
  - 전체 모드 저장 로그 다운로드는 v0.5.31에 웹까지 연결됐다. 로그가 비거나 끊겨도 LogPanel의 로그 내려받기는 활성이다. 이전 프로필의 “백엔드만 있음”은 폐기한다.
  - releases.go:writeReleaseLogDownload는 simple.go의 logRowScanner/writeSimpleRunLog/runLogDisposition/simpleRunLogTruncatedNotice를 재사용한다. 이름에 simple이 있어도 공용 동작이다.
  - 실시간 표시 상한은 전체 모드·단순 배포 4999줄. SimpleRunDetailPage 저장 로그는 MAX_LOG_PAGES=50, 화면 한도 초과 시 다운로드를 안내한다.
- 자주 깨지는 곳:
  - effect 의존성에 매 렌더 새 객체를 넣으면 재연결 폭주와 사용자당 3스트림 한도 초과가 난다.
  - 전체 모드 리셋 [releaseId, enabled]와 재연결 [releaseId, enabled, streamAttempt]의 역할을 섞으면 재연결 때 로그·안내가 사라진다.
  - setLogs updater 안에서 행 sequence를 읽으면 한 배치의 React key가 중복된다. 이벤트 시점에 읽는다.
  - 전체 모드 정상 end는 {}, timeout은 reason=max_duration; 단순 모드 정상 end는 status를 포함한다. 모드별 종료 계약을 섞지 않는다.
  - 이번 발견: SimpleRunDetailPage는 id 변경에도 로컬 상태가 유지되고 loadStoredLogs에 이전 요청 방어가 없다. id-keyed 내부 컴포넌트로 격리하는 과제는 아직 미구현이다.
  - 실행 생성 id는 simple.go→secure.NewID()의 UUID형 hex+하이픈. 형제 링크의 인코딩 차이는 현재 런 id 계약상 재현 가능한 결함이 아니다.
  - 단순 화면 권한은 배포 simple.deploy / 실행 상세 simple.read로 나뉜다. 배포→실행 상세 링크에는 canReadRuns 가드를 유지한다.
  - 사람이 반려한 접근(HELD enum 등)은 재시도하지 않는다. 반려 상세는 제공 기록 외 미확인.
