release: carry release markers to v0.2.50

v0.2.50 ships two fixes already merged to main. Channel bookmark reorder now
rewrites a channel's positions densely instead of writing only the row it was
asked to move, and the Go toolchain and `golang.org/x/net` are raised to
versions `govulncheck` accepts. There is no schema change, no migration, no new
route, no new error id and no web source change in either fix. One production
Go file changes, by 82 added and 12 removed lines including comments, alongside
the build and module pins and the `bookmarks` package's first test file.

`Reorder` in `bookmarks/service.go` carried a doc comment promising a dense,
conflict-free re-shuffle of the channel's bookmarks and a body that was a
single `UPDATE` of the target row's `sort_order`. The comment described a
"simple two-shot update"; the second shot was never written. Two or more
bookmarks in one channel were therefore left sharing a `sort_order`, and `List`
orders by `sort_order ASC, create_at ASC`, so the tie fell to the older row:
a drag landed one slot away from its target, or produced no visible movement at
all. Nothing read a corrupted value — the rows simply never stopped colliding,
and the old comment's own excuse for the shortcut, that a race only means two
clients "see slightly different orders for ~100ms", described a transient
disagreement the code could not actually produce. The duplicates persisted.

`Reorder` now opens a transaction, reads the channel's active rows in `List`'s
own order, moves the target inside that slice, and rewrites `0..n-1` in a
single `unnest` `UPDATE` scoped to the channel's non-deleted rows, which is the
idiom `sidebar.UpdateOrder` already uses. The read that decides the sequence
and the write that applies it share the transaction, so two concurrent reorders
cannot interleave back into the duplicate positions the change exists to
remove. Positions are 0-based to match Mattermost's endpoint, while `Create`
still appends with `COALESCE(MAX(sort_order),0)+1`; a channel that has never
been reordered therefore starts at 1 and a reordered one starts at 0. `List`
exposes only relative order, so that asymmetry is invisible to clients, and it
is recorded in the doc comment rather than smoothed over. An out-of-range
position still clamps to either end instead of erroring, keeping the response
contract callers already have. The handler, `Create`, `List` and `Patch` are
untouched, and the channel and `delete_at` filters on the rewrite keep another
channel's rows and soft-deleted rows out of it.

That fix also brings the `bookmarks` package its first tests, 371 lines on the
`sidebar` package's isolated-schema PostgreSQL harness. They are database-backed
and skip when `MOYRO_TEST_POSTGRES_DSN` is unset, so the run recorded below was
pointed at a real PostgreSQL instance to make them execute.

The toolchain half clears a release gate rather than changing any product
behavior. `govulncheck`, which `release.yml` runs against `server`, reported
reachable advisories while Go was pinned at 1.27.0 and `golang.org/x/net` at
v0.58.0. `Dockerfile`'s `server-build` stage moves to `golang:1.27.2-alpine` at
its matching digest, `server/go.mod`'s `go` directive to 1.27.2, and the module
graph to `x/crypto` v0.57.0, `x/net` v0.60.0 and the indirect `x/mod` v0.41.0,
`x/sync` v0.23.0, `x/sys` v0.48.0 and `x/text` v0.42.0. All of these are
patch and minor bumps within one module family; no direct dependency is added,
removed or re-ranged, and `GOTOOLCHAIN=local` in that stage means the image is
built by the pinned toolchain rather than by one downloaded at build time.
