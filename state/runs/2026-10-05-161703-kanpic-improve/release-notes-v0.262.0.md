# v0.262.0

## `IMPORTDATA` 가 깨진 글자가 든 표 대신 읽을 수 없는 파일이라고 알립니다

구분자로 나뉜 같은 파일이 kanpic 에 들어오는 문은 두 개입니다. 편집기에서
파일을 올려 가져오는 길과, 칸에 적은 `IMPORTDATA` 수식이 주소에서 받아 오는
길입니다. 두 문은 **같은 읽기 규칙**을 나눠 씁니다 — 구분자를 고르는 자,
수와 참을 알아보는 자, 인코딩을 밝히는 표시를 떼는 자가 하나씩뿐입니다. 같은
파일은 어느 문으로 들어와도 같은 표가 되어야 하기 때문입니다.

그런데 "UTF-8 이 아니면 거절한다" 는 검사만은 업로드 쪽에만 있었습니다.
그래서 어느 인코딩인지 **밝히지 않는** CP949·latin-1 본문이 `IMPORTDATA`
로는 그대로 통과했고, UTF-8 이 아닌 바이트가 칸 값 자체가 됐습니다. 같은
파일을 올려 가져오면 UTF-8 이 아니라는 이유로 거절되는데, 주소로 받아 오면
표가 나왔습니다.

CP949 로 적힌 `이름,메모` 두 글자를 받으면 칸에는 이런 값이 들어갔습니다.

```
rows=2 cols=2
values=["\xc0̸\xa7", "\xb8\u07b8\xf0", 1, 2]
```

사용자가 보는 것은 "읽을 수 없는 파일" 이 아니라 **"깨진 글자가 든 표"**
였습니다. 깨진 글자는 수식으로 견주어도 맞지 않고, 내보낸 CSV·XLSX 를 받는
쪽에서도 글자로 읽히지 않습니다. 틀린 줄 모르고 지나가기 쉬운 쪽입니다.

이제 `IMPORTDATA` 는 표시를 떼고도 UTF-8 이 아닌 본문을 업로드 문과 같이
거절합니다. 오류는 같은 함수가 CSV 를 읽지 못할 때와 **같은 코드** `#VALUE!`
이고, 문구는 `CSV 가 UTF-8 이 아닙니다` 입니다.

## 인코딩을 추측하지는 않습니다

CP949 로 보이는 본문을 CP949 로 **옮겨 읽지는** 않습니다. 인코딩을 밝히는
표시가 없으면 추측하지 않는다는 것이 읽기 규칙의 약속이고, 두 문 가운데
한쪽만 추측하기 시작하면 같은 파일이 다시 문에 따라 다르게 읽힙니다. 받는
쪽에서 할 일은 파일을 UTF-8 로 저장해 올리시거나, 인코딩을 밝히는 표시를
붙여 내려주도록 주소 쪽을 고치시는 것입니다.

표시가 있는 본문은 전과 똑같이 읽힙니다. UTF-8 표시(BOM)는 떼고 읽고,
UTF-16 LE·BE 표시가 붙은 본문은 UTF-8 로 옮겨 읽습니다.

## 사용하시는 분께 달라지는 점

- 전에 깨진 글자가 들어오던 자리는 이제 `#VALUE!` 가 됩니다. 수식을 적은
  칸 하나에서 멈추고, 그 수식이 채우던 표는 만들어지지 않습니다.
- **이미 칸에 들어간 깨진 값을 거슬러 고치지는 않습니다.** 그 수식이 다시
  계산될 때 `#VALUE!` 로 바뀝니다. 지난 값이 어느 인코딩이었는지는 어디에도
  남아 있지 않아 글자로 되살릴 수 없습니다.
- 거절은 성공한 응답과 같이 `external.cache_seconds` 동안(기본값 5분) 캐시에
  남습니다. 주소 쪽 파일을 UTF-8 로 고치신 뒤 그 시간까지는 전의 거절이
  그대로 답일 수 있습니다. 원격 장애를 최대 30초만 캐시하는 규칙은 주소에
  닿지 못한 경우에만 쓰이고, 이번 거절은 본문을 받아 **읽는 자리**에서
  나므로 거기에 해당하지 않습니다. 전부터 `#NUM!`(칸 수 상한) 같은 읽기
  단계의 거절이 그렇게 동작했고, 이번에 달라진 것은 없습니다.

## 그 밖에 바뀌는 것은 없습니다

- **마이그레이션도, 새 설정도 없습니다.** `external.enabled`,
  `external.allowed_hosts`, `external.cache_seconds`, 크기 상한, 시간 제한,
  사설 주소·리다이렉트 차단은 모두 그대로입니다.
- `WEBSERVICE` 는 달라지지 않았습니다. 받은 본문을 글자 하나로 돌려주는
  함수이고, 표로 자르지 않으므로 이 검사를 지나지 않습니다.
- 올려 가져오기 쪽은 한 줄도 손대지 않았습니다. 전부터 같은 바이트를
  거절해 온 쪽이 기준이었고, 이번 변경은 `IMPORTDATA` 를 그 기준에
  맞춘 것입니다.
- 이미 올바르게 읽히던 본문의 읽는 방법은 그대로입니다. 구분자 자동 판정,
  우편번호 `00123` 처럼 앞자리 0 이 붙은 글자를 수로 바꾸지 않는 규칙,
  참·거짓 판정, 칸 수 상한이 전과 같습니다.
- 관리자 가이드의 외부 호출 오류 코드 표(`docs/ADMIN_GUIDE.md`)는 이번에
  고치지 않았습니다. 이번 거절이 같은 함수의 기존 읽기 실패와 같은
  `#VALUE!` 라서 안내가 더 어긋나지는 않습니다.

## 확인

- **손으로 만든 대역 없이** 같은 바이트열 하나를 두 문의 실제 입구에 넣는
  검사를 더했습니다. 원격 쪽은 `httptest` 서버가 그 바이트를 내려주고
  프로덕션 `Fetcher.Resolve` 가 받습니다(오류 코드가 `#VALUE!` 인지, 거절한
  뒤 표가 남지 않는지 — 행 0·열 0·값 0개). 업로드 쪽은 프로덕션 가져오기가
  같은 바이트를 거절하는지 봅니다. 한쪽만 거절하면 검사가 실패합니다.
- 고치기 전에는 이 검사가 다음과 같이 실패했습니다.

  ```
  IMPORTDATA 가 UTF-8 이 아닌 본문으로 표를 냈다:
  rows=2 cols=2 values=[]interface {}{"\xc0̸\xa7", "\xb8\u07b8\xf0", 1, 2}
  ```

  고친 뒤 통과하고, 더한 검사 세 줄만 지우면 **정확히 이 검사만** 같은
  출력으로 다시 실패합니다. 새 검사가 바뀐 경로를 실제로 지난다는 뜻입니다.
- UTF-16 표시가 붙은 본문, 수·참거짓 판정, 구분자 자동 판정을 보던 기존
  검사는 모두 그대로 통과합니다.
- 릴리즈 준비에서 `go build ./...`, `go vet ./...`,
  `go vet -tags=integration ./internal/...`, `gofmt -l ./cmd ./internal ./pkg`,
  `go test ./...`(테스트가 있는 19개 패키지 전부 통과, 실패 없음),
  `go test ./internal/external ./internal/importexport ./internal/delimited
  -count=1`, `go test ./internal/external -race -count=1`,
  `scripts/check-release-docs.sh`, `scripts/check-commit-identities.sh` 를
  실행했습니다.
- 웹 단위 테스트·DB 통합 테스트·브라우저 E2E 는 이번 릴리즈 준비에서 다시
  돌리지 않았습니다. 변경은 Go 패키지 한 파일에서 받은 본문을 표로 자르기
  전에 거절할지 보는 세 줄이고, SQL·스키마·화면 코드는 손대지 않았습니다.
  이 셋은 태그를 올린 뒤 CI 에서 돌아갑니다.

## 올리실 때

v0.261.0 에서 올라오시는 분은 이미지를 바꿔 다시 띄우시면 됩니다.
마이그레이션이나 새 설정은 없고, 필수 환경 변수는 계속 `POSTGRES_DSN`
입니다.

`IMPORTDATA` 로 주소에서 표를 받아 쓰는 워크북을 두셨다면 올리기 전에 한 번
보십시오. 받아 오는 파일이 UTF-8 이 아니었다면 올린 뒤 그 칸은 `#VALUE!` 가
됩니다. **지금 화면에 깨진 글자가 보이는 워크북이 바로 그 자리입니다** —
올린 뒤 오류로 바뀌는 것이 아니라, 전부터 틀린 값을 담고 있었다는 뜻입니다.

운영 적용은 먼저 한 인스턴스에서 확인한 뒤 확대하십시오. 올린 뒤 UTF-8 로
내려주는 주소를 쓰는 `IMPORTDATA` 수식이 전과 같은 표를 내는지 보십시오.
전에 잘 읽히던 본문이 `#VALUE!` 로 거절되기 시작하면 운영 담당자가 확대를
중단하고 v0.261.0 이미지로 되돌릴 수 있습니다. 스키마도 설정도 바뀌지
않으므로 되돌린 뒤의 동작은 전과 같습니다.

## 오프라인 설치

이 릴리즈는 웹 자산과 서버 바이너리를 포함한 Docker 이미지 아카이브로 제공됩니다.

```bash
sha256sum -c kanpic-v0.262.0.tar.gz.sha256
gzip -dc kanpic-v0.262.0.tar.gz | docker load
docker run --rm -p 8080:8080 \
  -e POSTGRES_DSN='postgres://kanpic:password@postgres.internal:5432/kanpic?sslmode=require' \
  kanpic:v0.262.0
```

- 필수 런타임 환경 변수: `POSTGRES_DSN`
- Redis 및 외부 인터넷 연결: 불필요
- 관리자 초기 로그인을 보호하려면 `BOOTSTRAP_ADMIN_ID`와 `BOOTSTRAP_ADMIN_PASSWORD`를 함께 지정합니다.
- 무결성 검증 파일: `kanpic-v0.262.0.tar.gz.sha256`
