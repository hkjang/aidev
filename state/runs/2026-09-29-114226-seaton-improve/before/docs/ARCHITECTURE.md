# SeatOn 아키텍처

```text
Browser / MCP client
        │ same-origin HTTPS, OIDC PKCE, personal key
        ▼
┌────────────────────────────────────────────┐
│ SeatOn single container                    │
│ Go HTTP API + embedded React/MUI UI        │
│ RBAC · audit · rules · MCP                 │
│ PDF rasterizer (first page)                │
│ ┌────────────────────────────────────────┐ │
│ │ 좌석 인식 엔진 (설정으로 선택)          │ │
│ │  cv     : offline-cv-v2 (기본, 내장)   │ │
│ │  vlm    : 사내 비전 모델 판독           │ │
│ │  hybrid : 두 결과를 IoU 교차 검증       │ │
│ └───────────────┬────────────────────────┘ │
└────────┬────────┼──────────────────────────┘
         │        │ OpenAI 호환 /chat/completions (선택)
         │        ▼
         │   사내 VLM 추론 서버 (vLLM/SGLang/Ollama, Qwen2.5-VL 등)
         │ POSTGRES_DSN
         ▼
   PostgreSQL 14+

Persistent pair: PostgreSQL backup + /var/lib/seaton/master.key
```

도면 파일도 PostgreSQL에 보관하여 별도 오브젝트 스토리지가 필요 없다. Keycloak, 인사 API, VLM 추론 서버는 모두 관리자 설정으로 사내 엔드포인트를 지정한다. 기본값은 `cv`이므로 아무것도 설정하지 않으면 런타임 외부 통신이 전혀 없다. 설치별 마스터 키는 Keycloak Client Secret, 인사 API Token, VLM API 키 등 비밀 설정을 AES-256-GCM으로 암호화한다.

## 좌석 좌표계

좌석은 도면 대비 `0..1` 비율 값으로 저장한다. 좌석맵 SVG는 `viewBox`를 도면 원본 픽셀 비율과 동일하게 잡아 비율 좌표가 도면 픽셀에 1:1 대응하며, 포인터 입력은 `getScreenCTM()` 역변환으로 같은 좌표계에 매핑한다. 따라서 줌·레터박스·도면 비율과 무관하게 화면과 저장값이 일치한다. PDF는 업로드 시 첫 페이지를 150 DPI PNG로 래스터화해 보관하고, 좌석 오버레이와 분석이 **같은 래스터**를 기준으로 삼는다.

도면별 격자 보정값(`floor_maps.grid`)은 스냅과 일괄 정렬이 임의의 고정 간격 대신 실제 책상 열 간격을 따르게 한다. 분석이 반복 주기를 찾아내면 보정값이 비어 있는 도면에 자동으로 채운다.

## 좌석 인식 엔진

세 엔진 모두 동일한 후보 구조(비율 좌표 + 신뢰도 + 근거)를 산출하므로 이후 검토·편집·배정 흐름은 완전히 같다.

- `offline-cv-v2`: Otsu 이진화 → 벽·치수선 등 긴 획 제거 → 팽창 후 8방향 연결 요소 → 중앙값 크기 필터 → 후보 중심의 반복 주기로 격자 복원 → 격자 적합도 기반 신뢰도. 격자에서 빠진 자리는 도면에 잉크가 있는 곳만 보간한다. 결정적이고 외부 통신이 없다.
- VLM: 다운스케일한 도면(필요하면 겹치는 타일로 분할)을 OpenAI 호환 엔드포인트에 보내 정규화 경계 상자를 받는다. 모델이 픽셀이나 0~1000 좌표로 답하거나 `[x1,y1,x2,y2]`와 `[x,y,w,h]`를 혼용해도 후보 해석을 모두 적용해 가장 정합한 것을 고른다.
- 하이브리드: 두 결과를 IoU로 짝지어 기하학은 실제 잉크에서 나온 CV 상자를 쓰고, 합의 여부로 신뢰도를 재산정한다.

보정되지 않은 모델 확신도가 자동 승인으로 이어지지 않도록, VLM이 단독으로 찾은 좌석은 신뢰도 상한을 두어 항상 검토 큐에 남긴다. 좌석의 `metadata.source`(`cv`, `vlm`, `cv+vlm`, `grid-fill`)로 근거를 추적한다.

## 분석 작업 수명주기

VLM 판독은 수십 초에서 수 분이 걸리므로 분석은 비동기 잡이다. `POST /floor-maps/{id}/analyze`는 `analysis_jobs`에 잡을 넣고 `202`를 즉시 반환하며, 실제 작업은 요청 컨텍스트와 분리된(`context.WithoutCancel`) 고루틴에서 최대 30분 예산으로 돌아간다. 같은 도면의 동시 분석은 인메모리 점유와 도면 상태로 막고, 서비스 재시작으로 끊긴 잡은 다음 기동 시 실패로 정리하며 도면 상태도 복구한다. VLM 경로가 실패하면 어떤 오류든 CV 결과로 물러나 분석 자체는 완료되고, 사용자에게는 경고 목록으로 사실을 알린다.
