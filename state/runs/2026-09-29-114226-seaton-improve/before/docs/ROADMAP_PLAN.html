1. 비전 및 발전 마일스톤 개요

SeatOn 플랫폼은 오프라인 도면 판독과 비율 좌표 좌석 관리를 기반으로, 사내 AI 에이전트와 대화형으로 오피스 공간을 추천·배정하는 Autonomous Smart Office Platform으로 진화합니다. 모든 단계에서 에어갭 환경에서 기능이 완결되어야 한다는 원칙을 유지합니다. 외부 모델이나 클라우드 서비스는 선택 사항이며, 설정하지 않아도 제품이 온전히 동작합니다.

2. Phase별 세부 기술 명세 및 추진 전략

2.1 Phase 1: v1.0.0 오프라인 스마트 좌석 플랫폼 구축 (완료)

  • 도면 CV & SVG 엔진: PNG/JPG/PDF 도면 오프라인 후보 파싱, 비율 좌표 SVG 좌석 편집기.
  • 이상 좌석 감지: 미배정, 퇴직자 점유, 조직 구역 불일치, 저신뢰 좌석 자동 감지.
  • Keycloak OIDC & Break Glass: PKCE SSO 연동 및 3대 환경변수 부트스트랩.
  • Streamable HTTP MCP: AI 에이전트를 위한 5개 ACL-aware MCP Tools 탑재.

2.2 Phase 1.5: v1.1.0 좌석 매핑 정확도와 판독 엔진 선택 (완료)

Phase 1의 가장 큰 실사용 마찰은 인식률이 아니라 좌석이 도면과 어긋나는 문제였습니다. 좌표계를 도면 원본 비율에 정렬하고, 판독 엔진을 교체 가능한 구조로 바꿨습니다.

  • 좌표계 정합: 좌석맵 좌표계를 도면 픽셀 비율에 맞춰 비율 좌표가 1:1 대응하도록 수정. 이전에는 10:7 고정이어서 세로 도면에서 좌석이 도면 너비의 40%까지 밀렸습니다. 포인터 입력도 같은 좌표계로 변환해 드래그 정밀도를 확보했습니다.
  • PDF 좌석 오버레이: PDF 첫 페이지를 래스터화해 보관하고, 좌석 오버레이와 판독이 같은 이미지를 기준으로 동작하도록 통일.
  • 도면별 격자 보정: 도면마다 책상 열 간격을 저장해 스냅과 일괄 정렬이 실제 배치를 따르게 함. 관리자 보정값과 자동 추론값을 출처로 구분해, 잘못 추론된 격자가 영구히 남지 않도록 처리.
  • 판독 엔진 재설계(offline-cv-v2): Otsu 이진화, 벽·치수선 제거, 크기 군집 중 격자 정합도가 가장 높은 묶음 선택. 벽선이 관통하는 책상과 저대비 스캔 도면에서 이전 구현은 후보를 전혀 만들지 못했습니다.
  • 선택형 비전 모델(VLM) 판독: OpenAI 호환 사내 추론 서버로 Qwen2.5-VL 계열을 호출하는 경로 추가. 모델이 좌표계와 상자 형식을 임의로 바꿔도 자동 판별합니다.
  • 교차 검증(하이브리드): CV의 기하 정확도와 VLM의 의미 이해를 IoU로 교차 검증하고, 보정되지 않은 모델 확신도가 자동 승인으로 이어지지 않도록 신뢰도 상한을 둠.
  • 비동기 분석 작업: 판독을 백그라운드 잡으로 분리해 장시간 추론이 HTTP 응답 제한에 걸리지 않게 하고, 중단된 작업을 자동 복구.

2.3 Phase 1.6: v1.2.0 좌석맵 탐색과 관리자 화면 정비 (완료)

판독 정확도를 확보한 뒤 남은 마찰은 큰 도면을 다루는 방법과 화면 전반의 일관성이었습니다.

  • 좌석맵 탐색: 스크롤 확대를 뷰포트 기반 캔버스로 바꿔 화면 이동과 커서 기준 확대를 지원합니다. 검색으로 찾은 좌석은 중앙으로 이동하며 확대되고, 미니맵이 현재 영역을 보여줍니다.
  • 조직 시각화: 좌석 색상을 상태 또는 조직 기준으로 전환하고, 조직 구역을 배경으로 표시합니다. 좌석 API가 착석자의 소속을 함께 내려주어 구역 불일치를 화면에서 바로 구분합니다.
  • 좌석 렌더 분리: 좌석을 개별 memo 단위로 나눠 화면 이동·확대가 좌석 목록을 다시 그리지 않습니다.
  • 감사 이력 조회: 검색·방식·기간 필터와 CSV 내보내기를 더했습니다. 기간 경계는 사용자 시간대로 계산하고, 건수 집계는 상한에서 끊어 이력이 쌓여도 전체 스캔이 되지 않습니다.
  • 화면 일관성: 모든 관리자 화면에 로딩·빈 상태를 공통 컴포넌트로 적용해 "아직 못 불러왔다"와 "데이터가 없다"를 구분합니다.
  • 세션 만료 안내: 세션이 끊기면 한 곳에서 정리해 로그인으로 안내합니다.
  • 집계 비용 절감: 상단 배지 전용 집계를 분리하고 대시보드 집계를 제한된 동시성으로 실행합니다.

2.4 Phase 1.7: v1.3.0 화면 검증 체계와 도면 버전 수명주기 (완료)

타입 검사와 단위 테스트는 화면이 실제로 어떻게 그려지는지 보지 못합니다. v1.2.0까지의 결함 중 팬·확대가 통째로 죽은 것, 좌석 클릭이 삼켜진 것, 휠 확대가 조용히 사라진 것은 모두 그 사각지대에서 나왔습니다. v1.3.0은 그 사각지대를 없애고, 없애자마자 드러난 결함들을 함께 정리한 릴리즈입니다.

  • 브라우저 화면 검증: 실행 중인 SeatOn을 Playwright로 열어 확인하는 검증 28건을 CI에 붙였습니다. PostgreSQL과 방금 만든 이미지를 띄우고, 빈 데이터베이스에 사업장·층·도면·좌석·직원을 시드한 뒤(좌석은 실제 CV 분석으로 생성) 로그인부터 배치 편집까지 밟습니다. 검증 항목은 과거에 실제로 났던 결함을 따라가며, 주요 항목은 결함을 되살려 놓고 검증이 실패하는 것까지 확인했습니다.
  • 좌석 라벨 가독성: 좌석 번호에서 도면 공통 접두사를 떼어 좁은 좌석 안에서도 구분되는 뒷자리가 남게 했습니다. 라벨 크기는 확대 배율에 반비례시키되 배율보다 느리게 키워, 확대해도 글자가 좌석을 뒤덮지 않고 파묻히지도 않습니다. 배율은 단계로 뭉쳐 휠을 굴릴 때마다 좌석 전체를 다시 그리지 않습니다.
  • 조작 패널 배치: 색상·필터와 배치 편집 도구를 도면 위 떠 있는 패널에서 상단 툴바로 옮겼습니다. 이전에는 패널이 도면 좌상단 좌석과 확대 배율 표시를 가렸습니다.
  • 노트북 화면 대응: 검색·도면·상세 세 칸의 최소 폭 합이 1280px 화면을 넘겨 상세 패널이 잘려 나갔습니다. 도면 칸이 줄어들 수 있게 하고 양옆은 넓은 화면에서만 넉넉하게 줍니다.
  • 첫 실행 안내: 준비 단계가 아직 하지 않은 일까지 체크 표시로 보여 주던 것을, 끝난 단계·지금 할 단계·대기로 구분했습니다.
  • 연결 실패와 설정 오류 구분: 서버에 닿지 못했을 때 "로그인 방식이 없다"고 안내하며 입력란까지 감추던 것을, 연결 안내와 다시 시도로 바꿨습니다.
  • 키보드 접근: 좌석은 도면 위 그림이라 탭 순서에 들어오지 않으므로, 검색 결과 목록이 키보드로 좌석을 고르는 길입니다. 그 목록에 초점과 Enter·Space, 화면 낭독기용 레이블을 붙였습니다.
  • 도면 버전 수명주기: 잘못 올린 도면 버전을 지울 수 있게 했습니다. 게시 중인 도면과, 배정·변경 이력이 걸린 좌석이 있는 도면은 거절합니다. 좌석이 사라지면 변경 이력의 좌석 참조가 비어 감사 기록을 잃기 때문입니다.
  • 입력 마찰 제거: 고를 것이 하나뿐인 목록은 미리 골라 둡니다.

2.5 Phase 1.8: v1.4.0 키보드 탐색과 일괄 배정, 대형 도면 확인 (완료)

v1.3.0에서 만든 화면 검증으로 남은 사각지대 세 곳을 차례로 확인하고 메웠습니다.

  • 도면 좌석 키보드 탐색: 좌석은 도면 위 그림이라 탭 순서에 들어오지 않아, 도면을 훑어보는 것은 마우스로만 가능했습니다. 좌석 하나만 탭에 넣고 그 안에서는 방향키로 옮겨 다닙니다(roving tabindex). 도면 좌석은 표가 아니라 흩어진 사각형이므로, 줄을 벗어난 정도에 벌점을 주고 가장 가까운 좌석을 고릅니다. 초점이 화면 밖으로 나가면 화면이 따라가고, 이미 보이는 좌석이면 움직이지 않습니다.
  • 좌석 일괄 배정 화면: 문서에는 "사번과 좌석 번호 두 열로 일괄 배정"이 적혀 있었지만 화면에는 없었고, API 키로 직접 호출해야만 닿을 수 있었습니다. 화면을 붙이고, 반영되지 않은 행은 행 번호와 사유를 함께 보여 줍니다. 서버에서는 좌석 번호로 좌석을 찾을 때 게시된 도면으로 좁혔습니다. 좌석 번호는 도면마다 따로 매겨지므로, 검토 중인 새 버전이 있으면 그쪽 좌석에 배정되어 좌석맵에는 보이지 않았습니다.
  • 대형 도면 확인: 25열 × 20행 500석 도면에서 30석 도면과 화면 성능이 사실상 같음을 확인했습니다(첫 렌더 24ms, 화면 이동 중 프레임 간격 중앙값 16.7ms로 60fps 유지). 화면 이동이 좌석을 다시 그리지 않고 viewBox 만 바꾸기 때문이며, 그 특성이 유지되는지 검증이 확인합니다.
  • 도면 게시 내림: 게시 중인 도면은 지울 수 없는데 그 층의 유일한 버전이면 밀어낼 다른 버전도 없어, v1.3.0의 삭제 기능이 닿지 못하는 경우가 있었습니다. 게시를 내리면 좌석맵에서 사라지고 좌석과 이력은 남으므로, 그 뒤에 지울지 다시 게시할지 고를 수 있습니다.

2.6 Phase 2: v1.5.0 멀티 사옥 도면 동기화 & 실시간 센서 연동 (2026 Q3)

  • 다중 건물/사옥 통합 뷰: 본사, 지사, R&D 센터 멀티 사옥 레이아웃 통합 관리.
  • IoT 모션 센서 연동: 좌석 재실 센서 데이터 실시간 바인딩.
  • 도면 버전 간 좌석 이관: 새 도면 버전을 올릴 때 이전 버전의 좌석과 배정을 좌표 기준으로 자동 승계.

2.7 Phase 3: v2.0.0 AI 자율 좌석 코파일럿 (2026 Q4)

  • NL-to-Space Action (MCP 2.0): "10층 개발팀 구역 근처에 빈 좌석 찾아 배정해줘" 같은 요청을 권한 검증 후 자동 처리.
  • 판독 품질 피드백 루프: 관리자가 교정한 좌석을 판독 품질 지표로 축적해 엔진·프롬프트 선택을 데이터로 결정.

4. 문서 산출물 관리

docs/*.md 가 단일 원본이며, 배포용 HTML과 PDF는 scripts/build-docs.py 로 생성합니다. 문서를 고칠 때는 Markdown만 수정한 뒤 스크립트를 다시 실행하십시오.

python3 scripts/build-docs.py            # 전체 재생성
python3 scripts/build-docs.py ADMIN_GUIDE # 특정 문서만
이 문서는 docs/ROADMAP_PLAN.md 에서 scripts/build-docs.py 로 생성되었습니다. 내용 수정은 Markdown 원본에서 하십시오.
