# seaton 프로필 (2026-09-29)
- 목적: 사무실 도면에 좌석을 편집하고 직원을 배정·검색하는 오프라인 우선 서비스.
- 기준: main@6ae2417, v1.4.12 문서. 직원 조직 필터까지 머지됨.
- 스택: Go 모듈 1.24.0, chi v5·pgx v5·go-oidc v3·excelize, PostgreSQL 14+(CI 16-alpine), React 19·TS·MUI 7·Vite 7·Vitest 3·React Router 7·Playwright.
- 구조:
  - cmd/seaton/: 서버 진입점과 프런트 임베드(이 구조는 이전 프로필 계승).
  - internal/app/: HTTP 핸들러, auth.go 인증/사용자, employees.go 조직/직원/가져오기, seats.go 배정, server.go 라우터.
  - internal/database/: pgx와 시작 시 적용 migrations.sql(이전 프로필 계승).
  - internal/platform/: 환경/키 및 config_test.go·crypto_test.go 존재.
  - internal/tracking/: nonce·스니펫·CSP.
  - web/src/pages/: 화면, lib/: 값 규칙과 짝 테스트 11개 파일.
  - web/e2e/: 실서버 Playwright, helpers.ts 로그인/복구, global-setup.ts→seed.mjs.
  - docs/: Markdown 정본과 생성 HTML/PDF, scripts/build-docs.py 문서 생성.
- 빌드·테스트: go test ./... (이번 정찰 통과), go vet ./..., gofmt -l .
- 빌드·테스트: cd web && npm ci && npm test && npm run lint && npm run build. lint=tsc -b. 이 체크아웃 node_modules 없어 프런트는 이번 미실행; 이전 회차 150건 통과 기록.
- 빌드·테스트: docker build --build-arg VERSION=e2e -t seaton:e2e . 후 별도 PostgreSQL+앱 기동. web에서 E2E_BASE_URL=http://127.0.0.1:8080 E2E_USERNAME=admin E2E_PASSWORD=ci-e2e-password-123 npx playwright test (준비 수 분 이상).
- 빌드·테스트: python3 scripts/build-docs.py USER_GUIDE 는 HTML 생성; USER_GUIDE/ADMIN_GUIDE는 SHARED_PDF라 이 스크립트가 PDF를 만들지 않음.
- 관례: 한국어 feat/fix/docs/test/chore 커밋, CLAUDE.md/AGENTS.md는 저장소 파일 목록에서 미발견. internal·web/src·scripts TODO/FIXME 검색 결과 없음.
- 관례: 값 규칙은 lib 헬퍼를 읽는 쪽/쓰는 쪽이 공유. employeeQuery는 API 쿼리만 만들고 URL 복원 기능은 아직 없음.
- 관례: 초기 POSTGRES_DSN·BOOTSTRAP_ADMIN·BOOTSTRAP_ADMIN_PASSWORD, 기능 설정은 DB(이전 프로필 계승). 오류는 error.code/message.
- 현재 완료: 배정 해제·상세 소속/구역 분리·로그인 returnTo·좌석맵 q/map URL·직원 CSV·직원 조직 필터. 같은 과제를 다시 고르지 말 것.
- 직원 API: q·organizationId·status(active|leave|retired)·assignment(assigned|unassigned), limit<=500(기본100), total 없음.
- 직원 UI: EmployeesPage는 최초 필터가 모두 빈 값, URL 미소비. load에 이전 요청 순번 보호/오류 초기화 없음(개별 후속 후보).
- CSV 주의: 96c911e에서 왕복 가져오기 안내를 철회함. 내보낸 파일에는 조직코드가 없어 그대로 가져오면 조직 중복/소속 변경. 보고용이며 직원 양식과 구분. 이전 개선 기록의 왕복 가능 주장은 잘못됨.
- 좌석 계약: organizationName=지정 구역, employeeOrganizationName=직원 소속, 색은 직원 소속 우선. seatSpeech와 seatOrgDetail은 출력 맥락이 다르고 판정은 zoneMismatched 공유.
- 사용자 PATCH: updateUser는 Email 포함 시 대상 조회, 미포함 시 Exec RowsAffected 무시 후 204. 없는 ID의 body별 응답은 curl 미확인; 무조건 404라고 단정 금지.
- 씨드: 조직 개발6·영업2·인사2, 10명 전원 active·배정, 앞줄 좌석 개발팀 구역. 도면 한 개(이전 기록). URL E2E에는 실제 조직 API에서 id를 가져올 것.
- 접근성: 직원 Select 세 개 aria-label=조직 필터/재직상태 필터/배정상태 필터. 검색 단추 선택에는 exact:true(상단 직원 빠른 검색과 충돌).
- 위험 구역: auth.go·mcpoauth.go 인증/권한, migrations.sql 시작 시 DB 변경, tracking CSP, workflows 빌드/릴리즈. 이번 과제는 모두 제외.
- 자주 깨지는 곳: E2E 배정·구역 변경 복구 누락, 같은 값의 읽기/쓰기 계약 차이. helpers.restoreSeat는 좌표만 복구(이전 프로필 계승).
- 자주 깨지는 곳: employees.go listOrganizations/listEmployees가 Scan 실패를 버리고 rows.Err를 확인하지 않음. 다른 목록도 같은 문제라는 이전 기록은 이번 미재확인.
- 검증 함정: Go 통과는 UI/DB 계약 증명이 아님. 새 실서버 E2E를 변경 전 이미지에서 실패시킨 뒤 수정본 통과를 기록할 것. 소스 문자열 존재 검사는 실행 증거가 아님.
- 검증 함정: playwright.config는 서버를 안 띄우고 globalSetup은 시드만. 기본 URL 18781, CI URL 8080, workers=1. compose는 외부 DB 전제(이전 기록).
- 검증 함정: /healthz·/readyz는 server.go에 있고 CI 준비 확인은 /readyz. /api/v1/health를 기다리지 말 것. GET /만으로 준비 판정할 필요 없음.
- 검증 함정: mcp-oauth/tracking은 beforeAll에서 가짜 IdP/수집기를 직접 띄움. 별도 Keycloak 미기동이 필연적 실패 원인이라는 이전 프로필은 부정확. CI host network는 기본127.0.0.1; bridge는 E2E_COLLECTOR_HOST와 컨테이너→호스트 접근 필요.
- 검증 함정: 과거 2~8건 실패 기록을 정상 기준으로 고정 금지. 이번 전체 E2E 미실행. 실제 변경 전·후 실패 원인을 확인해야 함.
- 환경: 로컬 Go1.26.7·Node22.23.1, CI Node24·모듈 Go 버전. 의존성 신규/메이저 업그레이드 범위 외.
- 문서: PDF는 기존 이진 충돌 교훈으로 재생성하지 않고 md/html만 갱신.
