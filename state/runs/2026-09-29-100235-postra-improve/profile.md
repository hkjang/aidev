# postra 프로필 (2026-09-29)
- 목적: 개인·사내 POP3/IMAP/SMTP 메일 수집·검색·분석·작성·승인 발송과 AI·팀 업무를 REST/CLI/MCP/React로 제공하는 자체 호스팅 서비스. 확인 베이스 main@ecb9371, v0.23.9.
- 스택: Go 모듈 1.25.0, go.mod toolchain 및 CI 1.26.6. 이번 로컬 실제 실행은 go1.26.7 linux/amd64. SQLite/pgx PostgreSQL·pgvector; React 19/TypeScript/Vite, Vitest·Playwright; Node >=22.12.
- 구조:
  - cmd/postra: 서버·CLI 진입점. cmd/postra-contracts: API 계약 생성 및 -check.
  - internal/domain: 엔티티·포트·SecretHandle. account.go의 InboundSession/DialOptions는 POP3 타입 별칭; AuthError는 공통 인증 거부 타입.
  - internal/application: 수집·발송·계정·설정·OIDC·승인·워커. app.go:dialInbound에서 설정/비밀을 실제 어댑터로 전달하고 오류를 그대로 반환.
  - internal/adapters/{pop3,imap,smtp,ai,mailparse}: 프로토콜·콘텐츠 어댑터. POP3 client_test.go에 실제 TCP 테스트 5개가 존재함(예전 '테스트 없음' 프로필은 폐기).
  - internal/adapters/{persistence,pgstore,secretstore,objectstore}: DB·비밀·원문/첨부 저장.
  - internal/transport/{httpapi,mcpserver,spa}: REST·MCP/OAuth·임베드된 React 자산.
  - internal/platform: 설정·암호·추적·계측. internal/mailrender: 메일 렌더링.
  - web/: React 소스. api/: 생성 계약. docs/: 운영·사용 가이드, 설계, releases/.
- 빌드·테스트: go build ./...; go vet ./...; go test -race ./... (전체 수 분). make test는 전체 race 검사.
- 빌드·테스트: go run ./cmd/postra-contracts -check (읽기 전용 계약 검사, 별도 contracts.yml).
- 빌드·테스트: cd web 후 npm ci --no-audit --no-fund, npm run typecheck, npm test, npm run build. make build는 프런트 빌드 후 바이너리 생성; make build-offline은 캐시 및 로컬 툴체인 필요.
- 빌드·테스트: make lint = lint-format(gofmt 읽기 전용) + lint-security(gosec v2.28.0 -severity medium -exclude-dir=scripts ./...). CI 고정 버전과 정렬됨.

- 관례: 프런트 변경은 internal/transport/spa/assets 재생성 필요. CI/release가 미추적 파일까지 검사한다. 빌드/릴리즈 변경은 릴리즈 경로까지 검증해야 한다.
- 관례: 어댑터 동작은 실제 net.Listen 루프백 서버 + 실제 Dialer로 증명한다. 직접 만든 session/FakeSession만으로 프로덕션 배선이 검증됐다고 하지 않는다.
- 관례: 프로토콜 상한은 근거 주석이 붙은 상수와 정상 경로 실측 테스트를 사용한다. 빈 줄도 terminator·문자열 헤더 비용을 세어야 누적량 0 우회를 막는다.
- 문서 상태: CLAUDE.md/AGENTS.md/ROADMAP/TODO 파일 검색 결과 없음. internal/cmd/web/src의 TODO/FIXME 검색 결과 없음. docs/CONVERGENCE_CHECKLIST.md에 배포 산출물 확인 미체크 항목이 있으나 이것만으로 현재 릴리즈 실패를 추론하지 말 것.
- 위험 구역: OIDC·browser_auth·session·MCP OAuth/DCR·DB migrations·SecretStore/KEK·승인 토큰·.github/workflows·spa/assets. 이번 과제는 모두 피한다.
- 위험 구역: SMTP DATA 후 응답 유실은 Uncertain으로 유지하며 자동 재발송 금지(이전 기록 기반, 이번 SMTP 코드는 미열람).
- IMAP 상태: 리터럴 길이 ParseInt/도착 바이트만 버퍼링, 거부 리터럴 예산 내 드레인/초과 abandon, 줄 1 MiB, 응답 텍스트 8 MiB·리터럴 64개 상한은 이전 v0.23.4–7 기록과 현재 통과 테스트를 기준으로 유지. 이번 전체 프레이밍 구현은 재감사하지 않음.
- IMAP 주의: readLine은 데드라인 갱신, readLineNoReset은 IDLE 창 유지라는 다른 계약이다. 합치지 않는다. refusalThreshold <=0은 무제한이며 이번 직접 확인함.
- POP3 상태: readList에 maxListBytes 32 MiB + listLineOverhead(2+16) 상한이 있고 초과 시 연결을 닫는다(v0.23.8). 루프 안 deadline 위치는 그대로다.
- POP3 상태: Dial은 MaxMessageBytes를 저장하지 않고 retrBody는 bytes.Buffer에 무제한 누적한다. 04b15be는 HEAD 조상이 아님(exit 1). PR #22의 사람 반려 여부 미확인; 같은 접근 재제출/병합은 확인 전 금지.
- POP3 상태: 명령 메서드의 ctx 취소 전파는 여전히 없음. readResponse/readList/retrBody의 단일 행 읽기도 무제한. 둘 다 미병합 본문 구현과 겹치므로 이번 범위 밖.
- POP3 테스트: 현재 5개는 무종결/빈 줄 누적 상한·5000건 정상 maildrop·STLS 주입 거부·STLS 정상 명령을 다룬다. USER/PASS 거부·-ERR 인사말·RETR/TOP dot-unstuffing 회귀 테스트를 이번 과제로 선택.
- STLS/STARTTLS: 승인 응답 직후 버퍼 잔량을 검사하는 v0.23.9 변경이 HEAD에 포함. 커널 in-flight까지 검출하는 보장은 아니다. SMTP는 이 변경 범위 밖.
- sync 주의: UIDL 실패 후 LIST도 실패하면 JobFailed. UIDL 성공 후 LIST 오류는 무시되고 ingest 오류는 Failed++ 후 계속하며 마지막 JobSucceeded. Dial 실패는 이미 JobFailed이고 AuthError는 계정을 credential_error로 만든다.
- 신규 관찰: POP3 Dial은 USER/PASS 중 모든 cmd 오류를 AuthError로 감싼다. 일시적 네트워크 장애의 credential_error 오분류 가능성은 있으나 실제 TCP→StartSync 재현은 미확인; 별도 아이디어로 보류.
- 자주 깨지는 곳: 브랜치 성공과 main 반영 혼동. git merge-base --is-ancestor로 확인한다. 러너 세션 중단을 Actions 릴리즈 실패로 오인하지 않는다.
- 자주 깨지는 곳: locked 워크트리는 러너 wt_reset이 unlock→remove→삭제→prune으로 복구한 전례. 정찰이 작업 트리를 고치지 않는다.
- 검증 함정: README govulncheck @latest와 CI @v1.6.0 불일치 재확인. CI 포맷 검사는 없고 make lint-format 별도. 로컬 Go 1.26.7과 CI 1.26.6 차이를 기록할 것.
- 검증 함정: PG 검사는 POSTRA_TEST_PG 및 pgvector, 브라우저는 Chromium 필요. 전체 Go 성공만으로 이 외부 검사가 수행됐다고 하지 않는다. 이번 application 배선은 코드만 읽음.
- 검증 함정: 서버 핸들러 종료/timeout은 클라이언트 EOF와 다르다. 실제 읽기 결과를 채널로 확인하며 cleanup이 먼저 닫아 테스트를 거짓 통과시키지 않게 한다.
