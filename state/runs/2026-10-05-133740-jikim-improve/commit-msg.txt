fix: release the OIDC settings outage reporting fix for v0.2.29

OIDC 로그인 시작·콜백이 설정 읽기 실패를 "OIDC 로그인이 설정되지
않았습니다/비활성화되었습니다"로 보고하던 문제를 고친 PR #51 을 릴리즈합니다.
`oidcLogin`(oidc.go:121-125)과 `oidcCallback`(oidc.go:252-256)이
`s.store.OIDCConfig` 의 **모든** 오류를 `!cfg.Enabled` 와 한 조건(`if err != nil
|| !cfg.Enabled`)으로 묶어 503 `oidc_disabled` 로 내보내, PostgreSQL 장애나
`oidc_client_secret` 복호화 실패 순간 멀쩡히 설정된 SSO 가 "설정되지 않았다"로
보고됐습니다. 관리자는 이미 올바른 설정 화면을 다시 뒤지고 클라이언트는 재시도할
근거를 잃었습니다. 같은 PR 은 같은 파일 `oidcPublicConfig`(43-47)·`oidcTest`(55-59)
가 이미 쓰는 `if err != nil && !errors.Is(err, store.ErrNotFound) {
s.storeError(...) }` 모양으로 두 자리를 맞췄습니다(프로덕션 파일 2개: `server.go`
에 `oidcConfigLoader` seam 한 줄, `oidc.go` 에 nil-폴백 헬퍼 `loadOIDCConfig` 와
두 분기). 새 설치 동작은 바이트 단위로 그대로입니다. `store.ErrNotFound`,
`Enabled:false`, 켰지만 Issuer·ClientID 가 빈 경우 모두 여전히 503
`oidc_disabled` 와 기존 한국어 문구이고, 콜백 조건식은 지금처럼 `!cfg.Enabled` 뿐
입니다(Issuer·ClientID 검사를 더하지 않았고 그 뒤 `validateOIDCRuntimeConfig` 가
받습니다). 콜백 244행이 같은 파일의 seam 헬퍼 `s.openOIDCState` 를 우회해
`s.store.OpenOIDCState` 를 직접 부르던 한 줄도 헬퍼로 바꿨습니다(nil-폴백이 같은
저장소 호출로 접히므로 동작 불변). 같은 PR 은 실제 `s.requestID` 를 거친 요청
왕복으로 로그인 4개·콜백 3개, 일곱 경우의 상태 코드와 code 를 고정하는 회귀
테스트를 추가했고, 500 케이스는 본문에 DSN·호스트명·`SQLSTATE` 가 없고 ERROR 가
`request_id` 를 담아 정확히 한 줄 남는 것까지 못박았습니다.

기존 패치 릴리스와 같은 방식으로 버전 파일, 문서 프로파일과 CHANGELOG 를 v0.2.29 로
갱신했습니다. 캡처 출처는 실제로 찍은 v0.2.9 를 유지합니다. 두 가이드 PDF 는
v0.2.28 과 같은 이유로 표지가 `v0.2.18` 인 채로 남았습니다. 지금까지 쓰던
변환기(Markdown 표지 템플릿 + HeadlessChrome 인쇄)가 저장소에 없어 같은 판형으로
다시 구울 수 없었고, 다른 템플릿으로 바꿔 굽는 것은 릴리스 절차 밖의 변경이라 기존
파일을 그대로 두고 CHANGELOG 에 적었습니다. 본문 Markdown 은 갱신했습니다.
`./scripts/verify.sh` 전체(Go test·vet·gofmt, 웹 테스트 59개·lint·build,
문서·Compose)와 태그·소스 버전 일치 검사가 통과했습니다. 이미지 빌드, PostgreSQL
스모크, 브라우저 E2E, 번들 생성 및 게시 작업은 태그 푸시 후 release.yml 이
수행합니다.
