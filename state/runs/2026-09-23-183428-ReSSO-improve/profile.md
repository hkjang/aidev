# ReSSO 프로필 (2026-09-23)
- 목적: 오프라인 단일 바이너리로 운영하는 OIDC SSO 제공자와 사용자·Realm 관리 콘솔. 외부 RP 구현은 포함하지 않는다(이 저장소는 언제나 제공자 쪽이다).
- 스택: Go 1.26, chi v5, PostgreSQL/pgx v5, LDAP, React 19/TypeScript/MUI/React Query/Vite 7, vitest 4; CI Node 22.23.0.
- 구조:
  - cmd/resso: 서버·CLI·예약 LDAP 동기화·유지보수·메일 알림.
  - internal/httpserver: OIDC(oidc.go)·로그인/세션(auth.go)·관리/개인 API·MCP·미들웨어. integration_test.go는 실제 PostgreSQL과 httptest HTTP 서버를 쓴다(9천 행대의 단일 파일).
  - internal/store + store/migrations: DB 접근과 자동 SQL 마이그레이션(최신 017_mail_deliveries.sql).
  - internal/oidc, cryptoutil, password, ratelimit: 토큰 발급·검증, 암호화, 비밀번호, 실패 제한.
  - internal/federation, backchannel, mail: LDAP·로그아웃 통지·SMTP.
  - internal/tracking, observability: 방문 추적/CSP·Prometheus 지표·구조화 로그.
  - web/src(React 소스), webui/dist(Go embed 산출물).
  - scripts(test-services.sh·스모크·릴리즈·가이드 캡처), docs(운영/사용/호환 정본).
- 빌드·테스트:
  - `eval "$(scripts/test-services.sh)"` 로 PostgreSQL/LDAP/LDAPS 환경변수를 잡고 **같은 셸에서** 테스트한다. 출력이 비면 준비 실패이므로 eval 하지 말 것.
  - `make lint`(golangci-lint v2.13.1 + govulncheck + ESLint --max-warnings 0), `make test`(go test -race ./... + vet + vitest + build, 전체 수 분: httpserver 약 115s / store 약 80s), `make build VERSION=vX.Y.Z`.
  - 단일 테스트: `go test -race ./internal/httpserver -run '^TestIntegration…$' -count=1 -v`.
- 관례: 영문 `fix:`/`feat:`/`docs:`/`release:` 커밋. HEAD 73398a1 = v0.9.89. 설정은 환경변수 + `platform_settings` 키별 한 행. docs/가 운영·연동 정본이고 README는 개발 참고. 코드 주석이 매우 길고 "왜 이 답을 골랐는가"를 서술형으로 담는다 — 새 코드도 그 밀도를 따라야 한다. CLAUDE.md/AGENTS.md/roadmap/TODO는 저장소에 없다.
- 위험 구역: internal/httpserver/auth.go(세션·쿠키·로그인 계약), oidc.go의 토큰·로그아웃 경로, CSRF/API 키 예외, internal/store/migrations, .github/workflows/release.yaml. 로그아웃은 "조기 거절 금지"가 파일 안에 두 번 명시돼 있다(realm 404 주석, endSession 주석) — 실패해도 세션을 끝내고 트레일에 남기는 쪽이 이 저장소의 정책이다.
- 자주 깨지는 곳: gofmt 정렬(lint 첫 실행에서 자주 잡힌다), 빌드가 바꾸는 webui/dist/index.html(되돌릴 것), LDAPS bind mount와 CA 경로 불일치, 추측한 HTTP 상태 코드, 유지보수 SQL 문장 순서를 잠근 store 테스트(TestIntegrationTheRetentionSweepSaysOnlyWhatItSkipped).
- 검증 함정:
  - 환경변수가 없으면 연동 테스트가 SKIP인데도 종료 코드는 0이다. SKIP 0을 눈으로 확인할 것.
  - make test는 SKIP 집계용으로 연동 명령을 한 번 더 돌린다(중복 실행).
  - CI verify는 세 서비스를 준비하지만 release.yaml은 PostgreSQL만 준비한다. 두 workflow의 서비스 범위가 다르다.
  - CI lint는 npm 설치 전에 돌고, 로컬 make lint는 GO_PACKAGES로 vendored Go를 제외한다.
  - Docker는 이 환경에서 실행 가능(2026-09-21 확인). 기존 테스트 컨테이너 재사용만 검증됐고 깨끗한 환경에서의 신규 생성·삭제는 미검증.
- 최근 완료(반복 금지): UserInfo POST 폼 토큰·중복 거절·1MiB 제한(76f5974/3060a9b), 로그인 500/409/status 0 안내와 trace(0630871/c99757d), silent SSO 답별 지표(f292349), 메일 알림 체계(c8100c0), README 준비 절차 통일(92ccbb9).
