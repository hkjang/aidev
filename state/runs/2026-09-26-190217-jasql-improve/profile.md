# jasql 프로필 (2026-09-26)
- 목적: KCB JSON 메타데이터를 카탈로그·검색·조인·가드레일로 컴파일해 NL2SQL MCP/REST/웹 콘솔과 읽기 전용 Oracle 실행을 제공한다. 기준 base main@32a8811, v0.31.2 (이번 회차 `git log` 실측).
- 스택: Go(go.mod `go 1.25.0` 선언), godror(`oracle` 빌드 태그 + cgo 전용), pgx(PostgreSQL), x/crypto, go.sum 존재. 프런트는 go:embed 정적 HTML/JS. 기본 빌드·CI 는 태그 없이 돌아 Oracle 드라이버는 연결 불가 stub.
- 구조:
  - `cmd/jasql-mcp`: HTTP/stdio 서버 CLI. `cmd/jasql-eval`: 골든 평가 CLI. `cmd/jasql-goldgen`: 골든셋 생성 CLI. 세 패키지 모두 base 에서는 no test files(eval/goldgen 대상 CLI 테스트는 미머지 브랜치에만 존재).
  - `internal/catalog` (~13k 줄, 53 파일): 로드(load.go)·검색(search.go 876줄)·조인(graph.go/join.go/joinsuggest.go)·지표(metrics.go)·질문분석(analyze.go)·SQL 검증(validate.go 1039줄)·시간 파싱(timeparse.go)·시멘틱·템플릿·평가(eval.go/eval_retrieval.go). mcp 비의존. 테스트가 가장 무겁다.
  - `internal/mcp`: 도구 등록/디스패치(`tools()`/`callTool()`/`toolsForActor()`)·REST·인증/SSO/OAuth·실행 가드·개인화. `webui` 는 콘솔 정적 자산.
  - `internal/meta`: 메모리/PostgreSQL 저장소(사용자·세션·설정·프로파일), `pg.go`.
  - `internal/oracle`: 프로파일(profile.go)·연결 풀(manager.go)·읽기 전용 실행·계획(explain.go)·SQL 가드(sqlguard.go). **`c707512`(v0.6.0) 이후 아무도 손대지 않았다** — 이번 회차 `git log -- internal/oracle` 실측.
  - `data/kcb`: 실데이터와 골든셋. 기존 테스트가 읽으므로 테스트 출력 대상으로 절대 쓰지 않는다.
  - `docs`: 한국어 가이드(정본 목차 `docs/README.md`, 개발자 가이드 `docs/development.md` — 2026-09-25 에 소스와 동기화). `scripts`: 크로스 빌드·오프라인 도커 이미지 릴리즈. `.github/workflows/ci.yml`: 2026-09-25 신설, build→vet→test 단일 잡(ubuntu-latest, timeout 15, permissions contents:read). **포맷 게이트 없음.**
  - Go 파일이 있는 최상위 디렉터리는 `cmd`, `internal` 둘뿐(루트 `.go` 없음) — 이번 회차 `git ls-files '*.go'` 실측.
- 빌드·테스트: `go build ./...` → `go vet ./...` → `go test ./...`. 실측(이전 회차) catalog 55~58 초, mcp 약 10 초, meta/oracle 캐시. 골든 평가는 `go run ./cmd/jasql-eval [-verbose]`.
- 관례: 커밋 메시지는 영어 명령형, PR 머지 제목은 한국어. 버전은 `internal/mcp/server.go` 의 Version 을 정본으로 OpenAPI·README·배포 문서와 동기화하고 `scripts/release-image.sh` 가 그 값을 읽는다. 설정은 flag → env → 메타 DB settings.
- 관례: 카탈로그는 로드 후 불변 — 새 컴파일 결과로 원자 교체. 변경 테스트는 `t.TempDir()` JSON 을 `catalog.Load` 로 읽는다(`internal/mcp` 의 `newFixtureServer` 참고). `TestServeStdio` 는 실제 stdio 전송으로 도구 42 개와 스키마를 단정하고 `internal/mcp/docs_test.go` 가 문서에 적힌 도구 수를 실제 `tools/list` 왕복과 비교한다.
- 위험 구역:
  - `internal/mcp/auth.go`·`oauth.go`·`authapi.go` — 세션·권한. `dbapi.go` — 비밀번호·소유권.
  - `internal/oracle/sqlguard.go`·`internal/mcp/execguard.go` — 읽기 전용 정책 경계. 여기 변경은 단순 결함 수정으로 취급하지 말 것.
  - `internal/meta/pg.go` — 마이그레이션. `.github/workflows/` — 빌드·릴리즈 경로(단계 추가만, 트리거·permissions·잡 구조 유지).
  - `cmd/jasql-goldgen` 기본 `-out` 이 `data/kcb/golden_queries.json` 을 덮어쓴다. 반드시 임시 `-data`/`-out` 만 쓴다.
  - 전역 카탈로그 mutation, `internal/catalog/search.go:tokenize`/`stripKoreanSuffix` 같은 공용 프리미티브 — 호출부가 8 곳 이상이라 블라스트 반경이 넓다.
- 자주 깨지는 곳:
  - **base 가 머지되지 않은 '성공' 커밋 3 개만큼 계속 뒤처진다.** 2026-09-26 `git merge-base --is-ancestor` 로 재확인: `1507e00`(oracle `TrimStatement`), `caf7a00`(eval `-verbose` MISS 표시 — `cmd/jasql-eval/main.go` 의 세 bool 조건), `c712da1`(timeparse 보고 단위 순서 결정성) 모두 미머지. 이 세 영역을 다시 고르면 열린 PR 과 중복·충돌이다. 정찰은 매 회차 이 세 커밋의 ancestry 를 먼저 확인할 것.
  - `internal/oracle/profile.go`·`oracle_test.go` 의 gofmt 드리프트가 3 회차 반복 보고(2026-09-24·09-25 실측). CI 에 gofmt 게이트가 없어 계속 남는다 — 넣기 전에 이 두 파일을 먼저 포맷해야 첫 실행이 green 이다(같은 PR 에 담을 것).
  - 문서 숫자의 재드리프트(도구 수·데이터셋 수·Go 버전). 도구 수는 `docs_test.go` 로 고정됐으나 `docs/README.md` 의 데이터셋 개수는 `DatasetRegistry` 와 어긋난 것으로 보고됨(2026-09-22 이후 미재확인).
  - `tokenize` 등 공용 프리미티브 변경 시 골든 평가 지표 회귀를 손으로 비교해야 한다 — `cmd/jasql-eval` 의 종료 가드는 `table_selection_acc < 0.7` 뿐(2026-09-26 실측)이라 0.94→0.75 하락도 green.
- 검증 함정:
  - 기본 `driverAvailable=false` 라 기본 테스트는 실제 Oracle 전송·실행을 증명하지 못한다. Oracle e2e 주장 금지 — 헬퍼 단위 테스트까지만 증명된다.
  - PostgreSQL 통합 테스트는 `JASQL_TEST_PG` 가 unset 이면 skip.
  - godror 는 `oracle` 태그 + cgo 필요. 기본 빌드·크로스 빌드·CI 는 태그 없이 돌므로 태그 경로는 CI 가 검증하지 않는다.
  - 저장소 루트에 CLAUDE.md/AGENTS.md 없음.
  - `docs/evaluation.md` 의 `expected_columns` 는 **베어 정규화 비교 계약**이다. 한정자 보존은 결함 수정이 아니라 계약 변경이다.
  - **정찰 세션의 Bash 승인 게이트가 회차마다 다르다.** 2026-09-25·09-26 두 회차 모두 `gofmt`·`go build`·`go test`·`go run` 이 거부됐다(2026-09-26 은 `git`·`sed`·`ls`·단일 파이프 없는 명령만 통과). 정찰이 "실측" 이라고 적지 않은 숫자는 이전 회차 값이니 구현자가 다시 찍을 것.
