# vibe-code 프로필 (2026-09-29)
- 목적: 한국어 기본 VS Code AI 코딩 확장으로 목표 자율 루프·계획 보드·검증·감사·사용량 대시보드를 제공한다. 현재 1.4.5, main@43fd7a1.
- 스택: TypeScript ES2022/commonjs/strict, esbuild, vitest 3, CI Node 20. DB 없이 `.vibe-code/` markdown/JSONL 사용.
- 구조:
  - `src/extension.ts` → `src/activation.ts`: 자체 기능 등록(이전 프로필 기준, 이번 재열람 생략).
  - `src/features/`: goals/plans/verification, 트리·상태바, goal-loop/lint/health/catalog, checkpoints, proxy 등 기능별 모듈.
  - `src/util/markdown.ts`: 섹션·메타데이터·체크리스트 공용 읽기/편집. normalizeEol/detectEol/restoreEol로 LF/CRLF 처리.
  - `src/features/workspace.ts`: 상태 파일 경로·읽기·감사의 공통 관문(이번 import/호출 확인).
  - `src/core/`: vendor 접점. `vendor/extension.core.js`는 벤더 코어, 임의 수정 금지.
  - `webview-ui/build/`: 원본 미확보 UI 번들. 확장 UI는 별도 웹뷰로 추가하는 관례.
  - `tests/unit/`: 11개 테스트 파일, 82개 테스트. 기존 vscode-stub를 vitest alias로 사용.
  - `docs/`: 유지보수/자율 목표/프록시 문서와 improvement-roadmap.md 백로그.
- 빌드·테스트:
  - 기본 워크트리에는 node_modules 없음. `npm ci` → `npm run check`(typecheck + vitest run + build).
  - 집중 검증: `npx vitest run tests/unit/markdown.test.ts tests/unit/plans.test.ts`.
  - 정찰은 파일 쓰기 제한 때문에 run/validation에 lock 기반 의존성을 설치하고 외부 config로 원본 전체 테스트를 실행했다. Node 22.23.1 / vitest 3.2.7이며 Node 엔진 경고가 있었다.
  - 최초 결과 81/82 통과, checkpoints의 저장소 밖 테스트 1실패 및 worker timeout. 임시 경로의 상위 aidev Git 저장소를 감지한 환경 문제; 생성된 체크포인트 참조는 정리했다. Git 탐색 경계를 지정한 재실행은 11개 파일/82개 테스트 모두 통과(11.31초).
  - 루트 `npm run check`/typecheck/build와 VSIX 패키징은 이번 정찰에서 미실행. 성공으로 간주하지 말 것.
- 관례: 영어 conventional prefix + 한국어/영어 요약 커밋. UI 설정은 package.json과 package.nls.json/package.nls.ko.json을 함께 관리. 마이그레이션 체계 없이 상태 파일 편집.
- 관례: 순수 export 함수와 실제 planTemplate/goalTemplate·실제 fs/Git 테스트를 선호. 별도 FakeTask/가짜 문서 배선으로 결함 증명하지 않는다.
- 위험 구역:
  - checkpoints.ts: 임시 Git index와 commit-tree/update-ref. 작업 트리·index·stash 보존이 핵심.
  - vibe-coders-proxy.ts: provider 설정 저장/복원. host/provider를 가짜 객체로 대체하면 실제 배선을 검증하지 못함.
  - vendor/core hooks, .github/workflows, scripts/*.ps1, release/: 확장 활성화와 릴리즈에 영향.
  - 감사에는 출력/파일 내용/비밀을 추가하지 않는다.
- 자주 깨지는 곳:
  - writeSection은 섹션 전체 교체다. taskLines/lines로 걸러 넘기면 메모·들여쓰기 유실. sectionLines도 첫/끝 경계는 section.trim의 영향을 받음(첫 줄 들여쓰기 소실 이번 재현).
  - 1.4.4 advancePlanText의 내부 줄 보존, 1.4.5 appendVerificationLog/checkLine의 CRLF 보존은 이미 수정됨. 반복 과제로 고르지 말 것.
  - 메타데이터 `\s*`가 줄바꿈까지 먹는다. 빈 상태에서 작성일 삭제와 archiveDonePlans 오보관 재현 — 이번 brief 과제.
  - countChecks/isTaskLine vs taskLines/checkLine의 들여쓰기 판정이 다름. 하나만 고치면 UI와 진행률 불일치.
- 검증 함정:
  - 임시 디렉터리가 다른 Git 저장소 아래면 “저장소 아님” 테스트가 부모 저장소를 발견한다. 테스트 전용 TMPDIR을 쓸 때 `GIT_CEILING_DIRECTORIES=$TMPDIR`를 함께 지정한다.
  - CI는 Node 20, 이번 정찰은 Node 22. vscode-stub는 import 경계용이며 Extension Host 실제 동작을 증명하지 않는다.
  - npm run build는 dist를 생성한다. 런타임 자산은 릴리즈 VSIX에서 복원; 빌드 성공만으로 VSIX 실행을 보장하지 않는다.
  - CI package job은 릴리즈 자산 다운로드가 실패/누락되면 packaging을 건너뛸 수 있다.
  - `vsix`, `verify`, `smoke:vscode`, `test:extension-host`는 PowerShell/Windows 경로. Linux check job은 실제 확장 호스트를 실행하지 않는다.
  - KST 시간 고정. 새 편집 경로는 LF/CRLF 양쪽 확인. sectionOfLine CRLF 잔존 가설은 실제 함수 실행으로 기각.
