# nexabuilder 프로필 (2026-09-24)
- 목적: 엔티티·폼·목록·워크플로 메타데이터로 업무 화면을 만드는 Spring Boot 로우코드 플랫폼과 관리 콘솔.
- 스택: Java 21, Spring Boot 4.1.1, Gradle 8.14.3 Kotlin DSL, JPA/JdbcTemplate, Liquibase XML, 기본 H2와 외부 DB 프로필, Thymeleaf/Bootstrap/htmx/jQuery 4+migrate/jqWidgets, Groovy, POI 5.3.0/OpenPDF 3.0.5. 현재 버전 v1.20.0(커밋 014ace4).
- 구조:
  - src/main/java/com/nexabuilder/core/ui — NexaUiService(목록·폼·atom 정의, listData, formDefinition). `requireLiveList(listId)` 가 존재+deletedAt 판정의 **단일 게이트**로, listDefinition·listData·ListExportController.resolveExportable·DataAdapterService.queryList 네 경로가 모두 이것을 통과한다(이번 회차 소스로 재확인). 폼 쪽은 아직 formDefinition 안에 인라인(122-130).
  - core/data — DataAdapterService: jqxgrid용 `{Rows,totalCount}`. queryList/queryEntity 가 공유하는 `parse(Map,Integer)` 가 페이지 파라미터를 해석하고, executeEntityBacked 는 SqlPagination.limitOffset 으로 DB 페이징, executeSqlBacked 는 전체 행을 받아 applySort/applyPaging(List.subList) 으로 자바 페이징.
  - core/entity·core/sql — 동적 엔티티 DDL/DML, SQL 메타데이터 실행, SqlPagination 의 DB별 LIMIT/OFFSET.
  - core/* — permission, auth, session, audit, llm/ai, menu, version 등 도메인 서비스.
  - api/controller·api/dto — REST와 ApiResponse. GlobalExceptionHandler: IllegalArgumentException→400 JSON, AccessDenied→AccessAuditHandler, AI 쿼터→429.
  - web/controller·resources/templates·resources/static — 서버 화면과 브라우저 UI. nexa-data.js 는 layout 에서 전역 로드.
  - infra/security·infra/web·plugin/groovy — 필터·세션/토큰 보안, Jackson 2 호환, Groovy 실행.
  - resources/db/migration — Liquibase 001~079 XML + changelog-master.xml. 027이 목록/폼/엔티티 deleted_at 추가.
  - src/test — SpringBootTest/MockMvc/H2 통합 테스트 중심. 직전 회차 기준 578건 통과.
- 빌드·테스트: `sh ./gradlew --no-daemon test`(gradlew 가 100644라 sh 경유), 단일 `--tests 'com.nexabuilder.api.DataAdapter*'`, 전체 강제 `--no-daemon cleanTest test`(수 분, 테스트 힙 2g), 패키징 `--no-daemon bootJar -x test`. **자율 회차에서는 gradlew 실행이 샌드박스 승인 대상이라 정찰 단계에서 못 돌 수 있다**(2026-09-24 회차에서 실제로 차단됨) — 구현 단계에서만 실행 가능하다고 가정할 것.
- 관례: Lombok 생성자 주입, UUID 8자 접미사 테스트 픽스처(정리 없음). 커밋은 한국어 `type(scope): …합니다`, 버전 커밋/PR merge 는 영어. Liquibase 새 XML 을 master 에 include. 설정은 application.yml + nexa_config 런타임 설정.
- 위험 구역: core/auth·core/session·infra/security·core/permission, db/migration, .github/workflows, workflow 의 비동기 감사·종료 경합. Jackson2JsonConfig:57 에 [removal] 경고가 있으나 Jackson 3 이전은 별도 L 작업.
- 자주 깨지는 곳: `@DirtiesContext` 를 붙이면 컨텍스트 재생성으로 시간·힙·비동기 종료 경합이 악화(2026-09-17). 같은 값을 읽는 경로가 여럿이라 한 곳만 고치면 구멍이 남는 패턴이 4회차 연속 반복됐다(목록 soft-delete: 정의→내보내기→builder /data→어댑터). 새 판정을 넣을 때는 grep 으로 모든 리더를 세고 단일 헬퍼로 모을 것. webjar 버전 고정 URL 404, jQuery 4 에서 migrate 제거 시 jqWidgets 오류.
- 검증 함정: CI 는 chmod 후 gradlew 직접 실행 + setup-java Temurin21, foojay 가 누락 JDK 를 다운로드. CI 는 test+bootJar, CodeQL 은 public 저장소에서만. `/api/v1/data/*` 는 **성공 시 `{Rows,totalCount}`, 실패 시 `{success,message}`** 로 봉투가 다르므로 새 에러 경로를 추가하면 jqxgrid 어댑터가 파싱하지 못한다. `NexaListDef.pageSize` 는 nullable 이고 fallback 은 100(NexaUiService.listData 와 DataAdapterService.parse 가 같은 값을 써야 함). SQL 어댑터와 엔티티 어댑터의 컬럼 키 대소문자 처리가 다르다(엔티티 쪽만 lowerCaseKeys). PDF 한글 글리프는 환경 폰트 의존. 외부 서비스 의존 테스트 유무는 미확인.
