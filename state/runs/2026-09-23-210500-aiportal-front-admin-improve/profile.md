# aiportal-front-admin 프로필 (2026-09-23)
- 목적: AI 포털 관리자 SPA. 루트 `src/` 의 legacy 운영 앱과 `upgrade/admin-v2/` 의 독립 Admin V2 가 한 저장소에 공존.
- 스택: Vue 3 / Vite 7 / axios. V2 는 TypeScript + vue-tsc + Vitest(jsdom). 자체 DB 없음; 외부 Java/Python/IAM API.
- 구조:
  - `src/`: legacy 화면·API·storage 인증·라우터 (테스트 없음).
  - `upgrade/admin-v2/src/api/`: `http.ts`(envelope·세션 세대·401/400 토큰코드 처리), 도메인별 API + `mock.ts`.
  - `upgrade/admin-v2/src/modules/`: 화면 7개 — overview, operations, catalog, directory, content, policy(PolicyCenter·AdvancedPolicy).
  - `upgrade/admin-v2/src/shared/`: `async.ts`(createRequestGuard), `paging.ts`(lastPageWhenOutOfRange), `routeQuery.ts`(useRouteQuerySync), `format.ts`, `validation.ts`, `notifications.ts`.
  - `upgrade/admin-v2/scripts/`: runtime config·offline·integrity·check-version 검사 (.mjs, 한국어 주석, `fail()`→exit 1).
  - `upgrade/admin-v2/deploy/`, `.gitlab-ci.yml`: GitLab 브랜치 기반 정적 배포. `.github/workflows` 없음.
  - `docs/`: 운영·테스트·ROADMAP·RELEASE 등(`INDEX.md` 가 목록). V2 `docs/`: ARCHITECTURE, QUICK_WINS.
- 빌드·테스트: `cd upgrade/admin-v2 && npm ci && npm run verify`(typecheck+vitest; 26파일 202테스트가 최근 기준선). `npm run build` 는 verify+Vite+4개 검사(수분). `npm run check:version` 이 4개 파일 6개 값을 비교. 루트 앱은 `npm run build:<mode>` 만 있고 테스트 없음. node v22.23.1; 새 worktree 의 node_modules 는 비어 있음.
- 관례: 커밋 `fix(admin-v2): 한국어 문장`. auto/<날짜> 브랜치 → main PR 병합. 코드 주석은 "왜" 를 한국어 두세 줄로 적는 스타일이 일관됨. DB migration 없음. 릴리즈 절차는 `docs/RELEASE.md`, 노트는 루트 `CHANGELOG.md`(Keep a Changelog).
- 릴리즈 상태(2026-09-23): v0.1.1 이 2026-09-22 에 나갔다(커밋 e67da65 `chore(release): v0.1.1`). 루트·admin-v2 `package.json` 모두 0.1.1 로 일치. CHANGELOG 는 `[Unreleased]`(비어 있음) + `[0.1.1]`(fix 4건). 원격 태그·GitHub Release 는 미확인.
- 위험 구역: `src/` 인증·라우터·SSO, `upgrade/admin-v2/src/auth/`, `api/http.ts`(세션 세대·401 처리), `.gitlab-ci.yml`(URL 에 자격증명, 값 기록 금지), `deploy/`. backend RBAC 전 정책 쓰기 활성화 금지 — `public/config/runtime.json` 의 `enablePolicyWrites:false`, `enableMonitoring` 도 플래그. 루트 `package.json:34` 의 `crypto-js": "file:crypto-js-4.2.0.tgz"` 는 tarball 부재로 루트 `npm ci` 를 깨뜨린다 — 루트 설치 시도 금지.
- 자주 깨지는 곳:
  - 목록 화면의 "조회 중/조회했다" 판정. `items.length` 로 판단하면 query 가 바뀐 뒤 이전 사용자의 행이 남고(15e032f), `snapshot != null` 로 판단하면 결과 0건 탭이 매번 재조회된다(f29e2df). 정답은 화면별 `tabLoaded` 플래그.
  - 늦게 도착한 이전 응답. `createRequestGuard` 티켓 없이 쓰면 재조회·탭 전환에서 덮어쓰기가 난다(1709f01, f3016f9, 15e032f 가 모두 이 계열).
  - 외부 aidev 러너의 스킬 전달 결함을 겨냥한 과제는 6회 연속 no-change 였다 — 앱 회차에서 고를 수 없다.
- 검증 함정: Playwright 설정 파일은 있으나 의존성·스크립트 없음. 실제 Java/IAM/UAT 는 별도 환경. README 의 "21 unit/18 산출물" 수치는 옛 기준선이라 현재와 어긋남. 전 회차에 갱신 표시 테스트 4파일이 1회 간헐 실패했고 20회 재시도에서 재현되지 않음(원인 미규명) — `npm run verify` 가 한 번 붉게 나오면 재실행해 보고 기록할 것.
