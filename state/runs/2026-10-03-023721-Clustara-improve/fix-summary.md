# 수리 요약 (7fedbb3)

비평의 세 지적 모두 맞았고 전부 고쳤습니다. (1) capability 검사가 Restricted 허용 목록(NET_BIND_SERVICE)으로 Baseline 을 판정해 `add:[CHOWN]` 하드닝 Pod 가 privileged 로 올라갔습니다 — `baselineCapabilities`(PSS Baseline 기본 13개)를 추가해 목록 안은 `failsRestricted`, 목록 밖(SYS_ADMIN 등)만 `failsBaseline` 으로 보냅니다. (2) 명시적 `seccompProfile=Unconfined` 는 Baseline 실패인데 미설정과 같은 버킷이라 baseline·무알림으로 남았습니다 — 공용 헬퍼를 `containerProfileViolations`(통제별 `failsBaseline` 태그)로 바꾸고 `restrictedProfileViolations` 는 그것을 평탄화해 Deny 게이트가 보는 목록·순서를 그대로 유지했습니다. Unconfined 만 Baseline 태그를 받습니다.
틀린 의미를 못박던 테스트는 지우지 않고 기대값을 PSS 원문대로 고쳤습니다: `security_pss_level_test.go` 의 Unconfined 케이스를 privileged 로, allow-list 안 capability·seccomp 미설정·pod 상속·container 덮어쓰기 케이스를 추가. main 에 이미 있던 `security_seccomp_test.go` 도 `wantLevel` 을 `violates` 에서 파생하던 것(=모든 seccomp 실패를 baseline 으로 단정)을 케이스별 명시로 바꿨고, Restricted 위반·detail 단언은 모두 유지했습니다. proxy 종단 테스트에 Unconfined 페이징 1건과 CHOWN·seccomp 미설정 무알림 2건을 더했습니다. 문서는 등급↔버킷↔통제 표와 두 경계(capability 13개 목록, Unconfined vs 미설정)를 명시하고 릴리즈 영향 범위를 네 가지로 정정했습니다.
검증: 수리 전 `go test ./internal/analyzer -run TestPodSecurityLevelNames...` 가 CHOWN=privileged·Unconfined=baseline 로 실패 → 수리 후 통과. 인과 확인으로 `go test -overlay`(HEAD:security.go) 재실행 시 신규 단언 전부 실패(CHOWN `sent:1` 오탐 페이지, Unconfined `sent:0` 미알림) → 수리본에서 전부 통과. `go build ./...`·`go vet ./...`·`go test ./... -count=1` 전부 green(proxy 59.5s), 손댄 4개 파일 gofmt 클린.
미검증(이전 회차와 동일): 실 Kubernetes·실 PostgreSQL·ClickHouse·브라우저(admin_ui Pod Security 표), 실 클러스터 알림 증가 폭. hostProcess·sysctls·/proc mount·AppArmor·SELinux 등 나머지 Baseline 통제는 여전히 미검사라 "등급 = 가장 약한 허용 프로파일" 계약은 부분적입니다(범위 외로 두었습니다).
