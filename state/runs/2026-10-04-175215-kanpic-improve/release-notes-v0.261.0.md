# v0.261.0

## 시스템 로그에 남는 장애 원인이 더 이상 빈 객체가 아닙니다

kanpic 은 시스템 로그 한 줄을 두 곳에 적습니다. 서버 표준 출력의 콘솔 로그와,
관리자 콘솔의 로그 화면·CSV 내보내기가 읽는 `system_logs` 테이블입니다. 두
기록은 **같은 레코드 하나**에서 나오므로 같은 값이어야 합니다.

그런데 DB 쪽은 속성 값을 `encoding/json` 으로 그대로 굳혔습니다. Go 의 error
는 내보낼 필드가 없어 이 방식으로는 `{}` 가 됩니다. 그래서 다음 한 줄이

```
logger.Error("외부 호출 실패", "error", err)
```

콘솔에는

```json
{"level":"ERROR","msg":"외부 호출 실패","error":"상위: 연결 거부"}
```

로 적히는데, `system_logs.attributes` 에는 `{"error":{}}` 로 들어갔습니다.
콘솔 로그는 컨테이너를 다시 띄우면 사라지므로, 장애가 지나간 뒤 **원인이 적힌
유일한 영구 기록**이 빈 객체였습니다. 서버 안에서 `"error", err` 로 로그를
남기는 자리는 28곳이고, 관리자 콘솔의 로그 화면과 CSV 내보내기는 이
`attributes` 를 그대로 보여 줍니다.

이제 DB 기록은 콘솔 로그와 같은 규칙으로 만들어집니다.

- `json.Marshaler` 가 아닌 error 는 콘솔과 같이 `Error()` 문자열로 적습니다.
  스스로 JSON 표현을 가진 error 는 콘솔도 그 결과를 적으므로 그대로 둡니다.
- `slog.LogValuer` 를 구현한 값은 풀어서 적습니다. 콘솔도 풀어 적습니다.
- `slog.Group` 은 중첩된 객체로 적습니다. 전에는 `[{"Key":…,"Value":{}}]`
  같은 내부 표현이 그대로 저장됐습니다. 키 없는 그룹은 콘솔과 같이 부모에
  펼치고, 빈 그룹은 콘솔과 같이 적지 않습니다.
- 문자열·정수·실수·bool·시각·소요 시간·`trace_id` 추출은 달라지지 않았습니다.
  전부터 올바르게 저장되던 값입니다.

## 관리자에게 달라지는 점

올린 **뒤에 기록되는** 로그부터 원인 문자열이 보입니다. 로그 화면의 속성과
CSV 내보내기 파일 모두 같은 값입니다.

**이미 저장된 행은 그대로 `{}` 입니다.** 지나간 기록을 다시 채워 넣는 작업은
하지 않습니다 — 원래 값이 어디에도 남아 있지 않으므로 복원할 수 없습니다.
그래서 올리기 전 기간의 장애를 조사하실 때는 전과 같이 콘솔 로그를
보셔야 합니다.

로그 화면의 검색은 전과 같이 **메시지**만 찾습니다. 속성에 들어간 원인
문자열은 검색어로 걸리지 않습니다. 등급 거르개, 기간 거르개, 정렬 순서,
`trace_id` 로 한 요청의 로그를 모아 보는 동작도 그대로입니다.

## 그 밖에 바뀌는 것은 없습니다

- **마이그레이션은 없습니다.** `system_logs` 의 스키마, API 응답의 형태,
  CSV 의 열 구성은 그대로입니다. 달라지는 것은 `attributes` 안에 담기는 값뿐
  입니다.
- 로그를 남기는 자리를 새로 추가하거나 지우지 않았습니다. 어떤 등급의 로그가
  언제 남는지는 전과 같습니다.
- 시각(`time.Time`) 속성은 콘솔이 밀리초, DB 가 나노초까지 적습니다. 이번에
  확인했고 일부러 맞추지 않았습니다 — 저장 쪽이 더 정밀하고, 줄이면 이미
  저장된 행과 새 행의 정밀도가 달라집니다.
- `logger.With(...)` 로 handler 에 미리 붙인 속성은 전과 같이 DB 행에 담기지
  않습니다. 서버 안에 그 호출자가 없어 이번 범위에 넣지 않았습니다.

## 확인

- 손으로 만든 handler 없이 **프로덕션 handler** 를 `slog.New` 에 꽂고 레코드
  **한 번**을 적어, 콘솔 버퍼의 JSON 과 DB 큐에 담긴 `attributes` 를 둘 다
  받아 키별로 견주는 검사를 더했습니다. error, `json.Marshaler` 인 error,
  `LogValuer`, 중첩 그룹, 문자열, 정수, bool, 소요 시간, `trace_id` 아홉 개를
  봅니다. 두 번째 검사는 빈 그룹·빈 속성·키 없는 그룹에서 두 기록의 **키
  집합**이 같은지 봅니다.
- 수정 전에는 두 검사가 실패했습니다(`"error": DB={}, 콘솔="상위: 연결 거부"`,
  `"g": DB=[{"Key":"a","Value":{}},…], 콘솔={"a":1,"inner":{…}}`). 수정 뒤
  통과하고, 바뀐 한 줄만 되돌리면 정확히 같은 출력으로 다시 실패합니다. 새
  검사가 바뀐 경로를 실제로 지난다는 뜻입니다.
- 릴리즈 준비에서 `go build ./...`, `go vet ./...`,
  `go vet -tags=integration ./internal/...`, `gofmt -l ./cmd ./internal ./pkg`,
  `go test ./...`(테스트가 있는 19개 패키지 전부 통과, 실패 없음),
  `go test ./internal/observability -race -count=1`,
  `scripts/check-release-docs.sh`, `scripts/check-commit-identities.sh` 를
  실행했습니다.
- 웹 단위 테스트·DB 통합 테스트·브라우저 E2E 는 이번 릴리즈 준비에서 다시
  돌리지 않았습니다. 변경은 Go 패키지 한 파일에서 맵에 담을 값을 고르는
  곳이고, SQL·스키마·CSV 조립 코드는 손대지 않았습니다. 이 셋은 태그를 올린
  뒤 CI 에서 돌아갑니다.
- 실제 PostgreSQL 에 적재되는 고리(`run`)는 이번 검사에서 돌리지 않고 큐에
  담긴 값까지만 확인했습니다. 큐에 담은 뒤 적재까지의 경로는 바뀌지
  않았습니다.

## 올리실 때

v0.260.0 에서 올라오시는 분은 이미지를 바꿔 다시 띄우시면 됩니다.
마이그레이션이나 새 설정은 없고, 필수 환경 변수는 계속 `POSTGRES_DSN` 입니다.

운영 적용은 먼저 한 인스턴스에서 확인한 뒤 확대하십시오. 올린 뒤 오류 로그가
한 건 남는 것을 기다려, 관리자 콘솔 로그 화면의 `error` 속성에 원인 문자열이
보이고 같은 기간을 CSV 로 내보낸 파일에도 같은 값이 들어 있는지 보십시오.
원인이 여전히 `{}` 로 보이거나, 전에는 잘 보이던 문자열·숫자 속성이 비거나
모양이 달라지면 운영 담당자가 확대를 중단하고 v0.260.0 이미지로 되돌릴 수
있습니다. 스키마는 바뀌지 않으므로 되돌린 뒤에도 그 사이에 쌓인 행은 그대로
읽힙니다.

로그 속성을 기계로 읽는 도구를 두셨다면 올리기 전에 한 번 확인해 두십시오.
전에 `{}` 였던 `error` 가 문자열이 되고, 그룹 속성이 배열에서 객체로
바뀝니다. 값의 **타입**이 달라지는 자리이므로, `{}` 를 그대로 기대하던
파서가 있다면 함께 고쳐야 합니다.

## 오프라인 설치

이 릴리즈는 웹 자산과 서버 바이너리를 포함한 Docker 이미지 아카이브로 제공됩니다.

```bash
sha256sum -c kanpic-v0.261.0.tar.gz.sha256
gzip -dc kanpic-v0.261.0.tar.gz | docker load
docker run --rm -p 8080:8080 \
  -e POSTGRES_DSN='postgres://kanpic:password@postgres.internal:5432/kanpic?sslmode=require' \
  kanpic:v0.261.0
```

- 필수 런타임 환경 변수: `POSTGRES_DSN`
- Redis 및 외부 인터넷 연결: 불필요
- 관리자 초기 로그인을 보호하려면 `BOOTSTRAP_ADMIN_ID`와 `BOOTSTRAP_ADMIN_PASSWORD`를 함께 지정합니다.
- 무결성 검증 파일: `kanpic-v0.261.0.tar.gz.sha256`
