# Invenqor 프로필 (2026-10-09)
- 목적: Rust Agent가 호스트·프로세스·소프트웨어를 수집하고 Go Server·React 콘솔·REST·MCP로 IT 자산을 관리한다.
- 기준: 현재 체크아웃 main@16f2592, v0.2.46. 과거 완료 기록보다 현재 소스와 병합 이력을 우선한다.
- 스택: Rust 1.85, Go 1.25.14(chi·go-oidc·pgx·modernc sqlite), PostgreSQL 기본/명시적 SQLite 폴백, React 19·TypeScript·Vite 7·Vitest.
- 구조:
  - src/, tests/, Cargo.toml: Rust Agent 수집·전송·업데이트·테스트.
  - server/cmd/invenqor-server: 서버 진입점; server/internal/httpapi: REST·MCP·콘솔 핸들러와 라우터 테스트.
  - server/internal/{storage,storagetest,auth,apikeys,ingest,softwarecatalog,mail,tracking,updates,agents,audit,querydsl}: DB·인증·수집·운영 서비스.
  - server/migrations/{postgres,sqlite}: 두 방언의 같은 순번 마이그레이션. PostgreSQL 관계 양 끝점은 UUID, SQLite는 TEXT.
  - web/src: React 콘솔; web/scripts/sync-embedded.mjs가 빌드 결과를 server/internal/webui/dist에 동기화.
  - openapi.yaml: 공개 REST 계약; MCP 도구 스키마는 httpapi/mcp.go:mcpTools.
  - docs/: 역할별 Markdown·PDF·릴리즈 노트와 Pages 발행 소스; scripts/: DB 검사·Pages 빌드·문서·패키징·e2e.
  - .github/workflows/ci.yml: 두 DB·web·Rust·의존성 감사·e2e. Pages 빌드 스크립트 연결 없음.

- 자주 깨지는 곳:
  - PostgreSQL JSONB 연산·파라미터 타입 추론·대소문자·UUID와 SQLite 차이. SQLite 통과만으로 운영 DB를 보장하지 않는다.
  - assets.go:712 canonicalUUID는 36자 하이픈형만 허용하고 소문자 반환. REST 자산 상세·관계 생성/삭제·merge/split와 제안 관계 심사에 사용(일부는 이전 정찰 기록).
  - mcp.go:693 mcpAssetGet, :773 mcpAssetRelations는 UUID 선언에도 입력을 SQL에 직접 전달. 이번 과제는 이 두 곳만 검증·정규화.
  - mcp_arguments.go:String은 앞뒤 공백을 제거하고 수·bool을 문자열로 변환한다. RequiredString은 UUID format을 검사하지 않는다. 이번 수정에서 이 공용 동작을 변경하지 않는다.
  - MCP 핸들러 error는 writeMCPToolError로 HTTP 200 + result.isError=true. REST의 HTTP 500 설명을 그대로 적용하지 않는다.
  - assets.go:assetHistory/assetRelations는 rows.Err() 검사 없음. 과거 Runtime 반복 오류 재현 실패 때문에 이번에도 미선택.
  - mergeAssets의 missingAssetID 외 오류는 선행 rollback 없음; 실제 SQLite 교착 재현은 미확인. metadata에 중복·자기 secondary도 남음.
  - deleteAssetRelation은 관계 ID만 UPDATE 조건에 사용. 콘솔은 inbound/outbound 둘 다 현재 자산 아래 표시·삭제한다.
  - REST assetRelations와 MCP mcpAssetRelations는 valid_from을 any 그대로 응답. 실제 양 DB 날짜 파싱 결함은 미확인.
