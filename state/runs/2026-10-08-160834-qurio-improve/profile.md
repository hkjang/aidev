# Qurio 프로필 (2026-10-08)
- 기준: main cbbf578, VERSION 1.4.14. 이전 afd3882 이후 feb607a(reasonSet)와 v1.4.14 릴리즈가 머지됨. 이전 프로필의 'main에 reasonSet 없음'은 폐기.
- 목적: 오프라인 사내망용 AI SQL 워크벤치·데이터 카탈로그로 승인·감사·MCP/REST API를 제공한다.
- 스택: Go(go.mod 1.26.6, 이번 로컬 1.26.7), pgx/v5·PostgreSQL 17·pure-Go Oracle, React 19·TypeScript·Mantine·Vite·TanStack Query, Vitest·Playwright.
- 구조:
  - cmd/qurio — 서버 실행과 설치/마이그레이션 통합 테스트, 폐기 DB bootstrap.
  - internal/httpapi·oidcauth·mcpoauth — HTTP·세션·OIDC·OAuth 경계.
  - internal/store — 설정·계정·키·승인·감사 영속화.
  - internal/domain/{dbexec,legacy,sqlsafe} — DB 실행·SQL 정책·스키마 탐색; dbexec 정책 파일은 policy.go.
  - internal/{legacyapi,platformapi,runtimeapi,agentapi,intelligenceapi} — 기능별 API.
  - internal/{jobs,backup,integrations,authn,cryptox,config,runtimeenv,version} — 배경 작업·보조 서비스.
  - migrations — 임베드 SQL 마이그레이션, 새 번호만 추가; internal/webui/dist — 임베드 SPA.
  - web/src — React; lib/api.ts — 공유 HTTP/SSE 클라이언트; web/e2e — Playwright.
  - docs — architecture/requirements/legacy-compatibility/guides; scripts — 개발·릴리즈·오프라인 검증.
- 빌드·테스트:
  - make build: npm ci → SPA build → 임베드 자산 복사 → Go build(느림·출력 파일 변경).
  - make lint: 읽기 전용 gofmt 검사 → go vet → 웹 lint/typecheck. CI는 make lint를 직접 호출하지 않음.
  - make test-go / go test ./...; make test-web / npm test --prefix web -- --run.
  - 표적 웹: npm test --prefix web -- --run src/lib/api.test.ts; npm run typecheck --prefix web.
  - make test-e2e: 브라우저 필요·느림. -tags=integration은 별도 DB 필요.
  - npm pretest는 web/scripts/ensure-deps.mjs로 Vitest 부재 시 npm ci를 실행한다.
- 관례: 영어 conventional commits, UI/가이드에 한국어. 설정 env는 POSTGRES_DSN·BOOTSTRAP_ADMIN·BOOTSTRAP_ADMIN_PASSWORD·ENCRYPTION_KEY 네 개만; 나머지는 DB.

- 자주 깨지는 곳:
  - PostgreSQL 별칭/CTE 면제는 fail-open 회귀가 반복됨. AS 분기의 무조건 면제는 남지만 실제 악용 질의 미확인.
  - Oracle WITH 컬럼 목록 면제는 아직 없음; 3bf8799 미머지 원인에 관한 기록의 확정/추정 표현이 엇갈려 재제출 전 확인 필요.
  - reasonSet 성능 수정은 이제 머지됨. Reasons 상한은 없어 응답 증폭은 별도 후보(약 8MB는 이전 회차 실측, 이번 미측정).
  - 웹 응답 레이스 3파일은 기존 수정 머지됨. 나머지 전수 감사 미완료; 과거 결정적 프로브는 500ms 필요했고 50ms는 놓침.
  - 새로 재현: api.ts parseServerSentEvents가 정상/예외 모두 reader 잠금을 남기며, 서버 error·콜백 예외에서 열린 source를 취소하지 않음. 이번 과제.
  - login 목적지는 LoginPage와 App PublicOnly 두 경로가 계산하므로 한쪽만 고치는 과거 접근을 반복하지 않는다.
  - 픽스처: defer pool.Close와 t.Cleanup 정리가 섞이면 종료 순서 오류. 단순 defer 검색 결과를 결함 개수로 세지 말 것.
  - advanced_integration_test.go는 cleanup도 defer라 순서가 정상. 'DELETE 미등록 3파일'은 현재 코드와 어긋남(repository/publication은 t.Cleanup, agent_instructions는 defer DELETE).
  - credential_race 및 platformapi 공유 DB 잔존행 결함은 재현이 엇갈림; 이번 DB 검증 미실시.
- 검증 함정:
  - CI는 PostgreSQL 17에 POSTGRES_DSN·QURIO_INTEGRATION_DSN·QURIO_TEST_POSTGRES_DSN을 같은 폐기 DB로 지정하고 bootstrap 후 -race -p=1 -tags=integration 실행.
  - ci.yml·release.yml 전체 통합 실행에 여전히 -count=1 없음; CI test job timeout-minutes도 없음. 보호 경로라 과거 미머지 이유 확인 전 재선정 금지.
  - dbexec는 QURIO_TEST_POSTGRES_DSN 전용·연결 실패 Fatal; store 등은 POSTGRES_DSN/기본 포트와 Skip 관례. intelligenceapi 일부도 전용 DSN을 쓰므로 'dbexec만 전용'이라고 단정하지 말 것.
  - 일반 Go 테스트에도 DSN을 요구하는 intelligenceapi/repository_test.go 사례가 있음. 태그만 보고 모든 DB 의존 테스트가 제외된다고 단정하지 말 것.
  - release는 Oracle live도 실행하나 이번 정찰은 Oracle/DB 환경 미확인. sqlsafe 변경에는 방언별 현실 질의 판정 비교가 필요.
  - web의 실제 객체/공개 API 배선으로 검증하고 parser helper 대역·소스 문자열 검사만으로 증명하지 말 것.
  - agent/legacy SSE는 error 이후 done을 소비하는 계약. 파서가 이벤트 이름만 보고 취소하면 회귀한다.
  - 이번 환경: Node v22.23.1, CI Node 26. node_modules 없음. 저장소 밖 쓰기 제약 때문에 npm 설치/전체 스위트 미실행.
