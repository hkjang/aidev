- 결과: 성공
- 요약: Hunter 는 표준의 형식 표에 행이 없어 "이 저장소가 맡은 칸"이 명시돼 있지 않다. Hunter 가 이미 내보내는 문서는 에이전트 실행 보고서(MD·HTML·PDF)이고 들이는 것(SARIF·JSON 진단 결과·SBOM)은 표준 어휘에 없으므로, **보내는 쪽 `markdown` 하나만** 온전히 만들고 받는 쪽은 만들지 않았다(반쯤 된 양쪽보다 완성된 한쪽). 표준의 이름·모양·코드를 그대로 따랐다: `POST /api/v1/handoff/claims` `{"resource":<실행 ID>,"format":"markdown"}` → `201 {claim,source,filename,content_type,bytes,expires_at}`(256비트 난수, 5분, 다운로드와 같은 `reportRun` 권한 검사로 읽을 수 없는 실행은 404, 형식 오류 400), `GET /api/v1/handoff/claims/{claim}` 은 로그인 없이 `DELETE … RETURNING` 으로 한 번만 내주며(`text/markdown; charset=utf-8`, `Content-Disposition: attachment; filename*=UTF-8''…`, `no-store`) 사용됨·만료·미발급을 모두 같은 404 로 답한다. 본문은 발급 시점에 만들어 암호화 저장(`handoff_claims`, 표는 SHA-256 다이제스트만), 만료 행은 다음 발급 때 정리, 감사(`agent.handoff`)에는 실행 ID·바이트 수만, 패닉 로그 경로는 `{claim}` 으로 마스킹. 허용 목록은 추적 설정과 같은 자리인 설정 그룹 `handoff.targets`(이름·오리진·받는 형식, `trackingOrigin` 으로 정규화, 중복·경로·와일드카드 거절, 최대 20)로 두고 **기본값은 빈 목록** — 그때는 `GET /api/handoff/targets` 가 빈 배열을 주어 보고서 메뉴에 보내기 항목이 없고 `POST` 도 404 로 거절하므로 새 설치는 달라지지 않는다. `markdown` 을 받지 않는 서비스(kanpic)는 저장돼도 메뉴에 오르지 않는다. 화면: 실행 상세 **실행 보고서** 메뉴 아래 "다른 서비스로 보내기 → 서비스 이름"(클릭 안에서 창을 먼저 열고 opener 를 끊은 뒤 표를 받아 `origin/handoff?source=…&claim=…` 로 이동, 팝업 차단 안내), 서비스 설정 새 탭 "다른 서비스로 보내기"(행 추가·삭제, 형식 MultiSelect, markdown 없으면 경고, 받는 쪽에 알려 줄 Hunter 오리진 표시). 관리자 가이드 §5.7(흐름·허용 목록 설정·API 예시·확인 절차·경로 표)와 설정 표, 사용자 가이드 §10.8, README, llms.txt, openapi.json(경로 3개·스키마 4개·settings group enum) 갱신, html/pdf 재생성. 검증: `go vet ./...`, 임시 PostgreSQL 17 컨테이너로 `go test -race ./...`(새 테스트 3개: 설정 검증 10가지 거절·정규화, 파일명·RFC 5987·로그 마스킹, 통합 테스트로 기본 404·형식 표 필터·CSRF·남의 실행 404·표 1회·만료 404·감사에 표 없음·만료 행 정리·열람자 403), `npm test`(90 통과), `tsc`·`vite build`, `node scripts/render-guides.mjs`·`check-docs.mjs` 통과. 빌드한 서버를 실제로 띄워 playwright chromium 으로 목록이 비었을 때 메뉴에 항목이 없고, 설정 화면에서 Ptium 을 저장하면 항목이 생기며, 클릭 시 새 창이 `https://ptium.intra/handoff?source=http%3A%2F%2Flocalhost%3A8080&claim=…` 로 열리고(받는 쪽은 route 스텁), 그 표로 curl 하면 200·올바른 헤더·보고서 본문, 두 번째는 404, 감사 기록에 표가 없음을 확인했다.
