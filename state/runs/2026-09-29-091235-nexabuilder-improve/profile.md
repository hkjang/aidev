# nexabuilder 프로필 (2026-09-29)
- 목적: 엔티티·폼·목록·워크플로 메타데이터로 업무 화면을 만드는 Spring Boot 로우코드 플랫폼과 관리 콘솔.
- 스택: Java21, Spring Boot4.1.1, Gradle8.14.3 Kotlin DSL, JPA/JdbcTemplate, Liquibase XML, 기본 H2, Thymeleaf/Bootstrap/htmx/jQuery4+migrate/jqWidgets/ECharts, Groovy, POI5.3.0/OpenPDF3.0.5. 기준 master@c446d24, v1.26.0.
- 구조:
  - `core/ui/NexaUiService` — 목록/폼 정의와 데이터. requireLiveList가 정의·데이터·어댑터·내보내기의 목록 soft-delete 판정을 공유한다. requireLiveEntity는 엔티티 짝. formDefinition은 includeInactive별 인라인 판정.
  - `core/ui/NexaUiService.listData` — 복사한 params에서 `_offset`/`_limit`을 추출, 없는/비양수 limit은 page_size(null→100), 상한 MAX_FEED_ROWS=5000. SQL 분기에는 정규화한 두 값을 되돌려 바인딩. 기본값 상향 금지.
  - `core/data/DataAdapterService` — jqxgrid `{Rows,totalCount}`. queryList는 requireLiveList 후 SQL/엔티티 분기. 엔티티는 DB 페이징, SQL은 전체 조회 후 lowerCaseKeys→정렬→자바 페이징. parse의 pagenum 하한0/pagesize fallback·상한1000, offset은 long 계산(이전 회차 확인).
  - `core/entity` — EntityService 동적 DML/조회, SchemaDdlService DDL, RecordSet 행 컬렉션은 불변(이전 회차 확인). 모든 filters 키가 SQL 조건이므로 프로토콜 키 제거는 호출자 책임.
  - `core/sql` — SqlExecutor 공유 SQL 실행, SqlPagination DB별 페이징. SqlExecutor/RecordSet 계약은 Groovy·워크플로 등도 공유하므로 변경 주의.
  - `api/controller/ListExportController` — GET `/api/v1/lists/{listId}/export.csv|xlsx|pdf`. resolveExportable는 목록 생존+canView 검사. readQueryParams는 `_limit`이 없을 때 MAX_FEED_ROWS를 주입함(v1.26.0에서 해결). 명시 limit은 존중, listData 상한 유지.
  - `api/controller/UiBuilderController`, `DataAdapterController` — builder 응답은 ApiResponse, 어댑터 행 응답은 별도 봉투. 목록 데이터 메서드에는 ScreenPermissionService 호출이 없음; 전체 보안 정책은 이번 미확인.
  - `resources/templates/runtime` — 목록 그리드 및 7개 대체 뷰. chart/pivot의 데이터 요청 catch는 여전히 실패를 빈 데이터로 처리. `admin/list-designer.html`은 저장 시 entityId 필수라 SQL 단독 목록 편집 제약이 남음.
  - `core/*` — auth/session/permission/audit/llm/menu/report/version 등; `resources/db/migration`은 Liquibase(이전 프로필 001~079, 이번 개수 재집계 안 함).
  - `src/test` — SpringBootTest/MockMvc/H2 통합 테스트 중심. 실제 리포지토리·DDL·POI 등을 연결하는 픽스처. docs는 사용자·관리자·개발자·운영·API 가이드.
- 빌드·테스트:
  - `sh ./gradlew --no-daemon test --tests 'com.nexabuilder.api.ListExportIntegrationTest'` — 이번 정찰 실제 성공 25초, 9건/실패0/skip0.
  - `sh ./gradlew --no-daemon test` 또는 강제 `sh ./gradlew --no-daemon cleanTest test` — 전체 수 분. 직전 회차 605건 통과 기록, 이번 전체 미실행. 테스트 힙 2g.
  - `sh ./gradlew --no-daemon bootJar -x test` — CI 패키징 명령. 이번 미실행, 직전 회차 성공 기록.
  - gradlew는 git 모드100644라 sh 경유. CI는 chmod 후 직접 실행하며 setup-java Temurin21을 사용. 로컬에는 javap가 PATH에 없지만 Gradle JDK21의 bin에 있음.
- 관례: Lombok 생성자 주입, 테스트 UUID8 접미사·seed()/record Fixture·정리 없음. 한국어 type(scope) 커밋, 영어 버전/merge 커밋. 설정은 application.yml+nexa_config, 마이그레이션은 XML+master include(이전 프로필).
- 위험 구역: core/auth·session·permission, infra/security, DB migration, .github/workflows, workflow 종료/감사 경합. 이번 과제는 exportXlsx와 기존 테스트 한 파일로 제한.
- 자주 깨지는 곳: @DirtiesContext로 컨텍스트 재생성/힙/종료 경합; 같은 값을 읽는 복수 경로의 파라미터·삭제·키 대소문자 계약 불일치. jqWidgets는 jQuery-migrate 호환 계층 필요. 수정 범위를 공유 라이브러리 계약으로 넓히지 말 것.
- 검증 함정:
  - `/data/*` 성공은 `{Rows,totalCount}`, builder는 `{success,data,total}` 계열이며 실패 봉투는 다르다. 어댑터는 pagenum/pagesize, builder·내보내기는 `_offset`/`_limit`.
  - 내보내기 통합 테스트는 @WithMockUser와 sessionAttr("nexabuilder.user", User) 둘 다 필요. PDF 글리프는 환경 폰트 의존, 기존 테스트는 PDF magic만 검증.
  - XLSX는 listId를 그대로 createSheet에 전달한다. 실제 POI5.3.0에서 sales:2026은 IllegalArgumentException, WorkbookUtil.createSafeSheetName 후 성공. 긴 ID는 POI가 이미 31자로 자름. HTTP 실패 상태는 아직 미확인(이번 과제).
  - 컴파일은 Jackson2JsonConfig:57의 removal 경고 및 일부 deprecated/unchecked 경고를 출력. 테스트 외부 서비스 의존 전체 조사는 이번 미실시.
  - README의 JDK17/Boot3.4.4 배지, agent.md의 Windows 고정 경로·Git 저장소 아님, deployment.md의 JDK17 Docker 예시는 현재 코드와 어긋남. docs/roadmap.md도 v1.2.x 기준. 명령과 버전은 build.gradle.kts/CI를 기준으로 확인.
