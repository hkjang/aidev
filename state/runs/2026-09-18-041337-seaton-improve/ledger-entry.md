## 2026-09-18
- 선택: 캠페인 mcp-oauth-2026-09 — MCP 를 Keycloak 액세스 토큰(OAuth 2.1)으로도 열기 (가치 5 / 위험 2 / 작업량 M)
- 결과: 성공 (커밋 efc4874)
- 요약: 이 저장소는 사용자별 계정(users, source local/oidc)과 Keycloak 웹 로그인이 있고 go-oidc 를 이미 쓰므로 캠페인 대상이다. MCP-OAUTH-STANDARD 를 따라 `internal/app/mcpoauth.go` 한 파일에 메타데이터·401 도전·토큰 검증·계정 매핑을 두고, settings 에 표준 이름 그대로 `mcp.oauth.enabled`(기본 false)·`resource`·`audience`·`scopes`(기본 `read mcp`) 네 키를 시드했으며 `oidc.issuer_url` 을 재사용했다. **고른 것과 이유** — (1) 설정 자리는 다른 설정과 같이 settings 테이블 + 시스템 설정 화면(환경 변수 없음), Keycloak SSO 탭 아래 카드 하나. (2) 리소스 식별자 출처: 이 저장소에는 `server.public_url` 류가 없어 `mcp.oauth.resource` 를 두고, 비면 표준의 마지막 수단대로 요청의 `X-Forwarded-Host/Proto`(requestBaseURL, 웹 로그인 콜백과 같은 규칙)로 만든다. 저장 시 `/mcp` 로 끝나는 절대 URL 만 받는다. (3) 대상 검사는 aud 에 리소스 식별자, 또는 aud/azp 가 `mcp.oauth.audience` 에 — weekly 와 달리 `oidc.client_id` 를 암묵적으로 허용 대상에 넣지 않았다(표준의 Keycloak 절이 웹 로그인과 다른 공개 클라이언트를 요구하고, 숨은 세 번째 규칙은 거절 문장과 문서를 복잡하게 함). (4) 계정 매핑: users 에 oidc_subject 열이 없고 웹 로그인이 `preferred_username→email→"oidc-"+sub` 로 username 을 정하므로 같은 규칙으로 찾되 `source='oidc' AND active` 를 요구했다 — 이름이 같은 로컬 관리자 계정이 토큰으로 열리지 않는다. (5) 범위는 관리자 설정이 천장이고 토큰 scope 에 read/write/mcp 가 실려 오면 교집합, 아니면 그대로. mcp 핸들러의 기존 `mcp`·`write` 범위 검사와 authenticate 의 CSRF 면제를 키와 똑같이 지난다. (6) 거절은 `mcpOAuthRefusal{status,code,message,cause}` 하나로 모아 `refuseMCPToken` 한 곳에서 응답과 로그(`mcp oauth token rejected` + cause)를 함께 낸다 — 캠페인 규칙(원인 로깅)을 테스트로 고정했고 ADMIN_GUIDE 도 그 로그 이름을 적었다. discovery 실패는 401 이 아닌 `503 sso_unavailable`(도전 헤더 없음)로 두어 클라이언트가 로그인 루프에 빠지지 않게 했다. 켜기 조건(issuer·범위에 mcp)은 저장 시점에 `400 invalid_setting` 으로 거절한다. 검증: go test(가짜 IdP 가 실제 RSA 키 쌍으로 JWT 서명 — 메타데이터 on/off·CORS·맨 JSON·끝 `/` 제거, 도전 헤더는 /mcp 401 에만, 꺼짐/REST 에서 토큰 무시, 대상·만료·nbf·다른 issuer·다른 키·HS256·typ=ID·cnf·sub 없음 각각 거절과 로그 원인, 503, 범위 교집합, 설정 검증, JWT 모양)·vet·gofmt, tsc, vitest 104건(새 mcpOAuth 4건), docker 이미지 + PostgreSQL + Node 가짜 Keycloak(discovery·JWKS·authorize·token, 실제 RSA 서명)으로 Playwright 51건 전부 통과 — 새 `mcp-oauth.spec.ts` 4건이 실제 라우팅·DB 를 지나 웹 SSO 로그인으로 등록하기 전엔 `401 account_not_registered` 이고 계정도 생기지 않음, 브라우저로 SSO 로그인한 뒤 같은 사람의 토큰이 tools/list·search_employees 를 엶, 다른 앱 토큰은 azp 와 리소스를 말하며 거절, 허용 대상에 적으면 매퍼 없이 통과, REST 401, 비활성 401, 끄면 404 와 원래 401 을 확인. 서버 로그에서 cause 가 실제로 남는 것을 봤다. 호스트 8080 을 다른 세션이 쓰고 있어 브리지 네트워크 + `--add-host` 로 돌렸고, spec 은 `E2E_COLLECTOR_HOST` 가 127.0.0.1 이 아니면 Chromium host-resolver-rules 로 같은 이름을 127.0.0.1 에 붙인다(CI 의 --network host 는 기본값 그대로). 실제 Keycloak·Claude 클라이언트는 이 환경에 없어 가짜 IdP 로만 확인했다.
