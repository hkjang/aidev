# jasql 프로필 (2026-09-21)
- 목적: KCB JSON 메타데이터를 카탈로그·검색·조인그래프·가드레일로 컴파일해 NL2SQL MCP/REST/웹 콘솔과 읽기 전용 Oracle 실행을 제공한다. 기준 e9f3fb2, v0.31.0.
- 스택: go.mod Go 1.25.0; 로컬 Go 1.26.7; Dockerfile 빌더 Go 1.26. godror(oracle 태그), pgx PostgreSQL 메타 DB, x/crypto. 프런트는 go:embed 정적 HTML/JS.
- 구조:
  - cmd/jasql-mcp: 서버 CLI; cmd/jasql-eval: 골든셋 평가; cmd/jasql-goldgen: 골든셋 생성.
  - internal/catalog: 로드·검색·조인·SQL 검증·스켈레톤·시간 파싱·시멘틱·템플릿. mcp 비의존.
  - internal/mcp: HTTP/stdio 도구 42개, REST, 인증/SSO/OAuth, 실행 가드, 개인화; webui에 콘솔 자산.
  - internal/meta: 메모리/PostgreSQL 저장소, 사용자·세션·프로파일·설정 등.
  - internal/oracle: 프로파일·연결 풀·브레이커·실행·취소·SQL 가드·실행계획; 기본 빌드는 stub.
  - data/kcb: 실제 메타데이터·골든셋; 테스트가 읽으므로 수정 금지.
  - docs: 한국어 가이드 정본, reports에는 운영/경영 보고서와 확산 로드맵; scripts에는 빌드·이미지 릴리즈.
- 빌드·테스트: `go build ./...`, `go vet ./...`, `go test ./...` 정찰에서 모두 통과. catalog 55초, mcp 9.6초. 부분 검증 `go test ./internal/catalog ./internal/mcp -run 'Test.*(Time|Calendar)' -count=1`.
- 관례: 영어 명령형 커밋과 한국어 PR 머지 제목. 버전은 server.go/OpenAPI·README/배포 문서 동기화. 설정은 flag/env/메타 DB settings. DB 스키마는 internal/meta/pg.go(세부 변경 절차 이번에 미확인).
- 관례: 로드 후 카탈로그 불변, 새 컴파일 결과로 원자 교체. 변경 테스트는 t.TempDir JSON 픽스처를 catalog.Load로 로드. 새 도구 추가 시 stdio_test.go의 42개 단정 갱신.
- 위험 구역: internal/mcp/auth.go·oauth.go·authapi.go(세션·리다이렉트·권한), execguard.go·internal/oracle/sqlguard.go(읽기 전용 정책), dbapi.go(비밀번호/소유권), internal/meta/pg.go(스키마), 전역 카탈로그 mutation(admin-only).
- 자주 깨지는 곳: 누적 반복 실패 기록 없음. 검증 SQL과 실행 SQL의 trailing 주석/세미콜론 해석 차이는 전회 성공 기록이 있으나 현재 pinned HEAD에는 TrimStatement가 없다. 기록과 소스 불일치이므로 중복 구현하지 않는다.
- 검증 함정: Oracle 기본 빌드는 driverAvailable=false; 실제 Oracle 실행은 로컬 기본 테스트로 증명 불가. PostgreSQL TestPGStore는 JASQL_TEST_PG 미설정 시 skip하므로 전체 통과가 실 DB 검증을 의미하지 않는다.
- 검증 함정: .github/workflows 및 저장소 CLAUDE.md/AGENTS.md 없음. docs/development.md의 Go 1.24+, 외부 의존성 0/go.sum 없음, 도구 24개는 현재 소스와 불일치한다.
- 검증 함정: stdio 기동에서 실데이터 190 tables/118 relations/7583 examples/6 metrics와 relation 참조 오류 5건을 관찰했다. 기동은 계속되며 영향 메타데이터는 무시/열화된다는 로그가 나온다. 테스트 통과가 데이터 오류 0건을 뜻하지 않는다.
- 이번 정찰: 불가능한 숫자 날짜 2025-02-30이 resolve_time에서 BIRTH_DT = '20250230'으로 출력되는 것 재현; 공통 ParseTimeExpressions 달력 검증을 선택.
