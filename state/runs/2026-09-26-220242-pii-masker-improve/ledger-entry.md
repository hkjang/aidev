- 요약: `httpClient()`의 `CheckRedirect`가 `c.checkURLAllowed(request.URL)`로 호스트만 검사하고 스킴을 보지 않아서, `https://`로 나간 요청이 같은(또는 허용 목록에 있는) 호스트의 `http://`로 리다이렉트되면 그대로 따라갔습니다. `performParseRequest`가 본문을 `*bytes.Buffer`로 넘기므로 Go가 `GetBody`를 채우고 307·308에서 멀티파트 본문을 재전송하니, 마스킹 대상 원문 PII가 평문으로 네트워크에 다시 실립니다. 새 순수 헬퍼 `checkRedirectScheme(first, target *url.URL)`을 더해 `via[0].URL.Scheme`이 `https`(대소문자 무시)인데 대상이 `https`가 아니면 거부하고, 기존 `checkURLAllowed` 호출은 그 뒤에 그대로 남겼습니다. 거부 사유는 `blockedHostError`와 섞지 않고 별도 `fmt.Errorf("refusing to follow a redirect from https to %s", …)`로 두어 진단이 "차단된 호스트"로 오인되지 않게 했고(`classifyRequestError`에서 `network_error`로 떨어짐), 검사를 "최초가 https일 때만"으로 한정해 내장 mock의 http 체인은 영향이 없습니다. 검증은 프로덕션 배선인 `client.httpClient().CheckRedirect` 클로저를 직접 호출하는 테이블 테스트 5건(https→https 허용 / https→http 동일 호스트 거부 / http→http 허용 / http→https 허용 / `HTTPS://` 대문자도 거부, 거부 시 `errors.As(err, &blockedHostError{})`가 false임까지 단언)으로 했고, 정찰 지시대로 `httptest.NewTLSServer`는 쓰지 않았습니다(기본 Transport라 자체 서명 인증서 검증 실패로 원인이 흐려짐). 기존 `TestParseDocumentFollowsRedirectToAllowedHost`·`TestParseDocumentRejectsRedirectToDisallowedHost`가 무수정 통과하고 `internal/app` 통합 테스트도 통과합니다. `gofmt -l ./cmd ./internal`(무출력)·`git diff --check`·`go vet ./...`·`go build ./...`·`go test -count=1 ./...`(전부 ok)·`go test -race -count=3 ./internal/upstage ./internal/app`(ok 2.5s/2.4s) 전부 통과, 프로덕션 파일 1개(`internal/upstage/client.go`)에 README 한 문단만 추가했습니다.
