# 수리 요약 — PR #20, 커밋 943feab

1. **Host 폴백 제거**: `mcpOAuthState()` 가 더 이상 `*http.Request` 를 받지 않는다. resource 설정도 Redirect URI 도 없으면 `st.Reason` 을 채워 SSO 비활성(토큰은 키 경로로 떨어져 401 `invalid proxy API key`, 챌린지 헤더 없음, `/admin/mcp/oauth` 는 `active=false`+reason). `settingDescriptions[mcp.oauth.resource]`·ADMIN_GUIDE 표의 '요청 Host(마지막 수단)' 문구를 "받지 않는다"로 고침. 테스트 `TestMCPOAuthNeverDerivesTheResourceFromTheRequestHost`: RedirectURI 빈 하네스에서 listener 주소·`Host: attacker.example`·`X-Forwarded-Host/Proto` 세 경우 모두 aud 일치 토큰이 401, resource 를 적으면 Host 와 무관하게 200.
2. **request_id 로그**: 거부 `slog.Warn` 에 `request_id=traceIDFromRequest(r)` 추가(withTrace 가 요청 헤더에 고정한 값이라 응답 `X-Request-ID` 와 동일). `TestMCPOAuthRefusalLogsTheCause` 가 모든 케이스에서 비어 있지 않은 `request_id=` 가 응답 헤더와 같음을 단언하고, `X-Request-ID: req-mcp-oauth-42` 를 실은 케이스가 그대로 찍히는지 확인.
3. **OIDC 캐시 락**: `keycloakDiscover`/`keycloakJWKSKey` 는 락 안에서 조회·저장만, fetch(`fetchDiscovery`/`fetchJWKS`)는 락 밖에서 요청 ctx 로. TTL 경과 항목은 즉시 반환 + 백그라운드 1회 갱신(refreshing 플래그로 중복 방지, 실패 시 기존 값 유지·경고 로그). negative cache 30초: 실패한 fetch(ctx 취소는 제외)와 "최근 30초 안에 받은 JWKS 에 없는 kid"(미지 kid 폭주가 요청당 1회 fetch 가 되지 않음; 회전 직후 30초 창은 감수). 새 `keycloak_cache_test.go` 6개: 진행 중 fetch 를 기다리지 않는 캐시 히트, TTL 경과 항목 즉시 반환+백그라운드 갱신(JWKS·discovery), 미지 kid·실패 discovery negative cache, ctx 취소 준수.
4. 검증: 새 테스트 7개 모두 수정 전 실패(red) 확인 → 수정 후 `go vet ./... && go build ./... && go test ./... -count=1` 통과, `go test -race ./internal/proxy -run 'TestKeycloak|TestMCPOAuth' -count=3` 통과, `go run ./cmd/api-surface-audit` 이상 없음.
