Invenqor Server·Agent v0.2.26 릴리즈 노트

릴리즈 일자: 2026-09-08 호환 Agent: v0.2.26 (Linux·Windows)

이번 릴리즈는 제품 동작을 바꾸지 않습니다. 바뀐 것은 검증입니다 — 프로그램이 API Key로 외부 API를 호출할 때 지나는 경로 전체가 지금까지 테스트에서 한 번도 실행된 적이 없었습니다. 읽기만 되었을 뿐 돌아간 적이 없는 코드였고, 이번 릴리즈는 그 경로를 테스트로 고정합니다.

1. API Key로 외부 API를 호출하는 경로에 테스트가 없었습니다

/api/v1/external/*는 사람이 콘솔에서 쓰는 입구가 아니라 프로그램이 자격 증명 하나로 쓰는 입구입니다. 그 자격 증명이 지나는 단계 — 401과 그 응답이 달고 나가는 challenge 헤더, 키별 유량 제한, scope 검사, 감사 로그에 남는 이름 — 가운데 어느 것도 테스트에서 실행되지 않았습니다. 세 가지를 고정했습니다.

  • 유량 제한은 키마다 따로 셉니다. 한도를 넘은 키는 429와 API_RATE_LIMITED, 그리고 Retry-After 를 받습니다. 이 헤더가 없으면 호출하는 쪽에는 기다릴 간격이 없어 즉시 다시 시도하고, 그것은 이 제한이 막으려던 바로 그 동작입니다. 같은 시각 다른 키는 영향을 받지 않고 200을 받으며, 창이 지나면 원래 키도 다시 통과합니다. 재시도 루프에 빠진 통합 하나가 배포 전체의 다른 프로그램에게 429를 돌려주는 일이 없다는 뜻입니다.
  • 쓸 수 없는 자격 증명은 자격 증명 문제로 거절합니다. 키가 아예 없는 경우, 우리 키가 아닌 값, 우리 접두사에 모르는 비밀값, 그리고 폐기된 키 모두 401과 INVALID_API_KEY, WWW-Authenticate를 받습니다. 빈 목록으로 답하지 않습니다 — 빈 목록은 호출하는 쪽에서 “그곳에 아무것도 없다”로 읽힙니다. 폐기는 만료가 아니라 다음 요청부터 듣습니다.
  • 키는 발급 시 고른 scope까지만 합니다. 읽기 전용 키의 쓰기는 403과 FORBIDDEN으로 거절되고, 허용된 쓰기는 감사 로그에 소유자가 아니라 api-key:<이름> 으로 기록됩니다. 통합이 한 일과 그 키를 만든 사람이 한 일이 콘솔에서 구분됩니다.

검증

  • 테스트가 헛돌지 않는지 확인했습니다. Retry-After를 설정하는 줄을 지우고, 유량 제한의 Allow(KeyID)를 Allow("shared")로 바꿔 각각 실패하는 것을 본 뒤 되돌렸습니다.
  • 두 저장 모드에서. go test ./...이 SQLite fallback과 scripts/test-postgres.sh의 실제 PostgreSQL 양쪽에서 전 패키지를 통과하고, go vet·go build·gofmt가 통과합니다.
  • Agent(Rust)와 콘솔 코드, 공개 계약(openapi.yaml)은 이번 릴리즈에서 바뀌지 않았습니다.

호환성

  • 데이터베이스 마이그레이션이 없습니다.
  • API 응답 형식 변경이 없습니다.
  • 동작 변경이 없습니다. 서버와 Agent의 코드는 버전 문자열 외에 바뀌지 않았으므로, v0.2.25에서 올라오는 배포는 이미지·패키지 교체만으로 끝납니다.
