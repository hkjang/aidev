# Invenqor Server·Agent v0.2.28 릴리즈 노트

릴리즈 일자: 2026-09-08
호환 Agent: v0.2.28 (Linux·Windows)

이번 릴리즈는 결함 하나를 고칩니다. 자리는 **Query DSL의 `attributes.*` 등호
(`=`)**이고, 증상은 이전 릴리즈들과 같은 종류 — **오류 없이 받아들여진 뒤 조용히
짧아진 목록** — 입니다. 다만 이번에는 그 목록이 **저장 모드에 따라 달랐습니다.**
PostgreSQL에서는 제대로 답하던 질의가 SQLite fallback에서는 빈 목록이었습니다.

## 1. 속성 등호가 Agent가 보고한 숫자를 한 번도 맞히지 못했습니다

`attributes.*` 절은 자산에 저장된 JSON 문서에서 꺼낸 값을 **호출자가 입력한
문자열**과 비교합니다. 그러므로 값을 꺼내는 쪽이 두 저장 모드 모두에서 그 값을
**텍스트로** 내놓아야 합니다. PostgreSQL의 `#>>`는 그렇게 합니다. SQLite의
`json_extract`는 값을 **SQL 타입 그대로** 돌려주고, 그 비교는 아무것도 변환하지
않습니다 — INTEGER는 TEXT 파라미터와 결코 같지 않고, JSON 불리언은 `'true'`가
아니라 `1`로 도착합니다.

그래서 SQLite fallback에서 `attributes.cpu_count = 8`은 정확히 그렇게 보고한
호스트들을 두고도 **HTTP 200과 빈 목록**을 돌려주었고, 거울상인
`attributes.cpu_count != 8`은 **8을 가진 자산까지 포함해 전부**를 남겼습니다.
같은 질의가 PostgreSQL에서는 맞게 답했습니다.

하필 그 값들이 Agent가 가장 많이 보고하는 종류입니다 — CPU 개수, 메모리 바이트
수, 포트 번호는 모두 JSON 숫자로 저장됩니다. 수집된 것의 큰 부분이 여기에
해당하는데, 어느 응답에도 **값이 그 값이 아닌 무언가로 비교되었다는 표시가
없었습니다.** `/api/v1/query/validate`는 그 표현식을 이미 `valid`라고 답한
뒤였습니다.

이제 SQLite 쪽 추출이 값을 **PostgreSQL이 렌더링하는 것과 같은 텍스트로**
접습니다. 두 모드가 같은 질의에 같은 답을 돌려줍니다.

- **없는 키는 그대로 둡니다.** SQL `NULL`은 접지 않으므로, 그 키를 한 번도 보고한
  적 없는 자산은 여전히 `NULL`로 추출되고 v0.2.25에서 고친 부등호의
  `IS NULL OR ...` 절이 그 자산을 계속 알아봅니다.
- **정렬 비교는 여전히 숫자를 숫자로 비교합니다.** `>`·`<`·`>=`·`<=`는 접지 않은
  원본 추출을 쓰므로, v0.2.20에서 고친 "자릿수 문자열 비교" 문제가 되돌아오지
  않습니다.

## 검증

- **엔드포인트 너머에서.** `cpu_count`를 JSON 숫자로 가진 자산과 다른 값을 가진
  자산을 만들고 `/api/v1/query/execute`로 `attributes.cpu_count = 8`을 실행해
  전자가 돌아오는지 확인합니다. 이 테스트는 **수정 전 SQLite에서 실제로 빈 목록으로
  실패**하고 수정 후 통과합니다. 불리언과 부등호 쪽도 같은 방식으로 함께 고정했습니다.
- **컴파일 결과를 고정했습니다.** 등식이 두 모드에서 각각 `#>>`·`json_extract`
  기준으로 어떤 SQL 모양이 되는지를 단위 테스트로 고정하고, SQLite 기대값을 쓰던
  기존 두 테스트(정렬·`!=`)를 새 렌더링에 맞게 갱신했습니다.
- **두 저장 모드에서.** `go test ./...`이 SQLite fallback과
  `scripts/test-postgres.sh`의 실제 PostgreSQL 양쪽에서 전 패키지를 통과하고,
  `go vet`·`go build`·`gofmt`가 통과합니다.
- 문법 응답(`GET /api/v1/query/grammar`)과 HTTP 계약이 바뀌지 않아
  `openapi.yaml`·콘솔·Agent(Rust) 코드는 이번 릴리즈에서 바뀌지 않았습니다.

## 호환성

- 데이터베이스 마이그레이션이 없습니다.
- API 응답 형식 변경이 없습니다.
- **SQLite fallback에서 동작이 달라집니다.** 숫자·불리언 속성에 대한 `=` 절이
  이제 실제로 일치하는 자산을 돌려주므로 결과가 늘어나고, 같은 속성에 대한 `!=`
  절은 그 자산들을 빼므로 결과가 줄어듭니다. **PostgreSQL 배포에서는 답이 달라지지
  않습니다** — 그쪽은 처음부터 맞게 답하고 있었습니다.
- 문자열 속성에 대한 질의는 두 모드 모두 그대로입니다.
