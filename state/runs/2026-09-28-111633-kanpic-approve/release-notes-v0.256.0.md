# v0.256.0

## 칸을 저장하고 바로 창을 닫아도 알림 메일이 나갑니다

칸을 고치거나 댓글을 남긴 **다음**에 알림이 만들어집니다. 변경은 이미
저장소에 커밋됐고, 누구에게 보낼지는 그 뒤에 정해집니다. 그런데 브라우저가
저장 직후 탭을 닫거나 다른 문서로 넘어가면 그 요청의 컨텍스트가 취소되고,
알림을 채비하는 일은 모두 그 컨텍스트로 DB 를 불렀습니다.

pgx 는 취소된 컨텍스트에서 **질의에 닿기도 전에** 실패합니다(풀의 Acquire 가
`ctx.Done()` 을 먼저 봅니다). 그래서 설정 읽기·지켜보기 규칙 읽기·수신자 주소
조회가 그대로 실패했고, 변경은 남았는데 알림만 조용히 사라졌습니다. 아무 곳에도
오류로 드러나지 않았습니다 — 알림 경로의 실패는 사용자에게 보이지 않도록
일부러 삼키게 되어 있기 때문입니다.

눈에 띄는 것은 사람이 가장 자연스럽게 하는 동작일 때입니다. 값을 적고 곧바로
탭을 닫는 분, 댓글을 등록하고 바로 목록으로 돌아가는 분의 변경은 저장됐지만
지켜보던 사람에게 아무 메일도 가지 않았습니다. 같은 변경을 하고 화면에 잠시
머무르면 메일이 갔으니, 알림이 **가다 말다** 하는 것으로 보였습니다. 이제
요청이 끝나는 것과 무관하게, 이미 일어난 변경의 알림은 나갑니다.

## 취소를 떼어 내는 자리는 두 곳입니다

한 곳만 고치면 구제되지 않습니다.

- `mail.Service.Notify` — 설정 읽기, 수신자 주소 조회, 발송 기록. 여기까지
  왔다면 수신자는 이미 정해진 다음입니다.
- 수신자를 **구하는** 경계(`httpapi` 의 `notifyContext`) — 지켜보기 규칙,
  워크북, 공유 목록, 표시 이름 읽기. 이 일이 실패하면 수신자가 0 명이 되어
  `Notify` 는 불리지도 않으므로, 안쪽만 고쳐서는 닿지 않는 자리입니다.

두 자리 모두 값은 그대로 물려받고 취소만 떼어 냅니다(`context.WithoutCancel`).
취소를 떼면 남는 것이 없어 요청이 무한정 기다릴 수 있으니 10 초 시한을 같이
둡니다 — 전송에 쓰는 `SendNow` 와 칸 자동화의
`triggerCellAutomationsContext` 가 쓰던 것과 같은 꼴입니다. 이 시한이 세는
일은 저장소 읽기 몇 번뿐이고, 실제 전송은 `Notify` 의 고루틴이 제 컨텍스트로
하므로 여기에 걸리지 않습니다.

적용되는 알림은 칸 변경(지켜보기), 댓글, 멘션, 공유 부여, 권한 요청, 권한
결정입니다.

## 그 밖에 바뀌는 것은 없습니다

- 누구에게 보낼지 정하는 규칙은 그대로입니다. 지켜보기 규칙·공유 목록을
  읽는 방식도, 자기 자신을 수신자에서 빼는 것도 같습니다.
- 알림이 꺼진 이벤트는 여전히 나가지 않습니다. 이 릴리즈는 **보내야 할
  메일이 취소 때문에 사라지는 것**만 막습니다.
- SMTP 주소·TLS·인증, 제목과 본문 문구는 손대지 않았습니다. 요청 경로가
  메일 서버를 기다리지 않는 것도 그대로입니다 — 사용자가 받는 응답과 상태
  코드는 달라지지 않습니다.

  은 이미 취소된 컨텍스트로 `Notify` 를 부른 뒤 가짜 릴레이에 메시지가 실제로
  실리는지 봅니다.

  `TestWorkbookAudienceSurvivesRequestCancel`,
  `TestNotifyCommentMailSendsAfterRequestCancel` 셋은 취소된 요청 컨텍스트에서
  수신자가 제대로 구해지고 메일이 나가는지를 각 경계마다 봅니다.
- 고치기 전 빨강 4(메일 1 + httpapi 3) → 고친 뒤 초록. 네 파일의 변경을
  v0.255.0 으로 되돌려 실제로 네 개가 빨강이 되는 것을 보고 다시 돌려놨습니다.
- `go test ./...`(18개 패키지 통과), `gofmt -l ./cmd ./internal ./pkg`(출력
  없음), `go vet ./...`, `go build ./...`,
  `scripts/check-release-docs.sh`, `scripts/check-commit-identities.sh` 를
  돌렸습니다.
- 웹 테스트·DB 통합·브라우저 E2E 는 돌리지 않았습니다 — 바뀐 곳이 Go 서버
  안쪽에서 알림에 쓰는 컨텍스트를 만드는 자리뿐이고, 브라우저에 실리는 자산은
  이 릴리즈에서 달라지지 않습니다.

## 올리실 때

마이그레이션도 새 설정도 없고 필수 런타임 환경 변수는 계속 `POSTGRES_DSN`
하나입니다. v0.255.0 에서 올라오시는 분은 이미지만 바꿔 다시 띄우시면 됩니다.

이미 사라진 알림이 되살아나지는 않습니다 — 이 릴리즈 뒤에 일어나는 변경부터
적용됩니다. 확인하시려면 칸을 고치고 곧바로 탭을 닫아 보십시오. 지켜보던 분께
메일이 도착합니다.

## 오프라인 설치

이 릴리즈는 웹 자산과 서버 바이너리를 포함한 Docker 이미지 아카이브로 제공됩니다.

```bash
sha256sum -c kanpic-v0.256.0.tar.gz.sha256
gzip -dc kanpic-v0.256.0.tar.gz | docker load
docker run --rm -p 8080:8080 \
  -e POSTGRES_DSN='postgres://kanpic:password@postgres.internal:5432/kanpic?sslmode=require' \
  kanpic:v0.256.0
```

- 필수 런타임 환경 변수: `POSTGRES_DSN`
- Redis 및 외부 인터넷 연결: 불필요
- 관리자 초기 로그인을 보호하려면 `BOOTSTRAP_ADMIN_ID`와 `BOOTSTRAP_ADMIN_PASSWORD`를 함께 지정합니다.
- 무결성 검증 파일: `kanpic-v0.256.0.tar.gz.sha256`
