# Approval module contract

Optional globally (`approval_enabled`). With no explicit document policy, an enabled service uses a single `reviewer_role` gate for backwards-compatible administrator configuration. Runbook requests require an explicit policy; a missing execution approval policy must never implicitly allow execution.

Policies are service-admin managed and scoped to workspace, optional inherited space, and resource kind. Closest enabled space policy wins, then workspace policy. Stages are sequential. Each stage combines named reviewer gates with `any` or `all`. A gate is fulfilled by one eligible member of its user/team/role/document-reviewer selector. `all` gates permit parallel department representatives rather than requiring every department member to approve.

Submission snapshots policy version, global approval revision, candidates, document version, content and hashes. Assignments never silently expand when team membership changes. Decisions recheck active human identity, current document read ACL, current gate membership, configured policy/revision and unchanged source content. Requester and document owner cannot approve. Approve/reject require a cookie session and explicit request ID; API/plugin submissions cannot self-approve. Version/policy drift requires resubmission.

Lock order: document row → settings read lock → current policy read lock → request row. Inside a transaction use only the transaction's Query/Exec; do not acquire an external pool connection. Policy mutations never lock documents/requests. Request progression, final published state, document version, outbox and notifications commit atomically. Historical snapshots are returned only under current document ACL.

Tables, in backup dependency order: approval_policy_clock, approval_policies, approval_requests, approval_assignments, approval_decisions. None are ephemeral. Physical document deletion cascades its requests; application document soft delete keeps review history.

Public/authenticated hooks to register: document approval GET/status, existing approval POST command, request detail GET, personal approval inbox GET. Administrator CRUD uses /admin/approval/policies.

Generic requests retain resource_kind/resource_id/resource_version/resource_hash/snapshot. `ApprovalAdapter` is registered once at startup for `document`, `sql_query_plan`, or `runbook`. `Lock(ctx,tx,principal,id,writing)` takes the resource serialization lock and checks current module-specific scope and ACL. `CanReview(ctx,tx,userID,resource)` checks candidate ACL without acquiring the outer pool. Optional `Submit` returns the final immutable version after transitioning to review; optional `Complete` commits publication or the corresponding approved/rejected/cancelled resource effect. `DocumentID` is optional for a SQL proposal or other non-document resource; `WorkspaceID` and `OwnerID` are mandatory.

Execution must consume an approved request exactly once under transaction lock and revalidate current ACL/policy plus the exact payload hash; a document publication approval is never an execution approval. `ConsumeApprovalTx(ctx,tx,principal,"runbook",resourceID,requestID,requestVersion)` permits only the actual requesting human's cookie principal, applies the adapter's current write ACL, verifies the approved payload and policy, and transitions approved→consumed. The caller queues its execution in that same transaction. A failed enqueue must rollback both; remote network execution must start only after commit. The runbook adapter must preserve the approved payload/version in its Complete callback. On restore pending requests and non-document approved requests become superseded; already consumed requests remain consumed.

UI: `/app/approvals?request=<UUID>` opens the immutable review modal. The shared `ApprovalPanel` accepts `kind`, `resourceID`, optional `onChanged`. Raw frozen Markdown/JSON is shown, never dynamic embed/plugin output. Server-side ACL/current-state validation applies on every read and decision; the browser additionally revalidates an open review every 5 seconds and clears its contents when access is lost.
