# 역할별 지식 경로

지식 경로는 기존 문서를 읽기 → 직접 실습 → 독립 검토 순서로 묶습니다. 문서를 열었다는 사실을 실습 완료로 기록하지 않으며 경로를 완료해도 문서 접근 권한, 게시 승인, Runbook 실행 권한이 추가되지 않습니다.

## 경로 구성

`/app/knowledge-paths`에서 워크스페이스 소유자·관리자가 **경로 만들기**를 선택합니다. 이름·설명·안내용 역할 이름과 최대 100개의 순서 있는 단계를 구성합니다. 역할 이름은 권한 그룹이나 자동 배정 조건이 아닙니다.

각 단계는 같은 워크스페이스의 현재 읽을 수 있는 기존 문서를 참조합니다. 목록에서 문서 UUID를 고르거나 붙여 넣을 수 있습니다. 읽기 확인·실습 결과·독립 검토를 구분하고 단계 이름·안내를 작성합니다. 기존 단계의 문서나 종류를 바꾸려면 새 단계로 추가합니다. 이전 단계를 제외해도 개인 이력은 즉시 삭제하지 않습니다.

기본 공유 범위는 비공개입니다. 워크스페이스 또는 공간 공유 전에는 제목·설명·단계 안내의 전송 범위를 확인하고 동의합니다. **경로 공유가 참조 문서의 권한을 변경하지 않습니다.** 원문을 읽을 수 없는 사용자는 그 단계의 문서 ID·제목·안내와 실습 원문을 볼 수 없습니다. 접근할 수 없는 단계를 건너뛰어 완료할 수도 없습니다.

경로 목록은 최근 200개를 표시하며 제목·역할 검색은 현재 목록을 대상으로 합니다. 보관 경로는 선택해 표시할 수 있지만 새 완료 확인은 중단됩니다.

## 개인 진행

1. 경로와 원문 버전을 확인합니다. 원문 링크를 여는 것만으로 완료되지 않습니다.
2. 읽기 단계는 **직접 확인 완료**로 명시 기록합니다.
3. 실습 단계는 실제로 수행한 결과를 직접 작성합니다. 서버는 명령을 실행하거나 실습의 사실성을 자동 인증하지 않습니다.
4. 독립 검토 단계가 설정되어 있다면 요청 사유를 작성해 제출합니다. 제출은 승인 완료가 아닙니다.

순서는 현재 유효하게 완료한 이전 단계를 기준으로 검사합니다. 개인 기록은 경로 revision과 원문 version에 결합됩니다. 경로 구성이 바뀌거나 원문 버전이 바뀌면 기존 이력은 남지만 현재 완료로 계산하지 않습니다. 선행 실습 기록을 수정하면 그 원문을 검토했던 독립 승인도 다시 확인해야 합니다.

진행 분모는 **현재 정책에서 적용되는 단계 수**입니다. 관리자가 명시적인 `learning_step` 승인 정책을 설정하지 않았거나 승인 기능이 꺼져 있다면 독립 검토 단계는 분모에서 제외되고 화면에 그 수와 이유를 표시합니다. 이는 검토가 승인됐다는 뜻이 아닙니다. 나중에 정책을 켜면 검토 단계가 다시 포함되며 과거 승인이 자동으로 부활하지 않습니다.

## 독립 검토와 개인정보

관리자는 기존 승인 정책 화면에서 대상 **지식 경로 실습 검토**를 선택합니다. 공간별 상속과 다단계·검토자 조건은 일반 승인 엔진을 따르지만, 기본 문서 승인 정책이 자동으로 적용되지는 않습니다. 신청자 자신은 검토할 수 없습니다. 현재 경로와 모든 선행 근거 문서를 읽을 수 있는 다른 담당자가 필요합니다.

검토자는 승인 화면의 **제출한 실습 원문과 근거 확인** 링크에서 실제 제출한 기록을 봅니다. 검토 화면은 현재 권한과 고정된 기록 버전을 재검사합니다. 제출 뒤 선행 기록이 바뀌면 새 미제출 원문을 과거 검토자에게 보여주지 않고 재제출을 요구합니다. 열린 검토 화면도 주기적으로 현재 권한을 재확인합니다.

실습 기록·검토 요청 사유는 UTF-8 최대 16KiB이며 관리자 정보보호 정책의 차단·마스킹·경고를 적용합니다. 기록은 DB에서 암호화합니다. 승인 snapshot에는 실습 본문을 중복 저장하지 않고 기록 revision·원문 version·hash와 검토 화면 참조만 보관합니다. 기록은 평소 본인에게만 보이며, 독립 검토에 제출한 범위만 지정 검토자가 현재 근거 권한 안에서 볼 수 있습니다. 비밀값을 입력하지 마세요.

**개인 이력**은 최근 200개를 보여줍니다. 이전 실습 원문과 현재 완료를 구분합니다. 원문 권한을 잃거나 현재 정보보호 정책에 어긋나면 과거 기록의 원문도 숨깁니다. 문서가 영구 삭제된 경우 단계·현재 진행은 참조 삭제 정책을 따르며, 접근할 수 없는 과거 이력은 상세 원문을 표시하지 않습니다.

## API·MCP와 운영 경계

- `GET /api/v1/knowledge-paths?workspace_id=…`: 현재 접근 가능한 목록.
- `POST /api/v1/knowledge-paths`, `PUT /api/v1/knowledge-paths/{id}`: 관리자 쿠키 전용 구성; 변경은 revision CAS.
- `GET /api/v1/knowledge-paths/{id}`: 순서·현재 문서 참조·본인 진행. API 키에는 실습 원문을 반환하지 않습니다.
- `POST /api/v1/knowledge-paths/{id}/steps/{step}/confirm`: 본인 쿠키 전용. `path_revision`, `document_version`, 기존 개인 `revision`(첫 기록 0), `proof`, `confirmation:"CONFIRM"`가 필요합니다.
- `GET /api/v1/learning-progress/{id}/review`: 제출자 또는 실제 지정 검토자의 현재 제출 기록.
- `GET /api/v1/knowledge-paths/{id}/history`: 본인 쿠키 전용 개인 이력.

MCP의 `list_knowledge_paths`와 `get_knowledge_path`는 `document:read` 범위의 읽기 전용 도구입니다. AI Agent가 사람 대신 읽기·실습 완료나 검토 결정을 수행할 수 없습니다. OpenAPI는 `/api/v1/openapi.json`에서 확인할 수 있습니다.

경로·진행의 짧은 트랜잭션은 기존 ACL 변경 경로와 일관성을 유지하기 위해 문서·공간·공유 테이블에 보수적인 공유 잠금을 사용합니다. 다른 쓰기가 잠시 기다릴 수 있으며 lock timeout 3초·개별 SQL statement timeout 12초가 적용됩니다. 타임아웃이나 CAS 충돌에서는 결과와 현재 버전을 재조회한 후 명시적으로 다시 확인하세요. 최대 100단계 제한은 무제한 규모의 즉시 처리를 보증하지 않습니다.

백업은 경로·단계·암호화된 진행·개인 이력을 보관합니다. 복원은 기존 완료/검토 대기/승인 진행을 `needs_recheck`로 바꾸고 현재 승인 연결을 해제합니다. 과거 이력은 유지하지만 복원만으로 실습 완료나 비문서 승인을 되살리지 않습니다. 외부 작업을 자동 실행하지 않습니다.

## 검증

실제 PostgreSQL `-race` 교차 회귀(32.034초)에서 순서 건너뛰기, CAS 중복 제출, 원문·경로 변경 후 재확인, 개인 실습 암호화와 다른 사용자 비노출, PII 마스킹·차단, 키 원문 비노출, 명시 승인 정책 분모, 자기 승인 거부, 선행 실습 변경 후 승인 무효화, 현재 원문 ACL 상실을 검증했습니다. 최종 구성원 잠금 대기 중 세션이 만료되면 403으로 거부하고 이미 작성 중이던 개인 완료를 롤백하는 실제 경합 시험도 포함합니다.

실제 Chromium 두 사용자 시험(15.823초)에서 경로 구성·공유 확인, 뷰어의 개인 읽기·실습, 승인 정책 추가 후 분모 변경, 제출 원문 검토·독립 승인, 원문 변경 재확인, 개인 이력, 새로고침, 390px 화면과 권한 회수를 확인했습니다. 실제 `pg_dump`/`pg_restore`를 이용한 현재 전체 스키마 복원(3.853초)에서는 암호화한 개인 기록은 보존하고 현재 완료를 재확인 상태로 변경했습니다. 시험 시간은 공유 개발 환경 측정값이며 처리 시간 보증이 아닙니다.
