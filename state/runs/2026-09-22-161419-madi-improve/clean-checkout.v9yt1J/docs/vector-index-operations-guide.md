# 벡터 색인 세대와 안전한 검색 전환

워크스페이스의 **검색 운영 → 벡터 색인 세대**(`/app/search/generations`)에서 모델·차원이 다른 색인을 따로 준비하고 검증한 뒤 검색 세대를 전환합니다. 소유자 또는 워크스페이스 관리자인 일반 사용자만 설정을 변경합니다. 서비스 관리자도 다른 사람의 비공개 문서나 관리 멤버십을 우회하지 않습니다. API 키·서비스 계정·플러그인은 이 관리 API를 호출할 수 없으며, 기존 문서별 색인 API는 현재 키 스코프·원본 권한·동의를 계속 적용합니다.

## 세 가지 실행 모드

| 모드 | 실제 실행 | 한계 |
| --- | --- | --- |
| 정확 검색 | PostgreSQL `real[]`를 차례로 읽어 코사인 계산. `pgvector` backend를 선택한 경우에도 같은 제한 후보의 정확 거리 계산 | `rag_scan_limit`까지의 현재 권한 후보에서 정확하며 전체 저장소의 전역 최근접 보증은 아님 |
| 근사 검색 | 실제 세대별 부분 HNSW 인덱스의 코사인 거리 순서 탐색 | 탐색 예산과 현재 ACL 필터 때문에 후보가 부족할 수 있음 |
| 검증 검색 | 같은 질문으로 ANN과 배열 정확 검색을 함께 실행하고 후보 Recall@k 비교. 실제 응답 후보는 ANN | 정확 기준이 scan_limit으로 잘렸다면 제한된 기준의 비교이며, 두 경로 실행 비용이 더 큼 |

`rag_top_k`는 최종 출처 1~20개, `rag_candidates`는 비교 후보 10~200개, `rag_scan_limit`는 정확 후보 100~50,000개입니다. `rag_ann_ef_search`는 40~1000이며 기본 100입니다. HNSW의 `max_scan_tuples`에는 scan_limit을 전달하지만 이는 내부 탐색의 절대 메모리·지연 보증이 아닙니다. 진단의 `scanned`는 ANN에서 **반환된 현재 권한 후보 수**이며 내부 인덱스 방문 수가 아닙니다.

서비스 기본은 배열 기반 정확 검색입니다. ANN 모드는 명시적으로 세대를 준비하고 검증한 뒤 적용해야 합니다. 관리 설정의 문자열만 바꾸어 활성 세대의 검증된 모드와 달라지면 오류로 종료합니다. HNSW가 없거나 실행 계획이 해당 세대 인덱스를 사용하지 못하면 ANN 성공으로 가장하거나 정확 검색으로 조용히 대체하지 않습니다. 상위 AI 기능에서 별도로 제공하는 키워드 복구는 진단에 표시되는 다른 경로입니다.

## PostgreSQL 준비

일반 배열 검색에는 추가 확장이 필요 없습니다. HNSW에는 운영자가 PostgreSQL에 **pgvector 0.8 이상**을 먼저 설치해야 합니다. 서비스는 확장을 자동 설치하거나 DB 전역 설정을 변경하지 않습니다. 폐쇄망에서는 운영 환경에 맞는 PostgreSQL/pgvector 패키지를 별도로 반입해야 하며, madi 서비스 Docker 이미지가 PostgreSQL 확장 서버를 포함하지는 않습니다.

이번 구현은 `vector` 타입의 HNSW를 사용하므로 고정 차원 **1~2000**을 지원합니다. 배열 정확 검색과 세대 색인은 최대 8192차원까지 받지만 2000차원을 넘는 세대에 HNSW를 생성하지 않습니다. `halfvec`/양자화 방식은 구현하지 않았습니다. 공식 pgvector는 타입별 인덱스 차원 제한과 0.8 이후 반복 탐색을 설명합니다. [pgvector 공식 저장소](https://github.com/pgvector/pgvector)

HNSW 검색 트랜잭션 안에서만 `hnsw.iterative_scan=strict_order`, 탐색 예산, `enable_seqscan=off`, `enable_sort=off`를 적용합니다. 벡터 테이블을 거리 순서의 드라이버로 유지하고 `LATERAL` 조회에서 현재 문서·색인 동의 주체의 ACL을 확인한 뒤 LIMIT을 적용합니다. 같은 SQL과 인자의 읽기 전용 EXPLAIN이 정확한 세대 인덱스를 사용하는지 확인하고 실행합니다. 이 설정은 요청이 끝나면 사라지며, 서비스 계정으로 PostgreSQL의 영구 튜닝을 하지 않습니다. [PostgreSQL 실행 계획 안내](https://www.postgresql.org/docs/current/using-explain.html)

## 새 모델 준비 순서

1. **새 세대**에서 이름·모델·고정 차원을 입력하고 확인합니다. 별도 API 주소를 선택하면 현재 공급자의 키를 새 주소에 자동 전달하지 않습니다. 공급자 설정은 서버에서 암호화하며 생성한 세대의 모델·차원·공급자는 수정하지 않습니다. 바꾸려면 다른 세대를 만듭니다.
2. 처음 세대를 관리할 때는 현재 공급자와 기존 동의를 **기존 설정 기준 세대**로 보존합니다. 모델을 새로 만드는 행위만으로 문서를 외부에 보내거나 현재 검색을 전환하지 않습니다.
3. 필요한 각 문서의 **세대별 동의·색인**을 엽니다. 현재 원문 버전, 비공개 여부, 실제 공급자 주소와 모델을 보고 동의합니다. 첨부 본문 전송은 이 문서 Markdown 동의에 자동 포함되지 않습니다. 자동 재색인·선택적 재정렬 전송은 기본 해제입니다.
4. 해당 세대의 현재 문서 버전 색인이 준비될 때까지 작업 상태를 확인합니다. 그림자 세대의 자동 재색인 설정은 그 세대가 활성화된 이후 문서 변경부터 적용됩니다. 활성화 전 원문이 바뀌었으면 새 저장본에 맞게 명시적으로 다시 색인하고 검증해야 합니다.
5. ANN 또는 검증 모드를 사용할 때 **HNSW 인덱스 준비**를 실행합니다. 실제 `CREATE INDEX CONCURRENTLY` 작업이며 같은 DB 스키마에서 한 작업만 생성합니다. 공통 작업 큐에서 실패·취소를 확인하고 다시 준비할 수 있습니다. 실행 중 사용자·세션·관리 권한·RAG 설정이 바뀌면 중단합니다. 취소한 작업이 남긴 불완전한 인덱스는 같은 세대의 다음 준비 작업에서 정확한 이름·대상 테이블을 확인한 뒤 정리합니다.

문서 색인은 기존 공급자 요청의 취소·버전 검사·체크포인트 재개 경계를 유지합니다. 이미 외부 공급자에게 전달한 바이트는 취소로 회수할 수 없습니다. 세대 생성과 HNSW 준비는 로컬 설정/인덱스 작업이므로 그 자체로 문서 본문을 공급자에게 전송하지 않습니다.

## 실제 검증과 전환

검증할 현재 열람 가능한 문서를 1~30개 선택하고 질문을 입력합니다. 질문은 UTF-8 4000바이트까지 받으며 공급자 전송에 별도 동의해야 합니다. 검증은 현재 저장본·준비된 벡터와 현재 권한을 사용하고, 자료의 원본 소유자·키·플러그인 동의 권한도 다시 확인합니다. 정보보호 정책이 질문 수정을 요구하면 민감한 내용을 제거하고 다시 동의해야 합니다.

실제 임베딩 API로 질문 벡터를 얻고 선택한 문서 범위에서 검색을 비교합니다. 검증은 45초 요청 예산과 실행 중 재검사를 사용합니다. 조용한 공급자 대기 중에도 주기적으로 확인하지만, 1초 확인 주기는 모든 DB 지연을 포함한 권한 회수 SLA 보증은 아닙니다.

검증 결과는 선택한 **문서·질문 한 건·현재 사용자 ACL**의 표본입니다. 전체 조직의 검색 품질이나 모든 ACL 조합을 보증하지 않습니다. 정확 모드에서는 ANN 비교를 했다고 표시하지 않습니다. ANN/검증 모드의 실제 후보 Recall@k, 정확 기준의 잘림 여부, 인덱스 사용 여부와 경고를 확인하세요.

전환 가능 영수증은 같은 사용자 세션, RAG 설정 지문, 세대 revision, 활성 상태 revision, 각 문서 version·동의 revision·실제 index ID에 묶이며 15분 후 만료됩니다. 정확 기준이 잘리지 않았고 Recall@k가 0.9 이상일 때만 전환할 수 있습니다. 검증 후 설정·문서·권한·동의가 바뀌거나 로그아웃하면 이전 영수증을 사용할 수 없습니다. 질문 원문이나 원본 문서 본문은 이 영수증에 보관하지 않습니다.

**검증한 세대로 전환**을 누르기 전에 검색 범위가 달라질 수 있음을 확인해야 합니다. 새 세대에 동의하지 않았거나 현재 버전 색인이 준비되지 않은 자료는 전환 후 빠질 수 있습니다. 공급자 설정과 활성 세대 포인터는 한 DB 트랜잭션에서 CAS로 함께 바뀝니다. 두 탭이 같은 영수증으로 전환해도 한 요청만 성공합니다. 서버가 임의로 전체 자료 준비 완료를 선언하거나 자동 전환하지 않습니다.

## 이전 세대로 복귀·삭제·복원

이전 세대를 선택하고 현재 자료·권한으로 **새로 검증**한 뒤 복귀합니다. 예전 검증 영수증을 재사용하거나 현재 문서 버전을 낮추지 않습니다. 과거 세대의 동의가 철회되었거나 원문 버전이 바뀌었다면 먼저 새 동의·색인이 필요합니다.

최대 20개 세대를 보관합니다. 필요 없는 비활성 세대는 명시적으로 삭제할 수 있습니다. 원본 문서는 유지하지만 해당 세대의 암호화 공급자 설정·문서 동의·검증 영수증·파생 벡터·정확한 이름의 HNSW 인덱스는 삭제합니다. 현재 검색 중인 세대와 진행 중 작업이 있는 세대는 삭제하지 않습니다. 삭제는 500ms lock timeout/5초 statement timeout의 짧은 트랜잭션으로 수행하고, 경합 시 원본과 세대 상태를 유지한 채 재시도를 안내합니다.

논리/네이티브 복원 모두 세대를 비활성화하고 활성 포인터를 비웁니다. 검증 세션 지문을 제거하고 영수증을 만료시키며, 색인 동의·자동 재색인을 무효화하고 진행 작업을 취소합니다. 파생 벡터는 다시 생성해야 합니다. 복원 후 공급자와 새 문서 동의를 확인하기 전 무인 재전송을 하지 않습니다.

## API와 검증 기록

| API | 용도 |
| --- | --- |
| GET/POST `/api/v1/workspaces/{id}/rag-generations` | 현재 권한 상태 조회 / 불변 세대 생성 |
| POST `/api/v1/rag-generations/{id}/index` | 실제 HNSW 작업 요청 |
| GET/POST/DELETE `/api/v1/documents/{id}/rag-index?generation_id=UUID` | 특정 세대의 문서 동의·색인·철회 |
| POST `/api/v1/documents/{id}/rag-index/cancel?generation_id=UUID` | 특정 세대의 문서 작업 취소 |
| POST `/api/v1/rag-generations/{id}/verify` | 실제 표본 검증과 일회용 영수증 |
| POST `/api/v1/workspaces/{id}/rag-generations/activate` | 검증 영수증 CAS 전환 |
| DELETE `/api/v1/rag-generations/{id}` | 비활성 세대와 파생 자료 삭제 |

`generation_id`를 생략한 기존 문서 색인 API는 활성 세대에 적용합니다. MCP/AI의 기존 검색은 활성 세대만 사용하며 현재 문서 권한·키 스코프·공급자 동의가 계속 적용됩니다. 검증·전환 관리 도구를 일반 MCP 키에 노출하지 않습니다. 세부 JSON 계약은 서비스 OpenAPI에 포함됩니다.

```sh
# 시험마다 별도 임의 스키마를 생성/정리하는 전용 검증 DB만 사용
MADI_TEST_POSTGRES_DSN='postgres://tester@127.0.0.1:5432/madi_test?sslmode=disable' \
  go test -race ./internal/server -run '^TestPostgresRAGGeneration|^TestRAGGeneration' -count=1 -v

# web 빌드 + Playwright Chromium 설치 후 실제 화면 흐름
MADI_TEST_POSTGRES_DSN='postgres://tester@127.0.0.1:5432/madi_test?sslmode=disable' \
MADI_BROWSER_RAG_GENERATIONS=1 \
  go test ./internal/server -run '^TestBrowserRAGGenerations$' -count=1 -v
```

2026-09-08 Go 1.26.8/PostgreSQL 18.6의 실제 pgvector 환경에서 세대별 동의 격리, 명시 HNSW 작업, 동시 CAS의 200/409 분리, 이전 세대 재검증 복귀, 질문 처리 중 동의·공급자·세션 회수, 다른 관리자의 private 우회 금지를 검증했습니다. 기존 RAG/Workspace Agent/AI 스트리밍·Plugin AI 스트리밍의 교차 PG race 회귀는 78.140초에 통과했습니다. 실제 브라우저 전체 흐름과 390px 화면은 21.076초에 통과했습니다.

확대한 129문서 표본에서는 1/4이 private인 추가 128개의 결정적 3차원 합성 벡터와 실제 공급자 fixture의 문서 한 개를 사용했습니다. 관리자·viewer 각각 실제 HNSW와 정확 기준의 Recall@20=1을 확인했습니다. 이는 ANN/권한 필터 알고리즘 회귀이며 실제 모델 품질이나 대규모 성능 수치가 아닙니다. 원본 실행 계획·환경은 `test-results/rag-generations/ann-acl-129.json`에 남깁니다. pgvector가 없는 시험 환경은 자동 설치 대신 명시 오류 경계를 검증하며 ANN 시험을 실행했다고 주장하지 않습니다.
