검색 AI · 동의 기반 RAG 운영 가이드

madi는 PostgreSQL 키워드 검색과 명시적으로 동의한 문서의 벡터 검색을 함께 사용합니다. 문서 본문은 Markdown 원본이며, 벡터는 언제든 다시 만들 수 있는 파생 데이터입니다. 검색 결과의 문서 버전·원문 범위·해시를 검증한 인용을 AI 답변과 함께 제공합니다. 인용 검증은 AI 답변 자체의 사실성을 보증하지 않습니다.

관리자가 먼저 설정하기

서비스 관리자 → 검색 AI에서 임베딩 API 주소, 모델, API 키, 선택형 사내 CA 인증서를 저장합니다. 워크스페이스 관리자는 해당 워크스페이스의 설정으로 재정의할 수 있습니다. 환경변수를 추가할 필요는 없습니다.

  • 임베딩은 OpenAI 호환 POST /embeddings JSON API입니다. 기본 주소가 /v1이면 /v1/embeddings로 연결합니다. 키는 암호화하여 저장하고 화면에 다시 반환하지 않습니다.
  • 사내 HTTP 연결도 관리자가 명시적으로 허용해야 합니다. HTTPS 인증서 검증을 끄지 않으며 사내 CA를 등록할 수 있습니다. 리디렉션을 따라가지 않습니다.
  • 연결 검사는 고정된 진단 문구만 보냅니다. 저장된 비공개 문서를 임의로 사용하지 않습니다.
  • 공급자 주소를 바꾸면 기존 전역 API 키를 새 워크스페이스 주소로 자동 전달하지 않습니다. 새 공급자의 키를 직접 등록하세요.
  • 기본 벡터 저장 방식은 PostgreSQL real[]입니다. pgvector 선택 시 운영자가 호환 확장을 먼저 설치해야 합니다. madi는 확장을 자동 설치하거나, pgvector가 없을 때 몰래 다른 방식으로 대체하지 않습니다.

pgvector를 사용하려면 PostgreSQL 운영자가 해당 서버에 확장 파일을 설치한 후 대상 데이터베이스에서 CREATE EXTENSION vector;를 실행합니다. 서비스 이미지에 PostgreSQL 서버를 함께 넣거나 외부 다운로드를 수행하지 않습니다. 폐쇄망에서는 확장 패키지도 별도로 반입해야 합니다. pgvector 공식 설치·검색 문서를 참고하세요.

문서 작성자의 전송 동의

문서 도구 → 검색 AI 색인에서 현재 문서 버전과 임베딩 공급자를 확인합니다. 비공개 문서도 색인을 요청하면 해당 공급자에 본문이 전송됩니다. 동의 화면의 표시 주소는 인증정보 노출을 막기 위해 URL 쿼리를 생략하며, 실제 전체 설정의 비가역 지문으로 공급자 변경을 구분합니다.

  1. 현재 공급자에 본문을 전송하는 데 동의합니다.
  2. 필요할 때만 자동 재색인 또는 재정렬 공급자 전송을 별도로 선택합니다. 두 항목의 기본값은 꺼짐입니다.
  3. 색인을 요청하고 조각별 진행 상태를 확인합니다. document:write와 ai:execute 권한이 모두 필요하며 관리자가 다른 사람의 비공개 문서에 자동 접근할 수는 없습니다.

문서를 읽을 수만 있는 사용자는 제한된 색인 상태를 볼 수 있습니다. 공급자 동의 설정, 작업 ID, 내부 오류는 표시하지 않습니다. API 키와 플러그인 요청에도 원래 사용자·워크스페이스·현재 권한 제한이 그대로 적용됩니다.

취소·철회·재시도

  • 작업 취소는 진행 중인 작업과 자동 재색인을 중단합니다. 다시 색인하려면 현재 버전과 공급자를 확인하여 새 요청을 만듭니다.
  • 동의 철회는 후속 전송을 중단하고 madi에 저장된 파생 벡터를 삭제합니다. 이미 공급자에 전달된 내용은 회수할 수 없으므로 공급자의 보존 정책도 확인해야 합니다.
  • 일시적인 공급자 오류는 최대 3회 시도하며, 이미 저장한 배치부터 이어서 진행합니다. 문서 버전·동의 버전·키·권한·공급자가 바뀐 작업은 과거 상태로 계속하지 않습니다.
  • 자동 재색인은 동일한 임베딩 공급자 지문과 현재 권한이 유지될 때만 예약합니다. API 키·인증서·모델·주소 변경도 공급자 변경으로 취급합니다. 변경된 임베딩 공급자는 새 동의가 필요합니다.
  • 선택형 재정렬은 별도 공급자 동의를 받습니다. 검색된 출처 중 하나라도 현재 버전·재정렬 공급자 동의가 없으면 재정렬을 생략하고 그 이유를 표시합니다.
  • 삭제한 문서의 동의는 비활성화합니다. 백업을 복원하면 과거 동의와 자동 재색인을 비활성화하고 벡터를 재구축 대상으로 처리합니다. 복원 후 새 동의 없이 문서가 외부로 전송되지 않습니다.

계정·API 키·플러그인 권한·문서 접근권한과 공급자 설정은 배치 전후, 장시간 요청 중, AI 스트리밍 출력 전에 다시 확인합니다. 스트리밍 도중 출처의 동의를 철회하면 후속 텍스트를 차단하고 이미 표시한 답변도 회수하도록 클라이언트에 알립니다.

검색 방식과 범위

방식 동작
키워드 PostgreSQL 검색과 현재 Markdown 원문으로 출처를 선택합니다. 검색 단계에서 임베딩·재정렬 서버를 호출하지 않습니다.
의미 검색 현재 공급자에 동의된 최신 벡터만 코사인 유사도로 검색합니다. 사용할 수 있는 색인이 없으면 그 사실을 표시합니다.
혼합 검색 키워드와 벡터 결과를 RRF 순위 결합으로 합칩니다. 벡터가 없을 때 키워드 출처와 안내를 제공합니다.

선택형 재정렬은 vLLM의 Cohere/Jina 호환 /rerank API를 사용합니다. 응답의 출처 순서·중복·유효 점수를 검사하며 공급자가 돌려준 원문으로 기존 인용을 바꾸지 않습니다. vLLM 재정렬 API 문서를 참고하세요.

현재 정확 코사인 검색은 설정한 최대 조각 수 안에서 수행합니다. 기본은 5,000개, 설정 범위는 100~50,000개입니다. 한도에 도달하면 truncated와 안내를 표시합니다. 이는 전체 저장소의 무제한 전역 최근접 검색이나 HNSW 검색 성능 보장이 아닙니다. 배열 방식은 벡터를 한 개씩 읽어 후보만 유지하며, pgvector 방식도 동일한 제한 범위에서 실제 확장 연산을 사용합니다.

v0.2.0은 별도 벡터 색인 세대에서 HNSW 근사·검증 모드와 모델/차원 변경 전환을 제공합니다. 기존 기본 색인은 유지하면서 새 세대에 동의·색인·정확/근사 검증을 수행하고 현재 검증 결과를 명시적으로 활성화합니다. 롤백도 현재 권한과 정책을 다시 확인합니다. 세대별 운영 가이드의 차원·탐색·검사 한도와 검증 조건을 확인하세요. 단순 설정 문자열 변경으로 검증된 세대의 모드를 바꾸지 않습니다.

색인 문서는 최대 4MiB, 조각은 약 6KiB와 겹침 512바이트, 전송 배치는 16개입니다. 벡터 차원은 최대 8,192, 최종 인용은 1~20개, 재정렬 후보는 최대 200개입니다. 의미 검색 질문은 8,192바이트 이하여야 합니다. AI 답변의 최대 토큰 설정(최대 262,144)은 별도이며 실제 지원량은 연결한 모델을 확인해야 합니다.

API

  • GET /api/v1/documents/{id}/rag-index: 권한별 상태와 동의 정보
  • POST /api/v1/documents/{id}/rag-index: expected_version, provider_fingerprint, consent:true, 선택형 auto_reindex, allow_rerank, rerank_fingerprint
  • POST /api/v1/documents/{id}/rag-index/cancel: 현재 job_id의 작업 취소
  • DELETE /api/v1/documents/{id}/rag-index: 현재 grant_revision의 동의 철회
  • POST /api/v1/ai/chat: 기본 SSE 스트리밍, 첫 이벤트에 sources와 retrieval 진단

인용 링크는 현재 문서 버전·접근권한·UTF-8 원문 범위·해시가 모두 맞을 때만 해당 내용을 반환합니다. 문서가 바뀌면 이전 인용을 최신 내용인 것처럼 표시하지 않습니다.
