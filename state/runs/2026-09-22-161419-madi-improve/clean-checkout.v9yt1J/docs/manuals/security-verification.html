출시 전 보안 점검과 재검증

보안 검사는 출시 준비 시점의 알려진 취약점과 재현 가능한 동작을 확인합니다. 검사 통과가 향후 취약점이나 운영 설정 오류가 없다는 보장은 아닙니다. 운영망에서는 TLS·네트워크 경계·IdP·DB 권한과 백업 접근을 별도로 관리하세요.

의존성 기준선

2026-09-08 점검에서 초기 Go 1.26.0 표준 라이브러리와 DB·SSH·XML 서명 의존성 경고를 확인하여 다음 버전으로 변경했습니다.

구성 적용 버전 확인 근거
Go 1.26.8 공식 패치 이력
PostgreSQL 드라이버 pgx 5.9.2 쿼리 placeholder 보안 수정
golang.org/x/crypto 0.56.0 SSH 채널 서비스 거부 수정
goxmldsig 1.6.0 XML 서명 검증 수정
klauspost/compress 1.18.7 S2 사전 처리 수정

govulncheck는 모듈 이름의 경고와 실제 사용하는 패키지·호출 경로를 구분합니다. golang.org/x/crypto/openpgp는 사용하지 않습니다. SSH·bcrypt 등에 필요한 x/crypto 모듈에 해당 미사용 패키지가 함께 배포된다는 이유로 나타나는 모듈 수준 경고를, 실제 사용하는 암호화 경로의 경고와 혼동하지 않아야 합니다. OpenPGP 관련 공식 설명

웹과 데스크톱 프로덕션 npm 의존성 검사는 같은 날짜 기준 경고 0건을 확인했습니다. Docker Go 빌더는 1.26.8 패치 태그로 고정하고 릴리즈 빌드에서 기본 이미지를 다시 확인합니다. 서비스 실행에는 Go·Node·npm 및 다운로드가 필요하지 않습니다.

2026-09-09 v0.2.0 개발 후보를 다시 검사했습니다. govulncheck는 호출 경로 0건·가져오는 패키지 0건, 미호출 모듈 수준 1건을 보고했고 go vet ./...도 통과했습니다. 웹 npm audit --omit=dev는 0건입니다. 이 재검사는 서비스 Go·웹 범위이며 전날의 별도 데스크톱 Rust 검사 날짜를 갱신한 것이 아닙니다. 최종 릴리즈 게이트는 변경된 후보를 다시 검사합니다.

재현 명령

연결된 개발·검증 환경에서 실행합니다. 취약점 DB 조회를 위한 네트워크 사용은 빌드 시점에만 필요합니다.

go version
go run golang.org/x/vuln/cmd/govulncheck@v1.7.0 -show verbose ./...
npm --prefix web audit --omit=dev
npm --prefix sdk/desktop audit --omit=dev
node scripts/licenses.mjs --check

MADI_TEST_POSTGRES_DSN은 검증 전용 PostgreSQL을 가리키는 테스트 변수입니다. 서비스의 네 실행 환경변수에 추가되는 운영 설정이 아닙니다. CI는 별도 PostgreSQL에 독립 스키마를 생성하여 전체 Go race·프로토콜·브라우저 회귀를 수행합니다.

동작 검증의 주요 경계

  • API 키·MCP·AI·RAG·Agent는 사용자·워크스페이스·공간·문서의 현재 권한을 넘지 않습니다. 키 범위 변경·회전·폐기·세션 종료 후에도 열린 스트림과 작업을 다시 검사합니다.
  • OIDC PKCE/nonce와 검증된 계정, SAML 서명·audience·재사용 거부, LDAP TLS·인증서 검증, SCIM 범위·그룹 격리를 실제 프로토콜 시험으로 확인합니다.
  • Git HTTPS CA·redirect 거부·SSH host key 고정, 비공개 자료·현재 원문·CAS 충돌과 재동의 경계를 검사합니다.
  • 비밀 설정은 DB에서 암호화하고 응답·공용 감사에는 원문 비밀을 노출하지 않습니다. 검색어와 개인 AI 자료는 별도 사용자 저장과 동의 정책을 적용합니다.
  • 응답 목록은 원문 없는 요약을 사용하고 JSON 읽기 모델 합계를 32MiB로 제한합니다. 초과 시 일부 목록을 성공처럼 반환하지 않으며 작업은 같은 오류를 무한 재시도하지 않습니다.
  • Markdown 개별 조회는 원문 크기와 JSON 이스케이프 후 크기를 구분해 정상 원문이 읽히는지 확인합니다.
  • 백업 복원은 원문·첨부·암호화 설정을 보존하되 이전 세션과 외부 작업 실행 정책을 재개하지 않습니다. 오프라인 이미지에서 실제 복원도 별도로 검증합니다.

검증용 비밀번호·인증서·IdP·모델·DB 응답은 합성 시험 데이터이며 운영 조직의 계정으로 연결했다는 의미가 아닙니다. 상세 기능별 제한은 전체 범위와 운영 한계, 실제 운영 기록은 배포 검증을 참고하세요.

데스크톱 Rust 의존성 별도 검사

2026-09-08에 공식 cargo-audit 0.22.2와 RustSec DB 커밋 8a1eb4f933fb5821add5b4e98601ebd90b8b3538(2026-09-07 11:19:30 -07:00)으로 데스크톱 Cargo.lock 전체 570개 패키지를 검사했습니다. 대상 OS 필터와 권고 제외 목록은 사용하지 않았습니다. RustSec 취약점 0건, 정보형 경고 17건으로, npm 검사 결과나 “경고 없음”과 구분해야 합니다. 기본 명령은 종료 코드 0, --deny unsound를 추가한 검사는 종료 코드 1이었습니다.

구분 발견 영향과 대응 범위
glib 0.18.5 안전성 경고 1 VariantStrIter의 잘못된 C 출력 포인터 처리. 최적화 빌드에서 정의되지 않은 동작·충돌 가능성이 있으며 현재 SDK 호출은 발견되지 않음
GTK3 계열 유지보수 중단 10 Linux GUI 의존성. 공식 바인딩 저장소가 보관 상태이며 수정 버전 없음
proc-macro-error 유지보수 중단 1 glib/GTK 매크로 빌드 경로. 현재 알려진 취약점 분류가 아닌 유지보수 경고
Unicode 계열 유지보수 중단 5 urlpattern → tauri-utils의 빌드·런타임 경로. 유지보수 대체와 상위 의존성 변경 추적 필요

glib 권고의 공식 수정 범위는 0.20.0 이상입니다. 현재 GTK3가 요구하는 0.18 계열의 마지막 crates.io 버전은 0.18.5이며, 확인한 공식 0.18 브랜치에도 잘못된 &p 처리가 남아 있습니다. 상위 수정 PR의 backport 표시는 0.18 호환 수정이 제공되었다는 근거가 아닙니다. 0.19 브랜치의 수정은 확인했지만 GTK의 0.18 의존성을 대체하지 못합니다. 최신 glib를 별도로 추가하거나 버전 번호만 바꿔 경고를 숨기지 않았습니다. GTK3 유지보수 권고에는 수정 버전이 없습니다.

실제 SDK와 내려받은 Rust 의존성 소스에서 VariantStrIter·array_iter_str 호출을 검색했으며 glib 자체 정의·예제·테스트 외에는 발견되지 않았습니다. 원격 서비스 창은 기기 IPC 권한이 없고 로컬 명령은 창·원점 및 API 경로를 확인합니다. 이 증거는 현재 확인된 입력 경계를 설명할 뿐, 생성 코드·미래 변경까지 포함한 전체 프로그램의 비도달성 증명은 아닙니다. cargo audit 자체도 패키지 버전을 비교하는 도구이지 함수 도달성 분석기가 아닙니다.

다음은 저장소 루트에서 당시 DB로 재현하는 명령입니다. 도구와 DB는 작업용 임시 디렉터리에만 설치하며 제품·잠금 파일은 변경하지 않습니다. 이후 점검은 최신 RustSec DB로 별도로 반복하세요.

rust_audit_dir=$(mktemp -d)
cargo install cargo-audit --version 0.22.2 --locked --root "$rust_audit_dir/tools"
git clone https://github.com/RustSec/advisory-db "$rust_audit_dir/db"
git -C "$rust_audit_dir/db" checkout --detach 8a1eb4f933fb5821add5b4e98601ebd90b8b3538
"$rust_audit_dir/tools/bin/cargo-audit" audit \
  --file sdk/desktop/src-tauri/Cargo.lock \
  --db "$rust_audit_dir/db" --no-fetch --json
"$rust_audit_dir/tools/bin/cargo-audit" audit \
  --file sdk/desktop/src-tauri/Cargo.lock \
  --db "$rust_audit_dir/db" --no-fetch --deny unsound

원문 결과는 test-results/desktop-security/cargo-audit.json, 엄격 검사 결과는 cargo-audit-strict.json, 검사 버전·DB 커밋·원문 해시는 같은 폴더의 provenance.json에 보관합니다. 공개 문서에는 이 경고 요약만 싣습니다. 검사 전후 Cargo.lock SHA-256은 fefd544acbd1bbe4e256a2e859bf542ca90ce43024696813e2c02210d670c78d로 동일했습니다.

Rust SDK와 데스크톱 실행물은 릴리즈의 서비스 Docker 런타임에 들어가지 않습니다. 그렇다고 데스크톱 배포의 경고가 사라지는 것은 아닙니다. 조직별 Linux 데스크톱 빌드·배포에서는 GTK3 유지보수 위험을 검토하고 Tauri/Wry 전환과 운영체제 GLib·GTK·WebKitGTK 보안 업데이트를 계속 추적해야 합니다. 이 검사는 운영체제 공유 라이브러리의 취약점이나 macOS/Windows 설치물 실행을 검증한 결과가 아닙니다.
