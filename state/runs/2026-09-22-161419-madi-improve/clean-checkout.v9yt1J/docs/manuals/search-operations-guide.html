한국어 검색 운영과 진단

/app/search에서 현재 워크스페이스의 접근 가능한 지식을 검색합니다. 기본 화면은 같은 문서의 문서·블록·코드·할 일을 먼저 묶고 페이지를 나누며, 한 묶음의 일치 위치는 최대 3개 보여줍니다. 데이터베이스 등 문서에 속하지 않는 결과는 별도 항목입니다. 문서 미리보기는 현재 원문과 권한을 다시 확인하며, 검색할 때와 버전이 다르면 경고합니다.

용어 사전

워크스페이스 소유자·관리자는 검색 화면의 검색 운영에서 표준 용어와 별칭을 등록합니다. 예를 들어 쿠버네티스의 별칭으로 k8s, Kubernetes를 등록하면 같은 의미의 검색 부분으로 해석합니다. 사전은 해당 워크스페이스 구성원의 검색에 공유되므로 개인 문서의 비밀이나 민감한 문장을 등록하지 마세요. 저장 전 공유 확인이 필요하며 현재 정보보호 정책으로 차단·마스킹될 수 있습니다.

사전은 최대 300개 용어, 용어별 별칭 12개, 표준 용어·별칭 각각 UTF-8 200바이트까지 받습니다. 공백·대소문자·NFKC 정규화 후 서로 다른 용어가 같은 별칭을 사용하면 저장하지 않습니다. 여러 관리자가 동시에 변경하면 revision 충돌을 알려주므로 현재 사전을 다시 확인하고 적용해야 합니다. 서비스 관리자는 다른 워크스페이스의 관리 멤버십을 우회하지 않습니다.

검색 해석은 Unicode NFKC와 대소문자 정규화, 공백 차이, 등록된 약어·동의어를 처리합니다. k8s장애, 쿠 버 네 티 스 장애, 전각 영문 등은 사전과 로컬 정규화 색인을 통해 찾을 수 있습니다. ASCII 약어는 다른 영단어 내부에 끼어들지 않습니다. 예를 들어 AI 별칭이 mail을 인공지능으로 바꾸지 않습니다.

이 기능은 한국어 형태소 분석기가 아닙니다. PostgreSQL simple 사전도 한국어 어미·조사를 분석하는 사전이 아닙니다. 조직별 실제 용어를 등록하고 제공한 정답으로 품질을 평가하세요. 따옴표·OR·제외(-단어) 문법이나 16개를 넘는 검색 부분은 검색어를 잘라 버리지 않고 기존 검색 문법으로 처리하며, 화면의 검색어 해석에 확장 생략 이유가 표시됩니다. PostgreSQL 텍스트 검색 사전 설명

색인과 원문

원본 Markdown은 변경하지 않습니다. Go의 기존 로컬 색인 작업자가 현재 버전의 원문·제목·블록에서 정규화 투영을 만들고 PostgreSQL GIN 사전 필터와 정확한 정규화 문자열 검사를 함께 사용합니다. 새 외부 서비스나 환경변수, 외부 AI 전송은 필요하지 않습니다.

색인이 갱신 중이면 이전 문서 버전의 정규화 투영은 검색하지 않습니다. 문서 원본의 기존 FTS·부분 일치 경로는 유지합니다. 공백 확장에 사용되는 태그·별칭 투영은 각각 현재 목록과 같은 최대 32개·항목 200바이트의 제한을 적용하며, 기존 원문 FTS/태그 필터 경로는 별도로 유지합니다.

한 투영에서 서로 다른 문자 bigram이 32,768개를 넘으면 불완전한 사전 필터로 결과를 누락하지 않도록 그 투영의 bigram 필터를 생략하고 정확한 정규화 문자열을 검사합니다. 매우 큰 동의어 검색도 사전 필터 예산을 넘으면 정확 확인 경로를 유지하며 경고합니다. 이 경우 쿼리가 느려질 수 있으므로 진단의 정확 확인용 사전 필터 생략 수와 실제 실행 시간을 확인하세요. 이것은 검색 정확도 보증이나 무제한 크기 지원을 의미하지 않습니다.

결과 탐색과 복구

상세 필터 아래에는 공간·소유자·태그·상태·기간·첨부 조건이 각각 칩으로 표시됩니다. 개별 칩을 해제하면 다른 조건은 유지됩니다. 현재 워크스페이스와 권한 범위가 함께 표시됩니다. 데스크톱에서는 오른쪽 패널, 모바일에서는 대화상자로 문서를 미리 볼 수 있습니다.

페이지 이동은 암호화한 keyset cursor를 사용합니다. 사용자·워크스페이스·검색 조건·사전 revision에 결합하고 15분 후 만료됩니다. 만료되거나 조건이 바뀌면 첫 페이지부터 다시 검색합니다. REST 호환 offset도 남아 있지만 cursor와 동시에 사용하지 않습니다. 페이지마다 현재 권한을 다시 적용하며 실시간 문서 편집으로 순서가 바뀔 수 있으므로 고정 DB 스냅샷으로 간주하지 마세요.

검색 조건·선택한 미리보기는 주소에 남고, 같은 탭의 뒤로 가기에서는 검색 화면의 위치를 복원합니다. 원문·검색 결과·AI 답변은 탐색 상태에 저장하지 않습니다. 페이지 이동용 cursor와 위치는 사용자·워크스페이스별로 제한된 메모리에만 보관하며 브라우저를 완전히 다시 열면 이전 페이지 대신 첫 페이지로 돌아가야 할 수 있습니다.

결과 없음은 현재 조건과 현재 권한의 결과가 없다는 뜻입니다. 다른 사용자의 문서 존재 여부는 알려주지 않습니다. 색인 갱신 대기는 현재 열람 가능한 문서 중 갱신 대기가 있다는 정보이며, 그 검색어와 일치하는 문서가 있다는 뜻이 아닙니다. 검색어 다시 작성, 필터 해제, 색인 상태 새로 확인을 사용할 수 있습니다. 잘못된 조건·페이지 만료·시간 초과를 성공한 빈 결과로 바꾸지 않습니다.

실제 진단과 평가

검색 진단은 실제 API 검색의 해석·시간·현재 접근 가능한 투영 상태를 보여줍니다. 선택하면 같은 SQL·인자로 EXPLAIN (ANALYZE, BUFFERS)를 읽기 전용 트랜잭션에서 실행합니다. 계획 실행은 3초 statement timeout과 1초 lock timeout으로 제한합니다. 계획의 노드 종류와 인덱스 경로만 표시하며 검색 상수, 원문, 제거된 행 수, 접근 불가능한 모집단 통계는 표시하지 않습니다. PostgreSQL 설정·인덱스·통계를 서비스 권한으로 임의 변경하지 않습니다. PostgreSQL 실행 계획 설명

한국어 평가에서는 검색어와 기대한 현재 접근 가능한 문서를 명시합니다. 최대 30개 평가, 평가별 정답 최대 20개, k=1~20 범위에서 실제 검색 결과의 Recall@k와 MRR@k를 계산합니다. 정답 문서가 없거나 접근할 수 없으면 평가를 진행하지 않습니다. 조회 권한을 넘겨 점수를 높이지 않습니다.

진단·평가 입력은 자동으로 DB에 보관하거나 외부 AI로 전송하지 않습니다. 감사에는 실행 여부·개수만 기록합니다. 일반 검색의 개인 검색 이력은 별도 명시 동의 설정을 따릅니다. 합성 평가셋 다운로드는 실제 고객 자료가 아닌 공개 회귀 예제입니다.

2026-09-08 Go 1.26.8 / PostgreSQL 18.6에서 한국어 합성 문서 9개·질의 12개는 Recall@5=1.000, MRR@5=1.000을 기록했습니다. 약어·혼합 영문·공백·오류 코드·ASCII 약어 오탐 방지의 제공된 합성 사례만 검증한 수치이며 실제 조직 데이터의 검색 품질 보증은 아닙니다. 현재 버전·비공개 ACL·사전 CAS·4가지 정렬 cursor·진단 원문 비노출까지 포함한 최근 검색 PG race 회귀는 32.077초에 통과했습니다.

1만 문서 계획 시험은 단일 요청·작은 합성 본문·20% 비공개 조건입니다. 정규화 조건을 서로 배타적인 GIN/불완전 투영/정확 확인 경로로 나눈 뒤 k8s장애 64.581ms, 공백 질의 74.136ms였습니다. 해당 계획에서 GIN 사전 후보 100개를 확인했고 정규화 경로의 shared hit는 1,431에서 428로 줄었습니다. 별도의 원본 결과 test-results/search-operations/korean-10000-plan.json에서 환경과 계획을 확인하세요. 기존 규모 검증의 큰 본문·동시 요청 시나리오와 서로 같은 수치로 해석하지 않습니다. 서버 전체 메모리·천만 문서·지속 쓰기·전용 운영 환경은 추가 수용 시험이 필요합니다.

같은 날 실제 Chromium 브라우저 회귀는 24.65초에 통과했습니다. 사전의 공유 동의, 실제 계획·평가, 문서별 그룹의 40개/5개 페이지 이동, 개별 필터 해제, 선택 미리보기와 뒤로가기 위치 복원, 390px 모바일 화면, 미리보기 권한 회수, 만료 cursor 복구를 확인했습니다. 문서 그룹과 미리보기, 모바일 검색, 모바일 미리보기는 합성 문서만 사용하는 실제 시험 화면입니다.
