Git 동기화 가이드

madi의 Git 연동은 Markdown 원본과 첨부파일을 미리보기 → 명시적 동의 → PostgreSQL 작업으로 전송하거나 수신합니다. 기본값은 사용 안 함입니다. 운영 서비스의 Git 저장소를 자동으로 푸시하거나 시스템 Git 명령을 실행하는 기능이 아닙니다.

먼저 알아둘 권한 경계

  • Git 저장소의 접근 권한은 madi 권한과 독립적입니다. 개인·선택 공유 문서라도 전송하면 Git 열람자가 원문과 첨부파일을 볼 수 있습니다. 이후 madi에서 권한을 폐기해도 과거 Git 이력은 회수되지 않습니다.
  • 연결 생성·인증 정보 변경은 서비스 관리자만 가능합니다. 실행은 그 워크스페이스의 소유자·관리자인 실제 로그인 사용자만 가능합니다. API 키·플러그인 위임으로 동의하지 않습니다.
  • 전송 대상은 요청자와 연결 실행 계정이 현재 모두 접근 가능한 선택 문서입니다. 다른 문서나 보이지 않는 개인 문서를 묵시적으로 포함하지 않습니다.
  • 수신 시 원격 owner, id, visibility, status, 워크스페이스·공간 권한을 상속하지 않습니다. 새 문서는 요청자 소유의 개인 초안이며, 기존 문서는 일반 문서 수정·버전·정보보호·승인 경로를 거칩니다. 자동 공유를 피하기 위해 수신 연결의 실행 계정은 요청자 본인이어야 합니다.

관리자 설정

  1. /admin/git-sync에서 정확한 Git 호스트를 한 줄에 하나씩 등록합니다. 와일드카드가 아닌 호스트 이름입니다.
  2. 내부 IP로 연결한다면 사내망 IP 연결 허용을 명시적으로 선택합니다. 링크 로컬·멀티캐스트·미지정 IP는 허용되지 않습니다.
  3. Git 기능을 켠 뒤 /app/git-sync에서 연결을 등록합니다.
  4. HTTPS 또는 SSH URL, 고정 브랜치, Git 전용 폴더, 실행 계정과 수신 공간을 입력합니다. 예: https://git.example.internal/team/knowledge.git, main, madi.
  5. HTTPS는 내부 CA 인증서를 추가할 수 있지만 인증서 검증을 끌 수 없습니다. SSH는 개인 키와 서버의 고정 공개 키가 반드시 필요합니다. 서버 공개 키는 별도 신뢰 경로로 검증해서 등록하세요.
  6. 연결을 사용으로 저장한 뒤 읽기 연결을 진단합니다. 이 진단은 브랜치 조회만 확인하며 쓰기 권한을 시험하지 않습니다.

사용자 이름·비밀번호/토큰·개인 키·개인 키 암호는 ENCRYPTION_KEY로 암호화하여 DB에 저장합니다. 조회 API와 화면에는 비밀 원문이 다시 나오지 않습니다. 수정할 때 비밀 필드를 비우면 기존 값이 유지됩니다. 원격 URL·브랜치·폴더·실행 계정·공간은 기존 연결에서 바꿀 수 없으며 새 연결이 필요합니다. 정책이나 연결 인증 정보를 바꾸면 이전 미리보기 동의는 무효화됩니다.

문서 전송

  1. /app/git-sync에서 저장된 연결과 선택 문서를 Git으로 전송 방향을 선택합니다.
  2. 문서를 체크합니다. 연결된 첨부파일도 전송 목록에 포함됩니다.
  3. 고정 원격을 읽는 데 동의하고 미리보기를 만듭니다. 아직 commit/push하지 않습니다.
  4. 파일 이름·크기·변경 여부, 원격 commit, Git 권한 경고를 확인합니다.
  5. 충돌이 없으면 실행 동의 창에서 목록과 독립된 Git 권한을 확인하고 실행합니다.

문서에는 YAML Front Matter의 제목·태그·별칭·원본 ID·상태·원본 버전이 함께 내보내집니다. 문서와 첨부 링크는 상대 경로로 바뀝니다. 이미 연결한 Git 경로는 문서 제목을 바꿔도 유지하여 조용히 중복 파일을 만들지 않습니다. 기존 연결 경로가 여러 원본과 충돌하면 자동 추정하지 않고 중단합니다.

현재 원격 HEAD가 미리보기와 다르면 중단합니다. 마지막 동기화 이후 원격에서 수정·삭제한 파일이나 매핑되지 않은 기존 파일을 덮어쓰지 않습니다. 선택하지 않은 파일·폴더와 다른 Git 루트 항목은 보존합니다. 자동 삭제·강제 푸시·리베이스·충돌 병합은 하지 않습니다.

원격 문서 수신

  1. Git에서 개인 초안으로 수신을 선택하고 우선 원격 목록을 미리 봅니다.
  2. 수신할 Markdown과 첨부 경로를 직접 선택합니다. 첨부파일만 고르지 말고 연결할 Markdown을 하나 이상 포함합니다.
  3. 선택한 파일 다시 비교로 새 미리보기를 만들고 동의합니다.
  4. 새 문서는 지정 공간의 개인 초안으로 생성됩니다. 새 첨부파일은 선택한 첫 Markdown 문서에 연결되며, 선택한 문서 안의 일반 상대 링크는 서비스 문서·첨부 URL로 바뀝니다.

원격의 게시 상태나 권한 필드는 수신하지 않습니다. 기존 매핑 문서를 사용자가 수정했다면 버전 충돌을 표시합니다. 원격 파일 삭제로 madi 문서를 삭제하지 않습니다. 로컬 수신은 문서/첨부 항목별로 일반 저장과 Git 매핑·버전 체크포인트가 같은 DB 트랜잭션에 기록됩니다. 중간 오류 전에 이미 저장한 항목은 보존되므로 실행 이력을 확인하고 새 미리보기에서 남은 항목을 다시 비교하세요. 전체 묶음을 원자적으로 되돌린다고 보장하지 않습니다.

취소·장애·복원

  • 대기 작업은 취소할 수 있습니다. 이미 시작한 원격 전송은 네트워크 중단만으로 롤백되지 않으며 결과 확인 필요로 남을 수 있습니다.
  • 전송 전에 후보 commit ID를 DB에 기록합니다. 프로세스가 재시작해도 불명확한 전송을 자동 재실행하지 않고 그 후보와 현재 원격 HEAD를 비교합니다.
  • 원격 commit 결과 확인은 읽기만 합니다. 후보와 현재 HEAD가 정확히 같으면 추가 전송 없이 완료 처리합니다. 다르면 Git 관리자와 이력을 확인하고 새 미리보기를 만드세요. 후보가 후속 commit의 조상인지 자동 추정하지 않습니다.
  • 전송 직전 버전·현재 계정·문서 ACL·연결 정책을 재검사하고 전송 중에도 주기적으로 다시 확인하여 변경 시 연결을 중단합니다. 원격 Git과 PostgreSQL은 하나의 트랜잭션이 아니므로, 이미 전송·수신된 바이트를 권한 폐기와 동시에 회수할 수 있다고 보장하지 않습니다.
  • 미리보기 본문은 암호화된 임시 DB 스냅샷이며 동의는 24시간 유효합니다. 완료·중단된 만료 스냅샷은 정리하고 실행 메타데이터는 유지합니다. 결과가 불명확한 전송의 스냅샷은 결과 확인을 위해 남습니다.
  • 백업 복원 시 Git 정책과 연결은 중지됩니다. 대기 미리보기·작업은 취소하며 실행 중 원격 전송은 결과 불명으로 표시합니다. 복원만으로 원격 쓰기를 재개하지 않습니다. 원격 대상·키·권한과 과거 실행 이력을 재검증하세요.

작은 지식 저장소를 명시적으로 주고받는 기능입니다. 대형 Git 모노레포·LFS·서브모듈·서버별 전용 인증 확장·임의 CLI·양방향 실시간 병합 기능을 제공한다고 주장하지 않습니다. 서비스 이미지 안에 Git 실행 파일이나 인터넷 연결이 필요하지 않습니다. 내부 Git 서버도 동일한 정책으로 연결할 수 있습니다.

API

모든 아래 경로는 /api/v1 기준이며 관리자/워크스페이스 권한과 CSRF 보호를 적용합니다.

  • GET/PUT /admin/git-sync/settings
  • GET/POST /git-sync/connections, PUT /git-sync/connections/{id}
  • POST /git-sync/connections/{id}/test
  • POST /git-sync/connections/{id}/preview: direction, document_ids 또는 paths, read_consent: true
  • GET /git-sync/connections/{id}/runs, GET /git-sync/runs/{run}
  • POST /git-sync/runs/{run}/confirm: 현재 revision, config_fingerprint, remote_commit, confirm_external_visibility: true
  • POST /git-sync/runs/{run}/cancel, POST /git-sync/runs/{run}/inspect

실행 세부 응답의 파일 목록은 요청자 본인의 현재 원본 문서 ACL을 다시 확인한 뒤 제공합니다. 작업 목록·일반 작업 결과에는 본문이나 인증 정보를 포함하지 않습니다.

검증 근거

PostgreSQL 격리 스키마와 작업 전용 bare 저장소에서 선택 문서/첨부 내보내기, 암호화 스냅샷, 소스 버전 변경 차단, 원격 CAS 충돌, 동일 후보 commit 확인, 개인 초안 수신, 첨부 링크, canonical 저장·버전 경계를 시험합니다. HTTPS 테스트 서버에서는 미등록 CA 거부와 리디렉션 차단을, 실제 SSH 테스트 서버에서는 고정 서버 키와 ambient proxy 무시를 확인합니다. 실제 운영 GitLab/Gitea/GitHub 설치 버전별 수용 시험은 운영자가 자신의 내부 환경에서 별도로 수행해야 합니다.

관련 공식 문서: go-git 릴리즈, packfile API, 리디렉션 인증 정보 관련 보안 권고. 사용 라이브러리 버전은 저장소의 go.mod와 go.sum에 고정합니다.
