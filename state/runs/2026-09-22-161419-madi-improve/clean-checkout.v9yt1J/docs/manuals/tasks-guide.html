할 일과 통합 일정

/app/tasks에서 문서의 체크리스트를 목록·칸반·통합 캘린더로 볼 수 있습니다. 화면의 보기·검색어·담당 범위·달력 월은 URL에 보존되어 새로고침이나 링크 공유 후에도 유지됩니다.

문서와 연결된 할 일

Markdown의 - [ ], - [x]와 중첩·번호 목록 체크리스트, 편집기가 만든 HTML 표 안의 할 일을 함께 모읍니다. 코드 예제나 일반 HTML 입력 필드는 할 일로 취급하지 않습니다. 원본 문서 접근 권한을 그대로 적용합니다.

  1. 속성에서 담당자·마감일·우선순위·진행 상태를 선택합니다. 담당자를 지정해도 문서 공유 권한은 추가되지 않습니다. 담당자는 그 문서를 읽을 수 있어야 합니다.
  2. 처음 속성을 저장하면 Markdown 원문에 [작업](/app/tasks?task=UUID) 링크를 넣습니다. HTML 표에는 같은 주소의 HTML 링크를 보존합니다. 할 일 이름이나 위치를 바꾸어도 이 링크를 유지하면 담당자·기한이 연결됩니다.
  3. 같은 고유 링크를 복제한 경우 임의로 한 항목을 선택하지 않습니다. 속성에서 별도 작업으로 분리를 확인해야 새 ID를 발급합니다.
  4. 완료 체크 또는 칸반의 드래그 손잡이·상태 선택으로 원문 체크박스를 함께 바꿉니다. 다른 사용자가 문서를 수정한 경우 저장을 거부하고 현재 목록을 다시 불러오도록 안내합니다.

할 일 상세 속성은 PostgreSQL에 저장하며 서비스 백업으로 보존합니다. 단순 Markdown 파일만 내보내면 원문과 고유 참조 링크는 남지만 별도 담당자·우선순위 메타데이터의 복원까지 보장하지 않습니다.

담당자가 퇴사하거나 권한을 잃으면 속성에 재지정 필요 상태를 표시합니다. 관리자가 검토 프로세스를 켜지 않으면 ‘검토 대기’ 선택을 노출하지 않습니다. 할 일 상태는 문서 게시 승인이나 실행 권한을 대신하지 않습니다.

내 할 일과 팀 업무

내 담당·개인 할 일, 팀 담당, 미완료, 완료, 기한 초과, 오늘 및 이번 주 마감으로 좁힐 수 있습니다. 마감일은 날짜 단위이며 오늘 기준은 개인 설정의 시간대에 따릅니다. 문서에 쓴 2026-09-20과 고유하게 식별되는 @사용자명도 초기 속성으로 읽습니다. 이후 속성 저장 값이 우선합니다.

통합 캘린더

할 일 마감일, 문서의 Front Matter date, 날짜 이름의 일일 노트, 데이터베이스의 날짜 속성, 직접 등록한 회의·마일스톤을 함께 표시합니다. 모바일에서는 7열 요약 달력의 날짜를 누르고 아래에서 상세 일정을 봅니다.

회의·마일스톤은 기본 ‘나만 보기’이며 기간은 366일 이내입니다. 워크스페이스 공유를 선택해도 연결 문서가 비공개이면 해당 문서를 읽을 수 있는 사람에게만 보입니다. 소유자만 직접 등록한 일정을 수정·삭제할 수 있습니다. 일정을 삭제해도 연결 문서와 할 일은 삭제하지 않습니다.

키 호출에서는 document:read가 필요하고 DB 일정은 추가로 database:read가 있어야 나타납니다. 수정은 document:write와 현재 사용자 ACL을 모두 검사합니다.

REST 연동

  • GET /api/v1/tasks/board?workspace_id=UUID: 할 일·현재 문서 버전·줄·source_start·고유 ID·상세 속성. document_id와 task 필터를 지원합니다.
  • PUT /api/v1/tasks/details: document_id, version, line, source_start, 기존 task_id, status, priority, assignee_id, due_date. 동일 HTML 줄의 여러 항목은 source_start로 구분합니다. 오래된 위치·버전은 HTTP 409입니다.
  • GET /api/v1/tasks/calendar?workspace_id=UUID&month=2026-09: 현재 권한 내 통합 일정입니다.
  • POST /api/v1/tasks/calendar/events, PUT/DELETE /api/v1/tasks/calendar/events/UUID: 회의·마일스톤 관리입니다. 변경 요청에는 기존 일정 version이 필요합니다.

통합 조회는 최근 접근 가능한 문서 최대 2,000개·본문 합계 16MiB·할 일 10,000개, DB 날짜 2,000개로 제한합니다. 한도를 넘으면 응답의 truncated와 화면 안내가 표시됩니다. 모든 대규모 문서를 인덱싱했다고 오인하지 않도록 조회 범위를 명시합니다.

할 일 보드는 현재 문서 권한을 통과한 최신 문서 2,001개까지만 확인하고, 마지막 한 개는 상한 도달 판단에만 사용합니다. total_documents_exact=true인 경우에만 total_documents를 정확한 문서 수로 읽으세요. false이면 확인한 하한이며 total_documents_is_lower_bound=true로 함께 표시합니다. 열람할 수 없는 문서 수를 포함하거나 정확한 전체 총수를 세기 위해 응답을 지연시키지 않습니다. 화면은 결과가 제한되면 ‘전체 할 일’ 대신 ‘조회한 할 일’로 표시합니다.

특정 문서의 document_id 필터는 서버에서 조회 상한보다 먼저 적용되므로 워크스페이스의 최신 문서 2,000개 밖에 있는 오래된 문서도 직접 확인할 수 있습니다. 문서 필터가 잘못되면 전체 할 일로 대신 조회하지 않고 오류를 표시합니다. Markdown 정본과 현재 버전으로 수정하는 경로, 할 일 고유 ID·중복 구분·현재 담당자 권한 검사는 그대로 유지합니다.

달력의 document_id 필터도 같은 문서에 적용됩니다. 그 문서의 날짜·할 일, 실제 document_id로 연결한 회의·마일스톤만 현재 권한으로 조회하며, 독립 일정이나 DB 날짜 행을 임의로 연결하지 않습니다. task 링크는 특정 할 일을 찾아 편집하는 맥락이고 전체 달력의 모든 종류를 그 할 일로 제한한다는 뜻은 아닙니다.

검증

tests/tasks.mjs는 실제 서비스에서 담당자/마감일/우선순위 선택, 원문 고유 참조, 칸반 손잡이 드래그, URL 상태 유지, 문서·DB·회의 일정, PC·모바일 레이아웃을 확인합니다. PostgreSQL 회귀 시험은 비공개 ACL·담당자 권한 회수·버전 충돌·중복 참조 분리·동일 줄의 HTML 표 할 일·완료 outbox의 트랜잭션 정합성을 검증합니다.
