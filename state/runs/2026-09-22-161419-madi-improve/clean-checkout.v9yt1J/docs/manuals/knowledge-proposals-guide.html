지식 변경 제안서

v0.2.0이 게시되었습니다. main CI·태그 릴리즈의 통합 검사와 이미지 재반입·폐쇄망 검증을 통과했습니다. 실제 검증 범위와 한계는 배포 검증 기록을 확인하세요.

/app/knowledge-proposals에서 사람과 AI의 수정안을 문서 원문과 분리해 공유할 수 있습니다. 문서 속성의 ‘지식 변경 제안’으로 열면 해당 문서에서 시작합니다.

원문을 유지하고 제안하기

  1. 현재 작성 가능한 문서를 선택합니다. 화면에 표시된 기준 원문 version을 확인합니다.
  2. 제안 Markdown과 변경 이유를 작성합니다. ‘AI 도움을 받아 작성’은 작성자의 분류이며 모델 실행 증명은 아닙니다.
  3. 현재 문서 열람자가 제안과 변경 이유를 볼 수 있음을 확인합니다. 개인 비공개 임시 메모로 오해하지 마세요.
  4. 공유 전 비교에서 기준·제안 원문을 확인하고 저장합니다. 이 단계에서는 기존 문서를 변경하지 않습니다.

제안 본문과 이유는 서버에서 암호화되며 현재 문서의 ACL과 민감정보 정책을 적용합니다. 기준+제안 비교 JSON 합계는 2MiB, 열린 개인 변경안은 100개까지입니다. 원문과 같은 내용은 저장하지 않습니다.

비교 후 원자적으로 반영

‘비교 후 변경안 반영’은 문서의 기존 저장 경로를 사용합니다. 기준 원문 version과 제안 revision이 그대로인 경우에만 원문, 태그·블록 메타데이터, 문서 이력, 업무 이벤트와 제안 처리 기록을 한 트랜잭션에서 저장합니다. 한 단계라도 실패하면 일부만 반영하지 않습니다.

기준 문서가 바뀌면 자동 재배치나 자동 병합을 하지 않습니다. 기준·현재·제안 원문을 비교해 현재 버전으로 새 제안을 작성하세요. 이미 반영된 같은 제안을 다시 요청해도 원문을 다시 덮어쓰거나 추가 문서 버전을 만들지 않습니다.

제안 반영은 게시 승인이 아닙니다. 관리자 검토 설정이 켜져 있으면 기존 게시 정책을 그대로 따릅니다. 게시 문서의 내용이 달라지면 다시 초안이 될 수 있습니다. 관리자 설정이 없으면 검토 반려 UI/처리를 제공하지 않습니다. 작성자는 자신의 열린 제안을 철회할 수 있습니다.

API와 에이전트

POST /documents/{id}/proposals에는 base_version, markdown, reason, provenance, consent:true가 필요합니다. 현재 문서 열람·작성 권한과 키의 두 scope가 모두 필요합니다.

GET /knowledge/proposals/{id}는 현재 ACL로 기준·현재 원문과 변경 이력을 조회합니다. POST /knowledge/proposals/{id}/merge는 revision과 consent:true를 확인합니다. 외부 에이전트는 MCP의 create_document_proposal, get_document_proposal, merge_document_proposal로 같은 경로를 사용합니다. 에이전트에게 문서보다 높은 권한을 주지 않습니다.

해시 일치는 변경안이 변조되지 않았음을 확인하는 조건 중 하나일 뿐, 제안의 사실성이나 안전한 운영 실행을 보장하지 않습니다. 문서 안에 셸 명령이 있어도 제안 병합이 해당 명령을 실행하지 않습니다.

검증

격리 PostgreSQL에서 기준 충돌, 동의 누락, 암호화, Front Matter·할 일·게시 상태 보존, 재시도 멱등성, 강제 이력 저장 오류의 원자 롤백, MCP 범위 격리를 검사했습니다. 브라우저에서 공유 전 비교→원문 유지→반영 확인→새 버전, 모바일 390px 표시를 확인하는 별도 게이트가 있습니다. 통합 릴리즈 전 전체 회귀를 다시 실행합니다.
