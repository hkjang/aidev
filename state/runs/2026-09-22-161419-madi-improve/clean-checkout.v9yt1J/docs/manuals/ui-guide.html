UI 구성과 접근성

추천과 실제 선택

madi에는 Radix Primitives + 프로젝트 소유 React 컴포넌트·CSS 디자인 시스템을 선택했습니다. 대화상자와 프로필 메뉴처럼 포커스·키보드 동작이 중요한 요소는 Radix를 사용합니다. Radix는 접근성 패턴과 포커스 관리, 스타일을 직접 제어할 수 있는 기반을 제공합니다. Radix 공식 소개

사용자가 제시한 shadcn/ui도 컴포넌트 소스를 직접 관리하며 제품에 맞게 바꾸는 접근에 적합합니다. 현재 구현은 shadcn CLI로 생성한 프로젝트라고 표기하지 않고, 실제 사용한 Radix와 자체 컴포넌트를 명시합니다. shadcn/ui 공식 소개

단순 선택은 브라우저의 기본 select를 사용하고 한국어 접근성 이름을 연결했습니다. 다중 선택·DB 속성 변경·모바일 드롭다운은 실제 Chromium에서 옵션 선택과 저장·새로고침을 시험합니다. 라이브러리 사용만으로 모든 접근성이 보장된다고 간주하지 않습니다.

읽기와 탐색

  • 한국어 Noto Sans KR 폰트를 이미지에 포함하므로 외부 폰트 서버가 필요 없습니다.
  • 주요 본문과 입력은 16px를 기준으로 하고 개인화 화면에서 글자 크기와 문서 폭을 조정합니다. 날짜·버전 등 보조 표시는 구분된 크기를 사용합니다.
  • 짙은 녹색 탐색 영역, 차분한 배경, 여백과 대비로 문서와 조작을 구분합니다. 라이트·다크 모드를 제공합니다.
  • 관리자 /admin과 사용자 /app, 개인 설정·키 관리 영역을 분리합니다. 관리자 권한이 없는 사용자는 관리자 메뉴를 보지 않습니다.
  • URL에 선택 메뉴·뷰·검색 조건을 보존합니다. 개인 설정과 트리 상태는 서버에도 저장하고, 늦게 도착한 이전 문서·워크스페이스 응답은 현재 화면에 적용하지 않습니다.
  • 메뉴 스크롤바는 탐색 영역과 색을 맞춥니다. 모바일 표는 글자를 한 글자씩 줄이지 않고 필요한 경우 표 영역 안에서 가로로 스크롤합니다.

목적별 메뉴와 작업 시작

왼쪽 내 작업 방식에서 개인 노트, 팀 위키, 지식 데이터베이스, 지식 운영을 고릅니다. 홈·문서·검색·내 처리함은 기본 진입점이며 작업 방식에 맞는 도구를 가까이 배치합니다. 전체 도구 보기를 펼치면 도구 이름으로 검색하고 자주 쓰는 도구를 최대 12개 고정할 수 있습니다. 관리 기능은 별도 관리 및 설정에 모았습니다.

작업 방식·고급 메뉴 펼침·고정 도구·문서 패널 선택은 개인 설정으로 서버에 저장합니다. 관리자가 비활성화한 기능이나 현재 역할에 허용되지 않는 관리 메뉴를 고정 도구로 우회할 수는 없습니다. 메뉴를 접어도 현재 선택한 허용 메뉴는 찾을 수 있고, 기존 직접 URL은 유지합니다. 가져오기는 한 진입점이며 이전 /app/migrations 주소도 같은 이관 화면으로 연결됩니다.

홈의 바로 메모는 실제 개인 수집 문서를 만든 뒤 편집기를 엽니다. 분류를 먼저 선택할 필요가 없고, 새 메모는 기본적으로 나만 볼 수 있습니다. 이어서 작업 목록은 현재 열람 가능한 최근 문서를 보여주며, 템플릿 영역은 최근 업데이트된 사용자 템플릿과 기본 양식을 구분합니다. 내 처리함에서는 개인 수집 메모, 본인이 담당하는 미완료 작업, 현재 접근 가능한 계정 알림을 확인합니다. 검토함은 관리자가 검토·승인 기능을 활성화한 경우에만 표시합니다.

문서 패널과 네 가지 상태

문서 오른쪽 패널은 연결·속성·댓글·AI·이력 다섯 탭으로 구성됩니다. 작은 화면에서는 문서 아래로 이어지고, 패널 버튼으로 접거나 펼칠 수 있습니다. 방향키와 Home/End로 탭을 선택할 수 있습니다. AI 탭은 같은 스트리밍 API를 사용하며 별도의 가짜 응답을 표시하지 않습니다.

문서 상단의 상태는 서로 다른 의미입니다.

상태 의미
저장 현재 서버 버전과 아직 확정되지 않은 편집 내용
내부 공유 나만 보기, 선택한 사용자, 워크스페이스 접근 범위
게시 단계 초안·게시·검토 등 문서 운영 상태. 내부 공유와 별개
외부 링크 소유자가 확인하는 미폐기·미만료 링크. 실제 접속은 현재 정책·비밀번호·IP 조건을 따름

저장만으로 게시되거나 외부 링크가 만들어지지 않습니다. 게시 단계는 기존 운영 속성과 승인 정책을 따르며, 외부 링크는 소유자의 별도 명시적인 설정이 필요합니다.

상단 편집 모드는 읽기와 편집 두 가지로 시작합니다. 문서 보기 도구에서 Markdown 원문, 집중 모드, 발표, 인쇄/PDF를 엽니다. 원문 편집은 공동 편집 세대를 바꿀 수 있다는 안내를 유지하며, 모드를 바꾸기 전에 미확정 변경을 확인합니다. 태그는 칩으로 표시하고 현재 열람 가능한 문서의 태그를 제안합니다. 한국어 입력 조합 중 Enter는 태그 확정으로 처리하지 않습니다.

변경 검토와 복구

문서 저장, AI 초안, 위치 이동, 이관과 Git 반영에는 변경 전후·주의 사항·명시적 적용을 구분하는 공통 검토 UI를 사용합니다. 각 기능의 기존 권한, 원문 검증, 원격 전송 동의와 버전 검사는 유지됩니다.

  • 409 충돌: 서버 내용과 내 초안을 비교하고 확인한 서버 버전에만 다시 적용합니다. 그 사이 다른 변경이 생기면 다시 충돌로 안내합니다. 공동 편집 상태에서는 이 비교 창으로 강제 덮어쓰지 않습니다.
  • 401 세션 만료: 미확정 내용을 보관한 뒤 다시 로그인합니다. 자동으로 재전송하지 않습니다.
  • 403 접근 권한 변경: 소유자에게 권한을 확인하도록 안내하며 권한을 우회해 저장하지 않습니다.
  • 연결 실패: 보관 또는 명시적 재시도를 선택합니다. 성공 응답 전에는 저장 완료라고 표시하지 않습니다.

문서에서 그래프·할 일·근거 보관함으로 이동한 뒤 문서로 돌아가기를 누르면 해당 문서를 다시 권한 검사한 후 이전 위치를 복원합니다. 브라우저에는 사용자·워크스페이스별 URL, 스크롤 좌표, 숫자로 된 선택 범위만 저장하고 이 기능을 위해 문서 본문을 별도로 캐시하지 않습니다. 선택한 문서 버전이 달라지면 낡은 선택 범위를 재적용하지 않습니다.

문서 미리보기

연결 문서와 할 일의 미리보기는 현재 문서 조회 권한으로 원문을 다시 읽습니다. 지정된 출처 줄이 있으면 해당 위치 주변을 보여 주며, 미리보기 본문은 최대 30,000자로 제한합니다. 편집하거나 저장하지 않고, 2초마다 작은 권한 확인 요청으로 접근 가능 여부를 확인합니다. 문서 전체 열기는 정확한 문서·줄로 연결하며, 미리보기를 닫으면 처음 누른 버튼으로 포커스가 돌아갑니다. 데스크톱 우측 패널과 모바일 대화상자에 같은 컴포넌트를 사용합니다.

선택 영역 AI

  1. 먼저 문서 변경을 저장한 뒤 문장을 선택하고 선택 AI를 누릅니다. 원문 위치가 정확한 읽기·블록 편집의 문장 선택도 사용할 수 있습니다. 서식이나 중복 문장으로 위치를 확정할 수 없으면 추측하지 않고 Markdown 원문에서 범위를 선택하도록 안내합니다.
  2. 공급자 주소·모델·선택 구간을 확인하고 전송에 명시적으로 동의합니다. 작업은 문장 개선·요약·번역·이어 쓰기입니다. 한 번에 UTF-8 32KiB까지 보내며, 제목·태그·나머지 본문·검색 결과는 함께 보내지 않습니다. HTTP 주소라면 암호화되지 않는 구간임을 표시합니다.
  3. 실제 스트리밍 응답이 정상 완료되어야 원문과 비교할 수 있습니다. 중간 결과는 적용할 수 없으며, 생성 중 권한·문서 버전·공급자가 바뀌면 제안을 회수합니다.
  4. 선택한 범위만 교체, 선택한 범위 뒤에 추가, 새 개인 문서로 저장 중에서 적용 위치를 고릅니다. 원문 적용은 기존 버전 검사·승인·정보보호 정책을 거칩니다. 제목·태그·공개 범위를 불필요하게 다시 보내지 않습니다.

새 개인 문서 저장도 검증을 생략하지 않습니다. 완료된 제안의 암호화 확인값은 사용자·원문 버전/범위·제안 내용·공급자에 묶여 30분 뒤 만료됩니다. 문서 생성 트랜잭션에서 현재 참조 권한과 버전을 다시 확인합니다. AI 결과는 별도 실행 권한을 가지지 않으며 자동 게시되지 않습니다.

문서 접근 요청

공유 및 속성에서 내부 공유 범위나 상위 문서를 바꾸면 공유·이동 영향 확인을 먼저 표시합니다. 현재 문서 버전과 상위·공간·개별 공유·워크스페이스 역할을 기준으로 범위 확대 가능성을 보수적으로 설명합니다. 숨겨진 하위 문서 수나 열람 가능한 인원을 추정하지는 않습니다. 변경 동의는 목적지를 바꾸거나 현재 범위를 다시 확인할 때 해제됩니다. 확인 뒤 목적지나 공유 정책이 바뀌면 기존 티켓으로 적용하지 않고 409로 멈춥니다. 문서 우클릭의 위치 변경에도 같은 확인을 사용합니다.

내부 문서 주소 복사는 외부 공개가 아닙니다. 공유 범위나 위치를 바꿔도 외부 링크를 자동 생성하거나 게시 승인을 대신하지 않습니다. 문서 ID와 내부 링크는 이동 후에도 유지되지만 상위 제한이 달라지면 하위 문서 접근도 영향을 받을 수 있습니다.

문서 주소를 열 수 없을 때 접근 권한 요청에서 현재 워크스페이스와 읽기/편집 권한, 업무 목적을 확인합니다. 요청 화면이나 내가 보낸 요청에는 숨겨진 문서의 제목·원문을 표시하지 않습니다. 존재하지 않거나 현재 워크스페이스에 속하지 않는 주소도 같은 접수 응답과 제목 없는 기록을 만들므로, 접수됐다는 사실이 문서의 존재를 뜻하지 않습니다.

문서 접근 요청 → 내 문서에 온 요청에는 현재 소유하고 접근 가능한 문서의 요청만 표시합니다. 접근 허용에서 사용자·권한·공유 범위 변경을 확인하고 적용합니다. 나만 보기 문서는 선택한 사용자 공유로 전환되지만, 이전 비활성 공유가 남아 있다면 다른 사람의 권한을 다시 활성화하지 않고 거절합니다. 상위 문서·공간·워크스페이스의 권한 상한 때문에 실제 접근을 제공할 수 없는 경우에도 전체 변경을 적용하지 않습니다.

접근 허용은 보안 권한 처리이며 게시 검토·승인과 별개입니다. 서비스 관리자라도 다른 사람이 소유한 개인 문서의 요청을 대신 허용할 수 없습니다. 요청 사유는 현재 민감정보 정책을 적용한 뒤 암호화하여 보관합니다. 열린 요청과 시간당 새 요청은 각각 20개, 동일 대상은 열린 요청을 중복 생성하지 않으며 처리 후 10분 동안 다시 요청하지 못합니다. 본인의 대기 중 요청은 취소할 수 있습니다.

휴지통 이동과 실행 취소

문서의 확정된 상태에서 휴지통으로 이동하면 휴지통 이동 실행 취소 안내가 2분 동안 표시됩니다. 이 동작은 삭제 응답의 버전만 복원합니다. 그 사이 다른 사용자가 복원·변경·재삭제했다면 409 충돌로 멈추므로, 오래된 실행 취소가 동료의 후속 변경을 덮지 않습니다. 이때는 휴지통 확인에서 현재 상태를 다시 보고 복원하세요.

실제 삭제와 복원은 각각 문서 버전과 불변 스냅샷을 하나 증가시키며 보존 정책·현재 권한·정보보호·게시 정책을 그대로 적용합니다. 기존 외부 API의 expected_version 생략은 호환성을 위해 허용되지만 처리 시 최신 상태에 작동합니다. 안전한 되돌리기를 구현하는 클라이언트는 삭제 응답의 버전을 복원 요청에 반드시 넣어야 합니다.

선택 문맥 도구와 붙여넣기

블록 편집에서 텍스트를 선택하면 굵게·기울임·링크 도구가 나타납니다. 코드에 커서를 놓으면 코드만 복사하고, 표에서는 행·열 추가/삭제와 셀 병합/분할을 선택합니다. 같은 편집기의 실행 취소·다시 실행을 사용하며, 기존 블록 정리는 다중 선택·중첩·순서 이동의 키보드 대안입니다. 링크를 확인하는 동안 문서가 바뀌면 잘못된 위치에 적용하지 않고 다시 선택하도록 안내합니다.

HTML 서식이나 HTTP(S) URL을 붙여넣으면 먼저 방식을 선택합니다. 텍스트만 붙여넣기, 기본 서식 유지, URL의 링크로 붙여넣기·북마크로 붙여넣기를 구분합니다. 이미지·스크립트·추적 요소·스타일·복사된 블록 ID는 가져오지 않으며 URL 내용이나 미리보기 이미지를 자동 요청하지 않습니다. 북마크 제목과 설명은 사용자가 직접 수정합니다. 확인 중 문서가 바뀌면 기존 선택 범위에 덮어쓰지 않습니다.

완전한 블록을 새 문서로 분리

문서 변경을 저장한 뒤 완전한 문단·목록·표·코드 블록을 선택하고 선택 블록을 새 문서로 분리를 누릅니다. 정확한 위치가 필요한 복합 서식은 Markdown 원문에서 선택하세요. 제목을 정하고 분리 영향 확인에서 원본의 선택 내용, 대신 남길 위키 참조, 새 하위 초안을 비교합니다. 원문 최대 1MiB·선택 최대 256KiB이며 Front Matter·HTML 고급 블록·부분 문단·중간 표/목록/코드 구조는 분리하지 않습니다.

명시적으로 확인하면 원본 변경과 새 하위 문서, 문서 이력, 할 일 ID, 검색/이벤트, 재시도 기록을 하나의 트랜잭션에 저장합니다. 어느 단계든 실패하면 둘 다 변경하지 않습니다. 새 문서는 초안이며 원본·공간의 실제 접근 제한을 상속하므로 나만 보기 원본에서 분리했다고 공개되는 것은 아닙니다. 게시 승인·민감정보 정책을 그대로 적용하고, 원본의 Front Matter·태그·별칭과 선택하지 않은 내용은 보존합니다.

확인 티켓은 사용자·원문 버전/범위·새 제목에 묶이며 10분 뒤 만료됩니다. 버전이나 권한이 바뀌면 다시 확인해야 합니다. 연결 오류 뒤 같은 확인 화면에서 재시도하면 같은 요청 ID로 기존 결과를 찾아 중복 생성하지 않습니다. 이전 공동 편집 세대는 새 원문을 덮어쓰지 못하며, 미확정 초안은 기존 복구 절차로 보관합니다.

데이터베이스 셀 편집과 저장된 보기

테이블에서 셀을 선택하고 Enter/F2로 편집합니다. 방향키로 셀을 이동하고 Tab은 저장 후 다음 셀, Esc는 입력 취소입니다. 선택 속성은 등록된 옵션만 고를 수 있습니다. 관계·계산값과 여러 속성을 함께 확인할 때는 행 끝의 항목 상세로 우측 패널을 엽니다. 다른 사용자의 후속 변경과 충돌하면 입력을 보존하고 다시 확인하도록 안내하며, 오래된 버전으로 덮어쓰지 않습니다.

스프레드시트의 사각 범위를 붙여넣으면 최대 100행·500셀을 범위 입력 검토에서 확인합니다. 등록되지 않은 옵션·숫자·날짜 오류는 해당 셀에서 수정할 수 있습니다. 서버 검토와 명시적 동의 후에만 모두 함께 저장하며, 한 셀이라도 오류·버전 충돌·권한 변경이 있으면 전체를 적용하지 않습니다. 현재 표시된 행과 열을 넘어서 행이나 속성을 자동 생성하지 않습니다. 계산·관계 속성은 범위 입력 대상에서 제외합니다.

현재 보기 저장은 필터·정렬·보이는 열·표/보드/달력 등의 화면 구성을 저장합니다. 기본은 본인의 개인 보기이며, 개인 기본 보기로 지정하면 해당 데이터베이스를 다시 열 때 서버에 저장된 구성이 적용됩니다. 팀 보기는 데이터베이스 작성 권한과 명시적인 공유 확인이 필요합니다. 팀 보기를 보는 것과 수정하는 것은 구분되며, 다른 사람이 저장한 보기를 임의로 덮어쓰지 않습니다. 보기 저장 중 서버 구성이 바뀌면 충돌로 멈춥니다. 보기 삭제는 문서나 행을 삭제하지 않습니다.

브라우저 행 변경과 삭제는 항상 expected_version을 보냅니다. 기존 외부 API가 이를 생략하면 최신 행을 대상으로 작동하므로, 충돌 방지가 필요한 연동에서는 조회한 버전을 함께 보내세요. 데이터베이스 행 삭제는 문서 휴지통과 달리 물리 삭제이며 새 항목은 새 ID를 갖습니다. 전체 백업 복원은 별도의 운영 절차입니다.

제품 표시와 오프라인 자산

모바일과 개인 화면 조절

모바일 하단의 홈·찾기·개인 메모는 일상 작업으로 바로 연결합니다. 새 메모는 나만 보기로 생성됩니다. 입력 중이거나 모달·메뉴를 열면 하단 동작을 숨겨 편집기와 확인 버튼을 가리지 않게 합니다. 모바일 사이드바는 닫기 버튼·Escape로 닫고 키보드 초점을 메뉴 안에 유지합니다.

개인화에서 화면 밀도(여유·기본·간결)와 모바일 데이터베이스 기본 보기(카드·표)를 서버에 저장합니다. 밀도는 여백을 조절하며 글자 크기를 줄이지 않습니다. 카드에서도 모든 현재 표시 속성과 항목 상세를 확인할 수 있고, 표가 더 적합하면 즉시 전환합니다. 주요 조작은 제품 기준 44px와 16px 글자를 목표로 합니다. 이는 WCAG 2.2 AA의 24 CSS px 최소 대상 및 예외와 구분합니다.

할 일·DB 날짜의 말로 날짜 찾기에서 내일, 다음주 월요일, 2026년 9월 9일 등을 입력하면 개인 시간대 기준의 확정 날짜를 보여줍니다. 확인한 날짜 입력은 입력란만 바꾸며 바깥 저장을 눌러야 서버에 반영됩니다. 날짜·시간을 확정할 수 없는 표현과 존재하지 않는 날짜는 거절하고 현재 입력 날짜를 덮지 않습니다.

320px·390px의 줄바꿈, 조작 크기, 메뉴 초점, 감소 모션, CSS 200% 확대를 자동 브라우저로 검사했습니다. 이는 모든 보조공학·브라우저 확대·실제 사람의 관찰을 포괄하는 접근성 인증이 아닙니다. 초점 가림 최소 기준과 리플로는 별도 수동 점검에도 사용하세요.

작업 묶음과 참고 선반

전체 도구 → 작업 묶음에서 필요한 문서·DB 보기·할 일을 개인 업무 맥락으로 모읍니다. 작업 묶음은 20개 참조, 문서 전용 참고 선반은 6개 참조, 개인·워크스페이스별 묶음은 40개까지입니다. 문서·DB·할 일 화면의 작업 묶음에 보관을 누르면 현재 문서 위치 또는 DB 필터·정렬·보기 구성을 함께 저장합니다. 홈에는 최근 수정된 개인 묶음을 표시합니다.

보관하는 것은 참조 ID와 제한된 위치·보기 구성이며 원문을 브라우저 저장소에 복제하지 않습니다. 다시 열 때 현재 권한과 원문 버전을 검사합니다. 원문이 바뀌면 오래된 선택·스크롤은 복원하지 않고, 이미 보관한 자료에 접근할 수 없으면 제목 없이 현재 접근 불가로 표시합니다. 본인이 저장하지 않은 숨긴 자료의 개수나 이름은 알 수 없습니다. 묶음의 삭제는 실제 문서·DB·할 일을 삭제하지 않습니다.

참고 선반에서 문서 두 개를 선택하면 현재 권한으로 미리보기를 나란히 엽니다. 비교 중 권한이 철회되면 본문을 제거합니다. 문서의 속성 → 문서 여권은 소유자·현재 버전·내부 공유·게시 상태·등급·등록된 업무 유효기간을 설명합니다. 문서가 정확하다는 인증이나 공개 범위의 보증은 아닙니다.

본문에서 정리 후보 확인은 명시적으로 요청했을 때만 본문 제목·태그 후보를 규칙 기반으로 만듭니다. 외부 AI 전송은 없습니다. 후보를 선택하고 제목·태그·Markdown 변경 전후를 비교한 뒤 확인해야 저장합니다. 현재 버전이 바뀌면 409로 중단하고, 기존 민감정보·게시 승인 정책을 그대로 적용합니다. Front Matter의 태그를 바꾸면 YAML 서식을 다시 직렬화하되 다른 키·주석과 그 뒤 본문은 보존합니다. 자동으로 문서를 이동·공유·게시하지 않습니다.

로그인 화면과 프로필 메뉴에서 서비스 버전을 확인합니다. 로고는 지식이 연결되는 마디를 형상화한 SVG이며 favicon과 설치 아이콘을 함께 제공합니다. React·편집기·그래프·수식·다이어그램·폰트·아이콘을 서비스 이미지에 포함합니다.

프로필 메뉴의 오픈소스 고지는 서비스에 포함된 /licenses.txt를 엽니다. 프로덕션 의존성의 라이선스와 NOTICE 원문을 함께 배포하며 /licenses-manifest.json에 구성과 해시를 기록합니다.

실제 사람을 대상으로 한 사용성 관찰과 자동 UI 시험을 구분합니다. 신규·기존 사용자 동일 과제와 익명 로컬 기록·집계 방법은 사용성 관찰 프로토콜에 정리했습니다. 현재 실제 참여자 관찰은 미실시이며 완료시간이나 완료율 개선을 주장하지 않습니다.
