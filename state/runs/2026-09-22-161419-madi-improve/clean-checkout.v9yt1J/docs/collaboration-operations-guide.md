# 공동 편집 운영 및 복구 가이드

madi는 PostgreSQL에 저장한 Markdown을 정본으로 유지합니다. 공동 편집의 Yjs 상태는 정본과 함께 같은 트랜잭션으로 확정되며, 서버 응답을 받기 전의 변경은 아직 저장 확정이 아닙니다. Go 서버 안에서 처리하며 별도 Node.js 서비스나 새 환경변수는 필요하지 않습니다.

## 저장 상태와 사용자 복구

문서의 공동 편집 표시에서 다음 상태를 구분합니다.

| 표시 | 의미 및 권장 행동 |
| --- | --- |
| 로컬 변경 | 브라우저에 변경이 있으나 서버가 아직 확정하지 않았습니다. 탭을 닫지 마세요. |
| 서버 저장 중 | 변경을 전송했습니다. 확정 응답을 기다립니다. |
| 서버 저장 확정 | 해당 편집에 대한 DB 커밋 응답을 받았습니다. 내용 버전도 표시합니다. |
| 재연결 중 | 같은 탭의 미확정 Yjs 변경을 보관하여 다시 연결합니다. |
| 초안 복구 필요 | 원문 저장·이력 압축·백업 복원으로 편집 기준이 달라졌습니다. 자동 덮어쓰기를 하지 않습니다. |

복구가 필요하면 **현재 초안 다운로드**로 내용을 먼저 보관한 뒤 최신 문서를 다시 여세요. 다운로드한 초안과 최신 원문을 비교하여 필요한 부분을 명시적으로 다시 적용합니다. 다른 편집 기준의 미확정 변경을 서버가 자동 병합하거나 자동 저장하지 않습니다. 로컬 초안 보관은 현재 열린 탭의 메모리이며, 탭 종료·브라우저 충돌까지 보장하는 오프라인 저장소는 아닙니다.

## 증분 로그와 체크포인트

각 문서는 `epoch`(편집 기준), `sequence`(커밋된 CRDT 변경 순서), `snapshot_sequence`를 가집니다. PostgreSQL 문서 행 잠금이 서로 다른 madi 인스턴스의 저장도 직렬화합니다.

1. 변경을 검증하고 현재 세션·문서 ACL·기능 정책·정보 보호 정책을 재검사합니다.
2. CRDT에서 Markdown과 블록 메타데이터를 계산합니다. 본문 변경이면 내용 버전과 불변 문서 스냅샷도 함께 저장합니다.
3. `collaboration_updates`에 증분을 추가하고 `document_collaboration`의 확정 순서를 전진시킵니다.
4. 같은 트랜잭션의 커밋이 성공한 뒤에만 저장 확정 응답을 보냅니다.

첫 초기화, 이후 **64개 변경**, 누적 증분 **1 MiB**, 또는 마지막 체크포인트 후 **60초가 지난 다음 저장**에서 전체 Yjs 체크포인트를 기록합니다. 체크포인트에 포함된 증분만 같은 트랜잭션에서 제거합니다. 유휴 문서에 60초마다 쓰는 타이머는 없습니다. 서버 재시작이나 다른 인스턴스 연결에서는 체크포인트와 연속된 증분을 재생합니다. 순서가 누락된 손상 이력을 발견하면 원문을 변경하지 않고 공동 편집을 차단합니다.

전체 CRDT 상태가 **12 MiB**에 도달하면 현재 변경의 Markdown을 먼저 같은 트랜잭션으로 확정하고 새 편집 기준으로 전환합니다. 커밋된 변경인지 여부를 응답에 명시합니다. 이후 브라우저는 새 정본으로 다시 초기화해야 하며, 다른 오프라인 탭은 초안을 보관해야 합니다.

## 이력과 공간 사용의 차이

`documents.version`은 실제 내용 변경마다 계속 증가합니다. 원문 비교·복원·검토 승인의 버전 안전성은 그대로 유지됩니다. `document_versions`의 개별 불변 Markdown 스냅샷도 삭제하거나 합치지 않습니다.

별도 `collaboration_history_groups`는 같은 작성자의 연속 편집을 화면에서 묶습니다. 변경 간격 30초 이내, 전체 묶음 5분 이내, 같은 편집 기준과 연속 버전일 때만 같은 묶음입니다. 이는 **사용자 이력의 표시 개선**이지 Markdown 버전 저장량 축소가 아닙니다. 이번 증분 저장이 줄이는 부분은 전체 Yjs 상태의 반복 DB 기록입니다. 본문 투영·변경 시 Markdown 스냅샷·일부 전체 상태 응답 비용은 남습니다.

활성 문서의 native CRDT를 최대 8개 캐시하고, 인코딩 크기와 원문 크기의 가중치 합계 64 MiB 안에서만 보관합니다. 이 값은 **프로세스 RSS 상한이 아닙니다**. CRDT 객체·문자열·해시·Go 런타임 할당은 인코딩보다 훨씬 클 수 있습니다. 캐시는 DB 행 잠금 후에만 접근하고 epoch·순서·상태 해시가 일치해야 재사용합니다. 실패·롤백·파서 오류에서는 해당 객체를 폐기하며 마지막 문서 연결이 닫히면 캐시도 해제합니다.

2026-09-08 로컬 Linux/Go 1.26.8의 native 처리 구간 비교에서는 8문서 × 600블록, 총 80개 동일 변경의 재구성·투영 시간이 매번 재생 1,825 ms에서 캐시 748 ms로 줄었습니다. 누적 할당은 607 MB에서 261 MB로 감소했지만, 측정 시점 RSS는 44 MB에서 78 MB로 증가했습니다. 시작 인코딩 합계는 약 1.57 MB였습니다. 이 시험은 최종 본문·메타데이터·CRDT clock 일치를 확인하며 **DB/HTTP/실제 동시 접속 비용을 제외**합니다. 단일 실행의 관측 RSS는 최대 메모리 보증이 아니고 서버 전체 처리량을 뜻하지 않습니다. 재현: `MADI_COLLABORATION_BENCHMARK=1 go test ./internal/server -run '^TestCollaborationNativeCacheMeasurement$' -count=1 -v`.

## 인스턴스 간 전파와 권한 회수

활성 연결이 있는 서버 인스턴스마다 PostgreSQL 전용 `LISTEN` 연결 하나를 사용합니다. 일반 요청용 연결 풀 슬롯을 점유하지 않습니다. `NOTIFY`에는 문서 UUID 또는 전체 권한 재확인 신호만 포함하며 본문·제목·세션·키는 담지 않습니다.

- `LISTEN`을 먼저 확정한 뒤 DB의 최신 순서를 읽어 초기 연결 경합을 피합니다.
- 알림은 깨우기 신호일 뿐이며 실제 내용은 DB의 확정 순서로 다시 읽습니다. 중복·누락 알림에 의존하지 않습니다.
- 같은 편집 기준에서 체크포인트 이후의 순서를 알고 있으면 증분을 전송합니다. 재연결·체크포인트 이전 상태이면 전체 상태로 따라잡습니다.
- 알림 연결 실패 시 재연결하고, 별도 5초 주기의 durable 재조회도 유지합니다.
- 세션 종료, 사용자 비활성화, 멤버/문서 공유/상위 문서·공간 ACL, 기능·보호 정책 변경은 알림으로 재검증을 깨웁니다.
- 별도 권한 감시 루프는 최대 1초 간격으로 재검사를 시작하며, 출력 직전에도 현재 권한을 확인합니다. DB·네트워크·스케줄링 지연까지 포함한 **1초 이내 권한 회수 SLA를 보증하는 수치는 아닙니다**.

PostgreSQL 직접 연결 또는 세션을 유지하는 연결 경로를 사용하세요. 트랜잭션 풀링 프록시에서는 `LISTEN` 세션 유지가 보장되지 않을 수 있으므로 직접/세션 풀 연결에서 검증해야 합니다. 알림 큐와 긴 트랜잭션은 DB 운영 지표로 관리하되 madi가 DB 전역 설정을 임의 변경하지 않습니다. 알림은 커밋 때 전달되고 같은 트랜잭션의 같은 알림은 합쳐질 수 있습니다. [PostgreSQL NOTIFY](https://www.postgresql.org/docs/current/sql-notify.html), [LISTEN 초기 연결 주의사항](https://www.postgresql.org/docs/current/sql-listen.html)을 참고하세요.

## 공동 편집 진단과 수동 압축

문서 우측 패널의 **속성 → 공동 편집 진단**에서 현재 내용 버전, 확정 순서, 체크포인트, 남은 증분 개수·크기, 연결 수, 알림 연결 상태, 편집 활동 묶음을 확인합니다. 본문 읽기 권한이 있어야 조회할 수 있습니다.

문서 소유자 또는 현재 문서 쓰기 권한이 있는 워크스페이스 관리자는 명시적 확인 후 **원문을 보존하고 편집 이력 압축**을 실행할 수 있습니다. 일반 사용자 로그인 세션만 허용하며 API 키/플러그인은 실행할 수 없습니다. 확인했던 버전이나 편집 기준이 바뀌면 409로 거부하고 다시 확인하게 합니다. 관리자의 역할만으로 타인의 비공개 문서를 우회할 수 없습니다.

압축은 CRDT 상태와 증분 이력을 새 기준으로 바꾸며 Markdown, 내용 버전, 개별 문서 버전은 변경하지 않습니다. 다른 탭에 미확정 초안이 있는지 먼저 확인하세요. 손상된 협업 상태에서도 접근 권한이 유효하면 원문을 보존한 수동 압축으로 재시작할 수 있습니다.

| API | 권한 |
| --- | --- |
| `GET /api/v1/documents/{id}/collaboration/diagnostics` | 현재 문서 읽기 |
| `GET /api/v1/documents/{id}/collaboration/history?before=버전` | 현재 문서 읽기, 최대 50개 묶음 |
| `POST /api/v1/documents/{id}/collaboration/compact` | 위 소유자/관리자 조건 + 쿠키 세션 + CSRF + 버전/epoch/명시 확인 |

## 백업·복원·보호 정책

일관된 백업에는 `document_collaboration`, `collaboration_updates`, `collaboration_history_groups`가 포함됩니다. 사용자 presence는 복원할 영속 데이터가 아닙니다. 복원 시 기존 세션을 무효화하고 협업 기준을 새로 발급하며, 복원된 Markdown과 불변 문서 버전을 보존합니다. 과거 브라우저의 변경을 복원된 데이터에 자동으로 재전송하지 않습니다.

정보 보호의 block/mask 정책에서는 보이지 않는 Yjs 삭제 이력까지 안전하게 정제했다고 주장하지 않습니다. CRDT 저장 자체를 차단하고 정제 가능한 Markdown 원문 편집으로 안내합니다. 일반 공동 편집 기능을 끄더라도 원문 편집은 기존 ACL 안에서 사용할 수 있습니다.

검증은 실제 PostgreSQL 격리 스키마와 두 브라우저를 사용합니다. 실행 명령은 다음과 같습니다. 테스트용 DSN은 운영 DB가 아닌 별도 테스트 DB를 지정하세요.

```sh
MADI_TEST_POSTGRES_DSN='테스트 DB DSN' go test -race ./internal/server -run '^TestPostgresCollaboration|^TestCollaboration' -count=1 -timeout 5m
MADI_TEST_POSTGRES_DSN='테스트 DB DSN' MADI_BROWSER_COLLABORATION=1 go test ./internal/server -run '^TestBrowserCollaboration$' -count=1 -timeout 4m
```

## 장시간 입력·실제 프로세스 재시작 회귀

T1 전용 시험은 격리된 DB 스키마와 임시 로컬 서버만 사용합니다. 두 Chromium 컨텍스트가 최소 120초 동안 같은 문서를 편집하며 한 사용자의 한글 조합 중 다른 사용자의 실제 Yjs 변경을 받습니다. 매 라운드에서 저장 확정 표시, 현재 Markdown에 완성 문구가 정확히 한 번 존재하는지, 내용 버전 증가, Front Matter 바이트 보존을 검사합니다.

한글 입력은 Chromium의 `Input.imeSetComposition`과 `Input.insertText`를 통해 조합 시작·갱신·종료 이벤트가 실제로 발생했는지 확인합니다. 이는 단순 `input` 이벤트 위조나 완성 문자열만 넣는 시험과 다르지만, **Windows/macOS/Linux의 운영체제 한국어 입력기·모바일 키보드 전체를 검증한 것은 아닙니다**. [Chrome DevTools Input 프로토콜](https://chromedevtools.github.io/devtools-protocol/tot/Input/)을 사용한 브라우저 엔진 계층의 재현 시험입니다.

저장 후 ACK 하나만 브라우저에서 폐기하고 서버 정본에 반영된 버전을 확인한 다음, 실제 Go 자식 프로세스를 강제 종료하고 **다른 PID로 같은 주소에 재시작**합니다. 재전송 후 본문·내용 버전이 그대로인지 검사합니다. 다음에는 전송되지 않은 로컬 변경을 남긴 채 연결을 끊고 다른 사용자가 명시적으로 epoch를 압축합니다. 이전 초안은 다운로드할 수 있어야 하며 새 정본에 자동 반영되어서는 안 됩니다. 마지막으로 조용한 연결의 계정을 비활성화한 뒤 이후 변경이 전달되지 않는지 확인합니다. 이 자식 서버는 실제 Go HTTP/CRDT/DB 구현을 실행하지만 전체 운영 백그라운드 작업·컨테이너·네트워크 장비의 재시작 시험은 아닙니다.

```sh
# web/dist 빌드 및 tests의 Playwright Chromium 설치가 필요합니다.
MADI_TEST_POSTGRES_DSN='별도 테스트 DB DSN' MADI_BROWSER_COLLABORATION_SOAK=1 \
  go test -race ./internal/server -run '^TestBrowserCollaborationSoak$' -count=1 -timeout=8m -v

MADI_TEST_POSTGRES_DSN='별도 테스트 DB DSN' MADI_COLLABORATION_QUERY_LOAD=1 \
  go test -race ./internal/server -run '^TestPostgresCollaborationConnectionQueryLoad$' -count=1 -timeout=3m -v
```

2026-09-09 첫 실제 입력 시험은 131.266초에 통과했습니다. 그중 편집 120.177초, 한글 조합 시작/종료 각각 111회, 조합 갱신 444회, 두 작성자의 확정 문구 222개를 확인했습니다. ACK 유실 후 실제 프로세스 재시작 복구 1,057ms와 계정 철회 표시 40ms는 해당 1회 표본의 관측값이며 SLA가 아닙니다. 원본 근거는 `test-results/collaboration-soak/browser.json`에 생성됩니다. 실패 진단과 성공 근거는 별도 파일로 보관하며 공개 화면에는 실패 캡처를 쓰지 않습니다.
