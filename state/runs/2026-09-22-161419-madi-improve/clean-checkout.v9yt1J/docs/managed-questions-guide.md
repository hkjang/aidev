# 관리 질문과 공식 답변

`/app/knowledge-questions`는 반복 질문을 **기존 정본 답변 문서, 담당자, 검토 기한, 버전이 지정된 근거**에 연결합니다. 전체 도구에서 열거나 개인 AI 대화의 `이 질문을 공식 답변 초안으로 정리`로 시작합니다. 별도의 답변 사본을 계속 동기화하는 기능이 아닙니다.

## 직접 질문 정리

1. 답변으로 유지할 문서를 먼저 작성합니다. 이 문서의 공유·게시 정책이 그대로 적용됩니다.
2. `새 관리 질문`에서 답변 문서, 질문, 담당자, 다음 검토일, 정리 이유와 근거를 선택합니다.
3. 비교 화면에서 질문·답변의 현재 버전·근거·기본 공유 설정을 확인하고 명시적으로 동의합니다. 실제 접근 범위에는 상위 문서·공간과 모든 근거의 현재 권한도 적용됩니다.
4. 저장 결과는 `정리 중`입니다. 저장만으로 문서가 게시되거나 공식 답변이 되지 않습니다.

답변 문서 하나에 관리 질문 하나를 연결합니다. 같은 답변에 다시 등록하려는 요청은 기존 연결을 덮어쓰지 않습니다. 답변 문서는 평소 문서 편집·변경안·공유 화면에서 수정합니다.

## 개인 AI 질문에서 시작

개인 대화의 단일 메시지를 선택하면 본인의 질문·답변·현재 근거를 먼저 확인합니다. 미리보기만으로는 다른 사람에게 공유되지 않습니다. 전체 대화나 다른 메시지를 자동 복사하지 않습니다.

동의하면 서버가 현재 메시지와 근거를 다시 검사한 뒤 **본인 소유 비공개 답변 초안**을 만듭니다. 정본 문서 생성의 같은 트랜잭션 안에서 원문 버전·현재 세션·권한·정보 보호 정책과 생성 영수증을 확인합니다. 재시도는 같은 미변경 초안을 사용하며, 동시 요청 충돌은 다시 요청하여 기존 초안을 확인합니다.

초안 생성과 관리 질문 등록은 두 단계입니다. 등록이 실패해도 이미 만든 비공개 초안을 삭제하지 않으며 화면에서 링크를 제공합니다. 초안이 변경·공유·삭제됐다면 이전 내용으로 덮어쓰지 않고 기존 문서에서 확인하도록 안내합니다. 출처 메시지 ID와 원래 대화 ID는 조직의 질문 응답에 노출하지 않습니다.

팀 공유, 문서 게시, 공식 답변 확인은 이후 각각 수행합니다. 이미 명시적으로 복사·전달한 내용을 권한 변경으로 회수할 수 있다고 보장하지 않습니다. 이후 질문·근거 조회와 새 복사는 현재 권한을 다시 검사합니다.

## 공식 답변 표시의 조건

| 조건 | 의미 |
| --- | --- |
| 담당자 확인 | 현재 지정 담당자가 근거와 답변을 확인한 기록을 명시적으로 남겼습니다. |
| 답변·근거 최신성 | 등록한 버전과 SHA-256이 현재 정본과 일치합니다. 첨부 조각은 추출·파일 해시·위치까지 검사합니다. |
| 담당자 권한 | 담당자가 활성 구성원이며 답변 수정과 모든 근거 조회가 가능합니다. |
| 검토 기한 | 지정한 **UTC 날짜 당일까지** 유효하며 다음 날에는 기한 경과로 표시합니다. |
| 현재 게시 조건 | 답변 문서가 게시 상태이며, 승인 설정이 있으면 현재 정책으로 승인된 정확한 게시 버전입니다. |

모두 충족돼야 `공식 답변 · 현재 조건 충족`을 표시합니다. 해시 일치나 사람의 확인만으로 내용의 사실성을 자동 인증하지 않습니다. 근거 자료가 모두 승인·게시된 자료라는 뜻도 아닙니다.

관리자 승인 설정이 없으면 검토 요청·승인·반려 프로세스를 새로 만들지 않습니다. 담당자의 개인 확인 기록과 조직의 게시 승인 절차를 구분합니다. 승인 설정이 있으면 기존 **답변 문서의 게시 승인**을 먼저 완료해야 하며 질문 확인 버튼이 승인을 대신하지 않습니다.

## 변경·담당자 이동·복구

- 답변이나 근거가 변경되면 과거 확인 이력은 남지만 현재 공식 표시는 해제됩니다. 최신 버전으로 다시 정리하고 담당자가 확인합니다.
- 담당자·검토일·질문·근거를 정리하면 새 revision이 생성되고 이전 공식 확인은 해제됩니다. 다른 탭의 변경은 409로 보호합니다.
- 담당자가 비활성화되거나 이동했으면 **답변 문서의 현재 소유자**가 접근 가능한 자료 안에서 담당자를 재지정할 수 있습니다. 서비스 관리자라는 이유만으로 비공개 답변을 열거나 다른 담당자의 확인을 대신할 수 없습니다.
- `질문 보관`은 질문 상태만 바꾸며 정본 답변 문서를 삭제하지 않습니다. 문서의 휴지통·복원 정책은 별도로 사용합니다.
- 원본 근거가 휴지통으로 이동하거나 접근 권한이 철회되면 질문도 숨깁니다. 원본 문서나 참조 첨부가 영구 삭제되면 연결된 질문 사본·확인 이력도 제거합니다.
- 백업에 질문, 암호화된 이력, 초안 영수증이 포함됩니다. 복원 시 공식 확인을 `정리 중`으로 돌려 현재 정책과 근거를 다시 확인하도록 합니다.

## API·MCP와 한도

REST 목록/상세는 `/api/v1/knowledge/questions`, `/api/v1/knowledge/questions/{id}`입니다. 작성·정리·확인은 사람의 로그인 세션에서만 가능합니다. 개인 AI 질문 미리보기와 비공개 초안 생성도 본인의 브라우저 세션만 허용합니다.

범위 지정 API 키의 `document:read`로 MCP `list_managed_questions`, `get_managed_question`을 사용할 수 있습니다. 키의 워크스페이스, 현재 사용자와 모든 근거의 ACL을 동일하게 검사합니다. 읽기 도구는 게시·실행·담당자 확인 권한을 주지 않습니다. 실제 요청 필드는 서비스 OpenAPI를 확인하세요.

질문은 UTF-8 2,000바이트, 정리·확인 이유는 4,000바이트, 근거는 1~32개입니다. 답변과 근거의 정본 JSON 검사는 합계 8MiB까지이며 SQL statement는 8초·잠금 대기는 3초로 제한합니다. 목록은 UUID 커서로 최대 20개씩 제공합니다. 정본 답변 내용은 기존 통합 문서 검색에서 찾습니다. 개인 대화 전체를 검색하거나 조직 질문 빈도를 자동 수집하지는 않습니다.

## 검증 기록

차기 릴리즈 후보의 PostgreSQL race 15.480초: 현재 게시 승인·담당자 확인 분리, 담당자 비활성화와 문서 소유자의 재지정, MCP 읽기, 검토 기한·PII, 개인 복사 명시 동의와 원자 영수증 실패 롤백, 백업 목록을 검사했습니다.

개인 미리보기→비공개 초안→관리 질문→게시 후 재정리→담당자 확인→근거 변경·삭제, 새로고침·셀렉트·390px의 실제 브라우저 시험은 `main--4zCM3el`에서 키보드 포커스 복귀까지 포함하여 15.077초로 통과했습니다. 첫 실패는 같은 제목의 사이드바 문서를 누른 시험 선택자 문제였으며 목록 카드와 도착 화면을 명시한 뒤 검증했습니다. 최종 이미지·전체 회귀는 별도 확인합니다. 실제 사람 사용성 관찰이나 성능 SLA가 아닙니다.
