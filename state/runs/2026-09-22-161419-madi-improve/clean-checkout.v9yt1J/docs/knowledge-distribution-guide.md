# 망별 지식 배포 가이드

madi의 망별 지식 배포는 등록한 공개키로 발행 주체를 확인하고, 원본 파일의 SHA-256과 Ed25519 서명을 검증하는 기능입니다. 인터넷 연결이나 중앙 공개키 서버가 필요하지 않습니다. 서비스 Docker 이미지의 릴리즈 파일과는 별개인 **지식 데이터 ZIP**입니다.

서명은 내용의 사실성, 악성 파일의 안전성, 수신망의 게시 승인을 인증하지 않습니다. 이미 전달한 사본은 이후 키·권한 철회로 회수할 수 없습니다.

## 관리자 준비

1. `/admin/knowledge-distribution`에서 서명 반출·반입을 명시적으로 활성화합니다. 기본값은 비활성입니다.
2. 반출망에서는 `반출 서명키`를 생성합니다. 개인키는 서버에서 생성하여 `ENCRYPTION_KEY`로 암호화하고 API나 화면에 노출하지 않습니다.
3. 수신망에는 반출망 식별자·키 ID·공개키를 등록합니다. 공개키 전체 SHA-256 지문은 파일에 들어 있는 설명만 신뢰하지 말고 별도 신뢰할 수 있는 전달 경로로 확인합니다.
4. 서로 다른 설치의 망 식별자를 확인합니다. 수신망 식별자가 다른 묶음은 반입할 수 없습니다. 같은 DB를 복제한 환경은 새로운 신뢰 도메인으로 자동 간주되지 않습니다.
5. 서비스의 검토·승인 기능이 켜져 있으면 해당 워크스페이스에 **망간 지식 배포** 종류의 명시적 승인 정책을 만듭니다. 문서 게시 승인 정책과 구분합니다. 별도 배포 정책이 없으면 승인을 우회하지 않습니다.

키 변경·철회와 정책 변경은 현재 revision을 확인한 후 적용합니다. 공개키를 자동으로 덮어쓰거나 새 키를 자동 신뢰하지 않습니다. 이력을 포함한 키 수는 100개까지입니다.

## 반출 흐름

`/app/knowledge-distribution`에서 현재 접근 가능한 게시 문서를 선택하고 수신망 ID·서명키·유효기간·정확한 문서 버전을 확인합니다. 선택 문서의 첨부 전체가 포함됩니다.

- 승인 기능이 꺼져 있으면 검토 요청·승인·반려 절차를 추가하지 않습니다. 게시된 정확한 원문·첨부·현재 권한·정보 보호 정책을 검사하여 서명합니다.
- 승인 기능이 켜져 있으면 먼저 현재 정책으로 승인된 정확한 게시 버전인지 확인합니다. 이후 **문서와 첨부 전체의 해시·수신망·키·유효기간**을 고정한 미서명 배포 자료를 준비합니다.
- 신청자는 `배포 전체 검토 열기`에서 목록을 확인하고 검토를 제출합니다. 검토자는 현재 모든 원문에 접근할 수 있어야 하며 신청자·소유자의 자기 승인은 불가능합니다.
- 모든 승인 단계가 완료돼도 파일을 자동 서명하거나 전송하지 않습니다. 원신청자가 원래 로그인 세션에서 `승인 확인 후 서명 준비`를 실행합니다.
- 서명 준비 및 내려받기에서도 원문 버전·첨부 목록과 해시·승인·정책·키·세션을 다시 검사합니다. 문서 본문이 같아도 첨부가 추가되면 이전 묶음을 내려받을 수 없습니다.

검토 snapshot에는 파일 본문이나 제목을 중복 저장하지 않고, 암호화된 전체 매니페스트의 해시와 전달 조건을 연결합니다. 실제 목록과 원본 확인 링크는 현재 권한과 민감정보 정책을 적용하는 검토 화면에서 제공합니다. 원문·정책·기한이 달라지면 새 배포를 준비하세요.

## 수신망의 비공개 반입

1. `서명 반입`에서 ZIP을 선택합니다. 브라우저는 파일 목록·압축 한도·파일 해시만 먼저 검사하며, 이 단계는 서버의 신뢰 키 검증 완료가 아닙니다.
2. 원본과 수신망을 확인하고 `신뢰 확인·비공개 업로드`를 실행합니다. 서버가 현재 신뢰 공개키·서명·수신망·유효기간을 검사한 뒤 빈 이관 세션에 원본을 결합합니다.
3. 파일은 1MiB 청크로 전송합니다. 중단되면 같은 URL의 세션을 열고 같은 원본 ZIP을 다시 선택하여 확인된 청크 다음부터 준비할 수 있습니다. 다른 원본을 같은 세션에 바인딩할 수 없습니다.
4. 이관 센터에서 준비·원문 비교·변환 경고·명시적인 건너뛰기를 검토합니다. 부분 준비된 문서는 일반 사용자에게 공개하지 않습니다.
5. `IMPORT`로 확정하면 모든 서명 파일·메타데이터·신뢰 키·기간·권한을 다시 검사하고, 문서·첨부 및 버전 대응 기록을 한 트랜잭션으로 반영합니다. 실패하면 부분 문서와 성공 영수증이 남지 않습니다.

반입 문서는 새 ID의 **비공개 초안**으로 시작합니다. 반출망의 승인·외부 공유 권한·사용자 계정·API 키를 수신망에 복사하지 않습니다. 수신망에서 공유하거나 게시하려면 해당 망의 현재 정책과 승인 절차를 따릅니다.

반입 이력은 원본 시스템 ID·버전·해시와 수신망 대상 ID·버전을 연결합니다. 링크 재작성, 민감정보 처리 등으로 변환된 수신망 정본에 원본 파일의 서명이 그대로 유효하다는 뜻은 아닙니다. 이력의 대상 해시는 동시성 비교용 값일 수 있으며 서명 검증용 SHA-256과 혼동하지 마세요.

같은 원본 첨부를 여러 문서가 참조하면 문서마다 만들어진 첨부 사본을 별도 대응 행으로 기록합니다. `reference_copy`에는 대상 문서·첨부 ID와 내용 SHA-256을 함께 보관하며 현재 접근할 수 없는 사본은 이력에서도 숨깁니다. 이 기록은 원본 첨부의 서명을 변환된 문서 전체로 확대하는 것이 아닙니다.

## 한도와 보관

| 구분 | 한도 또는 동작 |
| --- | --- |
| 원본 | 문서·첨부 합계 1,000개, 해제된 원본 합계 50MiB |
| 문서 | 개별 원문 4MiB 이하 |
| 첨부 대응 | 문서별 첨부 사본 최대100,000개; 이관의 저장량·객체 수 검사도 별도 적용 |
| 매니페스트 | 2MiB 이하, 명확한 경로·중복 없는 ID·순환 없는 부모 참조 |
| ZIP | 실제 해제 바이트를 검사하며 경로 탈출·중복 경로·심볼릭 링크를 거부 |
| 개인 준비 | 대기·검토 대기 합계 5개, 준비 결과 합계 200MiB |
| 배포 유효기간 | 관리자 허용 범위 안에서 1~365일, 기본 최대 7일 |
| 서버 임시 결과 | 원본 내보내기의 유효기간 안에서만 내려받기 가능, 최대 24시간 |
| 현재 권한 | 새 요청마다 검사하고 내려받기 중에도 약 1초 간격으로 재검사. 이미 전송한 바이트는 회수 불가 |

원래 세션이 만료되거나 로그아웃한 경우 새 로그인에서 과거 반출 권한을 자동 승계하지 않습니다. 새로 준비하세요. 만료·폐기·실패한 서버 임시 결과는 정리하지만 이력은 유지합니다.

## 백업·복원과 키 회전

논리 백업과 PostgreSQL 전체 백업에는 정책·키·반입·반출·승인 이력이 포함됩니다. 서비스 임시 ZIP은 재생성 가능한 자료이므로 논리 백업에서 제외합니다. `ENCRYPTION_KEY`는 DB와 별도로 안전하게 보관해야 하며 분실하면 암호화된 개인키와 자료를 복구할 수 없습니다.

복원은 배포 정책을 끄고 모든 서명·신뢰 키를 철회하며 진행·준비 결과를 만료시킵니다. 승인 기록의 복원도 새로운 반출 권한을 만들지 않습니다. 운영자가 복원 상태를 확인한 후 새 서명키를 생성하고, 수신망에서 새 지문을 명시적으로 등록하세요. 철회된 신뢰 공개키의 재신뢰도 전체 지문 재확인과 현재 revision이 필요합니다. 서명 개인키의 재활성화는 지원하지 않습니다.

## API와 검증 범위

운영·키 API는 `/api/v1/admin/knowledge-distribution`, 사용자 배포는 `/api/v1/knowledge/distribution/exports`, 서명 반입 결합은 `/api/v1/migrations/sessions/{id}/signed-source`입니다. 배포 전체 검토·제출·서명은 각각 `/exports/{id}/review`, `/approval`, `/sign`으로 구분합니다. 이 기능은 실제 사용자 쿠키 세션의 명시 확인을 요구하며 API 키나 MCP를 사용한 무인 승인·반출은 허용하지 않습니다. 에이전트용 입력 묶음은 별도의 [AI 근거·지식 패키지 기능](evidence-guide.md)을 사용합니다.

현재 구현의 서명 대상은 `madi-distribution-v1`의 정확한 JSON 바이트입니다. 임의 JSON 정규화나 RFC 8785와 호환된다고 주장하지 않습니다. 알 수 없는 키·중복 키·다른 숫자 표현·공백 변경도 서버의 정규 표현과 일치하지 않으면 거부합니다.

개발 중 검증: 실제 PostgreSQL에서 독립 검토자·전체 배포 승인·명시 서명·승인 후 첨부 변경 차단을 검사했습니다. `main-C6aNRXQA`의 두 설치·3사용자 실제 브라우저 시험 43.256초는 전체 배포 동의·독립 승인·원신청자의 명시 서명, 실제 Ed25519 검증, 변조 ZIP의 업로드 전 거부, 비공개 반입과 원자 대응 기록·390px를 포함해 통과했습니다. 최종 이미지·전체 회귀는 차기 릴리즈 검증 기록으로 별도 관리합니다. 운영 규모 성능이나 모든 파일 형식의 안전성 보증이 아닙니다.
