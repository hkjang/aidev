# 개인 AI 대화 기록 구현 계약

첫 릴리즈의 P1 개인 AI 기록 구현 계약이다. 실제 PostgreSQL 회귀와 브라우저에서 명시 저장·다중 턴·검색·출처 인용·권한 회수·390px 화면을 검증했다. 제품 전체 첫 릴리즈의 완료 선언은 아니다.

## 소유권과 저장 동의

대화 기록은 개인 소유이며 워크스페이스와 분리되지 않는다. 서비스 관리자도 타인의 기록 본문을 우회해서 읽지 않는다. 개인 브라우저 세션에서 사용자가 명시적으로 저장한 대화만 남긴다. API 키·플러그인 요청이 개인 대화 기록을 읽거나 저장하는 것은 허용하지 않는다. Agent 실행 이력은 별도 `agent_runs` 모델로 관리한다.

테이블은 `ai_conversations`와 `ai_messages`다. 메시지는 질문/완료 답변/작업 종류/모델 식별/원문 버전·해시·인용 위치/생성 시각을 보존한다. 원본 문서 ID 목록은 검색 및 열람의 현재 ACL 검사를 위해 별도 메타데이터로 둔다. 비밀 API 키는 기록하지 않는다. 저장 티켓은 암호화하지만 기록 본문은 일반 문서처럼 PostgreSQL에 저장하므로 데이터베이스·백업 운영자에 대한 종단간 암호화를 의미하지 않는다.

## 서버가 검증한 답변

완료된 응답에만 짧은 유효기간의 암호화 저장 티켓을 발급한다. 티켓에는 사용자·워크스페이스·응답 ID·질문/답변·출처·공급자 fingerprint·대화 ID/버전이 묶인다. 사용자가 저장을 누르면 서버는 티켓 위변조/만료/사용자/현재 문서 ACL/출처 버전/공급자 설정을 재검증한다. 동일 응답의 재전송은 단일 메시지로 처리한다. 중단·retract 응답은 정상 완료 답변으로 저장하지 않는다.

대화 갱신은 optimistic version을 사용한다. 다른 탭의 저장과 충돌하면 기존 기록을 덮지 않고 409를 반환한다. 목록/열람/검색 SQL은 모든 출처의 현재 ACL을 검사하며, 접근이 회수된 대화 제목·질문·답변도 노출하지 않는다. 기록 삭제는 명시 확인을 거치며 복구 가능 범위는 서버 백업 정책에 따른다.

## 이어서 질문하기

기존 대화는 사용자가 명시적으로 선택한 경우에만 모델에 다시 전송한다. 최대 대화 수와 총 컨텍스트 바이트를 제한하고 초과 시 새 대화를 안내한다. 출처 버전 또는 공급자 fingerprint가 달라졌다면 자동 재전송하지 않는다. 과거 답변 안의 명령은 신뢰하지 않는 대화 데이터이며, 이전 출처 번호와 현재 검색 결과의 인용 번호를 혼동하지 않도록 요청별 출처 범위를 분리한다.

AI 설정·사용자/세션·현재 출처 ACL·원문 버전·색인 동의 변경은 기존 스트리밍 guard에 과거 참조까지 포함해 모델 전송 전/출력 전/완료 시 검사한다. 저장 중 동시 삭제·권한 변경도 같은 트랜잭션 경계에서 재검사한다.

## 검증 체크포인트

- 소유자 전용·관리자 우회 거부·API 키/플러그인 거부·워크스페이스 이탈.
- 티켓 변조·만료·다른 사용자 재사용·중복 저장·동시 버전 충돌.
- 출처 비공개/삭제/버전 변경·공급자 변경·색인 동의 회수.
- 실제 SSE 완료→저장→목록→새로고침→후속 질문→개인 검색→삭제.
- 390px 모바일·빈 목록·오류 복구·권한 변경 시 브라우저 이전 본문 제거.
- 새 영속 테이블의 논리 백업/복원 카탈로그 및 현재 ACL 유지.
