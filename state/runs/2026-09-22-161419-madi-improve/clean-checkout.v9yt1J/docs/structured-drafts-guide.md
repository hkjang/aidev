# 문서에서 데이터 정리

문서의 선택 구간을 지정한 데이터베이스 속성으로 정리하는 기능입니다. AI는 **한 행의 초안**만 제안합니다. 원문을 수정하거나 값을 자동으로 저장·게시하지 않습니다.

## 사용 흐름

1. 같은 워크스페이스의 원문과 작성 가능한 데이터베이스를 선택합니다.
2. AI에 보낼 원문 구간과 일반 입력 속성을 선택하고, 실제 공급자 주소·모델을 확인합니다.
3. 명시적으로 동의하면 스트리밍으로 생성을 시작합니다. 생성 중에는 내용 없는 진행 상태를 표시하며, 응답 형식과 민감정보 정책 검사를 마친 제안만 보여줍니다. 중단·권한 변경·오류가 난 결과는 완료된 제안으로 취급하지 않습니다.
4. 완료된 제안을 별도로 동의해 개인 검토함에 보관합니다. 아직 데이터 행은 없습니다.
5. 값별 원문 인용·타입 오류를 확인합니다. 잘못된 값이나 인용은 수정하고, 반영하지 않을 속성은 제외합니다.
6. 최종 미리보기에서 값을 다시 확인하고, 대상 데이터베이스에 공유되는 새 행 생성에 동의합니다.

원문에 일치하는 인용을 찾았다는 사실과 값의 의미·정확성이 검증됐다는 판단은 다릅니다. 숫자 `2`와 원문 `2개`의 연결은 사람이 판단합니다. 타입 검사는 날짜·숫자·선택 옵션 형식을 검사할 뿐 의미를 보증하지 않습니다.

## 화면에서 선택하고 수정하기

전체 도구의 **문서에서 데이터 정리**에서 시작합니다. 원문을 드래그한 뒤 **선택 구간 사용**을 누르거나, **키보드로 줄 범위 지정**을 열어 시작 줄·끝 줄을 입력합니다. 첫 줄은1이며 빈 줄도 셉니다. 선택 미리보기에서 실제 전송 문구와 UTF-8 바이트 수를 확인하세요. CRLF 줄바꿈과 한글·이모지의 원문 위치를 보존하며, 잘못된 줄 범위를 적용하면 기존 선택·전송 동의를 지웁니다.

**구조화 제안 생성**, **개인 검토함에 보관**, **확인한 값으로 새 행 생성**은 각각 별도 동의 단계입니다. 생성한 제안을 보관하지 않으면 데이터 행도 개인 검토 기록도 만들지 않습니다.

검토 화면의 선택·상태 속성은 일반 선택 상자, 다중 선택은 체크 상자를 사용합니다. 등록되지 않은 값은 ‘미등록 값’으로 남기며 기본 옵션으로 몰래 바꾸지 않습니다. 숫자와 근거 인용을 수정하고, 반영하지 않을 항목은 체크를 해제하세요. 날짜는 실제 달력에 존재하는 `YYYY-MM-DD` 형식입니다. 인용 위치를 비우면 선택 구간 안의 유일한 일치 위치를 찾고, 같은 문구가 여러 번 나오면 상대 UTF-8 바이트 위치를 지정해야 합니다.

검토 중 직접 수정한 값은 **최종 행 생성 전까지 이 화면에만 있습니다**. 오류가 나도 입력을 유지하지만 화면을 떠나면 수정분은 사라지고, 이미 보관한 최초 AI 제안만 남습니다. 미리보기가 열린 동안 속성·공유 대상·원문이 바뀌면 미리보기와 동의를 폐기합니다. 현재 원문이나 DB 접근 권한을 잃으면 표시하던 값과 인용도 제거합니다.

## 원문·AI 전송·공유 경계

AI에 전달하는 것은 선택한 원문과 선택한 속성의 ID·이름·타입·옵션입니다. 다른 원문 구간, 문서 제목·태그, 데이터베이스 이름·기존 행·선택하지 않은 속성, 대화 이력, 검색 결과, 실행 도구는 전송하지 않습니다. 속성 이름과 원문 안의 명령도 신뢰하지 않는 자료로 취급합니다.

텍스트·숫자·체크·선택·상태·다중 선택·날짜·URL·이메일·전화·진행률 속성을 지원합니다. 수식·자동 AI·관계·사용자·실행 버튼 속성은 이 흐름에서 제외합니다. 속성 이름의 자동 추측이나 일괄 행 생성은 하지 않습니다.

개인 검토함은 본인만 조회합니다. 조회 시에도 원문과 대상 데이터베이스의 현재 권한, 현재 민감정보 정책을 검사합니다. 서비스 관리자 권한만으로 다른 사람의 비공개 원문을 우회하지 않습니다. 사용자에게 DB 작성 권한이 없어지면 새 제안을 생성하거나 값을 반영할 수 없습니다.

**새 행은 대상 데이터베이스의 현재 열람자에게 보입니다.** 비공개 원문의 권한이 복사된 값에 상속되는 것은 아닙니다. 원문 권한을 철회해도 이미 공유한 행을 회수할 수 있다고 표현하지 않습니다. 반영 후 기존 데이터베이스 자동화가 설정돼 있으면 일반 행 생성과 같은 이벤트를 처리합니다. 별도 실행 권한이나 승인 권한을 부여하지 않습니다.

원문 버전·본문 해시·대상 속성·공유 정책이 바뀌면 이전 미리보기로 반영하지 않습니다. 현재 조건에서 새 제안을 만들고 다시 확인해야 합니다. 생성 중 공급자·세션·권한 변경은 조용한 스트림에서도 주기적으로 검사해 취소합니다. 정보보호 설정 잠금을 기다린 뒤에도 현재 세션·원문·대상·공급자를 다시 검사합니다. 공급자 API는 SSE 스트리밍을 사용하지만, 분할 수신 중인 원시 JSON은 브라우저로 보내지 않습니다. 생성 결과 자체도 현재 민감정보 정책으로 검사하며, 차단·마스킹 대상 결과를 검증된 제안으로 보관하거나 반영할 수 없습니다.

## 보관·복원과 한도

| 항목 | 적용 범위 |
| --- | --- |
| 원문 선택 | UTF-8 최대32KiB, 원문 문서 최대1MiB |
| 속성 | 일반 입력 속성1~32개, 한 번에 한 행 |
| AI | 기본 스트리밍, 관리자 설정 `max_tokens` 최대262144; 실제 제안 응답64KiB 한도 |
| 인용 | 선택 원문 안의 연속 구간1~4096바이트. 같은 인용이 여러 번 나오면 정확한 상대 바이트 위치 필요 |
| 속성 값 | JSON8KiB 이하, 검토 필드 전체256KiB 이하 |
| 생성 확인 | 완료된 제안의 암호화 확인30분; 자동 개인 보관 없음 |
| 미반영 개인 초안 | 24시간, 사용자별 유효 초안100개 |
| 최종 행 생성 확인 | 원문·속성·공유·개정·검토 값에 결합된10분 확인 |
| 목록 | 본인 자료20건씩 `next_after` 조회 |
| DB 처리 | 외부 AI 호출과 분리된 짧은 트랜잭션, 잠금3초·SQL8초 제한 |

검토 전 초안은 만료 후 표시하지 않습니다. 시간별 정리 작업은 법적 보존·보존기간 대상이 아닌 만료 초안을 최대500개씩 정리합니다. 반영한 근거는 원문·DB 권한과 보존 정책 아래 별도로 유지하며, 사용자가 동의한 근거 삭제는 이미 만든 데이터 행을 삭제하지 않습니다. 삭제 후에는 과거 생성 확인을 재사용해 같은 제안을 되살리지 못하도록 내용 없는 폐기 기록을 한 시간 유지합니다.

원문 또는 대상 데이터베이스를 물리 삭제하면 연결된 근거 사본은 삭제됩니다. 원문을 휴지통으로 옮기거나 접근을 철회하면 조회가 차단됩니다. 논리/네이티브 복원은 미반영 초안을 만료 처리합니다. 이미 반영한 행과 암호화 근거 이력은 보존하되 현재 권한·원문·속성을 다시 확인합니다. 복원 직후 자동 AI 호출이나 자동 행 생성은 없습니다.

## API와 MCP

실제 스키마는 `/api/v1/openapi.json`에서 확인합니다.

- `GET /api/v1/documents/{id}/structured-context?database_id=...`: 현재 원문·허용 속성·공급자·공유 확인 값
- `POST /api/v1/documents/{id}/structured-draft`: 선택 구간/속성의 스트리밍 제안
- `POST /api/v1/knowledge/structured-drafts`: 완료한 제안을 본인 검토함에 보관
- `GET /api/v1/knowledge/structured-drafts?workspace_id=...`: 본인 목록
- `GET /api/v1/knowledge/structured-drafts/{id}`: 현재 권한으로 제안·인용·반영 이력 조회
- `POST /api/v1/knowledge/structured-drafts/{id}/preview`: 수정한 값·인용·타입의 최종 확인
- `POST /api/v1/knowledge/structured-drafts/{id}/apply`: 공유 동의 후 일반 데이터 행 생성 명령으로 원자 반영
- `DELETE /api/v1/knowledge/structured-drafts/{id}`: 현재 개정과 명시 동의로 근거 사본 삭제

키와 MCP의 `get_structured_draft`, `list_structured_drafts`는 `document:read`와 `database:read`의 교집합 및 현재 원문·DB 권한으로 본인 자료만 읽습니다. 생성·보관·값 검토·반영·삭제는 사람의 로그인 화면에서만 수행합니다. 값별 `start_byte`는 응답에서는 문서 전체의 절대 UTF-8 위치이며, 미리보기 입력에서는 원래 선택 구간의 상대 UTF-8 위치입니다.

행과 반영 근거는 같은 트랜잭션에서 저장합니다. 기존 일반 행 생성의 타입 검사·자동화 이벤트·감사 흐름을 사용합니다. 저장 중 실패하면 양쪽 모두 취소합니다. 같은 확인의 재시도는 변경되지 않은 기존 행을 반환하거나 충돌로 안내하며, 다른 사용자의 후속 변경을 덮어쓰지 않습니다.

## 검증 상태

현재 로컬 PostgreSQL 기반 첫 실제 SSE·선택 정보 격리·타입 오류·명시 동의·저장 실패 전체 롤백·재시도 검증을 통과했습니다. 후속 Go race 교차40.575초는 원문/속성/공유 조건 변화, 현재 민감정보 정책, 초안 만료, read-only MCP·키 권한 회수, 동시 반영, 기존 일반 행 편집·백업 목록 검사를 포함합니다. 조용한 스트림의 원문·속성·작성 역할·공급자·세션 변경 회수31.609초, 실제 HTTP가 DB 잠금에 도달한 뒤 세션이 만료되는 보관/미리보기/반영403·롤백9.785초도 통과했습니다. 관련 E6 배포·E9 관리 질문·일반 데이터 행·백업을 포함한 통합 backend102.441초는 이 시험들을 함께 실행한 결과입니다.

이전 후보 번들 `main-BfuFzQ6M.js`의 Chromium 실제 화면과 PostgreSQL·모의 공급자 SSE를 연결한 Go race 시험은24.413초에 통과했습니다. 마우스/키보드 줄 선택, CRLF 원문 무변경, 미등록 선택 값·다중 선택 오류 보존과 명시 수정, 전송/개인 보관/공유의 별도 동의, 실제 행1개 생성, 새로고침과390px·16px 표시, 미리보기 중 속성 변경과 현재 원문 권한 회수, 근거 삭제 후 행 유지까지 확인했습니다. 브라우저 JavaScript 오류와 외부 자산 요청은0건이었습니다.

이후 교차 검토에서 발견한 검증 전 원시 응답 노출과 정책 잠금 대기 후 재검사 누락을 수정했습니다. 분할 생성한 민감정보의 차단·마스킹 2조건과 실제 정책 잠금 대기 중 세션 만료·상위 문서 권한·대상 멤버십·공급자 변경 8조건은 수정 전 실패를 재현한 뒤 통과했습니다. 후보 `main-BFRbO7Kl.js`의 실제 구조화 화면 재검사는17.32초에 통과했고, 조용한 스트림 회수·편집기·색인 동의까지 함께 검사한4개 Go race 시험은72.623초에 통과했습니다. 이는 자동화 시험이며 실제 외부 유료 모델 호출·사람 관찰·운영 규모 성능 보증 결과는 아닙니다. 최종 전체 릴리즈 검증은 별도입니다.
