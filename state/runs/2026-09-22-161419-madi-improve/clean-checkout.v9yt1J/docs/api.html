내 권한 안에서, 필요한 범위만.

REST 기본 경로는 /api/v1입니다. 외부 클라이언트는 개인 또는 서비스 계정 키를 Authorization: Bearer <TOKEN>에 넣습니다. 변경 요청에는 X-Madi-Request: 1 헤더를 함께 보냅니다. JSON 필드명은 snake_case입니다. 실행 중인 서비스의 /api/v1/openapi.json에서 기계가 읽을 수 있는 API 목록을 조회할 수 있습니다.

키 범위 용도
document:read 문서와 백링크 조회
document:write 문서 작성·수정·삭제
database:read 데이터베이스·행 조회
database:write 데이터베이스·행 변경
search:read 검색·그래프
ai:execute AI 요청

키의 워크스페이스와 범위, 사용자 문서 ACL, 만료·IP·호출 제한을 함께 적용합니다. 키를 발급했다고 관리자 설정에 접근하거나 자신의 권한을 늘릴 수는 없습니다. 발급·회전된 키의 비밀은 한 번만 반환되며 회전 즉시 이전 비밀은 폐기됩니다.

문서와 데이터를 REST로 다루세요.

메서드 경로 역할
GET, POST /documents 목록·작성
GET, PUT, DELETE /documents/{id} 조회·수정·휴지통
GET /documents/{id}/backlinks 백링크
GET /documents/{id}/versions 버전 목록
GET /graph?workspace_id={id} 연결 그래프
GET, POST /databases 데이터베이스 목록·생성
GET, POST /databases/{id}/rows 행 목록·추가
POST /ai/chat SSE 스트리밍 
curl --fail-with-body \
  'https://madi.example.internal/api/v1/documents' \
  -H "Authorization: Bearer $MADI_API_TOKEN" \
  -H 'Content-Type: application/json' \
  -H 'X-Madi-Request: 1' \
  --data '{
    "workspace_id": "WORKSPACE_UUID",
    "title": "운영 점검",
    "markdown": "# 운영 점검\n\n- [ ] 상태 확인"
  }'

문서 수정에는 읽을 때 받은 version을 함께 보내세요. 다른 사용자가 먼저 저장했다면 409가 반환됩니다. 목록에는 workspace_id, q, tag 등의 쿼리를 사용할 수 있습니다.

예시의 MADI_API_TOKEN은 호출하는 클라이언트에서 비밀을 주입하는 변수입니다. madi 서비스에 다섯 번째 실행 환경변수를 추가하는 것이 아닙니다.

AI 응답은 생성되는 순서대로.

POST /api/v1/ai/chat에 prompt와 선택적인 document_id, workspace_id를 전송합니다. 응답은 text/event-stream입니다. 

data: {"sources":[{"id":"DOCUMENT_UUID","title":"운영 점검"}]}

data: {"text":"문서의 핵심은 "}

data: {"text":"다음과 같습니다."}

data: [DONE]

오류는 {"error":"메시지"} 이벤트로 전달될 수 있습니다. 청크 경계와 SSE 이벤트 경계는 같지 않으므로 버퍼를 유지하는 파서를 사용하세요. 취소 시 연결을 종료하고, 프록시의 응답 버퍼링을 끕니다.

retract: true 이벤트를 받으면 이미 표시한 답변과 출처도 제거해야 합니다. 현재 문서 버전·권한·계정·키·공급자가 변경되면 진행 중인 요청을 중단합니다. 출처에는 원문 버전·행·UTF-8 바이트 범위·해시가 포함되며, 오래된 출처는 새로 확인합니다.

자연어 검색과 개인 검색 기록 분석, AI 그래프 후보·Agent 쓰기 확인은 일반 사용자 세션의 명시 동의가 필요한 별도 흐름입니다. API 키에 ai:execute가 있다고 개인 동의나 승인 절차를 우회할 수 없습니다. 상세 계약은 실행 중인 서비스의 /api/v1/openapi.json을 확인하세요.

관리자 설정은 최대 262,144 출력 토큰을 허용합니다. 실제 지원 한도는 제공자·모델을 따릅니다. 문서 출처를 표시하고 사용자가 접근 가능한 문서만 활용합니다.

에이전트에 지식 도구를 연결하세요.

MCP 주소는 https://madi.example.internal/mcp이며 /api/v1/mcp도 사용할 수 있습니다. Bearer 키가 필수이며, HTTP POST JSON-RPC의 상태 없는 JSON 응답 방식을 사용합니다. 원격 HTTP MCP와 Authorization 헤더를 지원하는 클라이언트를 연결하세요. 

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "initialize",
  "params": {
    "protocolVersion": "2025-11-25",
    "capabilities": {},
    "clientInfo": {"name": "company-agent", "version": "1.0"}
  }
}

프로토콜 버전 2025-11-25, 2025-06-18, 2025-03-26을 지원합니다. initialize, notifications/initialized, tools/list, tools/call을 제공합니다. stdio나 legacy SSE 세션 서버와는 다른 전송 방식입니다.

MCP 도구 기능
search_documents
search_workspace 		문서 검색
get_document 문서 조회
create_document
update_document
delete_document 		문서 변경
get_backlinks

list_databases

create_database_row 행 추가

정확한 입력 스키마는 tools/list에서 조회합니다. MCP는 사용자 ACL과 키 범위를 그대로 적용하므로 문서 ID를 직접 지정해도 권한 검사를 우회할 수 없습니다.

오류와 재시도를 명확하게.

일반 REST 오류는 {"error":"메시지","request_id":"요청 ID"} 형식입니다. 요청 ID가 있으면 관리자 로그 추적에 사용하세요. 인증·권한·유효성 오류를 무조건 재시도하지 않습니다.

응답 처리 방향
400 입력 필드와 형식 확인
401 토큰 유효성·만료·회전 여부 확인
403 워크스페이스·문서·범위·IP 정책 확인
404 리소스 존재·접근 가능 여부 확인
409 최신 문서를 읽고 충돌 해결
429 호출 속도를 낮추고 간격을 두어 재시도

엔드포인트별 세션·키 허용 여부와 전체 계약은 상세 API 문서와 현재 버전의 서버 구현을 확인하세요.
