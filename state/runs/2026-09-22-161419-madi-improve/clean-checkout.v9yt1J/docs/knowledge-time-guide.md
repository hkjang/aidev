# 시점 기준 지식 검색

v0.2.0이 게시되었습니다. main CI·태그 릴리즈의 통합 검사와 이미지 재반입·폐쇄망 검증을 통과했습니다. 실제 검증 범위와 한계는 [배포 검증 기록](deployment-verification.md)을 확인하세요.

`/app/knowledge-time`은 **문서가 수정된 날짜**와 **업무상 유효하다고 등록한 날짜**를 구분합니다. 문서 속성이나 통합 검색의 ‘시점 기준 지식’에서 이동할 수 있습니다.

## 기준일에 맞는 원문 찾기

1. 업무 기준일과 검색어를 입력합니다. 검색어를 비우면 현재 접근 가능한 등록 문서가 문서 ID 순서로 표시됩니다.
2. 결과에서 기준일 버전과 현재 버전을 구분해 봅니다. 원문 기록 시각은 업무 유효일과 별개입니다.
3. ‘당시 원문 미리보기’로 등록된 버전의 원문을 확인합니다. ‘현재 문서 열기’는 최신 문서로 이동합니다.
4. 해당 날짜에 등록된 기간이 없으면 결과에서 제외합니다. 수정 시각만으로 과거 유효성을 추정하거나 숨겨진 문서 수를 안내하지 않습니다.

현재 조직 용어 사전과 Unicode NFKC·공백·대소문자 정규화를 과거 제목·본문·태그에 적용합니다. 사전에 `K8s`, `Kubernetes`, `쿠버네티스`가 연결돼 있다면 과거 문서도 함께 찾을 수 있습니다. 따옴표·OR·제외 문법은 이 화면에서 지원하지 않으며 명시적으로 오류를 반환합니다. 현재 통합 검색의 고급 검색과 혼동하지 마세요.

## 유효기간 등록과 수정

현재 문서 작성 권한으로 문서 버전과 기간을 등록합니다. **시작일은 포함, 종료일은 제외**하며 종료일 공란은 무기한입니다. 예를 들어 v1을 `2026-01-01`부터 `2026-07-01`까지, v2를 `2026-07-01`부터 무기한으로 등록하면 6월 30일은 v1, 7월 1일은 v2가 나옵니다. 이 범위 규칙은 PostgreSQL의 날짜 범위 표현과 일치합니다. [PostgreSQL 날짜 범위 문서](https://www.postgresql.org/docs/current/rangetypes.html)

문서당 100개까지 등록할 수 있고, 기간 겹침·잘못된 날짜·없는 원문 버전은 거절합니다. 오래된 버전은 50개씩 더 불러올 수 있습니다. 저장 전 비교에서 기간 전체의 변경을 확인하고, 열람자에게 등록 내용과 이유가 공유되는 데 동의합니다.

문서 version과 기간 등록 revision을 모두 확인하므로 다른 사용자가 원문이나 기간을 먼저 바꾸면 409 오류가 납니다. 화면을 다시 읽은 뒤 비교하세요. 입력 중 내용은 브라우저 영구 저장소에 보관하지 않습니다. 문서 선택·조건 이동·다시 읽기에는 미등록 변경 확인이 있고, 탭 종료에는 브라우저 이탈 경고가 있습니다. 브라우저의 모든 이동을 차단하는 복구 보장으로 해석하지 마세요.

기간을 삭제해도 이전 등록 이력과 암호화된 변경 이유는 남습니다. 조회 화면은 최근 50개 이력을 보여줍니다. 문서를 영구 삭제하면 관련 등록·기간·이력도 제거됩니다. 별도 기간 등록을 문서 수정·게시·검토 승인으로 표시하지 않습니다.

## 신뢰·권한의 경계

- 등록은 작성자의 업무 메타데이터이며 사실성, 법적 효력, 게시 승인 인증이 아닙니다. 기준일 이후에 과거 날짜를 등록할 수도 있으므로 **등록 시각**을 확인하세요.
- 과거 버전에도 현재 사용자·워크스페이스·상위 문서/공간 권한·키 scope·민감정보 정책이 적용됩니다. 과거 ACL을 복원하지 않습니다.
- 미리보기의 SHA-256은 반환된 내용의 동일성을 비교하는 값입니다. 신뢰된 외부 서명이나 내용의 정확성을 의미하지 않습니다.
- 화면은 표시 중인 문서·기간·보호 정책을 한 번의 소량 요청으로 재검사하며 접근 실패나 변경 시 표시 사본을 비웁니다. 이미 사람이 복사한 내용을 회수할 수는 없습니다.
- 결과는 등록 내용의 현재 상태이며 DB 전체를 한 시점에 고정한 스냅샷이 아닙니다. 여러 페이지 사이의 등록 변경으로 결과가 달라질 수 있습니다.

## REST·MCP

모든 경로는 `/api/v1` 아래이며 현재 `document:read`가 필요합니다. 등록은 `document:write`도 필요합니다. 키는 지정한 워크스페이스 범위를 벗어날 수 없습니다.

| 경로 | 동작 |
| --- | --- |
| `GET /knowledge/time-search?workspace_id=…&date=2026-06-30&q=K8s` | 등록된 과거 버전 검색 |
| `GET /documents/{id}/valid-at?date=2026-06-30&revision=1` | 등록 revision이 같은 경우 당시 원문 조회 |
| `GET /documents/{id}/validity` | 현재 등록과 최근 이력 |
| `PUT /documents/{id}/validity` | 현재 문서/등록 CAS·이유·동의 후 기간 전체 등록 |
| `POST /knowledge/time-check` | 최대 52개 표시 자료의 현재 접근/버전 일괄 확인 |

MCP는 `search_knowledge_at_date`와 `get_document_at_date`로 같은 REST 권한 검증을 거칩니다. 검색 페이지는 기본·최대 50개이고 `next_after`를 `after`에 넣어 다음 결과를 조회합니다. SQL은 7초, 요청은 8초 읽기 예산으로 제한합니다. 대규모 역사 자료에 대한 응답시간 보장은 아니며 실제 규모별 측정이 필요합니다.

## 검증 범위

격리 PostgreSQL에서 날짜 경계·겹침·기준 버전 충돌·등록 이력 실패의 원자 롤백·현재 비공개 ACL·암호화 이유·MCP 범위를 시험했습니다. 별도 브라우저 게이트는 등록 전 비교, 당시 원문 미리보기, 7월 1일 버전 전환, 모바일 가로넘침, 포커스 복귀, 등록 변경 시 사본 제거를 검증합니다. 실제 사용자 관찰이나 대규모 운영 성능을 대신하지 않습니다.
