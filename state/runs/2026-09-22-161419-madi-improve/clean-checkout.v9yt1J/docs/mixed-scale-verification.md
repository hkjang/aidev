# 1만·10만 혼합 지식 데이터 검증

이 문서는 T2의 재현 조건과 실제 한계를 기록합니다. 문서 목록만의 이전 1만 건 측정을 재사용하지 않고, 같은 워크스페이스의 Markdown·블록·할 일·댓글·첨부 메타데이터·데이터베이스 행을 함께 생성하여 실제 HTTP API와 PostgreSQL 실행계획을 확인합니다. 운영 SLA, 천만 문서 또는 동시 2,000명 지원을 입증하는 시험은 아닙니다.

## 재현

운영 데이터베이스와 분리된 PostgreSQL 테스트 데이터베이스에서 실행합니다. DSN은 조직의 비밀 관리 방식으로 주입하며, 테스트가 임의로 만든 스키마만 종료 시 정리합니다. 서버 URL이나 운영 스키마를 입력하지 않습니다.

```sh
MADI_TEST_POSTGRES_DSN='postgres://tester@127.0.0.1:5432/madi_test?sslmode=disable' \
MADI_MIXED_SCALE=1 \
go test ./internal/server -run '^TestMixedKnowledgeScale$' -count=1 -timeout=22m -v
```

`MADI_MIXED_SCALE`은 시험 전용 선택값이며 서비스의 환경변수가 아닙니다. 기본 `go test ./...`에서는 이 규모 시험을 건너뜁니다. 내부 작업 제한은 20분이고, 개별 HTTP 클라이언트 제한은 30초입니다. 시간 측정은 `-race` 없이 수행합니다. 권한·저장 경합 및 공동 편집 검증은 별도의 `-race` 시험입니다.

빠른 계획 진단만 필요하면 `MADI_MIXED_SCALE_PLAN_ONLY=1`을 추가합니다. 이 모드는 경로별 단일 표본과 실행계획만 수집하며 448개 부하 요청을 실행하지 않습니다. `MADI_MIXED_SCALE_10K_ONLY=1`은 1만 건 단계만 사용하는 개발용 선택값입니다. 계획 전용 파일은 `10000-plan-only.json` 등 별도 이름으로 보관하여 부하 측정 보고서를 덮어쓰지 않습니다.

구현은 `internal/server/mixed_scale_test.go`입니다. 원본 결과는 `test-results/mixed-scale/results.json`, 규모별 데이터 수·응답 제한·실제 SQL·인자·읽기 전용 `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)`은 `10000-detail.json`과 `100000-detail.json`, 권한 회수 확인은 `current-acl.json`에 저장합니다. 이 디렉터리는 실행 결과이며 공개 문서에는 비밀 없는 요약만 제공합니다.

합성 문서는 YAML front matter, 한국어 제목·문단, 체크리스트 2개, 인용문, SQL 코드 블록을 포함합니다. 데이터베이스에는 텍스트·선택·숫자 속성을 사용합니다. 검색 조각과 정규화 색인은 서비스와 같은 순수 파서로 투영한 결과를 격리 스키마에 일괄 삽입합니다. 따라서 검색 읽기 시험이지 색인 작업자의 처리량 시험은 아닙니다.

문서의 20%는 다른 사용자의 개인 문서이며, 추가 1%는 개인 부모 문서 아래의 워크스페이스 문서입니다. 실제 열람자 계정 8개에 대해 원본·댓글·첨부 접근 거절을 확인합니다. 공통 현재 권한 함수가 반환하는 접근 가능 문서 수는 각각 7,900개와 79,000개여야 합니다. 응답의 비공개 전용 표식을 검사하고, 마지막에는 실제 멤버십을 삭제한 뒤 목록·검색·할 일·데이터베이스의 새 요청이 거절되는지 확인합니다.

첨부는 메타데이터만 있으며 실제 PDF 바이트, 파일 다운로드, 본문 추출, OCR을 실행하지 않습니다. 임베딩·ANN·AI 공급자, 외부망, 브라우저 렌더링, TLS 프록시, 모든 백그라운드 작업을 포함하는 운영 부하도 제외합니다. 공간 계층 전체 조합이나 모든 실데이터 분포를 대신하지 않습니다.

## 요청과 측정 방식

| 경로 | 실제 요청 | 반환/검사 범위 |
| --- | --- | --- |
| 문서 목록 | `GET /documents?limit=100` | 현재 권한 내 원문 없는 요약 100개 |
| 한국어 문서 검색 | `GET /search?q=k8s장애&type=document&limit=30&group=document` | `쿠버네티스 / k8s / Kubernetes` 용어 사전, 문서별 결과 |
| 전체 유형 검색 | `GET /search?q=쿠버네티스&limit=30` | 문서·블록·할 일·댓글·행 등의 실제 통합 검색 |
| 할 일 보드 | `GET /tasks/board` | 원문 검사 및 문서·바이트·할 일 제한 |
| 댓글 | `GET /documents/{id}/comments?limit=200` | 접근 가능한 단일 문서의 댓글 3개 |
| 첨부 목록 | `GET /documents/{id}/attachments` | 접근 가능한 단일 문서의 첨부 메타데이터 1개 |
| 데이터베이스 조회 | `POST /databases/{id}/query`, `limit:100` | 실제 서버 조회 엔진과 결과 제한 |

모든 경로는 `/api/v1` 아래이며 워크스페이스 ID를 지정합니다. 각 규모·경로에서 응답 형식 표본 1개를 수집하고, 동시성별 준비 요청 2개 후 측정 요청 16개를 실행합니다. 동시성은 독자 1명 또는 서로 다른 독자 8명입니다. 총 448개의 측정 요청이며 준비·권한 검사 요청은 지연 표본에 포함하지 않습니다.

P95는 기존 규모 시험과 같은 정렬 표본 인덱스 `floor((N-1)*0.95)`를 사용합니다. 16개 표본은 통계적 용량 추정에 충분하지 않습니다. HTTP 상태와 오류 수를 지연과 함께 확인해야 하며, 제한시간 오류가 섞인 수치를 정상 응답의 성능으로 해석하면 안 됩니다. 읽기 전용 실행계획 수집은 각 규모의 부하 요청이 끝난 뒤 별도 트랜잭션에서 수행하며 30초 제한을 사용합니다.

## 환경과 해석

2026-09-09 공유 WSL2 Linux/amd64, Go 1.26.8, PostgreSQL 18.6, 노출 CPU 4개, 호스트 메모리 약 15.6GiB에서 측정했습니다. 시험용 pgx 풀의 최대 연결은 16개입니다. 07:33 KST에 시작한 1만 건 구간은 다른 에이전트의 보안 검사·Go 컴파일·회귀 작업과 일부 겹쳤습니다. 해당 작업 종료 고지 이후의 10만 건 후반은 이 시험 외 대형 회귀 작업을 중지했지만, 전용 성능 호스트는 아닙니다. 기존 swap 사용량도 있으므로 운영 하드웨어와 동일한 수치로 해석하지 않습니다.

보고서의 Go heap·프로세스 RSS는 요청 그룹 종료 시점의 표본입니다. PostgreSQL·운영체제 페이지 캐시와 전체 서비스의 최대 메모리 사용량은 포함하지 않으며, 실제 컨테이너 메모리 제한으로 바로 사용해서는 안 됩니다.

## 개선 경계와 정확성 검증

검색의 FTS·원문 부분 문자열·정규화 후보를 각각 조회한 뒤 ID로 중복을 제거하고, 최종 결과에서는 현재 문서 권한·문서 버전을 확인합니다. 전체 유형 검색은 본문이 없는 접근 가능 문서 ID만 한 번 계산하여 여러 조각의 같은 조상 권한 검사를 반복하지 않도록 했습니다. 비공개 후보 수나 후보 원문을 API·AI 공급자로 보내지 않습니다. 원문 부분 문자열 검색, 현재 정규화 색인이 없는 원문의 기존 검색, 순위 계산과 결과 제한은 유지합니다.

댓글 FTS는 명시적 `simple` 설정의 표현식 GIN 인덱스를 사용합니다. 새 정본 컬럼이나 외부 검색 엔진은 필요하지 않습니다. 대소문자 변형이 없는 제한된 한글·ASCII 비문자 검색어만 동일 의미의 `LIKE`를 사용하며, 라틴 문자·기타 Unicode·결합 문자는 기존 로캘 기반 `ILIKE`를 유지합니다. 이 구분은 PostgreSQL의 [패턴 일치 규칙](https://www.postgresql.org/docs/18/functions-matching.html)과 [FTS 인덱스](https://www.postgresql.org/docs/18/textsearch-indexes.html)에 기반합니다.

`TestPostgresSearchCostOptimizationsMatchOriginal`은 한글·붙임/띄어쓰기·조직 용어·영문·특수문자·복합 Unicode·고급 검색 13개 × 실제 권한 주체 2명 × 검색 유형 6개, 총 156개 조합에서 기존 SQL과 새 SQL의 전체 JSON 및 점수를 비교합니다. 개인 부모 문서와 개인 문서, 정규화 투영이 없는 원문, 삭제된 댓글도 포함합니다. 기존 통합 유형·제한 키 scope·현재 ACL·원문 버전·불완전 gram·cursor 시험은 별도로 유지합니다. 이 검사는 한정된 합성 평가이며 모든 언어·콜레이션의 성능 보증은 아닙니다.

1차 개선에서는 할 일 보드의 10만 건·8독자 오류가 해소됐지만, 검색 후보 CTE의 불필요한 유형 평가와 중복 권한 검사 때문에 문서 검색 5건·전체 검색 15건이 실패했습니다. 해당 중간 결과도 `test-results/mixed-scale/phase1-*.json`에 보존합니다. 최종 개선과 혼동하여 1차 결과를 통과로 표시하지 않습니다.

준비된 SQL의 generic/custom 계획은 같은 읽기 전용 연결에서 별도로 비교했습니다. 할 일 13,000개 문서 표본에서는 강제 custom이 더 빠르지 않았고, 이 설정은 내부 권한 함수의 계획에도 영향을 주었습니다. 따라서 추정만으로 서비스에 `force_custom_plan`이나 DB 전역 튜닝을 적용하지 않았습니다. `EXPLAIN` 단일 표본과 실제 반복 HTTP 실행은 계획 선택·캐시·공유 부하가 달라질 수 있으므로 각각의 근거를 구분합니다.
