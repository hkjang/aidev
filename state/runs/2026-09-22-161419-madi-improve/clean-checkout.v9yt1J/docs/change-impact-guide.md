# 문서 변경 영향 분석

> v0.2.0이 게시되었습니다. main CI·태그 릴리즈의 통합 검사와 이미지 재반입·폐쇄망 검증을 통과했으며, 실제 검증 범위와 한계는 [배포 검증 기록](deployment-verification.md)에 구분합니다.

## 관계를 실제 유지보수 작업에 연결하기

그래프에서 문서를 선택한 뒤 ‘관계 연결’로 의존 대상을 등록합니다. 방향은 **사용하는 문서 → 의존하는 대상**입니다. 예를 들어 설치 Runbook이 운영 정책을 따라야 한다면 Runbook에서 정책을 대상으로 ‘정책 의존’을 연결합니다.

| 관계 | 의미 |
| --- | --- |
| 참조·관련 | 참고 가능성이 있는 연결이며 정책 준수 의무를 뜻하지 않습니다. |
| 정책 의존 | 이 문서가 대상 규정·정책을 따릅니다. |
| 실행 의존 | 이 문서의 실행 절차가 대상 절차·구성에 의존합니다. |
| 데이터 의존 | 이 문서가 대상 데이터의 정의·조건을 사용합니다. |

문서 변경 영향(`/app/knowledge-impact`)에서 변경된 정책과 이전 버전을 선택합니다. 현재 원문과의 차이, 역방향 의존 문서, Runbook 종류, 문서를 지식 범위에 포함한 Agent, 본인이 생성한 현재 열람 가능한 지식 패키지를 함께 보여 줍니다. 그래프의 ‘변경 영향 분석’에서도 같은 화면으로 이동합니다. 미리보기로 문서를 확인한 뒤 닫으면 원래 버튼으로 키보드 포커스가 돌아갑니다.

## 무엇을 감지하며 무엇을 보증하지 않나요?

- 수치·절차 표현·제목/태그·문서 행의 접근 조건 변경을 규칙으로 분류합니다. AI 의미 분석 결과나 자동 확정 판정이 아닙니다. 표현 변경 후보에도 실제 의미 변경이 있을 수 있습니다.
- 현재 원문 버전과 비교하므로 과거 대 과거 비교는 기존 문서 버전 비교를 사용합니다.
- 최대 5단계·500문서, 단계별 2,000개 관계, 패키지/Agent 각 100건을 검사합니다. 한도 도달을 화면에 표시합니다. 여러 경로가 있으면 첫 발견 경로를 대표로 표시합니다.
- 명시적으로 등록한 관계를 사용합니다. 등록하지 않은 업무상 의존, 미해결 위키 링크, 다른 시스템의 사본을 완전하게 추적하지는 못합니다.
- 문서 행의 소유자·공유 범위·위치 변경 기록은 이 기능 도입 이후부터 수집합니다. 상위 공간의 별도 권한 변경이 문서 본문 변경 이력에 모두 기록된다는 뜻은 아닙니다. 접근 허용 여부는 언제나 현재 ACL로 검사합니다.
- Agent가 해당 문서를 범위에 포함한다는 사실과 특정 실행 결과가 달라진다는 판단은 다릅니다. Agent 지시·도구를 자동으로 수정하거나 실행하지 않습니다.
- 다른 사람의 개인 지식 패키지 이름·존재·개수는 보여 주지 않습니다. 이미 외부에 전달된 사본을 권한 철회만으로 회수할 수 없습니다.

## 선택적으로 영향 검토를 운영하기

관리자 시스템 설정에서 검토·승인 기능을 활성화한 경우에만 영향 검토 요청과 처리함을 제공합니다. 설정하지 않으면 분석·문서 미리보기만 사용하며 검토 요청 API도 거절합니다. 비활성화해도 기존 기록을 삭제하지는 않습니다.

직접 의존 문서의 소유자가 변경 원문을 읽고 대상 문서를 수정할 수 있을 때, 변경 원문 작성자가 검토를 요청할 수 있습니다. 요청은 원문 버전·대상 버전·관계 종류에 묶입니다. 같은 변경의 중복 요청을 막고, 소유자에게 내부 알림을 보냅니다. 다른 문서의 제목을 알림에 복사하지 않습니다.

담당자 또는 현재 문서 수정 권한이 있는 워크스페이스 관리자는 근거 의견과 함께 ‘영향 없음’, ‘수정 필요’, ‘수정 완료’, ‘예외 요청’을 기록합니다. 기록은 수정 전 revision을 검사하고 의견을 암호화해 이력으로 남깁니다. **예외 요청은 예외 승인 완료가 아닙니다.** 이 영향 검토 기록은 문서 게시·Runbook 실행 승인과 별개이며, 기존 승인 정책을 대체하지 않습니다.

검토 중 대상 문서가 바뀌면 새 버전을 확인해야 합니다. 변경 원문이 다시 바뀌면 이전 검토를 최신 원문에 대한 완료로 처리할 수 없습니다. 새 변경 버전으로 다시 분석·요청하세요. 두 문서 중 하나라도 접근을 철회하면 해당 검토와 이력도 숨깁니다. 현재 민감정보 정책에 위반하는 검토 의견은 새로 저장하거나 과거 기록으로 표시하지 않습니다.

## API

| 요청 | 용도 |
| --- | --- |
| `POST /api/v1/documents/{id}/relations` | `target_id`, `type`, `expected_version`으로 관계 등록 |
| `GET /api/v1/documents/{id}/impact?from=1&depth=2` | 이전 버전부터 현재까지 변경 및 역방향 영향 후보 |
| `POST /api/v1/knowledge/impact-check` | 표시 중인 문서 버전·패키지·Agent의 현재 접근 조건 재검사 |
| `POST /api/v1/documents/{id}/impact-reviews` | `source_version`, `target_id`, `target_version`, `relation_type`으로 직접 의존 검토 요청 |
| `GET /api/v1/knowledge/impact-reviews?workspace_id=…` | 현재 접근 가능한 최신 200개 검토 |
| `PUT /api/v1/knowledge/impact-reviews/{id}` | `revision`, `target_version`, `status`, `note`로 처리 |
| `GET /api/v1/knowledge/impact-reviews/{id}/history` | 현재 ACL·보호 정책을 적용한 의견 이력 |

조회에는 `document:read`, 관계/검토 변경에는 추가로 `document:write`가 필요합니다. Agent 정보는 `ai:execute`와 현재 Agent 기능 설정도 검사합니다. 키의 워크스페이스·만료·철회·관리자 허용 scope 상한을 유지합니다.

## 운영과 검증

`knowledge_change_events`, `knowledge_impact_reviews`, `knowledge_impact_review_events`는 백업·복원 대상입니다. 원문 버전 본문을 다시 복제하지 않고 기존 불변 버전 기록을 비교합니다. 문서를 물리 삭제하면 연결된 변경·검토 기록도 삭제합니다. 삭제 전 기존 보존 정책 검사를 우회하지 않습니다.

부분 PostgreSQL race 시험에서 유형별 관계, 다단계 탐색, 접근 불가 중간 문서 차단, 중복 요청, 검토 CAS, 대상/원문 변경, 암호화 이력, 읽기 전용 키의 쓰기 차단을 확인했습니다. 관리자 설정에 따른 검토 제외와 새 테이블 백업 목록 완전성 검사도 포함합니다. 실제 브라우저 시험은 근거 보관→패키지→영향 분석→소유자 검토와 모바일 390px 흐름을 실행합니다. 대규모 성능이나 실제 사용자 과제 완료시간 개선을 입증한 시험은 아닙니다.
