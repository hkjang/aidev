# 서비스 운영 가이드

관련 문서: [[장애 대응 절차]]

- [ ] 배포 상태 확인
- [x] 담당자 확인

백링크는 현재 문서를 참조하는 문서를 보여줍니다. 그래프에서는 연결 관계를 따라갈 수 있습니다. 문서 버전 이력으로 변경을 확인하고 복구하며, 삭제 문서는 휴지통에서 복원합니다. 다른 사용자의 저장과 충돌하면 최신 버전을 확인한 뒤 다시 편집하세요.

할 일과 데이터베이스

문서 속 체크리스트를 할 일 화면에서 모아 보고 완료 상태를 변경합니다. 데이터베이스는 속성을 지정하고 행을 추가해 정보를 관리합니다. 선택 속성은 먼저 옵션을 설정하고 목록에서 선택하세요. 관계·수식·롤업과 표·보드·목록·달력·갤러리·타임라인을 제공하며, 잘못된 옵션·형식과 순환 수식은 저장 전에 검사합니다.

내 문서를 가져오고 내보내기

가져오기 센터에서 Markdown·Obsidian Vault·Notion HTML/Markdown ZIP·HTML·CSV·madi JSON을 미리 확인한 뒤 비동기 작업으로 반영합니다. 폴더와 첨부·지원되는 링크도 옮깁니다. 내보내기는 원문 Markdown, 이동식 링크 Markdown, HTML ZIP, JSON Vault, 데이터베이스 CSV를 지원합니다. 변환 범위와 한도는 입출력 가이드를 확인하세요.

내 화면과 연결 권한을 관리하세요.

프로필 메뉴에서 개인 설정을 열어 화면 테마, 글자 크기 등의 옵션을 선택합니다. 서비스 운영 설정과 개인 설정은 분리됩니다. 모바일에서도 메뉴 버튼으로 탐색하고 문서를 읽고 수정할 수 있습니다.

개인 API 키 발급과 회전

개인 API 키 메뉴에서 이름, 워크스페이스, 권한 범위, 만료, 허용 IP와 호출 제한을 지정합니다. 비밀은 발급할 때 한 번만 표시됩니다. 키는 내 계정의 권한보다 넓은 접근 권한을 가질 수 없습니다.

키를 회전하면 이전 비밀은 즉시 사용할 수 없게 됩니다. 사용하는 연동 시스템에 새 비밀을 반영하고 사용하지 않는 키는 폐기하세요. 개인 키 회전과 서버의 ENCRYPTION_KEY 교체는 다른 작업입니다.

REST API와 MCP 가이드에서 외부 시스템 연결 방법을 확인할 수 있습니다.

For administrators

조직의 운영 방식에 맞춰 설정하세요.

초기 관리자 계정으로 로그인한 뒤 관리자 화면에서 서비스 이름, 실제 서비스 URL, 세션, 키 정책을 설정합니다. 운영 설정은 DB에 보관하고 OIDC·AI 비밀은 암호화해 저장합니다.

관리 영역 설정과 사용
사용자 계정 생성, 서비스 역할, 비활성화와 서비스 계정 구분
워크스페이스 소유자·관리자·편집자·댓글 작성자·조회자 역할
SSO · AI 연결 주소·클라이언트·모델·암호화 비밀 설정
API 키 허용 범위와 기본 만료 정책
검토와 승인 활성화 여부와 검토자 역할
운영 기록 관리자 대시보드, 감사, 설정 변경 이력과 복구

승인 기능은 기본적으로 꺼져 있습니다. 관리자가 활성화한 경우에만 검토 요청·승인·반려 절차를 사용합니다. 1단계·다단계·부서·병렬 검토자를 설정하고 결재선과 현재 권한을 확인합니다. 설정하지 않은 워크스페이스에는 승인 절차를 강제하지 않습니다.

서비스 계정은 비밀번호 로그인 없이 토큰으로 접근합니다. 계정과 워크스페이스의 권한을 함께 관리하고 자동화용으로 관리자 세션을 공유하지 마세요.

Keycloak은 세 가지 연결 정보로.

Keycloak에서 confidential OpenID Connect 클라이언트를 만든 뒤 Standard flow를 활성화합니다. madi의 관리자 설정에 issuer, client ID와 client secret을 입력하면 discovery로 엔드포인트를 확인합니다.

설정 예시
서비스 URL https://madi.example.internal
Issuer https://sso.example.internal/realms/company
Client ID madi
Client secret Keycloak에서 발급한 비밀
Redirect URI https://madi.example.internal/api/v1/auth/oidc/callback

서비스와 브라우저가 모두 Keycloak에 접근할 수 있어야 합니다. 자동 계정 생성 여부는 조직 정책에 맞게 설정하세요. 연동은 Authorization Code, S256 PKCE, state와 nonce를 사용합니다. 기업 인증 페이지에서는 SAML·TLS LDAP·SCIM과 그룹 매핑을 별도로 설정할 수 있습니다.

SSO 설정 오류를 복구할 수 있도록 초기 로컬 관리자 계정을 안전하게 보관합니다.

사내 모델을 스트리밍으로 연결하세요.

관리자 AI 설정에서 OpenAI 호환 API 기본 URL, 모델 ID, API 키, 최대 출력 토큰과 시스템 지시문을 지정합니다. vLLM, Ollama 또는 사내 게이트웨이의 호환 엔드포인트를 사용합니다. 

기본 URL   http://llm.internal:8000/v1
모델       내부 서버에 배포된 모델 ID
최대 토큰  1 ~ 262144

기본 URL에 /chat/completions를 붙여 요청합니다. 이미 그 경로로 끝나는 URL은 그대로 사용합니다. 응답은 스트리밍으로 제공하며 프록시에서 SSE 버퍼링을 꺼야 합니다.

최대 262,144는 설정 가능한 출력 토큰 상한입니다. 실제 요청 가능량과 컨텍스트 크기는 제공자와 모델의 한도를 따릅니다. Azure 전용 엔드포인트는 호환 경로·인증을 제공하는 게이트웨이 구성이 필요할 수 있습니다.

사용자는 현재 문서 또는 워크스페이스를 대상으로 질문하고 출처를 확인합니다. 검색과 AI에 사용자 문서 권한을 적용합니다. 외부 AI를 설정하면 질문과 관련 문서가 그 제공자로 전송되므로 폐쇄망에서는 내부 주소를 사용하세요.

Inside your network

폐쇄망에 이미지를 반입하세요.

Docker와 외부 PostgreSQL을 먼저 준비합니다. 서비스 릴리즈는 madi:v0.2.0 이미지를 담은 madi-v0.2.0.tar.gz 하나입니다. 웹 자산은 이미지에 포함되며 실행 시 패키지나 CDN을 내려받지 않습니다. 기본 릴리즈 플랫폼은 Linux amd64입니다.

  1. 연결망에서 릴리즈 파일과 저장소의 compose.yaml, .env.example을 준비합니다.
  2. 파일 해시를 확인해 운영망에 반입하고 이미지를 불러옵니다.
  3. 네 환경변수를 설정한 뒤 Compose를 실행합니다.
  4. 준비 상태와 로그인, 문서 저장, 첨부파일을 확인합니다.
gzip -t madi-v0.2.0.tar.gz
gzip -dc madi-v0.2.0.tar.gz | docker load
cp .env.example .env
# .env 값을 실제 운영 정보로 편집합니다.
docker compose up -d
curl --fail http://127.0.0.1:8080/readyz
필수 환경변수 역할
POSTGRES_DSN PostgreSQL 연결 문자열
BOOTSTRAP_ADMIN 최초 관리자 이메일
BOOTSTRAP_ADMIN_PASSWORD 최초 관리자 비밀번호
ENCRYPTION_KEY 32바이트 무작위 값의 Base64 표현

openssl rand -base64 32로 암호화 키를 생성할 수 있습니다. 기존 키를 보관하고 배포마다 새로 만들지 마세요. 최초 관리자 비밀번호는 기존 계정의 재설정 수단이 아닙니다.

/var/lib/madi를 영구 볼륨으로 보관하며 컨테이너 UID/GID 10001에 읽기·쓰기 권한을 부여합니다. 기본 첨부 경로는 /var/lib/madi/attachments입니다. Compose는 이미지를 외부에서 받지 않도록 구성합니다. PostgreSQL과 선택 사항인 Keycloak·AI 서버는 릴리즈에 포함되지 않습니다.

운영에서는 사내 TLS 프록시를 사용하고 시스템 설정의 실제 서비스 URL을 지정하세요. Kubernetes 예제도 제공합니다.

복원할 수 있는 백업을 남기세요.

전체 복구에는 같은 시점의 PostgreSQL 백업, 파일 볼륨, ENCRYPTION_KEY와 배포 설정, 해당 버전 이미지가 필요합니다. 관리자 ZIP은 같은 서비스 버전과 ENCRYPTION_KEY 환경에서 복원할 수 있습니다. 백업 페이지에서 파일과 확인 문구 RESTORE를 입력하세요. 현재 데이터를 교체하고 세션을 폐기하므로 먼저 격리된 환경에서 시험합니다.

ZIP 복원은 압축 파일 256MB, 압축 해제 1GB, 10,000개 항목으로 제한합니다. 기존 파일은 보관하고 저장소 경로는 대상 환경을 유지합니다. 대규모 재해 복구와 PITR에는 PostgreSQL 네이티브 백업을 사용합니다.

서비스 쓰기를 중단한 상태에서 pg_dump --format=custom과 파일 볼륨 백업을 함께 수행합니다. DB 암호는 명령행에 노출하지 않고 조직의 비밀 관리 절차를 사용하세요. 

docker compose stop madi
pg_dump --format=custom --file=madi-postgres.dump \
  'postgresql://madi@postgres.internal:5432/madi'
# 같은 시점의 파일 볼륨과 암호화 키를 별도 보관합니다.
docker compose start madi

새 데이터베이스와 새 볼륨에 복원 시험을 진행하고 같은 ENCRYPTION_KEY로 서비스를 시작하세요. 사용자 로그인, 문서·버전·첨부파일과 연동 비밀을 확인합니다. 업데이트 후 이전 이미지로만 되돌리면 스키마가 맞지 않을 수 있으므로 같은 시점의 백업 복원이 필요할 수 있습니다.

첫 릴리즈의 전체 범위.

첫 릴리즈는 P0~P3를 함께 대상으로 합니다. 단계는 별도 출시를 의미하지 않습니다. 실제 기능은 관리자의 정책·사용자 권한·기능 플래그에 따라 표시되며 외부 연동은 운영 환경의 연결 설정이 필요합니다.

P0 · 문서와 안전한 기본 운영

Markdown 원문·블록·트리·그래프·통합 검색, 가져오기와 내보내기, OIDC·권한·API·MCP·개인 키 회전·문서 이력과 백업.

P1 · 협업과 지식 운영

Yjs 실시간 협업, 고급 데이터 보기, 벡터 검색, 문서 생명주기, Webhook과 자동화.

P2 · 확장 플랫폼

Canvas, Plugin SDK, AI 지식 그래프, 다단계 승인, 기업 커넥터와 네이티브 앱.

P3 · Knowledge OS

실행형 Runbook의 격리 실행·확인 절차, Workspace Agent의 도구 제한과 사용자 확인, 기업 데이터·문서·SQL 탐색과 읽기전용 Text2SQL.

CRDT 동시 편집과 문서 버전 충돌 감지는 다른 기능입니다. 검색 기반 AI 출처와 벡터 임베딩 RAG도 구분합니다. 벤치마크 없이 대규모 동시 접속·천만 문서 성능을 보장하지 않습니다.

전체 기능 범위와 운영 한계 · 릴리즈 노트

문제가 생겼을 때 확인할 것.

증상 확인
서비스가 시작되지 않음 DB 연결·TLS·권한, 암호화 키 형식과 32바이트 길이
SSO 리디렉션 오류 서비스 URL과 Keycloak redirect URI의 정확한 일치
AI가 한 번에 표시됨 프록시 버퍼링, 호환 제공자의 streaming 지원
403 접근 오류 계정·문서·워크스페이스 권한과 키 범위·IP 제한
409 저장 충돌 최신 버전을 다시 읽고 변경 사항 반영
파일 업로드 실패 볼륨 용량, UID 10001 권한, 파일 크기 제한

문제 보고에는 수행한 작업과 오류 메시지, 요청 ID를 포함합니다. 비밀번호, API 키와 민감 문서 내용은 제외하세요. GitHub Issues에서도 재현 정보를 남길 수 있습니다.
