# madi 운영 설정 가이드

관리자와 팀 관리자는 환경변수를 추가하지 않고 화면에서 운영 정책을 관리합니다. 서버가 요구하는 값은 기존 `POSTGRES_DSN`, `BOOTSTRAP_ADMIN`, `BOOTSTRAP_ADMIN_PASSWORD`, `ENCRYPTION_KEY` 네 가지입니다.

## 기능 정책

- 서비스 관리자: **서비스 운영 → 기능 정책** (`/admin/operations?tab=features`)
- 워크스페이스 소유자·관리자: **팀 운영 설정 → 기능 정책** (`/app/workspace-operations?tab=features`)

지원하는 기능 정책은 캔버스, 플러그인 실행, 실시간 공동 편집, 데이터베이스 수식, AI 지식 그래프, 워크스페이스 에이전트입니다. 별도 설정이 없으면 켜져 있습니다.

서비스·워크스페이스·사용자 정책을 모두 만족해야 실행할 수 있습니다. 어느 단계라도 꺼져 있으면 하위 단계에서 켜짐을 선택해도 사용할 수 없습니다. 기능 정책은 권한을 추가하지 않으므로 기존 문서 ACL, API 키 범위, 승인 절차, 정보보호 정책은 계속 적용됩니다.

서비스 관리자는 적용 대상에서 특정 사용자를 선택하여 사용자 제한을 저장하고 이력을 복원할 수 있습니다. 개인 사용자는 이 정책을 바꿀 수 없습니다. 워크스페이스 화면의 **현재 사용 가능** 표시는 로그인한 사용자 기준입니다.

| 기능 | 비활성화했을 때 |
| --- | --- |
| 캔버스 | 열람·편집·AI 실행 요청 차단. 실행 중 AI는 권한을 재확인하고 취소. 원본은 보존 |
| 플러그인 | 실행·브리지 차단. 실행 중 작업은 약 1초 간격의 정책 재검사로 취소. 설치·설정은 보존 |
| 실시간 공동 편집 | 공동 편집 연결 종료. 일반 문서 열람·REST 편집과 Markdown 원본은 유지 |
| 데이터베이스 수식 | 수식과 수식에 의존하는 집계는 셀 오류로 표시. 원본 행·수식 정의 및 일반 숫자 집계는 유지 |
| AI 지식 그래프 | 새 분석·추천 실행 차단. 수동 문서 관계와 원본은 보존 |
| 워크스페이스 에이전트 | 새 실행·도구 호출 차단, 진행 중 실행 취소. 설정·기록은 보존 |

정책은 API·백그라운드 작업에도 적용합니다. 메뉴 숨김은 보조 표시이며 실제 권한 판정은 서버가 수행합니다. 기능을 끄는 것은 이미 실행된 외부 변경을 되돌리는 기능이 아닙니다.

서비스·워크스페이스 설정 이력은 기존 설정 화면에서, 사용자 기능 이력은 해당 사용자 정책 화면에서 확인합니다. 다른 관리자가 설정을 바꾸었을 때는 `409` 충돌을 표시하고 저장하지 않은 화면 값을 보존합니다. 최신 설정을 다시 불러온 뒤 변경을 재적용하세요.

## 팀 브랜딩

**팀 운영 설정 → 브랜딩** (`/app/workspace-operations?tab=branding`)에서 이름·대표 색상·로고·파비콘을 설정합니다. 비우면 서비스 기본값을 사용합니다.

1. **이미지 파일 선택**에서 PNG/JPEG를 고르고 **이미지 등록**을 누릅니다.
2. 등록된 이미지를 로고 또는 파비콘 선택 항목에서 고릅니다.
3. 미리보기를 확인한 뒤 **브랜딩 저장**을 누릅니다.

이미지 제한은 업로드 1MB, 최대 2048×2048 픽셀입니다. 서버가 디코딩하고 긴 변을 최대 512픽셀로 줄인 뒤 PNG로 다시 인코딩합니다. 변환 결과는 최대 512KB입니다. 원본의 위치정보·EXIF·댓글 등 메타데이터는 유지하지 않습니다.

외부 이미지 주소, SVG, 사용자 CSS·스크립트는 허용하지 않습니다. 등록한 이미지는 워크스페이스 구성원의 현재 권한을 확인한 뒤 제공하며 장기 브라우저 캐시를 사용하지 않습니다. 대표 색상은 `#RRGGBB` 형식이고 흰색 글자와 최소 4.5:1 대비가 필요합니다.

워크스페이스당 최대 40개 이미지를 보관합니다. 설정 이력 복원을 위해 이미지는 변경 불가능한 항목으로 유지합니다. 기본 이미지로 돌아가도 등록 이미지가 물리 삭제되지는 않습니다. 해당 이미지와 사용자 기능 정책·이력은 서비스 전체 백업에 포함됩니다.

## 상태와 오류

**서비스 운영 → 상태와 오류** (`/admin/operations?tab=health`)는 실제 PostgreSQL 연결·연결 수·응답 시간, 현재 Go 프로세스 메모리·작업 수, HTTP 응답 집계를 표시합니다. 화면은 10초마다 갱신합니다. 프로세스 카운터는 재시작 후 다시 시작합니다.

최근 오류 목록은 HTTP 4xx/5xx와 서버 예외의 제한된 메타데이터입니다. `403` 권한 거부나 `409` 저장 충돌은 정상적인 보호 동작일 수도 있습니다. 요청 ID와 발생 시각을 이용해 관련 감사로그를 확인하세요.

저장하는 값은 요청 ID·등록된 경로 템플릿·HTTP 메서드·상태·소요 시간·오류 종류뿐입니다. 본문·질문·쿠키·실제 문서 ID·사용자 ID·URL 쿼리는 저장하지 않습니다. 전용 운영 오류 기록은 감사로그와 구분되며 전체 백업 대상이 아닙니다.

보존 기간은 1~90일, 기본 7일입니다. 매분 보존 기간과 50,000건 보존 한도를 기준으로 정리하므로 정리 직전에는 일시적으로 한도를 넘을 수 있습니다. 화면에는 최신 200건까지 표시합니다. 과부하·DB 연결 장애로 큐에 담거나 저장하지 못한 오류 수를 별도로 표시합니다.

## OpenTelemetry

**서비스 운영 → OpenTelemetry** (`/admin/operations?tab=telemetry`)에서만 설정합니다. 기본적으로 전송하지 않으며 별도 `OTEL_*` 환경변수 설정은 필요하지 않습니다. 샘플링·리소스·범위 제한·전송 설정은 명시적으로 구성하여 표준 SDK 환경변수의 값이 서비스 정책을 바꾸지 못하게 합니다.

1. 수집기의 **전체 OTLP HTTP/protobuf traces 주소**를 입력합니다. 예: `https://otel.intranet:4318/v1/traces`.
2. 사내 CA를 사용한다면 PEM 인증서를 입력합니다. 시스템 CA에 추가되며 TLS 검증을 끌 수 없습니다.
3. 필요하면 Bearer 인증 토큰을 등록합니다. 토큰은 `ENCRYPTION_KEY`로 암호화하며 다시 표시하지 않습니다. 빈 입력은 기존 토큰 유지, 명시적인 삭제 선택은 토큰 제거입니다.
4. 수집 비율과 제한 시간을 선택하고 저장합니다.
5. **저장된 연결 테스트**로 고정 진단 Trace 한 개를 실제 전송합니다. 이 테스트는 문서·질문을 전송하지 않으며 자동 전송이 꺼져 있어도 명시적으로 실행할 수 있습니다.
6. 자동 전송을 활성화하면 약 1초 내에 적용합니다.

HTTP는 **평문 전송 허용**을 켠 경우에만 사용할 수 있습니다. 토큰과 진단 정보가 암호화되지 않으므로 HTTPS를 권장합니다. 주소에 계정정보·쿼리·fragment를 넣을 수 없고 리다이렉트는 따라가지 않습니다. 프록시 환경변수도 사용하지 않습니다.

전송하는 정보는 서비스 이름 `madi`, 서비스 버전, HTTP 메서드, 등록된 경로 템플릿, 요청 ID, 상태, 시작·종료 시간입니다. 예를 들어 실제 문서 주소 대신 `GET /api/v1/documents/{id}`를 사용합니다. 사용자·워크스페이스·문서 ID, 프롬프트, 요청/응답 본문, 인증정보, 외부 헤더의 trace context는 전송하지 않습니다.

큐는 최대 2,048개이고 요청 처리와 별개로 전송합니다. 설정 변경·종료 시 기존 대기 Trace를 폐기하고 진행 중 전송을 취소합니다. 실패한 전송을 자동 재시도하지 않습니다. 성공·실패·폐기·대기 개수는 실제 관측 결과이며 수집기 내부의 장기 저장 성공까지 보장하는 수치는 아닙니다.

운영 설정도 서비스 설정 이력에 기록됩니다. 전체 백업을 복원한 뒤에는 자동 진단 전송이 비활성화되므로 수신 주소·인증서·망 정책을 확인하고 필요한 경우 다시 켜세요.

## 검증

`TestOperations*` PostgreSQL·경쟁 검사에는 3단계 기능 정책, 실제 수식·캔버스·실행 중 플러그인, 이미지 안전 변환·워크스페이스 격리, OTLP protobuf 실제 송수신, 사내 CA·리다이렉트 거부, 민감정보 미포함, SDK 환경변수 영향 차단, 진행 중 전송 취소가 포함됩니다.

`tests/operations.mjs`는 실제 서비스 화면의 저장·충돌·이력·선택 항목·브랜딩·OTLP 수신·오류·모바일 배치를 검증합니다. 테스트용 새 워크스페이스와 사용자를 만들며 전역 진단 설정은 실행 후 원래 값으로 복원합니다. 운영 데이터베이스가 아닌 검증 환경에서 실행하세요.

공식 프로토콜 참고: [OpenTelemetry Go exporters](https://opentelemetry.io/docs/languages/go/exporters/), [OTLP specification](https://opentelemetry.io/docs/specs/otlp/).
