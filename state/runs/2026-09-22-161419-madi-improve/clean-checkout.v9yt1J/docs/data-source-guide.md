# 외부 데이터 소스 · Text2SQL 가이드

madi의 외부 데이터 소스는 원격 DB를 문서 DB로 복제하지 않습니다. 허용된 테이블의 컬럼 메타데이터, 사람이 작성한 설명과 관련 문서, 제한된 조회 계획만 저장합니다. 실제 행 데이터는 사용자가 등록된 조회를 실행할 때 가져오며 조회 이력에는 결과값을 남기지 않습니다.

## 연결 구성

1. 서비스 관리자가 `/admin/connectors`에서 외부 연결을 켜고 정확한 DB 호스트 이름을 허용 목록에 등록합니다.
2. 로그인할 수 없는 전용 서비스 계정을 만들고 대상 워크스페이스와 공간의 읽기 권한을 부여합니다.
3. 소유자 또는 워크스페이스 관리자가 `/app/data-sources`에서 데이터 소스를 추가합니다. 엔진, 호스트·포트, DB 이름, 전용 서비스 계정, 원격 읽기 전용 계정과 허용 테이블을 입력합니다.
4. 원격 계정은 필요한 테이블의 SELECT만 허용하세요. 관리자·DDL·쓰기 권한은 연결 진단에서 거부될 수 있습니다.
5. 연결을 켜고 **연결 진단 · 메타데이터 갱신**을 실행합니다. 이 단계에서는 행 데이터가 아니라 컬럼 정보를 읽습니다.

PostgreSQL, MySQL, MariaDB, SQL Server, Oracle용 연결 어댑터를 제공합니다. PostgreSQL에서는 실제 읽기 전용 계정·트랜잭션·권한 회수와 브라우저 조회를 검증했습니다. 나머지 엔진은 드라이버 및 제한된 쿼리 생성기 검증과 별개로, 운영할 DB 제품·버전·인증 방식에서 연결 수용 시험이 필요합니다. 임의 SQL 호환성을 보장하는 기능이 아닙니다.

허용 테이블은 줄마다 `schema.table` 형식으로 최대 100개입니다. MySQL/MariaDB는 schema에 데이터베이스 이름, Oracle은 실제 저장된 소유자·테이블 대소문자를 사용합니다. 식별자는 영문·숫자·밑줄 중심의 제한된 형식을 사용합니다. 특수 식별자, 복잡한 자료형은 필요한 스칼라 컬럼만 갖는 읽기 전용 뷰로 제공하는 것을 권장합니다.

## 네트워크와 보안

TLS 인증서 검증은 기본으로 적용합니다. 사내 CA가 있으면 CA PEM을 입력합니다. 비암호화 연결 및 인증서 검증 생략은 관리자 확인이 필요한 명시적 옵션이며, 운영에서 검증 생략은 권장하지 않습니다. 호스트 허용 목록과 연결 시점의 DNS·IP 검사를 함께 적용하고 클라우드 메타데이터 및 링크 로컬 목적지는 차단합니다.

자격 증명은 ENCRYPTION_KEY로 암호화하여 DB에 저장합니다. 조회 화면은 설정 여부만 보여주며, 수정할 때 빈 비밀은 기존 값을 유지합니다. 새 값을 입력하면 교체됩니다. 소스의 워크스페이스·공간·엔진·서비스 계정은 생성 뒤 임의 이동하지 않습니다. 새 경계가 필요하면 새 연결을 만드세요.

사용자의 현재 워크스페이스·공간 접근 권한, 서비스 계정의 현재 권한, API 키의 `database:read` 범위를 함께 검사합니다. 원격 DB의 행별 권한이 madi 사용자별로 자동 매핑되지는 않습니다. 원격 계정으로 볼 수 있는 데이터가 대상 공간 사용자에게 제공된다는 점을 확인하고 공간과 DB 뷰를 구성하세요.

PostgreSQL/MySQL/MariaDB는 읽기 전용 트랜잭션을 사용하고 Oracle은 트랜잭션 첫 명령으로 READ ONLY를 적용합니다. SQL Server는 동일한 읽기 전용 트랜잭션 옵션 대신 실제 대상 객체 권한 검사와 폐쇄형 SELECT 생성기를 함께 적용합니다. 모든 엔진에서 별도의 최소 권한 원격 계정이 필요합니다.

## 테이블 설명과 저장 쿼리

테이블 화면에서 설명과 관련 문서를 연결합니다. 관련 문서 링크는 열람자의 현재 문서 권한으로 다시 걸러집니다. `/app/enterprise`에서 문서·원격 자료·외부 테이블·저장 쿼리를 함께 찾고, `/app/entities`에서 사람·팀·기술·시스템 등의 엔터티를 등록할 수 있습니다. 문서의 실제 `[[엔터티 이름]]` 참조와 테이블의 관련 문서 연결이 엔터티 프로필에 모입니다. 코드 예시 안의 위키 링크는 참조로 세지 않습니다. 문서 연결 탐색은 현재 접근 가능한 최근 2,000개 문서를 대상으로 합니다.

관리자가 등록하는 조회 계획은 단일 테이블, 선택 컬럼, 매개변수 필터, 정렬, 행 제한으로 구성합니다. 자유 SQL, JOIN, 임의 함수, 하위쿼리, 프로시저 및 쓰기 문장은 지원하지 않습니다. 일반 조회는 최대 2,000행, 결과 8MB, 셀 64KB로 제한하고 한도를 초과하면 잘림 또는 명시적 오류를 표시합니다. BLOB/LOB·바이너리·JSON/XML·배열 등은 메타데이터 탐색 대상으로만 제공합니다.

조회 조건값은 DB 드라이버의 바인딩 매개변수로 전달합니다. 실행 직전과 결과 반환 전에 현재 사용자·서비스 계정·키·소스 설정·쿼리 상태를 다시 확인합니다. 조회 중 권한이나 설정이 바뀌면 결과를 반환하지 않습니다.

## AI 조회 계획 생성

1. 관리자 AI 설정 또는 워크스페이스 AI 설정에 스트리밍을 지원하는 OpenAI 호환 API를 구성합니다.
2. 데이터 소스 편집에서 **AI 조회 계획 제안 허용**을 켭니다. 기본은 꺼짐입니다.
3. 검사한 테이블을 열고 **AI 데이터 조회 질문**에 질문을 입력합니다.
4. 스트리밍으로 생성되는 계획과 설명, 대상 테이블·컬럼·조건·행 제한, 메타데이터 출처를 확인합니다.
5. 확인란에 `CREATE QUERY`를 입력합니다. 승인 정책이 꺼져 있으면 저장 조회로 등록하고, 켜져 있으면 공통 검토 요청을 만듭니다. [승인 가이드](approval-guide.md)를 참고하세요.
6. 등록된 조회의 **조회 실행**을 눌러야 실제 원격 데이터를 읽습니다. 계획 생성·확인·승인 자체는 원격 조회를 실행하지 않습니다.

모델에는 선택한 테이블의 컬럼 메타데이터와 질문만 전송하고 원격 행 데이터나 접속 비밀은 보내지 않습니다. 이름과 자료형도 기밀일 수 있으므로 AI 공급자의 망 위치와 데이터 처리 정책을 확인하세요. 모델 응답은 엄격한 JSON 및 허용 목록 검사 후 제안으로 저장합니다. 임의 SQL이 섞이거나 스트림이 완료되지 않으면 저장하지 않습니다.

AI의 서비스 최대 토큰 설정은 1~262,144 범위를 유지합니다. Text2SQL은 64KB의 구조화된 계획만 받으므로 이 작업의 출력은 최대 16,384토큰으로 추가 제한합니다. 이는 일반 문서 AI의 출력 설정을 변경하지 않습니다.

확인·승인한 AI 계획은 수정할 수 없습니다. 변경은 새 제안으로 진행합니다. 원본 요청자나 서비스 계정 권한 회수, 테이블 메타데이터·데이터 소스 설정 변경, 승인 정책 변경은 이전 실행 허가를 무효화할 수 있습니다. 자기 승인은 허용하지 않습니다. 복원 뒤에는 소스와 AI 조회가 중지되고 비문서 승인도 무효화되므로 재확인이 필요합니다.

## API 경로

REST 기본 경로는 `/api/v1`입니다. 설정 변경·AI 제안 생성·확인은 권한 있는 사람의 웹 세션 전용입니다. API 키는 허용 범위 안에서 목록·메타데이터와 이미 등록된 조회 실행을 사용할 수 있습니다.

| 메서드 | 경로 | 동작 |
| --- | --- | --- |
| GET, POST | `/data-sources` | 목록 · 소스 등록 |
| GET, PUT | `/data-sources/{id}` | 테이블과 쿼리 · 소스 수정 |
| POST | `/data-sources/{id}/inspect` | 읽기 전용 권한과 메타데이터 검사 |
| PUT | `/data-sources/{id}/table` | 설명 · 관련 문서 연결 |
| POST | `/data-sources/{id}/queries` | 일반 조회 등록 |
| PUT | `/data-sources/{id}/queries/{query}` | 일반 조회 수정 |
| POST | `/data-sources/{id}/queries/{query}/execute` | 현재 권한으로 읽기 전용 조회 |
| GET, POST | `/data-sources/{id}/ai/proposals` | 내 제안 이력 · 스트리밍 생성 |
| POST | `/data-sources/{id}/ai/proposals/{proposal}/confirm` | 버전과 `CREATE QUERY` 확인 |
| GET | `/enterprise/search?workspace_id=UUID&q=검색어` | 권한별 통합 소스 탐색 |
| GET, POST | `/enterprise/entities` | 엔터티 목록 · 등록 |
| GET, PUT | `/enterprise/entities/{id}` | 프로필 · 엔터티 종류 수정 |

AI 생성 SSE에는 `sources`, `text`, `proposal_id`와 `stored`, `done` 또는 `error` 이벤트가 담깁니다. 네트워크 청크가 아닌 완전한 SSE 이벤트 단위로 처리하세요. 공통 승인 화면은 `/app/approvals?request=승인_UUID`입니다.
