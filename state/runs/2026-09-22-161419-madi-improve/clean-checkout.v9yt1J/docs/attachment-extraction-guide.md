# 첨부 본문·위치·선택 OCR

madi는 첨부 원본과 검색·인용용 추출 결과를 분리합니다. 추출은 기본으로 꺼져 있으며, 관리자가 켠 뒤 문서 쓰기 권한이 있는 사용자가 파일별로 실행합니다. 원본 파일을 바꾸거나 업로드된 모든 첨부를 자동 분석하지 않습니다.

## 지원 형식

| 형식 | 추출·위치 | 주의점 |
| --- | --- | --- |
| PDF | 페이지, 텍스트 줄, 원본 좌표 | 암호화 PDF는 지원하지 않습니다. 읽기 순서·폰트 매핑이 잘못된 PDF는 원본과 확인해야 합니다. |
| 스캔 PDF | 사용자가 선택한 빈 페이지의 영어·한국어 OCR, 좌표 | 먼저 일반 추출 후 텍스트 없는 페이지를 선택합니다. OCR 오인식·누락 가능성이 있으며 자동 사실 검증이 아닙니다. |
| DOCX | 문단, 표·행·열 | 본문/표 텍스트 중심입니다. 원래 페이지 나눔·도형·수식의 완전한 렌더링을 보장하지 않습니다. |
| PPTX | 슬라이드, 문단 | 슬라이드 순서를 따릅니다. 애니메이션·미디어·복잡한 도형은 재현하지 않습니다. |
| XLSX | 시트·셀, 저장된 값 | 수식은 실행하지 않고 파일에 저장된 캐시 값을 사용합니다. 외부 연결·매크로는 실행하지 않습니다. |
| UTF-8 TXT·Markdown·CSV | 텍스트 구간 | CSV를 데이터베이스로 바꾸려면 별도의 [가져오기](transfer-guide.md)를 사용하세요. |

구형 DOC·PPT·XLS, 비 UTF-8 텍스트, 비밀번호로 암호화된 Office, 임의 바이너리의 본문 추출은 지원하지 않습니다. 압축 해제·XML 구조·개별 파일 한도를 넘는 자료는 일부 결과를 게시하지 않고 실패로 보고합니다. 바이너리 원본의 개인정보를 완벽하게 탐지한다는 의미도 아닙니다.

## 관리자 설정

관리자 → **첨부 본문 추출**(`/admin/attachment-extraction`)에서 추출 사용 여부, 선택 OCR, 파일·페이지·텍스트·구간·시간 한도를 설정합니다. 새 필수 환경변수나 별도 서비스는 필요하지 않습니다.

최대 한도는 원본 50MiB, PDF 500페이지, 추출 본문 8MiB, 구간 20,000개입니다. 개별 구간은 16KiB, 선택 OCR은 한 번에 최대 20페이지입니다. Office 압축 해제는 100MiB, XML은 32MiB·200만 토큰·깊이 128로 제한됩니다. 관리자는 운영 한도를 더 낮출 수 있으며 전체 작업 시간은 30~600초입니다. 대형 자료가 이 범위 안에 있더라도 변환기·시간·메모리 한도 때문에 실패할 수 있습니다.

정책 수정은 revision 비교 후 저장됩니다. 정책이 바뀌면 예전 추출 결과를 현재 검색·인용에 사용하지 않으며 다시 추출해야 합니다. 기존 결과를 켜기만 해 무심코 재사용하지 않도록 한 동작입니다.

## 파일별 실행과 검토

1. 문서의 첨부에서 **본문·위치 보기**를 엽니다.
2. 파일명·크기·부모 문서 버전과 추출 범위를 확인하고 실행합니다. 접수는 완료가 아니며 진행 상태가 갱신됩니다.
3. 추출 완료 후 구간을 선택합니다. PDF는 원본 페이지와 위치를, Office는 슬라이드·시트·셀·문단 등의 위치를 보여줍니다.
4. PDF에 빈 페이지가 있으면 필요한 페이지만 선택하고 **OCR** 실행을 확인합니다. 이미 텍스트가 있는 페이지에는 OCR을 덧씌우지 않습니다.
5. 새로고침해도 첨부·추출·선택 구간 URL을 유지합니다. 부모 문서로 돌아가 원본과 대조할 수 있습니다.

개인별 대기 작업은 최대 5개, 한 첨부의 동시 추출은 1개입니다. 원래 실행자는 진행 작업을 취소할 수 있습니다. 작업은 PostgreSQL에 보관되며 재시도하더라도 최종 결과·활성 포인터는 같은 트랜잭션에서 한 번만 교체됩니다. 실행자의 계정·원래 세션/키·IP 조건·권한·정책·원본 해시를 시작, 진행, 저장 단계에 다시 확인합니다. 로그아웃·키 폐기·권한 변경 등으로 작업이 취소될 수 있습니다.

## 검색과 인용

활성 결과만 통합 검색의 **파일** 결과에 들어갑니다. 제목뿐 아니라 추출 본문을 검색하며 조직 용어 사전 확장도 적용됩니다. 결과는 현재 부모 문서·공간 권한을 따릅니다. 오래된 원본 해시, 삭제 첨부, 비활성 정책, 대체된 추출 결과는 현재 검색에서 제외됩니다.

인용은 부모 문서 ID/버전과 함께 첨부 ID·SHA-256, 추출 ID/revision, 구간 ID/hash, 위치를 보관합니다. 인용의 `start_byte`/`end_byte`는 **해당 첨부 구간의 UTF-8 텍스트** 기준이며 부모 Markdown 오프셋이 아닙니다. 원본 PDF 위치로 이동하거나 Office 위치를 확인할 수 있습니다.

추출 시 정보보호 정책의 검사·마스킹을 적용한 결과만 검색에 저장합니다. 이는 바이너리 원본 파일의 자동 마스킹이 아닙니다. 원본 다운로드·열람 권한 및 기존 정보보호 정책을 함께 관리하세요.

## AI와 근거 패키지

첨부 구간에서 AI에 보낼 부분을 직접 선택하고 공급자와 정확한 원문을 확인합니다. 한 번의 선택은 최대 8KiB입니다. **선택 텍스트와 질문만** 전송하며 파일 바이너리, 부모 문서 본문, 이웃 구간, 이전 대화나 RAG를 자동으로 추가하지 않습니다. 기존 문서 색인 동의가 첨부 본문 전송 동의를 대신하지 않습니다.

읽기 전용 원문에서 드래그한 뒤 **선택 구간 사용**을 누르거나 **전송 시작·끝 글자**를 지정합니다. 일부 브라우저에서는 읽기 전용 입력의 방향키 선택을 지원하지 않으므로 숫자 입력으로도 범위를 정할 수 있습니다. 전송 전 **실제 전송할 텍스트**를 확인하세요. 화면의 글자 범위를 서버의 UTF-8 좌표로 바꿀 때 이모지와 CRLF/CR 줄바꿈을 원본 좌표로 매핑합니다.

AI 응답은 스트리밍이 기본이고 관리자 최대 출력 토큰 설정(최대 262,144)을 따릅니다. 공급자가 지원하는 한도를 별도로 확인해야 합니다. 공급자·현재 권한·첨부 원본·추출 정책이 바뀌면 결과를 철회하고 다시 확인하도록 합니다. AI 답변은 자동으로 문서에 적용하지 않습니다.

**이 구간을 AI 컨텍스트 패키지에서 검토** 링크는 `/app/knowledge-packages?extraction=…&fragment=…`로 이동합니다. 여기에서도 구간 확인·명시 선택이 필요합니다. 현재 인용/새 전송은 활성 결과와 해시가 일치해야 합니다. 보관한 과거 근거는 현재 첨부와 부모 문서 ACL을 다시 확인한 뒤 당시 인용을 보여주며, 원본 변경은 최신성 경고로 구분합니다. 과거 근거 보관이 새 모델 전송이나 현재 결과 사용을 허용하지 않습니다.

## 폐쇄망 실행과 격리

Linux 서비스 이미지에 Poppler 25.12.0-r1, Tesseract 5.5.2-r0 및 영어·한국어 모델, PDF.js 뷰어의 worker·CMap·폰트·WASM을 함께 넣습니다. 실행 시 도구나 모델을 다운로드하지 않습니다. 별도 OCR API는 필요하지 않습니다.

PDF/OCR은 서비스와 분리된 고정 명령 프로세스로 실행됩니다. 사용자 파일명·설정에서 임의 명령이나 옵션을 구성하지 않습니다. 원래 DSN·관리자 암호·ENCRYPTION_KEY·프록시·클라우드 환경변수는 자식 프로세스에 전달하지 않습니다. 전용 0700 임시 디렉터리, 파일 접근 허용 목록, 네트워크 차단, 시스템 호출 제한, CPU 45초/주소 공간 2GiB/출력 파일 32MiB/열린 파일 64개 제한을 적용합니다. 실행 UID의 프로세스·스레드 한도는 256이고 Compose의 컨테이너 PID 한도는 512입니다. 각 도구 호출은 최대 60초이고 전체 작업 제한이 추가로 적용됩니다.

**Landlock ABI 3 이상과 seccomp를 지원하는 Linux 커널이 필요합니다.** 도커 실행만으로 이 커널 조건이 충족되는 것은 아닙니다. 격리를 적용할 수 없으면 PDF/OCR을 실패 처리하며 약한 격리로 자동 전환하지 않습니다. 컨테이너 전체 CPU/RAM/프로세스 제한도 별도로 유지하세요. 뷰어는 로컬 PDF.js로 렌더링하며 PDF 스크립트·폼·외부 자원 실행을 활성화하지 않습니다.

PDF.js의 로컬 이미지 코덱이 사용하는 WebAssembly는 번들에 실제 존재하는 `assets/pdf.worker.min-*.mjs` 응답에만 CSP `wasm-unsafe-eval`로 허용합니다. 일반 페이지·다른 worker·플러그인에는 추가하지 않으며 JavaScript `eval`/`new Function`이나 외부 스크립트를 허용하지 않습니다. WASM·CMap·폰트 URL은 같은 서버로 고정합니다. 이 구분은 [PDF.js 6.3.289의 로컬 WASM 설정](https://github.com/mozilla/pdf.js/blob/v6.3.289/src/display/api.js)과 [JPX 디코더 구현](https://github.com/mozilla/pdf.js/blob/v6.3.289/src/core/jpx.js)에 맞춘 것입니다.

대응 소스는 같은 이미지의 `/usr/share/madi/sources`에 있습니다. 실제 설치 APK 69개의 버전/원본 commit, 52개 origin의 APKBUILD·패치·SHA-512 검증 upstream 소스, Tesseract 원본·레시피·모델 라이선스, SHA-256 목록을 포함합니다. GPL/LGPL/MPL 19개 origin뿐 아니라 MIT/BSD 등 나머지 구성 요소의 저작권·라이선스·NOTICE도 원본 압축 파일 안에 보존합니다. 실제 영어·한국어 모델 파일은 `/usr/share/tessdata`에 있습니다. 별도 upstream이 없는 메타패키지·공개키는 원래 레시피/자료를 보존합니다. 개별 구성 요소에는 원래 라이선스가 적용됩니다. 이 소스는 코드 수정·재빌드를 위한 자료이며 런타임에 컴파일하지 않습니다.

PDF.js가 별도로 포함하는 Liberation Sans 1.07.4는 GPLv2와 폰트 예외를 적용합니다. APK 소스와 별개로 `pdfjs-liberation/`에 공식 SFD 소스·Makefile·FontForge 스크립트·원본 라이선스·실제 네 폰트·고정 SHA-256과 `REBUILD.txt`를 보존합니다. 역사적 빌드와 바이트 단위 재현성을 주장하지 않습니다. 폰트는 [PDF.js의 glyph 인덱스 의존성](https://github.com/mozilla/pdf.js/blob/v6.3.289/external/standard_fonts/README.md) 때문에 임의로 2.x 폰트로 바꾸지 않습니다. 사용하지 않는 PDF 스크립팅용 QuickJS 자산은 배포하지 않습니다.

## 백업·복원·정리

백업은 원본 첨부와 정책·작업 메타데이터를 보관합니다. 검색용 추출 구간과 활성 포인터는 재생성 가능한 파생 자료라 백업 복원 뒤 삭제합니다. 복원은 추출/OCR을 끄고 모든 기존 실행을 `obsolete`로 바꾸며 세션/키 결합을 제거합니다. 관리자가 재설정하고 사용자가 다시 실행해야 합니다.

취소·실패·대체된 결과의 텍스트는 24시간 이후 제한된 배치로 정리됩니다. 실행 이력은 남습니다. 임시 디렉터리는 성공/실패 후 정리하며 재시작 후에도 저장된 전용 경로와 현재 작업 리스를 확인해 정리합니다. 원본 첨부는 이 정리 작업에서 삭제하지 않습니다.

## 확인한 범위

실제 PostgreSQL 시험에서 활성 결과 교체, 개인정보 마스킹, 원본 바이트 보존, 세션 만료·정책 잠금 경합, 현재 ACL·해시 변경, 조직 용어 검색, UTF-8 범위 인용과 별도 AI 동의를 확인했습니다. 실제 브라우저에서 텍스트/DOCX 작업, 검색, PDF 원본 렌더링, AI 스트리밍·인용, 새로고침과 390px 화면을 확인했습니다. 별도 Linux 컨테이너에서는 실제 2페이지 PDF의 원본 텍스트와 선택 스캔 페이지의 영어·한국어 OCR을 검증했습니다.

첨부→AI→과거 근거 보관→AI 컨텍스트 패키지의 별도 교차 시험은 PostgreSQL과 실제 Chromium 화면에서 통과했습니다(마지막 14.40초). 한글·이모지를 포함한 선택 93바이트가 18~111바이트 좌표와 같은 SHA-256으로 보관·필수 패키지·실제 다운로드 JSON에 유지됐습니다. 부모 문서와 선택하지 않은 앞뒤 문장은 전송하지 않았고, 로컬 토큰 추정은 모델을 호출하지 않았습니다. 시험용 로컬 SSE 공급자로 진행 응답을 보낸 뒤 정책을 끄자 임시 답변이 철회되고 공급자 연결이 취소됐습니다. 과거 인용은 남지만 새 패키지 전달은 409로 차단됐으며, 재추출·현재 부모 권한 회수·390px 화면도 확인했습니다. 이는 실제 외부 LLM의 품질 검증과는 다릅니다.

삭제 경계는 **격리 시험 데이터의 지정 첨부 ID를 DB에서 제거**하여 보관 근거와 패키지가 조회되지 않는지 검사했습니다. 이것은 장애·삭제 후 권한 검증 시험이며, 제품에 개별 첨부 삭제 API나 버튼이 있다는 뜻은 아닙니다. 원본 첨부 삭제와 개인 근거·패키지 사본 삭제를 구분하세요.

별도 Chromium 격리 시험에서는 전용 PDF worker에서만 최소 WASM 모듈이 컴파일되고 일반 화면·다른 worker에서는 거부되는지 확인했습니다. 전용 worker에서도 동적 JavaScript 생성과 외부 fetch가 거부되며 플러그인 CSP는 그대로입니다. 이는 CSP 경계 검증이며 모든 JPX/JBIG2 파일의 렌더링 호환성을 검증했다는 뜻은 아닙니다.

이는 모든 Office/PDF 생성 프로그램·폰트·스캔 품질의 완전 호환성 보증이 아닙니다. 검색·OCR 결과를 사용하기 전에 원본 위치를 확인하세요.
