**로그인의 두 가지 500이 같은 code로 반대의 지시를 주고 있었습니다.** `POST /api/v1/auth/login`이 500으로 답하는 경우는 둘입니다. 하나는 이쪽이 시도를 **끝내지 못한** 것입니다 — 저장소나 디렉터리가 답하지 않았고, 계정에도 인가 요청에도 아무것도 기록되지 않았으므로 장애가 걷히면 **같은 폼**이 출구입니다. 다른 하나는 로그인이 **끝난** 경우입니다 — 비밀번호가 통과해 세션이 만들어지고 쿠키까지 브라우저에 들어갔으며 감사 트레일에 `LOGIN_SUCCESS result=PARTIAL`이 남았는데, 인가 코드만 쓰지 못한 것입니다. 그 직전 줄에서 인가 요청을 소진했으므로 이 폼은 **재시도가 성공할 수 없는 유일한 자리**이고(같은 자격증명으로 다시 제출하면 핸들러 첫 조회에서 `400 expired_request`를 만납니다), 출구는 RP입니다 — 거기서 다시 시작하면 방금 만든 세션이 그대로 쓰여 비밀번호를 다시 묻지 않습니다. 둘 다 `internal_error`였기 때문에 화면은 붉은 줄 한 줄로 두 반대의 지시 중 어느 쪽인지 말할 수 없었습니다.

### 수정

- **코드 발급 실패는 이제 `500 authorization_code_failed`로 답합니다.** 상태 코드·문구·감사 이벤트·카운터는 그대로이고 code만 다릅니다. 이 경로의 다른 500은 전과 같이 `internal_error`입니다 — 그쪽은 정말로 "이 화면에서 다시 시도"가 맞는 답이기 때문입니다.
- **로그인 화면이 세 답에 「연결한 서비스로 돌아가 다시 시작하세요」를 띄우고 폼을 잠급니다.** `authorization_code_failed`와, 제출한 뒤에야 요청이 없어진 것을 알게 되는 `409 request_already_used`·`400 expired_request`입니다 — 뒤의 둘은 "이미 처리됐다"고만 하고 어디로 갈지 말하지 않았는데, challenge의 404는 같은 사실에 이미 RP로 돌려보내고 있었습니다. 폼을 잠그는 이유는 challenge를 읽지 못했을 때와 같습니다: 그 request token으로는 여기서 무엇을 입력해도 이어지지 않습니다. `authorization_code_failed`는 방금 로그인한 세션이 그대로 쓰인다는 것과 이 화면에서 다시 로그인하지 말라는 것을 함께 말하고 **Trace ID를 보입니다** — 서버 로그의 `authorization code could not be created after a successful login`과 대조하는 값입니다.
- **평범한 `500 internal_error`는 달라지지 않습니다.** 붉은 줄과 폼이 그대로이고, 잠금 경고를 세지 않는 것도 전과 같습니다.
- OpenAPI Error 스키마의 "분기할 만한 code" 목록에 `authorization_code_failed`와 `request_already_used`를 더했습니다.
- `docs/operations.md`의 «로그인 화면이 로그인 요청을 읽지 못할 때»에 login POST 답 넷의 표(뜻과 사용자가 할 일)를 적고, 계정 잠금 절의 "500은 아무것도 기록되지 않았다"에 이 예외를 적었습니다. 사용자 가이드 「막혔을 때」 표에 두 행을 더했습니다.

### 확인

- 기존 연동 테스트 `TestIntegrationALoginThatCannotMintItsCodeIsStillRecorded`에 code 단언과, 폼에서 다시 제출하면 만나는 답(`400 expired_request`) 단언을 더했고 **수정 전 핸들러에서 code 단언이 실제로 실패하는 것을 확인**했습니다(`error = internal_error`). 조사 초기에 재제출의 답을 409로 짐작했다가 이 테스트가 400임을 잡아내 주석과 단언을 고쳤습니다.
- 페이지 테스트 넷 — `authorization_code_failed`에 안내·trace·폼 잠김·잠금 경고 없음, 409와 400 각각에 안내·폼 잠김, 평범한 500에 안내 없음·폼 유지 — 을 더했고 **수정 전 페이지에서 새 테스트 둘이 실제로 실패하는 것을 확인**했습니다.

### Upgrade notes

달라지는 곳은 둘입니다: 로그인 성공 뒤 인가 코드 발급에 실패한 500의 `code`가 `internal_error`에서 `authorization_code_failed`로 바뀌고(상태·문구·감사·지표는 그대로), 로그인 화면이 그 답과 `409 request_already_used`·`400 expired_request`에 붉은 줄 대신 **노란 안내와 다음에 할 일**을 보이며 폼을 잠급니다. 로그인 API를 직접 호출하며 `code == "internal_error"`로 분기하는 클라이언트가 있다면 그 한 경우가 새 code로 오는 것만 확인하시면 됩니다 — 상태 코드 500은 그대로입니다. 저장되는 데이터도 그대로이고 **마이그레이션도 설정 변경도 없습니다.** 지원 창구에는 「로그인은 되었지만 인가 코드를 생성하지 못했습니다」를 본 사용자를 **RP로 돌려보내고**(이 화면에서 재시도하지 않게), 함께 보이는 `trace:` 값을 받아 두라고 알리시면 됩니다(`docs/operations.md`). 되돌릴 때 이전 이미지도 그대로 동작합니다.
