- 요약: `POST /api/v1/auth/login`의 500은 두 가지다. `writeLoginError`의 500은 이쪽이 시도를 끝내지 못한 것(저장소·디렉터리 장애)이라 요청은 소진되지 않았고 장애가 걷히면 **같은 폼**이 출구다. 다른 하나는 로그인이 **끝난** 경우다 — 비밀번호가 통과해 세션과 쿠키가 브라우저에 들어갔고 트레일에 `LOGIN_SUCCESS result=PARTIAL`이 남았으며 인가 코드만 못 썼다. 그 직전 줄에서 인가 요청을 소진했으므로 폼은 재시도가 성공할 수 없는 유일한 자리이고(같은 자격증명으로 다시 제출하면 핸들러 첫 조회에서 400 `expired_request`를 만난다 — 조사 초기에 409로 짐작했다가 연동 테스트가 400임을 잡아내 주석과 단언을 고쳤다) 출구는 RP다 — 거기서 다시 시작하면 방금 만든 세션이 그대로 쓰여 비밀번호를 다시 묻지 않는다. 둘 다 `internal_error`라 화면은 붉은 줄 한 줄로 반대의 두 지시 중 어느 쪽인지 말할 수 없었다. 백엔드는 두 번째의 code만 `authorization_code_failed`로 바꿨다(상태·문구·감사·카운터 그대로 — 미병합 브랜치 9ba95ab가 만지는 줄과 겹치지 않는다). 화면은 그 답과, 제출 뒤에야 요청이 없어진 것을 알게 되는 409 `request_already_used`·400 `expired_request`(둘 다 "이미 처리됐다"고만 하고 어디로 갈지 말하지 않았다 — challenge의 404는 같은 사실에 이미 RP로 돌려보낸다)에 노란 알림으로 「연결한 서비스로 돌아가 다시 시작하세요」를 띄우고 폼을 잠근다(challenge 실패가 잠그는 것과 같은 이유 — 그 request token으로는 여기서 무엇을 입력해도 이어지지 않는다); 500은 Trace ID를 함께 보인다. 평범한 `internal_error`는 붉은 줄과 폼을 그대로 유지한다. OpenAPI Error 스키마의 "분기할 만한 code" 목록에 두 code를 더했다. 검증: 기존 연동 테스트 `TestIntegrationALoginThatCannotMintItsCodeIsStillRecorded`에 code 단언과 폼 재제출이 만나는 답(400 `expired_request`) 단언을 더했고 **수정 전 핸들러에서 code 단언이 실제로 실패**함을 확인했다(`error = internal_error`); 페이지 테스트 넷(`authorization_code_failed` → 안내·trace·폼 잠김·잠금 경고 없음, 409/400 각각 → 안내·폼 잠김, 평범한 500 → 안내 없음·폼 유지)을 더했고 **수정 전 페이지에서 새 테스트 둘이 실제로 실패**함을 확인했다. `make lint` 통과(golangci-lint 0 issues, govulncheck 0, eslint --max-warnings 0), `make test` 전체 통과(exit 0) — `go test -race ./...` 13개 패키지 ok(httpserver 120s / store 86s), 연동 테스트 SKIP 0건(기존 컨테이너 셋 재사용, CA는 `/tmp/resso-test-certs-0916`이 LDAPS와 일치함을 `openssl s_client`로 확인), `go vet`, `npm run test`(29파일/158테스트, 디스크 파일 수와 일치), `npm run build`. 빌드가 만든 `webui/dist/index.html` 변경은 되돌렸다. `docs/operations.md`의 «로그인 화면이 로그인 요청을 읽지 못할 때»에 login POST 답 넷의 표를, 잠금 절의 "500은 아무것도 기록되지 않았다" 문장에 예외를 적었고, `docs/USER_GUIDE.md` 「막혔을 때」 표에 두 행을 더했다(문장만 더했으므로 PDF 재생성·캡처는 하지 않았다 — 이전 회차 관례).
