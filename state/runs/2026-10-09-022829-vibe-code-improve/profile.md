- 자주 깨지는 곳:
  - Markdown 정규식의 \s*가 줄바꿈을 먹고 trim이 들여쓰기를 잃는 문제. LF/CRLF와 부분 편집 계약을 보존한다.
  - tickCriteria CRLF 보존은 main 반영됨. stampAgeHours 명시적 오프셋 처리·KST 예산 알림도 반영됨.
  - gitChangedFiles NUL 수정, readRecentAudit/readCommandHistory 날짜 창, 감사 exitCode 집계는 현 main에 없음. 과거 제출 접근 재선정 금지, 원격 판정 미확인.
  - 파일명/검출 원문을 감사 details에 새로 넣지 않는다. 실제 fs/Git 및 production 배선 검증을 우선하고 공유 스텁을 늘려 결함을 가리지 않는다.
- 검증 함정:
  - CI는 이제 ci.yml / release-vsix.yml / ui-snapshots.yml 세 개. 'ci.yml만 존재'라는 이전 프로필은 틀림.
  - ci.yml: Ubuntu check → Windows 자산 다운로드·패키징·검증·실제 Extension Host·SHA256·업로드. 자산 있는 release 전무(exit2)만 경고 후 skip; 기타 다운로드 실패는 실패 처리.
  - release-vsix.yml: published release 또는 수동 태그 입력에서 패키징/첨부. 태그 push 자체로 release를 만드는 것과 다르다.
  - build.mjs는 런타임 자산 부족을 경고만 한다. build 성공과 VSIX/VS Code 실행 성공을 구분한다.
  - 원격 CI·PR 상태, Windows 패키징, UI 알림/실제 설치는 이번 미확인. 과거 결제 실패 원인을 현재 원격 실패로 단정하지 않는다.
  - GitHub read 도구는 이번 노출돼 있으나 인증/호출 성공은 미확인. '접근 도구 없음'이라고 단정하지 않는다.
  - Node 런타임을 프로젝트 node_modules에 설치하면 npm ci가 지울 수 있다. /tmp/node2019/bin/node는 이번 v20.19.2로 확인.
  - 실제 작업 저장소에서 stash 금지. 임시 Git 테스트의 상위 repo 탐색·전역 설정·index 불변을 주의한다.
  - 새 export 없는 실제 반환값 AssertionError가 재현 증거다. 심볼 누락 오류를 결함 증거로 삼지 않는다.
