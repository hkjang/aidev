# Ptium 1.69.22

## 따옴표 하나 때문에 CSV 파일 전체를 돌려보냈습니다

CSV 를 엄격하게 읽으면, 따옴표로 감싸지 않은 칸 안에 있는 따옴표는 문법
오류입니다. 그런데 그 따옴표는 대개 문법이 아니라 **인치 기호**입니다.
`15" 모니터`, `21"`, `27" 커브드` — 가격표와 자산 대장에 흔히 있는 표기이고,
쓴 사람은 무엇도 인용하려 한 적이 없습니다.

한 줄에 그런 글자가 하나만 있어도 `ReadAll` 은 아무것도 돌려주지 않기
때문에, **500줄짜리 파일이 통째로 거부**되었습니다. 게다가 그때 나온 말은
한국어 문장 안에 영어 파서 메시지가 박힌 것이어서, 읽는 사람이 할 수 있는
일을 알려 주지 못했습니다.

```
파일:   제품,가격 / 15" 모니터,120000 / 27" 모니터,300000
이전:   이 파일을 표로 읽지 못했습니다: parse error on line 2, column 3:
        bare " in non-quoted-field
지금:   15" 모니터 · 27" 모니터 — 차트 한 장
```

이제 **엄격하게 먼저 읽고**, 그때만 따옴표를 글자 그대로 보는 방식으로 다시
읽습니다. 제대로 따옴표를 쓴 파일 — 칸 안에 쉼표가 있어 감싼 칸, `""` 로 적은
따옴표 — 은 전과 똑같이 엄격하게 읽히고 경고도 붙지 않습니다. 달라지는 것은
전에는 거부되던 파일뿐입니다.

봐준 자리는 말해 줍니다. `가격.csv의 3번째 줄에 짝이 없는 따옴표가 있어 글자
그대로 읽었습니다` — 정말로 감싸려던 칸이었다면 어디를 고쳐야 하는지 바로
찾을 수 있습니다. 닫히지 않은 따옴표처럼 뒤를 통째로 삼키는 경우에도, 파일을
돌려보내는 대신 읽고 **따옴표를 연 줄**을 짚어 줍니다. `.csv` 와 `.tsv` 가
같습니다.

## 지키는 장치

`internal/docs/csvquotes_test.go` 가 인치 기호가 든 가격표, 경고에 파일 이름과
줄 번호가 들어가는지, 닫히지 않은 따옴표, 탭으로 나눈 같은 파일, 그리고 제대로
따옴표를 쓴 파일이 **경고 없이** 예전과 똑같이 읽히는지를 각각 봅니다. 봐주고
읽은 뒤에도 나머지 줄이 순서와 칸 수 그대로인지는 따로 확인합니다.
