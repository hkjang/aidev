- 요약: `web/package.json:10` 의 `"test": "vitest run"` 만 `.bin` 심링크와 기설치를 전제해서 `web/node_modules` 가 없는 워크트리에서 `sh: 1: vitest: not found` 로 깨졌다. 저장소 관례대로 `node_modules/vitest/vitest.mjs` 를 직접 부르게 고치고 `scripts/build-ui.sh:6` 과 글자까지 같은 설치 가드를 `pretest` 로 넣었으며, `Makefile:17`·`ci.yml:57` 은 `npm test --silent` 로 바꿔 vitest 호출 문장을 저장소에 한 곳만 남겼다. 가드를 넣자 그 뒤에 숨어 있던 두 번째 실패가 드러났다 — npm 은 lifecycle 스크립트의 PATH 에 **모든 상위 디렉터리**의 `node_modules/.bin` 을 앞에 붙이고, 이 환경의 `/home/hkjang/node_modules/.bin/node` 는 Node 20.19.2 를 가리킨다. Node 20 에는 `worker_threads.markAsUncloneable` 이 없어서(`undefined` 확인) jsdom 30 이 쓰는 undici 8.11.2(`engines: >=22.19.0`)가 로드 중 죽고 vitest 가 테스트를 한 개도 돌리지 못했다. 그래서 인터프리터를 `"${npm_node_execpath:-node}"` 로 고정했다(npm 을 돌리고 있는 그 Node — PATH 로 가로챌 수 없다). 검증: 수용 기준 1 `rm -rf web/node_modules && cd web && npm test --silent` → exit 0, `src/utils/format.test.ts` 3개 + `src/App.test.tsx` 1개 = 4 passed (skip 0), 기준 2 즉시 재실행 2.00s(설치는 ~9s 이므로 가드가 no-op), 기준 3 `git grep` 결과 vitest 호출은 `web/package.json:11` 한 곳뿐, 기준 4 `node node_modules/typescript/bin/tsc -b` exit 0. 추가로 `make lint`(gofmt 빈 출력 + go vet + verify-version 1.0.0 일치)와 `make test` 모두 exit 0. `web/package-lock.json` 은 바뀌지 않았고(`npm ci` 만 사용) 빌드 산출물도 커밋에 없다.
- 실패 재현: 고치기 전 `cd web && npm test --silent` → `sh: 1: vitest: not found` (exit 127; npm 래퍼를 거치면 exit 1). 설치 가드를 넣은 직후의 2차 실패도 재현했다: `Caused by: TypeError: webidl.util.markAsUncloneable is not a function` / `❯ new CacheStorage node_modules/undici/lib/web/cache/cachestorage.js:20:17`, `Test Files no tests / Errors 2 errors`, exit 1. 고친 뒤 `"${npm_node_execpath:-node}"` 를 바레 `node` 로 되돌리면 같은 `markAsUncloneable` 오류가 그대로 다시 났고, 되돌림을 취소하면 다시 통과 — 인과를 양방향으로 확인했다.
- 보류 아이디어: `internal/logbuf` 링 버퍼·`Subscribe()` 해제 경로 테스트 0개 [3/1/S]; `internal/mattermost` 의 남은 경로(FileContent 의 `*[]byte` 우회, `PostList.Ordered()` 가 없는 id 를 조용히 버림, `New()` 의 깨진 CAPEM 거부) [4/1/M]; `ChannelMembers` 가 `per_page` 한 페이지만 받아 멤버를 조용히 잘라냄 — 호출자 의도 먼저 확인 [3/3/M]; `web/package.json` 의 나머지 스크립트(`build`·`dev`·`preview`)는 아직 `.bin` 심링크(`tsc`/`vite`)에 의존 — CI 는 패키지 경로를 쓰므로 안 깨지지만 관례에서 빠져 있다 [2/1/S]; `mattermost.New()` 가 BaseURL 의 query/fragment 를 보존해 요청 URL 이 깨질 수 있음 [2/2/S]
- 과제서: 채택 — 과제서의 근거(`web/package.json:9` 만 `.bin` 의존 + 가드 없음, 나머지 전부 패키지 경로, `release.yml` 은 web 테스트를 부르지 않음)가 현재 코드와 정확히 일치했다. 다만 과제서가 "미확인" 으로 남긴 두 가지를 확인한 결과 한 곳에서 처방을 넘어섰다: `npm ci` 는 이 환경에서 레지스트리에 **닿았고**(191 packages, 9s) `node_modules/vitest/vitest.mjs` 경로도 **맞았으나**, 과제서가 예상하지 못한 npm 의 PATH 오염 때문에 `scripts.test` 를 패키지 경로로만 바꾸면 수용 기준 1을 못 채운다. 기준을 낮추는 대신 인터프리터를 고정해 해결했다(테스트 제외·`--passWithNoTests`·`continue-on-error` 는 쓰지 않았다).
