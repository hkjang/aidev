(6) 거부 분기는 `s.logger.Warn("mcp oauth token refused", code, cause)`가 실제로 호출되어 서명·발급자(go-oidc 문구 "different provider")·만료·nbf·대상·계정 중 무엇이 실패했는지 남는다 — 테스트가 로거를 버퍼로 바꿔 각 원인 문자열을 확인한다. OAuth 토큰은 `/mcp`에서만 받고(JWT 모양이어도 REST는 종전대로 401 `authentication_required`), 꺼져 있으면 메타데이터 404·토큰도 종전과 똑같이 거부되어 새 설치에서 달라지는 것이 없다. 켜기는 Issuer가 비면 저장 시 거부(`mcp_oauth_incomplete`)하고, 가져온 설정으로 그 상태가 되면 조용히 꺼진 채 로그에 이유를 남긴다. Discovery는 issuer별로 캐시(요청 컨텍스트와 분리, 10초 제한 클라이언트)하고 실패는 5초 기억한다. 검증: `gofmt`·`go vet ./...`, docker postgres:16-alpine의 `VISITFLOW_TEST_DSN` 전체 Go 테스트 통과(internal/app 53.5초), `npm ci && npm run lint && npm test(8) && npm run build`, `docker build` 통과. 새 테스트는 통합 5개(기본 꺼짐·메타데이터 두 경로의 맨 JSON+CORS·MCP 401 헤더와 REST 401 무헤더·설정 리소스 우선·키 페이지 정보 / 정식 aud·웹 클라이언트 azp·타 앱 azp 거부 메시지·허용 대상 등록 후 통과·미등록/비활성 거부와 계정 미생성·미바인딩 SSO 계정·로컬 동명 거부·role claim 무시·REST 거부 / 범위 천장·교집합·mcp 없는 토큰 403·키 정책 상한·mcp 없는 천장 저장 거부 / 만료·nbf·타 발급자·타 키 서명·typ=ID·cnf·sub 없음·HS256·none 각각 거부와 로그 원인, 뒤이어 정상 토큰과 키 모두 동작 / Keycloak 불통 시 거부와 실패 기억·메타데이터 계속 제공)와 단위 1개(JWT 모양·메타데이터 URL·교집합 7경우·설정 검증)이며, 가짜 IdP는 `crypto/rsa`로 직접 RS256 서명하고 discovery·JWKS를 서빙해 go.mod를 건드리지 않았다. 변이 3건(대상 검사 제거·거부 로그 제거·빈 교집합 통과+핸들러 검사 제거)에서 각각 해당 테스트가 실제로 실패하는 것을 확인했다. 실제 확인: 릴리즈 Dockerfile로 만든 이미지를 postgres와 가짜 IdP 컨테이너에 붙여 띄우고 curl로 꺼짐 404/401 무헤더 → 켜기 → 메타데이터 200+CORS → 401에 `resource_metadata` → 미등록 subject `account_not_registered` → 등록 후 `tools/list` 200 → azp=claude-mcp 거부 메시지(aud=[account], azp="claude-mcp", 고칠 값) → 허용 대상에 적은 뒤 200 → 기본 천장에서 create_visit "write 범위가 필요합니다" → REST에 토큰 401 → 서버 로그에 원인까지 봤다. 실제 Keycloak/Claude 클라이언트는 이 환경에 없어 하지 못했고, 가이드에 Keycloak 클라이언트·Audience 매퍼·(선택) `read`/`mcp` client scope·짧은 토큰 수명과 introspection 없음의 한계·curl 확인·거부 메시지별 조치 표를 적고 공용 md2pdf로 ADMIN_GUIDE.pdf를 다시 구웠다(27쪽, 16쪽에 새 소절).
