- 요약: 릴리즈 게이트는 `npm test` 의 요약 줄과 종료 코드를 읽는데, 서버가 부팅에 실패하면 `stop()` 이 **이미 끝난** 자식의 `exit` 이벤트를 기다려 영원히 settle 되지 않았다(escalation 타이머가 `.unref()` 라 루프가 비면 뛸 수 없다). 그래서 node 가 unsettled top-level await 로 종료 코드 **13** 을 내고 요약 줄과 `process.exit(1)` 을 건너뛰었다 — 실패가 실패로 보이지 않고 결과 없음으로 보인 경로다. 더해 `waitForHealth` 가 자식의 죽음을 모른 채 120×500ms 예산을 전부 폴링해(실측 56.2초) 원인을 말하지 않는 메시지만 남겼다. `stop()` 이 `exitCode/signalCode` 를 먼저 확인하고 ref 된 타이머를 exit 시 clear 하도록, `waitForHealth(url, supervised)` 가 자식의 죽음을 즉시 서버 stderr 와 함께 보고하도록 고쳤다. `startExtraServer` 의 stderr 는 pipe 만 하고 아무도 읽지 않아(진단 유실 + 파이프 가득 차면 교착) 함께 배수했다. 검증: 새 `tools/harness-selftest.mjs` (`npm run test:harness`) 가 실제 `tools/smoke-test.mjs` 를 실제 `server.js` 에 대해 돌리며 포트를 직접 점유해 부팅을 깨뜨린다 — 대역 없이 프로덕션 배선 그대로다. 56222ms/exit 13/4 FAIL → **558ms/exit 1/4 PASS**. 버그를 되돌려 4건이 다시 FAIL 하는 것까지 확인했다. 릴리즈 게이트 `SMOKE_REQUIRE_BROWSER=1 npm test` 는 이 워크트리에서 **150 passed, 0 failed, 0 skipped (exit 0)** 로 통과했다(`npm install` + `npx playwright install chromium` 수행 후).
- 실패 재현: `FAIL  a smoke run whose server cannot boot exits 1 — expected exit code 1, got 13 (signal null); code 13 means a top-level await never settled` / `FAIL  the harness reports a dead server without waiting out its health budget — took 56222ms; a dead server should be reported within 15000ms` (고치기 전, `0 passed, 4 failed`)
- 보류 아이디어: ① `waitForHealth` 나머지 11개 호출처는 여전히 핸들 없이 호출돼 죽은 서버에 60초를 쓴다 — `superviseServer` 가 이미 있으니 호출처마다 한 토큰씩이면 된다(가치 4) ② 녹화 중복 제거가 `step.value` 만 비교해 `selectOption`(`values`)·`press`(`key`) 를 삼킨다 — 이 워크트리에 chromium 을 깔아 뒀으니 다음 회차 선행 비용 없음(가치 4) ③ 바른 체크아웃에서 `npm install` 을 하라고 말해 주기 — 이제 원인 문자열은 0.5초에 나오므로 남은 건 실행 지시 한 줄뿐(가치 3) ④ `check()` 가 그룹 SKIP 과 검사 SKIP 을 두 줄로 찍어 skipped 집계가 부풀려진다 — 단 HEAD 에 `{ skip: reason }` 반환 경로는 **없다**(정찰의 전제가 틀렸다), 먼저 추가해야 한다(가치 2) ⑤ `recorderLocatorCandidates` 의 따옴표 이스케이프가 백슬래시를 둘 넣어 CSS 선택자가 무효가 된다 — 같은 값을 읽는 `page_inspect` 경로를 함께 봐야 한다(가치 2)
- 과제서: 차선 — 정찰 단계가 실패해 공식 과제서는 없었지만 정찰 노트의 진단 방향(릴리즈 게이트 = `SMOKE_REQUIRE_BROWSER=1 npm test`, 실패 스크립트 = `tools/smoke-test.mjs`, 56초 소모)은 그대로 채택했고, 노트가 놓친 진짜 치명적 원인(`stop()` 의 미settle await → 종료 코드 13 + 요약 줄 소실)을 측정으로 더 찾아 함께 고쳤다. 노트의 환경 기술 중 node 버전은 틀렸다 — v20.19.2 가 아니라 **v22.23.1** 이다.
