- 보류 아이디어: ① **직전 회차의 하네스 수정(`stop()` 이 이미 끝난 자식의 exit 를 기다려 부팅 실패가 exit 13 + 요약 줄 없음이 되는 것, `waitForHealth` 감시, `startExtraServer` stderr 배수, `tools/harness-selftest.mjs`)은 머지되지 않아 main 에 전혀 없다** — 이번 회차로 그 PR 을 떨어뜨린 플레이크가 사라졌으니 알려진 좋은 diff 를 그대로 다시 올리는 것이 다음 1순위다(가치 5) ② `waitForHealth` 나머지 11개 호출처 감시 배선 — 단 ①이 먼저 들어가야 성립한다(가치 4) ③ 녹화 중복 제거가 `step.value` 만 비교해 `selectOption`(`values`)·`press`(`key`) 를 삼킨다, HEAD 에서 재확인함(가치 4) ④ 스모크의 남은 고정 `sleepMs` 대기들을 관측 가능한 사후조건으로 — 이번과 같은 결함 부류이며 반드시 부하를 걸어 실패를 먼저 볼 것(가치 3) ⑤ 바른 체크아웃에서 `npm install` 을 하라고 말해 주기 — ①이 미머지라 원인 문자열조차 main 에는 없다(가치 3). 그리고 `Recording nth note overwrites the ambiguous note` 는 **기각**했다: `resolved.nth` 는 `unique: true` 로 돌아오는 좁히기 분기에서만 설정되므로 두 조건은 동시에 성립할 수 없다(server.js:7251-7258 / 7345 / 7353).
- 과제서: 기각 — 정찰 과제서 없이 러너의 오류 적재만 있었고, 그 지시대로 실패한 검증(`npm test`)의 실패 단계를 읽어 고쳤다. 다만 러너 노트가 전제한 "직전 회차의 수정이 트리에 있다" 는 틀렸다 — base 는 pristine `main@a2a44d4` 이고 그 수정은 머지되지 않았다.

## 2026-10-04
- 선택: **[요청 과제]** 저장소의 검증 명령을 `.github/workflows/ci.yml` 로 옮겨 러너 PR 의 "CI 검사 없음" 을 없앰 (가치 5 / 위험 1 / 작업량 S)
- 결과: 성공
- 요약: 변경 파일은 `.github/workflows/ci.yml` 하나다(프로덕션 코드 0개, CHANGELOG 없음 — 이 저장소에는 그 파일이 없다). `push: [main]` + `pull_request` 에서 돌고, 언어 버전·설치 단계는 러너가 쓰는 것과 같다: `actions/setup-node@v4` node 22(`engines: >=22`, 이 환경 실측 v22.23.1) + `npm ci`(lockfile 이 있고 Dockerfile 도 `npm ci` 를 쓴다) + `npx playwright install --with-deps chromium`. 잡은 둘이다 — `check` 는 `npm run check`(= `node --check server.js`) 를 돌리는 **게이트**이고, `smoke` 는 릴리즈 체크리스트 1절과 같은 `SMOKE_REQUIRE_BROWSER=1 npm test` 를 돌리지만 **지금은 막지 않는다**(`continue-on-error`). 이유는 측정이다: 이 base(pristine `main@a2a44d4`)에서 전체 스위트를 두 번 돌렸고 **두 번 다 실패**했다 — 1차 `149 passed, 1 failed`, 2차 `148 passed, 2 failed`(각 5m47s). 실패 2건은 전부 이 회차 이전부터 main 에 있던 보류 결함이다(플레이그라운드 녹화 패널의 낡은 읽기 — 직전 회차가 고쳤지만 그 PR 이 머지되지 않았다; Playwright step duration 이 음수). 그래서 "지금 통과하는 것만 CI 로 옮긴다" 는 지시대로 통과가 증명된 명령만 게이트로 걸고, 테스트 명령은 CI 에 넣되 알려진 결함으로 모든 PR 을 막지는 않게 했다 — 두 결함이 고쳐지면 `continue-on-error` 한 줄을 지우는 것이 게이트 승격이고, 그 조건을 파일 주석에 적었다. 검증: 워크플로를 `actionlint 1.7.12` 로 린트해 깨끗했고(일부러 잘못된 입력을 넣은 사본은 린터가 잡는 것까지 확인해 "조용한 초록" 이 아님을 확인), `act 0.2.89 --dryrun` 으로 `pull_request`·`push` 두 이벤트의 잡·스텝 계획을 실제 워크플로 엔진으로 확인했고, CI 가 돌릴 명령 네 줄(`npm ci` → `npm run check` → `npx playwright install chromium` → `SMOKE_REQUIRE_BROWSER=1 npm test`)을 node_modules 없는 이 워크트리에서 같은 순서로 직접 돌렸다. 게이트가 되는 `npm run check` 는 `CHECK_OK` 로 통과한다.
- 실패 재현: 못 함 — 이 회차는 CI 설정 파일 추가이고 프로덕션 코드를 고치지 않았다(지시도 "테스트를 쓰거나 고치지 말 것"). 대신 CI 가 돌릴 명령을 그대로 돌려 **현재 상태를 측정**했다: `FAIL  a person can record and edit a scenario from the playground page — ["0. gotohttp://127.0.0.1:3911/demo/test-page?lang=ko↑↓✕"]` / `FAIL  a run records per-step durations and the step that failed — negative step duration: [... "durationMs":-1868 ...]` (2회 실행, `149 passed, 1 failed` / `148 passed, 2 failed`). 린터가 실제로 검사하는지는 사본에 오류를 주입해 확인했다: `input "bogus-input" is not defined in action "actions/checkout@v4"` (exit 1).
- 보류 아이디어: ① 직전 두 회차의 수정이 둘 다 머지되지 않아 main 에 없다 — 하네스 수정(`stop()` 이 끝난 자식의 exit 를 기다려 부팅 실패가 exit 13 + 요약 줄 없음)과 플레이그라운드 녹화 검사 동기화 수정을 다시 올리는 것이 1순위이고, 이제 CI 가 붙으니 PR 에서 결과가 보인다(가치 5) ② 음수 step duration — 이 회차에 **재현됐다**(`durationMs: -1868/-455/-457/-1644/-1646`, 콜드 chromium 의 Before Hooks 구간), server.js:1196/1252/2421 을 함께 고치면 CI smoke 를 게이트로 올리는 데 필요한 두 번째 조각이다(가치 4) ③ 도커 빌드와 최소 컨테이너 검증을 CI 로 — 릴리즈가 네 번 깨진 곳인데 전부 수동이다, 단 이 환경에서 `docker build` 통과를 확인한 뒤에 옮길 것(가치 4) ④ `npm audit` 이 advisory 2건을 보고한다(body-parser DoS low, qs moderate, 둘 다 `npm audit fix` 범위) — 지금 빨간 명령이라 CI 에는 일부러 넣지 않았다(가치 3) ⑤ CI 의 chromium 다운로드를 `actions/cache` 로 캐시(가치 2)
