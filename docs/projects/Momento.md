- 보류 아이디어: 망 구분(네트워크) 추가 실패도 한국어로 안내한다 — `AdminPage.tsx:3245` ← `createNetwork`(admin.go:800-828), CIDR 을 손으로 적는 칸이 있어 잘못된 CIDR 이 흔하다. 이번 회차의 차선 후보였고 이제 1순위 유력 (가치 2 / 위험 1 / S); 남은 create/update 오류 Alert 들(2410·2507·2954·3109·3750, 1365·2758)도 핸들러 단위로 한 조각씩 — 묶지 말 것 (가치 2 / 위험 1 / M); 표 검색이 숨긴 열의 값까지 뒤져 보이는 곳에 일치가 없는 행을 내놓는다 — 네 회차 연속 미선정, 집으려면 docs 검색 절로 의도를 먼저 가릴 것 (가치 2 / 위험 2 / S); DataTable CSV 가 column.format 을 적용하지 않고 원시값을 내보낸다 — '원시값' 이 의도일 가능성이 높다 (가치 2 / 위험 1 / S)
- 과제서: 채택 — 인용한 행 번호(AdminPage.tsx:1997·2121, admin.go 232·236·249·256·269·318·322·335·339·343·347·352·376, UserErrorAlert 3331-3349, 테스트의 `apiError` 헬퍼 18-21행, `.ts` 확장자 관례)와 "`sites.name` 에 UNIQUE 없음" 경고가 모두 현재 코드와 일치했고 수용 기준 3개를 그대로 구현·증명했다. 과제서가 재현하지 않은 채 추측으로 남긴 `SITE_CREATE_FAILED` 500 의 원인(workspaces 조회가 빔)은 이번에도 **DB 로 재현하지 않았다** — 그래서 그 추측에 기대지 않는 쪽을 골랐다(문구를 중립으로 두고 `no rows in result set` 을 특별 취급하지 않음). 과제서가 판단을 맡긴 "두 Alert 컴포넌트를 합칠지" 는 레이아웃만 `AdminNoticeAlert({notice})` 로 모으고 describe\* 선택은 호출자에 남기는 쪽으로 했다. 과제서에 없던 것 하나를 더 했다고 기록한다: 두 함수가 공통으로 쓰는 세 문장(`UNREADABLE_PAYLOAD`·`LOST_REQUEST`·`PASS_TO_ADMIN`)을 상수로 묶어 `describeUserError` 쪽에서도 쓰게 했다 — 글자는 그대로이고, 기존 사용자 6건이 그 문장을 글자 그대로 단언하므로 바뀌지 않았음이 테스트로 증명된다.
