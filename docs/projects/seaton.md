(6) 거절은 `mcpOAuthRefusal{status,code,message,cause}` 하나로 모아 `refuseMCPToken` 한 곳에서 응답과 로그(`mcp oauth token rejected` + cause)를 함께 낸다 — 캠페인 규칙(원인 로깅)을 테스트로 고정했고 ADMIN_GUIDE 도 그 로그 이름을 적었다. discovery 실패는 401 이 아닌 `503 sso_unavailable`(도전 헤더 없음)로 두어 클라이언트가 로그인 루프에 빠지지 않게 했다. 켜기 조건(issuer·범위에 mcp)은 저장 시점에 `400 invalid_setting` 으로 거절한다. 검증: go test(가짜 IdP 가 실제 RSA 키 쌍으로 JWT 서명 — 메타데이터 on/off·CORS·맨 JSON·끝 `/` 제거, 도전 헤더는 /mcp 401 에만, 꺼짐/REST 에서 토큰 무시, 대상·만료·nbf·다른 issuer·다른 키·HS256·typ=ID·cnf·sub 없음 각각 거절과 로그 원인, 503, 범위 교집합, 설정 검증, JWT 모양)·vet·gofmt, tsc, vitest 104건(새 mcpOAuth 4건), docker 이미지 + PostgreSQL + Node 가짜 Keycloak(discovery·JWKS·authorize·token, 실제 RSA 서명)으로 Playwright 51건 전부 통과 — 새 `mcp-oauth.spec.ts` 4건이 실제 라우팅·DB 를 지나 웹 SSO 로그인으로 등록하기 전엔 `401 account_not_registered` 이고 계정도 생기지 않음, 브라우저로 SSO 로그인한 뒤 같은 사람의 토큰이 tools/list·search_employees 를 엶, 다른 앱 토큰은 azp 와 리소스를 말하며 거절, 허용 대상에 적으면 매퍼 없이 통과, REST 401, 비활성 401, 끄면 404 와 원래 401 을 확인. 서버 로그에서 cause 가 실제로 남는 것을 봤다. 호스트 8080 을 다른 세션이 쓰고 있어 브리지 네트워크 + `--add-host` 로 돌렸고, spec 은 `E2E_COLLECTOR_HOST` 가 127.0.0.1 이 아니면 Chromium host-resolver-rules 로 같은 이름을 127.0.0.1 에 붙인다(CI 의 --network host 는 기본값 그대로). 실제 Keycloak·Claude 클라이언트는 이 환경에 없어 가짜 IdP 로만 확인했다. ADMIN_GUIDE 는 §3.3 안의 굵은 소절("MCP를 SSO로 열기")로 넣어 §3.4~3.6 번호와 미머지 메일 브랜치의 §3.7 을 건드리지 않았고, 새 캡처 1장(카드만)을 더해 HTML 만 다시 만들었다(PDF 는 09-17 회차와 같은 이유로 굽지 않음 — 릴리즈 뒤 문서 정비 회차에서 md2pdf). 남은 관찰: 웹 SSO 로그인 upsert 가 `active` 를 되살리지 않아 비활성 SSO 사용자가 로그인해도 세션만 생기고 아무것도 못 한다(기존 동작, 이번 범위 밖).
