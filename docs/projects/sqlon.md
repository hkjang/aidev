## 2026-09-14
- 선택: Silent SSO(prompt=none) 자동 로그인 — 캠페인 silent-sso-2026-09 (가치 5 / 위험 2 / 작업량 M)
- 결과: 성공
- 요약: 이 저장소에는 Keycloak OIDC(authorization code + userinfo)가 이미 있어 표준대로 auto_login 을 붙였다. 서버는 `oidc_auto_login` 설정(기본 꺼짐, 환경변수 `SQLON_OIDC_AUTO_LOGIN`/플래그 `-oidc-auto-login`, 저장 설정이 우선)이 켜진 경우에만 `/auth/sso/login?prompt=none` 을 제공자로 넘기고, 꺼져 있으면 조용히 평범한 로그인으로 바꾼다. 왕복 컨텍스트(silent 여부·return_to)는 짧은 쿠키로 들고 다니며, 콜백이 login_required/interaction_required/consent_required 를 받으면 `/auth/login?sso=none&next=<deep link>` 로 보내고 성공하면 `return_to`(`/`로 시작·`//` 아님·절대 URL 아님)로 돌아간다. 로그인 화면(login.html)이 시도 여부를 정한다: 탭 세션당 한 번(sessionStorage), 직접 로그아웃 후 억제(nav.js 가 표시하고 세션이 다시 생기면 지움), 주소의 `sso=none|error` 표시, 저장소 예외는 '이미 시도했다'로 처리. 최상위 이동(location.assign)이며 iframe 은 쓰지 않는다. 검증: Go 테스트 7개(auto_login 꺼짐 시 prompt=none 무시, 거절→로그인 화면+표시, 깊은 링크 복귀(가짜 IdP httptest), return_to 검증, 설정/`/auth/me` 노출, 부팅 기본값) + login.html 인라인 스크립트를 node vm 으로 돌리는 브라우저 규칙 테스트 9개(node 없으면 skip); `go vet ./...`, `go test ./...` 전부 통과. 관리자 가이드 3.4 와 README 에 설정·동작을 적었다.
- 보류 아이디어: OIDC 콜백의 error 분기에서도 state 쿠키 일치를 확인(비-silent 경로 견고화) / OIDC 로그인에 nonce·PKCE(S256) 추가 / 설정 화면에서 boolean 설정(`oidc_auto_login`)을 토글로 렌더링 / docs/auth.md 가 0바이트 — 인증 모델(로컬·SSO·MCP 키·마스터 토큰) 문서 채우기 / 서버 측 guard 리다이렉트에서 `?next=` 를 `RequestURI` 로 넘길 때 절대 URI 형태(프록시 요청) 방어 테스트 추가

- 요약: 이 저장소는 Go 로 짠 HTTP 관리 콘솔(`internal/mcp/webui`, embed 정적 HTML)을 제공하므로 표준대로 넣었다. 새 패키지 `internal/tracking` 이 설정(메타 DB `tracking_*` 12개 키, 기본 꺼짐)·검증(8KB 제한, 제공자 조합)·스니펫 렌더링(요청별 nonce 를 모든 `<script>` 에, ASCII 만 접는 검색으로 `İ`/U+212A 안전)·스니펫 출처 추출·정책 조립·차단 출처 기록(고리 100건, 지시어+출처 단위)을 맡고, `serveWebUI` 가 HTML 화면에만 스니펫을 넣는다(`/api/*`·`nav.js` 등 자산은 절대 아님). provider 는 momento 를 첫 자리에 두고 같은 오리진 프록시(`/momento/*` → 수집기, 세션 쿠키·인증 헤더 제거, `data-endpoint="/momento"`)를 기본으로 삼아 외부 출처가 정책에 나오지 않는다. **CSP 판단**: 이 앱은 원래 CSP 가 전혀 없고 화면 27개에 인라인 이벤트 핸들러(`onclick=`)가 93곳이라 `script-src 'self' 'nonce-…'` 를 강제하면 화면이 멈춘다(걷어내는 일은 L 규모). 그래서 추적이 켜진 화면에만 `Content-Security-Policy: img-src/connect-src + report-uri` 를 **강제**하고 `script-src 'self' 'nonce-…' <출처>` 는 **Report-Only** 헤더로 내보내 위반을 신고받는다(`'unsafe-inline'` 없음, 끄면 두 헤더 모두 사라져 원래대로). 신고는 `POST /api/tracking/csp-report`(무인증, 켜진 동안만 기록) → `/admin/settings` 의 "차단된 출처" 표(차단/보고/허용됨) → [허용] 한 번으로 `tracking_allowed_hosts` 반영. 설정 정의에 `Type`(bool/select/multiline)·`Validate` 를 두어 설정 화면이 체크박스·드롭다운·textarea 로 그리고, `PUT /api/settings` 는 tracking_* 가 섞이면 바뀐 뒤 조합 전체를 먼저 검사해 잘못되면 아무것도 저장하지 않는다. 검증: `internal/tracking` 단위 테스트 10개(기본 꺼짐·momento 프록시/직접·검증·admin 제외·길이 변하는 룬에서 nonce·출처 추출·삽입 위치·기록 상한/중복·허용 목록) + `internal/mcp` HTTP 테스트 4개(꺼진 새 설치에 헤더/스니펫 없음, momento 프록시 end-to-end(httptest 수집기·쿠키 제거·nonce 가 태그와 script-src 에 일치·요청마다 다름·admin 제외·body 배치·끄면 원복), 설정 검증(불완전 조합·8KB 초과 저장 안 됨·제공자 enum·URL), custom 스니펫 출처→정책·위반 신고→목록→허용→정책 반영→지우기), `go vet ./...`, `go test ./...` 전부 통과. 관리자 가이드 3.4(설정 표·Momento·CSP 두 헤더 설명·차단 출처 허용 절차)와 README·OpenAPI·nav 도움말을 갱신하고 `docs/reports/generate_docs.py` 로 admin_guide PDF/HTML 을 다시 구워 `docs/admin_guide.pdf` 에 복사했다(시스템 Chrome 사용, 표지 메타는 스크립트 값 그대로). 참고: 이전 회차의 silent SSO(`oidc_auto_login`) 커밋 07e74de 는 `auto/2026-09-14-2102` 브랜치에만 있고 main 에 머지되지 않아, 그와 관련된 보류 아이디어는 이 브랜치에서 평가·적용할 수 없었다.
