- 요약: 러너 검증이 `npm test --silent` 를 단독으로 돌리는데 두 가지 이유로 늘 실패했다. ① `npm test` 가 테스트용 빌드 세 벌(dist·dist-draft·dist-email)을 만들지 않아 Playwright webServer 가 없는 폴더를 제공하다 죽었고(사람이 `npm run test:build` 를 먼저 돌려야 했다), ② 빌드를 갖춘 뒤에도 28건이 실패했는데 고정 포트 8788·8789 를 **같은 기계의 다른 프로젝트 개발 서버**(`:8788`=your, `:8789`=옆자리 인사이트)가 잡고 있었고 `reuseExistingServer: true` 때문에 Playwright 가 남의 서버를 우리 서버로 알고 그대로 테스트했다. `package.json` 에 `pretest`(test:build + `npx playwright install chromium`)를 넣고, `playwright.config.ts` 가 `scripts/free-ports.mjs` 로 빈 포트 5개를 받아 쓰며 서버 재사용을 끄게 했다(포트가 들어가는 Worker 변수 `RESEND_API_BASE`·`ALLOWED_ORIGINS` 는 `.wrangler/test-ports.env` 로 덮어쓰고, 테스트 파일은 `MOCK_RESEND_BASE`·`WORKER_ORIGIN` 환경변수로 받는다). 워크플로를 느슨하게 하거나 테스트를 지우지 않았다 — 검증 명령은 그대로다. 확인: 빌드 세 벌을 모두 지운 상태에서 `npm test --silent` → 75 통과·4 건너뜀·exit 0(8788·8789 는 남의 서버가 그대로 잡고 있는 채로 통과), `npm run build --silent` → `✓ 모두 통과`.
- 실패 재현: 고치기 전 `npm test --silent` → `Error: ENOENT: no such file or directory, open '.../dist-email/404.html'` / `Error: Process from config.webServer was not able to start. Exit code: 1` (exit 1). 빌드를 갖춘 뒤 같은 명령 → `✘ 문의 API › 다른 출처에서 온 요청은 거절 — Expected: 403 / Received: 404`, `✘ 화면: 보내기 버튼… — getByRole('button', { name: '문의 보내기' }) element(s) not found` 등 28건 실패(`curl :8788` 이 다른 프로젝트의 `<title>your · …</title>` 를 돌려주는 것으로 원인 확정).
- 보류 아이디어: ① 서비스 페이지 목록 드리프트 감지(verify-build 사이트맵 목록 vs tests/site.spec.ts PAGES — 합치지 말고 감지만) ② src/lib/inquiry.ts 순수 함수 단위 테스트 ③ worker/index.ts handleInbound 첨부 누적 용량 계산 오류(초과분을 total 에서 되돌리지 않아 이후 작은 첨부까지 skip) ④ handleInbound 의 FORWARD_TO 루프 감지가 500 을 돌려 Resend 가 무한 재시도 ⑤ 지난 회차 브랜치(auto/2026-10-07-1758)의 harfbuzzjs·fontverter 선언 + verify-deps.mjs 가 main 에 들어가지 못했다 — 같은 변경을 다시 올릴 것인지 판단 필요
- 과제서: 채택 — 과제서가 지목한 `npm test --silent` 실패를 그대로 재현해 두 가지 원인을 모두 고쳤다.
