Actions 가 풀리는 즉시 러너 OS 가 바뀌어 `check.yml` 의 `--with-deps` playwright·postgres 서비스가 처음 터질 수 있다. 라벨 고정(`ubuntu-24.04`)은 사람의 판단이 필요해 이번 회차 범위(“이것만 고치세요”)에서 뺐다 [4/2/S, 신규] ② Actions 복구 후 PR #4·#5·#6·#7·#8 을 그대로 머지 — 저장소 변경 불필요, 세 회차 연속 로컬 전체 게이트로 결백 증명됨 [5/1/S] ③ `scripts/perf.mjs` 의 95% 경고가 main 에 없어(PR #8 미머지) 224.1/230 KB = 97.4%, 여유 5.9 KB 가 CI 로그에 안 보인다 — 이번 회차에 실행으로 재확인 [3/1/S] ④ e2e 가 깨끗한 DB 를 암묵적 전제로 하는 것(개수·빈 목록 단정 검사를 run-id 로 격리) — dev-reset 직후 218/0 이 여덟 회차 연속 같은 기준선 [3/2/M] ⑤ `v.string` 의 max 는 UTF-16, `v.text` 는 코드포인트로 세어 같은 `max:4` 에 `'🙂🙂🙂'` 가 한쪽만 거부된다 — 테스트로 고정만 돼 있다 [2/2/S]
- 과제서: 차선 — 러너 명세의 사실(워크플로 'check' · 잡 'check' · 단계 '' · `BlobNotFound`)은 정확했고 지시한 1)2)3) 순서도 그대로 밟았으나, 전제인 “원인을 고치세요” 가 저장소 안에서 성립하지 않았다. 단계 이름이 빈 값이라는 명세 자체가 이미 잡 미시작의 신호였고, 주석 원문이 계정 결제 차단을 지목한다 — 이번엔 그 추론을 `gh` 로 증거까지 끌어와 닫았다.
