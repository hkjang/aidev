## 2026-10-17
- 선택: 루트 `test` 스크립트에 turbo 패스스루(`--`) 추가 — `pnpm test --silent` 가 turbo 사용법 오류로 죽는 것 수정 (가치 4 / 위험 2 / 작업량 S)
- 결과: 성공
- 요약: 수정 과제(지난 회차 `verify-failed`)였다. pnpm 은 스크립트 이름 뒤 인자를 그대로 스크립트 명령줄에 덧붙이므로 `--silent` 가 turbo 자신의 플래그 자리에 떨어져 turbo 2.9.5 가 `unexpected argument` 로 즉시 종료했고, 테스트는 한 개도 실행되지 않은 채 exit 1 이 나 러너가 테스트 실패로 보고했다. 루트 `package.json` 의 `scripts.test` 한 줄만 `turbo test --filter=!@multica/mobile --` 로 끝맺어 뒤따르는 인자가 각 패키지의 `vitest run` 으로 전달되게 했다(프로덕션 코드 파일 1개, 테스트 추가 없음). 접근을 고르기 전에 정찰이 미확인으로 남긴 **빈 패스스루**를 먼저 검증했다: turbo 2.9.5 는 인자 없는 trailing `--` 를 받아들이고(exit 0), `--dry-run=json` 으로 비교한 6개 `#test` 태스크 해시가 `--` 유무와 **바이트 단위로 동일**해 인자 없는 경로와 기존 캐시 항목이 전혀 영향받지 않음을 확인했다. 검증은 네 명령을 실제로 돌렸다: `pnpm test` → `Tasks: 6 successful, 6 total / Cached: 0 cached` exit 0, `pnpm test --silent` → 같은 `6 successful, 6 total / 0 cached` exit 0(캐시 적중이 아닌 실제 실행), `pnpm typecheck` → `10 successful, 10 total / 0 cached` exit 0, `pnpm lint` → `7 successful, 7 total / 0 cached` exit 0. Go(`make test`)와 E2E 는 이 변경과 무관하여 **실행 안 함**. 테스트 스킵·필터 축소·`continue-on-error`·`|| true` 는 없고 커밋 diff 는 한 줄이다.
- 실패 재현: 고치기 전 `pnpm test --silent` 실행 결과 — `> turbo test --filter=!@multica/mobile --silent` / ` ERROR  unexpected argument '--silent' found` / `tip: to pass '--silent' as a value, use '-- --silent'` → `EXIT=1`, 실행된 테스트 0개. 고친 뒤 같은 명령이 `Tasks: 6 successful, 6 total`, exit 0. 또한 **실패가 여전히 실패로 보이는지** 별도로 증명했다(수용 기준 3): `packages/core/paths/` 에 일부러 깨지는 임시 프로브 테스트를 넣고 `pnpm test --silent` 를 돌려 `× deliberately_fails_to_prove_failures_are_reported` / `FAIL paths/sabotage-probe.test.ts > silent-passthrough-probe > ...` / `Tests 1 failed | 2265 passed` / `Failed: @multica/core#test`, `EXIT=1` 을 확인했고, 프로브 안의 `console.log` 줄은 출력에 나타나지 않아 `--silent` 가 **실제로 vitest 까지 도달해 동작**했음(무시된 것이 아님)을 함께 증명했다. 프로브는 확인 후 삭제했고 커밋 전 `git status` 는 `M package.json` 한 줄뿐이었다.
- 보류 아이디어: ① 백엔드 Opus 4.8/4.7/4.6/4.5·Sonnet 4.6/4.5·Haiku 4.5 규칙에 `claudeVersionEnd` 종결자가 없어 후속 SKU(`claude-opus-4-5-1`)를 조용히 같은 등급으로 삼킴 — 단가가 같아 금액 회귀로는 안 보이므로 규칙 매칭 수준 테이블 테스트 필요(이번 회차 차선 후보, 미착수) ② deepseek v4-flash 단가가 백엔드 0.56/1.12 vs 프런트 0.14/0.28 로 4배 어긋남 — 어느 쪽이 공식가인지 출처 확인 없이는 데이터 추측이라 보류 ③ 백엔드 `(^|/|:)k3$` 규칙의 `^` 분기가 공급자 없는 bare `k3` 를 Kimi 단가로 매김 — 실제로 bare k3 를 보고하는 공급자를 확인 못 해 가설 단계 ④ 프런트 `cursorBaseModel` 의 `-max`/`-high` 변이 접미사가 실제 SKU 이름 끝을 깎음 — 지금은 raw 후보가 남아 결과가 맞지만 `cursor/<base>` 행 추가 시 오해석(파서 통합 금지, 좁히는 방향만) ⑤ 프런트/백엔드 요금표의 **공통 SKU 에 한정한** 좁은 단가 동등성 검사를 CI 에 추가(두 표의 계약이 달라 통합은 금지)
- 과제서: 채택 — 과제서의 진단(pnpm → turbo 인자 누출)과 지정 파일 1개가 지금 코드와 정확히 일치했고, 미확인으로 남긴 빈 패스스루를 먼저 검증해 turbo 2.9.5 가 받아들이는 것과 태스크 해시가 불변인 것을 확인한 뒤 그대로 구현했다.

## 2026-10-18
- 선택: 루트 turbo 집계 스크립트가 pnpm 이 덧붙이는 플래그를 삼키도록 wrapper 도입 (`pnpm run typecheck --silent` 수정) (가치 4 / 위험 2 / 작업량 S)
- 결과: 성공
- 요약: 수정 과제(지난 회차 `verify-failed: pnpm run typecheck --silent`)다. 원인은 지난 회차 `test` 와 동일하다 — pnpm 은 스크립트 이름 뒤 인자를 스크립트 명령줄에 그대로 덧붙이므로 `--silent` 가 turbo 자신의 옵션 자리에 떨어지고 turbo 2.9.5 는 `unexpected argument '--silent'` 로 즉시 종료한다(패키지 하나도 검사하지 않은 채 exit 1). **베이스(main@18fa9f7)를 확인해 보니 지난 회차의 `test` 패스스루(`--`) 수정이 main 에 들어오지 않았고, build/typecheck/test/lint 네 스크립트가 모두 같은 결함을 갖고 있었다.** 거부되었을 수 있는 같은 접근(`--` 패스스루)을 다시 올리지 않고 다른 방식으로 고쳤다: `tsc --noEmit --silent` / `eslint --silent` 는 그 자체로 실패하므로 패스스루는 typecheck·lint 에는 애초에 쓸 수 없다. 새 `scripts/turbo-run.mjs` 가 turbo 에 없는 verbosity 플래그(`--silent`/`--quiet`)만 turbo 의 `--output-logs=errors-only` 로 번역하고 나머지는 그대로 넘긴다(첫 bare `--` 뒤는 태스크 인자로 보존). 프로덕션 코드 2개 파일(package.json, 새 wrapper) + 테스트 1개 + CI 배선 1줄. 검증: 캐시를 믿지 않도록 `--force` 로 실제 실행을 확인했다 — `pnpm run typecheck --silent --force` → `10 successful, 10 total / 0 cached` exit 0, `lint --silent --force` → `7 successful / 0 cached` exit 0, `test --silent --force` → `6 successful / 0 cached` exit 0. **실패가 여전히 실패로 보이는지**도 양쪽으로 증명했다: packages/core 에 임시 타입 오류를 넣고 `pnpm run typecheck --silent` → `error TS2322 ... Failed: @multica/core#typecheck`, EXIT=2; 임시 실패 테스트를 넣고 `pnpm run test --silent` → `× deliberately_fails_to_prove_failures_are_reported`, `Tests 1 failed | 2265 passed`, EXIT=1. 두 프로브는 확인 뒤 삭제했고 커밋 diff 에 없다. Go(`make test`)·E2E 는 이 변경과 무관해 실행하지 않았다. `pnpm knip` 은 새 파일에 대해 새 지적을 내지 않았다(기존 12건 그대로).
- 실패 재현: `node --test scripts/turbo-run.test.mjs` (고치기 전) → `not ok 1 - pnpm run typecheck plans the same workspaces when pnpm appends --silent` … `# pass 0 / # fail 4`, 각 실패의 본문은 `> turbo typecheck --filter=!@multica/mobile --silent` / ` ERROR  unexpected argument '--silent' found`. 다섯 번째 테스트(`--` 뒤 인자 보존)도 wrapper 의 분리 로직을 `separator = -1` 로 일시 무력화해 `not ok 5` 로 떨어지는 것을 확인한 뒤 되돌렸다(무해한 테스트가 아님을 증명).
- 보류 아이디어: ① 백엔드 Opus 4.8/4.7/4.6/4.5·Sonnet 4.6/4.5·Haiku 4.5 규칙에 `claudeVersionEnd` 종결자가 없어 후속 SKU 를 같은 등급으로 삼킴(규칙 매칭 수준 테이블 테스트 필요) ② deepseek v4-flash 단가 백엔드/프런트 4배 불일치 — 공식가 출처 확인 없이는 데이터 추측 ③ 백엔드 `(^|/|:)k3$` 의 `^` 분기가 bare `k3` 를 Kimi 단가로 매김 ④ ci.yml 의 `--filter='!@multica/mobile'` 와 루트 package.json 필터가 주석으로만 동기화됨 — 드리프트 검사 추가 ⑤ 프런트/백엔드 요금표의 공통 SKU 에 한정한 좁은 단가 동등성 검사(두 표 통합은 금지)
