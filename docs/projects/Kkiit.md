- 요약: `updateCoupon` 이 UPDATE 의 모든 오류를 `err != nil || tag.RowsAffected() == 0` 로 묶어 404 `coupon_not_found` 로 돌려주었고, `coupons.code` 가 UNIQUE 이므로 관리자가 쿠폰 코드를 다른 쿠폰의 코드로 바꾸면 눈앞의 쿠폰을 두고 "쿠폰을 찾을 수 없습니다" 를 받아 원인을 알 수 없었다(반대로 `createCoupon` 은 모든 INSERT 오류를 409 로 묶어 DB 장애를 중복으로 보고). 두 저장 경로에서 `isUniqueViolation`(SQLSTATE 23505)만 409 `coupon_exists`, 나머지는 500 `coupon_save_failed`, `RowsAffected()==0` 만 404 로 갈랐다. 검증: 통합 테스트를 먼저 써서 실제 라우터·버릴 PostgreSQL 16(docker 29.7.2)으로 `status=404 body={"error":{"code":"coupon_not_found"...}}` 를 재현한 뒤 수정해 통과시켰고, 분류기를 두 방향으로 변이시켜(항상 참 / 23505 를 절대 안 맞춤) 단위·통합 테스트가 각각 다시 실패하는 것까지 확인했다. 깨끗한 DB 로 `go test ./cmd/... ./internal/...` 전체 통과(httpapi 82.7초, 통합 실제 실행), `go vet`·`gofmt -l` 무결, `npm --prefix web test` 10건 통과. 프런트는 이미 `error.message` 를 띄우므로 서버만 고쳐도 "이미 사용 중인 쿠폰 코드입니다." 가 나와 `web/`·`internal/ui/dist` 를 건드리지 않았고, `openapi.yaml` 의 PUT 응답에 409 한 줄만 더했다.
