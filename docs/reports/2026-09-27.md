## 무엇을 왜 바꿨나 (원장 발췌)

### [relio](https://hkjang.github.io/aidev/projects/relio/)

- 선택: PostgreSQL 에 닿지 못한 오류(`failed to connect to \`user=… database=…\``)를 REST·MCP 두 문 모두에서 원문 없이 서버 오류로 접기 (가치 4 / 위험 2 / 작업량 S)
- 결과: 성공
- 요약: 지난 회차의 SQLSTATE 분류(18c83f2)는 SQLSTATE 가 **실린** 오류만 보므로, 드라이버가 PostgreSQL 에 닿지 못해 SQLSTATE 가 아예 없는 `*pgconn.ConnectError` 는 REST 에서 기본값 400 `invalid_request` + 드라이버 원문으로, MCP 에서는 `sanitizeToolError` 의 마지막 줄 `return message` 로 원문 그대로 나갔다 — 그 원문이 DB 계정명·DB 이름·내부 host:port 를 싣는다. 새 `database.Unreachable(err)`(`errors.As(err, &connErr)`) 하나로 두 문의 판정을 맞췄다: `serviceError` 는 `case isPg:` 뒤·영어 substring 앞에 case 하나를 더해 500 `internal_error`(기존 `status >= 500` 블록이 문장 교체와 로깅을 이미 한다), `sanitizeToolError` 는 74행 조건만 넓혀 `code` 가 빈 채로 switch 를 통과해 이미 있는 일반 문장으로 떨어진다. 두 SQLSTATE→문장 표는 한 글자도 건드리지 않았다. 프로덕션 3파일. 정찰이 미확인으로 남긴 동적 타입을 먼저 probe 로 확인했다 — `*pgconn.ConnectError`, `errors.As` 참, 사슬에 `PgError` 없음, 문자열 폴백 불필요. 증명은 손으로 만든 대역 없이 실제 `*pgxpool.Pool`(아무도 듣지 않는 포트)의 실제 질의 오류를 실제 `serviceError`(httptest)·`sanitizeToolError` 에 넣어 했고, 각 분기를 끄면 해당 테스트만 다시 실패함을 확인했다. 검증: `go build ./...`(순환 없음) · `go vet ./...` · `go test ./...` exit 0 (22 ok, FAIL 0) · `go test -race ./...` exit 0 (DATA RACE 0) · `gofmt -l` 5파일 무출력 · `git diff --check` 무출력 · `check-env-contract.sh` 통과 · 기존 `service_error_test.go` 27건 전부 통과하며 삭제된 줄 0. 커밋 f5064f6.
- 실패 재현: REST — `got 400 invalid_request, want 500 internal_error ({"error":{"code":"invalid_request","message":"담당자 목록을 읽을 수 없습니다: failed to connect to \`user=relio database=relio\`: 127.0.0.1:42875 (127.0.0.1): dial error: dial tcp 127.0.0.1:42875: connect: connection refused","requestId":"req-42"}})`. MCP — `got "담당자 목록을 읽을 수 없습니다: failed to connect to \`user=relio database=relio\`: 127.0.0.1:32833 …", want the generic sentence this function already uses for a database error`.
- 보류 아이디어: `context.DeadlineExceeded`·`net.Error` 로 끊긴 질의도 400 이 아니라 서버 오류로 — 같은 자리에 case 하나, 단 클라이언트 취소(Canceled)와 서버측 한도 초과를 구분할지 결정 필요 (가치 3 / 위험 2 / S) · `pgErrorVerdict` 와 `sanitizeToolError` 의 SQLSTATE→문장 표가 어긋나는 것을 `go/ast` 대조로 잡기 — 이번 차선 후보, 프로덕션 0파일 (가치 2 / 위험 1 / S) · `serviceError` 의 영어 substring 분류를 센티널 오류로 옮기기 — 354개 호출부에 번져 단독 S 아님 (가치 3 / 위험 3 / M) · `ClientIP` 가 X-Forwarded-For/Forwarded 를 읽지 않음 — 신뢰 프록시 설정과 함께, 12회차 연속 보류 (가치 4 / 위험 3 / M) · `DealsAtRisk`·`Coaching` 열린 딜 200건 상한 — 커서 페이징, 사용자 계약 결정이 먼저 (가치 3 / 위험 2 / M)
- 과제서: 채택 — 과제서가 지목한 자리와 근거(`server.go:714` 의 case 순서, `results.go:98` 의 `return message`, `pgconn/errors.go` 가 싣는 DSN 조각, `unreachablePool` 패턴)가 코드와 전부 일치했고, 미확인으로 남긴 동적 타입도 probe 에서 `*pgconn.ConnectError` 로 확인돼 문자열 폴백 없이 `errors.As` 만으로 수용 기준 1~5 를 그대로 구현했다.
