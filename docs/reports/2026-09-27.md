### [relio](https://hkjang.github.io/aidev/projects/relio/)

- 선택: PostgreSQL 에 닿지 못한 오류(`failed to connect to \`user=… database=…\``)를 REST·MCP 두 문 모두에서 원문 없이 서버 오류로 접기 (가치 4 / 위험 2 / 작업량 S)
- 결과: 성공
- 요약: 지난 회차의 SQLSTATE 분류(18c83f2)는 SQLSTATE 가 **실린** 오류만 보므로, 드라이버가 PostgreSQL 에 닿지 못해 SQLSTATE 가 아예 없는 `*pgconn.ConnectError` 는 REST 에서 기본값 400 `invalid_request` + 드라이버 원문으로, MCP 에서는 `sanitizeToolError` 의 마지막 줄 `return message` 로 원문 그대로 나갔다 — 그 원문이 DB 계정명·DB 이름·내부 host:port 를 싣는다. 새 `database.Unreachable(err)`(`errors.As(err, &connErr)`) 하나로 두 문의 판정을 맞췄다: `serviceError` 는 `case isPg:` 뒤·영어 substring 앞에 case 하나를 더해 500 `internal_error`(기존 `status >= 500` 블록이 문장 교체와 로깅을 이미 한다), `sanitizeToolError` 는 74행 조건만 넓혀 `code` 가 빈 채로 switch 를 통과해 이미 있는 일반 문장으로 떨어진다. 두 SQLSTATE→문장 표는 한 글자도 건드리지 않았다. 프로덕션 3파일. 정찰이 미확인으로 남긴 동적 타입을 먼저 probe 로 확인했다 — `*pgconn.ConnectError`, `errors.As` 참, 사슬에 `PgError` 없음, 문자열 폴백 불필요. 증명은 손으로 만든 대역 없이 실제 `*pgxpool.Pool`(아무도 듣지 않는 포트)의 실제 질의 오류를 실제 `serviceError`(httptest)·`sanitizeToolError` 에 넣어 했고, 각 분기를 끄면 해당 테스트만 다시 실패함을 확인했다. 검증: `go build ./...`(순환 없음) · `go vet ./...` · `go test ./...` exit 0 (22 ok, FAIL 0) · `go test -race ./...` exit 0 (DATA RACE 0) · `gofmt -l` 5파일 무출력 · `git diff --check` 무출력 · `check-env-contract.sh` 통과 · 기존 `service_error_test.go` 27건 전부 통과하며 삭제된 줄 0. 커밋 f5064f6.
