- 요약: 제출 핸들러의 요청 구조체에 `binds` 가 없어 `ExecOptions.Binds` 가 항상 nil 이었고, 같은 플레이스홀더 SQL 이 동기(`POST /api/query/execute`)에서는 바인드되어, 비동기에서는 인자 0개로 실행됐다. 핸들러에 `Binds []any` 를 추가해 `submitAsyncQuery` 로 넘기고, `asyncJob` 에 비직렬화 비공개 필드 `opts` 를 두어 백그라운드 실행이 그 값을 그대로 `executeGuarded` 에 넘기게 했다(잡 조회 JSON 응답 계약 무변화). 검증은 실제 로그인 쿠키 → 실제 `Register` mux → `POST /api/query/submit` 으로 했고 수정 전 `Binds=nil` 로 RED, 수정 후 GREEN 을 확인했다(`go test ./internal/mcp -run 'TestAsync|TestSyncAndAsync'`). 도커가 있어 실 DB 통합 검증도 추가했다 — `TestExecuteBindsReachDriver` 가 PostgreSQL/MySQL/MariaDB 세 컨테이너에서 `ExecOptions{Binds: []any{7}}` 가 드라이버까지 가 7 을 돌려주고 binds 없는 같은 SQL 은 실패함을 확인한다. `go test ./... -count=1`(19 패키지 ok)·`go vet ./...`·`go build ./...`·`go test ./internal/mcp -run TestAsync -race`·`go test -tags integration ./test/integration -count=1`·손댄 파일 `gofmt -l` 무출력·`git diff --check` 모두 통과.
