Hunter 는 스니펫을 앱 본문이 아니라 `sandbox allow-scripts` 불투명 출처 프레임에서만 실행해 앱 CSP(`script-src 'self'`)에 nonce·`'unsafe-inline'` 을 더하지 않는 구조라 표준 §2 는 해당 없고, 빠져 있던 §4 를 채웠다: 프레임 bridge 가 `securitypolicyviolation` 의 blockedURI·effectiveDirective 를 postMessage 로 부모에 전달(http(s)만, 지시어·URI 조합당 1회, 100개 상한)하고, 로그인한 부모 화면(`TrackingRuntime`)이 2초 배치로 세션·CSRF 를 갖춘 `POST /api/tracking/violations` 에 고정 경로 템플릿과 함께 대신 신고한다(불투명 출처의 report-uri 는 세션 없이 나가므로). 서버(`tracking_violations.go`)는 kanpic Recorder 처럼 출처를 `trackingOrigin` 으로 정규화해 인스턴스 메모리 고리 버퍼(100개, LastSeen 가장 오래된 것 축출, 횟수·최초/최근·고정 경로만, 경로·쿼리 미보관)에 두고 `GET/DELETE /api/admin/tracking/violations` 로 허용 여부와 함께 보여 준다; 추적이 꺼져 있으면 관리자 미리보기만 신고 가능(그 외 404). 설정 화면에 "보안 정책에서 차단된 출처" 패널(새로 고침·기록 지우기·**허용 목록에 추가** → 허용 원점 입력에 채움)을 넣고 격리 미리보기 경고에도 차단 출처와 추가 버튼을 붙였다. openapi.json(경로 3개·스키마 3개), 관리자 가이드(md/html/pdf 재생성, CSP 설명), README, llms.txt 갱신. 검증: `go vet ./...`, 임시 PostgreSQL 컨테이너로 `go test -race ./...`(새 단위·통합 테스트 2개 포함), `npm test`(87 통과), `tsc`·`vite build`, `node scripts/check-docs.mjs`, 그리고 빌드한 서버를 실제로 띄워 playwright chromium 으로 허용 원점 밖 fetch·이미지가 `connect-src`·`img-src` 출처로 서버에 기록되고 새로 고침 시 횟수만 늘며(중복 없음) 설정 패널의 추가 버튼이 원점 입력을 채우는 것을 확인했다.
