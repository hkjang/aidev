### [moyro](https://hkjang.github.io/aidev/projects/moyro/)

- 선택: 캠페인 mcp-oauth-2026-09 — Keycloak 액세스 토큰으로도 /mcp 에 들어오게 하는 OAuth 2.1 리소스 서버(RFC 9728 메타데이터·401 도전·JWKS 검증·대상 검사·계정 매핑, 기본 꺼짐) (가치 5 / 위험 2 / 작업량 M)

- 요약: 이 저장소는 사용자별 계정과 Keycloak OIDC 로그인(`oidcauth` + `user_identities`)이 이미 있어 표준을 그대로 적용했다. 설정 자리는 settings 저장소 `mcp` 섹션의 `oauth` 객체(`mcp.oauth.enabled/resource/audience/scopes`)로 두어 기존 MCP 카드·PATCH 경로를 재사용했고, 발급자·클라이언트 ID·username claim 은 `oidc/keycloak` 레코드를 재사용한다. 리소스 식별자는 `mcp.oauth.resource` → 사이트 공개 주소+`/mcp` 순이며 Host 헤더 폴백은 두지 않았다(이 저장소는 Keycloak 을 켜려면 공개 주소가 필수라 마지막 수단이 필요 없고, 헤더로 대상 검사를 흔들 여지를 없앤다) — 대신 저장 시점에 OIDC 미가동·리소스 없음·범위 없음을 거부하고, 저장 뒤 Keycloak/MCP 가 꺼지면 카드 경고와 로그(`MCP SSO is enabled but not accepting tokens`)에 이유를 남기며 메타데이터는 404 가 된다. 검증은 `oidcauth.Manager.VerifyAccessToken`(스냅샷의 go-oidc provider 에 `SkipClientIDCheck` + RS/ES/PS/EdDSA 한정 verifier 를 하나 더 붙임)이 서명·iss·exp·nbf 를, 그 위에서 `typ=ID`·`cnf`·빈 `sub` 를 거부하고, `aud` 에 리소스가 있거나 `aud`/`azp` 가 관리자 목록에 있어야 통과시키며 거부 메시지에 본 aud/azp 와 고칠 값을 넣는다. 계정은 `user_identities(provider=keycloak:<issuer hash>, subject=sub)` 로 이미 연결된 활성 계정만 — weekly 와 달리 username 일치 폴백은 일부러 뺐다(Keycloak preferred_username 이 로컬 관리자 이름과 겹치면 그 계정으로 들어가는 길이 되므로;
