(4) 계정은 `users.oidc_subject = sub AND active` 만 — username 폴백은 두지 않음(로컬 `admin` 과 같은 SSO username 이 그 계정으로 매핑되는 길을 열지 않기 위해). 주체는 `KeyID="sso"`·`KeyScopes=mcp.oauth.scopes`(토큰 `scope` 가 Relio 어휘를 싣고 오면 교집합, `mcp:use` 는 항상)·`KeyChannels=[MCP]` 로 키와 같은 `Has`/`ChannelAllowed` 문을 지남 — 관리자 계정이라도 상한 밖 권한은 없고 REST 채널은 닫힘. (5) 401 은 `Bearer realm="Relio MCP"` 에 활성일 때만 `resource_metadata=` 를 더하고 거부된 토큰이면 `error="invalid_token"` — 한국어 사유는 헤더가 아니라 JSON 본문(RFC 6750 문자 제한). 메타데이터는 `/.well-known/oauth-protected-resource` 와 - 요약: Hunter 는 사용자별 계정·역할과 OIDC 웹 로그인(`users.oidc_subject = digest(issuer|sub)`)이 이미 있으므로 표준을 그대로 적용했다. **고른 것과 이유**: (1) 설정 자리는 관리 화면 설정 그룹 `mcp` 의 `oauth` 객체 하나 — 경로가 `mcp.oauth.enabled/resource/audience/scopes` 로 표준 이름과 같고, `oidc.issuer`·`oidc.client_id` 를 재사용하며 audience·scopes 는 Hunter 의 다른 설정처럼 배열이되 표준의 공백 구분 문자열도 받는다; 켤 때 OIDC 가 꺼져 있거나 issuer 가 없거나 scopes 가 비면 PUT 을 400 으로 거부하고(postra 방식), 켠 뒤 전제가 사라지면 조용히 꺼진 것처럼 동작하며 `mcp oauth switched on but inactive` 로그를 남긴다. (2) 리소스 식별자는 `mcp.oauth.resource`, 비면 `general.public_url + /mcp` — Host 헤더는 쓰지 않고(기본값이 있어 마지막 수단이 필요 없음) 메타데이터 주소는 항상 public_url 아래(서버가 실제로 답하는 곳). (3) 계정 매핑은 웹 로그인과 같은 `digest(issuer|sub)` 만 — Hunter 에는 `oidc.username_claim` 이 없고 웹 로그인도 username 으로 병합하지 않으므로 username 대체 조회는 두지 않았다(로컬 bootstrap 계정이 Keycloak 사용자명으로 열리는 일이 없게). 구현(`internal/app/mcp_oauth.go`): `/.well-known/oauth-protected-resource(/mcp)` 맨 JSON·CORS `*`·꺼지면 404, `/mcp` 401 에 `WWW-Authenticate: Bearer realm="hunter", resource_metadata="…"`(거부 시 `error="invalid_token"`, MCP 경로에서만), `authenticate` 가 같은 Bearer 헤더에서 `hnt_` 접두사 → 키, JWT 모양 → OAuth(요청 컨텍스트의 MCP 표시가 없으면 거부, 즉 REST·GraphQL·관리 API 는 지금처럼 키·세션만), 나머지 → 기존 "로그인이 필요합니다". 검사는 헤더 `typ=ID`·비대칭 알고리즘(RS/ES/PS)을 JWKS 요청 전에 먼저, 그 다음 go-oidc(`SkipClientIDCheck`)로 서명·iss·exp·nbf, 손으로 `cnf`·`sub`·대상(`aud` 에 리소스 식별자, 또는 `aud`/`azp` 가 `mcp.oauth.audience` 또는 웹 client_id) — 거부 메시지에 본 aud/azp 와 적을 값을 넣는다. provider 는 issuer+신뢰 CA 해시로 캐시(`context.WithoutCancel`, Hunter 의 신뢰 CA 클라이언트 재사용)하고 JWKS 재요청은 초당 1회로 묶었다(postra). 범위는 역할 ∩ `mcp.oauth.scopes`(기본 읽기 3개)이고 **교집합이 비면 명시적 거부**. 캠페인 규칙 점검: `KeyID != ""` 를 키/세션 판정에 쓰는 지연 재인가 지점 6곳(agentPrincipal·scheduleOwner·finding_bulk·modelPrincipalCurrent·workflowPrincipal·agents_control)을 모두 나열했는데 어느 것도 MCP 도구 표면에서 닿지 않고(도구가 남기는 scan 행의 credential_key_id 를 다시 읽어 권한을 만드는 소비자 없음), 그래도 `User.Auth="oauth"` 를 두어 감사 기록 `mcp.<도구>` 에 `auth: sso` 로 표시하고 주석에 빈 KeyID 센티널 주의를 적었다; 모든 거부 경로는 `mcpOAuthRefusal{message,cause}` 하나로 만들어 `/mcp` 핸들러 한 곳에서 `mcp sso token rejected cause=…` 로 로그하며 테스트 실행 로그에서 12가지 원인이 모두 찍히는 것을 grep 으로 확인했다. 화면: 설정 새 탭 **MCP · SSO 연결**(스위치·리소스 식별자·허용 대상 TagsInput·범위 MultiSelect·MCP 주소/메타데이터 주소 복사·Keycloak 안내), 개인 키 페이지 MCP 카드에 "키 없이 SSO 로 연결하기"(`/api/settings/public` 의 `mcp_sso_enabled`·`mcp_sso_url`). 문서: 관리자 가이드 §15.6(흐름·설정 표·검사 표·Keycloak 클라이언트/Audience 매퍼 표·curl 확인·거부 메시지별 조치·introspection 없음 한계), 설정 그룹 표, 사용자 가이드 §12.4 "키 없이 SSO 로 연결하기", README, llms.txt, AGENTS.md, openapi.json(경로 2개·스키마 1개·settings enum), html/pdf 재생성. 검증: `go vet`, 임시 PostgreSQL 16 컨테이너로 `go test -race ./...`(새 테스트 4개: 기본 꺼짐·메타데이터 404·꺼진 상태에서 토큰이 키와 똑같이 거부되고 JWKS 미요청·OIDC 없이 켜기 400 / 설정 검증 6가지 거절과 정규화 / 가짜 IdP 가 서명한 진짜 JWT 로 메타데이터·MCP 전용 401 헤더·매퍼 경로 통과·감사 `auth: sso`·다른 대상 거부 메시지에 aud/azp/고칠 값·azp 허용 목록·웹 client_id·만료·nbf·다른 issuer·typ=ID·cnf·sub 없음·미등록·HS256(키 요청 없이)·비활성 계정·빈 교집합 거부·REST/GraphQL 에서 토큰 거부·키 그대로 동작·공개 설정·끄면 즉시 닫힘 / 사용자 지정 리소스), `npm test`(93 통과), `tsc`·`vite build`, `render-guides.mjs`·`check-docs.mjs`. 빌드한 서버를 컨테이너로 실제로 띄워 curl 로 꺼짐 404·`Bearer realm="hunter"` 만, OIDC 없이 켜기 400, 켜면 메타데이터 200+CORS·401 의 resource_metadata·REST 401 에는 헤더 없음·닿지 않는 issuer 의 토큰이 메시지와 로그 cause 로 거부됨을 확인하고, playwright chromium 으로 설정 탭 렌더·리소스 입력·저장 PUT 200·저장값 반영·키 페이지 안내 표시를 확인했다. **미검증 한계**: 실제 Keycloak·실제 MCP 클라이언트(Claude/Cursor)로 URL 만 넣어 연결하는 것은 이 환경에 Keycloak 이 없어 하지 못했다(가짜 IdP 의 Keycloak 26 모양 토큰으로 대체).
