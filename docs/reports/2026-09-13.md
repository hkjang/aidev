- 요약: `AppCard`는 공개 카탈로그용으로 쓰여 status를 전혀 그리지 않는데 같은 컴포넌트를 `/my/apps`와 내 홈이 재사용해, 소유자의 초안·검토 대기·반려·보관 앱이 모두 똑같이 보였다 — 사용자 가이드가 "카드 자체에는 상태 배지가 붙지 않습니다"라고 우회해 적고 내 홈 숫자 카드로 안내했지만 그 숫자는 '몇 개'만 말하지 '어느 것'인지는 말하지 않는다. `AppCard`에 `showStatus` prop을 두어 소유자 두 화면만 켜고(공개 카탈로그는 게시된 앱만 있으므로 그대로), admin-pages.tsx에 있던 `APP_STATUSES`·`AppStatusBadge`를 `features/apps/app-status.tsx`로 옮겨 관리 콘솔과 같은 라벨·톤을 쓰게 했다. 함께 보류 목록의 fixture 항목을 처리했다 — e2e mock의 `/me/apps`에 review가 실린 반려 앱(Release Radar) 하나를 더하고 my-app-edit 캡처 route를 그 앱으로 바꿔, my-apps·my-home·my-app-edit 캡처 6장이 배지와 반려 안내를 실제로 담는다(공개 카탈로그 `apps` 목록은 건드리지 않아 공개 화면 캡처는 바이트 동일). USER_GUIDE.md의 2.4·3.8·3.9·4.1 문장을 고치고 공용 md2pdf.mjs로 PDF를 다시 구웠다(24쪽, 표지 v2.6.0 유지). 검증: MyAppsPage에 "초안·검토 대기·보관됨 배지가 카드마다 붙는다" 테스트, 공개 AppsPage에 "게시됨 배지가 없다" 단언을 더한 뒤 `npm run lint`, `npm test`, `prettier --check`, `npm run build`, `check-offline-assets.sh`, `gofmt`·`go vet`·`go test -race`(CI 패키지 목록)·`go build`, `check-env-contract.sh`, `check-docs.sh`, 그리고 `APPSTORE_PREVIEW_PORT=4317 make screenshots VERSION=v2.6.0`(Playwright desktop·mobile 49 통과) 모두 통과. 캡처는 4 화면 8장 중 의도한 6장만 남기고 렌더링이 흔들린 admin-authentication 2장은 manifest 항목과 함께 HEAD로 되돌렸다. 커밋 f9d54a1.
- 보류 아이디어: 소유자 카드의 앱 이름·"자세히" 링크가 `/apps/{slug}`로 가는데 공개 상세는 published+public만 조회해(`GetAppBySlug(..., false)`) 초안·검토 대기·반려·보관 앱에서는 "앱을 찾을 수 없습니다"가 뜸 — showStatus 문맥에서 게시되지 않은 앱은 수정 화면으로 보내거나 링크를 끄면 됨(가치 3/위험 1/S) · `clientAddress`가 RemoteAddr만 보아 reverse proxy 뒤에서 rate limit이 전역이 됨 — 신뢰 프록시 설정을 system_settings에 두는 쪽이 관례(가치 3/위험 3/M) · 방문 추적 화면에 현재 설정이 만들 CSP 문자열 미리보기 — `pagePolicy`가 순수 함수라 GET 한 개와 `<code>` 블록이면 됨(가치 2/위험 1/S) · 소유자가 볼 수 있는 검토 이력이 마지막 한 건뿐 — `/me/apps/{id}/reviews` 읽기 경로 + OpenAPI + 화면(가치 2/위험 1/M) · 프런트엔드 `streamAiChat`이 스트림 종료 시 `\n\n` 없이 끝난 마지막 event를 버림 — reader done 뒤 남은 buffer를 한 번 더 파싱하면 됨(가치 2/위험 2/S)
