- 요약: `SimpleRunDetailPage` 의 스트림 effect 가 `log`·`end` 만 듣고 `error` 는 듣지 않아, 서버가 429 `stream_limit`(`server.go:121` 사용자당 3·전역 64) 로 거절하거나 세션 만료·프록시 절단으로 연결이 죽으면 브라우저는 `readyState=CLOSED` 로 두고 `error` 만 한 번 내며 재연결하지 않았고, `end` 프레임이 없으니 기존 재연결 경로(`streamAttempt`)도 상태 재조회도 돌지 않아 화면은 "진행 중" 인 채 로그만 영구히 멈췄습니다. 순수 헬퍼 `streamDisconnected(readyState)` 로 브라우저가 스스로 재시도하는 CONNECTING(0) 오류와 포기한 CLOSED(2) 를 갈라, 후자일 때만 로그 영역에 경고 Alert 와 "다시 연결" 버튼을 띄우고(`open` 이벤트가 오면 거둡니다), 그 조작은 끊긴 동안 쌓인 줄이 보이도록 저장 로그를 다시 수집한 뒤 스트림 하나만 마지막 id 에서 이어 엽니다 — 자동 재시도 루프는 넣지 않았습니다(스트림을 거절한 그 한도를 되레 때립니다). 검증은 TDD 로 — 테스트 4건을 먼저 넣어 3건 실패를 본 뒤 구현했고, `streamDisconnected` 를 `return true` 로 되돌리면 CONNECTING 테스트만 실패함을 확인해 readyState 판정이 그 테스트에 고정돼 있음을 증명했습니다. `cd web && npm test -- --run` 102건 전부 통과(직전 98 + 신규 4), `npx tsc -b --noEmit` 통과, 백엔드 무관함을 보이려 `cd backend && go test ./...` 통과(DSN 미설정이라 통합 테스트는 Skip). `EventSource.CLOSED` 같은 정적 상수 대신 모듈 상수를 썼고 리스너는 `addEventListener` 로만 달았으며, effect 의존성 배열·`appendStreamedLine`·`streamEndedRun`·자동 스크롤은 건드리지 않았습니다.
