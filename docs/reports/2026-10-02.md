CI 순서 그대로 `npm ci && npm test && npm run build` 한 체인 exit 0, `npm run typecheck`(tsc --noEmit) 0, `prettier --check web/package.json` 통과, `git diff --check` 0. 릴리즈 경로를 건드렸으므로 `cp -a web/dist/. internal/webassets/dist/` 후 `node scripts/verify-pentagi.mjs`(312파일 확인), `go vet ./...` 0, `go build ./cmd/hunter` 성공까지 확인하고 생성된 `hunter` 바이너리는 커밋 전에 삭제했다. **미검증**: 원격 CI(Node 26)와 Docker 빌드·릴리즈는 돌릴 수 없어 미확인이다. Node 26 미설치라 가장 가까운 v25.9.0·v25.0.0 에서 플래그 없는 `.ts` import 가 되는 것만 확인했다. Go 변경이 없어 `go test -race ./...`(HUNTER_TEST_DSN 필요)는 생략했다.
- 실패 재현: `npm ci` 를 마친 트리에서 수정 전 `npm test --silent` → `node: bad option: --experimental-strip-types` / `EXIT=9`(테스트 0건). 과제서가 제안한 플래그 삭제만의 반증도 같은 트리에서 실측: `npm exec -c 'node --test tests/*.test.mjs'` → `# tests 19` / `# pass 0` / `# fail 19` / exit 1 — 가로채진 Node 20 에는 `.ts` 타입 스트리핑이 아예 없어 전 파일이 import 단계에서 죽는다. 인과 확정: 같은 글롭을 `$npm_node_execpath`(v22.23.1)로만 바꾸면 19파일 104통과.
- 보류 아이디어: web 테스트 러너의 Node 요구를 `engines`(>=22.18) 로 선언해 드리프트를 조용한 실패가 아니라 경고로 만들기 (3/1/S — 이번에 `node_modules/.bin` 가로채기를 중화했으므로 별도 회차) / bulk due_date 의 해제·형식·오류 래핑 순수 테스트 (3/1/S) / 직접 API 담당자 비문자열·trim 전 바이트 한도 테스트 (2/1/S) / `oidcReturnTo`(Go)와 `safeReturnPath`(TS) return_to 규칙 공유 벡터 교차 검증 (3/2/M) / 서버 CSV 내보내기 개인 키 권한 교집합 HTTP 회귀 (3/1/S, HUNTER_TEST_DSN 필요)
