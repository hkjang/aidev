# 관리자 가이드

관리 화면(`/admin/*`)에서 켜고 끄는 설정 가운데, 켜면 사용자가 보는 흐름이 달라지는
것을 적습니다. 환경변수는 [환경변수](environment-variables.md)에, 로그인 방어의 배경은
[로그인 방어](authentication-hardening.md)에 있습니다.

## SSO(OIDC) 설정 — `/admin/sso`

Keycloak 등 OIDC 공급자로 로그인하게 합니다. Issuer·Client ID·Client Secret·Redirect URL 을
넣고 **SSO 활성화**를 켜면 저장 즉시 적용되어 로그인 화면에 SSO 버튼이 나타납니다.
Client Secret 은 마스터 키로 암호화되어 저장되고, 설정 변경은 `mgnt_audit_log` 에 남습니다.

| 항목 | 기본값 | 뜻 |
|---|---|---|
| SSO 활성화 | 꺼짐 | 로그인 화면에 SSO 버튼을 보이고 `/auth/sso/*` 를 엽니다 |
| 미등록 사용자 자동 생성 | 켜짐 | IdP 가 준 이메일로 계정이 없으면 기본 역할로 만듭니다 |
| 기본 역할 | `USER` | 자동 생성되는 계정의 역할 |
| 버튼 라벨 | `SSO로 로그인` | 로그인 화면 버튼 글자 |
| **IdP 세션이 있으면 자동 로그인** (`auto_login`) | **꺼짐** | 아래 참고 |

### 자동 로그인 (`auto_login`)

IdP 에 이미 로그인한 사람이 DartFly 를 열면 **로그인 화면을 보지 않고** 바로 본 화면으로
들어갑니다. 사내 앱을 여럿 오가며 같은 로그인 화면을 매번 지나는 일을 없애는 설정입니다.

동작은 OIDC 표준의 silent authentication(`prompt=none`)입니다. 로그인 화면이 뜨기 전에
브라우저가 IdP 에 **최상위 이동**으로 다녀옵니다(숨은 iframe 이 아니므로 서드파티 쿠키가
막힌 브라우저에서도 동작합니다). IdP 는 화면을 전혀 그리지 않고 둘 중 하나로 답합니다.

- 세션이 살아 있으면 인가 코드가 곧바로 돌아오고 평소 로그인이 이어집니다. 깊은 링크
  (`/resources?tab=2` 같은)로 들어왔다면 로그인 뒤 **그 자리로** 돌아갑니다.
- 세션이 없으면 `login_required` 가 돌아옵니다. 이것은 실패가 아니라 평범한 대답이며,
  사용자는 평소 로그인 화면을 봅니다(오류 메시지 없음).

**무한 리다이렉트를 막는 장치**가 세 겹 있습니다. 거절당했는데 다시 시도하면 브라우저가
IdP 와 앱 사이를 끝없이 오가고 사용자는 화면이 깜빡이는 것만 보기 때문입니다.

1. **한 탭에 한 번만** 시도합니다(`sessionStorage`). 거절당한 뒤 새로고침해도 다시 시도하지
   않고, 새 탭에서는 다시 시도합니다.
2. **스스로 로그아웃한 사람은** IdP 세션이 남아 있어도 자동으로 다시 들어오지 않습니다.
   로그아웃했는데 곧바로 다시 로그인되면 로그아웃이 고장 난 것처럼 보이기 때문입니다.
   다시 로그인하면 억제가 풀립니다.
3. 거절을 받으면 `/login?sso=none` 으로 돌아오며, 이 표시가 붙은 주소에서는 브라우저
   저장소가 지워졌더라도 다시 시도하지 않습니다. 깊은 링크로 들어왔다면 `return_to`
   도 함께 따라오므로, 이어서 비밀번호나 SSO 단추로 로그인하면 원래 자리로 갑니다.

사생활 보호 모드처럼 저장소를 읽을 수 없는 브라우저에서는 **시도하지 않는 쪽으로**
동작합니다(막히는 쪽으로 실패).

서버는 이 설정이 꺼져 있으면 `?prompt=none` 을 붙여 불러도 평범한 로그인으로 바꿉니다.
리다이렉트가 생기는 자리는 관리자 설정에만 묶여야지, 누구든 주소에 붙여 흐름을 바꿀 수
있으면 안 되기 때문입니다. 그래서 **기본 설치에서는 이 설정을 켜기 전까지 아무것도
달라지지 않습니다.**

Keycloak 클라이언트에서 따로 켤 것은 없습니다. Valid redirect URIs 에 Redirect URL 이
등록되어 있으면 됩니다. API·MCP·헬스 경로는 이 흐름과 무관합니다 — 브라우저 화면 이동에만
해당합니다.

관리 화면 없이 환경변수(`DARTFLY_OIDC_*`)로만 SSO 를 구성한 배포에서는
`DARTFLY_OIDC_AUTO_LOGIN=true` 가 같은 스위치입니다. 환경변수는 화면에 저장된 설정이
하나도 없을 때만 읽으므로, 화면에서 한 번 저장한 뒤에는 화면의 값이 이깁니다
([환경변수 1.5](environment-variables.md#15-ssooidc-설정)).

이 설정과 무관하게, **이미 로그인한 상태로 `/login` 을 열면**(북마크·뒤로가기·이메일
링크) 서버가 세션 쿠키를 보고 폼 대신 `return_to`(없으면 `/`)로 바로 보냅니다. 밖을
가리키는 `return_to` 나 `/login` 자신을 가리키는 값은 `/` 로 취급합니다. 비활성화된
계정의 쿠키는 세션으로 치지 않으므로 폼이 나옵니다.

#### 확인하는 법

- IdP 에 로그인한 상태로 DartFly 를 열면 로그인 화면 없이 본 화면이 뜬다.
- 로그인하지 않은 상태로 열면 로그인 화면이 뜨고, 새로고침을 여러 번 해도 깜빡이지 않는다.
- 로그아웃한 뒤 다시 열어도 자동으로 로그인되지 않는다.
- 설정을 끄면 예전과 똑같이 SSO 버튼만 보인다.
- 켰는데 한 번도 자동 로그인이 되지 않으면 서버 로그에서 `조용한 SSO 시도가 세션 없음이
  아닌 오류로 돌아옴` 경고를 찾는다. `login_required` 류(세션 없음)는 정상이라 남기지 않고,
  `invalid_client`·`invalid_request` 같은 값은 IdP 클라이언트 설정 문제라 오류값과 설명을
  함께 남긴다.
