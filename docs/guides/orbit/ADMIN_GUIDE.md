# 관리자 가이드

서비스 관리 콘솔(`/admin`)에서 다루는 설정 가운데 동작을 알고 써야 하는 것을
적는다. 화면 구성은 [사용자 가이드 §2.9](guide.md#29-서비스-관리-콘솔-admin),
배포와 환경 변수는 [오프라인 배포](OFFLINE.md)를 본다.

## Keycloak SSO (OIDC)

**Keycloak SSO** 탭에서 Issuer URL, Client ID, Client Secret을 넣으면 Discovery와
토큰 검증이 자동으로 구성된다. Keycloak 클라이언트의 Valid Redirect URI 에는
`<서비스 URL>/api/v1/auth/oidc/callback` 을 등록한다. 서비스 URL 은 **일반** 탭의
값이며, 콜백 주소는 이 값에서 만들어진다.

| 설정 | 기본값 | 뜻 |
| --- | --- | --- |
| Keycloak SSO 사용 | 꺼짐 | 로그인 화면에 SSO 버튼을 보인다 |
| 첫 SSO 로그인 시 사용자를 자동 등록 (`auto_provision`) | 켜짐 | 처음 오는 사용자를 기본 역할로 만든다. 꺼져 있으면 관리자가 미리 등록한 사용자만 들어온다 |
| 신규 사용자 기본 역할 (`default_role`) | 멤버 | 자동 등록되는 사용자의 역할 |
| 자동 로그인 (`auto_login`) | **꺼짐** | 아래 참고 |

### 자동 로그인 (`auto_login`)

Keycloak 에 이미 로그인한 사람이 Orbit 을 열면 **로그인 화면 없이** 바로 본
화면으로 들어가게 한다. 여러 사내 서비스를 오가며 같은 로그인 화면을 반복해서
지나는 일을 없애는 설정이다.

**동작.** 로그인하지 않은 브라우저가 화면 경로를 열면, 화면을 그리기 전에
`/api/v1/auth/oidc/start?prompt=none` 으로 한 번 다녀온다. `prompt=none` 은
제공자에게 "이미 있는 세션으로만 답하라"고 요구하므로 제공자는 화면을 그리지
않는다.

- Keycloak 세션이 있으면 인가 코드가 곧바로 돌아와 평소처럼 로그인된다. 깊은
  링크(`/people/…`)로 들어왔다면 로그인한 뒤 그 자리로 돌아간다.
- 세션이 없으면 `login_required` 로 돌아온다. 이것은 실패가 아니라 평범한
  대답이다. 브라우저는 `/login?sso=none` 으로 가서 평소의 로그인 화면을 본다.

숨은 iframe 이 아니라 최상위 이동을 쓰므로 서드파티 쿠키가 막힌 브라우저에서도
동작하고, Keycloak 의 프레임 정책과 무관하다.

**루프를 막는 장치.** 거절당한 뒤 다시 시도하면 브라우저가 Keycloak 과 Orbit
사이를 끝없이 오간다. 그래서 다음 세 겹으로 막는다.

1. 한 탭의 브라우징 세션에 한 번만 시도한다 (`sessionStorage`). 새 탭에서는
   다시 시도하고, 거절당한 뒤 새로고침하면 다시 시도하지 않는다.
2. 사용자가 스스로 로그아웃하면 다음 로그인까지 시도하지 않는다. 로그아웃
   직후 다시 조용히 로그인되면 로그아웃이 고장 난 것처럼 보이기 때문이다.
3. 콜백이 거절을 받으면 `/login?sso=none` 으로 보내 주소에도 표시를 남긴다.
   브라우저 저장소가 지워졌더라도 이 표시가 있으면 다시 시도하지 않는다.

브라우저 저장소를 읽지 못하는 환경(사생활 보호 모드 등)에서는 "이미 시도했다"로
보고 시도하지 않는다.

**안전 장치.** 이 설정이 꺼져 있으면 누가 주소에 `?prompt=none` 을 붙여 불러도
서버가 평범한 로그인으로 바꾼다. 조용한 시도는 화면 경로에서만 일어나며
`/login`, `/api/…`, `/mcp`, `/healthz` 에서는 하지 않는다. 로그인 뒤 돌아갈
`return_to` 는 `/` 로 시작하고 `//` 로 시작하지 않는 같은 사이트 경로만 받는다.

**켜기 전에 확인할 것.**

- Keycloak SSO 사용이 켜져 있고 SSO 버튼으로 로그인이 되는지 먼저 확인한다.
- 켠 뒤에는 (1) Keycloak 에 로그인한 브라우저에서 Orbit 을 열면 로그인 화면
  없이 본 화면이 뜨는지, (2) 로그인하지 않은 브라우저에서는 로그인 화면이
  깜빡임 없이 뜨고 새로고침을 여러 번 해도 리다이렉트가 반복되지 않는지, (3)
  로그아웃한 뒤 다시 열어도 자동으로 로그인되지 않는지 본다.
- 감사 로그의 `auth.login` 항목에는 `"silent": true` 가 함께 남아, 자동
  로그인으로 들어온 세션을 구분할 수 있다.
